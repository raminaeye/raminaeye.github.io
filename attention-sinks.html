Attention Sinks and Streaming Generation

A model trained with full attention collapses when its cache is cut to a window, because it parks spare attention on the first tokens; keeping those few tokens, the attention sinks, lets it stream for millions of tokens in fixed memory.

A chat assistant that runs for hours, or a model reading a live transcript, generates far more tokens than it was trained on. Its KV cache cannot keep everything.

1 Streaming breaks a full-attention cache

Models such as Llama 2, MPT, Falcon and Pythia are trained with full attention over a fixed length. Streamed past it, there are three plain options, and each fails in its own way. Keeping everything grows memory with every token and breaks past the training length. Keeping only a recent window, as a window-trained model would, collapses as soon as the first tokens are evicted. Recomputing the window from the text for every token stays stable but redoes the whole window each step.

Xiao et al. (2023) traced the collapse to a handful of tokens at the very start, and kept them.

2 Softmax has to put its attention somewhere

In all but the lowest layers, many heads put a large share of their attention on the first tokens, whatever those tokens say. These are the attention sinks.

Where the newest query's attention goes: the softmax weights and their denominator.
\({\displaystyle \htmlClass{eqt sym-a}{\htmlStyle{color:#117a7a}{a_{tj}}}=\frac{e^{\htmlClass{eqt sym-x}{\htmlStyle{color:#9a6400}{x_{tj}}}}}{\htmlClass{eqt sym-z}{\htmlStyle{color:#1f618d}{Z_t}}}}\)
Picture a chat assistant built on Llama 2 that keeps talking for hours. At step \(t\) the newest query scores every cached key; \(x_{tj}\) is the score of key \(j\), and \(a_{tj}\) is the weight it gets. Dividing by \(Z_t\), the sum of all the exponentials, makes the weights add up to one, so the query must put its attention somewhere even when no key matches.
\({\displaystyle \htmlClass{eqt sym-z}{\htmlStyle{color:#1f618d}{Z_t}}=\htmlClass{eqt sym-sink}{\htmlStyle{color:#b03a2e}{Z_t^{\text{sink}}}}+\htmlClass{eqt sym-z}{\htmlStyle{color:#1f618d}{Z_t^{\text{rest}}}}}\)
Split the denominator in two: the part that comes from the first few tokens and the part from every other cached token.
\({\displaystyle \htmlClass{eqt sym-sink}{\htmlStyle{color:#b03a2e}{Z_t^{\text{sink}}}}=\sum_{j<\htmlClass{eqt sym-s}{\htmlStyle{color:#b03a2e}{s}}}e^{\htmlClass{eqt sym-x}{\htmlStyle{color:#9a6400}{x_{tj}}}}}\)
In trained models the first part is large: the model parks the attention it does not need on the first \(s\) tokens, which every later token can see. Evict them and \(Z_t\) loses that part, so every remaining weight is divided by a smaller number and jumps, and the layer outputs drift away from anything seen in training.

Why the first tokens? They are the only tokens every later token can see, so training finds them the easiest place to park attention. Meaning plays no part: the paper replaced the first four tokens with line breaks and the model recovered just as well, so their position is what counts.

3 Keep the sinks, roll the window

The fix is a cache of two parts: the first few tokens, pinned, and a rolling window of the most recent ones. Everything in between is evicted, and memory stays fixed.

The tokens the cache keeps at step \(t\).
\({\displaystyle \text{kept}(t)=\htmlClass{eqt sym-S}{\htmlStyle{color:#b03a2e}{S}}\cup \htmlClass{eqt sym-R}{\htmlStyle{color:#117a7a}{R_t}}}\)
The cache keeps two sets and evicts everything in between.
\({\displaystyle \htmlClass{eqt sym-S}{\htmlStyle{color:#b03a2e}{S}}=\{0,\dots,\htmlClass{eqt sym-s}{\htmlStyle{color:#b03a2e}{s}}-1\}}\)
\(S\) is the sinks: the first \(s\) tokens of the stream, pinned for good.
\({\displaystyle \htmlClass{eqt sym-R}{\htmlStyle{color:#117a7a}{R_t}}=\{t-\htmlClass{eqt sym-w}{\htmlStyle{color:#117a7a}{w}}+1,\dots,t\}}\)
\(R_t\) is the recent window: the last \(w\) tokens, rolling forward one token per step as in a rolling buffer.
sinksrecent window
The position given to kept token \(j\).
\({\displaystyle \htmlClass{eqt sym-pos}{\htmlStyle{color:#7d3c98}{p_j}}=\#\{i\in\text{kept}:i<j\}}\)
The position \(p_j\) a kept token \(j\) gets is its rank inside the cache: \(\#\) counts the kept tokens before it. Counting in the original text would hand the model gaps and positions far beyond its training length; counting inside the cache keeps every position within what it has seen.
position inside the cache

With rotary positions (RoPE), the cache stores keys before the rotation and rotates them at each step with their position inside the cache; with ALiBi, a contiguous distance bias is used.

6 Training a sink in from the start

The model needs several first tokens as sinks only because nothing in training gave it one dedicated place to park attention. Xiao et al. pretrained small language models two ways to give it one.

Softmax with a built-in place to park attention, which Xiao et al. tested as the “zero sink”.
\({\displaystyle \mathrm{softmax}_1(x)_j=\frac{e^{x_j}}{1+\sum_i e^{x_i}}}\)
Softmax-off-by-one adds 1 to the denominator. That is the same as an extra key whose score is zero and whose value is all zeros: a built-in place to park attention that adds nothing to the output.
  • Zero sink. Softmax-off-by-one, the line above, helped only partly: the model still leaned on other first tokens.
  • Learnable sink token. One extra token placed at the start of every training sample. With it, a single sink was enough when streaming, and training and benchmark quality did not suffer.

7 What the paper measured

The setup: Llama 2, MPT, Falcon and Pythia models read the PG19 book collection as one long stream, with the cache cut to a fixed size and perplexity measured as the stream runs. Chat models were also given a stream of exam questions (ARC) to answer one after another, with every earlier question and answer still in the stream.

  • Window attention alone collapses once the first tokens leave the cache; dense attention fails past the training length.
  • Keeping a few first tokens plus the window keeps the stream stable over very long streams, while keeping only one or two does not fully recover.
  • On the question stream, dense attention ran out of memory, window attention scored near zero, and the sink cache matched answering each question on its own.
  • Against recomputing the window, the sink cache avoids recomputing it, so it is much faster per token at similar memory.
  • A larger cache did not reliably help: the models use little of a long context anyway.

Sinks give stability, not memory. The model still sees only what is in the cache; a fact that has rolled out of the window is gone.

8 Using a sink cache

import torch

class SinkCache:
    def __init__(self, sink, window, d):
        self.sink, self.window = sink, window
        self.k = torch.zeros(sink + window, d)
        self.v = torch.zeros(sink + window, d)
        self.n = 0  # tokens written so far

    def write(self, i, k, v):  # token i; k cached before the rotary rotation
        if i < self.sink:
            slot = i
        else:
            slot = self.sink + (i - self.sink) % self.window
        self.k[slot], self.v[slot] = k, v
        self.n = i + 1

    def read(self):
        used = min(self.n, self.sink + self.window)
        # window slots form a ring, so slot order is not token order;
        # each token's position is its rank among the kept tokens
        return self.k[:used], self.v[:used]
  1. 1One slot per sink plus one per window position, the two sets of the kept line.
  2. 2The first tokens fill the sink slots for good; every later token rolls through the window slots, a rolling buffer shifted past the sinks.
  3. 3Attention reads the sinks plus the recent window, never anything older; the position line renumbers them before the rotation is applied.
WhenInference only, for a model trained with full attention that must run past its cache: long chat sessions, live transcripts, assistants that never reset. No retraining.
What it keepsThe \(s\) sinks plus the last \(w\) tokens, in every layer; positions are renumbered each step.
Sinks \(s\)Four in the paper; one if the model was pretrained with a sink token.
Window \(w\)Within the training length; the paper used about half of it. A window-trained model such as Mistral needs no sinks: its rolling buffer is enough.

The paper reports the method adopted in Hugging Face Transformers, NVIDIA TensorRT-LLM, Intel Extension for Transformers and MLC LLM.
