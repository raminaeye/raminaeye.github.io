Cross-Entropy Loss

You know me, I'm gonna talk about loss functions now! Let's start with binary cross entropy.

Binary Cross Entropy (BCE)

BCE is how you score a coin-flip prediction. The model says how likely it thinks a class is present, and BCE measures how wrong that probability was. Confident and right, tiny loss. Confident and wrong, the loss blows up.

Binary cross entropy: how you score a coin-flip prediction, averaged over every example.
L = −1NΣi (yi log pi + (1 − yi) log (1 − pi))
Here pi is the predicted probability, the logit (the model's raw score for a class) squashed through a sigmoid, and yi is the ground truth: 1 if the class is present, 0 if not. L is the average loss, Σi means add over every example and N is how many examples were added, so the sum is divided by N, and log is the punisher: confident wrong bets cost more. The first term scores the yes side: if the true answer is yes, punish how far the model's confidence was from 1. The (1 − yi) log(1 − pi) branch scores the no side: if no, punish how far from 0.

The bce_with_logits_loss listing below runs this line in its three commented steps: sigmoid, binary cross entropy per class, then the average over classes and batch.

Two steps. First, squash each logit through a sigmoid to get a probability. Then score it with BCE against the ground truth. Each class is its own independent yes-or-no bet, so nothing stops you from running this on multi-label data: sigmoid every logit, BCE per class, average over classes. That is how you model multiple classes co-occurring.

With BCE you can't compress the label into one integer anymore, so you need a multi-hot vector: each class is an independent yes/no bet, so you determine the cross-entropy for each class and average over them.

def bce_with_logits_loss(logits, targets):
    """
    logits: (N, C) raw outputs
    targets: (N, C) multi-hot labels {0,1}
    """
    # sigmoid
    probs = 1 / (1 + torch.exp(-logits))

    # binary cross entropy per class
    bce = -(targets * torch.log(probs) + (1 - targets) * torch.log(1 - probs))

    # average over classes and batch
    loss = bce.mean()
    return loss

Categorical Cross Entropy

Categorical cross entropy is BCE with a one-hot target (all zeros except a single 1) and one extra rule: exactly one class can be true. The probabilities come from a softmax over the logits.

With categorical cross entropy you apply a softmax over logits and get a probability over C classes. Then you apply categorical cross-entropy against a one-hot target. If the model assigns a small probability to the correct class, the loss is the negative log of that one probability.

CE assumes mutual exclusivity, that exactly one class is correct. So, that's why you get categorical cross entropy, you can show it as a single index. Internally, PyTorch converts that into a one-hot vector.

Remember negative log means lower loss is higher probability; it's just like the negative log likelihood of the true class under the predicted distribution.

CE punishes the model when it assigns low probability to the true class.

BCE charges the negative log of the bet on the true class, and log is the punisher: confident wrong bets cost more. MSE charges the squared gap between the bet and 1.
And their gradients: how hard each loss pulls back.

The two grad lines are the losses' gradients: cross-entropy's gradient stays huge when the model is confidently wrong, while MSE's gradient goes quiet there. BCE's pull is one over the probability, so it screams louder the more confident and wrong the bet; MSE's pull fades toward nothing at exactly that point. That is why classification uses cross-entropy: the gradient stays alive exactly where the model needs the strongest correction.

How to play

  • The point: Cross-entropy's gradient stays huge when the model is confidently wrong while MSE's gradient goes quiet there, which is why classification trains with cross-entropy.
def cross_entropy_loss(logits, target_index):
    """
    logits: (N, C) raw outputs
    target_index: (N,) integer labels (0 <= y < C)
    """
    # softmax
    exp_logits = torch.exp(logits)
    probs = exp_logits / exp_logits.sum(dim=1, keepdim=True)

    # pick probability of the correct class
    correct_class_probs = probs[torch.arange(len(target_index)), target_index]

    # negative log likelihood
    loss = -torch.log(correct_class_probs).mean()
    return loss

Squash and compete: what softmax and sigmoid actually do

Softmax is a competition with a fixed prize. There is exactly 1.0 probability to hand out, so when class 0 gets more confident, classes 1 and 2 must get less. One class's bar grows only by taking height from the others. That stealing is the whole reason cross-entropy works for classification. Sigmoid mode is the opposite arrangement: same logits, but the bars stop caring about each other. Three separate coin flips. That is BCE, and it is why you use it when labels can co-occur.

Squash and compete: what softmax and sigmoid actually do.
sigmoid: p = 11 + exp(−logit)
The sigmoid squashes one logit into a probability on its own. A logit is the model's raw score: a large positive logit drives the exp term toward zero and p toward 1, and a large negative one does the reverse.
softmax: pi = exp(logiti)Σc exp(logitc)
The softmax exponentiates every logit and divides by their sum, giving a probability over C classes that share exactly 1.0 probability to hand out, so when class 0 gets more confident, classes 1 and 2 must get less.
The categorical loss reads only the correct class.
categorical loss: L = −log(pcorrect)

Cross-entropy variants

Plain cross-entropy assumes the labels are exactly right and every class matters equally. When that is not true, reach for one of these:

  • Label smoothing: softens the one-hot target, so the model is never rewarded for total certainty. Helps when labels are noisy or the model gets overconfident.
  • Focal loss: down-weights the easy examples so training spends its effort on the hard ones. Helps when one class drowns out the others.
  • Class weighting: multiplies the loss of rare classes by a bigger constant. Helps with imbalanced data when you would rather reweight than resample.
