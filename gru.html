GRU: Gated Recurrent Unit

  1. RNN Basics: Recurrence and Backpropagation Through Time
  2. Gated RNNs: Why Gates Keep Memory Alive
  3. GRU: Gated Recurrent Unit

Two gates guard one memory, and a shut update gate lets that memory pass a step unchanged.

1 The GRU in one picture

A GRU keeps one memory alive with two gates, so a name mentioned many words earlier can still shape the next word.

Take "Ramin wrote the best tutorial, he did it again!". A vanilla RNN might overwrite "Ramin" and forget who "he" was; a GRU's update gate can say "don't overwrite Ramin, hold on to that memory." A language model meets this all the time: to predict the next words it must link "he" back to a name many tokens earlier.

The cell runs at every step of the sequence and carries one hidden state \(h\) between steps. The GRU has no separate cell state (a memory stream beside the hidden state); the update gate's identity path is enough to preserve long-term memory. One GRU step costs three weight blocks per step (update gate, reset gate, candidate), each weight about one multiply and one add, as the intro cost line counts it. Its two gates are the update gate and the reset gate.

2 The two gates

2.1 Gates decide what to keep and what to forget

There are 2 gates, both little feedforward networks (networks that read input to output in one pass, with no loop back) with a sigmoid activation, so their outputs are between 0 and 1.

  • The update gate asks "Keep the old hidden state or update it?" 0 means keep the old memory, 1 means overwrite it with new memory.
  • The reset gate asks "When computing new candidate memory, how much of the old memory should I ignore?"
  • The candidate hidden state is a proposal for new memory. With the reset gate at zero, the candidate ignores past memory and depends only on the input.

The update is a weighted average of the old memory and the candidate, and the network learns the gate setting from data, per step, per neuron. Figure 1 draws this as dataflow.

When the update gate keeps the old memory, the hidden state is copied straight to the next step: no multiplication, no tanh, an identity connection. Gradients flow back along that same path unchanged, which is how the GRU beats vanishing gradients.

3 The five lines

First the two gates decide how much to keep and how much old memory the candidate may see.
\(\displaystyle \htmlClass{eqt}{\htmlData{k=zt}{\htmlStyle{color:#88283c}{z_{t}}}} = \sigma (W_{z}\cdot [\htmlClass{eqt}{\htmlData{k=xt}{\htmlStyle{color:var(--sym-x)}{x_{t}}}}, \htmlClass{eqt}{\htmlData{k=htprev}{\htmlStyle{color:var(--sym-hidden)}{h_{t-1}}}}])\)
The update gate sets how much of the new candidate to let in versus keeping the old memory. \(\htmlClass{eqt}{x_{t}}\) is the input and \(\htmlClass{eqt}{h_{t-1}}\) the old memory; the brackets stack them into one vector, so \(W_{z} \cdot [x_{t}, h_{t-1}]\) is the RNN line's \(W \cdot x_{t} + U \cdot h_{t-1}\) written as one matrix on the stacked vector; each gate has its own pair. \(\sigma\), the sigmoid, squashes the result to between 0 and 1. Each line also adds a learned bias, left off here.
\(\displaystyle \htmlClass{eqt}{\htmlData{k=rt}{\htmlStyle{color:#88283c}{r_{t}}}} = \sigma (W_{r}\cdot [\htmlClass{eqt}{\htmlData{k=xt}{\htmlStyle{color:var(--sym-x)}{x_{t}}}}, \htmlClass{eqt}{\htmlData{k=htprev}{\htmlStyle{color:var(--sym-hidden)}{h_{t-1}}}}])\)
The reset gate sets how much of the old memory the candidate gets to see. It is built the same way from the input and the old memory, squashed to between 0 and 1.
Then the filtered memory, the candidate, and the blend that decides what survives.
\(\displaystyle \htmlClass{eqt}{\htmlData{k=mt}{\htmlStyle{color:#18625e}{m_{t}}}} = \htmlClass{eqt}{\htmlData{k=rt}{\htmlStyle{color:#88283c}{r_{t}}}} \odot \htmlClass{eqt}{\htmlData{k=htprev}{\htmlStyle{color:var(--sym-hidden)}{h_{t-1}}}}\)
The reset gate filters the old memory first, and \(\htmlClass{eqt}{m_{t}}\) is the part of the memory the candidate gets to see. The \(\odot\) multiplies element by element (matching entries one by one).
\(\displaystyle \htmlClass{eqt}{\htmlData{k=htilde}{\htmlStyle{color:#a04000}{\tilde{h}_{t}}}} = \text{tanh}(W_{h}\cdot [\htmlClass{eqt}{\htmlData{k=xt}{\htmlStyle{color:var(--sym-x)}{x_{t}}}}, \htmlClass{eqt}{\htmlData{k=mt}{\htmlStyle{color:#18625e}{m_{t}}}}])\)
The candidate is the new word mixed with the filtered memory, squashed by tanh to between −1 and 1. It is only a proposal; the next line decides what survives.
\(\displaystyle \htmlClass{eqt}{\htmlData{k=ht}{\htmlStyle{color:var(--sym-hidden)}{h_{t}}}} = \htmlClass{eqt}{\htmlData{k=omzt}{\htmlStyle{color:#88283c}{(1-z_{t})}}}\cdot \htmlClass{eqt}{\htmlData{k=htprev}{\htmlStyle{color:var(--sym-hidden)}{h_{t-1}}}} + \htmlClass{eqt}{\htmlData{k=ztb}{\htmlStyle{color:#88283c}{z_{t}}}}\cdot \htmlClass{eqt}{\htmlData{k=htilde}{\htmlStyle{color:#a04000}{\tilde{h}_{t}}}}\)
In the blend, \(\htmlClass{eqt}{h_{t}}\) adds the old memory scaled by \(1 - z_{t}\), the keep share, to the candidate scaled by \(z_{t}\), the replace share. \(z_{t} = 0\) keeps everything, \(z_{t} = 1\) replaces everything: the update gate is the blend knob.

3.1 The gradient on the keep path

The direct-path factor on the keep path
\(\displaystyle \frac{\partial \htmlClass{eqt}{\htmlData{k=ht}{\htmlStyle{color:var(--sym-hidden)}{h_{t}}}}}{\partial \htmlClass{eqt}{\htmlData{k=htprev}{\htmlStyle{color:var(--sym-hidden)}{h_{t-1}}}}} = 1 - \htmlClass{eqt}{\htmlData{k=zt}{\htmlStyle{color:#88283c}{z_{t}}}}\)
The blend line gives the gradient factor on the keep path: the old memory enters multiplied by one minus the update gate, so with \(z_{t} = 0\) this factor is exactly 1 and the gradient passes the step unchanged. It is the direct path only; \(z_{t}\) and the candidate also read \(h_{t-1}\), which adds side paths left off here.

This is the paper that introduced the GRU (Cho et al., EMNLP 2014). Figure 2 is the paper's Figure 2, its real hidden-unit diagram, with an excerpt of its original caption.

That paper and PyTorch put \(z\) on the old state; this page follows Chung et al. (2014), which puts \(z\) on the candidate. PyTorch's nn.GRU also applies the reset after the matrix rather than before it. The two reset placements are the two formulations Chung et al. (2014) section 3.2 footnote 1 compares, and Chung et al. report in preliminary experiments that both of these formulations performed as well as each other. That is preliminary evidence only, not a main controlled comparison.

Chung's footnote describes the after-matrix form as Cho's original, but Cho equation 8 as published puts the reset before the matrix, \(U(r \odot h)\); the page follows the published form when it names Cho's equation 8. The PyTorch docs agree with the published form: their "original implementation" note gives the candidate with the reset before the matrix, in contrast to PyTorch's own reset-after-matrix form. So the two sources disagree only because the paper changed between draft and publication.

The forms are not numerically equivalent with the same weights, since PyTorch puts \(z\) on the old state and applies the reset after the matrix while Chung equation 5 puts \(z\) on the candidate and Cho equation 8 as published applies the reset before the matrix, so weights trained in one convention give wrong outputs in the other.

The two reset placements Chung compares, and the published form PyTorch quotes.
\(\displaystyle \htmlClass{eqt}{\htmlData{k=htilde}{\htmlStyle{color:#a04000}{\tilde{h}_{t}}}} = \text{tanh}(W x_{t} + \htmlClass{eqt}{\htmlData{k=rt}{\htmlStyle{color:#88283c}{r_{t}}}} \odot (U \htmlClass{eqt}{\htmlData{k=htprev}{\htmlStyle{color:var(--sym-hidden)}{h_{t-1}}}}))\)

\(\displaystyle \htmlClass{eqt}{\htmlData{k=htilde}{\htmlStyle{color:#a04000}{\tilde{h}_{t}}}} = \text{tanh}(W x_{t} + U (\htmlClass{eqt}{\htmlData{k=rt}{\htmlStyle{color:#88283c}{r_{t}}}} \odot \htmlClass{eqt}{\htmlData{k=htprev}{\htmlStyle{color:var(--sym-hidden)}{h_{t-1}}}}))\)
Reset before the matrix: the reset gate scales the old memory first, then the matrix mixes it.

4 One GRU step, in code

The whole cell is the five card lines above, as one function: each nn.Linear holds one \(W\) and its bias, torch.cat builds the stacked vector, and the names match the cards: 

import torch
from torch import nn

# input and hidden sizes
d_in, d_h = input_size, hidden_size
d = d_in + d_h
W_z = nn.Linear(d, d_h)
W_r = nn.Linear(d, d_h)
W_h = nn.Linear(d, d_h)

def gru_step(x_t, h):
    # h is h_t-1: (batch, d_h)
    xh = torch.cat([x_t, h], -1)
    z = W_z(xh).sigmoid()
    r = W_r(xh).sigmoid()
    m = r * h
    xm = torch.cat([x_t, m], -1)
    h_tilde = W_h(xm).tanh()
    keep = (1 - z) * h
    return keep + z * h_tilde
  1. 1Builds one weight matrix with its bias for each of \(W_{z}\), \(W_{r}\) and \(W_{h}\), each reading the stacked vector.
  2. 2Stacks input and memory and computes the two gates, the first card.
  3. 3Filters the memory, builds the candidate and blends: keep is the old memory times the keep share \(1 - z\), the second card.

The library call for the same step returns the output at every step plus the final hidden state hn, with no cell state to return.

6 When to use a GRU

The GRU's home is the RNN encoder-decoder for machine translation from Cho et al. 2014, encoding a source sentence and decoding a target sentence. Chung et al. 2014 used it for polyphonic music modelling, music with several notes sounding at once, and speech signal modelling. It also fits streaming sequence work where one memory and fewer weights matter.

GRUs typically achieve similar results to LSTMs with fewer parameters: no separate cell state, two gates instead of three. If you are not sure which to pick, start with a GRU.

The experiment behind this comparison, what was trained, on what data and what was measured, is set out on the intro page, section 4. On the speech tasks the gated units clearly beat tanh, the plain RNN cell, while on the music tasks the three were close, measured by the average negative log-probability of the next element, where a lower value means the model assigns higher probability to what actually comes next, with tanh best on the Nottingham test set and tanh tying LSTM on Piano-midi.

7 What breaks and what to watch

Dropout sits between stacked layers or shares one mask across steps, never a fresh mask inside the recurrence; the full teaching is on the intro, section 5.

Gradients can still explode, so clipping still applies (Clipping keeps the direction and caps the size in RNN Basics).

Picking an LSTM by default costs extra weights for no gain where Chung et al. found the two comparable, so the failure is overpaying in weights and state.

A reset gate shut at the wrong step strands the candidate with only the input, which the walkthrough shows; watch for a model that forgets its context mid-sentence.

What changes when the memory gets its own separate state with three guards? That is LSTM: Long Short-Term Memory.
