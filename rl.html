RL Basics

No answers, just a score. The agent figures out the rest.

Reinforcement learning trains an agent’s strategy for picking moves to collect as much total reward as it can. There are no labels and no examples of correct behavior, just a world, a few possible moves and a reward; the agent tries things, the world returns rewards, and the strategy slowly shifts toward the moves that earn them.

Whenever the right move is unknown but the score is clear, RL is the tool.

1 The reinforcement learning loop

Each turn the agent sees the state, what it senses right now. Its policy, the strategy being learned (often a neural network), picks an action. The world answers with a reward, the score for what just happened, and the next state, the world after the action lands. The goal is the most total reward over time.

2 The banana collector environment

Walk the loop with the banana collector, a Unity ML-Agents environment from my Value-based-methods repo. ML-Agents is the toolkit that connects a Unity game world to training code. Each step the Python side sends one of four moves; Unity steps the physics and sends back 37 numbers, the next state, plus a reward: +1 for a yellow banana, −1 for a blue one, 0 otherwise.

The actions are a list of four, not a continuous range: forward, back, left, right.

This snippet plays one episode, one game from reset until the world reports done, with a random policy that learns nothing. Each pass of the while loop is one turn, and env.step returns the next state and the reward.

import random
from unityagents import UnityEnvironment

env = UnityEnvironment(file_name="Banana.app")
brain = env.brain_names[0]
info = env.reset(train_mode=True)[brain]
state = info.vector_observations[0]   # 37 numbers
score = 0
while True:
    action = random.randrange(4)      # random policy
    info = env.step(action)[brain]
    state = info.vector_observations[0]
    reward = info.rewards[0]          # +1, -1 or 0
    score += reward
    if info.local_done[0]:
        break
print("score", score)
  1. 1Starts an episode by resetting the banana world and reading the first state, the 37 numbers in Figure 3.
  2. 2One turn of the loop in Figure 2, a random move and its reward.
  3. 3Ends the episode when the world reports done, then prints the score.

3 Why copying an expert is not enough

The obvious alternative is behavior cloning: train a network to copy an expert’s moves. It is stage 1 of RLHF (reinforcement learning from human feedback) in Aligning Language Models with RL. The clone only saw perfect play, so once it drifts where the expert never went, its mistakes compound. RL learns from its own failures.

When nobody knows the right moves, the agent has to learn by trial and error.

4 Why RL is hard

Three things make RL hard. First, credit assignment. The agent turns left at step 40, drifts forward, and eats the banana at step 57. The +1 lands at 57, but the decision that mattered was the turn at 40. The discount gives earlier steps a share of that reward, smaller for each step of delay. Sparse rewards, long stretches that pay nothing, make every credit trail longer.

The return counts each reward less the later it arrives.
Gt = rt+1 + γ rt+2 + γ2 rt+3 + …
Gt, the return from step t, adds every later reward r, each shrunk once more by the discount γ, a number between 0 and 1, per step of delay.
1 + γ + γ2 + … = 11 − γ
A reward of +1 at every step, forever, adds up to this sum (Sutton and Barto 2018). As a rule of thumb the agent looks about that many steps ahead, 10 at γ 0.9 and 100 at γ 0.99.

Second, exploration. You cannot learn what you never try, and trying costs blue bananas, so the agent explores most early on (Section 6).

Third, sample inefficiency. Learning from scratch takes many tries. My banana run played 1,600 episodes for a task with four moves (Value-based-methods repo).

5 Scoring each move with Q-values

Every step, the agent notes "in this kind of state, I tried forward, and it led to +1", and raises its score for forward a little.

That remembered score is a Q-value, Q for quality: one number per state-move pair, its guess of the return.

One learning step moves the played move's Q-value a little toward a target built from that step.
target = r + γ · max Q(s′, a′)
The target is the reward r just earned plus the highest Q-value in the next state, max Q(s′, a′) (primes mark the next state and move). The max assumes the agent plays its best move from the next state on. The discount γ from the return (Section 4) shrinks that future part for the delay.
Q(s, a) ← Q(s, a) + α · (target − Q(s, a))
The Q-value moves a share α, the learning rate, of the gap between the target and itself; the arrow means replace. With a small α one lucky step cannot overwrite the Q-value. This update runs once after every step.

A table needs one row per state, and 37 continuous numbers never repeat, so a network replaces the table.

6 Explore early, exploit late

The agent’s Q-values say forward has been the best move so far. Always stepping forward means never learning that right might be better; picking at random every turn means never using what it knows.

The standard fix is ε-greedy: with chance ε (epsilon, eps in code) play a random move, otherwise the move with the highest Q-value.

import random
import numpy as np

N_MOVES = 4
EPS_FLOOR, EPS_DECAY = 0.01, 0.998   # as in my run
eps = 1.0

def epsilon_greedy(q_values, eps):
    if random.random() < eps:
        return random.randrange(N_MOVES)   # explore
    return int(np.argmax(q_values))       # exploit

q_values = np.array([0.82, 0.10, -0.40, 0.05])
action = epsilon_greedy(q_values, eps)
eps = max(EPS_FLOOR, eps * EPS_DECAY)  # after each episode
  1. 1Sets ε to start at 1 and decay to a floor of 0.01, the curve in Figure 8.
  2. 2A random move with probability ε, else the move with the top Q-value.
  3. 3Picks one move from toy Q-values, then shrinks ε once per episode.

8 The trained banana agent

My agent is a Dueling Double DQN (Deep Q-networks in RL Method Families): dueling splits each score into how good the state is plus how much better each move is. It trains on batches drawn from replay memory, a store of past steps. For the Section 5 target, the learning network picks the next move and the target network, a slowly updated copy, scores it.

import torch
import torch.nn.functional as F

GAMMA, TAU = 0.99, 1e-3   # values in my agent.py

def learn(q_local, q_target, optimizer, batch):
    s, a, r, s_next, done = batch   # 64 replayed steps
    with torch.no_grad():
        a_star = q_local(s_next).argmax(1, keepdim=True)   # learning net picks
        best_next = q_target(s_next).gather(1, a_star)     # target net scores
        target = r + GAMMA * best_next * (1 - done)
    q_sa = q_local(s).gather(1, a)   # Q(s, a) of moves played
    loss = F.mse_loss(q_sa, target)
    optimizer.zero_grad()
    loss.backward()
    optimizer.step()
    for p, p_t in zip(q_local.parameters(), q_target.parameters()):
        p_t.data.copy_(TAU * p.data + (1 - TAU) * p_t.data)
  1. 1Double DQN target for 64 replayed steps, eq card in Section 5, line 1, with the best next move picked by the learning network.
  2. 2Compares Q(s, a) with the target, the gap in line 2.
  3. 3Takes one gradient step on that loss.
  4. 4Moves the target network a fraction τ toward the learning network.
Runsevery 4 moves, once the memory holds more than 64 steps
Carriesreplay memory, the target network, ε
Costone forward and backward pass on 64 states per update
γweights the next best score; lower favors sooner bananas, 0 sees one step, near 1 looks far ahead (Figure 5); 0.99
εchance of a random move; 1 never uses what it learned, 0 never explores; a decay nearer 1 explores longer, lower stops sooner; 1.0, ×0.998 per episode, floor 0.01
Batchsteps replayed per update; larger gives a less noisy gradient at more compute, 1 learns from single noisy steps; 64

Learning ratethe network’s α: higher learns faster but can diverge, 0 never learns; Adam 0.0005

The training code (env.py) stops early once the 100-episode average score reaches 17.0. The run never hit that bar, so all 1,600 episodes ran (the DQN page).

9 Reward hacking

The agent does not learn what you meant. It learns what you rewarded. Reward hacking is an agent raising its reward in a way the designer did not intend. An OpenAI agent playing the boat-racing game CoastRunners learned to circle a lagoon knocking over three respawning targets, kept catching fire, and still outscored human players by about 20 percent instead of finishing the race (Clark and Amodei 2016).

So before training, ask "what is the easiest way to score high without doing the task?"

Reward shaping, extra pay for getting closer, carries the same risk (an agent can approach and back away forever), and so do learned rewards, where it is called reward over-optimization in RLHF.

Watch what the agent actually does, then fix the reward, not the agent.

The same arena scored two ways, by bananas or by steps survived.
scorereal = yellows − blues
The real banana reward pays +1 per yellow banana eaten and −1 per blue.
scorealive = 0.10 × steps alive
Pays 0.10 for every step alive, the same whether the agent eats or not, so standing still in a corner scores as well as any banana hunt.

10 Three algorithms, one loop

Three agents built on this loop live in my Value-based-methods, RF-DDPG and TennisGym repos; each handles what the previous one could not.

From scoring a list of moves to outputting the move.
a = argmaxa Q(s, a)
DQN scores every move a in state s and plays the biggest. Four moves, fine; a continuous range of joint torques has no list to score.
a = μ(s)
In DDPG the actor μ outputs the move directly, a vector of joint torques, and a critic Q(s, a) grades the pair. No argmax over infinitely many moves.
ai = μ(oi)
In Tennis one shared actor drives both rackets from each racket i's own observations oi, i being A or B. This is self-play DDPG, one actor playing both sides, so the opponent improves every episode (Multi-Agent Reinforcement Learning, which also shows how MADDPG differs).

The DDPG page shows the actor and critic code.

RL Method Families sorts these agents and the other methods into families.
