t-SNE

Neighbors first.

What if your data is a Swiss roll? No flat shadow, no viewing angle, no rotation ever shows it unrolled. Every linear projection crushes it into mush. I hit this wall looking at real embeddings: PCA showed one big smear where I knew there were ten clean digit clusters. PCA asks: which 2D shadow loses the least? t-SNE asks a better question: which 2D arrangement keeps the right neighbors together? Same data, totally different question, and the answer became the most famous visualization in machine learning.

Neighbors first, coordinates later

t-SNE never projects anything. It does something sneakier. First, for every point in high dimensions, write down who its neighbors are, as probabilities: each point looks at every other point and assigns a neighbor probability that decays with distance. Second, scatter all the points onto a 2D canvas at random. Third, compute the same neighbor probabilities down in 2D, and shuffle the points around until the 2D probabilities match the high-D ones. The shuffling is plain gradient descent on a KL divergence, how far the map's neighbor list is from the true one. The neighbors are the contract; everything else is negotiable.

Two things make it work where older methods failed. First, every point gets its own neighborhood width, tuned so each point has about perplexity effective neighbors. Dense regions get tight kernels, sparse regions get wide ones. Second, the 2D side uses a heavy-tailed Student-t distribution instead of a Gaussian. That is the famous trick, and it fixes the crowding problem: in 2D there is not enough room to honor every medium-range distance honestly, so the t-distribution gives up on far distances gracefully and spends all its effort keeping neighbors together.

Picture every point grabbing the hands of its closest neighbors, then everyone shuffles around a dance floor until nobody is holding a stranger's hand. The t-distribution is the bouncer: it stops caring who stands far away and only breaks up the wrong hand-holds.

t-SNE in five steps: from neighbor probabilities to the 2D map

The setup: a toy Swiss roll, a sheet curled up in 3 dimensions. Drawn flat it looks like a plain sheet, but every probability below comes from the true 3D distances. Each point also gets a position on the 2D map, which is what we optimize.

1. High-D neighbor probabilities

Every point turns its distances into neighbor probabilities: near points get the biggest shares, far points almost nothing. This list is the contract the 2D map has to match.

2. Perplexity picks the neighborhood size

Perplexity sets roughly how many neighbors each point listens to. Crowded and lonely regions need different kernel widths to honor the same count, so every point tunes its own width: a point in a crowd gets a tight kernel, a lonely point a wide one.

3. The heavy tail in 2D

Down in 2D, a plain Gaussian would crush everything into the middle. The heavy-tailed Student-t lets far pairs stay vaguely far, which gives clusters room to separate: the map's probabilities use that heavy tail, not the Gaussian.

4. The cost: make the maps agree

The KL cost asks one question: do the 2D neighbor probabilities match the high-D ones? Breaking a true neighborhood costs far more than misplacing a distant stranger; both mistakes are what the cost counts.

5. The gradient: springs

Gradient descent moves each point like a spring system: true neighbors pull it in, overcrowded strangers push it away. When the springs balance, the map is done.

The five steps, written as five lines, from neighbor probabilities to the 2D map:

Σ means add over, and exp is e to the power of. The bar in pj|i, the | between j and i, reads given: the probability for j given i. The k≠i under the Σ uses ≠, not equal to: the sum runs over every k not equal to i.
σi ← set by perplexity
σi, point i's kernel width: the ← arrow reads gets set by, so σi gets set by perplexity, tuned per point so every point ends up with about the same number of effective neighbors: a point in a crowd gets a tight kernel, a lonely point a wide one.
qij = (1+d²ij)−1Σk≠l(1+d²kl)−1
qij is the map's version of the neighbor probability: one over one plus the squared map distance between i and j, the −1 power, divided by the total of the same quantity over all pairs: the Σ underneath runs over k≠l, k not equal to l, every pair of different points. Because that shape falls off slowly, the heavy Student-t tail, far pairs stay vaguely far and clusters get room to separate instead of crushing into the middle.
C = KL(P‖Q)
The cost: C is the KL divergence from the high-D neighbor list P to the map's list Q, one number for how far the map's neighbor list is from the true one. The ∥ between P and Q is the separator inside KL: KL(P∥Q) reads the divergence from P to Q. Breaking a true neighborhood costs far more than misplacing a distant stranger, and C is the number the steps push downhill.
∇C: pull true neighbors, push the crowded
The gradient ∇C is the direction each point moves, and it works like springs: true neighbors pull a point in, overcrowded strangers push it away. When the springs balance, the map is done.

Each list above looks one way: pj|i is i's pull toward j, and j's own list gives a different number for the same pair. The KL cost compares one joint list, so the two directions are averaged into a single joint probability for the pair: pij is pj|i plus pi|j, divided by 2N for the N points. That averaged list is the P the cost checks the map against.

What this shows

  • The contract: each point lists its neighbors as probabilities, and the map is good when its neighbor lists match the high-D ones. Nothing else about the map has to be right.
  • Step 1 links: each orange dot's strongest neighbor ties. A thicker link means a stronger tie; width is the whole message, there are no numbers.
  • Step 2 rings: each dashed ring is one point's kernel width at the same perplexity. The orange dot sits in a dense crowd and gets a tight ring; the teal dot sits in a sparse stretch and gets a wide one.
  • Step 3 inset: the gray curve is the Gaussian tail, the red curve the heavy Student-t tail. The horizontal axis is distance and the vertical is similarity weight. The heavy tail lets clusters separate instead of piling up in the middle.
  • Step 4 highlights: red links are true neighbors the map tore apart, purple links are strangers it crowded together. The cost punishes the red kind most.
  • Point color from step 3 on: color runs along the roll, so neighbors share a color. Color staying together means the map kept the right neighbors.
  • The springs: gradient descent pulls true neighbors together and pushes the overcrowded apart until every spring balances. That is all step 5 does.

t-SNE finds clusters it was never told about

One honest note first: the source notebook for this page is an empty shell. One empty code cell, no outputs. So this tool does not replay notebook output. It runs the canonical t-SNE example live, in your browser: 300 points in 24 dimensions, grouped into 4 clusters, each hiding 3 sub-clusters. Think of each point as one digit image: 24 numbers here, 784 in MNIST.

The tool computes real t-SNE: for each point it searches for the kernel width (how far that point's similarity reaches) that hits the perplexity, averages the two directions' probabilities into joint probabilities, then runs momentum gradient descent on the KL cost from a random start. No libraries, all vanilla JS. Nothing moves at rest. t-SNE never sees the labels, only pixel similarity. The dots crawl from noise into clusters driven by those probabilities alone.

What the t-SNE map does not tell you

t-SNE maps are gorgeous and liars in equal measure. Five things I wish someone had told me before I trusted my first one.

  • Cluster sizes and gaps mean almost nothing. Change the perplexity or the random seed and they move around. I have seen people measure distances between t-SNE clusters. Do not be those people.
  • Never cluster on t-SNE output. It is a visualization, not a fact. Run k-means on the original features, then color the t-SNE map by the labels. That order matters.
  • This toy has 300 points, and the pairwise math means twice the points is four times the work. The paper's MNIST figure in 6,000 MNIST digits, laid out by t-SNE used 6,000 digits with a random-walk approximation; naive t-SNE on all 70,000 MNIST digits would melt your laptop. Barnes-Hut, the standard fast approximation for pairwise methods like this, exists for exactly this reason.
  • Run it twice, get two maps. The random start means the details are never identical. If your conclusion does not survive a re-run, it was never a conclusion.
  • UMAP (Uniform Manifold Approximation and Projection) is the modern default for big data. Same spirit (neighborhoods first), different math, much faster. t-SNE is still the one everyone recognizes.

t-SNE preserves neighborhoods, not distances

The pattern to keep: whenever a method promises a 2D map of high-D data, ask what it preserves and what it sacrifices. PCA preserves variance and sacrifices nothing it can measure linearly. t-SNE preserves neighborhoods and sacrifices global distances. Nothing preserves everything: a 24-dimensional cloud does not fit on a dance floor without somebody stepping on somebody's toes.
