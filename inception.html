1 Big picture

The same object can fill a corner of a photo or all of it, so the right kernel size for a layer is unknown. Making a network uniformly wider is costly: widen two chained conv layers together and their compute grows with the square of the width. Szegedy et al. ran several kernel sizes in parallel inside each module and concatenated the results, at a constant computational budget [1].

Their network, GoogLeNet, has 22 layers with parameters and nine Inception modules, and won ILSVRC 2014; it was built at the same time as VGG. It is a plain forward stack, with two auxiliary heads used only during training. Full Inception networks are mostly historical; the reusable idea is the 1×1 reduce layer, which returns in ResNet bottlenecks and MobileNet.

2 1×1 convolutions

A 5×5 branch run on many channels makes each module's cost explode. The fix comes from Network in Network [2]: a 1×1 convolution looks at one pixel, so it cannot find shapes; it only mixes the channels at that pixel. It is a small fully connected layer applied at every position.

What a 1×1 convolution computes, and why it makes the next layer cheaper.
\(\displaystyle {\begin{aligned}\htmlClass{eqt sym-hat}{\htmlStyle{color:var(--sym-hat)}{y_{o}}} &= \sum_{c=1}^{\htmlClass{eqt sym-mean}{\htmlStyle{color:var(--sym-mean)}{C_{\text{in}}}}} \htmlClass{eqt sym-w}{\htmlStyle{color:var(--sym-w)}{W_{o,c}}}\, x_c \\ &\quad + \htmlClass{eqt sym-bias}{\htmlStyle{color:var(--sym-bias)}{b_o}}\end{aligned}}\)
At one pixel (the pixel index is left off), each output channel \(o\) is a weighted sum of the input channels \(c\) at that same pixel; \(W_{o,c}\) is how much channel \(c\) counts toward output \(o\), and \(b_o\) is its bias. Nothing from neighbouring pixels enters.
\(\displaystyle {\text{cost}_{k\times k} \propto \htmlClass{eqt sym-slice}{\htmlStyle{color:var(--sym-slice)}{k}}^2\, \htmlClass{eqt sym-mean}{\htmlStyle{color:var(--sym-mean)}{C_{\text{in}}}}\, \htmlClass{eqt sym-var}{\htmlStyle{color:var(--sym-var)}{C_{\text{out}}}}}\)
A \(k \times k\) layer's cost grows with its input channels \(C_{\text{in}}\), so a 1×1 layer that shrinks \(C_{\text{in}}\) first makes the expensive layer cheaper.
The first line is the shrink; the second says why it pays: the big kernel now runs on fewer channels.

3 The Inception module with reduce layers

The module puts a 1×1 reduce layer in front of the 3×3 and the 5×5, and a 1×1 projection after the pool, so every expensive kernel runs on fewer channels. In the paper's Table 1 these are the "#3×3 reduce" and "#5×5 reduce" columns, the channel counts of the shrinking layers [1].

The reduce layer shrinks \(C_{\text{in}}\) for the 3×3 and 5×5 that follow.

5 Shrink channels before the big kernel

A 1×1 layer that shrinks channels first makes the 5×5 branch far cheaper, while the module's output shape stays the same.

6 GoogLeNet as a whole

GoogLeNet is a short stem of ordinary convolutions, then nine modules (3a and 3b, 4a to 4e, 5a and 5b) with max pools between groups. Before the classifier it averages each final map to one number instead of using large fully connected layers, an idea from Network in Network; dropout stayed essential [1]. Compare VGG's fully connected head, which holds most of its weights.

Two auxiliary classifiers sit on modules 4a and 4d during training; their losses are added with weight 0.3, and both are discarded at inference. The ILSVRC 2014 entry used about 12 times fewer parameters than AlexNet [1].

7 Batch normalization in later Inceptions

The BatchNorm paper's network was an Inception with a normalization step after each convolution; with BN, a five times higher learning rate and a few related changes (the paper's BN-x5), it trained far faster [3]. Batch Normalization teaches the mechanism and shows the paper's curves.

9 In practice

torchvision.models.googlenet builds each module as Inception(in_channels, ch1x1, ch3x3red, ch3x3, ch5x5red, ch5x5, pool_proj): the 1×1 branch width; the reduce width and output width of the 3×3 branch; the same two for the 5×5 branch; and the pool projection width. It adds BatchNorm after every convolution, which the 2014 network did not have [4].

class InceptionBlock(nn.Module):
    def __init__(self, c_in, c1, c3r, c3, c5r, c5, cp):
        super().__init__()
        self.b1 = nn.Conv2d(c_in, c1, 1)
        self.b3 = nn.Sequential(nn.Conv2d(c_in, c3r, 1), nn.ReLU(), nn.Conv2d(c3r, c3, 3, padding=1))
        self.b5 = nn.Sequential(nn.Conv2d(c_in, c5r, 1), nn.ReLU(), nn.Conv2d(c5r, c5, 5, padding=2))
        self.bp = nn.Sequential(nn.MaxPool2d(3, stride=1, padding=1), nn.Conv2d(c_in, cp, 1))
    def forward(self, x):                   # x: (N, c_in, H, W)
        outs = [self.b1(x), self.b3(x), self.b5(x), self.bp(x)]
        return torch.relu(torch.cat(outs, dim=1))  # (N, c1 + c3 + c5 + cp, H, W)

block_3a = InceptionBlock(192, 64, 96, 128, 16, 32, 32)  # module 3a's widths
y = block_3a(torch.randn(1, 192, 28, 28))  # (1, 256, 28, 28)

def n_params(m): return sum(p.numel() for p in m.parameters())
reduced = n_params(nn.Sequential(nn.Conv2d(192, 16, 1), nn.Conv2d(16, 32, 5)))
unreduced = n_params(nn.Conv2d(192, 32, 5))
assert reduced < unreduced                # the reduce layer makes the 5x5 branch smaller

GoogLeNet trained 22 layers with helper heads. Why did plain networks deeper than about 20 layers get worse even on their training data? ResNet answers it.
