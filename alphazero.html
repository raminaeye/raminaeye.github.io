In Go and chess the rules are known, so the agent can look ahead before each move instead of guessing. A network gives two quick judgements of a position: which moves look promising and what result to expect. A tree search uses those judgements to explore many continuations and counts how often it visited each move. Those visit counts are a better policy than the network's guess; the agent plays them against itself. The network is trained to predict the search's choices and the game's result, so next time it guides the search better.

1 One quick guess per move misses wins a few moves deep

A program that maps a chess position straight to a move misses a win or a trap that only shows a few moves later.

The running example is chess. In this late position only a few pieces are left, so one good move can decide the game.

The agent is the learner that picks the moves. (RL Basics) A state is the agent’s situation right now; a move, or action, is one choice the agent can make in a state; a reward is the number the world hands back after each move, good or bad. (RL Basics) Here the agent is a program that plays one side, and the state is the position on the board. Every move turns that position into a new one, so the possible moves branch like a tree.

Two players, called White and Black, take turns, and on each turn the player to move must make exactly one legal move, a move the rules allow. A simple chess program rates the position after each legal move and plays the move whose position rates best.

A policy is the agent’s rule for choosing a move in each state; it may always pick the same move or pick by chance. (RL Basics) So the quick guesser of the problem above picks its move from the position alone and never looks further.

Here a model is anything that tells the agent what a move leads to; for chess that is the rules themselves. A model can be given, like the exact rules of a board game, or learned from the agent’s own steps. (Model-Based RL) Chess’s model is given in full, so the agent can try moves on it exactly.

Looking ahead, or search, means trying several moves in the model, then their replies, before choosing one for real. (Model-Based RL) Chess players look ahead, and with the rules known the agent can too, but there are far too many possible continuations to try them all.

AlphaZero brings this look ahead to chess, to shogi, which is Japanese chess, and to the board game Go. The same method, with only the rules swapped, learns each game separately, starting from random play.

Dyna-Q’s model made training data but never looked ahead at decision time. (Dyna-Q)

2 A network that steers the look-ahead

In chess no reward arrives until the game ends in a win, a draw or a loss. A single chess game can last many moves on each side.

The return is all the reward still to come, with later rewards counted a little less. (RL Basics) Counting later rewards a little less is called a discount. A state’s value \(V(s)\) is the return the agent expects from state \(s\). (RL Basics) So in Go and chess a position’s value is the result the player to move can expect from here. AlphaZero counts the result in full, with no discount, however many moves away it is, so the network must judge positions long before any reward arrives.

A tree search tries moves from the current position, then the replies to them; the current position is the root, and the newest position at the end of a path is a leaf. From any position the tree fans out fast, because every reply opens new branches.

Each node of the tree is a position and each edge is a move. Most paths from the root are never tried, because the tree is far too big.

A head is one output branch of the network. One network gives two quick judgements of a position: the policy head gives a chance for each legal move, and the value head estimates the game result the player to move can expect from here, anywhere from a loss through a draw to a win. The policy head says which branches to try first; the value head rates a position without playing the game out.

2.1 Self-play

In self-play the same network plays both sides, so its opponent improves exactly as fast as it does. Every finished game gives a result to learn from.

An episode is one run from the start until it ends. (RL Basics) Here an episode is one game. The game result \(z\) is a win, a draw or a loss, seen from the player whose turn it is. Every position of a finished game is later labelled with that result.

Equation 1. The game result. A loss counts -1, a draw 0 and a win +1, always seen from the player to move.
\(\displaystyle \htmlStyle{color:var(--sym-reward)}{z} \in \{-1,\ 0,\ +1\}\)
A finished game. A loss counts \(-1\), a draw \(0\) and a win \(+1\), always seen from the player to move. This builds on the reward and value sentences above.

3 How the search picks and scores moves

Monte Carlo tree search runs many simulations, each one pass from the root down to a new leaf and back up, and counts which moves they went through. The more simulations the search runs, the deeper and wider the part of the tree it explores.

Monte Carlo means deciding by random trials. The name Monte Carlo tree search (MCTS) comes from older searches that played random games to the end. AlphaZero never plays a game out and trusts the value head’s guess instead.

A simulator is a program that applies the rules exactly, so a search can step through positions without playing them for real. For chess it is a move generator that knows every rule. The search calls it at every step down the tree, so every position the search reaches is exact.

Equation 2. The network. One look gives two judgements: which moves look good and what result to expect.
\(\displaystyle (\htmlStyle{color:var(--sym-policy)}{\mathbf{p}}, \htmlStyle{color:var(--sym-statevalue)}{v}) = \htmlStyle{color:var(--sym-model)}{f_\theta}(\htmlStyle{color:var(--sym-state)}{s})\)
The network looks at a chess position once. One look gives two judgements: which moves look good and what result to expect. \(f_\theta\) the network with weights \(\theta\), and \(s\) the board position, the state; one pass gives both outputs at once. \(\mathbf p\) the policy head, a chance for each legal move; \(v\) the value head, the result the player to move can expect from here, between \(-1\) for a loss and \(+1\) for a win, with draws in between, as the game-result card in Self-play sets it; the head’s last step, a tanh, keeps \(v\) in that range. This builds on the value of a state, learned here and seen from the side to move (RL Basics), the game-result card in Self-play, and a softmax policy (Softmax, Temperature and Decoding).

The prior \(P(s,a)\) is the network’s first guess of how good each move is, before any search. The visit count \(N(s,a)\) is how many simulations went through move \(a\) in position \(s\). Both are stored on every move in the tree.

The search must balance trying rarely tried moves against repeating the ones that look best. (RL Basics) A move that looks weak after a few visits can still be the best one.

The search settles that balance with a rule called PUCT (predictor plus upper confidence bounds, a bonus for moves tried less often, applied to trees). PUCT steers each simulation toward moves that have looked good so far, plus a bonus for moves the prior likes that the search has rarely tried. So a move the prior likes gets tried early, even before it has looked good.

A move’s value \(Q(s,a)\), also called its score, is the return the agent expects if it makes move \(a\) in state \(s\) and plays on from there. (RL Basics) The search keeps Q on every move in the tree, beside the prior and the visit count.

\(\arg\max\) picks the move whose score is largest. (RL Basics) Each simulation picks, at every position on its way down, the move with the best score plus bonus.

Equation 3. The selection rule. Each simulation picks the move with the best score plus a bonus for moves rarely tried.
\(\displaystyle \begin{aligned} \htmlStyle{color:var(--sym-qvalue)}{U}(\htmlStyle{color:var(--sym-state)}{s}, \htmlStyle{color:var(--sym-action)}{a}) &= \htmlStyle{color:var(--sym-eta)}{c_{\text{puct}}}\, \htmlStyle{color:var(--sym-prior)}{P}(\htmlStyle{color:var(--sym-state)}{s}, \htmlStyle{color:var(--sym-action)}{a}) \\ &\quad \times \frac{\sqrt{\sum_b \htmlStyle{color:var(--sym-visits)}{N}(\htmlStyle{color:var(--sym-state)}{s}, \htmlStyle{color:var(--sym-action)}{b})}}{1 + \htmlStyle{color:var(--sym-visits)}{N}(\htmlStyle{color:var(--sym-state)}{s}, \htmlStyle{color:var(--sym-action)}{a})} \end{aligned}\)
At the root of the chess tree the search must pick which move to explore next on this simulation. A bonus for moves the network likes that the search has not tried much yet. \(P(s,a)\) the prior, the policy head’s chance for move \(a\); \(N(s,a)\) how many simulations went through this move (the visit count); the sum over \(b\) all visits at this position; the bottom of the fraction grows as this move gets visited, so its bonus shrinks. The square root on top grows with every visit to any move, so a move that is rarely tried gets a bigger bonus the longer the search runs; together the two halves keep the search trying other moves; \(c_{\text{puct}}\) the weight of the bonus.
\(\displaystyle \htmlStyle{color:var(--sym-action)}{a^{*}} = \arg\max_{\htmlStyle{color:var(--sym-action)}{a}} \big[\, \htmlStyle{color:var(--sym-qvalue)}{Q}(\htmlStyle{color:var(--sym-state)}{s}, \htmlStyle{color:var(--sym-action)}{a}) + \htmlStyle{color:var(--sym-qvalue)}{U}(\htmlStyle{color:var(--sym-state)}{s}, \htmlStyle{color:var(--sym-action)}{a}) \,\big]\)
Go where the moves have looked good so far, plus the bonus. \(Q(s,a)\) the average value found below this move so far, the same idea as a Q-value, measured inside the tree; a move no simulation has tried yet scores \(0\) for \(Q\), so at first only its bonus decides whether it is tried; \(a^{*}\) the move followed on this simulation. This builds on the network card above, where the prior comes from the policy head, and exploration versus exploitation (RL Basics).

The code adds one inside the square root so the first visit follows the prior.

Rosin (2011) first added a predicted chance for each move to UCT (upper confidence bounds applied to trees), an older tree-search rule; the form on this card is the variant DeepMind used in its earlier Go programs, AlphaGo and AlphaGo Zero, with the network’s move chances as the prior.

Each simulation ends its way down at a position not yet in the tree. Expanding adds the new leaf to the tree and asks the network about it. The backup carries a new leaf’s value back up the path, flipping its sign at each level because the players take turns. The value climbs the path one edge at a time, leaf to root.

Equation 4. The backup. The value climbs back to the root, flipping at each level.
\(\displaystyle \htmlStyle{color:var(--sym-statevalue)}{v} \leftarrow -\htmlStyle{color:var(--sym-statevalue)}{v}\)
The simulation reached a new position; the network valued it from the side of the player to move there; that value is carried back up the path, one edge at a time from the leaf upward. Before an edge is credited, the value is turned into the view of the player who chose that move, which is the other player: a position good for one side is bad for the other. \(v\) the leaf’s value from the network card at the start; it flips once per level as it climbs. With the game-result card’s results, flipping the sign turns \(+1\) for one player into \(-1\) for the other, and a draw stays \(0\).
\(\displaystyle \htmlStyle{color:var(--sym-visits)}{N}(\htmlStyle{color:var(--sym-state)}{s}, \htmlStyle{color:var(--sym-action)}{a}) \leftarrow \htmlStyle{color:var(--sym-visits)}{N}(\htmlStyle{color:var(--sym-state)}{s}, \htmlStyle{color:var(--sym-action)}{a}) + 1\)
The move on the path counts one more visit.
\(\displaystyle \htmlStyle{color:var(--sym-qvalue)}{Q}(\htmlStyle{color:var(--sym-state)}{s}, \htmlStyle{color:var(--sym-action)}{a}) \leftarrow \htmlStyle{color:var(--sym-qvalue)}{Q}(\htmlStyle{color:var(--sym-state)}{s}, \htmlStyle{color:var(--sym-action)}{a}) + \frac{\htmlStyle{color:var(--sym-statevalue)}{v} - \htmlStyle{color:var(--sym-qvalue)}{Q}(\htmlStyle{color:var(--sym-state)}{s}, \htmlStyle{color:var(--sym-action)}{a})}{\htmlStyle{color:var(--sym-visits)}{N}(\htmlStyle{color:var(--sym-state)}{s}, \htmlStyle{color:var(--sym-action)}{a})}\)
The move’s running average moves toward the new value; dividing by \(N\) makes \(Q\) the plain average of every value seen below. This builds on the network card and the selection card above, and the “nudge toward” form of the Q-learning update (Q-Learning), here with a step that shrinks as visits grow. Lines 1 to 3 repeat for every edge on the path, leaf to root.

The search policy is each move’s share of the root’s visits, a better policy than the network’s first guess. The root’s visits then decide the move.

Equation 5. The search policy. Moves the search kept returning to are the ones it trusts.
\(\displaystyle \htmlStyle{color:var(--sym-policy)}{\pi_{\text{search}}}(\htmlStyle{color:var(--sym-action)}{a} \mid \htmlStyle{color:var(--sym-state)}{s}) = \frac{\htmlStyle{color:var(--sym-visits)}{N}(\htmlStyle{color:var(--sym-state)}{s}, \htmlStyle{color:var(--sym-action)}{a})}{\sum_b \htmlStyle{color:var(--sym-visits)}{N}(\htmlStyle{color:var(--sym-state)}{s}, \htmlStyle{color:var(--sym-action)}{b})}\)
After all simulations, the root’s visit counts decide the move. Moves the search kept returning to are the ones it trusts; their share of visits is the improved policy. \(\pi_{\text{search}}\) the search policy (as a vector \(\boldsymbol\pi_{\text{search}}\) in the training-loss card; the paper writes \(\pi\); the subscript keeps it apart from a network policy \(\pi_\theta\)); the fraction is each move’s share of the root’s visits. This builds on the backup card above, where the counts come from.

During self-play moves are drawn in proportion to these shares; in a match the most visited move is played.

The network then learns from finished games, its value head from the result and its policy head from the search’s visit shares. Cross-entropy is a loss that is lower when the predicted chances put weight where the search’s chances put weight. (Cross-Entropy Loss) A small extra term pulls every weight toward zero, so no weight grows without need.

Equation 6. The training loss. Teach the value head to predict the game’s result and the policy head to predict what the search chose.
\(\displaystyle \begin{aligned} \ell &= (\htmlStyle{color:var(--sym-reward)}{z} - \htmlStyle{color:var(--sym-statevalue)}{v})^2 \\ &\quad - \htmlStyle{color:var(--sym-policy)}{\boldsymbol{\pi}_{\text{search}}}^{\top} \log \htmlStyle{color:var(--sym-policy)}{\mathbf{p}} \\ &\quad + \htmlStyle{color:var(--sym-discount)}{c_{\text{L2}}}\, \lVert \htmlStyle{color:var(--sym-model)}{\theta} \rVert^2 \end{aligned}\)
A self-play game ended in a win for White; every position in it is labelled with that result (a win when White is to move, a loss when Black is, as the game-result card sets it) and with the search’s visit shares. Teach the value head to predict the game’s result and the policy head to predict what the search chose, with a small pull of every weight toward zero. The first row takes \(z\), the game result from the player to move, as the game-result card in Self-play sets it, so \((z - v)\) squared is the value error. The second row is the cross-entropy between the search policy and the policy head (Cross-Entropy Loss), and the \(\top\) turns the column of shares into a row, so the product adds up share times log chance over every move. The third row is the L2 penalty, \(c_{\text{L2}}\) times the squared weights, a small pull of every weight toward zero (weight decay; Optimizers in Practice); the paper writes this weight as \(c\). This builds on the network card, the search-policy card, self-play and the game-result card in Self-play.

5 AlphaZero in PyTorch

A two-head network, one PUCT choice, the backup and the loss; the move generator is left out.

5.1 A two-head network

import numpy as np
import torch
from torch import nn

# Shapes: x is [B, input], logits and log_p are [B, n_moves],
# v_pred is [B, 1], z is [B] and pi_t is [B, n_moves].
class Net(nn.Module):
    def __init__(self, in_dim, n_moves, h=256, c_l2=...):
        super().__init__()
        self.trunk = nn.Sequential(nn.Linear(in_dim, h), nn.ReLU())
        self.policy = nn.Linear(h, n_moves)
        self.value = nn.Sequential(nn.Linear(h, 1), nn.Tanh())

    def forward(self, x):
        h = self.trunk(x)
        return self.policy(h), self.value(h)

net = Net(in_dim=119 * 64, n_moves=4672)
logits, v_pred = net(x)
log_p = torch.log_softmax(logits, -1)

eta = 0.2  # the learning rate, 0.2 at the start of training
  1. The network card; the tanh keeps the value in the range of the game-result card. c_l2 =... has no value here; the preprint does not restate it, so the code does not invent one.
  2. The preprint's chess input is 119 planes of 8 by 8, so the code flattens those planes into one vector and in_dim is 119 times 64: eight past positions, each with 6 planes for the player's pieces, 6 for the opponent's and 2 for repetitions, plus 7 constant planes for colour, move count, castling and no-progress count. The policy is an 8 by 8 by 73 stack, so n_moves is 4672: 73 move kinds from each square, 56 queen moves, 8 knight moves and 9 underpromotions.

5.2 One PUCT choice

# s is the current position, legal is its list of legal moves, and
# visits and scores are dictionaries keyed by (s, a). P is the
# prior, the policy head's chance for each move.
def select(s, legal, P, visits, scores, c_puct):
    N = np.zeros(n_moves)
    Q = np.zeros(n_moves)
    for a in legal:
        N[a] = visits.get((s, a), 0)
        Q[a] = scores.get((s, a), 0.0)
    U = c_puct * P * np.sqrt(N.sum() + 1) / (1 + N)
    a = (Q + U).argmax()
    return legal[int(a)]
  1. Lines 1 and 2 of the selection card; the + 1 lets the first visit at a fresh node follow the prior. N and Q start at zero for every move, so a move no simulation has tried yet scores 0 for Q.

# pi = the visit shares at the root; pi_t = the search policy

6 Search finds the winning move the network missed

In chess you win by checkmate, which means attacking the opposing king so that it has no safe square left.

White has two pieces left and Black has only one.

A rook slides any distance along its row or its column and attacks every square on them. A king steps one square in any direction and may never step onto a square the other side attacks.

Together they can trap a king against the edge of the board.

White’s rook and king stand on the bottom row, and Black’s king is near the bottom left corner; White moves first.

A check attacks the king at once, so it looks strong at a glance, and a network that judges at a glance likes it best.

7 AlphaZero in practice

In every self-play game, each move runs one search. Replay keeps a memory of past steps, and training draws random batches from it. (DQN) Here the replay memory, or buffer, holds positions from recent games. The network trains on them continually, and the newest network always plays.

AlphaGo Zero only let a new network play once it had beaten the old one; AlphaZero drops that test. It carries one network and the game buffer; the rules are given.

For each game it stores every position with the search policy and the final result. During self-play it adds Dirichlet noise at the root, a little random push to the prior there, so self-play tries moves the network would skip. During self-play it also draws moves in proportion to their visit shares to keep games varied, and in matches it plays the most visited move.

More simulations per move give stronger moves at more computing per move. A higher \(c_{\text{puct}}\) leans more on the network’s move chances and spreads visits over more moves; a lower one sticks with the moves the search so far rates best.

The learning rate \(\eta\) sets how big a step each update takes. (RL Basics) The preprint drops the learning rate in steps as training goes on.

The games ran on Google’s tensor processing units (TPUs), chips built for neural-network math. Self-play and training ran on separate sets of these chips.

7.1 Matches against the strongest chess, shogi and Go programs

AlphaZero lost no chess game to Stockfish, lost a few shogi games to Elmo, and beat AlphaGo Zero in most Go games; during training it passed Stockfish, Elmo and AlphaGo Lee within hours.

It searched far fewer positions each second than Stockfish and Elmo, and chose them better.

8 Games with known rules

AlphaZero fits two-player games, and any task with a perfect, cheap simulator and a short list of moves.

It does not fit when the rules are unknown, or when actions are amounts such as a joint’s turning force. (Continuous Actions)

Dyna-Q spends its computing between the moves it really makes, to learn from fewer of them; AlphaZero spends it at every decision to choose a better move. (Dyna-Q)
