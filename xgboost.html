XGBoost and LightGBM

XGBoost gives each boosting round a curvature-aware leaf score and a price on tree size; LightGBM keeps those scores and finds splits much faster.

1 What XGBoost and LightGBM add

Plain gradient boosting steps along the slope of the loss with one learning rate. It ignores how curved the loss is, puts no price on tree size beyond depth limits, sorts every feature for every split, and needs missing values filled in first. XGBoost (Chen and Guestrin, 2016) fixes the first two and speeds up the search; LightGBM (Ke et al., 2017) keeps the same leaf scores and changes only how splits are found, so it lives in this page’s fast-split section.

The rounds run in sequence as in gradient boosting. Before training, each feature is bucketed into bins once (XGBoost’s hist method, LightGBM’s Dataset). Each round makes one pass that computes every training window’s slope and curvature (or only the sampled windows’, under LightGBM’s sampling), sums them per bin at each node, takes the best split point (a bin edge, section 6.1), scores the leaves with a formula, and adds the tree with weight \(\nu\). The running prediction for every window and the bin edges carry over between rounds; early stopping checks a held-out metric every round; prediction sums all trees.

2 Curvature: a second-order step

Take two activity windows the model gets wrong by the same amount: one where the loss bends sharply, one where it is nearly flat. Plain boosting moves both the same way. The slope says which way to move a window’s prediction; the curvature says how far before the slope flips, so a sharply curved loss deserves a short step and a gently curved one a longer step. XGBoost fits each tree to a bowl-shaped approximation of the loss built from slope and curvature; the paper credits this second-order method to Friedman, Hastie and Tibshirani (2000).

XGBoost adds a price on every tree to the loss, then scores each new tree with a bowl per window built from the loss’s slope and curvature.
\(\displaystyle \begin{aligned} \mathcal{L} &= \sum_{i} l\!\left(\htmlClass{eqt sym-target}{\htmlStyle{color:var(--sym-target)}{y_i}}, \htmlStyle{color:#6c3483}{F(x_i)}\right) \\ &\quad + \sum_{m} \htmlStyle{color:#a04000}{\Omega}(\htmlStyle{color:#196f3d}{f_m}) \end{aligned}\)
\(F(x_i)\) is the model’s summed prediction for window \(i\) (the paper writes \(\hat{y}_i\)). The objective is the usual loss \(l\) plus a price \(\Omega\) on every tree \(f_m\); with the price at zero it is plain gradient tree boosting (Chen and Guestrin 2016, eq. 2 and section 2.1).
\(\displaystyle \htmlStyle{color:#a04000}{\Omega}(f) = \htmlStyle{color:#b9770e}{\gamma}\, \htmlStyle{color:#117a65}{J} + \tfrac{1}{2}\,\htmlClass{eqt sym-lambda}{\htmlStyle{color:var(--sym-lambda)}{\lambda}} \sum_{j=1}^{J} \htmlStyle{color:#196f3d}{w_j}^{2}\)
\(\gamma\) is charged once per leaf, for \(J\) leaves (the XGBoost paper writes this count \(T\)), and \(\lambda\) charges large leaf scores \(w_j\), the same L2 penalty used on network weights (Regularization). Raising \(\gamma\) gives fewer leaves; raising \(\lambda\) gives smaller leaf scores.
\(\displaystyle \htmlStyle{color:#c0392b}{g_i} = \left.\frac{\partial\, l(y_i, F)}{\partial F}\right|_{F = F_{m-1}(x_i)}\)
The slope of window \(i\)’s loss at the current prediction. Minus \(g_i\) is the residual of gradient boosting’s Each tree is a gradient descent step, line 2.
\(\displaystyle \htmlStyle{color:#7d6608}{h_i} = \left.\frac{\partial^{2} l(y_i, F)}{\partial F^{2}}\right|_{F = F_{m-1}(x_i)}\)
The curvature: how fast that slope changes as the prediction moves. A large \(h_i\) means a sharply bent loss.
\(\displaystyle \begin{aligned} \tilde{\mathcal{L}}^{(m)} &= \sum_{i} \bigg[\, \htmlStyle{color:#c0392b}{g_i}\, \htmlStyle{color:#196f3d}{f_m(x_i)} \\ &\qquad + \tfrac{1}{2}\, \htmlStyle{color:#7d6608}{h_i}\, \htmlStyle{color:#196f3d}{f_m(x_i)}^{2} \bigg] \\ &\quad + \htmlStyle{color:#a04000}{\Omega}(\htmlStyle{color:#196f3d}{f_m}) \end{aligned}\)
Round \(m\) scores a candidate tree with one bowl per window built from slope and curvature: a window with a large slope wants a big move, and a window with a large curvature resists one. The tilde marks an approximation: the loss after adding \(f_m\), expanded to slope and curvature, with the terms that do not depend on \(f_m\) dropped (paper eq. 3).
\(\displaystyle \begin{aligned} \htmlStyle{color:#c0392b}{g_i} &= p_i - \htmlClass{eqt sym-target}{\htmlStyle{color:var(--sym-target)}{y_i}} \\ p_i &= \sigma\!\left(\htmlStyle{color:#6c3483}{F_{m-1}(x_i)}\right) \end{aligned}\)
For log loss (The cross-entropy loss) the slope is the predicted probability minus the label, the negative of gradient boosting’s classification residual.
\(\displaystyle \htmlStyle{color:#7d6608}{h_i} = p_i\,(1 - p_i)\)
The curvature is largest when the model is unsure, with \(p_i\) near one half, and small when it is confident either way, so confident windows count little in a leaf’s curvature sum. This is the standard result for log loss.
So every window contributes a slope and a curvature, and each new tree is chosen to minimize the sum of their bowls plus the price on its leaves.

3 Leaf scores and split gain

Picture two leaves: one holding windows the model badly under-calls, one holding windows it already gets right. The first should get a large score, the second almost none. Summing the bowls of Section 2, line 5 over a leaf’s windows gives one bowl per leaf, and its bottom is the leaf’s score.

Each leaf’s score is the bottom of its windows’ summed bowls, and a split is worth the drop in loss it buys, minus the price of the extra leaf.
\(\displaystyle \htmlStyle{color:#196f3d}{w_j^{*}} = -\frac{\sum_{i \in I_j} \htmlStyle{color:#c0392b}{g_i}}{\sum_{i \in I_j} \htmlStyle{color:#7d6608}{h_i} + \htmlClass{eqt sym-lambda}{\htmlStyle{color:var(--sym-lambda)}{\lambda}}}\)
\(I_j\) is the set of windows in leaf \(j\). The leaf’s best score is its windows’ total push divided by their total curvature plus \(\lambda\), so \(\lambda\) shrinks every leaf and shrinks most the leaves with little curvature. With squared error every \(h_i\) is one and \(g_i\) is minus the residual, so this is the leaf’s mean residual, shrunk by \(\lambda\) (paper eq. 5).
\(\displaystyle \begin{aligned} &\text{Gain} = \tfrac{1}{2}\bigg[\frac{G_L^{2}}{H_L + \htmlClass{eqt sym-lambda}{\htmlStyle{color:var(--sym-lambda)}{\lambda}}} \\ &\quad + \frac{G_R^{2}}{H_R + \htmlClass{eqt sym-lambda}{\htmlStyle{color:var(--sym-lambda)}{\lambda}}} \\ &\quad - \frac{(G_L + G_R)^{2}}{H_L + H_R + \htmlClass{eqt sym-lambda}{\htmlStyle{color:var(--sym-lambda)}{\lambda}}}\bigg] \\ &\quad - \htmlStyle{color:#b9770e}{\gamma} \end{aligned}\)
\(G_L\) and \(H_L\) are the summed slopes and curvatures of the windows sent left, \(G_R\) and \(H_R\) of those sent right. A split is worth how much better the two children’s best scores fit than the parent’s, minus the leaf price \(\gamma\). It is the boosting version of the impurity gain in Impurity and information gain; the paper says its structure score is like the impurity score for evaluating decision trees (eq. 7).
So the tree is grown exactly like a decision tree, with this gain in place of impurity, and each leaf then takes the score of line 1.

Both formulas in NumPy, plus the slope and curvature of log loss.

import numpy as np

def leaf_weight(g, h, lam):
    return -g.sum() / (h.sum() + lam)

def split_gain(gL, hL, gR, hR, lam, gamma):
    def s(G, H):
        return G * G / (H + lam)
    G_L, H_L, G_R, H_R = gL.sum(), hL.sum(), gR.sum(), hR.sum()
    both = s(G_L, H_L) + s(G_R, H_R)
    return 0.5 * (both - s(G_L + G_R, H_L + H_R)) - gamma

def log_loss_grad_hess(p, y):
    return p - y, p * (1 - p)

5 Pricing leaves

The penalty \(\lambda\) is added to every leaf’s curvature sum, so leaves supported by little curvature (few windows, or windows the model is already sure about) are pulled hardest toward zero. The price \(\gamma\) removes a split when its gain in Section 3, line 2 is below zero, that is, when its fit improvement does not pay for the extra leaf; XGBoost removes such splits after the tree is grown. With both at zero, XGBoost is plain gradient boosting with second-order leaf scores.

Two more guards come from the paper’s section 2.3. Shrinkage scales each new tree by \(\nu\), as in Learning rate and number of rounds. Column subsampling borrows the random feature subsets of Random Forests; XGBoost’s users found it prevents overfitting even more than subsampling the windows.

6 Faster split finding

6.1 Histograms

Each feature is cut into bins once. A split scan then sums \(G\) and \(H\) per bin and tries only the bin edges, not every window. XGBoost proposes its bin edges by quantiles weighted by each window’s curvature, so unsure windows get finer bins (its weighted quantile sketch, paper section 3.3). scikit-learn’s histogram gradient boosting bins the same way (Boosting in practice).

Bins replace the walkthrough’s scan over every gap between sorted windows: the scan now tries only bin edges, with \(G\) and \(H\) summed once per bin.

6.2 Missing values

At every split XGBoost tries sending the windows with a missing value left, then right, and keeps the direction with the larger gain as that split’s default direction (sparsity-aware split finding, paper section 3.4, Algorithm 3). A smartphone window whose sensor dropped a reading goes down the learned default branch instead of being filled in.

6.3 LightGBM’s gradient-based sampling

Most windows are already fit well and carry tiny slopes. LightGBM’s GOSS (gradient-based one-side sampling; Ke et al. 2017, section 3) keeps every window with a large slope and samples the rest, then weights the sampled ones up so they stand in for the windows dropped.

Keep the windows that still matter, sample the ones that are already fit, and scale the sample up so the sums stay fair.
\(\displaystyle \tilde{G}_L = \sum_{i \in \htmlStyle{color:#1f618d}{A_L}} \htmlStyle{color:#c0392b}{g_i} + \frac{1 - \htmlStyle{color:#1f618d}{a}}{\htmlStyle{color:#ca6f1e}{b}} \sum_{i \in \htmlStyle{color:#ca6f1e}{S_L}} \htmlStyle{color:#c0392b}{g_i}\)
\(A\) is the set of kept large-slope windows, the top share \(a\) of all windows. \(S\) is a random sample from the rest, a share \(b\) of all windows (the paper writes this set \(B\)). \(A_L\) and \(S_L\) are their windows sent left. The sample is weighted up by \((1-a)/b\) so it stands in for the whole share that was set aside. The curvatures get the same weight, giving \(\tilde{H}_L\), and Section 3, line 2 uses these sums (Ke et al. 2017, Algorithm 2). Raising \(a\) or \(b\) keeps more windows: a more accurate gain and a slower round.
So GOSS spends its work on the windows with large slopes, where the gain is decided, and keeps the sums unbiased with one weight.

6.4 Bundling sparse features

LightGBM’s exclusive feature bundling (section 4) merges features that are rarely nonzero at the same time, such as one-hot columns, into one column with offset bins, so there are fewer features to scan.

6.5 Leaf-wise growth

LightGBM grows next the leaf whose best split has the largest gain, anywhere in the tree (LightGBM docs, Features: leaf-wise, best-first). On small data that can overfit, which max_depth limits. XGBoost’s default grows level by level (grow_policy="depthwise"), with "lossguide" as its leaf-wise option.

7 XGBoost and LightGBM in practice

XGBoost with early stopping on a validation set; learning_rate is \(\nu\) (XGBoost also calls it eta).

from xgboost import XGBClassifier
m = XGBClassifier(n_estimators=2000, learning_rate=0.1,
                  max_depth=6, reg_lambda=1.0, gamma=0.0,
                  colsample_bynode=0.5, tree_method="hist",
                  early_stopping_rounds=50)
m.fit(X_tr, y_tr, eval_set=[(X_val, y_val)])
best_rounds = m.best_iteration

  • Prefer permutation importance over the built-in split counts.

9 Trees versus margins

Every model in this series, from one decision tree to a LightGBM ensemble, cuts one feature at a time. What would a classifier look like that draws one boundary, placed as far as possible from both classes? That is Support Vector Machines (SVM).
