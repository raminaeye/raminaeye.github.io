The STFT and Spectrograms

A spectrum for every moment, and the trade-off between time and frequency detail.

Fourier Transform and the FFT turned a whole signal into one spectrum. Speech and music change from moment to moment, so this page takes one spectrum per short slice of time.

The short-time Fourier transform (STFT) cuts a signal into short overlapping frames, fades the edges of each frame, and takes the spectrum of each one. Its output is a spectrogram, a picture with time across, frequency up and brightness for strength. The one choice that matters most is the frame length, which trades sharp timing against sharp pitch.

One spectrum for the whole clip hides when things happen

A rising and a falling siren hold the same frequencies in opposite order, and one spectrum of the whole clip adds every moment together. Here a tone sweeps from 500 to 3,000 Hz in one second, then the same clip plays backward (fs = 8 kHz).

Same spectrum, opposite stories; only the spectrogram shows which way the pitch moved.

A spectrogram shows time left to right, frequency bottom to top, and loudness as colour. The short-time Fourier transform (STFT) computes it.

Frames, windows and the DFT

Cut the signal into short frames of L samples, each starting R samples (the hop) after the last. Fade each frame’s edges with a window w[n], take its DFT, and stand the result up as one column. The Frames, windows and the DFT walkthrough uses a tone that jumps from 500 Hz to 1,500 Hz.

One frame of the STFT.
xm[n] = x[n + mR] w[n]
Frame m starts mR samples in, R being the hop between frames, and the window w fades its edges so the cut adds no false clicks. A smaller hop gives more frames per second, and each frame keeps L samples.
X[m, k] = Σn=0L−1 xm[n] e−j2πkn/N
The DFT of that frame gives column m of the spectrogram, one spectrum per frame; side by side the columns show how the spectrum changes over time.

Frames usually overlap by a half or three quarters. The DFT size N can exceed L by padding with zeros, which adds bins but no detail.

Leakage and the Hann window

The DFT treats a frame as if it repeated forever. If a tone does not fit a whole number of cycles, the copies meet with a jump, and a jump contains every frequency, so the tone’s energy spills into far bins. This is leakage.

A window that fades to zero at both ends removes the jump; the Hann window is one raised cosine.

The Hann window of length L.
w[n] = 12 (1 − cos 2πnL)
Zero at the start, one in the middle and back towards zero at the end, so samples near the frame edges count less. That smooth fade keeps a tone's energy out of far bins, at the cost of a slightly wider peak.

The fade widens the main peak but pushes the side lobes far lower. The Leakage tool shows a tone between two bins with and without the window.

① Plain cut, highest side lobe 13 dB down; ② Hann, 32 dB down and falling 18 dB per octave (Harris 1978).

The time-frequency trade-off

A long frame tells close pitches apart but smears events across the frame; a short frame pins down when an event happens but blurs its frequency. Dennis Gabor showed in 1946 that no signal is sharp in both time and frequency at once.

How finely one frame resolves time and frequency.
time resolution ≈ Lfs
The frame's length in seconds. An event anywhere inside the frame lands in the same column, so a longer frame smears timing.
frequency resolution ≈ fsL
Bins sit fs/L apart, so a longer frame sees finer pitch, the same trade-off from the other side. Zero-padding adds bins but not sharpness, because the frame still holds only L real samples.

At fs = 8 kHz with a Hann window, two tones at 1,000 and 1,050 Hz merge at 8, 16 and 32 ms frames and only split from 64 ms up. The same long frames also blur two clicks into one, as the window length tool shows.

Going back with overlap-add

Denoising edits a spectrogram and then needs the sound back. Take the inverse DFT of every column, slide each frame back into place and add the overlaps. If the windows add up to a flat line, the original comes back exactly.

Hann windows half a window apart add up to a flat line, so nothing is lost.

The condition for overlap-add to give the signal back.
Σm w[n − mR] = constant
Overlap-add gives the signal back only when the shifted windows add up to a flat line, so every sample gets the same total weight. Hann at 50% overlap does, because where one window fades out the next fades in by the same amount.

Jont Allen and Lawrence Rabiner tied overlap-add and filter-bank resynthesis together in 1977.

Overlap-add in SciPy. check_COLA confirms that Hann at 50% overlap sums flat, then stft and istft go there and back and the last line prints True.

import numpy as np
from scipy import signal

FS, L, HOP = 16000, 400, 200
print(signal.check_COLA('hann', L, L - HOP))
x = np.random.default_rng(0).standard_normal(FS)
_, _, Z = signal.stft(x, fs=FS, nperseg=L, noverlap=L - HOP)
_, x_back = signal.istft(Z, fs=FS, nperseg=L, noverlap=L - HOP)
print(np.allclose(x, x_back[:len(x)]))

This is how Spectral Subtraction for Denoising rebuilds audio after cleaning the spectrogram.

In practice

Speech systems usually take 25 ms frames every 10 ms. At 16 kHz that is 400 samples with a hop of 160, and the DFT size is the next power of two, 512. Conformer starts from features on exactly such 10 ms frames, and CTC Loss lines labels up with them.

The speech settings in librosa, window L = 400 and hop R = 160. One second of samples goes in, and the complex STFT comes out with 257 bins by 101 frames.

import numpy as np
import librosa

SR, N_FFT, L, R = 16000, 512, 400, 160
x = np.random.default_rng(0).standard_normal(SR)
X = librosa.stft(x, n_fft=N_FFT, hop_length=R, win_length=L)
power = np.abs(X) ** 2
print(X.shape)                      # (257, 101)

librosa centres each frame on its time by padding the signal with zeros, so the first frames look quieter.

Gotchas

  • librosa pads the signal so each frame is centered on its hop position; set center=False to start frames there instead.
  • Inverting needs the same window, hop and length as the forward call.
