1 BPE merges the most frequent pair

A tokenizer needs a fixed list of pieces that can spell any text, with common words as one piece and rare words as a few. Byte Pair Encoding (BPE) builds that list from the bottom up: start from single characters, join the adjacent pair seen most often in a large training text, called the corpus, and repeat. What it keeps is the ranked list of those joins, the merge list.

The idea comes from a 1994 compression method by Gage that replaces the most frequent pair of bytes with an unused byte; Sennrich, Haddow and Birch (2016) used it to split rare words for translation (References 1, 2). BPE trains once, on the corpus, before the model is trained. Splitting text later replays the saved list and keeps no state between calls. The Tokenizers page shows when a tokenizer runs. The family map shows where BPE sits next to WordPiece, Unigram and SentencePiece.

2 Counting pairs and merging

GPT-4o’s tokenizer has one token for ␣is and one for ␣great (the pipeline figure in Tokenizers). Why those pieces? A space followed by those letters was so common in its training text that BPE joined them early.

Count every adjacent pair, merge the most frequent one, repeat.

\(\displaystyle \htmlClass{eqt sym-c}{\htmlStyle{color:#1f6aa5}{c(a,b)}} = \sum_{w} \htmlClass{eqt sym-f}{\htmlStyle{color:#1e8449}{f(w)}}\, n_w(a,b)\)
\(n_w(a,b)\) is how often symbol \(a\) sits right before symbol \(b\) inside word \(w\). Each word appears \(f(w)\) times in the corpus, so weighting by it and adding over all words gives the pair count \(c(a,b)\) without reading repeated words again.
\(\displaystyle \htmlClass{eqt sym-ab}{\htmlStyle{color:#a85a14}{(a^{*},b^{*})}} = \operatorname*{arg\,max}_{(a,b)}\; \htmlClass{eqt sym-c}{\htmlStyle{color:#1f6aa5}{c(a,b)}}\)
arg max returns the pair itself, not its count. The winner becomes one new symbol, every adjacent copy of it in the corpus is replaced, the merge goes to the end of the merge list, and the counts are taken again. On this page a tie goes to the pair counted first.
\(\displaystyle \htmlClass{eqt sym-v}{\htmlStyle{color:#7d3c98}{V}} = V_0 + M\)
Each merge adds one entry, so the vocabulary size \(V\) is the starting alphabet \(V_0\) plus the number of merges \(M\), plus any special tokens, reserved entries such as an end-of-text marker that never come from text. \(M\) is the one setting BPE has: more merges give longer pieces and fewer tokens per text.

The toy corpus below is a few short words, each ended with </w>, the end-of-word marker of the BPE paper. It lets a piece at the end of a word differ from the same letters inside one.

Code 1 is the card in Section 2 as code. It learns the toy corpus’s first merges; the first five are the steps of Figure 3.

from collections import Counter

def merge(symbols, pair):
    out, i = [], 0
    while i < len(symbols):
        if symbols[i:i + 2] == pair:
            out.append(symbols[i] + symbols[i + 1])
            i += 2
        else:
            out.append(symbols[i])
            i += 1
    return tuple(out)

def train_bpe(text, num_merges):
    word_freqs = Counter(text.split())
    words = {tuple(w) + ("</w>",): f for w, f in word_freqs.items()}
    merges = []
    for _ in range(num_merges):
        pairs = Counter()
        for symbols, f in words.items():
            for pair in zip(symbols, symbols[1:]):
                pairs[pair] += f
        best = max(pairs, key=pairs.get)
        merges.append(best)
        words = {merge(symbols, best): f for symbols, f in words.items()}
    return merges

text = "decode decode decode decode decode decode encode encode encoder encoder models models"
merges = train_bpe(text, 6)
print(merges)  # [('d', 'e'), ('o', 'de'), ('c', 'ode'), ('code', '</w>'), ('de', 'code</w>'), ('e', 'n')]
  1. 1merge replaces every adjacent copy of the pair with one symbol.
  2. 2Each distinct word once, with its frequency \(f(w)\) and the end marker.
  3. 3Line 1 of the card: every pair, weighted by its word’s frequency.
  4. 4Line 2: max takes the most frequent pair, the first counted on a tie, and the corpus is rewritten with it.
  5. 5The toy corpus. The printed list is Figure 1.

The BPE paper’s own toy, the words low, lower, newest and widest, has a three-way tie on its first step, so its printed merge order depends on how ties are broken; this page’s corpus has none in the steps it shows.

3 Splitting new text with the merge list

To split a word, start from its characters and replay the merges in the order they were learned, never counting again. A merge only fires where its pair is present, so the end marker matters: code at the end of a word becomes code</w>, but not inside decoder.

A character the corpus never had has no starting symbol, so character BPE still needs an unknown token, <unk>.

Code 2 splits two words that are not in the toy corpus with the merges from Code 1. The second has an x, a letter the corpus never had.

def encode(word, merges, alphabet):
    symbols = tuple(c if c in alphabet else "<unk>" for c in word) + ("</w>",)
    for pair in merges:
        symbols = merge(symbols, pair)
    return symbols

alphabet = set(text) - {" "}
print(encode("decoder", merges, alphabet))  # ('de', 'code', 'r', '</w>')
print(encode("codex", merges, alphabet))    # ('code', '<unk>', '</w>')
  1. 1A new word starts as single characters plus the end marker; an unseen character becomes <unk>.
  2. 2The merges are replayed in learned order.
  3. 3decoder is Figure 4; codex keeps code and loses the x.

4 Byte-level BPE starts from 256 bytes

GPT-2 (Radford et al., 2019) runs BPE on UTF-8 bytes instead of characters. A byte has only 256 values, so the starting alphabet is small and fixed, every string can be encoded, and no <unk> exists. GPT-2’s vocabulary holds the 256 bytes and one end-of-text token (References 3, 7). The cost: a rare character can be cut into byte pieces that are not text on their own, the hatched cells of the vocabulary-size tool in Tokenizers, and scripts other than English need more tokens for the same text. The Tokenizers page shows why other languages cost more tokens.

Before merging, a regular expression cuts the text into chunks of one kind, such as letters, digits or punctuation, and keeps a single space on the front of the next chunk. Merges never cross a chunk border. Without this, the GPT-2 paper reports, BPE learned many copies of one word with punctuation attached, such as dog., dog! and dog?.

OpenAI’s tiktoken encodings are byte-level BPE vocabularies of this kind; what current models use lists which model uses which.

5 BPE-dropout: a different split each time

Plain BPE gives a word the same split every time, so the model never sees the pieces a rare word is made of. BPE-dropout (Provilkov, Emelianenko and Voita, 2020) keeps the merge list but, while splitting a word during training, skips each possible merge with a probability \(p\). The model sees varied splits of the same word and becomes more robust to typos and rare words; after training, splitting goes back to plain BPE (Reference 4).

\(p = 0\) is plain BPE and \(p = 1\) leaves single characters; the paper usually trains with \(p = 0.1\). SentencePiece’s alpha setting is this \(p\) for a BPE model (Reference 5). The Unigram tokenizer gets the same effect a different way, by sampling whole splits by their probability.

6 The training text decides the pieces

The merges come only from pair counts, so they mirror whatever the corpus repeats. Train on code and BPE spends merges on indentation and keywords; train on prose and the same line of code stays in small pieces. The tool trains byte-level BPE on three short texts and splits one line of Python with each. The prose comes from Reference 9; the code and chat texts are illustrative.

7 BPE in practice

A trained byte-level BPE tokenizer is three things: the vocabulary (vocab.json, piece to id), the merge list (merges.txt, one pair per line, in learned order) and the chunking rule that runs before it. All three must match the model exactly. Training is cheap next to model training: each merge needs the pair counts, and real trainers update only the counts a merge changed instead of counting the corpus again. Encoding replays up to \(M\) merges per chunk, so real encoders cache common chunks.

Code 3 trains a byte-level BPE vocabulary with Hugging Face tokenizers on a plain text file (Reference 6).

from tokenizers import Tokenizer, models, pre_tokenizers, trainers, processors, decoders

tokenizer = Tokenizer(models.BPE())
tokenizer.pre_tokenizer = pre_tokenizers.ByteLevel(add_prefix_space=False)
trainer = trainers.BpeTrainer(
    vocab_size=25000,
    special_tokens=["<|endoftext|>"],
    initial_alphabet=pre_tokenizers.ByteLevel.alphabet(),
)
tokenizer.train(["wikitext-2.txt"], trainer=trainer)

tokenizer.post_processor = processors.ByteLevel(trim_offsets=False)
tokenizer.decoder = decoders.ByteLevel()
print(tokenizer.encode("    return tokens").tokens)
tokenizer.save("bpe.json")

  2. 2\(V\) is set directly; the trainer merges until it is reached. All 256 bytes start in the alphabet, so nothing is ever unknown.
  3. 3Counting and merging, the card in Section 2.
  4. 4Encoding replays the merges; the saved file holds the vocabulary, the merges and the chunking rule.

8 What goes wrong

  • Keep the tokenizer files with the model: a model only understands the ids of the tokenizer it was trained with.
  • Count tokens on real samples of your input before choosing \(V\) (how big the vocabulary should be).

BPE picks the most common pair, even when its two parts are just common on their own. How would you pick a pair that belongs together instead? WordPiece Tokenizer answers that.
