How can a Pong paddle learn which moves to make from nothing but the points it wins and loses?

  • The agent picks the moves. A state is its situation right now, a move (or action) is \(1\) choice it can make, and a reward is the number the world hands back after each move.
  • An episode is \(1\) run from the start until it ends. A policy is the agent’s rule for choosing a move in each state.
  • The return is all the reward still to come, later rewards counted a little less; the discount \(\gamma\) sets how much less.
  • A state’s value \(V(s)\) is the return the agent expects from state \(s\). A move’s value \(Q(s,a)\) is the return it expects after making move \(a\) in state \(s\).

1 A Pong paddle that learns from points

In Atari Pong, the video game system, each player moves a paddle up and down to hit the ball back past the other. The state is a stack of the last few frames so the ball’s direction shows. The moves are up, stay and down, with \(1\) move every few frames; \(1\) such move is \(1\) step. The reward is +1 for a point won, −1 for a point lost and 0 on every other step. \(1\) episode is \(1\) full game. \(J\) is the average points per game, later points counted a little less: the number learning tries to raise.

Figure 1 sets the running example: the agent's paddle, orange on the right, can only move up, stay or down, so every move the page teaches is one of those three.

2 A network that outputs move chances

Value methods such as Q-Learning and Deep Q-Networks (DQN) learn how good every move is, then play the best one. Policy methods do it differently: a policy network learns the choice itself.

Figure 2 shows that the network picks no move itself: it outputs chances, and the move is drawn from them, so the same state can give a different move next time.

The network that does this is the policy network. For Pong it gives \(3\) raw outputs, \(1\) per move, and a softmax turns them into \(3\) chances that add to \(1\). Its weights are written \(\theta\) (theta), and the chance it gives move \(a\) given state \(s\) is \(\pi_\theta(a\mid s)\).

3 Moves before a won point get more likely, moves before a lost point less likely

Push each move by its credit

Picture a Pong rally: the paddle slides up, holds still, slides down, and halfway through it wins a point. The moves just before that point set it up, so they deserve the credit and the moves before a lost point deserve the blame.

A method that learns this way is a policy-gradient method: each move is pushed by its credit, a number saying how well things turned out after it, with positive credit raising the move’s chance and negative credit lowering it.

This holds when the credit for a point goes to the moves before it, not to the game as a whole.

Figure 3 shows the rule in one game: a move is pushed up or down by what follows it, not by how good it looked at the time, so the same move can be pushed up in one game and down in another.

Pushing a move up means a small change to \(\theta\) that raises that move’s chance in that state; the other \(2\) drop, since the \(3\) add to \(1\).

Policy-gradient methods differ in the credit they use; here the credit is the points that followed each move.

4 Weighting each move by the points that followed

\(1\) game, \(1\) push per move

Picture the whole game as a finished story: every move in it already happened, and the points after each move are already known.

REINFORCE plays \(1\) full game, works out each move’s return, and pushes each move by its own return. Learning from finished games, rather than from a guess of what comes next, is called Monte Carlo learning.

This holds only once the game is finished, when every move already has the points that followed it to learn from.

Equation 1. REINFORCE learns from whole games, so it needs \(1\) number that scores each step by the points that followed it. A chess player judging a move by the game that followed it faces the same need.
1\(\displaystyle \htmlClass{eqt}{\htmlStyle{color:#196f3d}{G_t}} = \sum_{k=t}^{T-1} \htmlClass{eqt}{\htmlStyle{color:#2c3e50}{\gamma}}^{\,k-t}\, \htmlClass{eqt}{\htmlStyle{color:#7d6608}{r_{k+1}}}\)

Figure 4 shows why the discount matters: with a discount near \(1\), a point reaches far back and many moves share its credit, while with a small discount only the moves just before the point learn from it.

Line 1Intuition. A move can only claim the points that come after it, so this line adds those points into \(1\) number to push by.
The mathematics. \(\htmlClass{eqt}{\htmlStyle{color:#196f3d}{G_t}}\) is the return from step \(\htmlClass{eqt}{t}\) on, and the subscript \(\htmlClass{eqt}{t}\) names that step. The sum over \(\htmlClass{eqt}{k}\) runs from \(\htmlClass{eqt}{t}\) to \(\htmlClass{eqt}{T-1}\), the last step; each term is \(\htmlClass{eqt}{\htmlStyle{color:#2c3e50}{\gamma}}\) to the \(\htmlClass{eqt}{k-t}\) times \(\htmlClass{eqt}{\htmlStyle{color:#7d6608}{r_{k+1}}}\), the reward after step \(\htmlClass{eqt}{k}\). Here \(\htmlClass{eqt}{k-t}\) counts steps of delay: at \(\htmlClass{eqt}{k}\) equals \(\htmlClass{eqt}{t}\) the next reward, \(\htmlClass{eqt}{\htmlStyle{color:#7d6608}{r_{t+1}}}\), counts whole, and each later reward is shrunk by \(\htmlClass{eqt}{\htmlStyle{color:#2c3e50}{\gamma}}\). \(\htmlClass{eqt}{\htmlStyle{color:#196f3d}{G_t}}\) is \(\htmlClass{eqt}{\htmlStyle{color:#7d6608}{r_{t+1}}}\) plus \(\htmlClass{eqt}{\htmlStyle{color:#2c3e50}{\gamma}}\) times \(\htmlClass{eqt}{\htmlStyle{color:#7d6608}{r_{t+2}}}\) plus \(\htmlClass{eqt}{\htmlStyle{color:#2c3e50}{\gamma}}\)-squared times \(\htmlClass{eqt}{\htmlStyle{color:#7d6608}{r_{t+3}}}\). Each \(\htmlClass{eqt}{\htmlStyle{color:#7d6608}{r_{k+1}}}\) is the reward after step \(\htmlClass{eqt}{k}\).
Example. Take a game where the paddle wins a point halfway through and loses one near the end: the moves before the won point count it almost whole, while the first moves count it shrunk by the steps between.

To turn this into a loss to minimize, reuse the classification loss of supervised learning, cross-entropy, which scores each move by the log of its chance, with the move actually played as the label, scaled by the return that followed it. The return stays fixed during the update: it is a number from the game just played, and the weights cannot change it.

Equation 2. A finished game must push every move in it, so the game needs to become a loss the weights can minimize.
1\(\displaystyle \begin{aligned}&\mathcal{L}_G(\theta)\\&\;= -\sum_{t} \log \htmlClass{eqt}{\htmlStyle{color:#1f4e9c}{\pi_\theta}}(a_t\mid s_t)\; \htmlClass{eqt}{\htmlStyle{color:#196f3d}{G_t}}\end{aligned}\)

Figure 5 shows the log at work: a move the policy already plays often is pushed less hard for the same return, because the log undoes how common the move is, so common moves do not hog every update.

Line 1Intuition. The loss turns a finished game into a push by adding each move’s log chance, weighted by the points that followed that move.
The mathematics. \(\htmlClass{eqt}{\mathcal{L}_G(\theta)}\) is the REINFORCE loss for the weights \(\htmlClass{eqt}{\theta}\). The sum over \(\htmlClass{eqt}{t}\) adds over every step; each term multiplies log \(\htmlClass{eqt}{\htmlStyle{color:#1f4e9c}{\pi_\theta}}(a_t\mid s_t)\), the log chance of the move given state \(\htmlClass{eqt}{\htmlStyle{color:#1f4e9c}{s_t}}\), by \(\htmlClass{eqt}{\htmlStyle{color:#196f3d}{G_t}}\), its return. The minus makes the sum a loss to minimize, pushing each move up by its return. \(\htmlClass{eqt}{\htmlStyle{color:#196f3d}{G_t}}\) is held fixed: the loss treats it as a number, not a function of \(\htmlClass{eqt}{\theta}\). So the whole equation says this: weight each move's log chance by the return that followed it, and \(1\) update pushes every move by its own return.
Example. Take the moves before the won point: the loss pushes them up, and the moves before the lost point down.

Why the log? The gradient of the expected return is the expected return-weighted gradient of the log chance, so the log is what turns the average push over games into the direction that raises the average points. The commonness effect follows from the same identity: a move played often gets pushed often, just because it is common, and the slope of a log chance is the slope of the chance itself, divided by that chance, so the more common a move is, the smaller each of its pushes.

5 Why one game is a noisy judge

The true push is an average over every game the paddle could play, but REINFORCE estimates it from the \(1\) game it just played, so each update carries that game’s luck.

The bad move that still gets pushed up

Picture the paddle winning a point after a bad down move that let the ball slip past. The points after that move are high anyway, so the bad move gets pushed up just like the good ones.

One game is all the evidence the update gets, so that game's luck rides along with every push.

This holds over many games, when the lucky pushes and the unlucky ones average out; any \(1\) update on its own can still point the wrong way.

  1. The paddle goes down while the ball comes in high, a bad move.
  2. The paddle wins the points after it anyway, so its return is high.
  3. Each arrow is sized by the full return that followed its move.

Figure 6 shows the trap: the points after a move are all the evidence \(1\) game gives about it, so the update cannot tell a move that earned the point from one that only came before it.

6 Subtracting the usual result

The advantage from \(1\) game

Picture \(2\) states: in \(1\) state the paddle is well placed and points usually follow, in the other it is badly placed and points rarely follow. What matters is whether a move did better or worse than usual from that state.

A baseline is that usual result, subtracted from the return. The return minus the guess is the move’s advantage, how much better than usual it did. A second network, the value network, learns the guess.

This holds when the baseline is the usual result from that state, so a move is pushed up only when it beats what its state usually returns.

The value network looks at the state and outputs \(1\) number, \(V_\phi(s)\), its guess of the usual result. \(\phi\) (phi) stands for its weights, as \(\theta\) does for the policy network.

The advantage from \(1\) game is only an estimate, so the hat above it marks it as the estimate from that one game: \(\hat A_t\).

Equation 3. \(1\) game is a noisy judge of a move, so each move is judged against what its state usually returns. A coach who scores a player against the team’s usual result faces the same need.
1\(\displaystyle \htmlClass{eqt}{\htmlStyle{color:#196f3d}{\hat{A}_t}} = \htmlClass{eqt}{\htmlStyle{color:#196f3d}{G_t}} - \htmlClass{eqt}{\htmlStyle{color:#a04000}{V_\phi(s_t)}}\)
2\(\displaystyle \begin{aligned}&\mathcal{L}_{\hat A}(\theta)\\&\;= -\sum_{t} \log \htmlClass{eqt}{\htmlStyle{color:#1f4e9c}{\pi_\theta}}(a_t\mid s_t)\; \htmlClass{eqt}{\htmlStyle{color:#196f3d}{\hat{A}_t}}\end{aligned}\)
3\(\displaystyle \begin{aligned}&\mathcal{L}_V(\phi)\\&\;= \sum_{t} \big(\htmlClass{eqt}{\htmlStyle{color:#196f3d}{G_t}} - \htmlClass{eqt}{\htmlStyle{color:#a04000}{V_\phi(s_t)}}\big)^2\end{aligned}\)

Figure 7 shows the two lines working together: the advantage line tells the push which way to go, and the value loss curve tells the guess how far off it is. The value loss is smallest when the guess equals the return and grows as the guess moves away in either direction, so it pulls the guess back toward the return.

Line 1Intuition. This line takes the return and subtracts the usual result, so only how much better the move did than usual counts.
The mathematics. \(\htmlClass{eqt}{\htmlStyle{color:#196f3d}{\hat{A}_t}}\) is the advantage of the move at step \(\htmlClass{eqt}{t}\), how much better it did than usual; the mark above it means it is an estimate: \(1\) game is \(1\) sample of all the games the paddle could have played. \(\htmlClass{eqt}{\htmlStyle{color:#196f3d}{G_t}}\) is the return from step \(\htmlClass{eqt}{t}\) on, the points that followed; minus \(\htmlClass{eqt}{\htmlStyle{color:#a04000}{V_\phi(s_t)}}\) takes off the value network's guess for the state \(\htmlClass{eqt}{\htmlStyle{color:#1f4e9c}{s_t}}\). A move that beats the guess has a positive advantage and one that falls short has a negative one.
Example. Take a state where the ball is already past the paddle, so the next point is almost always lost: the value network's guess there is low, so every move there is pushed down unless it beats the guess.
Line 2Intuition. The advantage must reach every move in the game. Each move’s push is now weighted by how much better it did than usual instead of by the raw points that followed.
The mathematics. \(\htmlClass{eqt}{\mathcal{L}_{\hat A}(\theta)}\) is the baseline loss for the weights \(\htmlClass{eqt}{\theta}\). The sum over \(\htmlClass{eqt}{t}\) adds over every step; each term multiplies log \(\htmlClass{eqt}{\htmlStyle{color:#1f4e9c}{\pi_\theta}}(a_t\mid s_t)\), the log chance the policy gave the move given state \(\htmlClass{eqt}{\htmlStyle{color:#1f4e9c}{s_t}}\), by \(\htmlClass{eqt}{\htmlStyle{color:#196f3d}{\hat{A}_t}}\), the advantage, the return minus the value network's guess for the state. The minus turns the weighted sum into a loss to minimize, weighting each move's log chance by its advantage. \(\htmlClass{eqt}{\htmlStyle{color:#196f3d}{\hat{A}_t}}\) is held fixed: the advantage is computed once and not differentiated through.
Example. Take the bad move that let the ball slip past: its return is high, yet the usual result from its state is higher still, so its advantage is negative and the loss pushes it down.
Line 3Intuition. The advantage is only as good as the guess it subtracts. This line shrinks the gap between the guess and the real return, so the guess gets closer with every update.
The mathematics. \(\htmlClass{eqt}{\mathcal{L}_V(\phi)}\) is the value loss for the weights \(\htmlClass{eqt}{\phi}\), so only \(\htmlClass{eqt}{\phi}\) changes through this line. The sum over \(\htmlClass{eqt}{t}\) adds over every step; each term squares the brackets, \(\htmlClass{eqt}{\htmlStyle{color:#196f3d}{G_t}}\) minus \(\htmlClass{eqt}{\htmlStyle{color:#a04000}{V_\phi(s_t)}}\), the return minus the guess; the square makes it a squared gap, so a miss in either direction counts. Making it smaller pulls the guess toward the real return. If the guess fits badly, the pushes stay as noisy as in REINFORCE without a baseline. \(\htmlClass{eqt}{\mathcal{L}_V(\phi)}\) equals the sum over \(\htmlClass{eqt}{t}\) of (\(\htmlClass{eqt}{\htmlStyle{color:#196f3d}{G_t}}\) minus \(\htmlClass{eqt}{\htmlStyle{color:#a04000}{V_\phi(s_t)}}\)) squared.
Example. Take the states late in a lost game: the returns there are low, so the value loss pulls the guess for those states down toward them.

A push is biased when, averaged over many games, it points somewhere other than the direction that raises \(J\).

The baseline must depend only on the state, never on the move made there. Then subtracting it adds no bias. Picture the paddle in \(1\) state over many games: in each game it picks a move by chance and pushes it by the baseline, so a move it picks often gets that baseline push often. The push on a move is its chance times the slope of its log chance, and that product is the slope of the chance itself. Add the slopes of all the chances and the total is the slope of their sum. The chances always add to \(1\), so that slope is \(0\), and on average the baseline’s pushes cancel.

7 How a baseline narrows the spread

The learning rate \(\eta\), the lr in the code, sets how big a step each update takes, the same role a step size plays in any update. Raising it takes bigger steps, so the policy moves faster but can overshoot; lowering it takes smaller steps, so the policy moves steadier but slower.

A less noisy push makes separate training runs end closer together. How far apart they end is the spread. A baseline set above the usual result makes the pushes noisier, so the training runs spread out again.

The tool sets its own win chances, for illustration: up is the most likely winner, then stay, then down. Its baseline is the exact usual result, worked out from those win chances, not a value a network learned.

Figure 8 shows what the spread looks like at rest: the thick line is \(1\) training run and the faint lines the other \(29\). Press Next to see where the runs end, and press it again to see each game’s push on the chance of up.

8 Keeping the paddle undecided

Paying the paddle to stay undecided

Picture the paddle winning a few points by staying still: every push raises stay a little more, until up and down are almost never tried and the paddle never finds out that moving up wins more.

Entropy is how undecided the policy is, and the entropy bonus rewards the policy for staying undecided, so it keeps trying moves it rarely picks. The bonus is borrowed from A3C (Mnih et al. 2016), a method that runs many games at once and pools what each one learns, not part of the original REINFORCE. The entropy weight \(c_H\) sets how much the loss pays for staying undecided.

This holds while the bonus still pays the paddle to stay undecided, so the rarely picked moves keep enough chance to be tried.

Figure 9 shows what the bonus buys: on the left the paddle has almost stopped trying up and down, while on the right those moves keep a sliver of chance.

Equation 4. A paddle that wins a few points by staying still stops trying the other moves, so the loss pays it to stay undecided. A player who only ever tries \(1\) opening, one way of starting the game, faces the same trap.
1\(\displaystyle \begin{aligned}&\htmlClass{eqt}{\htmlStyle{color:#0e6d80}{\mathcal{H}}}\big(\htmlClass{eqt}{\htmlStyle{color:#1f4e9c}{\pi_\theta}}(\cdot\mid s)\big)\\&\quad=-\sum_{a}\htmlClass{eqt}{\htmlStyle{color:#1f4e9c}{\pi_\theta}}(a\mid s)\\&\qquad\times\log \htmlClass{eqt}{\htmlStyle{color:#1f4e9c}{\pi_\theta}}(a\mid s)\end{aligned}\)
2\(\displaystyle \begin{aligned}&\mathcal{L}_{\text{total}}\\&\;=\mathcal{L}_{\hat A}(\theta)+\mathcal{L}_V(\phi)\\&\qquad-c_H\sum_{t}\htmlClass{eqt}{\htmlStyle{color:#0e6d80}{\mathcal{H}}}\big(\htmlClass{eqt}{\htmlStyle{color:#1f4e9c}{\pi_\theta}}(\cdot\mid s_t)\big)\end{aligned}\)

Figure 10 shows how the weight sets the price of certainty: a bigger entropy weight pays more for staying undecided at every chance, so raising it is how the loss buys more trying of rare moves.

Line 1Intuition. A paddle that locks onto \(1\) move stops learning. This line measures how undecided its chances still are.
The mathematics. \(\htmlClass{eqt}{\htmlStyle{color:#0e6d80}{\mathcal{H}}}\) of \(\htmlClass{eqt}{\htmlStyle{color:#1f4e9c}{\pi_\theta}}(\cdot\mid s)\) is the entropy of the whole policy given state \(\htmlClass{eqt}{s}\), the dot standing for all \(3\) chances. The sum over \(\htmlClass{eqt}{a}\) adds over the moves \(\htmlClass{eqt}{a}\); each term multiplies \(\htmlClass{eqt}{\htmlStyle{color:#1f4e9c}{\pi_\theta}}(a\mid s)\), the chance the policy gives that move, by log \(\htmlClass{eqt}{\htmlStyle{color:#1f4e9c}{\pi_\theta}}(a\mid s)\), the log of that chance; the minus in front makes \(\htmlClass{eqt}{\htmlStyle{color:#0e6d80}{\mathcal{H}}}\) positive, since a log below \(1\) is negative. When the moves are about equally likely \(\htmlClass{eqt}{\htmlStyle{color:#0e6d80}{\mathcal{H}}}\) is high; when \(1\) move is certain \(\htmlClass{eqt}{\htmlStyle{color:#0e6d80}{\mathcal{H}}}\) is \(0\).
Example. Take the \(3\) moves sharing chance equally: each term is the same and the entropy is at its highest.
Line 2Intuition. This line subtracts a small bonus for staying undecided from the total, so the loss stays low while the paddle keeps trying moves and rises as it commits to one.
The mathematics. \(\htmlClass{eqt}{\mathcal{L}_{\text{total}}}\) is the total loss. \(\htmlClass{eqt}{\mathcal{L}_{\hat A}(\theta)}\) is the baseline loss, pushing toward good moves; plus \(\htmlClass{eqt}{\mathcal{L}_V(\phi)}\) is the value loss, fitting the value network; minus the entropy term takes off the bonus, \(\htmlClass{eqt}{c_H}\) the entropy weight. The minus means training pays a small price for certainty: raising \(\htmlClass{eqt}{c_H}\) keeps the paddle undecided longer, while lowering it lets it commit sooner. The value loss changes only \(\htmlClass{eqt}{\phi}\); the rest changes only \(\htmlClass{eqt}{\theta}\). \(\htmlClass{eqt}{\mathcal{L}_{\text{total}}}\) equals \(\htmlClass{eqt}{\mathcal{L}_{\hat A}(\theta)}\) plus \(\htmlClass{eqt}{\mathcal{L}_V(\phi)}\) minus \(\htmlClass{eqt}{c_H}\) times the sum over \(\htmlClass{eqt}{t}\) of \(\htmlClass{eqt}{\htmlStyle{color:#0e6d80}{\mathcal{H}}}\) of \(\htmlClass{eqt}{\htmlStyle{color:#1f4e9c}{\pi_\theta}}(\cdot\mid s_t)\). So the whole equation says this: add the push toward good moves and the fit of the value, subtract a small price for certainty, and \(1\) update minimizes all \(3\) at once.
Example. Take a state where stay has won lately, so it gets most of the chance: the entropy there is near \(0\), so the bonus keeps a sliver on up and down for the paddle to try.

9 Step through one REINFORCE update

Put together, \(1\) update has \(4\) ideas: the return, the advantage, the value fit and the entropy bonus.

10 The update written out as code

The whole update is \(1\) short script, a toy REINFORCE for Pong to read rather than run, in \(6\) stages. It makes Pong with ale_py, the Atari plugin. Step through the stages below.

Figure 12 shows the order the code follows: the game is made before any move is picked, and the return and the advantage are worked out before any push happens, so a mistake early on rides through to the push.

import gymnasium as gym, ale_py
import torch
from torch import nn
from torch.distributions import (
    Categorical)

gym.register_envs(ale_py)
env = gym.make(
    "ALE/Pong-v5", frameskip=1,
    full_action_space=False)
# frameskip=1 skips none
env = gym.wrappers \
    .AtariPreprocessing(
    env, frame_skip=4)
env = gym.wrappers \
    .FrameStackObservation(env, 4)
MOVES = [2, 0, 3]   # up, stay, down
DISCOUNT, C_ENTROPY = 0.99, 0.01
FRAMES, C1, C2 = 4, 32, 64
FLAT, HIDDEN = 5184, 512
N_MOVES, LEARNING_RATE = 3, 0.0001
N_EPISODES = 10
gamma, c_h = DISCOUNT, C_ENTROPY
def returns_to_go(rewards, gamma):
    G, out = 0.0, []
    for r in reversed(rewards):
        G = r + gamma * G
        out.insert(0, G)
    return torch.tensor(out)

def body():
    return nn.Sequential(
        nn.Conv2d(FRAMES, C1, 8,
                  stride=4),
        nn.ReLU(),
        nn.Conv2d(C1, C2, 4,
                  stride=2),
        nn.ReLU(),
        nn.Flatten(),
        nn.Linear(FLAT, HIDDEN),
        nn.ReLU())

policy = nn.Sequential(
    body(),
    nn.Linear(HIDDEN, N_MOVES))
# up, stay, down
value = nn.Sequential(
    body(), nn.Linear(HIDDEN, 1))
# V_phi(s)
opt = torch.optim.Adam(
    [*policy.parameters(),
     *value.parameters()],
    lr=LEARNING_RATE)

for episode in range(N_EPISODES):
    # repeat: one game, one update
    s, info = env.reset()
    states, moves = [], []
    rewards, done = [], False
    while not done:
        # one whole game
        x = torch.as_tensor(
            s, dtype=torch.float32)
        x = x.unsqueeze(0) / 255
        with torch.no_grad():
            a = Categorical(
                logits=policy(x)
            ).sample()
        s, r, terminated, \
            truncated, \
    info = env.step(MOVES[a.item()])
        states.append(x)
        moves.append(a)
        rewards.append(r)
    # r_{t+1}: reward after move t
        done = terminated or \
            truncated
    S, M = torch.cat(states), \
        torch.cat(moves)
    dist = Categorical(
        logits=policy(S))
    # softmax of the logits
    logp = dist.log_prob(M)
    G = returns_to_go(
        rewards, gamma)
    Gs = (G - G.mean()) / \
        (G.std() + 1e-8)
    # Gs: mean 0,
    # standard deviation 1
    # 1e-8 is a tiny number added so
    # division never divides by 0
    V = value(S).squeeze(-1)
    value_loss = (G - V).pow(2) \
        .sum()
    adv = (Gs - V).detach()
    pg_loss = -(logp * adv).sum()
    loss = pg_loss + value_loss \
        - c_h * dist.entropy().sum()
    opt.zero_grad()
    loss.backward()
    opt.step()
  1. 1The return of every step, added up backward from the last reward.
  2. 2The policy network’s logits, its raw outputs before the softmax; logp is the log chance of each move taken.
  3. 3The returns are first shifted and scaled to mean \(0\) and standard deviation \(1\), a typical distance of \(1\) from the average, giving Gs. That shift and scale is for the policy push only, so one game with huge returns cannot swamp the others. The value loss uses the raw return G: the value network’s guess for every state and its squared gap to the return.
  4. 4The advantage and the baseline loss: adv is \(\hat A_t\) from the standardized return, held fixed by detach(), and pg_loss is \(\mathcal{L}_{\hat A}\).
  5. 5The total loss, with the entropy of the move distribution as its entropy line; zero_grad clears the last update’s gradients, the backward call works out every gradient, which is the rate each weight must change to lower the loss, and the optimizer update is \(1\) Adam update, a step that gives each weight its own step size from its past gradients.
  6. 6The settings, assigned in the code. The toy run plays N_EPISODES \(10\) episodes with DISCOUNT \(0.99\), FRAMES \(4\) stacked frames and N_MOVES \(3\) moves, an entropy weight of C_ENTROPY \(0.01\) and a learning rate of LEARNING_RATE \(0.0001\). The first layer scans the stacked frames with C1 \(32\) filters, each filter looking for one kind of pattern, and the second layer scans that result with C2 \(64\) filters. Conv2d is the layer that scans: the \(8\) is the width of each filter’s window and stride \(4\) is how far it steps each time. Flattening stacks the result into \(1\) long list of FLAT \(5184\) numbers, the next layer turns that list into HIDDEN \(512\) numbers, and the last layer turns those numbers into the move scores.

11 How to set up each update

Three settings shape each update: the learning rate sets how big a step each update takes, the discount sets how far ahead each push looks, and the entropy weight sets how undecided the paddle stays.

  • Learning rate \(\eta\): \(10^{-4}\). Raising the learning rate takes bigger steps, and steps too big collapse the chances onto \(1\) move; lowering the learning rate takes smaller steps, so learning is steadier but slower. Source: Karpathy’s Pong from Pixels.
  • Discount \(\gamma\): \(0.99\). Raising the discount lets far-off points count more, so the push carries less bias and more noise; lowering the discount lets only near points count, so the push carries less noise and more bias. Source: the PyTorch cart-pole example (a cart keeping a pole upright).
  • Entropy weight \(c_H\): \(0.01\). Raising the entropy weight keeps the paddle undecided longer, so it tries more and settles slower; lowering the entropy weight lets it commit sooner and may lock onto \(1\) move. Source: the A3C supplementary material, where beta \(0.01\) is stated; beta is the paper’s name for the entropy weight, and A3C, asynchronous advantage actor-critic, is the parallel method the entropy bonus comes from.

Each update runs once per finished game, and what carries over between updates is the \(2\) networks’ weights and the optimizer’s running averages. \(1\) update’s time grows with the length of the game it just played, and its memory is the game itself: the states, moves and rewards it must keep until the update runs.

  • Normalize the returns: shift and scale them so each update’s returns average \(0\) and have a standard deviation of \(1\). That keeps the pushes on the same scale from one update to the next, so one game with huge returns cannot swamp the others.
  • Average several games into \(1\) update, so the update then runs once per batch of games instead of once per finished game. Each update then learns from more games at once, so its push is steadier.

12 When REINFORCE fits

REINFORCE fits short games. Picture a rally that ends after a few hits: the moves just before the point are few, so each one clearly earns its push. Picture a rally that runs for hundreds of hits before the point: every move in it shares the same point, so no single move can be told apart, and each push carries the whole game’s luck.

13 What breaks REINFORCE

\(5\) symptoms, \(5\) fixes

Picture a paddle after a long night of training that still loses: its training runs end far apart, its chances have collapsed onto \(1\) move, and it never settles on anything better.

What breaks REINFORCE is never the idea of learning from whole games; it is one part of the update set wrong: the baseline, the learning rate, the entropy weight, or the length of the game.

  • Training runs end far apart and learning is slow. With no baseline, every push carries the whole game’s luck, so separate runs drift apart. Subtract a learned value, so each push counts only how much better the move did than usual.
  • The paddle drifts toward worse moves. A baseline that depends on the move tilts the push, so the push is biased. Let the baseline see only the state, so subtracting it adds no bias.
  • The chances collapse onto \(1\) move. A learning rate too high takes steps too big, or an entropy weight too small pays too little for staying undecided. Lower \(\eta\) or raise \(c_H\), so the paddle keeps trying the other moves.
  • The paddle never commits. An entropy weight too large pays so much for staying undecided that the paddle keeps spreading its chances. Lower \(c_H\), so the paddle can settle on the better move.
  • Learning barely moves in very long games. Each move’s share of the result is hard to tell apart when many moves come before the point. Judge moves sooner, so each move is judged a few steps later instead of at the end of the game.

14 Judging each move before the game ends

What if the value network’s guess stood in for the points still to come, so each move could be judged a few steps later instead of at the end of the game?

Judging each move before the game ends is the idea behind Actor-Critic: it judges each move with the value network’s guess a few steps ahead instead of waiting for the game to end. Proximal Policy Optimization (PPO) builds on that by capping how far each update can move the policy, so one bad game cannot swing it far.

Aligning Language Models with RL applies the same push to the text a language model writes: each move is the next word it writes, and the points are the reward for the text.
