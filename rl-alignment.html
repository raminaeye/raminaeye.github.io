1From next-token predictor to assistant

1.1Predicting text is not following instructions

A pretrained language model is trained only to predict the next word piece, or token, of the text it reads. Given a question, it may carry on with more questions instead of answering.

Aligning a model means training it to do what people want from it, so that its replies are helpful, honest and harmless.

OpenAI's paper on following instructions states the goal as "follow the user's instructions helpfully and safely".

GPT-3, a large pretrained OpenAI language model, continues the prompt with more questions; InstructGPT, the same model after the training these pages describe, answers it.

1.2Comparing is easier than writing

Writing ideal answers is slow and people word them differently; picking the better of two is fast and consistent.

Training a model to copy demonstrations is called behaviour cloning; it can only be as good as the examples (RL Basics).

Learning from comparisons came from robotics and games research (References).

2Training a language model by trial and reward

2.1One reply, one run of choices

The agent is the learner that picks the moves. (RL Basics)

A state is the agent's situation right now; a move, or action, is one choice the agent can make in a state; a reward is the number the world hands back after each move, good or bad. (RL Basics)

Here the agent is the language model.

Instead of copying example replies, the model tries replies and learns from the rewards they earn.

Here the state is the prompt plus the tokens written so far, and the move is the next token.

Here the reward is one number for the whole reply, given when the reply ends.

Writing a reply is then a run of choices, one token after another, and the loop in Figure 2 repeats until the reply ends; only then does a reward come back.

RL, short for reinforcement learning, is learning which moves to make from rewards rather than from labelled answers. (RL Basics)

The rewards can come from people, from another model, or from a program that checks the answer, as the methods below show.

For the moon-landing question, a reply that answers earns a high reward and one that dodges a low one.

A policy is the agent's rule for choosing a move in each state; it may always pick the same move or pick by chance. (RL Basics)

The policy is the language model being trained to write replies.

Each update changes the policy so that replies that earned high rewards become more likely, and the model writes them more often next time.

An episode is one run from the start until it ends. (RL Basics)

Here an episode is one written reply.

Training repeats this over many prompts, one written reply at a time.

The return is all the reward still to come, with later rewards counted a little less. (RL Basics)

Here the return is the reward for the whole reply.

An expected value is the average over everything that can happen by chance, weighted by how likely each outcome is. (Probability and Bayes Rule, RL Basics)

The agent's goal is to make its expected return as large as possible, averaged over the replies it might write.

So a reply's log-probability is the sum of its tokens' log-probabilities.

Any language model gives a score (logit) for every word piece at every position; this turns those into the log-probability of one reply.

import torch
logits = torch.randn(1, 12, 50_000)              # [1] model output: (batch, length, vocab)
ids = torch.randint(0, 50_000, (1, 12))          # the tokens actually in prompt + reply
reply_mask = torch.zeros(1, 12)                  # reply starts after the prompt
reply_mask[:, 5:] = 1
logp = torch.log_softmax(logits[:, :-1], -1)     # [1] line 1 of the whole-reply probability card; the score at position t predicts token t+1
tok = logp.gather(-1, ids[:, 1:, None]).squeeze(-1)      # [2] the chosen tokens
reply_logp = (tok * reply_mask[:, 1:]).sum(-1)   # [3] lines 2 and 3 of the whole-reply probability card, sum over reply tokens

2.2Start from supervised fine-tuning

SFT, supervised fine-tuning, trains the model on replies people wrote with the ordinary next-token loss; RL usually starts from that model.

DeepSeek-R1-Zero, a model trained to write out its reasoning steps before answering, is the exception: it runs RL straight on the pretrained model.

Every other method on these pages starts from the SFT model.

2.3Stay close to the starting model

The reference model \(\pi_{\mathrm{ref}}\) is a frozen copy, one whose weights never change during training, of the SFT model.

KL measures how different two probability distributions are, zero when they match; the KL penalty charges the policy for drifting away from the reference model.

The reward, learned by a network from people's picks or computed by a program, can be fooled, or can push the policy to unreadable text far from familiar text.

The thing that gives the reward is called a scorer, a network trained on people's picks or a program that checks the answer.

The prompts the model is trained on are written \(\mathcal{D}\).

The sign \(\sim\) means drawn at random from. (RL Basics)

Training takes one prompt at a time from that set and lets the policy write a reply to it.

3One pipeline, several changes

3.1The full pipeline and what each method changes

A reward model is a language model with a one-number output, trained on people's comparisons so the reply they preferred scores higher.

In RLHF, reinforcement learning from human feedback, people compare replies and a reward model learns their preferences.

The RL loop writes fresh replies with the current model during training, rewards them, and updates the model; it does not learn from a fixed dataset.

A critic is a second network that guesses each state's value, the return expected from it. (Actor-Critic: A2C and A3C)

The RL loop compares each reply's reward with the critic's guess, so a reply is pushed up only when it did better than expected.

Later methods change one box of this pipeline.

RLAIF, reinforcement learning from AI feedback, puts an AI labeler, an existing language model asked which of two replies is better, in the person's place.

The rest of the RLHF pipeline stays the same.

In Constitutional AI a feedback model, a language model that reads a written principle and picks the less harmful reply, writes the harm labels; its list of principles is called a constitution.

People still label helpfulness.

DPO, direct preference optimization, trains on the pairs with one loss.

DPO removes the reward model and the RL loop.

GRPO compares the reward of each of several replies to one prompt with the average over those replies, which are called a group.

GRPO keeps the reward model and the RL loop and removes only the critic.

In DeepSeek-R1 an answer checker, a program that compares the final answer with the known one and checks the reply's format, replaces the reward model on reasoning questions such as math and code.

Think tags are the markers <think> and </think> that the model is asked to put around its reasoning.

DeepSeek-R1 keeps GRPO and swaps the learned reward for these checks on reasoning questions.

The full DeepSeek-R1 runs SFT first, on examples its first run wrote; only R1-Zero skips SFT.

4One example through each alignment pipeline

5Choose the method by where the reward comes from

You have pairs of replies where people picked the better one, and want simple training: DPO trains on the pairs with one loss.

A program can check the answer (math, code): GRPO with an answer checker, or DeepSeek-R1.

You have few human harm labels: Constitutional AI writes harm labels from principles, and RLAIF lets an AI labeler pick.

You want the classic, most flexible recipe and have the compute: RLHF.

How do you turn "A is better than B" into a number a network can learn? Reward Models answers it.
