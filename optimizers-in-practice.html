Optimizers in Practice: AdamW, SAM, Schedules and Clipping

  1. Optimizers from SGD to Adam
  2. Optimizers in Practice: AdamW, SAM, Schedules and Clipping

AdamW, SAM, schedules and clipping, the four things a real training loop adds to the update rule.

The optimizer turns each gradient into a step. Around it, AdamW changes how weight decay enters Adam's step, SAM spends a second forward and backward pass to prefer flat minima, a schedule changes the learning rate α between steps, and clipping caps a rare huge gradient at a length τ between backward() and the step.

This page builds on Optimizers from SGD to Adam, which teaches the update rules that these controls wrap.

1 Decoupled weight decay (AdamW)

Weight decay shrinks the weights toward zero each step. Here it is added to Adam, whose update, from the Adam section of Optimizers from SGD to Adam, keeps two running averages and scales each weight's step:

Adam smooths the slope and divides each weight's step by its own recent scale.
mt = β1mt−1+(1−β1)gt
The momentum mt is a running average of the gradients gt; β1, about 0.9, is the share of the old average it keeps each step.
vt = β2vt−1+(1−β2)gt2
vt is a running average of the squared gradients, each weight's own scale; β2, about 0.999, plays the same role for it.
θ ← θ − α·m̂t√v̂t+ε
The weights θ move by the learning rate α times the smoothed slope divided by the root of that scale; m̂t and v̂t are the two averages corrected for their start at zero, and ε guards the division.

Adam applies weight decay as L2 inside the gradient, where it is divided by each weight's gradient scale; AdamW decouples it, with the same state as Adam (Loshchilov and Hutter 2019):

Adam with L2 and AdamW differ only in where the weight decay term goes.
gt = ∇L(θ) + λθ
Adam with L2 adds λθ, the slope of the L2 penalty, to ∇L(θ), the slope of the loss L; λ (lambda) is the decay strength. Added here, the decay flows into both moments and gets divided by the root of v̂t, so weights with large gradients get almost no decay. The penalty is λ/2 times the sum of squared weights; the Regularization page drops the one-half, which only rescales λ.
θ ← θ − α·(m̂t√v̂t+ε + λθ)
AdamW moves the decay outside the fraction. The moments see only ∇L(θ), and every weight shrinks by the same α·λ share of itself each step, which is the decay the penalty intended. A larger λ keeps the weights smaller and the model simpler, too large underfits, and λ = 0 is plain Adam; PyTorch's AdamW defaults to 0.01.

PyTorch has both, so pick one.

import torch
from torch.optim import Adam
from torch.optim import AdamW
model = torch.nn.Linear(10, 1)
p = list(model.parameters())
lr, lam = 1e-3, 1e-2  # α, λ
decay = dict(weight_decay=lam)
# Adam: λθ joins the grad
adam = Adam(p, lr, **decay)
# AdamW: decay outside it
adamw = AdamW(p, lr, **decay)
  1. 1A small model, α and λ.
  2. 2Adam with λ inside the gradient, the L2 line.
  3. 3AdamW with the decay outside the rescaling, the AdamW line.

So for adaptive methods, weight decay is not L2 regularization.

2 Sharpness-aware minimization (SAM)

SAM wraps another optimizer instead of replacing it. Plain optimizers can land in a sharp minimum; SAM looks for flat minima, where the loss stays low when the weights change a little. Both of its passes use the same minibatch. It keeps no state between steps but holds δ, one copy of the weights, during each step, and each step costs two forward and backward passes, about twice plain training (Foret et al. 2021).

SAM finds the worst small change to the weights, then descends from there.
δ = ρ·∇L(θ)‖∇L(θ)‖
δ (delta) is a perturbation, a small change to the weights, of length ρ (rho) pointing straight uphill: the gradient divided by its own length ‖∇L(θ)‖ is an arrow of length one, and ρ sets how far it reaches. For a small radius uphill is where the loss rises fastest, so the perturbed point is roughly the worst point within ρ. A larger ρ judges flatness over a wider neighborhood, and too large a ρ lands on points that say little about the minimum; ρ = 0 is the base optimizer. SAM's CIFAR examples use 0.05.
gSAM = ∇L(θ + δ)
gSAM is the slope at that worst point, and the optimizer applies it at θ itself. In a sharp minimum the worst point sits high on its side and its slope is large, so SAM is pushed out of sharp minima and settles in flat ones.

perturb is SAM's first pass; ps holds the weight tensors with zeroed gradients and closure returns the minibatch loss.

import torch
from torch import stack
def perturb(ps, closure, rho):
    closure().backward()
    gs = [p.grad for p in ps]
    ns = [g.norm() for g in gs]
    k = rho / stack(ns).norm()
    ds = [k * g for g in gs]
    with torch.no_grad():
        for p, d in zip(ps, ds):
            p.add_(d)  # θ + δ
    return ds
  1. 1Reads the gradient at θ.
  2. 2Scales it to length ρ, which is δ, the first SAM line.
  3. 3Moves every weight to θ + δ and returns δ.

One SAM step calls perturb, reads the gradient at θ + δ, moves back to θ, and lets the base optimizer, opt, take its step with that gradient, gSAM.

ds = perturb(ps, closure, rho)
opt.zero_grad()
closure().backward()  # θ + δ
with torch.no_grad():
    for p, d in zip(ps, ds):
        p.sub_(d)  # back to θ
opt.step()  # steps with g_SAM
  1. 1Moves to θ + δ with perturb.
  2. 2Reads the gradient there, gSAM, the second SAM line.
  3. 3Moves the weights back to θ.
  4. 4Lets the base optimizer step with gSAM.

Different weights can compute the same function yet look sharper or flatter, so flatness is a rule of thumb, not a guarantee.

3 Learning rate schedules

A large rate moves fast early, but near a minimum a constant rate keeps bouncing, so schedulers bring α down as training goes.

  • Step decay drops it by a factor every few epochs (passes over the data).
  • Exponential decay shrinks it by a fixed fraction each step or epoch.
  • Cosine annealing stays near the maximum rate early and eases into the minimum late.
  • Warm restarts jump back to the maximum after each cosine cycle, so training can leave its minimum for others (Loshchilov and Hutter 2017).
  • Warmup raises the rate from a small value to its target over the first steps or epochs, so the large early gradients do not throw the weights far; Goyal et al. 2017 ramped it linearly over 5 epochs.
  • One-cycle rises first, then falls, pairing the large rate with low momentum (Smith 2018); momentum is a decaying sum of past gradients that the step follows, from the momentum section of Optimizers from SGD to Adam.
Cosine annealing lowers the rate from its maximum to its minimum along a cosine.
αt = αmin + 12(αmax − αmin)·st
αt is the learning rate at step t of a T-step schedule. It is αmin plus a share of the range up to αmax, and the share is half of st, so the rate always stays between the two.
st = 1 + cos(π·tT)
st is 1 plus a cosine that sweeps half a turn as t runs from 0 to T, so it falls from 2 to 0. A cosine is flat at both ends, so the rate lingers near αmax early, drops fastest mid-training and eases gently into αmin at the end.

A scheduler keeps one counter, the steps or epochs so far, and sets α from it at almost no cost. Step decay, exponential decay and cosine annealing usually step once per epoch; one-cycle steps once per batch (the one-cycle paper counts its cycle in iterations), and warm restarts can too, as in the SGDR paper.

Each schedule is a PyTorch class wrapping the optimizer: StepLR multiplies the rate by gamma, 0.1 here, every 30 epochs, ExponentialLR by 0.95 every epoch, and CosineAnnealingLR follows a cosine over T_max epochs.

import torch
import torch.optim as optim
S = optim.lr_scheduler
net = torch.nn.Linear(4, 1)
ps = net.parameters()
opt = optim.SGD(ps, lr=0.1)
# pick one, stepped per epoch
s = S.StepLR(opt, 30, 0.1)
s = S.ExponentialLR(opt, 0.95)
Cos = S.CosineAnnealingLR
s = Cos(opt, T_max=100)
  1. 1Builds a model and an SGD optimizer to schedule.
  2. 2Step decay, the rate times 0.1 every 30 epochs.
  3. 3Exponential decay, the rate times 0.95 every epoch.
  4. 4Cosine annealing over 100 epochs, the cosine schedule equation.

Warm restarts repeat every T_0 epochs; one-cycle rises to a peak rate of 0.1 and back over 1000 steps, stepped per batch. A smaller gamma or a shorter interval cuts the rate sooner and harder, which can freeze training before the loss flattens; a longer T_max or T_0 stretches each cycle; a higher one-cycle peak explores more but can diverge. PyTorch's defaults are a gamma of 0.1 for StepLR, a minimum rate eta_min of 0 for the cosine schedules, and 30 percent of the one-cycle spent warming up.

WR = S.CosineAnnealingWarmRestarts
s = WR(opt, T_0=10)
OneCycle = S.OneCycleLR
s = OneCycle(opt, 0.1, 1000)
for step in range(1000):
    opt.step()
    s.step()  # per batch
  1. 1Warm restarts every 10 epochs.
  2. 2One-cycle up to 0.1 and back over 1000 steps.
  3. 3Steps the optimizer, then the one-cycle schedule, once per batch.

4 Gradient clipping

Gradient clipping guards against exploding gradients, gradients that suddenly become very large: a gradient longer than a threshold τ is shrunk to length τ. It keeps no state and costs one length over all the gradients (Pascanu et al. 2013).

Clipping by norm keeps the direction and caps the length at τ.
g ← g·min(1, τ‖g‖)
g is the gradient over all weights together and ‖g‖ its length. Under the threshold τ (tau), τ divided by the length is above 1, the min picks 1 and nothing changes. Above it, the factor rescales the whole gradient to length exactly τ. Every weight is scaled by the same factor, so the direction is kept and only a rare very large gradient is scaled down. A smaller τ clips more steps, steadier but slower when large gradients are real; a very large τ never clips. PyTorch sets no default.

Clipping sits between backward() and opt.step(): clip_grad_norm_ rescales all gradients by one factor so their joint length is at most max_norm (τ); 1.0 is a common starting value, not a rule. To pick τ, the clipping paper suggests looking at "statistics on the average norm over a sufficiently large number of updates".

import torch
import torch.nn.utils as U
net = torch.nn.Linear(4, 1)
ps = list(net.parameters())
opt = torch.optim.SGD(ps, 0.1)
x = torch.randn(8, 4)
y = torch.randn(8, 1)
err = net(x) - y
loss = (err ** 2).mean()
loss.backward()
U.clip_grad_norm_(ps, 1.0)
opt.step()  # after the clip
  1. 1Builds a model, an optimizer and one batch.
  2. 2Computes the loss and fills the gradients.
  3. 3Gradient length capped at τ, the clipping equation.
  4. 4Steps with the clipped gradient.

Exploding gradients are most common in recurrent networks, where backpropagation through time multiplies the gradient by the same recurrent weights at every step (see Why gradients vanish or explode).

5 AdamW, a schedule and clipping in one PyTorch loop

The optimizer is built once, before the loop, and owns the parameters' buffers from then on; each batch runs forward, backward, the optional clip and opt.step(), and the scheduler changes α per batch or per epoch.

The setup builds a linear model net, AdamW, and a cosine schedule with T_max of 80 steps.

import torch
import torch.nn.utils as U
import torch.optim as optim
S = optim.lr_scheduler
net = torch.nn.Linear(8, 1)
ps = list(net.parameters())
opt = optim.AdamW(ps)  # once
Cos = S.CosineAnnealingLR
sched = Cos(opt, T_max=80)
  1. 1Builds the model and AdamW once, before the loop.
  2. 2Wraps the optimizer in a cosine schedule over 80 steps.

One update per batch, over 80 batches of 32 rows with 8 inputs and 1 target.

data = torch.randn(80, 32, 9)
for b in data:
    x, y = b[:, :8], b[:, 8:]
    err = net(x) - y
    loss = (err ** 2).mean()
    opt.zero_grad()
    loss.backward()
    U.clip_grad_norm_(ps, 1.0)
    opt.step()  # every batch
    sched.step()  # per batch
  1. 1Splits each batch into inputs and targets and computes the loss.
  2. 2Clears old gradients and fills new ones.
  3. 3Caps the gradient's total length at 1.0 before the step; Section 4.
  4. 4One optimizer update per batch.
  5. 5One schedule tick per batch.

SAM replaces the single opt.step() with its two-pass step from Section 2.

Here T_max counts batches, so the scheduler steps every batch; with T_max in epochs it steps once per epoch, after the inner loop, as in the PyTorch docs example.

PyTorch's AdamW uses a rate of 1e-3, betas of 0.9 and 0.999 and eps of 1e-8 by default (AdamW documentation), as the Adam paper suggests. SAM's official code is in JAX (google-research/sam).

  • Calling sched.step() before opt.step() skips the schedule's first value; PyTorch requires this order since version 1.1 (torch.optim documentation).
  • Saving only the model loses Adam's moments, so a resumed run restarts them at zero; save opt.state_dict() too.
