CAGrad (Conflict-Averse Gradient Descent)

Improve the task each step helps least, while still lowering the average loss.

MethodEach step, weight the tasks so the least-helped one gains most, and move the average gradient along that blend’s direction by a set fraction of its length.
GuaranteeWhile that fraction stays below 1, the average loss’s gradient provably shrinks toward zero.
CostOne backward pass per task each step, plus a small solve over the task weights.

1 What CAGrad does each step

A task’s loss measures how badly the model performs that task; its gradient points where that loss rises fastest, and training steps against it.

Each training step, CAGrad takes the gradient \(g_{i}\) of each task \(i\) over the shared weights, one entry per shared parameter, often millions (the figures draw two entries). It keeps training on the average loss and changes only the update’s direction, in three moves.

  1. It searches a ball around the average gradient, the vectors within one radius of it. The radius is a set fraction of that gradient’s length, so the ball grows and shrinks with it (Section 2).
  2. In the ball it looks for the update that most helps the least-helped task, the one whose loss drops least (Section 3).
  3. That search comes down to choosing one weight per task, each zero or more and adding up to 1, so the least-helped task gains most. The weighted task gradients add up to the weighted gradient, and the update moves from the average gradient one radius along its direction (Section 4, Section 5).

CAGrad keeps no state between steps; the official CAGrad code restarts the weight solve from equal weights each step.

2 A ball around the average gradient

The average gradient \(g_{0}\), the mean of the task gradients, can raise one task’s loss.

Searching only the ball around \(g_{0}\) keeps the update near \(g_{0}\), so the average loss still falls. \(\lVert g_{0}\rVert\) is the length of \(g_{0}\). The hyperparameter \(c\) sets the radius as a fraction of that length, so the radius is \(c\lVert g_{0}\rVert\).

With \(c\) at its smallest CAGrad is plain gradient descent (GD); at its largest it gives the direction MGDA (Multiple Gradient Descent Algorithm) picks, the shortest weighted average of the task gradients. Raising \(c\) favors the least-helped task; lowering it stays near the average.

3 The worst-case improvement objective

A candidate direction \(d\) works like a gradient: parameters move against it. A task’s improvement is how much a small step against \(d\) lowers its loss.

CAGrad looks for the step that helps its least-helped task the most, without straying far from the average gradient.
\(\displaystyle \htmlClass{eqt}{\htmlData{k=d}{\htmlStyle{color:#2c3e50}{\max_{d}}}}\; \htmlClass{eqt}{\htmlData{k=worst}{\htmlStyle{color:#2c3e50}{\min_{i}\,\langle g_{i}, d\rangle}}}\)
For a small step against \(d\), \(\langle g_{i}, d\rangle\) is approximately how much task \(i\)’s loss drops per unit of step size, its improvement. The angle brackets are the dot product: multiply the two vectors entry by entry and add. It is large when \(d\) points along \(g_{i}\), zero at right angles, and negative when the step raises task \(i\)’s loss. min over \(i\) keeps the smallest per-task improvement, the worst-case improvement. max over \(d\) picks the direction where it is largest.
\(\displaystyle \text{s.t.}\;\; \htmlClass{eqt}{\htmlData{k=ballr}{\htmlStyle{color:#2471a3}{\lVert \htmlClass{eqt}{\htmlData{k=d}{\htmlStyle{color:#2c3e50}{d}}} - \htmlClass{eqt}{\htmlData{k=g0}{\htmlStyle{color:#5d6d7e}{g_{0}}}} \rVert \le c\,\lVert \htmlClass{eqt}{\htmlData{k=g0}{\htmlStyle{color:#5d6d7e}{g_{0}}}} \rVert}}}\)
s.t. means such that. The constraint keeps \(d\) within \(c\lVert g_{0}\rVert\) of \(g_{0}\), so \(d\) stays inside the ball. While \(c\) is below 1, every direction in the ball still lowers the average loss, to first order. If some direction in the ball lowers every task’s loss, CAGrad’s choice does too; with small \(c\) none may exist, and the least-helped task’s loss can rise.
So CAGrad trades a little average progress for the worst task’s sake: when the average step would raise one task’s loss, CAGrad searches the ball for a direction whose worst-case improvement is higher.

4 Solving for one weight per task

A direction \(d\) has millions of entries, so CAGrad solves its dual problem instead: the same answer, found by searching over one weight per task. The weighted sum of the task gradients is the weighted gradient \(g_{w}\).

Instead of searching every direction, CAGrad solves for one weight per task and scores each weight list by the best value it allows.
\(\displaystyle \htmlClass{eqt}{\htmlData{k=gw}{\htmlStyle{color:#2c3e50}{g_{w}}}} = \htmlClass{eqt}{\htmlData{k=w1}{\htmlStyle{color:#8e44ad}{w_{1}}}}\htmlClass{eqt}{\htmlData{k=g1}{\htmlStyle{color:#8e44ad}{g_{1}}}} + \htmlClass{eqt}{\htmlData{k=w2}{\htmlStyle{color:#a04000}{w_{2}}}}\htmlClass{eqt}{\htmlData{k=g2}{\htmlStyle{color:#a04000}{g_{2}}}}\)
This replaces the search over directions of Section 3. \(w_{1}\) and \(w_{2}\) are the task weights. Each is zero or more, and they add up to 1. So \(g_{w}\) is a weighted average of the task gradients \(g_{1}\) and \(g_{2}\). The line shows two tasks, as in Figure 4. \(K\) is the number of tasks; in general the sum runs over all \(K\).
\(\displaystyle \htmlClass{eqt}{\htmlData{k=wstar}{\htmlStyle{color:#2c3e50}{w^{*}}}} = \operatorname{argmin}_{w \in \Delta}\, \htmlClass{eqt}{\htmlData{k=F}{\htmlStyle{color:#2c3e50}{F(w)}}}\)
\(F(w)\) is the largest value of \(\langle g_{w}, d\rangle\) over directions \(d\) in the ball. \(\langle g_{w}, d\rangle\) is a weighted average of the task improvements, so it is never below the worst one. So \(F(w)\) is an upper bound on the best worst-case improvement. \(\Delta\) is the set of allowed weights, and \(w \in \Delta\) (read \(\in\) as “is in”) says \(w\) is one of them. argmin picks the weights \(w^{*}\) with the lowest upper bound. The paper shows this bound is reached, so \(w^{*}\) also solves the search over directions.
\(\displaystyle \htmlClass{eqt}{\htmlData{k=F}{\htmlStyle{color:#2c3e50}{F(w)}}} = \langle \htmlClass{eqt}{\htmlData{k=gw}{\htmlStyle{color:#2c3e50}{g_{w}}}}, \htmlClass{eqt}{\htmlData{k=g0}{\htmlStyle{color:#5d6d7e}{g_{0}}}} \rangle\)
At the ball’s center, the direction \(g_{0}\) gives \(g_{w}\) the improvement \(\langle g_{w}, g_{0}\rangle\). This term is small when the weights favor the task \(g_{0}\) helps least. So on its own it moves the weights toward that task.
\(\displaystyle + \htmlClass{eqt}{\htmlData{k=ballr}{\htmlStyle{color:#2471a3}{c\,\lVert \htmlClass{eqt}{\htmlData{k=g0}{\htmlStyle{color:#5d6d7e}{g_{0}}}} \rVert}}}\,\lVert \htmlClass{eqt}{\htmlData{k=gw}{\htmlStyle{color:#2c3e50}{g_{w}}}} \rVert\)
Moving the full radius \(c\lVert g_{0}\rVert\) along \(g_{w}\) adds the radius times the length of \(g_{w}\). This term favors short weighted gradients. As \(c\) grows it dominates, and \(w^{*}\) approaches the weights of the shortest weighted gradient, MGDA’s choice.
So the weights say which task the step must lean toward: the weight moves onto the task the average step helps least, and \(F(w^{*})\) is the best worst-case improvement the ball allows.

\(G\) holds one task gradient per row. solve_weights takes the Gram matrix GG (the \(K \times K\) table of dot products between task gradients) and \(c\) and returns \(w^{*}\).

import numpy as np
from scipy import optimize

def F(w, GG, c):
    g0_len = np.sqrt(GG.mean())
    center = w @ GG.mean(axis=1)
    gw_sq = max(w @ GG @ w, 0.0)
    gw_len = np.sqrt(gw_sq)
    ball = c * g0_len * gw_len
    return center + ball

CONSTRAINT = {"type": "eq", "fun": lambda w: w.sum() - 1}

def solve_weights(GG, c):
    K = len(GG)
    res = optimize.minimize(F, np.full(K, 1 / K), args=(GG, c), method="SLSQP",
                            bounds=[(0, 1)] * K, constraints=CONSTRAINT)
    return res.x

5 The CAGrad update

The step starts at the average gradient and moves one full radius along the solved blend’s direction.
\(\displaystyle \htmlClass{eqt}{\htmlData{k=ds}{\htmlStyle{color:#2c3e50}{d^{*}}}} = \htmlClass{eqt}{\htmlData{k=g0}{\htmlStyle{color:#5d6d7e}{g_{0}}}}\)
\(w^{*}\) is the weight solve of Section 4. \(d^{*}\) is the update direction, the star marking a solved quantity. It starts at the ball’s center, \(g_{0}\).
\(\displaystyle + \htmlClass{eqt}{\htmlData{k=ballr}{\htmlStyle{color:#2471a3}{c\,\lVert \htmlClass{eqt}{\htmlData{k=g0}{\htmlStyle{color:#5d6d7e}{g_{0}}}} \rVert}}}\, \htmlClass{eqt}{\htmlData{k=ds}{\htmlStyle{color:#2c3e50}{\frac{g_{w}^{*}}{\lVert g_{w}^{*} \rVert}}}}\)
The fraction is \(g_{w}^{*}\), the weighted gradient built from \(w^{*}\), divided by its own length, so only its direction counts. Multiplied by the radius \(c\lVert g_{0}\rVert\), the step is exactly one radius long, so \(d^{*}\) lands on the ball’s edge. On the pair Figure 3 draws, this \(d^{*}\) is the point on the ring where the least-helped task gains most. The exception is a \(g_{w}^{*}\) of length zero, where the weighted task gradients cancel. That point is Pareto stationary: no small step lowers every task’s loss at once.
So the step keeps the average gradient as its base and spends one radius on the least-helped task, which raises the worst-case improvement.

Continuing from the solver of Section 4, this code turns \(w^{*}\) into \(d^{*}\).

g_w = w_star @ G  # optimal g_w
g0 = G.mean(axis=0)
radius = c * np.linalg.norm(g0)
EPS = TINY_GUARD  # zero-length guard

gw_len = np.linalg.norm(g_w)
unit = g_w / (gw_len + EPS)
d_star = g0 + radius * unit

  2. 2The center \(g_{0}\), line 1 of the update in Section 5, and the radius \(c\lVert g_{0}\rVert\), line 2.
  3. 3The fraction in line 2, guarded against length zero.
  4. 4One radius out to \(d^{*}\), which for this pair is the best point on the ring in Figure 3 and where step 4 of Figure 5 ends.

7 Convergence guarantee

CAGrad provably reaches a stationary point of the average loss (zero gradient, possibly a saddle point), assuming \(H\)-Lipschitz gradients (the gradient changes at most \(H\) times as fast as the parameters), a loss bounded below, and a step size \(\alpha\) no larger than 1 divided by \(H\).

Summed over all steps, the average gradient’s squared length stays below a fixed bound, so CAGrad still converges on the average loss.
\(\displaystyle \sum_{t=0}^{T} \lVert \nabla L_{0}(\theta_{t}) \rVert^{2}\)
This sums the squared length of the average gradient while the update of Section 5 runs every step; \(c\) is the radius factor of Section 2. \(L_{0}\) is the average loss and \(\theta_{t}\) the parameters at step \(t\), so \(\nabla L_{0}(\theta_{t})\) is the average gradient at step \(t\); the double bars squared give its squared length. \(\textstyle\sum\) adds these over steps \(t\) from 0 to \(T\).
\(\displaystyle \le \frac{2\,\bigl(L_{0}(\theta_{0}) - L_{0}^{*}\bigr)}{\alpha\,(1 - c^{2})}\)
\(L_{0}^{*}\) is the lowest the average loss can go. Only a \(c\) below 1 keeps the denominator positive. The bound stays fixed as \(T\) grows, so the average gradient’s length must shrink toward zero. A larger \(c\) raises the bound; that is the cost of favoring the least-helped task.
So caring for the least-helped task costs only a constant factor in convergence: the \(1 - c^{2}\) in the denominator, which is largest for plain gradient descent and shrinks as \(c\) grows.
  1. Other proofs are weaker. MGDA proves only a Pareto-stationary end point; PCGrad, which removes the part of each task gradient that conflicts with another task’s, has a proof that covers two tasks with convex (bowl-shaped) losses.
  2. Past a certain size of \(c\), the guarantee is gone. The update can then settle where the average loss’s gradient is not zero, at a point that is only Pareto stationary.

10 When to use CAGrad, and its cost

  1. Use it when task gradients conflict and the average loss still matters.
  2. Time per step is \(K\) backward passes plus the small solve. CAGrad-Fast keeps the guarantee while sampling a random task subset per step. Sampling a few tasks per step cuts the backward passes from one per task to one per sampled task plus the average, so the speedup grows with the number of tasks.
  3. Memory holds \(K\) flattened shared gradients plus each task’s computation graph (what autograd keeps for a backward pass).

11 CAGrad in a PyTorch training step

Builds on per-task gradients in one step (Gradient Balancing Inside the Training Loop, Section 3), SGD and mini-batches (SGD, Momentum and Nesterov, Section 1) and Adam (Adaptive Optimizers: AdaGrad, RMSProp and Adam, Section 4)

The listing stacks the task gradients into \(G\) (Section 3 of Gradient Balancing Inside the Training Loop shows how each is computed), calls solve_weights (Section 4), and writes \(d^{*}\) into the .grad of body, the shared backbone’s parameters. heads, each task’s output layers, get the average loss’s gradient.

import torch
from torch.nn.utils import clip_grad_norm_

c = RADIUS  # the ball radius, kept below the full step
EPS = TINY_GUARD  # zero-length guard

def flat_grad(loss, body):
    grads = torch.autograd.grad(loss, body, retain_graph=True)
    return torch.cat([g.ravel() for g in grads])

def fill_grads(params, vec):
    i = 0
    for p in params:
        n = p.numel()
        part = vec[i:i + n]
        p.grad = part.view_as(p)
        i += n

def cagrad(losses, parts, opt):
    body, heads = parts
    K = len(losses)
    rows = [flat_grad(L, body) for L in losses]
    G = torch.stack(rows)  # K x P
    GG = (G @ G.T).cpu().numpy()
    w_star = solve_weights(GG, c)
    w = torch.tensor(w_star).to(G)
    g0 = G.mean(dim=0)
    g_w = w @ G
    gw_len = g_w.norm()
    unit = g_w / (gw_len + EPS)
    radius = c * g0.norm()
    d_star = g0 + radius * unit
    opt.zero_grad()
    fill_grads(body, d_star)
    avg = sum(losses) / K
    avg.backward(inputs=heads)
    clip_grad_norm_(body + heads, max_norm=CLIP_CAP)
    opt.step()
  1. 1One task’s body gradient \(g_{i}\), line 1 of the objective in Section 3, as one row of \(G\).
  2. 2Writes a flat vector into the .grad of body, which box 5 of Figure 10 reads.
  3. 3One backward pass per task, box 2 of Figure 10, stacked into \(G\).
  4. 4GG and \(w^{*}\), the solver of Section 4.
  5. 5\(d^{*}\), the update of Section 5.
  6. 6\(d^{*}\) to the body, the average loss’s gradient to the heads, clip, step (Figure 10).

Global-norm clipping rescales all gradients together when their combined length exceeds max_norm, keeping their direction. A larger max_norm clips less often, a huge one never. A modest cap is a common choice, not from the CAGrad paper. Gradient Balancing Inside the Training Loop compares other clipping types.

  • Log each task’s unweighted loss and its improvement \(\langle g_{i}, d^{*}\rangle\). The smallest marks the least-helped task.
  • Each kept graph costs memory. retain_graph=True keeps every task’s graph in memory; the final backward pass, for the heads, frees them all.
  • Many tasks need a different solver. For many tasks the official README suggests writing the weights as a softmax of free numbers (positive, adding up to 1) and taking a few SGD steps on them. The official Meta-World code does this, taking a few SGD steps on them per training step.
  • Implementations differ. The official NYUv2 code divides the update by a factor that grows with c squared and multiplies by \(K\), the toy code divides by a factor that grows with c, and LibMTL rescales by default; this page uses none. Under Adam a constant scale barely matters; under SGD it rescales the learning rate.

The official CAGrad repository holds the paper’s code; LibMTL, an open-source PyTorch multitask library, ships it as --weighting CAGrad.

12 Comparison with other multitask methods

Reweight the losses when task gradients differ in size; edit the direction when they conflict.

MethodThe question it answers
GradNormHow much weight should each task's loss get so all tasks train at a similar rate? (learned during training from how fast each loss falls)
Uncertainty WeightingHow much weight should each task's loss get, given how noisy that task's targets are? (the noise level is learned along with the model)
PCGradHow should a task gradient be edited when it conflicts with another task's gradient?
GradVacHow should each pair of task gradients be moved toward a target cosine, a running average of that pair's past cosines?
CAGrad (this page)How can a step raise the smallest per-task improvement while staying near the average gradient?
MGDAWhich convex combination of task gradients (a weighted average whose weights are zero or more and add up to 1) lowers every task's loss at once, and when does no such combination exist?
