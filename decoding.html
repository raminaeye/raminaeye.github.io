1 One token at a time

A support-chat assistant has just read My order has not arrived and starts its reply. It does not write the reply in one go. At every step the decoder network of The Transformer Block gives one score to every token in its vocabulary, the word pieces of Tokenizers. Decoding is the rule that turns those scores into the one token written next. The token is appended to the reply, and the loop runs again.

It runs once for every generated token, and only when the model writes text. Ordinary training never decodes, because the loss reads the true next token from the data. The exception is RL fine-tuning in Aligning Language Models with RL, where the model samples its own replies while it trains.

The chooser comes in two families. A search looks for the likeliest reply and gives the same reply every time: Beam Search, with greedy decoding as its simplest case. A draw picks a token at random with its own chance, so the same question can get two different answers: Sampling the Next Token.

2 From the model’s scores to probabilities

The last layer gives one raw score, a logit, for every entry of the vocabulary at every step. Logits are any real numbers and do not add up to anything, so they are not chances yet. Softmax over the whole vocabulary turns them into chances. The shape it makes is a categorical distribution, taught in Bernoulli, Categorical and Uniform Distributions; here it matters only as the input every chooser reads.

Each token’s chance is its exponentiated score as a share of the total over the vocabulary, and subtracting the top score first keeps the sum from overflowing.

(1)\(\displaystyle {\htmlClass{eqt sym-p}{\htmlStyle{color:#1e8449}{p_i}} = \frac{e^{\htmlClass{eqt sym-z}{\htmlStyle{color:#1f6aa5}{z_i}}}}{\sum_{j=1}^{V} e^{\htmlClass{eqt sym-z}{\htmlStyle{color:#1f6aa5}{z_j}}}}}\)
Start from the reply: the assistant needs one chance per possible next token. \(z_i\) is the logit of token \(i\) and \(V\) the vocabulary size. The exponential makes every score positive, even a negative one, and stretches the gaps between large scores. Dividing by the total over every token makes the chances \(p_i\) add up to one. Every token is divided by the same total, so the order of the scores is kept.
(2)\(\displaystyle {\begin{aligned}\htmlClass{eqt sym-p}{\htmlStyle{color:#1e8449}{p_i}} &= \frac{e^{\htmlClass{eqt sym-z}{\htmlStyle{color:#1f6aa5}{z_i}} - \htmlClass{eqt sym-m}{\htmlStyle{color:#7d3c98}{m}}}}{\sum_{j} e^{\htmlClass{eqt sym-z}{\htmlStyle{color:#1f6aa5}{z_j}} - \htmlClass{eqt sym-m}{\htmlStyle{color:#7d3c98}{m}}}} \\ \htmlClass{eqt sym-m}{\htmlStyle{color:#7d3c98}{m}} &= \max_j \htmlClass{eqt sym-z}{\htmlStyle{color:#1f6aa5}{z_j}}\end{aligned}}\)
A very large logit makes the exponential overflow, and infinity over infinity is not a number. \(m\) is the largest score. Subtracting it from every score divides top and bottom by the same amount, so each chance is unchanged, and the biggest term becomes exactly one (Goodfellow et al. 2016, section 4.1). Line 1 says what softmax computes; line 2 is how libraries compute it safely.

The same softmax picks the weights in Attention and feeds the loss in Cross-Entropy Loss. Temperature reshapes exactly this step, by dividing the scores before the softmax: Sampling the Next Token, the temperature section.

3 The generate loop

Each turn of the loop does five things: run the model on the conversation so far, take the scores at the last position, turn them into chances, let the chooser pick one token, and append it. The loop stops when the chooser picks the end token or when the reply reaches a length limit. Each step reuses the keys and values of earlier tokens instead of recomputing them; The KV Cache explains how.

4 The tool: one loop, different choosers

Step through one turn of the loop with the arrows; the last step appends the token and goes round again. Switch the chooser to see the same loop write a different reply.

Greedy always takes the longest bar. Beam search sometimes takes a shorter bar because the reply it leads to scores better as a whole; Beam Search, the walkthrough shows how it keeps several replies at once. Sampling draws, so every new draw can give a new reply.

5 Search or sample: which job wants which

A task with one right answer wants the likeliest reply. Open-ended writing wants text that varies but stays on topic. Holtzman et al. (2020) measured both sides: GPT-2 Large wrote 5,000 passages of web text with each method, scored by perplexity (how surprised the model is by the text; human text sits in the middle) and by the share of passages stuck in a loop.

jobfamilywhy
translation, summarization, speech recognitionBeam Searchthe input pins the answer down, so the likeliest reply is the right one
chat, stories, brainstormingSampling the Next Token, temperature with top-p or min-pmany replies are good, and the likeliest one loops or reads flat

6.2 Calling generate

Hugging Face generate runs the whole loop; the arguments choose the chooser.

from transformers import AutoModelForCausalLM, AutoTokenizer

tok = AutoTokenizer.from_pretrained(MODEL_NAME)
model = AutoModelForCausalLM.from_pretrained(MODEL_NAME)
ids = tok("My order has not arrived.", return_tensors="pt").input_ids

greedy = model.generate(ids, max_new_tokens=LIMIT, do_sample=False)

beam = model.generate(ids, max_new_tokens=LIMIT, num_beams=WIDTH)

sampled = model.generate(ids, max_new_tokens=LIMIT, do_sample=True,
                         temperature=TAU, top_p=P_TOP)
print(tok.decode(sampled[0], skip_special_tokens=True))
