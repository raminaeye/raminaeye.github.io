1 Unigram starts big and prunes

BPE and WordPiece give each word one split, fixed by the order of their merges. The Unigram tokenizer (Kudo, 2018) instead gives every piece in its vocabulary a probability and scores every way to split a word, so it can pick the most probable split, or draw a different one while the model trains (Reference 1).

It also builds the vocabulary the other way round. Training starts from a huge list of candidate pieces and removes, round by round, the pieces the corpus would miss least, until the target size is left. Like BPE it trains once, before the model; splitting runs on every text, and sampling is used only during model training.

2 Splitting with piece probabilities

A word can be cut many ways. Draw the positions between its letters as dots and each vocabulary piece as an arc between two dots: every split is then a path from the left edge to the right edge.

Score a split by multiplying its piece probabilities, then keep the best split.

\(\displaystyle \htmlClass{eqt sym-p}{\htmlStyle{color:#1e8449}{P(\mathbf{x})}} = \prod_{i=1}^{n} p(x_i)\)
A split \(\mathbf{x}\) cuts the word into \(n\) pieces \(x_1\) to \(x_n\), and \(p(x_i)\) is the probability of piece \(x_i\). The pieces are treated as independent draws, which is what “unigram” means, so the split’s probability is their product. Every extra piece multiplies in a number below one, so splits into fewer, likelier pieces win.
\(\displaystyle \mathbf{x}^{*} = \operatorname*{arg\,max}_{\mathbf{x}\in\mathcal{S}(X)} \htmlClass{eqt sym-p}{\htmlStyle{color:#1e8449}{P(\mathbf{x})}}\)
\(\mathcal{S}(X)\) is the set of all splits of the word \(X\), every path in Figure 2. The tokenizer returns the split \(\mathbf{x}^{*}\) with the highest probability.
\(\displaystyle \log \htmlClass{eqt sym-p}{\htmlStyle{color:#1e8449}{P(\mathbf{x})}} = \sum_{i=1}^{n} \log p(x_i)\)
The log turns the product into a sum (Maximum Likelihood Estimation). Each arc now carries a score that adds along the path, so the best split is the best-scoring path through the lattice, and the next section finds it without listing every path.

3 Finding the best split with Viterbi

A long word has a huge number of splits. The Viterbi algorithm walks the word left to right and, at each position, keeps only the best way to reach it: the best path into a position must end with some piece, and everything before that piece must itself be the best path to where the piece starts. This is the same idea as Viterbi in hidden Markov models, with positions in place of time steps.

start

\(\displaystyle \log \htmlClass{eqt sym-p}{\htmlStyle{color:#1e8449}{P(\mathbf{x})}} = \sum_{i=1}^{n} \log p(x_i)\)
Scores add along a path, so the best path into a position is the best path to some earlier position plus one more piece.
\(\displaystyle \mathbf{x}^{*} = \operatorname*{arg\,max}_{\mathbf{x}\in\mathcal{S}(X)} \htmlClass{eqt sym-p}{\htmlStyle{color:#1e8449}{P(\mathbf{x})}}\)
The kept arcs followed back from the end spell the highest-probability split.

Figure 3. Viterbi on unbroken, one position per step. Piece probabilities are illustrative.

Code 1 is Viterbi over a trained model’s piece scores, which SentencePiece stores as log probabilities.

import math
import sentencepiece as spm

def viterbi(word, logp):
    n = len(word)
    best, back = [0.0] + [-math.inf] * n, [None] * (n + 1)
    for end in range(1, n + 1):
        for start in range(end):
            piece = word[start:end]
            if piece in logp and best[start] + logp[piece] > best[end]:
                best[end] = best[start] + logp[piece]
                back[end] = start
    if back[n] is None:
        return None
    pieces, end = [], n
    while end > 0:
        start = back[end]
        pieces.append(word[start:end])
        end = start
    return pieces[::-1]

sp = spm.SentencePieceProcessor(model_file="tok.model")
logp = {sp.id_to_piece(i): sp.get_score(i) for i in range(sp.get_piece_size())}
print(viterbi("▁unbroken", logp))

  2. 2Line 3 of the card: a path’s score is an earlier best plus one piece’s log probability.
  3. 3Line 2: following the kept starts back from the end reads the best split; if no piece reaches the end, there is no split.
  4. 4A real model’s pieces and their log probabilities. Its pieces mark the space before a word with ▁, so the word is looked up as ▁unbroken, explained in SentencePiece Toolkit.

4 Training by pruning

Training needs a seed list and a way to judge each piece. The seed is every character plus the corpus’s most frequent substrings, found with a suffix array, a sorted index of every substring; SentencePiece keeps up to 1,000,000 seed pieces by default, seed_sentencepiece_size (References 1, 3). Then one loop repeats: fit the piece probabilities to the corpus, then drop the pieces the corpus misses least.

How well the vocabulary explains the corpus, and how much each piece is worth.

\(\displaystyle \htmlClass{eqt sym-l}{\htmlStyle{color:#7d3c98}{\mathcal{L}}} = \sum_{s=1}^{|D|} \log \Big( \sum_{\mathbf{x}\in\mathcal{S}(X^{(s)})} \htmlClass{eqt sym-p}{\htmlStyle{color:#1e8449}{P(\mathbf{x})}} \Big)\)
\(D\) is the corpus, \(|D|\) its number of sentences, and \(X^{(s)}\) its sentence \(s\). For each sentence, add the probability of every way to split it, take the log, and sum over sentences. A good vocabulary makes \(\mathcal{L}\) large. Expectation maximization sets the piece probabilities to make it largest: the E step weighs every split of each sentence by its probability and adds up how often each piece is expected to be used (2 in Figure 4), and the M step sets each piece’s probability to its share of those expected uses (3).
\(\displaystyle \htmlClass{eqt sym-d}{\htmlStyle{color:#a85a14}{\Delta_i}} = \htmlClass{eqt sym-l}{\htmlStyle{color:#7d3c98}{\mathcal{L}}} - \htmlClass{eqt sym-l}{\htmlStyle{color:#7d3c98}{\mathcal{L}_{-i}}}\)
\(\mathcal{L}_{-i}\) is the same likelihood with piece \(i\) removed, so \(\Delta_i\) is what the corpus loses without it. A piece whose words split almost as well without it has a small loss. Each round keeps the share \(\eta\) of pieces with the largest loss and always keeps single characters (4 in Figure 4).

The paper’s example keeps \(\eta\) at 80% each round, and SentencePiece’s shrinking_factor defaults to 0.75 (References 1, 3). A share close to one prunes gently over many rounds; a smaller one prunes hard in few. The cost is training time: each round runs EM over the whole corpus and then estimates each piece’s loss, where BPE only counts adjacent pairs.

5 Sampling a different split each time

While the model trains, the Unigram paper draws a different split of each sentence every time it is seen, instead of always the best. The model meets the same word cut many ways and becomes more robust to rare words and noise; the paper calls this subword regularization. Once training is over, the tokenizer returns the single best split \(\mathbf{x}^{*}\) again. BPE has its own version, BPE-dropout (Reference 7).

Each split’s chance of being drawn, sharpened by \(\alpha\).

\(\displaystyle P(\mathbf{x}\mid X) = \frac{\htmlClass{eqt sym-p}{\htmlStyle{color:#1e8449}{P(\mathbf{x})}}^{\htmlClass{eqt sym-r}{\htmlStyle{color:#c0392b}{\alpha}}}}{\sum_{\mathbf{x}'\in\mathcal{S}_l(X)} \htmlClass{eqt sym-p}{\htmlStyle{color:#1e8449}{P(\mathbf{x}')}}^{\htmlClass{eqt sym-r}{\htmlStyle{color:#c0392b}{\alpha}}}}\)
Raise each split’s probability to the power \(\alpha\) and divide by the total over the candidate splits, so the chances add to one, a categorical distribution over splits. \(\mathcal{S}_l(X)\) is the \(l\) best splits, or every split when SentencePiece’s nbest_size is set to minus one. A small \(\alpha\) flattens the chances so many splits appear; a large \(\alpha\) hands almost every draw to the best split.

The paper’s experiments use \(\alpha\) between 0.1 and 0.5; the SentencePiece README uses 0.1 (References 1, 4).

7 Unigram in practice

A trained Unigram model is a list of pieces with a log probability each, and no merge list. Splitting runs Viterbi over the text, sampling runs the same lattice with random draws. SentencePiece trains it by default, and T5 is among the models whose vocabulary was trained this way (References 2, 5).

Code 2 trains a Unigram vocabulary with Hugging Face tokenizers (Reference 6), then with SentencePiece, and draws a sampled split.

from tokenizers import Tokenizer, models, pre_tokenizers, trainers, decoders

tokenizer = Tokenizer(models.Unigram())
tokenizer.pre_tokenizer = pre_tokenizers.Metaspace()
trainer = trainers.UnigramTrainer(
    vocab_size=8000,
    special_tokens=["<unk>"],
    unk_token="<unk>",
    shrinking_factor=0.75,
)
tokenizer.train(["corpus.txt"], trainer=trainer)
tokenizer.decoder = decoders.Metaspace()

import sentencepiece as spm
spm.SentencePieceTrainer.train(input="corpus.txt", model_prefix="tok", vocab_size=8000, model_type="unigram")
sp = spm.SentencePieceProcessor(model_file="tok.model")
print(sp.encode("unbroken tokenizers", return_type=str))
print(sp.encode("unbroken tokenizers", return_type=str, enable_sampling=True, alpha=0.1, nbest_size=-1))  # out_type= before v0.2.2

  3. 3The same algorithm through SentencePiece, its default model type (SentencePiece Toolkit).
  4. 4The best split, then a sampled one with \(\alpha\) set as in the README, over every split.
