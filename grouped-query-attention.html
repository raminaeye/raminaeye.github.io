Multi-Query and Grouped-Query Attention

Every query head keeps its own question, but groups of heads share one stored key head and one value head, so the KV cache shrinks and decoding speeds up.

The KV cache stores a key and a value for every head of every layer, and each decode step reads all of it, so memory bandwidth sets the speed. Sharing stored heads cuts what there is to read.

1 Query heads can share keys and values

Multi-query attention (MQA, Shazeer 2019) keeps all \(h\) query heads but stores one key head and one value head. Grouped-query attention (GQA, Ainslie et al. 2023) splits the query heads into \(g\) groups, each sharing one key head and one value head.

Head \(i\) reads the stored head of its group.
\({\displaystyle \htmlClass{eqt sym-s}{\htmlStyle{color:#9a6400}{s_i}}=\frac{\htmlClass{eqt sym-q}{\htmlStyle{color:#7d3c98}{Q_i}}\,\htmlClass{eqt sym-k}{\htmlStyle{color:#a04000}{K_{\gamma(i)}}}^{\top}}{\sqrt{d_k}}}\)
Picture Mistral 7B answering a chat message. Each of the \(h\) query heads asks its own question \(Q_i\) and scores it against the keys of its group, \(\gamma(i)\). \(d_k\) is the number of entries in each key; dividing by its square root keeps the scores from growing with the head size.
\({\displaystyle o_i=\mathrm{softmax}(\htmlClass{eqt sym-s}{\htmlStyle{color:#9a6400}{s_i}})\,\htmlClass{eqt sym-k}{\htmlStyle{color:#a04000}{V_{\gamma(i)}}}}\)
The weights then average the group's values into \(o_i\), the output of head \(i\). This is the per-head attention of multi-head attention with the key and value heads shared.
\({\displaystyle \htmlClass{eqt sym-gam}{\htmlStyle{color:#a04000}{\gamma(i)}}=\left\lfloor \frac{i}{\htmlClass{eqt sym-h}{\htmlStyle{color:#7d3c98}{h}}/\htmlClass{eqt sym-g}{\htmlStyle{color:#a04000}{g}}}\right\rfloor}\)
Heads are counted from 0, and each run of \(h/g\) consecutive query heads forms one group: \(i\) divided by \(h/g\), rounded down. With \(g\) equal to \(h\) every head is its own group, plain multi-head attention; with one group it is MQA.
query headsshared key and value headsscores

Sharing costs little quality because the query heads still ask different questions: each head still weights the past tokens its own way. What is lost is the number of distinct ways the past tokens are summarized as keys and values, and the GQA paper found a few groups keep most of that.

The paper gives a second reason for groups over one shared head. Large models split each layer's heads across several chips, and with MQA the single key and value head has to be copied onto every chip, so part of the saving is wasted; with one group per chip nothing is copied. As models grow they add heads, so one shared head is an ever more aggressive cut, while a fixed share of groups keeps the cut in proportion. 

import torch
import torch.nn.functional as F

sdpa = F.scaled_dot_product_attention
B, T, d_k = 1, 16, 64
h, g = 8, 2  # query heads, KV heads
Q = torch.randn(B, h, T, d_k)
K = torch.randn(B, g, T, d_k)  # the cache stores g heads
V = torch.randn(B, g, T, d_k)

per_group = h // g
K_rep = K.repeat_interleave(per_group, dim=1)  # temporary
V_rep = V.repeat_interleave(per_group, dim=1)
out = sdpa(Q, K_rep, V_rep, is_causal=True)
print(out.shape)  # torch.Size([1, 8, 16, 64])
  1. 1Eight query heads, but only two stored key and value heads.
  2. 2Each stored head is repeated for the consecutive query heads of its group, the group line of the first card, then attention runs as usual.

2 The cache shrinks to g over h

Mistral 7B has 32 query heads and 8 key-value heads, so each stored head serves a group of query heads.

How much of the multi-head cache grouped-query attention keeps.
\({\displaystyle \text{cache}_{\text{GQA}}=\frac{\htmlClass{eqt sym-g}{\htmlStyle{color:#a04000}{g}}}{\htmlClass{eqt sym-h}{\htmlStyle{color:#7d3c98}{h}}}\,\text{cache}_{\text{MHA}}}\)
Here \(\text{cache}_{\text{MHA}}\) is the multi-head cache, one stored head per query head. The cache is proportional to the stored heads \(h_{kv}\) in the cache-size card of The KV Cache, and GQA stores \(g\) heads instead of \(h\). Fewer groups, smaller cache, less to read every step.

3 Turning a multi-head model into GQA

A trained multi-head model can be converted instead of trained again. The GQA paper mean-pools each group's key and value projection heads, which it found works better than keeping one head or starting fresh, then trains a small extra fraction of the original run.

Uptraining starts each shared head as an average.
\({\displaystyle \htmlClass{eqt sym-k}{\htmlStyle{color:#a04000}{K_{\gamma}}}=\frac{\htmlClass{eqt sym-g}{\htmlStyle{color:#a04000}{g}}}{\htmlClass{eqt sym-h}{\htmlStyle{color:#7d3c98}{h}}}\sum_{i\in\gamma}\htmlClass{eqt sym-ko}{\htmlStyle{color:#d35400}{K_i}}}\)
The sum runs over the \(h/g\) query heads of group \(\gamma\), and \(g\) over \(h\) turns it into their average.
\({\displaystyle \htmlClass{eqt sym-k}{\htmlStyle{color:#a04000}{V_{\gamma}}}=\frac{\htmlClass{eqt sym-g}{\htmlStyle{color:#a04000}{g}}}{\htmlClass{eqt sym-h}{\htmlStyle{color:#7d3c98}{h}}}\sum_{i\in\gamma}\htmlClass{eqt sym-ko}{\htmlStyle{color:#d35400}{V_i}}}\)
Applied to the key and value projection weights: each shared head starts as the average of the \(h/g\) heads it replaces. The converted model starts close to the original, and a short extra training run recovers the rest.

5 Sharing heads trades a little quality for much faster decoding

The cache shrinks in proportion to \(g\). GQA with 8 groups scores close to multi-head, while MQA scores lower. Time per sample rises only modestly from 1 to 8 groups and more steeply after that.

7 Choosing the number of groups

import torch
import torch.nn.functional as F

B, T, d_k, h, g = 1, 16, 64, 8, 2
q = torch.randn(B, h, T, d_k)
K = torch.randn(B, g, T, d_k)  # g stored heads
V = torch.randn(B, g, T, d_k)
out = F.scaled_dot_product_attention(q, K, V, is_causal=True, enable_gqa=True)
  1. 1The cache holds only the \(g\) shared heads, the cache line of section 2.
  2. 2enable_gqa=True lets each group of query heads read its shared head with no copies made.
WhenFixed in the architecture, chosen before training or at uptraining, in every layer it applies to; the cache keeps \(g/h\) of the multi-head size.
Groups \(g\)More groups approach multi-head quality, fewer approach MQA speed. One group is MQA; \(h\) groups is multi-head. The GQA paper chose 8.

Fewer heads shrink each token's entry; a long conversation still adds entries forever. What if the model only looked back a fixed distance? Sliding-Window Attention.
