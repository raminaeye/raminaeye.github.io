Random Forests

Many deep trees, each grown on its own resample of the data with a random subset of features per split, vote; the votes average away each tree’s quirks.

1 Why one tree is not enough

A deep decision tree fits its training windows closely, so it has low bias, but a small change in those windows gives a different tree (Where trees break, the instability row). That is high variance. Figure 1 grows three deep trees on three resamples of the same smartphone activity windows: each boundary is jagged in its own place, and their average is smoother than any of them.

A random forest turns that average into a model: resample the windows, grow one deep tree per resample, let the trees vote, and test each tree on the windows its resample left out. Sections 2 to 6 take those four steps in order.

The \(B\) trees are grown once each and independently, so they train in parallel (n_jobs); nothing is carried from one tree to the next. Prediction runs \(B\) root-to-leaf paths and averages them. The out-of-bag score is computed once after training, from the windows each tree left out.

2 Bagging: one tree per resample

A bootstrap resample draws as many windows as the data holds, with replacement: some windows are drawn twice, most once, and about a third are never drawn. Each tree is grown on its own resample. Breiman (1996) called this bagging, short for bootstrap aggregating.

Now a forest of trees each looks at one new window and calls it moving or still. The card below turns those calls into one answer.

Each tree casts one vote; the forest reports the share of trees saying moving and calls the majority.
\(\displaystyle \htmlStyle{color:#7d6608}{v(x)} = \frac{1}{B} \sum_{t=1}^{B} \htmlStyle{color:#196f3d}{h_t(x)}\)
\(h_t(x)\) is tree \(t\)’s call on window \(x\), 1 for moving and 0 for still, so \(v(x)\) is the share of the \(B\) trees voting moving. Each tree is grown by the split rule of Impurity and information gain.
\(\displaystyle \hat{y}(x) = \begin{cases} 1 & \htmlStyle{color:#7d6608}{v(x)} > \tfrac{1}{2} \\ 0 & \text{otherwise} \end{cases}\)
The forest says moving when more than half the trees do, a majority vote. scikit-learn averages each tree’s class probabilities instead, a soft vote, which usually agrees.
So the forest’s answer is the share of trees saying moving, read against one half; a share near one half means the trees disagree and the call is uncertain.

A forest by hand, each tree on its own bootstrap sample idx; X, y are training windows and Xte held-out windows.

import numpy as np
from sklearn.tree import DecisionTreeClassifier
Tree = DecisionTreeClassifier
rng = np.random.default_rng(0)
B, n = 100, len(X)
trees = []
for t in range(B):
    idx = rng.integers(0, n, n)
    h = Tree(max_features="sqrt")
    h.fit(X[idx], y[idx])
    trees.append(h)
P = [h.predict(Xte) for h in trees]
v = np.mean(P, axis=0)
y_hat = (v > 0.5).astype(int)
  1. 1Sets the number of trees \(B\).
  2. 2Fits each deep tree on its own bootstrap sample, with a random subset of features per split (Section 3).
  3. 3The vote share \(v\) of line 1 and the majority call of line 2.

3 Random features make the trees disagree

Averaging only helps when the trees make different mistakes. If one feature is strong, every bagged tree puts it at the root, the trees grow alike, and averaging near-copies barely helps. The card below says how much the trees’ likeness limits the average.

Builds on independence and correlation (Probability)

More trees remove only the part of the variance where trees disagree; the part they share stays, so the trees must be made less alike.
\(\displaystyle \operatorname{Var}\!\left[\frac{1}{B}\sum_{t=1}^{B} \htmlStyle{color:#196f3d}{h_t(x)}\right] = \htmlStyle{color:#a04000}{\rho}\,\htmlStyle{color:#117864}{\tau^2} + \frac{1-\htmlStyle{color:#a04000}{\rho}}{B}\,\htmlStyle{color:#117864}{\tau^2}\)
Each tree’s prediction swings by the same amount \(\tau^2\) as its training sample changes (the Elements of Statistical Learning, section 15.2, writes this \(\sigma^2\)), and \(\rho\) is how alike two trees’ swings are. More trees shrink only the second term. The first term stays as a floor, so lowering \(\rho\) is the only way under it.
\(\displaystyle \htmlStyle{color:#6c3483}{m} = \left\lfloor \sqrt{d} \right\rfloor\)
At each split only \(m\) of the \(d\) features, drawn at random, may be chosen. That lowers \(\rho\) in line 1 while keeping each tree reasonably strong. This is scikit-learn’s classifier default, max_features="sqrt"; \(m = d\) gives plain bagging. Raising \(m\) makes trees stronger but more alike; lowering it makes them more different but weaker. Breiman (2001, section 1.2) found results insensitive to this number, with one or two features often near best.
So a forest has two levers on its variance: more trees, which shrink the second term, and fewer features per split, which lower the floor.

6 Out-of-bag error: a free test set

Each tree never saw the windows its resample left out, so those windows can grade that tree, like a held-out set that costs nothing.

About a third of the windows are left out of each tree’s sample, and those windows test the trees that never saw them.
\(\displaystyle P(\text{window } i \text{ left out}) = \left(1 - \frac{1}{N}\right)^{N}\)
Each of the \(N\) draws misses window \(i\) with chance \(1 - 1/N\). The draws are independent, so the misses multiply.
\(\displaystyle \left(1 - \frac{1}{N}\right)^{N} \;\longrightarrow\; e^{-1} \quad (N \to \infty)\)
More draws and a smaller miss chance nearly cancel, so whatever the data size a little over a third of the windows are left out of each tree’s sample.
\(\displaystyle \text{err}_{\text{OOB}} = \frac{1}{N} \sum_{i=1}^{N} \mathbf{1}\!\left[\hat{y}_{\text{OOB}}(x_i) \neq y_i\right]\)
\(\hat{y}_{\text{OOB}}(x_i)\) is the vote of Section 2, line 2, taken only over trees whose sample left out window \(i\), and \(\mathbf{1}[\cdot]\) counts one for each wrong call. Every window is graded only by trees that never saw it, so the error estimates test error with no held-out set.
So the forest grades itself: each window is a test window for roughly a third of the trees, and their vote on it counts toward the out-of-bag error.

Press Play on Tool 1 again and watch the out-of-bag line settle onto the test line. In scikit-learn the forest keeps those votes when asked:

from sklearn.ensemble import RandomForestClassifier as RF
rf = RF(n_estimators=100, oob_score=True)
rf.fit(X, y)
oob_acc = rf.oob_score_
oob_error = 1 - oob_acc
  1. 1A forest that keeps its out-of-bag votes.
  2. 2oob_score_ is the out-of-bag accuracy; one minus it is \(\text{err}_{\text{OOB}}\) of line 3 above.

Breiman proved that a forest’s error is small when its trees are individually strong and unlike each other (Breiman 2001, Theorem 2.3). His Random Forests paper tested this on sonar returns labelled mine or rock, varying \(m\). Strength is each tree’s own accuracy; correlation is how alike two trees’ votes are. 7 Random forests in practice

A forest on UCI HAR’s own split of volunteers, 561 features per window and six activity labels (Anguita et al., 2013).

import numpy as np
from sklearn.ensemble import RandomForestClassifier as RF
root = "UCI HAR Dataset/"
def load(part):
    X = np.loadtxt(root + part + "/X_" + part + ".txt")
    y = np.loadtxt(root + part + "/y_" + part + ".txt")
    return X, y.astype(int)
Xtr, ytr = load("train")
Xte, yte = load("test")
forest = RF(n_estimators=100, oob_score=True, n_jobs=-1)
forest.fit(Xtr, ytr)
oob = forest.oob_score_
acc = forest.score(Xte, yte)
print(oob, acc)
  1. 1Loads the training and test volunteers’ windows.
  2. 2A forest of 100 trees on all cores.
  3. 3The out-of-bag accuracy and the test accuracy.
  4. 4The two should agree closely, which is what makes the out-of-bag score trustworthy.

The best-known field use is the Kinect body-part recognizer (Shotton et al., CVPR 2011): a randomized decision forest labels each pixel of a depth image with a body part, and the paper reports 200 frames per second on consumer hardware and under 5 ms per frame on the Xbox 360 GPU. To see which features a fitted forest leans on, shuffle each feature on held-out windows and measure the drop: permutation_importance(forest, X_te, y_te, n_repeats=5).

9 Forests vote; boosting corrects

A forest averages trees that are each already complex. That cuts their variance but leaves their bias: if every tree misses the same pattern, so does the vote. What if each new small tree fixed the mistakes left by the ones before it, instead of voting alongside them? That is Gradient Boosting.
