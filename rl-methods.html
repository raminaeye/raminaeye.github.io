1 Where value-based methods fit

Value-based methods are one of four RL families. Every family runs the reinforcement learning loop; what differs is what the agent learns to pick its move. A value is an estimate of how much future reward to expect; a policy is the rule that picks the move. Some methods also learn, or are handed, a model that predicts what each move will do, and plan with it (model-based); methods without one are model-free. Actor-critic methods learn both a policy, the actor, and a value, the critic. Choosing a method, at the end, says when to reach for each.

2 What each family stores

Given one state, a value-based agent outputs a score per move, a policy-based one move probabilities, and an actor-critic probabilities plus the critic’s score of the state.

3 Value-based methods

A value-based agent keeps a score, a Q-value, for every move in every state: the future reward it expects from that move and good play after. It mostly plays the highest score, explores with a small chance ε (ε-greedy) and updates as in RL Basics. Q-learning (Watkins and Dayan 1992) keeps these scores in a table, one row per state:

Q-learning moves the score of the move played a little toward a target built from that step.
target = r + γ · max Q(s′, a′)
The target is the reward r the move earned plus the highest score in the state s′ it led to, max Q(s′, a′) over every move a′ there. The discount γ, from 0 to 1 and often just below 1, shrinks that future score for the delay (the discount plot in RL Basics).
Q(s, a) ← Q(s, a)
+ α · (target − Q(s, a))
The score of move a in state s moves a fraction α, the learning rate, of the way toward the target (the arrow means replace with).

In the cliff walk of Sutton and Barto’s RL textbook (2018, Example 6.6), a 4 × 12 grid, an episode runs from start S to goal G, the two ends of the bottom row, past the cliff between them. Every step costs −1; the cliff costs −100 and a return to S. The code runs tabular Q-learning on gymnasium’s CliffWalking.

import random
import numpy as np
import gymnasium as gym

alpha, gamma, eps = 0.5, 1.0, 0.1   # values from the book's cliff code
env = gym.make("CliffWalking-v1")
Q = np.zeros((48, 4))   # 48 squares, 4 moves

def epsilon_greedy(Q, s):
    if random.random() < eps:
        return random.randrange(4)
    return int(Q[s].argmax())

for episode in range(500):
    s, info = env.reset()
    done = False
    while not done:
        a = epsilon_greedy(Q, s)
        s_next, r, terminated, truncated, info = env.step(a)
        best_next = 0.0 if terminated else Q[s_next].max()
        Q[s, a] += alpha * (r + gamma * best_next - Q[s, a])
        s, done = s_next, terminated or truncated
  1. 1Sets α, γ and ε and an all-zero Q-table for the 48-square cliff.
  2. 2Defines ε-greedy move choice.
  3. 3Starts an episode, picks a move and steps the environment.
  4. 4Target and update, eq card in Section 3, lines 1 and 2.
  5. 5Moves on to the next state.

4 On-policy and off-policy

An off-policy method learns about a policy other than the one making its moves. Q-learning is off-policy because its target scores the best move in s′, whatever the agent plays next, so it learns best-move values while exploring. SARSA, named for the five things one update uses (State, Action, Reward, next State, next Action), changes that one term (the RL textbook, section 6.4):

SARSA scores the move it will really play next, not the best one.
targetSARSA = r + γ · Q(s′, a′next)
a′next is the move ε-greedy really picks in s′, random moves included. SARSA learns the values of the policy it runs, so it is on-policy.

The SARSA inner loop picks a_next first; env, Q and epsilon_greedy come from Section 3’s code.

for episode in range(500):
    s, info = env.reset()
    a = epsilon_greedy(Q, s)
    done = False
    while not done:
        s_next, r, terminated, truncated, info = env.step(a)
        a_next = epsilon_greedy(Q, s_next)   # really played
        q_next = 0.0 if terminated else Q[s_next, a_next]
        Q[s, a] += alpha * (r + gamma * q_next - Q[s, a])
        s, a = s_next, a_next
        done = terminated or truncated
  1. 1Starts an episode and picks the first move.
  2. 2Steps, then picks a′next, the move the agent will really play.
  3. 3SARSA target, eq card in Section 4, line 1, then the update from Section 3, line 2.
  4. 4Carries the next state and move into the next step.

Both agents explore with ε 0.1. SARSA’s target counts the random moves that fall off the cliff, so squares on the edge score low and it learns a route a row away.

5 Deep Q-networks

DQN, deep Q-network (Mnih et al. 2015), replaces the table with a neural network that outputs one score per move. Two fixes keep it from oscillating or diverging:

  • Experience replay trains on random batches from a replay buffer, a memory of past steps, so nearly identical steps do not arrive in a row. Those steps came from older policies, so replay needs an off-policy method.
  • A target network, a frozen copy of the network, computes the targets and is recopied every C updates, so targets hold still between copies.

Among noisy scores the highest is usually one that came out too high, so the max makes Q-learning and DQN overestimate (van Hasselt et al. 2016). Double DQN fixes the target:

Double DQN splits picking the next move from scoring it.
targetDQN = r + γ · max Q−⁠(s′, a′)
Q− is the frozen copy. The same scores both pick the best move and value it, so a score that came out too high is the one picked and used.
a* = argmax Q(s′, a′)
The learning network Q picks the move. argmax returns the move a′ with the highest score, not the score itself.
targetDouble = r + γ · Q−⁠(s′, a*)
The frozen copy values that move. A score inflated in one network is less often inflated in the other, so the target is inflated less often.

Dueling DQN (Wang et al. 2016) changes the network instead, splitting it into two streams:

A dueling network adds a state value and an advantage per move.
Q(s, a) = V(s) + A(s, a)
− meana′ A(s, a′)
V(s) is how good the state is overall; A(s, a), the advantage, is how much better move a is than the average move. Subtracting the mean advantage over all moves a′ makes the split unique, since otherwise any amount could shift between V and A. V learns from every step, which helps when many moves score about the same.

My DQN agent for the banana collector game in RL Basics uses both; Deep Q-Networks (DQN) draws its two streams.

One DQN update; for Double DQN, pick the next move with q_net and score it with target_net.

import random
import torch
import torch.nn.functional as F

gamma, batch_size, C = 0.99, 32, 10_000   # DQN paper

def dqn_update(q_net, target_net, optimizer, buffer, n_updates):
    batch = random.sample(buffer, batch_size)
    s, a, r, s_next, done = map(torch.tensor, zip(*batch))
    with torch.no_grad():
        best_next = target_net(s_next).max(1).values
        target = r + gamma * best_next * (1 - done.float())
    q_sa = q_net(s).gather(1, a.unsqueeze(1)).squeeze(1)
    loss = F.smooth_l1_loss(q_sa, target)   # Huber
    optimizer.zero_grad()
    loss.backward()
    optimizer.step()
    if n_updates % C == 0:
        target_net.load_state_dict(q_net.state_dict())
  1. 1Samples 32 stored steps from the replay buffer.
  2. 2Target from the target network Q−, first eq card in Section 5, line 1.
  3. 3Huber loss (squared for small errors, linear for large) between Q(s, a) and the target, then one gradient step.
  4. 4Copies the network into Q− every C updates.

6 Choosing a method

Two facts usually decide: whether actions are a short list (discrete) or real numbers, and what a real step costs.

TD3, SAC, PPO and A2C are taught in Policy-Based and Actor-Critic Methods: REINFORCE, PPO and SAC; AlphaZero, MuZero, Dyna and Dreamer in Model-Based RL: Dyna, AlphaZero and MuZero.

A score per move needs a max over a list of moves. What does an agent learn when it outputs the move itself, or when a move is a real number such as a joint torque? Policy-Based and Actor-Critic Methods: REINFORCE, PPO and SAC takes up that question.
