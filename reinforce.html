How can a Pong paddle learn which moves to make from nothing but the points it wins and loses?

  • The agent picks the moves. A state is its situation right now, a move (or action) is one choice it can make, and a reward is the number the world hands back after each move (RL Basics).
  • An episode is one run from the start until it ends. A policy is the agent’s rule for choosing a move in each state (RL Basics).
  • The return is all the reward still to come, later rewards counted a little less; the discount \(\gamma\) sets how much less (RL Basics).
  • A state’s value \(V(s)\) is the return the agent expects from state \(s\). A move’s value \(Q(s,a)\) is the return it expects after making move \(a\) in state \(s\) (RL Basics).

1 A Pong paddle that learns from points

In Atari Pong each player moves a paddle up and down to hit the ball back past the other. The state is the screen, a stack of the last few frames so the ball’s direction shows. The moves are up, stay and down, one every few frames; one such move is one step. The reward is +1 for a point won, −1 for a point lost and 0 on every other step. One episode is one full game. \(J\) is the average points per game, later points counted a little less: the number learning tries to raise.

Figure 1 shows the running example: Atari Pong, the agent's paddle on the right and the other player on the left, with the ball traveling between them. Take the agent's paddle: it sits on the right, orange, and its job is to hit the ball back past the other player.

2 A network that outputs move chances

Value methods such as Q-Learning and Deep Q-Networks (DQN) learn how good every move is, then play the best one. The network learns the choice itself: one chance per move on each screen.

Figure 2 shows the chances coming out largest for up on the screen shown, and up is the move drawn.

The network that does this is the policy network. For Pong it gives three raw outputs, one per move, and a softmax (Softmax, Temperature and Decoding) turns them into three chances that add to one. Its weights are written \(\theta\) (theta), and the chance it gives move \(a\) on screen \(s\) is \(\pi_\theta(a\mid s)\).

3 Make the moves before a point was won more likely

Push each move by its credit

What. Picture a Pong rally: the paddle slides up, holds still, slides down, and halfway through it wins a point. The moves just before that point set it up, so they deserve the credit and the moves before a lost point deserve the blame.

How. A method that learns this way is a policy-gradient method: each move is pushed by its credit, a number saying how well things turned out after it, with positive credit raising the move’s chance and negative credit lowering it.

Why. When it works, the paddle repeats the moves that won points and drops the ones that lost them, so its play sharpens game by game.

Figure 3 runs the timeline left to right, each mark one move, with a green check where a point is won and a red cross where one is lost; green up arrows stand under the moves before the won point and red down arrows under the moves before the lost point.

Pushing a move up means a small change to \(\theta\) that raises that move’s chance on that screen; the other two drop, since the three add to one.

Policy-gradient methods differ in the credit they use; here the credit is the points that followed each move.

4 Weighting each move by the points that followed

One game, one push per move

What. Picture the whole game as a finished story: every move in it already happened, and the points after each move are already known.

How. REINFORCE plays one full game, works out each move’s return, and pushes each move by its own return. Learning from finished games, rather than from a guess of what comes next, is called Monte Carlo learning.

Why. When it works, a single finished game is enough to teach the paddle, because every move in it already has the points that followed it.

To turn this into a loss to minimize, reuse the classification loss of supervised learning, cross-entropy, which scores each move by the log of its chance, with the move actually played as the label, scaled by the return that followed it. The return stays fixed during the update: it is a number from the game just played, and the weights cannot change it.

Why the log? A move played often gets pushed often, just because it is common. The log undoes that. The slope of a log chance is the slope of the chance itself, divided by that chance. So the more common a move is, the smaller each of its pushes (Policy Gradients: REINFORCE, Actor-Critic and PPO).

5 Why one game is a noisy judge

The bad move that still gets pushed up

What. Picture the paddle winning a point after a bad down move that let the ball slip past. The points after that move are high anyway, so the bad move gets pushed up just like the good ones.

How. The true push is an average over every game the paddle could play, but REINFORCE estimates it from the one game it just played, so each update carries that game’s luck.

Why. When it works, the paddle still learns over many games, because the lucky pushes and the unlucky ones average out, even though any single update can point the wrong way.

  1. The paddle goes down while the ball comes in high, a bad move.
  2. The paddle wins the points after it anyway, so its return is high.
  3. Each arrow is sized by the full return that followed its move.

Figure 4 shows why one game is a noisy judge: the points after a move are all the evidence one game gives about it, so the update has no way to tell a move that earned the point from one that only came before it.

6 Subtracting the usual result

The advantage from one game

What. Picture two screens: on one the paddle is well placed and points usually follow, on the other it is badly placed and points rarely follow. What matters is whether a move did better or worse than usual from that screen.

How. A baseline is that usual result, subtracted from the return. The return minus the guess is the move’s advantage, how much better than usual it did. A second network, the value network, learns the guess.

Why. When it works, the pushes carry less noise, because a move is pushed up only when it beats the usual result and down when it falls short, instead of by the raw points that followed it.

The value network looks at the screen and outputs one number, \(V_\phi(s)\), its guess of the usual result. \(\phi\) (phi) stands for its weights, as \(\theta\) does for the policy network.

The advantage from one game is only an estimate, so it wears a hat, the mark for an estimate: \(\hat A_t\).

Equation 2. One game is a noisy judge of a move, so each move is judged against what its screen usually returns. A coach who scores a player against the team's usual result faces the same need.
1\(\displaystyle \htmlClass{eqt}{\htmlStyle{color:#196f3d}{\hat{A}_t}} = \htmlClass{eqt}{\htmlStyle{color:#196f3d}{G_t}} - \htmlClass{eqt}{\htmlStyle{color:#a04000}{V_\phi(s_t)}}\)
Intuition. This line takes the return and subtracts the usual result, so only the edge over usual counts.
The mathematics. \(\htmlClass{eqt}{\htmlStyle{color:#196f3d}{\hat{A}_t}}\) is the advantage of the move at step \(\htmlClass{eqt}{t}\), how much better it did than usual; the hat means estimate: one game is one sample of all the games the paddle could have played. \(\htmlClass{eqt}{\htmlStyle{color:#196f3d}{G_t}}\) is the return from step \(\htmlClass{eqt}{t}\) on, the points that followed; minus \(\htmlClass{eqt}{\htmlStyle{color:#a04000}{V_\phi(s_t)}}\) takes off the value network's guess for the screen \(\htmlClass{eqt}{\htmlStyle{color:#1f4e9c}{s_t}}\). A move that beats the guess has a positive advantage and one that falls short has a negative one. The next line swaps this advantage in for the return: minus the sum over every step of log \(\htmlClass{eqt}{\htmlStyle{color:#1f4e9c}{\pi_\theta}}(a_t\mid s_t)\) times \(\htmlClass{eqt}{\htmlStyle{color:#196f3d}{\hat{A}_t}}\), so the push follows the edge, not the raw return.
Example. Take a screen where the ball is already past the paddle, so the next point is almost always lost: the value network's guess there is low, so every move there is pushed down unless it beats the guess.
2\(\displaystyle \begin{aligned}&\mathcal{L}_{\hat A}(\theta)\\&\;= -\sum_{t} \log \htmlClass{eqt}{\htmlStyle{color:#1f4e9c}{\pi_\theta}}(a_t\mid s_t)\; \htmlClass{eqt}{\htmlStyle{color:#196f3d}{\hat{A}_t}}\end{aligned}\)
Intuition. The advantage must reach every move in the game. This line swaps it in for the return in the REINFORCE loss.
The mathematics. \(\htmlClass{eqt}{\mathcal{L}_{\hat A}(\theta)}\) is the baseline loss for the weights \(\htmlClass{eqt}{\theta}\). The sum over \(\htmlClass{eqt}{t}\) adds over every step; each term multiplies log \(\htmlClass{eqt}{\htmlStyle{color:#1f4e9c}{\pi_\theta}}(a_t\mid s_t)\), the log chance the policy gave the move on screen \(\htmlClass{eqt}{\htmlStyle{color:#1f4e9c}{s_t}}\), by \(\htmlClass{eqt}{\htmlStyle{color:#196f3d}{\hat{A}_t}}\), the advantage, the return minus the value network's guess for the screen. The minus turns the weighted sum into a loss to minimize, as the REINFORCE loss does, weighting each move's log chance by its advantage. \(\htmlClass{eqt}{\htmlStyle{color:#196f3d}{\hat{A}_t}}\) is held fixed, as the return was in the REINFORCE loss. The next line fits that value network: the sum over every step of the squared gap between the return and the guess, keeping the advantage honest.
Example. Take the circled bad move of Figure 4: its return is high, yet the usual result from its screen is higher still, so its advantage is negative and the loss pushes it down.
3\(\displaystyle \begin{aligned}&\mathcal{L}_V(\phi)\\&\;= \sum_{t} \big(\htmlClass{eqt}{\htmlStyle{color:#196f3d}{G_t}} - \htmlClass{eqt}{\htmlStyle{color:#a04000}{V_\phi(s_t)}}\big)^2\end{aligned}\)
Intuition. The advantage is only as good as the guess it subtracts. This line teaches the value network to guess better.
The mathematics. \(\htmlClass{eqt}{\mathcal{L}_V(\phi)}\) is the value loss for the weights \(\htmlClass{eqt}{\phi}\), so only \(\htmlClass{eqt}{\phi}\) changes through this line. The sum over \(\htmlClass{eqt}{t}\) adds over every step; each term squares the brackets, \(\htmlClass{eqt}{\htmlStyle{color:#196f3d}{G_t}}\) minus \(\htmlClass{eqt}{\htmlStyle{color:#a04000}{V_\phi(s_t)}}\), the return minus the guess; the square makes it a squared gap, so a miss in either direction counts. Making it smaller pulls the guess toward the real return. A badly fit guess leaves the pushes as noisy as plain REINFORCE. \(\htmlClass{eqt}{\mathcal{L}_V(\phi)}\) equals the sum over \(\htmlClass{eqt}{t}\) of (\(\htmlClass{eqt}{\htmlStyle{color:#196f3d}{G_t}}\) minus \(\htmlClass{eqt}{\htmlStyle{color:#a04000}{V_\phi(s_t)}}\)) squared. So the whole equation says this: score each move against the usual result, push each move's log chance by that score, and fit the value network to the returns, so the pushes carry less noise.
Example. Take the screens late in a lost game: the returns there are low, so the value loss pulls the guess for those screens down toward them.

A push is biased when, averaged over many games, it points somewhere other than the direction that raises \(J\).

The baseline must depend only on the screen, never on the move made there. Then subtracting it adds no bias. The baseline’s part of a single move’s push is the slope of its log chance, times the baseline. Averaged over the moves, each push is weighted by that move’s chance: the chance-weighted pushes added together give the baseline times the slope of all the chances added together. The chances always add to one, so their slope is zero, and on average the baseline’s pushes cancel.

7 Keeping the paddle undecided

The price of certainty

What. Picture the paddle winning a few points by staying still: every push raises stay a little more, until up and down are almost never tried and the paddle never finds out that moving up wins more.

How. Entropy is how undecided the policy is, and the entropy bonus rewards the policy for staying undecided, so it keeps trying moves it rarely picks. The entropy weight \(c_H\) sets how much the loss pays for staying undecided.

Why. When it works, the paddle still tries the moves it rarely picks, so it can still find the better move.

Figure 5 puts the two cases side by side: on the left the stay bar takes almost all the chance, so the paddle is decided; on the right stay is still largest, so the paddle stays undecided.

Equation 3. A paddle that wins a few points by staying still stops trying the other moves, so the loss pays it to stay undecided. A player who only ever tries one opening faces the same trap.
1\(\displaystyle \begin{aligned}&\htmlClass{eqt}{\htmlStyle{color:#0e6d80}{\mathcal{H}}}\big(\htmlClass{eqt}{\htmlStyle{color:#1f4e9c}{\pi_\theta}}(\cdot\mid s)\big)\\&\quad=-\sum_{a}\htmlClass{eqt}{\htmlStyle{color:#1f4e9c}{\pi_\theta}}(a\mid s)\\&\qquad\times\log \htmlClass{eqt}{\htmlStyle{color:#1f4e9c}{\pi_\theta}}(a\mid s)\end{aligned}\)
Intuition. A paddle that locks onto one move stops learning. This line measures how undecided its chances still are.
The mathematics. \(\htmlClass{eqt}{\htmlStyle{color:#0e6d80}{\mathcal{H}}}\) of \(\htmlClass{eqt}{\htmlStyle{color:#1f4e9c}{\pi_\theta}}(\cdot\mid s)\) is the entropy of the whole policy on screen \(\htmlClass{eqt}{s}\), the dot standing for all three chances. The sum over \(\htmlClass{eqt}{a}\) adds over the moves \(\htmlClass{eqt}{a}\); each term multiplies \(\htmlClass{eqt}{\htmlStyle{color:#1f4e9c}{\pi_\theta}}(a\mid s)\), the chance the policy gives that move, by log \(\htmlClass{eqt}{\htmlStyle{color:#1f4e9c}{\pi_\theta}}(a\mid s)\), the log of that chance; the minus in front makes \(\htmlClass{eqt}{\htmlStyle{color:#0e6d80}{\mathcal{H}}}\) positive, since a log below one is negative. When the moves are about equally likely \(\htmlClass{eqt}{\htmlStyle{color:#0e6d80}{\mathcal{H}}}\) is high; when one move is certain \(\htmlClass{eqt}{\htmlStyle{color:#0e6d80}{\mathcal{H}}}\) is zero. The next line takes the entropy off the total loss, so the entropy becomes the bonus that keeps the paddle undecided: the baseline loss plus the value loss minus \(\htmlClass{eqt}{c_H}\) times the summed entropy.
Example. Take the three moves sharing chance equally: each term is the same and the entropy is at its highest.
2\(\displaystyle \begin{aligned}&\mathcal{L}_{\text{total}}\\&\;=\mathcal{L}_{\hat A}(\theta)+\mathcal{L}_V(\phi)\\&\qquad-c_H\sum_{t}\htmlClass{eqt}{\htmlStyle{color:#0e6d80}{\mathcal{H}}}\big(\htmlClass{eqt}{\htmlStyle{color:#1f4e9c}{\pi_\theta}}(\cdot\mid s_t)\big)\end{aligned}\)
Intuition. The loss must pay the policy to stay undecided. This line takes a small entropy bonus off the total.
The mathematics. \(\htmlClass{eqt}{\mathcal{L}_{\text{total}}}\) is the total loss. \(\htmlClass{eqt}{\mathcal{L}_{\hat A}(\theta)}\) is the baseline loss, pushing toward good moves; plus \(\htmlClass{eqt}{\mathcal{L}_V(\phi)}\) is the value loss, fitting the value network; minus the entropy term takes off the bonus, \(\htmlClass{eqt}{c_H}\) the entropy weight. The minus means training pays a small price for certainty: raising \(\htmlClass{eqt}{c_H}\) keeps the paddle undecided longer, while lowering it lets it commit sooner. The value loss changes only \(\htmlClass{eqt}{\phi}\); the rest changes only \(\htmlClass{eqt}{\theta}\). \(\htmlClass{eqt}{\mathcal{L}_{\text{total}}}\) equals \(\htmlClass{eqt}{\mathcal{L}_{\hat A}(\theta)}\) plus \(\htmlClass{eqt}{\mathcal{L}_V(\phi)}\) minus \(\htmlClass{eqt}{c_H}\) times the sum over \(\htmlClass{eqt}{t}\) of \(\htmlClass{eqt}{\htmlStyle{color:#0e6d80}{\mathcal{H}}}\) of \(\htmlClass{eqt}{\htmlStyle{color:#1f4e9c}{\pi_\theta}}(\cdot\mid s_t)\). So the whole equation says this: add the push toward good moves and the fit of the value, subtract a small price for certainty, and one update minimizes all three at once.
Example. Take a screen where stay has won lately, so it gets most of the chance: the entropy there is near zero, so the bonus keeps a sliver on up and down for the paddle to try.

8 Step through one REINFORCE update

Put together, one update has four ideas: the return, the advantage, the value fit and the entropy bonus.

Figure 6 shows one game and one update: the game, the points that followed each step, the push on each move, and the chances on the circled screen. Stages 1 to 7 light the six lines in order, from the return to the total. The gauge at the bottom shows how undecided the paddle is.

9 The update written out as code

Picture the whole update as one short script: play a game, work out each move’s return, and push. A toy REINFORCE for Pong, to read rather than run. Pong has six actions: stay, fire, up, down, up plus fire and down plus fire, and we keep up, stay and down because fire does nothing useful here. Gymnasium is the library that runs the game, and ale_py, the Atari plugin, plugs the Atari games into it. The game is made with frameskip 1, so it skips no frames of its own, and the preprocessing repeats each move over four frames, so one move is one step. The wrappers prepare the screen: one turns each frame gray and smaller, one stacks four frames so the ball’s direction shows, and Categorical, the move picker, draws a move from the policy’s chances. Each screen is divided by 255, so its pixels run from 0 to 1, and unsqueeze(0) adds a batch of one, so the network sees one screen at a time. Sampling runs under no_grad, so choosing the move builds no gradients. The move list holds Pong’s own codes for up, stay and down.

import gymnasium as gym, ale_py
import torch
from torch import nn
from torch.distributions import Categorical

gym.register_envs(ale_py)
env = gym.make("ALE/Pong-v5", frameskip=1)
env = gym.wrappers.AtariPreprocessing(env, frame_skip=4)
env = gym.wrappers.FrameStackObservation(env, 4)
MOVES = [2, 0, 3]   # up, stay, down
gamma, c_h = DISCOUNT, C_ENTROPY

def returns_to_go(rewards, gamma):
    G, out = 0.0, []
    for r in reversed(rewards):
        G = r + gamma * G
        out.insert(0, G)
    return torch.tensor(out)

def body():
    return nn.Sequential(
        nn.Conv2d(FRAMES, C1, 8, stride=4), nn.ReLU(),
        nn.Conv2d(C1, C2, 4, stride=2), nn.ReLU(),
        nn.Flatten(), nn.Linear(FLAT, HIDDEN), nn.ReLU())

policy = nn.Sequential(body(), nn.Linear(HIDDEN, N_MOVES))   # up, stay, down
value = nn.Sequential(body(), nn.Linear(HIDDEN, 1))    # V_phi(s)
opt = torch.optim.Adam([*policy.parameters(), *value.parameters()], lr=LEARNING_RATE)

for episode in range(N_EPISODES):                       # repeat: one game, one update
    s, info = env.reset()
    states, moves, rewards, done = [], [], [], False
    while not done:                                 # one whole game
        x = torch.as_tensor(s, dtype=torch.float32).unsqueeze(0) / 255
        with torch.no_grad():
            a = Categorical(logits=policy(x)).sample()
        s, r, terminated, truncated, info = env.step(MOVES[a.item()])
        states.append(x); moves.append(a)
        rewards.append(r)   # r_{t+1}: the reward after move t
        done = terminated or truncated
    S, M = torch.cat(states), torch.cat(moves)
    dist = Categorical(logits=policy(S))   # softmax of the logits
    logp = dist.log_prob(M)
    G = returns_to_go(rewards, gamma)
    V = value(S).squeeze(-1)
    value_loss = (G - V).pow(2).sum()
    adv = (G - V).detach()
    pg_loss = -(logp * adv).sum()
    loss = pg_loss + value_loss - c_h * dist.entropy().sum()
    opt.zero_grad(); loss.backward(); opt.step()
  1. 1The return of every step, added up backward from the last reward.
  2. 2The policy network’s logits, its raw outputs before the softmax; logp is the log chance of each move taken, as in the REINFORCE loss.
  3. 3The value loss: the value network’s guess for every screen and its squared gap to the return.
  4. 4The advantage and the baseline loss: adv is \(\hat A_t\), held fixed by detach(), and pg_loss is \(\mathcal{L}_{\hat A}\).
  5. 5The total loss, with the entropy of the move distribution as its entropy line; zero_grad clears the last update’s gradients, the backward call works out every gradient (Backpropagation and Gradient Checking) and the optimizer update is one Adam update (Adaptive Optimizers: AdaGrad, RMSProp and Adam).
  6. 6The settings, named in the code. DISCOUNT 0.99 is the discount, FRAMES 4 is the number of stacked frames, N_MOVES 3 is the number of moves, and N_EPISODES 10 is the number of toy episodes. C_ENTROPY 0.01 is the entropy weight and LEARNING_RATE 0.0001 is the learning rate. The first layer scans the stacked frames for patterns, and C1 32 counts how many patterns it looks for. The second layer does the same on the result, and C2 64 counts its patterns. Flattening stacks those into one long list, and FLAT 5184 counts the numbers in it. The next layer turns that list into a list of HIDDEN 512 numbers, and the last layer turns those numbers into the move scores. The network turns the stacked frames into move chances.

10 How a baseline narrows the spread

The learning rate \(\eta\), the lr in the code, sets how big a step each update takes (Q-Learning).

A less noisy push makes separate training runs end closer together. How far apart they end is the spread. A baseline set above the usual result makes most pushes point the wrong way, so the training runs spread out again.

The tool sets its own win chances, for illustration: up is the most likely winner, then stay, then down. Its baseline is the exact usual result, worked out from those win chances, not a value a network learned.

Figure 7 shows thirty training runs of forty games: the chance of up, the best move here, over the games, with the end strip showing where each training run ends. The thick line is one training run, the faint lines the other twenty-nine, and the shaded band is how far apart the training runs end, against the dashed band for the usual-result baseline.

Table 1 gathers the settings for REINFORCE with a baseline: the learning rate, the discount and the entropy weight, each with its value and what raising or lowering it does. Each row names its source, from the Pong post to the PyTorch cart-pole example, so the values are the ones the field uses, not guesses.

Each update runs once per finished game, and what carries over between updates is the two networks’ weights and the optimizer’s running averages. One update’s time grows with the length of the game it just played, and its memory is the game itself: the states, moves and rewards it must keep until the update runs.

  • Normalize the returns: shift and scale them so each update’s returns average zero and have a standard deviation of one.
  • Average several games into one update, so the update then runs once per batch of games instead of once per finished game.

12 When REINFORCE fits

REINFORCE fits short games. A long game piles up many moves before the point, so each push carries the whole game’s luck.

13 What breaks REINFORCE

Five symptoms, five fixes

What. Picture a paddle after a long night of training that still loses: its training runs end far apart, its chances have collapsed onto one move, and it never settles on anything better.

How. Each break has its own cause: no baseline, a baseline that sees the move, a step too big, an entropy weight set too low or too high, and games too long to tell which move deserves the credit.

Why. When it works, read the symptom and name the fix: subtract a learned value, let the baseline see only the screen, lower the step, raise or lower the entropy weight to fit the symptom, or judge moves sooner.

Training runs end far apart and learning is slowNo baselineSubtract a learned value
The paddle drifts toward worse movesA baseline that depends on the move, so the push is biasedLet the baseline see only the screen

The paddle never commits\(c_H\) too largeLower \(c_H\)

14 Judging each move before the game ends

What if the value network’s guess stood in for the points still to come, so each move could be judged a few steps later instead of at the end of the game?

Judging each move before the game ends is the idea behind Actor-Critic, and Proximal Policy Optimization (PPO) builds on that.
