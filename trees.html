Decision Trees, Random Forests, and Boosting

A decision tree classifies a point by asking yes-or-no questions about its features. The running example is the UCI smartphone activity dataset (Anguita et al., 2013): a waist phone records six activities, from walking to laying, as short windows of motion data.

1 How a decision tree classifies a point

Each question is a threshold on one feature; a leaf votes for the class most common among its training points. A regression tree's leaf predicts its points' mean.

A tree (Section 3) is grown once, a forest (Section 4) grows each tree once on its own resample, and boosting (Section 6) adds one small tree per round. One balanced tree costs about points × features × log(points) (scikit-learn documentation).

Figure 2 is an illustrative cut of 40 windows on two features: the body-acceleration mean, how hard the phone shakes, and the gravity angle, how it is tilted.

2 Impurity and information gain

The tree tries every feature and threshold and keeps the split whose children are purest, scored by one of two classic measures. Impurity is how mixed the classes in a group are. Take the root of Figure 2, moving against still:

A split is worth making when the groups it leaves are much purer than the group it started from; the gain counts how much purer.
ΔI = I(parent) − Ichildren
The gain ΔI is the impurity before the split minus the impurity after it; with entropy as I it is called the information gain. The tree keeps the split with the biggest gain; a split that separates nothing scores zero.
Ichildren = Σc NcN·I(c)
Each child c counts its impurity I(c) weighted by its share of the points, Nc out of N; Σ adds the children up.
Ientropy = −Σk pk log2 pk
Entropy is measured in bits, where pk is the share of the node's points in class k. An evenly split node scores 1 bit, a pure node 0. −log2 pk is the surprise of meeting class k, large for a rare class; entropy is the average surprise, so it peaks when the classes are evenly mixed.
IGini = 1 − Σk pk²
Gini, which needs no logarithm, is the chance two points drawn at random from the node disagree, 0.5 for an evenly split node and 0 for a pure one. In practice both measures grow nearly the same tree.
So the gain is the parent’s impurity minus the children’s weighted impurity, 0.601 bits for the root of Figure 2, and the tree keeps the split with the largest gain. The eq card in Section 4 grows many such trees and lets them vote.

With Gini the same root scores 0.48 and the cut gains 0.344. Its left child mixes 8 laying, 14 upright and 1 moving (1.163 bits); the gravity-angle question gains 0.932. The Decision_tree notebook in the Machine-Learning-Concepts repo searches splits the same way.

Split scoring in NumPy; f and 1 − f are the children's shares.

import numpy as np

def gini(y):
    p = np.bincount(y) / len(y)
    return 1 - (p ** 2).sum()

def splits(X):
    for j in range(X.shape[1]):
        vals = np.unique(X[:, j])
        for thr in vals[:-1]:
            yield j, thr

def best_split(X, y):
    best = (0.0, None, None)
    for j, thr in splits(X):
        left = X[:, j] <= thr
        f = left.mean()
        gl = gini(y[left])
        gr = gini(y[~left])
        kids = f*gl + (1-f)*gr
        gain = gini(y) - kids
        if gain > best[0]:
            best = (gain, j, thr)
    return best
  1. 1Gini impurity, line 4 of the card in Section 2.
  2. 2Tries every feature and threshold.
  3. 3Weighted impurity of the two children, line 2.
  4. 4Keeps the split with the largest drop, line 1.

The tree recurses on each child until a max depth or until every leaf is pure; depth 1 asks one question. Unchecked it memorizes the noise (depth 125 in the notebook), the high-variance failure of Bias and Variance.

3 Growing a tree greedily

The tools from here on use synthetic blobs so the boundary fits a flat plot; the activity windows have 561 features. Each point has features x1 and x2 and a class label y. The tree grows greedily: each node keeps its own best split, and earlier splits are never revisited.

4 Random forests

A random forest trains many deep trees, each on a bootstrap resample (same size as the data, drawn with replacement), and averages their votes.

A forest of 20 trees sees one new window; 13 vote moving (illustrative votes).

One tree can be fooled by a few odd windows; many trees, each grown on a different sample, vote and the oddities wash out.
v(x) = 1T·Σt ht(x)
Each tree grows by the split rule of the eq card in Section 2. ht(x) is tree t's call, 0 or 1, on point x, so v(x) is the share of the T trees voting 1.
ŷ = 1 if v(x) > 0.5, else 0
The forest says 1 when more than half the trees do: a majority vote. (scikit-learn averages each tree's class probabilities instead, a soft vote, which usually agrees.)
m = √d
A random forest proper also lets each split look at only m random features out of d, scikit-learn's default for classification. That makes the trees less alike. With d = 2 here, m rounds to 1 feature per split; the tool and the code keep both features, which is plain bagging.
So the forest is the share of trees that say moving, 0.65 for the new window, read against one half. On the paper’s 561 features line 3 gives 23 features per split, the square root rounded down. The eq card in Section 5 shows each tree also leaves windows out, which test it for free.

A forest by hand, each tree on its own bootstrap sample idx; X, y are training points and Xte held-out test points.

import numpy as np
from sklearn.tree import DecisionTreeClassifier
Tree = DecisionTreeClassifier
rng = np.random.default_rng(0)
T, n = 20, len(X)
ts = []
for t in range(T):
    idx = rng.integers(0, n, n)
    h = Tree(max_depth=5)
    h.fit(X[idx], y[idx])
    ts.append(h)
P = [h.predict(Xte) for h in ts]
votes = np.mean(P, axis=0)
y_hat = (votes > 0.5).astype(int)

  2. 2Fits each tree on a bootstrap sample.
  3. 3Averages the votes and calls 1 above 0.5 (Section 4).

5 Out-of-bag error

Each tree sits out about a third of the data. On the 40 windows, one tree’s bootstrap sample, 40 draws with replacement, missed 15 windows (illustrative draw):

Each tree’s bootstrap sample misses about a third of the points, and those missed points act as that tree’s own test set.
P(left out) = (1 − 1N)N
The bootstrap samples are the ones of the eq card in Section 4. The chance one point never lands in a tree's bootstrap sample. Each of the N draws misses it with chance 1 − 1N, and the draws are independent, so the misses multiply into the power N. A bigger N means more draws, but each draw is less likely to hit this point, and the two effects nearly cancel.
(1 − 1N)N ≈ e−1 ≈ 0.37
For large N the power settles at 1e, about 0.37, with e the base of natural logs, about 2.718, whatever the data size: roughly a third of the points are never seen by a given tree, and they become its free test set.
So at N = 40 the chance is 0.363, about 14.5 windows out per tree, close to the large-N 0.368: the forest gets a test score for free. The eq card in Section 6 builds trees one after another instead of side by side.

The forest's vote on each point, counting only the trees that never saw it, gives the out-of-bag error, an estimate of test error that needs no held-out data.

With oob_score=True the forest stores that accuracy, and one minus it is the out-of-bag error.

from sklearn.ensemble import RandomForestClassifier
RF = RandomForestClassifier
rf = RF(20, max_depth=5)
rf.set_params(oob_score=True)
rf.set_params(max_features=None)
rf.fit(X, y)
oob_error = 1 - rf.oob_score_
  1. 1A 20-tree forest that keeps out-of-bag votes.
  2. 2Fits and reads the out-of-bag error (Section 5).

The Random Forests paper (Breiman, 2001) tested this on sonar returns labeled mine or rock, varying m (scikit-learn's max_features; the paper writes F). Strength is each tree's own accuracy; correlation is how alike two trees' votes are. Figure 7 redraws the paper's Figure 1 from values read off the published plot (PDF).

6 Gradient boosting

Boosting grows trees in sequence, each fitting the mistakes left so far.

Each small tree fits the residuals, the signed mistakes so far, and nudges the prediction toward it. With moving as 1 and still as 0, 16 of the 40 windows are moving, so the first guess is 0.4; a moving window’s residual is 0.6, a still one’s −0.4. A first tree predicting 0.6 at learning rate 0.1 lifts a moving window to 0.46.

Builds on the gradient descent update (Gradient Descent, section 1.1)

Boosting starts from one constant guess and adds small trees, each fitted to what the model still gets wrong.
F0 = mean(y)
Where the forest of Section 4 votes trees side by side, boosting adds them in sequence. The start F0 predicts every point as the mean of the labels y, before any tree exists. This is the start for squared error, as in the notebook; scikit-learn's classifiers start from the log-odds of the classes instead.
ri = yi − F(xi)
The residual ri on point i is its truth yi minus the current prediction F(xi). The next tree is trained to predict these residuals. The residual is the negative gradient of the squared error ½(yi − F)² with respect to F, so each tree is one gradient-descent step on the predictions, hence the name (Friedman, 2001); for classification the tree fits the negative gradient of the log loss instead.
F ← F + lr · h(x)
The ← means "gets replaced by", so F moves a small step, the learning rate lr, toward the new tree h's output, so the boundary corrects itself where it is still wrong. A larger lr fits in fewer rounds and overfits sooner; a smaller one needs more rounds; scikit-learn's default is 0.1.
So boosting is a chain of small corrections on the residuals, 0.4 to 0.46 for the moving window above, a downhill step taken by trees, and the split rule of the eq card in Section 2 grows each one. End of the chain.

Boosting by hand with step size LR.

import numpy as np
from sklearn.tree import DecisionTreeRegressor
Tree = DecisionTreeRegressor
LR, ROUNDS = 0.01, 100
F = np.full(len(y), y.mean())
for _ in range(ROUNDS):
    r = y - F
    h = Tree(max_depth=3)
    h.fit(X, r)
    F = F + LR * h.predict(X)
  1. 1Starts from the mean, F0.
  2. 2Residuals r, what the trees still miss.
  3. 3Fits a small tree to r and adds a scaled step (Section 6).

7 Forests and boosting in practice

A forest and a boosted model on UCI HAR’s own split of volunteers.

import numpy as np
from sklearn.ensemble import RandomForestClassifier as RF
from sklearn.ensemble import HistGradientBoostingClassifier as HGB

root = "UCI HAR Dataset/"
def load(part):
    X = np.loadtxt(root + part + "/X_" + part + ".txt")
    y = np.loadtxt(root + part + "/y_" + part + ".txt")
    return X, y.astype(int)
Xtr, ytr = load("train")
Xte, yte = load("test")
forest = RF(100, oob_score=True)
forest.set_params(n_jobs=-1)
forest.fit(Xtr, ytr)
boost = HGB(learning_rate=0.1)
boost.fit(Xtr, ytr)
oob = forest.oob_score_
acc_rf = forest.score(Xte, yte)
acc_gb = boost.score(Xte, yte)

RandomForestClassifier trains its trees in parallel. HistGradientBoostingClassifier bins each feature into 255 bins for speed and native missing values; its rounds run in order. Permutation importance on held-out data is safer than impurity-based feature_importances_, which favor features with many distinct values.

8 Strengths, limits and variants of trees

Trees suit tabular data with mixed types or missing values, and models you need to read.

CauseSymptomFix
a deep tree memorized the noiseTrain accuracy near 100%, test lowercap the depth (depth limits are regularization for trees), prune, or vote a forest
every split tests one featureStaircase boundary on a diagonaladd a combined feature such as x1 + x2, or use a linear model
greedy splits score one feature at a time, and in an XOR pattern neither helps aloneMisses a pattern that needs two features togethergrow deeper or boost so later splits can pick it up
a leaf can only repeat values it sawFlat predictions past the training rangea linear model when you must extrapolate
MethodWhat changesWhen to use
Extra Treeseach cut point is drawn at random instead of searcheda faster forest that is often just as accurate
AdaBoostreweights the points the last tree got wrongboosting with very small trees

Pruninggrows deep, then cuts branches that do not pay for themselvesone readable tree that does not memorize

In XGBoost, reg_lambda (default 1) penalizes large leaf weights, so raising it shrinks each tree's push, and colsample_bynode below its default 1 samples columns per split.

from xgboost import XGBClassifier
m = XGBClassifier()
m.set_params(tree_method="hist")
m.set_params(reg_lambda=1.0)
m.set_params(colsample_bynode=0.5)

Trees cut one feature at a time; Support Vector Machines (SVM) draw one boundary with the widest margin between classes.
