1 The tennis environment and the new problem

On every earlier page the world’s rules stayed fixed while the learner improved. AlphaZero came closest to a changing opponent, because it played against a copy of itself, but it trained only on its most recent games. (AlphaZero: Search and Self-Play)

The running example is a tennis game from the TennisGym repo, in which two rackets keep a ball in play over a net. The ball goes back and forth until one racket misses it.

The agent is the learner that picks the moves. (RL Basics) A state is the agent’s situation right now; a move, or action, is one choice the agent can make in a state; a reward is the number the world hands back after each move, good or bad. (RL Basics) Here each racket is an agent, and both learn at once. Each racket sees the ball and the court from its own side of the net.

RL, short for reinforcement learning, is learning which moves to make from rewards rather than from labelled answers. (RL Basics) Both rackets start with no skill, so at first nearly every ball drops.

Learning with several agents at once is called multi-agent reinforcement learning. A racket earns a little for each clear, a ball it hits over the net, and loses a little for each ball it lets drop. Neither racket is told how the other one plays.

An episode is one run from the start until it ends. (RL Basics) A rally ends when the ball drops, and the episode ends with it.

An observation is what the agent senses at one moment. (RL Basics) Each racket reads its own observations, never the other’s.

A torque is a turning force a motor applies at a joint. (Continuous-Action RL) A continuous action is a real number, or a list of them, that can take any value in a range, like a torque, instead of one choice from a list. (Continuous-Action RL) A racket has no joints, so its action is not a torque but two amounts of the same kind, how far to scoot and how high to jump, chosen while the other racket is still changing how it plays. Both rackets pick their two amounts at the same moment, at every step.

A gym is a training environment that steps the world forward and hands back observations and rewards. Partial observability means an agent sees only part of the state, so the state can hold things its observation leaves out. Each racket’s view leaves out what the other racket reads.

brain_name, the name the environment gives the rackets, keys them in the output of env, states holds one row per racket, and each step returns one reward and one done flag per racket; the flag is set when that racket’s rally ends.

2 One learner playing both sides

A policy is the agent’s rule for choosing a move in each state; it may always pick the same move or pick by chance. (RL Basics) In self-play the same network plays both sides, so its opponent improves exactly as fast as it does. (AlphaZero) Self-play with a shared policy means both rackets play by one policy, which learns from the steps of both sides. Here each racket learns from rallies stored long ago, against an opponent that has kept learning since, so those rallies go stale.

The return is all the reward still to come, with later rewards counted a little less. (RL Basics) The discount \(\gamma\) sets how much a reward one step later still counts. (RL Basics) A racket’s return counts every later clear, the far ones a little less.

The critic \(Q_\phi\) is a network with weights \(\phi\) that scores a state and an action together; its score stands for the return the agent expects. (DDPG) The critic learns by being pulled toward a target, the step’s reward plus its own score for what comes next, counted a little less. (Continuous-Action RL) The shared critic scores what one racket saw and what it did.

The deterministic actor \(\mu_\theta\) is a network with weights \(\theta\) that outputs one action every time, with no random draw. (DDPG) Deep Deterministic Policy Gradient (DDPG) trains such an actor together with a critic that scores its actions. Self-play DDPG runs one such pair for both rackets.

2.1 One actor for both rackets

Both rackets send their own observation into the same actor.

Equation 3. The shared actor. One network answers each racket from its own side.

\( \displaystyle \htmlClass{eqt sym-action}{\htmlStyle{color:var(--sym-action)}{a_i}} = \htmlClass{eqt sym-actor}{\htmlStyle{color:var(--sym-actor)}{\mu_{\theta}}}\left(\htmlClass{eqt sym-state}{\htmlStyle{color:var(--sym-state)}{o_i}}\right) \)

Here \(i\) names racket A or B, and \(o_i\) its observation; both rackets ask the same network. \(\mu_\theta\) is the shared deterministic actor with weights \(\theta\); \(a_i\) is its scoot and jump, kept inside its allowed range by the actor’s tanh, a squash at its output. The update equations below train this actor; later on this page each racket gets an actor of its own. 2.2 The critic target, the critic loss and the soft update

Every step of both rackets is stored for later learning. Each stored step is called a transition: the observation, the action, the reward, the next observation, and the done flag. Replay keeps a memory of past steps, and training draws random batches from it. (DQN) The memory is called a replay buffer. Old rallies stay in it long after they were played.

A batch is a handful of remembered steps trained on together; the loss averages how far their scores are from their targets. (DQN) These random batches are drawn in the bursts of Figure 1.

Deep Q-Network (DQN) is the method that scores each move with a neural network, the Q-network, and picks the top score. The rackets cannot use it as it is, because scoot and jump are amounts, not a short list.

The target network is a slow copy of the Q-network, with weights \(\phi'\), that computes the targets. (DQN) DQN needs that slow copy because a target built from the network being trained moves at every update, and DDPG, from the same family of methods, needs one too. In this family the critic plays the Q-network’s part. (Training DDPG) The rackets need that steadiness most, since the opponent already shifts the ground under them.

In DDPG both the actor and the critic have a slow copy, marked by a prime on the weights, and the targets are built from those copies. (Training DDPG) The critic’s target here is the step’s reward plus the discounted score the slow critic gives to where the step led. Because the slow copies move only a little each update, that target stays nearly still while the critic chases it.

An expected value is the average over everything that can happen by chance, weighted by how likely each outcome is. (Probability and RL Basics) The sign \(\mathbb{E}\) marks an expected value. (Probability) In the card below the average runs over steps drawn from the buffer.

Equation 4. The self-play update. The critic learns what an observation and action are worth, and the actor shifts toward what the critic scores higher.

\( \displaystyle \htmlClass{eqt sym-qvalue}{\htmlStyle{color:var(--sym-qvalue)}{y}} = \htmlClass{eqt sym-reward}{\htmlStyle{color:var(--sym-reward)}{r}} + \htmlClass{eqt sym-discount}{\htmlStyle{color:var(--sym-discount)}{\gamma}} \htmlClass{eqt sym-statevalue}{\htmlStyle{color:var(--sym-statevalue)}{Q_{\phi'}}}\left(\htmlClass{eqt sym-state}{\htmlStyle{color:var(--sym-state)}{o'}}, \htmlClass{eqt sym-actor}{\htmlStyle{color:var(--sym-actor)}{\mu_{\theta'}}}\left(\htmlClass{eqt sym-state}{\htmlStyle{color:var(--sym-state)}{o'}}\right)\right) \)

\( \displaystyle \htmlClass{eqt sym-qvalue}{\htmlStyle{color:var(--sym-qvalue)}{\text{loss}}} = \mathbb{E} \left[ \left( \htmlClass{eqt sym-qvalue}{\htmlStyle{color:var(--sym-qvalue)}{y}} - \htmlClass{eqt sym-statevalue}{\htmlStyle{color:var(--sym-statevalue)}{Q_{\phi}}}\left(\htmlClass{eqt sym-state}{\htmlStyle{color:var(--sym-state)}{o}}, \htmlClass{eqt sym-action}{\htmlStyle{color:var(--sym-action)}{a}}\right) \right)^2 \right] \)

\( \displaystyle \htmlClass{eqt sym-return}{\htmlStyle{color:var(--sym-return)}{J(\theta)}} = \mathbb{E} \left[ \htmlClass{eqt sym-statevalue}{\htmlStyle{color:var(--sym-statevalue)}{Q_{\phi}}}\left(\htmlClass{eqt sym-state}{\htmlStyle{color:var(--sym-state)}{o}}, \htmlClass{eqt sym-actor}{\htmlStyle{color:var(--sym-actor)}{\mu_{\theta}}}\left(\htmlClass{eqt sym-state}{\htmlStyle{color:var(--sym-state)}{o}}\right)\right) \right] \)

\(y\) is the critic’s target: the reward that followed the stored action, written \(r_{t+1}\) on RL Basics, plus the discounted score the slow critic gives the next step. Primes on \(Q\) and \(\mu\) mark the slow copies \(\phi'\) and \(\theta'\), and the prime on \(o\) marks the next observation. When the racket’s rally ends the \(\gamma\) term is dropped and \(y\) is just \(r\).

The TD (temporal difference) error \(\delta\) is how much one step surprised the agent, the target minus the current guess. (RL Basics) The loss pulls \(Q_\phi\) toward \(y\), and \(y\) minus \(Q_\phi\) is that TD error \(\delta\).

\(J\) is the actor’s expected return, the quantity the actor’s weights are moved to raise. (Deep Deterministic Policy Gradient (DDPG): Actor and Critic) Here it is the critic’s average score of the actor’s own actions, which the actor climbs: training minimises \(-J\), the negative of line 3, in one line. Because both rackets share this actor, each climb also moves the other racket’s target, and a later section gives the critic a view of both rackets. This builds on the shared-actor card above and the DDPG critic target and actor update, on Deep Deterministic Policy Gradient (DDPG): Actor and Critic.

\(y\) the critic’s target\(r\) the reward just earned\(\gamma\) the discount\(Q_\phi\) the critic\(\mu_\theta\) the actor\(o\) one racket’s observation\(\text{loss}\) the critic’s loss\(a\) one racket’s action\(J(\theta)\) the actor’s objective

The slow copies still have to follow the live networks. The live networks are the actor and critic being trained, with weights \(\theta\) and \(\phi\). (Training DDPG) The soft update blends a small share \(\tau\) of the live weights into each slow copy after every update, instead of overwriting it. (DQN) The slow copies therefore trail the live ones smoothly.

Equation 5. The soft update. After each update, the slow copies move a small share of the way toward the live networks.

\( \displaystyle \htmlClass{eqt sym-actor}{\htmlStyle{color:var(--sym-actor)}{\theta'}} \leftarrow \htmlClass{eqt sym-discount}{\htmlStyle{color:var(--sym-discount)}{\tau}} \htmlClass{eqt sym-actor}{\htmlStyle{color:var(--sym-actor)}{\theta}} + (1 - \htmlClass{eqt sym-discount}{\htmlStyle{color:var(--sym-discount)}{\tau}}) \htmlClass{eqt sym-actor}{\htmlStyle{color:var(--sym-actor)}{\theta'}} \)

\( \displaystyle \htmlClass{eqt sym-statevalue}{\htmlStyle{color:var(--sym-statevalue)}{\phi'}} \leftarrow \htmlClass{eqt sym-discount}{\htmlStyle{color:var(--sym-discount)}{\tau}} \htmlClass{eqt sym-statevalue}{\htmlStyle{color:var(--sym-statevalue)}{\phi}} + (1 - \htmlClass{eqt sym-discount}{\htmlStyle{color:var(--sym-discount)}{\tau}}) \htmlClass{eqt sym-statevalue}{\htmlStyle{color:var(--sym-statevalue)}{\phi'}} \)

A small \(\tau\) keeps the slow copies moving slowly; \(\tau\) at its top end copies outright. This builds on the target network of Deep Q-Networks (DQN).

2.4 Exploration noise

Exploration noise is a small random nudge added to the actor’s actions while it learns, so the agent tries moves it is not sure about. (Training DDPG) Ornstein-Uhlenbeck (OU) noise is a nudge with memory: each step it keeps most of the last nudge, is pulled back toward zero, and gets a fresh random kick. (Training DDPG) The repo adds this noise to each racket’s scoot and jump while it trains.

3 A world that shifts as the opponent learns

A replay buffer works only while old rallies still show what the next ones will be like. In tennis, what happens after each shot depends on the other racket, and that racket’s policy changes with every update. Non-stationarity means the world keeps changing under a learner, because another agent in it is learning too. A joint action is the actions of all rackets together, which decide what happens next. Each racket’s stored rallies were played against an opponent that no longer exists. A lesson such as “hit the ball deep” stops working once the opponent learns to stand deep.

Training only on recent steps would give up the large replay buffer that keeps DDPG stable. Other fixes include predicting the opponent’s next move and opponents that get harder step by step. A later section fixes this with a critic that sees both rackets while it trains.

6 Why the curve jumps

Once both rackets can return the ball, a single rally can run long and the total reward jumps; longer rallies, not fewer mistakes, drive it up.

8 Self-play DDPG in practice

The learning rate \(\eta\) sets how big a step each update takes. (RL Basics) A learning rate set too high makes both rackets’ play swing from one burst of updates to the next.

The recipe is DDPG from Training DDPG: Target Networks, Replay and Noise, with three additions. Both networks use batch norm, which keeps each layer’s inputs on a steady scale, and gradient clipping, which caps each update; the critic also uses weight decay, a small pull of every weight toward zero. Both rackets trained with the same settings, listed in the table below.

Both networks learn with Adam, an optimizer that adapts each weight’s step size from its recent gradients.

In the loop, s holds both rackets’ observations o, agent is the shared DDPG agent, noise its exploration noise and buf the one replay buffer both rackets fill, with add and sample(n); learn is the update below.

import numpy as np

BATCH, LEARN_EVERY, N_UPDATES = 128, 64, 128
max_steps, BREAK_AFTER = 2500, 10
count = 0

for t in range(max_steps):
    a = agent.act(s)
    a = a + noise.sample() / 5
    a = np.clip(a, -1, 1)
    out = env.step(a)
    info = out[brain_name]
    s2 = info.vector_observations
    r = info.rewards
    d = info.local_done
    rows = zip(s, a, r, s2, d)
    for row in rows:
        buf.add(*row)
    s = s2
    ready = len(buf) >= BATCH
    due = t % LEARN_EVERY == 0
    if due and ready:
        for _ in range(N_UPDATES):
            b = buf.sample(BATCH)
            learn(b)
    if np.any(d):
        count += 1
    if count > BREAK_AFTER:
        break
  1. 1Acts with exploration noise, clips to [−1, 1], and steps the court; a is (2, 2), one row per racket. The repo clips first and adds the noise after, so its actions can leave [−1, 1].
  2. 2Stores one transition per racket in the shared buffer.
  3. 3Every LEARN_EVERY steps, runs N_UPDATES updates on random batches.
  4. 4Counts the done steps and ends the episode after more than 10 of them, or after 2,500 steps.

The buffer holds the last million transitions and gains only two per step, so its contents change slowly and most samples come from older versions of the opponent. That steadies learning when the world is fixed and slows adaptation when the opponent changes (a world that shifts as the opponent learns).

import torch
import torch.nn.functional as F
import torch.nn.utils as U

GAMMA, TAU, CLIP = 0.99, 1e-3, 1.5
tgts = actor_target, critic_target
nets = actor, critic

def soft_update(tgt, live):
    dst = list(tgt.parameters())
    src = list(live.parameters())
    with torch.no_grad():
        for t, p in zip(dst, src):
            t.lerp_(p, TAU)

@torch.no_grad()
def td_target(r, s_next, done):
    a2 = actor_target(s_next)
    q2 = critic_target(s_next, a2)
    keep = 1 - done
    return r + GAMMA * q2 * keep

def learn(batch):
    s, a, r, s_next, done = batch
    y = td_target(r, s_next, done)
    q = critic(s, a)
    critic_loss = F.mse_loss(q, y)
    critic_opt.zero_grad()
    critic_loss.backward()
    w = critic.parameters()
    U.clip_grad_norm_(w, CLIP)
    critic_opt.step()
    q = critic(s, actor(s))
    actor_loss = -q.mean()
    actor_opt.zero_grad()
    actor_loss.backward()
    w = actor.parameters()
    U.clip_grad_norm_(w, CLIP)
    actor_opt.step()
    for t, n in zip(tgts, nets):
        soft_update(t, n)
  1. 1Sets the constants, pairs each target network with its live network, and defines soft_update.
  2. 2Builds the target y from the target networks; keep is 0 on a step where the racket's rally ended, its done flag (line 1 of the self-play update card).
  3. 3Critic step, with gradient clipping.
  4. 4Actor step, with gradient clipping.
  5. 5Soft-updates both target networks (the soft-update card).

9 A critic that sees both rackets

Multi-Agent DDPG (MADDPG) gives each racket its own actor and its own critic, and each critic sees both rackets while it trains. A centralized critic sees every agent’s observations and actions during training, while each actor still acts on its own observation. In TennisGym both critics would read the same two observations and the same two actions.

Centralized training with decentralized execution means the critics see everything while learning, but each actor acts on its own view. At test time the critics are set aside and each racket plays from its own observations alone.

Equation 6. The two-racket critic. Each racket keeps its own actor, and its critic scores the play of both rackets together.

The first line is one actor per racket, still fed only its own observation. The second line collects both rackets’ observations into bold \(\mathbf{o}\) and both rackets’ actions into bold \(\mathbf{a}\), the joint action taught above.

The third line is the next actions from both slow actors.

The fourth line is racket \(i\)’s target: its own reward plus its slow critic’s score of the next step, over both rackets.

The fifth line is its critic loss, pulling its critic toward its target.

The last line is racket A’s actor climbing its own critic, with its own action from \(\mu_{\theta_A}\) and racket B’s stored action \(a_B\) from the buffer. Racket B’s line swaps the letters. Because every action is an input, the world the critic models stays the same while the other policy changes. This builds on the self-play update card above, with the critic widened.

9.1 MADDPG on small cooperative and competitive tasks

The paper’s multi-agent particle environments are flat two-dimensional worlds of agents and landmarks. In cooperative communication a speaker sees which landmark is the goal landmark and only speaks, and a listener can move but cannot see which one it is. So the speaker must learn to signal and the listener to follow.

In physical deception a team of agents is paid by how close the nearest of them gets to the goal landmark, while an adversary, who does not know which landmark it is, tries to reach it too. So the agents must split up to hide the goal landmark.

The paper compares MADDPG against DDPG and DQN, and against actor-critic, a policy network trained with a second network that scores it, and REINFORCE, a policy method that pushes each move by the return that followed it. Actor-critic and REINFORCE were first built for a single agent. Every method in Table 2 trained for 25000 episodes on the same task.

The paper also compares against Trust Region Policy Optimization (TRPO), a policy method that limits how far each update may move the policy. In the paper each baseline agent learns on its own, with the others treated as part of the world. Table 2 reports how often the listener reached the goal landmark.

10 Ways to pick an action, from DQN to MADDPG

Each rule turns one input into an action (Figure 16).

DQN scores a list of moves and argmax picks the top score; the agent is the banana-collecting agent of the DQN page, which walks a square arena collecting yellow bananas and picks from a short list of moves. DDPG’s actor outputs the move. Self-play runs one actor for both sides.

A move’s value \(Q(s,a)\), also called its score, is the return the agent expects if it makes move \(a\) in state \(s\) and plays on from there. (RL Basics) The sign \(\arg\max\) picks the move whose score is largest. (RL Basics) The rackets pick amounts, so their action rule cannot be a pick from a short list.

\( \displaystyle \htmlClass{eqt sym-action}{\htmlStyle{color:var(--sym-action)}{a}} = \htmlClass{eqt sym-actor}{\htmlStyle{color:var(--sym-actor)}{\mu_{\theta}}}\left(\htmlClass{eqt sym-state}{\htmlStyle{color:var(--sym-state)}{s}}\right) \)

The first line is the DQN rule: the move value \(Q_\phi(s, a)\) scores each move, \(a^*\) is the move with the highest score, and the agent takes it. The banana-collecting agent of the DQN page picks from a short list of moves. This builds on the greedy action rule of Q-Learning and epsilon-greedy around it, on RL Basics.

The second line is the DDPG rule: the actor answers the state with one move, and noise is added to that answer while training. (Training DDPG: Target Networks, Replay and Noise) This builds on the DDPG actor.

The third line is the self-play rule: each racket’s actor reads only its own observation. It is the shared-actor card, with one actor for both rackets. This builds on the shared-actor card above.
