Uncertainty Weighting

Uncertainty Weighting learns each task’s loss weight from how noisy the task is. Noisier tasks get smaller weights.

Uncertainty Weighting changes only the loss. Each task’s loss is multiplied by a weight that depends on a learned noise level σi, and a penalty term stops every noise level from growing without limit. The noise levels are trained every step, by the same optimizer and in the same backward pass as the network. The extra state is one number per task, and the extra cost is negligible. Where GradNorm sets the weights from training speed, Uncertainty Weighting sets them from each task’s learned noise level.

1 Hand-tuned loss weights

The paper that introduced the method, by Kendall, Gal and Cipolla (2018), tests it on scene understanding with Cityscapes, a dataset of street scenes. A regression task predicts a number or vector per pixel; a classification task picks a label per pixel.

The paper shows that performance depends strongly on the loss weights, and a grid search over weights is expensive. Its answer is to learn one number per task, the task uncertainty, as a parameter during training, and derive the loss weight from it.

2 Loss weighting without gradients

Like GradNorm, Uncertainty Weighting is a loss-weighting method. Unlike GradNorm, it never measures a gradient. It treats each task’s output as a probability distribution over answers, and uses one rule from probabilistic modeling: a loss that is inherently noisier should count less.

3 Task uncertainty

Builds on the standard deviation (Common Probability Distributions, section 5)

Some tasks have answers that are fully determined by the input. Others have a floor of error that no model can beat, because the information is not in the image; exact per-pixel depth is an example. The paper models this with one noise level σi per task, the same for every input, called homoscedastic task uncertainty. A larger σi means a noisier task. Pushing hard on a noisy loss partly fits the noise, so the loss weight falls with 1/σi2 (1/(2σi2) for a regression task, Section 4).

A penalty term, log σi, grows with the noise level and prevents this.

4 The uncertainty-weighted loss

Each task learns its own noise level σ, a noisier task’s loss counts for less, and a log term stops σ from growing forever. The first line is for regression tasks, the second for classification tasks.
L = Σi (Li2σi² + log σi)
The total loss L sums over every task i. Li is task i’s loss and σi (sigma) its learned noise level, so the loss weight is 12σi²: twice the noise, a quarter of the weight. On its own this term would push every σi to infinity, where every loss costs nothing. The penalty log σi grows with σi and stops that; below σi = 1 it is negative. The two terms balance where σi² equals Li, so the learned noise level follows the size of the task’s loss.
L ≈ Σi (Liσi² + log σi)
A classification task has no factor 2 in the denominator, so at the same σi its loss weighs twice as much as a regression loss. The ≈ is there because the paper derives this line with an approximation that is exact at σi = 1. The penalty is the same.

5 One training step

The weighted losses and penalties are summed into one total, and one backward pass gives gradients to the network and the noise levels together (code in Section 7).

7 Implementation in PyTorch

Builds on Adam (Adaptive Optimizers: AdaGrad, RMSProp and Adam, section 4) and weight decay (Optimizers in Practice: AdamW, SAM, Schedules and Clipping, section 1)

The code learns s = log σ² instead of σ, so the weight stays positive and training stays stable; both terms of the loss in the eq card in Section 4 rewrite in si.
si = log σi²
This keeps the σ steps of the eq card in Section 5 stable. si is the log of the squared noise level. The paper learns it because this is “more numerically stable” than learning σi and avoids division by zero: any real si gives a positive σi².
12σi² = e−si2
The regression weight is exp(-s) divided by 2. In the code, 1 + REG supplies the 2 for regression tasks only; REG is written for this page’s three tasks (semantics, instance, depth, in that order) and marks the regression ones.
log σi = si2
The penalty is s / 2 in the code. A larger start value of s starts every weight smaller, and a smaller one starts them larger; the paper found the end result insensitive to it.

The step below runs every training step on that step’s batch, with losses as batch means, as in the paper.

import torch
import torch.nn as nn
from torch.optim import Adam

# s[i] = log sigma_i^2
s = nn.Parameter(torch.zeros(K))
params = list(model.parameters())
params.append(s)
opt = Adam(params, lr=lr)
# 1 marks a regression task
REG = torch.tensor([0., 1., 1.])

def uw_step(losses):
    L = torch.stack(losses)
    w = torch.exp(-s) / (1 + REG)
    total = (w * L + s / 2).sum()
    opt.zero_grad()
    total.backward()
    opt.step()

  2. 2Marks which tasks use the regression line of the eq card in Section 4.
  3. 3Weighted losses plus penalties, a few extra operations on K numbers: line 1 of that eq card for regression tasks, line 2 for classification. Each σi² settles near its task’s loss, so a summed loss would make σ grow with the batch size. Expect a negative total, since log σ is negative below σ = 1.
  4. 4One backward pass and one step for the network and s together, step 4 in Figure 4, with no extra backward pass. The weight multiplies the whole task loss, so the heads also get gradients scaled by it (Section 3 of Gradient Balancing Inside the Training Loop compares methods that edit only the shared gradients).

There is no official code. LibMTL ships a version (--weighting UW) that uses the same s = log σ2 form with the regression factor ½ for every task.

The paper uses weight decay 10−4 and does not say whether s is excluded. Decay pulls s toward 0, which pulls every weight toward its start value. Gradient Balancing Inside the Training Loop covers how the noise levels interact with the optimizer in Sections 9.3 and 9.2.

8 When weighting is enough

GradNorm and Uncertainty Weighting both change only the loss weights. Both beat fixed weights in their papers:

PaperComparisonResult
Uncertainty WeightingThree Cityscapes tasks at 128×256, against equal weights and the best fixed weights from a grid searchBetter on all three tasks
GradNormNYUv2, against 100 networks with random fixed weightsThe best of the 100 fell short of GradNorm at the same training step

Uncertainty Weighting can be combined with a gradient method, because it only changes the losses. The weights handle scale; a method such as PCGrad or CAGrad then handles direction.

Neither weighting method fixes conflicting gradients, gradients that point against each other. Uncertainty Weighting never looks at gradients, and GradNorm measures only their norms.

Two methods learn each task’s loss weight (GradNorm and Uncertainty Weighting). Four methods edit the task gradients (PCGrad, GradVac, CAGrad and MGDA). The question each one answers:

MethodThe question it answers
GradNormHow much weight should each task's loss get so all tasks train at a similar rate? (learned during training from how fast each loss falls)
Uncertainty Weighting (this page)How much weight should each task's loss get, given how noisy that task's targets are? (the noise level is learned along with the model)
PCGradHow should a task gradient be edited when it conflicts with another task's gradient?
GradVacHow should each pair of task gradients be moved toward a target cosine, a running average of that pair's past cosines?
CAGradHow can a step raise the smallest per-task improvement while staying near the average gradient?
MGDAWhich convex combination of task gradients lowers every task's loss at once, and when does no such combination exist?

When the weights are right but the gradients still conflict, PCGrad edits the directions.
