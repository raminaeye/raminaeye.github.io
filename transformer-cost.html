Transformer Cost and Efficiency

Attention compares every token with every other token, so its cost grows with the square of the length. This page shows where that cost lands and maps the techniques that cut it.

1 Each technique cuts a different part

Each technique below cuts a different part of attention's cost, and each has its own page.

The cost is paid in every attention layer: over all \(n\) tokens at once in training and when a prompt is read in (prefill), then once per new token while the model writes (decoding).

2 Attention's cost grows with the square of the length

Every token is \(d\) numbers wide (the model width). Attention scores each token against every other token, so the work and memory follow the number of pairs.

Attention, the operation whose cost this page measures.
\({\displaystyle \htmlClass{eqt sym-s}{\htmlStyle{color:#9a6400}{S}}=\frac{\htmlClass{eqt sym-q}{\htmlStyle{color:#7d3c98}{Q}}\htmlClass{eqt sym-k}{\htmlStyle{color:#a04000}{K}}^{\top}}{\sqrt{d_k}}}\)
Think of a chat model reading a long prompt: every word is compared with every other word. The score table \(S\) holds how well each query \(Q\) matches each key \(K\). \(d_k\) is the number of entries in each key; dividing the scores by its square root keeps them from growing with the head size. \(S\) has one entry for every pair of tokens, an \(n\) by \(n\) table, so double the tokens and the table has four times the entries. That table is the cost this page follows.
\({\displaystyle \htmlClass{eqt sym-o}{\htmlStyle{color:#117a7a}{O}}=\mathrm{softmax}(\htmlClass{eqt sym-s}{\htmlStyle{color:#9a6400}{S}})\,\htmlClass{eqt sym-v}{\htmlStyle{color:#a04000}{V}}}\)
Softmax turns each row of scores into weights, and each row of the output \(O\) is the weighted average of the values \(V\).

After attention, each layer runs a feed-forward network on every token on its own. The card below compares the two costs.

The two costs of one layer in FLOPs (one per multiply or add), attention against the feed-forward network.
\({\displaystyle \text{attention FLOPs}=4\,\htmlClass{eqt sym-n}{\htmlStyle{color:#9a6400}{n}}^{2}\htmlClass{eqt sym-d}{\htmlStyle{color:#1f618d}{d}}}\)
Building the table takes one dot product of length \(d\) for every pair of tokens, and the weighted sum of the values takes as many multiply-adds again; each multiply-add is two FLOPs. The square on the length \(n\) is the whole point: double the prompt and attention costs four times as much.
\({\displaystyle \text{FFN FLOPs}=4\,\htmlClass{eqt sym-n}{\htmlStyle{color:#9a6400}{n}}\,\htmlClass{eqt sym-d}{\htmlStyle{color:#1f618d}{d}}\,d_{\mathrm{ff}}}\)
The feed-forward network (FFN) widens each token from \(d\) to \(d_{\mathrm{ff}}\) and back, two matrix products per token, each multiply-add two FLOPs. It works on each token alone, so it grows only in a straight line with the length.
\({\displaystyle \phantom{\text{FFN FLOPs}}=16\,\htmlClass{eqt sym-n}{\htmlStyle{color:#9a6400}{n}}\,\htmlClass{eqt sym-d}{\htmlStyle{color:#1f618d}{d}}^{2}}\)
With \(d_{\mathrm{ff}}\) four times \(d\), as in the original Transformer, the FFN's square is in the width \(d\), not in the length.
\({\displaystyle 4\,\htmlClass{eqt sym-n}{\htmlStyle{color:#9a6400}{n}}^{2}\htmlClass{eqt sym-d}{\htmlStyle{color:#1f618d}{d}}=16\,\htmlClass{eqt sym-n}{\htmlStyle{color:#9a6400}{n}}\,\htmlClass{eqt sym-d}{\htmlStyle{color:#1f618d}{d}}^{2}}\)
Setting the two costs equal asks at what length attention catches up with the FFN.
\({\displaystyle \htmlClass{eqt sym-n}{\htmlStyle{color:#9a6400}{n}}=4\htmlClass{eqt sym-d}{\htmlStyle{color:#1f618d}{d}}}\)
Dividing both sides by \(4nd\) gives the answer: when the sequence is four times as long as the model is wide. Shorter sequences spend most of their FLOPs in the FFN; longer ones spend most in attention. GPT-3's context window is far shorter than four times its width, so most of its compute still goes to the FFN.

The count leaves out the query, key, value and output projections, the softmax and the norms; it compares only the two parts whose growth differs. Memory follows the same square, because the score table has one entry per pair of tokens in every head.

Windowed attention bounds the square (Sliding-Window Attention). Sparse attention scores only chosen pairs, and linear attention rewrites the formula so no table is built; neither has its own page here.

3 Training pays for the table, generation pays for memory

In training and prefill, the whole table is computed at once, so moving it in and out of memory sets the time. In decoding, each step adds only one row, but it reads the stored keys and values of every earlier token.

4 When the length makes attention too costly

With very long sequences, windowed, sparse or linear attention cuts the quadratic cost itself; FlashAttention cuts only memory traffic, and attention sinks let a model trained with full attention stream through a windowed cache.

Conformer puts convolution back beside attention for speech; Quantization and Pruning make a trained Transformer cheaper to serve, and Adapters fine-tune one without retraining all of it.

5 Cost failures and the page that fixes each

The score table is the first thing to fix: can attention give the exact same answer without ever writing the table to slow memory? FlashAttention.
