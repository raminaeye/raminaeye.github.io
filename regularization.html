Regularization and Data Augmentation

Methods that reduce overfitting, a model fitting the noise in its training data instead of the pattern.

A model overfits when training error sinks while test error climbs (Understanding Model Errors). Two families of methods reduce it, constraining the model and adding training data; the third part cleans the data so the model learns the signal, not sensor faults. Every technique here acts only while training or on the data, and is judged on held-out data.

Constrain the modeldropout, L1 and L2
Add training dataaugmentation, class imbalance
Clean the datafiltering, missing channels, fusion

1 Constraining the model

1.1 Dropout

Dropout trains the network with random neurons switched off, so it cannot rely on any one of them; at test time the full network runs. Dropout zeroes each activation with probability p on every forward pass (one run of an input through the network), so each pass trains a slightly different, thinned sub-network and no single neuron can carry the prediction alone. The mask is a Bernoulli draw: a weighted coin flip per neuron that lands on "keep" with probability 1 − p.

Dropout acts on every training forward pass with a fresh random mask for every example, keeps no state between steps, and is switched off at test time; its cost is one random draw and one multiply per activation (Srivastava et al. 2014). A larger drop chance p is a stronger regularizer and underfits when too high; p = 0 turns dropout off, and at p = 1 nothing passes. PyTorch's default is 0.5.

Dropout masks the activation, then rescales the kept units.
ã = (m · a) · 11 − p
a is the activation before the mask, one number per neuron. The mask m is 1 for a kept unit and 0 for a dropped one, so multiplying zeroes the dropped units. Only a share 1 − p survives on average, so the output would shrink by that share; the fraction scales the kept units back up and keeps the expected activation the same. That is why nothing changes at test time, when no unit is dropped. ã (a-tilde) is the result.

The equation in PyTorch for one layer of 12 activations: the mask m keeps each unit with probability 1 − p, and a_tilde is ã, the kept units scaled by 1/(1 − p); 0.2 is a common rate.

import torch

p = 0.2  # drop chance
a = torch.randn(12)
u = torch.rand_like(a)
m = (u > p).float()  # mask
a_tilde = m * a / (1 - p)  # ã
  1. 1Sets the drop chance p and 12 activations a.
  2. 2Draws the mask m, keeping each unit with probability 1 − p.
  3. 3Keeps the unmasked units and scales them by 1/(1 − p), the dropout equation.

At inference time, when the trained model runs on new data, nothing is dropped: the full network runs, and the training-time rescale already matches its scale. In PyTorch torch.nn.Dropout masks only in training mode; the code reuses p and a, and in a real model model.train() and model.eval() switch every dropout layer at once.

drop = torch.nn.Dropout(p)
drop.train()
a_train = drop(a)  # masked
drop.eval()
a_test = drop(a)  # equals a
  1. 1In training mode the layer masks and rescales.
  2. 2In evaluation mode it passes a through unchanged.

Dropout also acts like noise injection in the hidden layers: the noise forces the model to learn features that survive small disturbances. Rates are often small; the original Transformer used 0.1. Its relatives drop bigger or smaller pieces: stochastic depth skips whole residual blocks during training (Huang et al. 2016) and DropConnect zeroes single weights instead of units (Wan et al. 2013).

1.2 L1 and L2 penalties

Another way to constrain the model is to make large weights cost something: add a penalty on the weights to the loss, so training trades a little fit for smaller weights. What comes out is a model with smaller weights, and with L1 many of them exactly zero.

The penalty is part of the loss, so it acts at every step on every weight, keeps no state and costs one sum over the weights; AdamW applies the L2 penalty as weight decay inside the optimizer step instead (AdamW).

L1 and L2 add the weights' sizes, or their squares, to the loss.
Ltotal = L + λ·Σi |wi|
L1. L is the data loss, how wrong the model is, and λ (lambda) sets how much the penalty counts against it. Σi adds up over every weight i, and the bars take each weight's size without its sign, so every unit of weight costs the same whether the weight is big or small. A larger λ makes weights more expensive, so the fit gives up some data loss to keep them small; λ = 0 removes the penalty, and a very large λ pushes every weight toward zero and underfits. There is no universal default; PyTorch's optimizers default to 0 except AdamW at 0.01.
Ltotal = L + λ·Σi wi2
L2 squares each weight instead. A weight twice as large costs four times as much, so L2 punishes big weights hardest and barely notices small ones, so the model uses many small weights instead of a few large ones.

L2 produces shrinkage: the weights get smaller but stay non-zero. With Adam, use AdamW for this (Optimizers).

L1 regularization uses absolute values instead. It produces sparsity, and the gradients show why.

Each penalty pushes on a weight with its gradient.
∂∂wi (λ·wi2) = 2λ·wi
The stacked ∂ fraction is the slope of the penalty as wi changes. For L2 the push is proportional to the weight: a big weight is pulled back hard and a small one gently, so the push fades as the weight shrinks and the weight approaches zero without reaching it.
∂∂wi (λ·|wi|) = λ·sign(wi)
sign(wi) is +1 for a positive weight and −1 for a negative one; the slope of |wi| is undefined at zero. The L1 push has the same size whatever the weight, so a small weight is pushed toward zero as hard as a big one, and many weights land exactly at zero, the corners in Figure 2.

A penalty can also be read as a constraint: the weights must stay inside a region around the origin, a ball for L2 and a diamond for L1, and the solution is the first point of that region the loss contours (rings of equal loss) touch.

2 Adding training data

Regularization cuts the estimation error, the part of the error that comes from too little data for the model's flexibility (Understanding Model Errors). Adding training data also cuts it: with more varied examples there is less room to memorize.

2.1 Data augmentation for wearables

A gesture recorded with the wristband twisted is still the same gesture, so a twisted copy of a recording is a new training example with a true label. Each augmentation in the table mimics one real source of variation. The same label-keeping edits make the positive pairs of Contrastive Learning.

Augmentations are drawn fresh each time a training window is loaded, so every epoch sees a different copy; they touch the training data only, never validation or test data, keep no state, and cost time in the data loader rather than in the model.

augmentationwhat it mimics
channel dropoutlost contact or a misaligned sensor
channel shufflingthe band shifting along the arm
spatial mixingthe displacement blur of a shifted band
rotationthe band worn twisted or at another angle
random scalingstrap tightness or skin-electrode impedance (how much the skin contact holds back the signal)
temporal jitterthe delay that altered placement introduces
cross-modal maskinga missing sensor type

Twisting the band around the arm keeps x and rotates y and z, so a twisted band records the same motion rotated; the augmentation applies that rotation to the readings.

A general rotation multiplies one rotation per axis together and applies it to each sensor vector.
v′ = Rz(ψ) Ry(θ) Rx(φ) v
The rotated reading v′ (v-prime) is the original reading v, a 3D vector in the band's x, y, z axes, multiplied by three rotation matrices. Rx(φ) turns by the roll angle φ (phi) around x, Ry(θ) by the pitch angle θ (theta) around y, and Rz(ψ) by the yaw angle ψ (psi) around z. Each matrix only turns the vector, so its length, the strength of the motion, stays the same. The matrices apply right to left, roll first and yaw last, and the order matters because turns about different axes do not commute.

SciPy turns one window of 200 accelerometer readings by a small random roll, pitch and yaw, drawn fresh for each window in degrees and converted to radians; acc_rotated keeps the shape [time, 3].

import numpy as np
import scipy.spatial.transform as st
rng = np.random.default_rng()
shape = (200, 3)  # [t, 3]
acc = rng.normal(size=shape)
# roll, pitch, yaw in degrees
deg = rng.uniform(-15, 15, 3)
rad = np.radians(deg)
euler = st.Rotation.from_euler
rot = euler("xyz", rad)
acc_rotated = rot.apply(acc)
  1. 1Makes one window of 200 readings on three axes.
  2. 2Draws roll, pitch and yaw within 15 degrees.
  3. 3Builds the rotation and applies it to every reading.

Channel dropout and shuffling on one window x of 8 channels by 500 samples; each writes a new array, so x itself is unchanged.

import numpy as np
rng = np.random.default_rng()
x = rng.normal(size=(8, 500))
n_ch, p = len(x), 0.1
# channel dropout: zero rows
keep = rng.random(n_ch) > p
x_drop = x * keep[:, None]
# shuffle: swap rows i, i + 1
i = rng.integers(n_ch - 1)
rows = [i, i + 1]
x_shuf = x.copy()
x_shuf[rows] = x[rows[::-1]]
  1. 1Makes one window of 8 channels by 500 samples.
  2. 2Channel dropout zeroes each channel with chance p.
  3. 3Shuffling swaps two neighbouring channels.

Random scaling and jitter reuse x and rng: each channel gets its own gain between 0.8 and 1.2, and the whole window shifts by up to 20 samples. Wider ranges make more varied windows and a stronger regularizer, until they produce signals no real wearer would record.

# strap tightness per channel
u = rng.random((n_ch, 1))
gain = 0.8 + 0.4 * u
x_scaled = x * gain
# jitter: shift ≤ 20 samples
k = rng.integers(-20, 21)
x_jit = np.roll(x, k, axis=1)
  1. 1Scales each channel by its own gain between 0.8 and 1.2.
  2. 2Shifts the whole window by up to 20 samples.

2.2 Class imbalance

If 95 of 100 windows are rest, always guessing rest scores 95 percent and catches nothing. Class imbalance makes the model overfit to easy, frequent samples. You can oversample minority classes, undersample majority classes, or augment minority classes more. SMOTE (Synthetic Minority Over-sampling Technique, Chawla et al. 2002) oversamples without duplicating: it uses k-NN (k-nearest neighbors, the classifier from k-Nearest Neighbors) to find a nearby minority sample and interpolates a new one on the line between them.

SMOTE places a new minority sample at a random point on the line to a neighbor.
xnew = xi + u · (xnn − xi)
The new sample xnew starts at a minority sample xi and moves a share u of the way toward xnn, one of its nearest minority neighbors. u is drawn between 0 and 1, so the new point always lies between two real minority examples: it fills in the region the class already occupies instead of copying a point. A far neighbor would put samples in unlikely places, which is why SMOTE uses the nearest ones.

Loss-level techniques reweight instead. Class-weighted loss weights the minority class higher, and balanced batch sampling gives each batch (a group of examples processed together) roughly the same class representation. In the code 95 labels are common and 5 rare, and w is the inverse class frequency; it goes to the loss as one weight per class or to the sampler as one weight per sample, so use one of the two.

from torch import nn, tensor
import torch.utils.data as tud
labels = [0] * 95 + [1] * 5
y_train = tensor(labels)
counts = y_train.bincount()
w = counts.sum() / counts
# option 1: weighted loss
loss_fn = nn.CrossEntropyLoss(w)
# option 2: balanced batches
WRS = tud.WeightedRandomSampler
n = len(y_train)
sampler = WRS(w[y_train], n)
  1. 1Counts each class and sets its weight to the inverse frequency.
  2. 2Option 1 passes the weights to the loss.
  3. 3Option 2 passes one weight per sample to the sampler.

The class weights are computed once from the training labels, before training; a weighted loss then applies them at every step, and a weighted sampler uses them to draw every epoch's batches (PyTorch's CrossEntropyLoss and WeightedRandomSampler). SMOTE runs once, on the training split only.

commonrarecommon, flaggedrare, caughtflagged as rare

Figure 5. A logistic-regression line splits 60 common windows from 6 rare ones; a larger w pushes it into the common class, catching more rare cases and flagging more common ones.

Focal loss (Lin et al. 2017) focuses training on hard-to-classify examples by down-weighting the easy ones the model already classifies confidently, so they stop dominating the loss:

Focal loss is cross-entropy scaled down for confident examples.
FL = −(1 − pt)γ log pt
pt is the probability the model gives the true class, and −log pt is the usual cross-entropy, large when pt is small. The factor in front shrinks the loss of examples the model already gets right: a confident example has pt near 1, so the factor is near 0 and it barely counts, while a misclassified one keeps nearly its full loss. A larger γ (gamma) down-weights easy examples harder, and γ = 0 gives back plain cross-entropy; a very large γ ignores almost every example the model already gets right. The focal loss paper used γ = 2.

3 Cleaning sensor data

Wearable signals arrive noisy, drifting, and sometimes missing entirely. A model fed raw signals can learn the sensor faults instead of the signal.

3.1 Preprocessing sensory data

A powerline hum is added to every channel, and the zero level drifts slowly. A little signal processing removes both and keeps the signal.

Filtering runs on each recording before the model sees it, in the same way for training, test and live data; the z-score uses one person's recording, so the only state it keeps is a mean and a spread per channel.

stepwhat it removes
band-pass filterlow-frequency drift and high-frequency noise, keeping one band
notch filterone narrow band, the powerline hum, leaving the frequencies around it
rectify and envelopethe sign and the fast oscillation: absolute value, then a low-pass, traces how strong the signal is
z-score per channel, per person or sessionamplitude differences across people and sessions: subtract that recording's average, divide by its spread

SciPy designs each filter once and runs it forward and backward with filtfilt, so nothing shifts in time: a 4th-order band-pass from 20 to 450 Hz, its edges given as fractions of the Nyquist rate nyq, half the sampling rate, then a notch at the 60 Hz mains hum, on 8 channels sampled at 1000 Hz.

import numpy as np
from scipy.signal import butter
from scipy.signal import filtfilt
from scipy.signal import iirnotch
fs, hum = 1000, 60  # Hz
x = np.random.randn(8, 2000)
nyq = fs / 2
wn = (20 / nyq, 450 / nyq)
b, a = butter(4, wn, "bandpass")
x_band = filtfilt(b, a, x)
b, a = iirnotch(hum, 30, fs)
clean = filtfilt(b, a, x_band)
  1. 1Sets the sampling rate, the hum frequency and 8 channels of signal.
  2. 2Band-pass from 20 to 450 Hz, run forward and backward.
  3. 3Notch out the 60 Hz hum.

The envelope is the rectified signal low-passed at 5 Hz; the z-score subtracts each channel's mean and divides by its spread over this person's recording, and z keeps the shape [channels, time].

# rectify, low-pass at 5 Hz
b, a = butter(4, 5, fs=fs)
rect = np.abs(clean)
env = filtfilt(b, a, rect)
# z-score per channel
mu = env.mean(axis=1)[:, None]
sd = env.std(axis=1)[:, None]
z = (env - mu) / (sd + 1e-8)
  1. 1Rectifies and low-passes at 5 Hz to get the envelope.
  2. 2Z-scores each channel over this recording.

Features can then be hand-made in time and frequency, or learned by the model's own layers.

3.2 Missing data and fusing modalities

Bluetooth packet loss or sweat can leave missing channels. In the code a channel is bad when it has no spread or sits at the top of the range, 5 here, more than half the time; each bad channel gets the mean of the good channels, and the mask bad goes to the model too, so it learns to ignore the missing channels.

import numpy as np
x = np.random.randn(8, 500)
x[3] = 0.0  # a flat channel
flat = x.std(axis=1) < 1e-6
pegged = np.abs(x) >= 5.0
share = pegged.mean(axis=1)
bad = flat | (share > 0.5)
fill = x[~bad].mean(axis=0)
x_fill = x.copy()
x_fill[bad] = fill
  1. 1Makes 8 channels and flattens one.
  2. 2Marks a channel bad when it is flat or stuck at its maximum value more than half the time.
  3. 3Fills each bad channel with the mean of the good ones.

The channel check runs on every window, in training and on live data, keeps no state across windows, and its mask travels with the window into the model.

Combining modalities lets one sensor cover for another. An encoder is the part that compresses a signal into features, and a decoder makes the prediction from them.

Very late fusion, one separate model per sensor with only the outputs joined, does not solve the missing-signal problem.

With cross-modal attention (Cross-Attention) instead, one sensor's features query the other's, so the model learns how much to trust each in context and down-weights a missing or noisy one. In PyTorch A's features are the queries and B's the keys and values, so fused has A's shape, w says how much each A step used each B step, and off is True for B steps to ignore; the tensors are laid out [time, batch, features], the layer's default.

import torch
from torch import nn
# [time, batch, features]
A = torch.randn(50, 2, 32)
B = torch.randn(20, 2, 32)
off = torch.zeros(2, 20).bool()
off[:, 10:] = True  # B drops
MHA = nn.MultiheadAttention
attn = MHA(32, num_heads=4)
# 4th argument: the B mask
fused, w = attn(A, B, B, off)
  1. 1Makes features for sensors A and B and marks B's last 10 steps as missing.
  2. 2Builds an attention layer with 4 heads.
  3. 3A's features query B's, skipping the masked steps.

The mask handles a partly missing B. If every B step in a row is masked, that row can come out as NaN; one fix is to keep one always-valid token in B.

Foundation-style models such as SensorLM (Zhang et al. 2025) pretrain one encoder on a large cohort of people (Self-Supervised Learning); a small labeled calibration set from a new person can then fine-tune lightweight per-person heads.

4 Regularizers in a PyTorch training loop

Each regularizer lives in a different part of the training code. Augmentation runs in the data pipeline, on each sample every time it is drawn. Dropout lives inside the model and draws a fresh mask on every training forward pass. Weight decay lives in the optimizer step, and class weights live in the loss. The first snippet builds three of them once, a small classifier net with dropout, an AdamW optimizer, and a loss that weights a rare third class 5 times higher.

import torch
from torch import nn
net = nn.Sequential()
net.append(nn.Linear(8, 64))
net.append(nn.ReLU())
net.append(nn.Dropout(p=0.5))
net.append(nn.Linear(64, 3))
# AdamW default decay: 0.01
ps = net.parameters()
opt = torch.optim.AdamW(ps)
w = torch.tensor([1., 1., 5.])
loss_fn = nn.CrossEntropyLoss(w)
  1. 1Builds the classifier with dropout inside the model.
  2. 2Builds AdamW, which carries the weight decay.
  3. 3Builds the loss that weights the rare class 5 times higher.

The second snippet runs one training step on a batch of 32 rows. A small random jitter stands in for augmentation (in a real project it sits in the dataset's __getitem__), net.train() turns dropout on, and net.eval() turns it off before any evaluation.

x = torch.randn(32, 8)
noise = torch.randn_like(x)
x = x + 0.05 * noise  # jitter
y = torch.randint(3, (32,))
net.train()  # dropout on
loss = loss_fn(net(x), y)
opt.zero_grad()
loss.backward()
opt.step()  # also decays
net.eval()  # dropout off
  1. 1Makes one batch and jitters it, the data-pipeline step.
  2. 2Turns dropout on and computes the weighted loss.
  3. 3Backward pass and one step, which also decays the weights.
  4. 4Turns dropout off before evaluation.

None of these costs much. Dropout draws one random mask per forward pass and is an identity in eval mode. Weight decay is one multiply per weight per step with no state, and class weights add almost no cost. Augmentation costs CPU time in the data loader every epoch, because each sample is transformed afresh. The dropout paper kept hidden units with probability 0.5 and inputs with probability 0.8; the focal loss paper used gamma=2 and alpha=0.25, where α weights the rare positive class against 1 − α for the rest, so raising it counts rare examples more; these are also the defaults of torchvision's sigmoid_focal_loss. Dropout itself is torch.nn.Dropout.

  • PyTorch's p is the chance a unit is dropped; in the dropout paper it is the chance a unit is kept, so their 0.8 for inputs is p=0.2 here.
  • Augment only the training data; the validation and test sets stay untouched, or the scores no longer measure real inputs.
  • weight_decay means two things: in SGD and Adam it adds L2 to the gradient, in AdamW it shrinks the weights directly.

Constraining the model, adding data and cleaning the inputs all reduce overfitting. Training must still lower the loss, and choosing the size and direction of each training step is the job of Optimizers.
