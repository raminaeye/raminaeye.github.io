Logistic Regression

On the regression page a line predicts a number. Here the answer is yes or no: is this forum post about hockey? Logistic regression keeps the line and maps its score to a probability with the sigmoid.

1 Why a linear score is not a probability

The posts come from 20 Newsgroups, nearly 19,000 posts from 20 Usenet discussion groups (Lang, 1995). Two groups are used here, rec.sport.hockey and comp.windows.x (the X Window System), and each post is described by two counts: how often it says window or widget, and how often it says game or team.

Fit a line to 0-or-1 labels and it predicts values above 1 or below 0, which are not probabilities, and one far point drags the whole line sideways.

So we keep the line as a raw score and pass it through the sigmoid, a function that maps any number into the range 0 to 1. That number reads as a probability, and 0.5 becomes the decision boundary.

2 The sigmoid function

The line's raw score can be anything from minus infinity to plus infinity. The sigmoid squashes it into a chance between 0 and 1: a large positive score means almost surely hockey, a large negative one almost surely comp.windows.x, and whatever chance is not hockey is the chance of comp.windows.x:

The sigmoid squashes any score into a number between 0 and 1, so it can be read as a probability: big positive scores give nearly 1, big negative scores nearly 0.
\(\displaystyle \sigma (\htmlStyle{color:var(--sym-logit)}{z}) = \frac{1}{1+e^{\htmlStyle{color:var(--sym-logit)}{-z}}}\)
\(z\) is the raw score and \(\sigma\) (sigma) here is the sigmoid function, not a standard deviation; \(e\) is Euler's number, about 2.718. Big positive scores come out near 1, big negative scores near 0.
\(\displaystyle \sigma (0) = 0.5\)
A score of 0 lands at an even split, a probability of one half. The curve is steepest here, where the decision lives, and flattens at the extremes, where the probability is already near 0 or 1.
\(\displaystyle \sigma (-\htmlStyle{color:var(--sym-logit)}{z}) = 1 - \sigma (\htmlStyle{color:var(--sym-logit)}{z})\)
The curve is symmetric around zero, so a score of \(-z\) gives no the same probability that \(z\) gives yes.
So the chance of hockey rises smoothly as the score grows, fastest near a score of 0. The first eq card in Section 3 scores those probabilities.

3 The cross-entropy loss

Squared error asks "how far off was the number?" For probabilities the better question is "how surprised were you?" If the truth is yes and you were confident it was yes, little surprise. If you were confident it was no, huge surprise. That is the binary cross-entropy cost (the cross-entropy loss with two classes): each sample's cost depends only on the probability it gave its true label.

Binary cross-entropy charges each post by how surprised the model was by its true label: a confident miss costs far more than a confident hit.
\(\displaystyle L = -\log \htmlStyle{color:var(--sym-prob)}{p} \quad (\htmlStyle{color:var(--sym-target)}{y} = 1)\)
It scores the probability \(p\) from the eq card in Section 2. \(y\) is the true label, 1 for yes and 0 for no; \(p = \sigma (z)\) is the predicted probability of yes; \(\log\) is the natural log. For a yes (\(y = 1\)) the cost is \(-\log p\): near 0 when \(p\) is near 1, and growing without limit as \(p\) falls toward 0, so a confident right answer costs almost nothing and a confident wrong one costs a lot.
\(\displaystyle L = -\log (1 - \htmlStyle{color:var(--sym-prob)}{p}) \quad (\htmlStyle{color:var(--sym-target)}{y} = 0)\)
The cost of a no (\(y = 0\)), the same rule mirrored: \(1 - p\) is the probability given to no. The NumPy training step packs both cases into one line, where \(y\) switches one term off.
So the cost rewards probabilities that match the truth, and a confident miss costs far more than a confident hit. The next eq card gives the slope of this cost.

Cross-entropy is the negative log likelihood of a coin-flip model.

Builds on losses as likelihoods (Maximum Likelihood and EM, section 6)

The gradient, the arrow that points uphill on the cost so the learning step can go the other way and lower it, has a shape you already know:

The slope of one post’s cost along each weight is its error, the chance minus the label, times that weight’s input.
\(\displaystyle \frac{\partial L}{\partial \htmlStyle{color:var(--sym-w)}{w_{j}}} = (\htmlStyle{color:var(--sym-prob)}{p} - \htmlStyle{color:var(--sym-target)}{y})\cdot \htmlStyle{color:var(--sym-x)}{x_{j}}\)
This is the slope of the cost in the eq card above. How much the cost changes when weight \(w_{j}\) alone changes (\(\partial\) reads "partial"): the error \(p - y\) times feature \(x_{j}\). The error is \(p - 1\) for a yes and \(p\) for a no, so a sure, right answer barely moves the weights.
\(\displaystyle \frac{\partial }{\partial \htmlStyle{color:var(--sym-w)}{w_{j}}} \frac{1}{2}(\hat{y} - \htmlStyle{color:var(--sym-target)}{y})^{2} = (\hat{y} - \htmlStyle{color:var(--sym-target)}{y})\cdot \htmlStyle{color:var(--sym-x)}{x_{j}}\)
The squared-error gradient from linear regression, where \(\hat{y}\) is the raw line's prediction. Put \(p\) in place of \(\hat{y}\) in this result and you get the first line: cross-entropy's log cancels the sigmoid's slope, which squared error would keep as an extra \(p (1 - p)\).
So the same gap \(p - y\) drives every weight, and a weight whose input is 0 does not move. The eq card in Section 4 runs that step.

One full-batch training step in NumPy, with labels 0 or 1.

import numpy as np
# X: (n, 2), y: (n,) of 0/1
EPS = 1e-12  # keeps log finite
z = X @ w + b
p = 1 / (1 + np.exp(-z))
p = np.clip(p, EPS, 1 - EPS)
yes = y * np.log(p)
no = (1 - y) * np.log(1 - p)
loss = -np.mean(yes + no)
n = len(y)
grad_w = X.T @ (p - y) / n
grad_b = np.mean(p - y)
w = w - lr * grad_w
b = b - lr * grad_b
  1. 1Score \(z\) and sigmoid \(p\) (Section 2).
  2. 2Cross-entropy averaged over the batch (Section 3).
  3. 3The gradient is \((p - y)\) times each feature.
  4. 4One step downhill with step size \(\text{lr}\).

4 One post, from counts to a learning step

Figure 2. The ringed hockey post is scored, turned into a probability, called, and used for one learning step.

One post goes from counts to a probability to a call, then nudges the weights: add up the weighted counts, turn the score into a probability, call it at 0.5, and take one learning step.
\(\displaystyle \htmlClass{eqt}{\htmlData{k=z}{\htmlStyle{color:var(--sym-logit)}{z}}} = \htmlClass{eqt}{\htmlData{k=w1x1}{\htmlStyle{color:var(--sym-w)}{w_{1}}}}\cdot \htmlClass{eqt}{\htmlData{k=w1x1}{\htmlStyle{color:var(--sym-x)}{x_{1}}}} + \htmlClass{eqt}{\htmlData{k=w2x2}{\htmlStyle{color:var(--sym-w)}{w_{2}}}}\cdot \htmlClass{eqt}{\htmlData{k=w2x2}{\htmlStyle{color:var(--sym-x)}{x_{2}}}} + \htmlClass{eqt}{\htmlData{k=b}{\htmlStyle{color:#2c3e50}{b}}}\)
Lines 1 and 2 are the score and the sigmoid of the eq card in Section 2; line 4 uses the slope from Section 3. The score multiplies each count by its weight, adds them up and shifts the sum by the bias. A larger weight makes its count matter more; the bias moves every post's score by the same amount.
\(\displaystyle \htmlClass{eqt}{\htmlData{k=p}{\htmlStyle{color:var(--sym-prob)}{p}}} = \sigma (\htmlClass{eqt}{\htmlData{k=z}{\htmlStyle{color:var(--sym-logit)}{z}}}) = \frac{1}{1+e^{\htmlClass{eqt}{\htmlData{k=z}{\htmlStyle{color:var(--sym-logit)}{-z}}}}}\)
The sigmoid turns the score into a probability by mapping any number into the range between 0 and 1. Read the fraction as 1 divided by 1 plus \(e\) raised to the power \(-z\).
\(\displaystyle \text{decide}\;\; \htmlClass{eqt}{\htmlData{k=p}{\htmlStyle{color:var(--sym-prob)}{p}}} \ge \htmlClass{eqt}{\htmlData{k=half}{\htmlStyle{color:#c0392b}{0.5}}}\)
The call is yes when the probability is at least one half, and no otherwise.
\(\displaystyle \htmlClass{eqt}{\htmlData{k=wj}{\htmlStyle{color:var(--sym-w)}{w_{j}}}} \leftarrow \htmlClass{eqt}{\htmlData{k=wj}{\htmlStyle{color:var(--sym-w)}{w_{j}}}} - \htmlClass{eqt}{\htmlData{k=eta}{\htmlStyle{color:#2c3e50}{\eta }}}\cdot (\htmlClass{eqt}{\htmlData{k=p}{\htmlStyle{color:var(--sym-prob)}{p}}} - \htmlStyle{color:var(--sym-target)}{y})\cdot \htmlStyle{color:var(--sym-x)}{x_{j}}\)
In one learning step on this post, each weight moves against its gradient \((p - y) \cdot x_{j}\), scaled by the learning rate \(\eta\) (eta, lr in the code). Here \(y = 1\), so \(p - y\) is negative and each weight grows along its feature; the bias takes the same step with \(x\) set to 1.
So even a post called right still nudges the line: its chance of hockey rises a little, and over many steps the line settles where the posts’ gaps balance. The first eq card in Section 5.1 names where that line sits.

5 The decision boundary

5.1 A threshold draws a straight boundary

The sigmoid hits one half exactly when the raw score is zero. With the fit used in the figures, that line runs between the two groups and calls every one of the ten illustrative posts in Figure 2 right.

Calling a post hockey when its chance is at least one half is the same as asking whether its score is at least zero, and the points with score zero form a straight line.
\(\displaystyle \sigma (\htmlStyle{color:var(--sym-logit)}{z}) \ge 0.5 \Leftrightarrow \htmlStyle{color:var(--sym-logit)}{z} \ge 0\)
The score \(z\) is the one from the eq card in Section 2, and the 0.5 call is line 3 of the eq card in Section 4. The sigmoid crosses one half exactly at zero (\(\Leftrightarrow\) reads "exactly when"), so "probability at least one half" is "raw score at least zero".
\(\displaystyle \htmlStyle{color:var(--sym-w)}{w_{1}}\cdot \htmlStyle{color:var(--sym-x)}{x_{1}} + \htmlStyle{color:var(--sym-w)}{w_{2}}\cdot \htmlStyle{color:var(--sym-x)}{x_{2}} + \htmlStyle{color:#2c3e50}{b} = 0\)
The boundary is the points where the score \(w_{1} \cdot x_{1} + w_{2} \cdot x_{2} + b\) is zero: a straight line, the same line from regression, now working as the boundary between yes and no.
So a threshold of one half means this straight line between the two groups. The next eq card moves it for other thresholds.

Any other threshold \(t\) also gives a straight boundary, just shifted.

Calling a post hockey only when its chance clears a threshold \(t\) moves the line to where the score equals the logit of \(t\), the log odds.
\(\displaystyle \operatorname{logit}(\htmlClass{eqt}{\htmlData{k=t}{\htmlStyle{color:#c0392b}{t}}}) = \log \frac{\htmlClass{eqt}{\htmlData{k=t}{\htmlStyle{color:#c0392b}{t}}}}{1 - \htmlClass{eqt}{\htmlData{k=t}{\htmlStyle{color:#c0392b}{t}}}}\)
It shifts the line of the eq card above. \(\operatorname{logit}(t)\) is the log of the threshold \(t\) divided by \(1 - t\), the share that is left. It names the raw score whose sigmoid is exactly \(t\), so the boundary for a general threshold sits where the raw score equals \(\operatorname{logit}(t)\), and at \(t = 0.5\) this gives the score-zero boundary of the 0.5 card.
So the threshold is a choice about misses against false alarms, applied to the same line; a higher \(t\) pushes the line further into the hockey side. The eq card in Section 5.2 extends the model past two groups.

Every point whose probability clears \(t\) lands on the yes side. Raising \(t\) calls fewer posts hockey (fewer false alarms, more misses); lowering it calls more. Figure 3 lets you move it.

5.2 More than two classes

Telling all 20 groups apart needs one score per group. One-vs-rest runs one yes-or-no model per group; the softmax, the multi-class form of the sigmoid, scores all groups at once, with one weight vector per group trained on the 11,314 training posts.

Builds on softmax (Common Probability Distributions, section 3)

Softmax gives one probability per group, all adding to 1, so the same model covers all 20 groups.
\(\displaystyle \htmlStyle{color:var(--sym-prob)}{p_{c}} = \frac{e^{\htmlStyle{color:var(--sym-logit)}{z_{c}}}}{\sum_{m} e^{\htmlStyle{color:var(--sym-logit)}{z_{m}}}}\)
Each \(z_{c}\) is a score like the one from the eq card in Section 2, one per group. \(z_{c}\) is class \(c\)'s score and \(m\) runs over every class. Exponentiate every class score and divide by their sum, so the probabilities \(p_{c}\) sum to 1. Exponentiating makes every score positive and widens the gaps, so the top class takes most of the probability; adding the same number to every score changes nothing. With two classes it is the sigmoid again.
So two groups is the special case of this line, and the top score takes most of the probability. The eq card in Section 6 keeps the weights in check.

The tools on this page use ten illustrative posts and an illustrative fit, so each step is easy to see; the code below runs the same steps on the real posts.

The two groups in scikit-learn, with a vocabulary of just the two word lists.

from sklearn.datasets import fetch_20newsgroups
from sklearn.feature_extraction.text import CountVectorizer
from sklearn.linear_model import LogisticRegression
import numpy as np
groups = ["comp.windows.x", "rec.sport.hockey"]
data = fetch_20newsgroups(categories=groups)
words = ["window", "windows", "widget", "widgets",
         "game", "games", "team", "teams"]
counts = CountVectorizer(vocabulary=words).fit_transform(data.data)
X = np.c_[counts[:, :4].sum(1), counts[:, 4:].sum(1)]
y = data.target  # 1 = rec.sport.hockey
clf = LogisticRegression()
clf.fit(X, y)
p = clf.predict_proba(X)[:, 1]
t = 0.5  # threshold
called_hockey = p >= t
print(clf.coef_, clf.intercept_)
  1. 1Fetches the two groups and counts the window words \(x_{1}\) and the game words \(x_{2}\) in each post.
  2. 2Fits the weights by lowering the cross-entropy (Section 3).
  3. 3Chance of hockey, called at threshold \(t\) (Section 5).

6 Regularization and class weights

When a straight line can almost split the classes, training inflates the weights to push probabilities to 1 and 0. Regularization adds a penalty that grows with the weights.

scikit-learn sets the penalty with \(C\), the inverse of its strength: a smaller \(C\) means a stronger penalty.

Regularization adds a charge for large weights, so the model cannot lean hard on a few rare words.
\(\displaystyle \htmlClass{eqt}{\htmlData{k=Lt}{\htmlStyle{color:#2c3e50}{L_{\text{total}}}}} = \htmlClass{eqt}{\htmlData{k=L}{\htmlStyle{color:#2c3e50}{L}}} + \htmlClass{eqt}{\htmlData{k=lam}{\htmlStyle{color:#8e44ad}{\lambda }}}\cdot \sum_{j} \htmlClass{eqt}{\htmlData{k=w}{\htmlStyle{color:var(--sym-w)}{w_{j}}}}^{2}\)
\(L\) is the cross-entropy of the first eq card in Section 3, added over all posts. \(\lambda\) (lambda) is the penalty strength; \(\sum_{j}\) adds up over every weight \(j\). Each weight is squared, so a weight twice as large costs four times as much. Raise \(\lambda\) and the weights shrink, the probabilities soften toward 0.5; at \(\lambda = 0\) the weights on separable data grow without bound. scikit-learn sets the strength with \(C\) instead, the eq card’s next line; its default is \(C = 1.0\).
\(\displaystyle \htmlClass{eqt}{\htmlData{k=C}{\htmlStyle{color:#2c3e50}{C}}} = \frac{1}{2\htmlClass{eqt}{\htmlData{k=lam}{\htmlStyle{color:#8e44ad}{\lambda }}}}\)
\(C\) is one over twice the penalty strength, so a small \(C\) is a strong penalty.
So the weights stay moderate, and the probabilities with them. End of the chain.

When yes is rare, class weights multiply each yes sample's loss: a larger weight calls more posts yes, a smaller one fewer, and the default weights every class 1.

Each line builds one model; "balanced" weights each class by the inverse of its share of the samples.

from sklearn.linear_model import LogisticRegression
LR = LogisticRegression
strong = LR(C=0.1)  # strong penalty, small C
yes_x5 = LR(class_weight={1: 5})
bal = LR(class_weight="balanced")

The boundary is still straight. The SVM page trains the same kind of boundary with the hinge loss, a cost that is zero once a point is past the boundary by a margin.

7 Logistic regression in practice

The usual pipeline; predict_proba returns one row per post and one column per group.

from sklearn.datasets import fetch_20newsgroups
from sklearn.feature_extraction.text import TfidfVectorizer
from sklearn.linear_model import LogisticRegression
from sklearn.pipeline import make_pipeline

fetch = fetch_20newsgroups
train = fetch(subset="train")
test = fetch(subset="test")
Xtr, ytr, Xte, yte = train.data, train.target, test.data, test.target
LR = LogisticRegression
clf = LR(C=1.0, max_iter=1000)
vec = TfidfVectorizer()
model = make_pipeline(vec, clf)
model.fit(Xtr, ytr)
proba = model.predict_proba(Xte)
acc = model.score(Xte, yte)
  1. 1Loads all 20 groups with their own train and test split.
  2. 2Word weights (TF-IDF, counts scaled down for common words), then logistic regression with \(C = 1\) and up to 1,000 solver iterations (max_iter); too few stops early with a warning.
  3. 3Fits, then test probabilities and accuracy.

LogisticRegression uses the lbfgs solver with an L2 penalty; each iteration is about one pass over the data. The penalty is on by default, so scale first, or unscaled features are penalized unevenly. With three or more classes it fits one softmax model, not the notebook's one-vs-rest set, so its probabilities can differ slightly. For streaming data, SGDClassifier with the log loss takes the per-batch steps taught above.

8 Failure modes of logistic regression

Unscaled featuresSlow, uneven steps, with one weight racing while the other crawlsStandardize the features first

9 XOR needs a nonlinear boundary

A group that sits between two others cannot be cut off by one straight line. XOR, two classes on the two diagonals of a square, is the simplest data set with that problem. Stacking lines with bends between them fixes it, on the next page, Multilayer Perceptrons (MLP).
