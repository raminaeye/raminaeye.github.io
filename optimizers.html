Optimizers

Each one fixes a failure of plain stochastic gradient descent (SGD).

An optimizer turns each step's gradient into a weight update that lowers the training loss; the ones here differ in how they smooth that slope and how large a step each weight gets. Neural nets, unlike linear regression, have no closed-form answer, so they are trained step by step (Gradient Descent), and each optimizer in the map fixes one failure of the one before it.

SGDone step size

Adammomentum plus RMSPropAdamWdecoupled decayNadamNesterov momentum

Each row fixes a failure of the row above.

Each acts once per training step on one minibatch's gradient and keeps its own buffers between steps; a schedule changes α between steps, and clipping trims the gradient just before the update (PyTorch's torch.optim documentation).

1 SGD and adaptive optimizers

1.1 Gradient descent and SGD

Stochastic gradient descent (SGD) steps against the gradient of one fresh random minibatch instead of the whole dataset (Robbins and Monro 1951): a noisier slope for one minibatch's forward and backward pass per step, with no state beyond the weights.

Plain SGD moves every weight by one shared step size times its minibatch slope.
θ ← θ − α·∇L(θ)
The weights θ move against the slope ∇L(θ), scaled by the learning rate α, exactly as in gradient descent. The slope is read on a random minibatch, so each step is a cheap, noisy estimate of the full slope, and the noise averages out over many steps. One α serves every weight, so a weight on a steep direction and one on a flat direction get the same multiplier, the weakness the rest of this page fixes.

Plain SGD on a three-weight linear model in NumPy; every weight in w (θ) moves by the same lr (α) times its own slope.

import numpy as np
rng = np.random.default_rng(0)
X = rng.normal(size=(256, 3))
y = X @ rng.normal(size=3)
w = np.zeros(3)
lr, bs = 0.1, 32  # α, batch
for i in range(0, 256, bs):
    xb = X[i:i + bs]
    yb = y[i:i + bs]
    err = xb @ w - yb
    grad = 2 * xb.T @ err / bs
    w = w - lr * grad
  1. 1Data, zero weights, α and the batch size.
  2. 2Takes the next minibatch of rows.
  3. 3Slope of the batch's mean squared error.
  4. 4Steps every weight by the same α.

Too large an α oscillates or diverges, too small converges slowly; PyTorch's SGD defaults to 0.001 and its documentation example uses 0.1. A larger batch gives a less noisy slope but fewer steps per pass over the data: the whole set is plain gradient descent, and 1, the default of PyTorch's DataLoader, follows a single example. The noise is cheap and helps near a saddle point:

At a saddle point the gradient is zero, yet the point is not a minimum.
L(x, y) = x2 − y2
In this two-weight toy loss L, the squared x term rises on both sides, so along x the point is a minimum; the subtracted y term falls on both sides, so along y it is a maximum. Curvatures of opposite sign are what make a saddle.
∇L(0, 0) = (0, 0)
At the origin the slope is zero in both directions, so gradient descent started exactly there never moves, and started near it moves very slowly because the slope is tiny. Minibatch noise or momentum moves the weights off the saddle and down along y.

High-dimensional losses are full of saddles; full-batch descent can sit near one for a long time, and minibatch noise can push the weights off it.

1.2 SGD with momentum

Momentum damps SGD's oscillation with a velocity v, a running sum of past slopes kept per weight, a model-sized buffer for one extra multiply and add (PyTorch's momentum_buffer; Sutskever et al. 2013), written as in PyTorch's SGD:

Momentum builds a velocity from past slopes, then steps by it.
v ← μ·v + ∇L(θ)
The new velocity v is the old one shrunk by μ (mu), typically 0.9, plus today's slope. Slopes that keep pointing the same way pile up, so speed grows along a consistent direction, up to about ten single slopes at 0.9; slopes that flip sign from step to step cancel, so the oscillation dies down. A larger μ averages over more past slopes: smoother and faster on long slopes, slower to turn.
θ ← θ − α·v
The weights move by α times the velocity instead of the raw slope, so every step carries the memory of past slopes.

Momentum in NumPy on a quadratic loss 20 times steeper in one direction.

import numpy as np

# loss ½(x² + 20y²)
# its slope is curv·θ
curv = np.array([1.0, 20.0])
theta = np.array([-4.0, 1.0])
v = np.zeros_like(theta)
lr, mu = 0.04, 0.9  # α, μ
for t in range(100):
    grad = curv * theta
    v = mu * v + grad
    theta = theta - lr * v
  1. 1Loss, start, zero velocity, α and μ.
  2. 2Reads today's slope.
  3. 3Shrink v by μ, add the slope, the first momentum line.
  4. 4Steps by α times the velocity, the second momentum line.

At μ = 0 this is plain SGD; as μ nears 1 old slopes never fade, so the weights overshoot and swing around the minimum. PyTorch's SGD defaults to μ = 0; its documentation example uses 0.9. How momentum interacts with gradient balancing is on the multitask training loop page.

1.3 Nesterov accelerated gradient (NAG)

NAG computes the gradient at the lookahead point, where the velocity is about to carry the weights, instead of at the current weights, so it sees an overshoot one step early and overshoots less; its state is the same one velocity per weight.

NAG is momentum with the slope read where the velocity is taking you.
v ← μ·v + ∇L(θ − α·μ·v)
The velocity update is the same, except the slope is read at the lookahead point the current velocity is about to carry the weights to. If that point has overshot, its slope already points back, so the velocity slows down one step earlier than plain momentum and swings less around a minimum.
θ ← θ − α·v
The step itself is the same as momentum; only where the slope was read changed. The momentum paper writes the velocity with α inside it and the opposite sign; the path is the same.

1.4 AdaGrad

The next optimizers give every weight its own step size: a weight tied to a rare input feature needs a large step when that feature appears, and one with a gradient every step needs small steps.

AdaGrad keeps, per weight, the running sum of its squared gradients, a model-sized buffer that only grows (Duchi et al. 2011). α scales every step by one factor, so a larger α moves further before the growing total stalls it; ε matters only while a total is near zero, where a larger ε keeps the first steps smaller. PyTorch defaults to α = 0.01 and ε = 1e-10.

AdaGrad divides each weight's step by that weight's own gradient history.
Gt = Gt−1 + gt2
Gt adds today's squared gradient gt to a running total for one weight. Squaring makes every gradient count as a positive size, so Gt measures how large that weight's gradients have been so far. It never shrinks.
θ ← θ − α·gt√Gt+ε
Each weight's step is divided by the square root of its own total, which brings the total back to gradient units. A weight that gets large gradients often builds a big total and takes small steps; a rarely updated weight keeps a small total and large steps. Because the total only grows, every step keeps shrinking, which can stall training late. ε is a tiny guard against dividing by zero.

Because the sum never shrinks, the step shrinks forever.

1.5 RMSProp

RMSProp swaps the sum for a decaying average per weight, again model-sized, so old gradients fade and the step follows the recent scale (Tieleman and Hinton 2012).

RMSProp lets old gradients decay, so the step tracks the recent scale.
Et = β2Et−1 + (1−β2)gt2
Et keeps the β2 share of the old average and takes the rest from today's squared gradient. Old gradients fade by a factor β2 each step, so at 0.9 the average reflects roughly the last ten steps; a β2 nearer 1 reacts more slowly to a change in gradient size, and β2 = 0 uses only today's gradient. PyTorch's RMSProp defaults to 0.99, with α = 0.01 and ε = 1e-8. It is the same average as Adam's vt, so its rate gets the same name.
θ ← θ − α·gt√Et+ε
AdaGrad's step with Et in place of the growing sum. Because Et falls again when gradients get small, the step recovers instead of shrinking forever.

1.6 Adam (adaptive moment estimation)

Adam combines momentum with RMSProp's per-weight scale. It carries two averages per weight, m and v, plus a step counter t for the zero-start correction, twice the model's size in state (Kingma and Ba 2015).

Adam keeps two running averages: one smooths the slope, the other tracks each weight's own scale.
mt = β1mt−1+(1−β1)gt
The momentum mt keeps the β1 share of its old value and takes the rest from today's raw slope gt. A slope that flips sign cancels out while a steady one survives; at 0.9 the average spans about ten steps.
vt = β2vt−1+(1−β2)gt2
vt averages the squared slope instead, with β2 near 0.999, so it spans about a thousand steps. Squaring drops the sign, so vt tracks how large each weight's gradients are, not which way they point.
Both averages start at zero, so early on they are scaled back up.
m̂t = mt1−β1t
The divisor is one minus the decay rate raised to the step count t. On the first step it is small, so mt is scaled up to a real slope size; as t grows the divisor heads to 1 and the correction disappears.
v̂t = vt1−β2t
The same correction for the squared average. It matters more here: with β2 at 0.999 the divisor stays far below 1 for hundreds of steps, and without it the early steps would be far too large.
Adam steps by the smoothed slope, scaled per weight.
θ ← θ − α·m̂t√v̂t+ε
The step is the corrected momentum divided by the root of the corrected squared average, times α. That ratio is the slope over its own typical size, so for a steady direction it sits near one whatever the units: steep directions are scaled down, flat ones up, and α alone sets the step length. When the slope is noisy the ratio shrinks, so Adam takes smaller steps where the slope keeps changing sign. ε guards the division; a larger ε caps the step where the squared average is tiny and pushes Adam toward plain momentum. Raising β1 toward 1 smooths the slope over more steps but turns more slowly, and β1 = 0 drops momentum; lowering β2 lets a single very large gradient shrink the step quickly. The Adam paper's defaults are α = 0.001, β1 = 0.9, β2 = 0.999 and ε = 1e-8.
read the slope smooth it track each axis's own scale fix the startup bias step

2 AdamW, Nadam and sharpness-aware minimization

2.1 AdamW (Adam with decoupled weight decay)

Weight decay shrinks the weights toward zero each step. Adam applies it as L2 inside the gradient, where it gets rescaled per weight and distorted; AdamW decouples it, with the same state as Adam (Loshchilov and Hutter 2019):

Adam with L2 and AdamW differ only in where the weight decay term goes.
gt = ∇L(θ) + λθ
Adam with L2 adds λθ, the slope of the L2 penalty, into the gradient; λ (lambda) is the decay strength (the penalty is written as λ/2 times the sum of squared weights; the Regularization page drops the one-half, which only rescales λ). Added here, the decay flows into both moments and gets divided by the root of v̂t, so weights with large gradients get almost no decay.
θ ← θ − α·(m̂t√v̂t+ε + λθ)
AdamW moves the decay outside the fraction. The moments see only ∇L(θ), and every weight shrinks by the same α·λ share of itself each step, which is the decay the penalty intended. A larger λ keeps the weights smaller and the model simpler, too large underfits, and λ = 0 is plain Adam; PyTorch's AdamW defaults to 0.01.

PyTorch has both, so pick one; 1e-3 and 1e-2 are AdamW's defaults for α and λ.

import torch
from torch.optim import Adam
from torch.optim import AdamW
model = torch.nn.Linear(10, 1)
p = list(model.parameters())
lr, lam = 1e-3, 1e-2  # α, λ
decay = dict(weight_decay=lam)
# Adam: λθ joins the grad
adam = Adam(p, lr, **decay)
# AdamW: decay outside it
adamw = AdamW(p, lr, **decay)
  1. 1A small model, α and λ.
  2. 2Adam with λ inside the gradient, the L2 line.
  3. 3AdamW with the decay outside the rescaling, the AdamW line.

So for adaptive methods, weight decay is not L2 regularization.

2.2 Nadam (Nesterov-accelerated Adam)

Nadam brings Nesterov's idea to Adam: it adds a larger share of the current slope to the smoothed momentum, so it reacts faster, without moving the weights to a lookahead point; its state is Adam's (Dozat 2016).

Nadam is Adam's step with an extra share of the current gradient.
m̄t = β1m̂t + (1−β1)gt1−β1t
m̄t blends the corrected momentum with a bias-corrected share of today's raw gradient gt. Mixing today's gradient in directly is Nesterov's lookahead in Adam form: the step points further toward where the momentum is heading instead of waiting a step for the average to catch up.
θ ← θ − α·m̄t√v̂t+ε
Adam's step with m̄t in place of m̂t; the per-weight pacing is unchanged. This follows the Nadam paper, simplified to a constant β1.

2.3 SAM (sharpness-aware minimization)

SAM wraps another optimizer instead of replacing it. Plain optimizers can land in a sharp minimum; SAM looks for flat minima, where the loss stays low when the weights change a little. Both of its passes use the same minibatch; it adds no state, but each step costs two forward and backward passes, about twice plain training (Foret et al. 2021).

SAM finds the worst small change to the weights, then descends from there.
δ = ρ·∇L(θ)‖∇L(θ)‖
δ (delta) is a perturbation, a small change to the weights, of length ρ (rho) pointing straight uphill: the gradient divided by its own length ‖∇L(θ)‖ is an arrow of length one, and ρ sets how far it reaches. For a small radius uphill is where the loss rises fastest, so the perturbed point is roughly the worst point within ρ. A larger ρ judges flatness over a wider neighborhood, and too large a ρ lands on points that say little about the minimum; ρ = 0 is the base optimizer. SAM's CIFAR examples use 0.05.
gSAM = ∇L(θ + δ)
gSAM is the slope at that worst point, and the optimizer applies it at θ itself. In a sharp minimum the worst point sits high on its side and its slope is large, so SAM is pushed out of sharp minima and settles in flat ones.

perturb is SAM's first pass; ps holds the weight tensors with zeroed gradients and closure returns the minibatch loss.

import torch
from torch import stack
def perturb(ps, closure, rho):
    closure().backward()
    gs = [p.grad for p in ps]
    ns = [g.norm() for g in gs]
    k = rho / stack(ns).norm()
    ds = [k * g for g in gs]
    with torch.no_grad():
        for p, d in zip(ps, ds):
            p.add_(d)  # θ + δ
    return ds
  1. 1Reads the gradient at θ.
  2. 2Scales it to length ρ, which is δ, the first SAM line.
  3. 3Moves every weight to θ + δ and returns δ.

One SAM step calls perturb, reads the gradient at θ + δ, moves back to θ, and lets the base optimizer opt step with that gradient, gSAM.

ds = perturb(ps, closure, rho)
opt.zero_grad()
closure().backward()  # θ + δ
with torch.no_grad():
    for p, d in zip(ps, ds):
        p.sub_(d)  # back to θ
opt.step()  # steps with g_SAM
  1. 1Moves to θ + δ with perturb.
  2. 2Reads the gradient there, gSAM, the second SAM line.
  3. 3Moves the weights back to θ.
  4. 4Lets the base optimizer step with gSAM.

SAM's one uphill step approximates the worst loss within ρ of the weights.

Different weights can compute the same function yet look sharper or flatter, so flatness is a rule of thumb, not a guarantee.

3 Learning rate schedules and gradient clipping

3.1 Learning rate schedulers

A large rate moves fast early, but near a minimum a constant rate keeps bouncing, so schedulers bring α down as training goes.

  • Step decay drops it by a factor every few epochs (passes over the data).
  • Exponential decay shrinks it by a fixed fraction each step or epoch.
  • Cosine annealing stays near the maximum rate early and eases into the minimum late.
  • Warm restarts jump back to the maximum after each cosine cycle, so training can leave its minimum for others (Loshchilov and Hutter 2017).
  • One-cycle rises first, then falls, pairing the large rate with low momentum (Smith 2018).
Cosine annealing lowers the rate from its maximum to its minimum along a cosine.
αt = αmin + 12(αmax − αmin)·st
αt is the learning rate at step t of a T-step schedule. It is αmin plus a share of the range up to αmax, and the share is half of st, so the rate always stays between the two.
st = 1 + cos(π·tT)
st is 1 plus a cosine that sweeps half a turn as t runs from 0 to T, so it falls from 2 to 0. A cosine is flat at both ends, so the rate lingers near αmax early, drops fastest mid-training and eases gently into αmin at the end.

A scheduler keeps one counter, the steps or epochs so far, and sets α from it at almost no cost. Step decay, exponential decay and cosine annealing usually step once per epoch; one-cycle steps once per batch (Smith 2018 counts its cycle in iterations), and warm restarts can too (Loshchilov and Hutter 2017).

Each schedule is a PyTorch class wrapping the optimizer: StepLR multiplies the rate by gamma, 0.1 here, every 30 epochs, ExponentialLR by 0.95 every epoch, and CosineAnnealingLR follows a cosine over T_max epochs.

import torch
import torch.optim as optim
S = optim.lr_scheduler
net = torch.nn.Linear(4, 1)
ps = net.parameters()
opt = optim.SGD(ps, lr=0.1)
# pick one, stepped per epoch
s = S.StepLR(opt, 30, 0.1)
s = S.ExponentialLR(opt, 0.95)
Cos = S.CosineAnnealingLR
s = Cos(opt, T_max=100)
  1. 1Builds a model and an SGD optimizer to schedule.
  2. 2Step decay: the rate times 0.1 every 30 epochs.
  3. 3Exponential decay: the rate times 0.95 every epoch.
  4. 4Cosine annealing over 100 epochs, the cosine schedule equation.

Warm restarts repeat every T_0 epochs; one-cycle rises to a peak rate of 0.1 and back over 1000 steps, stepped per batch. A smaller gamma or a shorter interval cuts the rate sooner and harder, which can freeze training before the loss flattens; a longer T_max or T_0 stretches each cycle; a higher one-cycle peak explores more but can diverge. PyTorch's defaults are a gamma of 0.1 for StepLR, a minimum rate eta_min of 0 for the cosine schedules, and 30 percent of the one-cycle spent warming up.

WR = S.CosineAnnealingWarmRestarts
s = WR(opt, T_0=10)
OneCycle = S.OneCycleLR
s = OneCycle(opt, 0.1, 1000)
for step in range(1000):
    opt.step()
    s.step()  # per batch
  1. 1Warm restarts every 10 epochs.
  2. 2One-cycle up to 0.1 and back over 1000 steps.
  3. 3Steps the optimizer, then the one-cycle schedule, once per batch.

3.2 Gradient clipping

Gradient clipping guards against exploding gradients, gradients that suddenly become very large: a gradient longer than a threshold τ is shrunk to length τ. It keeps no state and costs one length over all the gradients (Pascanu et al. 2013).

Clipping by norm keeps the direction and caps the length at τ.
g ← g·min(1, τ‖g‖)
g is the gradient over all weights together and ‖g‖ its length. Under the threshold τ (tau), τ divided by the length is above 1, the min picks 1 and nothing changes. Above it, the factor rescales the whole gradient to length exactly τ. Every weight is scaled by the same factor, so the direction is kept and only a rare very large gradient is scaled down. A smaller τ clips more steps, steadier but slower when large gradients are real; a very large τ never clips. PyTorch sets no default.

Clipping sits between backward() and opt.step(): clip_grad_norm_ rescales all gradients by one factor so their joint length is at most max_norm (τ); 1.0 is a common starting value, not a rule.

import torch
import torch.nn.utils as U
net = torch.nn.Linear(4, 1)
ps = list(net.parameters())
opt = torch.optim.SGD(ps, 0.1)
x = torch.randn(8, 4)
y = torch.randn(8, 1)
err = net(x) - y
loss = (err ** 2).mean()
loss.backward()
U.clip_grad_norm_(ps, 1.0)
opt.step()  # after the clip
  1. 1Builds a model, an optimizer and one batch.
  2. 2Computes the loss and fills the gradients.
  3. 3Gradient length capped at τ, the clipping equation.
  4. 4Steps with the clipped gradient.

4 Optimizers in a PyTorch training loop

The optimizer is built once, before the loop, and owns the parameters' buffers from then on; each batch runs forward, backward, the optional clip and opt.step(), and the scheduler changes α per batch or per epoch.

The setup builds a linear model net, AdamW, and a cosine schedule with T_max of 80 steps.

import torch
import torch.optim as optim
S = optim.lr_scheduler
net = torch.nn.Linear(8, 1)
ps = net.parameters()
opt = optim.AdamW(ps)  # once
Cos = S.CosineAnnealingLR
sched = Cos(opt, T_max=80)
  1. 1Builds the model and AdamW once, before the loop.
  2. 2Wraps the optimizer in a cosine schedule over 80 steps.

One update per batch, over 80 batches of 32 rows with 8 inputs and 1 target.

data = torch.randn(80, 32, 9)
for b in data:
    x, y = b[:, :8], b[:, 8:]
    err = net(x) - y
    loss = (err ** 2).mean()
    opt.zero_grad()
    loss.backward()
    opt.step()  # every batch
    sched.step()  # per batch
  1. 1Splits each batch into inputs and targets and computes the loss.
  2. 2Clears old gradients and fills new ones.
  3. 3One optimizer update per batch.
  4. 4One schedule tick per batch.

Here T_max counts batches, so the scheduler steps every batch; with T_max in epochs it steps once per epoch, after the inner loop, as in the PyTorch docs example.

The update is a few element-wise operations per weight, small next to the forward and backward passes; optimizers differ in memory and passes per step. Adam's state is exp_avg and exp_avg_sq per weight tensor.

PyTorch's AdamW defaults are a rate of 1e-3, betas of 0.9 and 0.999, eps of 1e-8 and weight decay of 0.01 (AdamW documentation), the first three as the Adam paper suggests. SAM's official code is in JAX (google-research/sam); its CIFAR examples use a radius ρ of 0.05.

  • Calling sched.step() before opt.step() skips the schedule's first value; PyTorch requires this order since version 1.1 (torch.optim documentation).
  • Saving only the model loses Adam's moments, so a resumed run restarts them at zero; save opt.state_dict() too.
  • weight_decay in SGD and Adam is an L2 term in the gradient, which Adam rescales; only AdamW decays the weights directly.
