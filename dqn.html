This page builds on Q-Learning and keeps its words.

  • A Q-table keeps one move value \(Q(s,a)\) for every state \(s\) and move \(a\): the return the agent expects if it makes that move and plays on from there (A table of move values).
  • After each move, the target \(y_t\) is the step’s reward plus the best move value in the next state, shrunk by the discount \(\gamma\) (The target).
  • The TD error \(\delta_t\) is the target minus the old guess (The TD error).
  • The learning rate \(\eta\) sets what share of that gap each update closes (The learning rate), and the update rule moves the played entry that share of the way to the target (The update rule).
  • Epsilon-greedy usually picks the move with the highest value and, with a small chance \(\varepsilon\), a random one, so the agent keeps exploring (Explore or exploit).
  • Q-learning is off-policy: its target uses the best next move, whatever move the agent really makes next, so it learns best play while it explores (Learning best play while exploring).

Some worlds never show the same situation twice, so a table of move values can never be filled. This page builds what replaces it, Deep Q-Networks, and how to keep it steady while it learns, one idea at a time.

1 Why a table fails

The running example is my own banana collector. An agent walks around a square arena, earning a reward of plus one for each yellow banana it picks up and minus one for each blue one. It has four moves: forward, backward, turn left and turn right.

The agent does not see a grid square. Its state is a list of sensor readings: its own speed, and for each ray fanned out in front of it, what the ray hits and how far away.

Move a hair to the left and every reading shifts a little, so the agent hardly ever meets the same list twice. A Q-table would need a new row for every list, each seen once and never again, and what one row learned would not help the next, nearly equal one. The Atari agent of Mnih and colleagues at DeepMind, the work that made DQN famous, saw screen pixels, which repeat even less.

What is needed is something that gives a move value for any list of readings, even a new one, and similar answers for similar lists.

2 A network for move values

A neural network does that. A multilayer perceptron takes a list of numbers in, passes it through layers of weights, and hands a list of numbers out. Here the readings go in and one move value per move comes out, so one pass fills a whole row of the old table, for any state.

This network is called a Q-network, and its move value for move \(a\) in state \(s\) is written \(Q(s,a;\phi)\), where \(\phi\) (the Greek letter phi) stands for all of its weights. The semicolon says the value depends on the weights as well as on the state and move.

The network has far fewer weights than a table would need rows, so it must reuse the same weights for every state. That is the point: two nearly equal lists of readings come out with nearly equal move values, so a lesson learned in one moment carries over to the next. Standing in for a table this way is called function approximation.

3 Learning from a target

Q-learning’s target still works: after a move, the agent knows the step’s reward and the next state, and the network gives the best move value there. The update does not. A network has no entry to nudge, because every value comes out of the shared weights, so the nudge has to happen to the weights.

The way to change weights is the one from Gradient Descent: write down a loss, a number that is large when the network is wrong, and take a step downhill on it. Here the network is wrong by the TD error, the gap between the target and its own value for the move just played. Squaring the gap makes every miss count as a positive amount.

\(\displaystyle \begin{aligned} \htmlClass{eqt}{\htmlStyle{color:#196f3d}{y_t}} &= \htmlClass{eqt}{\htmlStyle{color:#7d6608}{r_{t+1}}} \\ &\quad + \htmlClass{eqt}{\htmlStyle{color:#2c3e50}{\gamma}} \max_{\htmlClass{eqt}{\htmlStyle{color:#a04000}{a'}}} \htmlClass{eqt}{\htmlStyle{color:#8e44ad}{Q}}(\htmlClass{eqt}{\htmlStyle{color:#2471a3}{s_{t+1}}}, \htmlClass{eqt}{\htmlStyle{color:#a04000}{a'}}; \htmlClass{eqt}{\htmlStyle{color:#1b4f72}{\phi}}) \end{aligned}\)
The target is Q-learning’s: the step’s reward \(r_{t+1}\) plus the discounted best move value that the network now gives in the next state \(s_{t+1}\). \(\max_{a'}\) takes the largest over the next moves \(a'\). On the last step of an episode nothing follows, so the target is the reward alone.
\(\displaystyle \htmlClass{eqt}{\htmlStyle{color:#b03a2e}{\delta_{t}}} = \htmlClass{eqt}{\htmlStyle{color:#196f3d}{y_t}} - \htmlClass{eqt}{\htmlStyle{color:#8e44ad}{Q}}(\htmlClass{eqt}{\htmlStyle{color:#2471a3}{s_{t}}}, \htmlClass{eqt}{\htmlStyle{color:#a04000}{a_{t}}}; \htmlClass{eqt}{\htmlStyle{color:#1b4f72}{\phi}})\)
The TD error, as before: the target minus the network’s value for the move that was played.
\(\displaystyle \htmlClass{eqt}{\htmlStyle{color:#2c3e50}{\mathcal{L}}}(\htmlClass{eqt}{\htmlStyle{color:#1b4f72}{\phi}}) = \htmlClass{eqt}{\htmlStyle{color:#b03a2e}{\delta_{t}}}^{2}\)
The loss \(\mathcal{L}\) is the squared gap. It is zero only when the played move value already equals its target.
\(\displaystyle \htmlClass{eqt}{\htmlStyle{color:#1b4f72}{\phi}} \leftarrow \htmlClass{eqt}{\htmlStyle{color:#1b4f72}{\phi}} - \htmlClass{eqt}{\htmlStyle{color:#2c3e50}{\eta}}\, \nabla_{\htmlClass{eqt}{\htmlStyle{color:#1b4f72}{\phi}}} \htmlClass{eqt}{\htmlStyle{color:#2c3e50}{\mathcal{L}}}\)
One gradient step. \(\nabla_{\phi}\mathcal{L}\) is the direction in which the loss grows fastest, so the weights take a step the other way, scaled by the learning rate \(\eta\). The arrow means replace.

While the gradient is computed, the target is treated as a fixed number, so the step pulls only the played move value toward it, the way Q-learning nudged one entry. But the step changes the weights, and the next target is computed from those same weights, so the target has moved by then. Section 4.2, The target moves, comes back to this.

3.1 Learning from a batch

A gradient step on one played step follows a single moment, so it is a noisy pull. Network training usually averages the loss over several examples, a batch, so that each step follows many moments. For now, take the batch to be the agent’s last \(B\) steps; replay memory, in section 5, later changes where they come from.

A batch holds steps from different times, so from here on step \(i\) of the batch is written \(s_i, a_i, r_i, s_i'\): state, move, reward and next state, the prime meaning next, as in \(a'\).

\(\displaystyle \htmlClass{eqt}{\htmlStyle{color:#b03a2e}{\delta_{i}}} = \htmlClass{eqt}{\htmlStyle{color:#196f3d}{y_i}} - \htmlClass{eqt}{\htmlStyle{color:#8e44ad}{Q}}(\htmlClass{eqt}{\htmlStyle{color:#2471a3}{s_{i}}}, \htmlClass{eqt}{\htmlStyle{color:#a04000}{a_{i}}}; \htmlClass{eqt}{\htmlStyle{color:#1b4f72}{\phi}})\)
The TD error of step \(i\), with its target \(y_i\) built as above from \(r_i\) and \(s_i'\).
\(\displaystyle \htmlClass{eqt}{\htmlStyle{color:#2c3e50}{\mathcal{L}}}(\htmlClass{eqt}{\htmlStyle{color:#1b4f72}{\phi}}) = \frac{1}{\htmlClass{eqt}{\htmlStyle{color:#2c3e50}{B}}} \sum_{i} \htmlClass{eqt}{\htmlStyle{color:#b03a2e}{\delta_{i}}}^{2}\)
The loss is now the average squared gap: the sum \(\sum_i\) adds up the batch’s steps and \(\tfrac{1}{B}\) divides by their count. The gradient step is the same as before.

That is the core of a Deep Q-Network (DQN), “deep” for the network’s layers: a Q-network trained by gradient steps toward Q-learning’s target. Done exactly as written, it tends to go wrong, and the full recipe adds two fixes. Section 4, Why plain training wobbles, shows why.

4 Why plain training wobbles

A gradient step touches shared weights, so it changes the move values of many states at once, not only the one played. That sharing makes the network useful, and it can also make plain training swing or run off to huge values, for two separate reasons.

4.1 Steps in a row look alike

A batch of the agent’s most recent steps comes from one small stretch of the arena, all with nearly the same readings, so every step in it pulls the shared weights the same way. The network gets good at that stretch and, through the shared weights, can get worse everywhere else. A moment later the agent is somewhere new, and the pull swings there.

4.2 The target moves

In a table, nudging one entry leaves the entry the target came from alone. In a network, the target \(y_i\) is computed by the same weights that the gradient step changes. The next state is a nearly equal list of readings, so a step that raises the played move value raises the next state’s values too, and with them the target. The network keeps aiming at a mark that slides away as it reaches for it, and the values can climb without end.

Each problem gets its own fix. Replay memory breaks up steps in a row, and a target network holds the target still.

5 Replay memory

The first fix keeps a replay memory, a long store of past steps. After every move the agent stores the step: state, move, reward, next state, and whether the episode ended there. When the memory is full, the oldest steps fall out. Each batch is drawn at random from the whole memory instead of taken from the last few moves. Its steps come from all over the arena and from long ago, so their pulls on the weights point many ways and cancel where they disagree, leaving the lesson they share. Each stored step is also reused in many batches, so every move teaches more than once.

Is it fair to learn from steps that an older, more random version of the agent made? For Q-learning’s target, yes. It asks what the best move from the next state is worth, not what move the agent made next, so a stored step teaches the same lesson whoever made it. That is the off-policy property from Q-Learning.

6 The target network

The second fix gives the target its own weights. DQN keeps two copies of the Q-network. The live network, weights \(\phi\), picks moves and takes the gradient steps. The target network, weights \(\phi'\), is a slow copy used only to compute targets (the Atari paper writes \(\theta\) and \(\theta^-\)). Because the copy changes slowly, a gradient step no longer drags the target along: for a while the network chases a mark that stands still.

A hard copy overwrites the target network with the live weights every so many updates and freezes it in between, as the Atari paper did. A soft update moves the target weights a small share \(\tau\) (the Greek letter tau) of the way toward the live weights after every update, so the copy trails smoothly, as my banana agent does.

\(\displaystyle \htmlClass{eqt}{\htmlStyle{color:#5d4037}{\phi'}} \leftarrow \htmlClass{eqt}{\htmlStyle{color:#2c3e50}{\tau}}\, \htmlClass{eqt}{\htmlStyle{color:#1b4f72}{\phi}} + (1 - \htmlClass{eqt}{\htmlStyle{color:#2c3e50}{\tau}})\, \htmlClass{eqt}{\htmlStyle{color:#5d4037}{\phi'}}\)
The soft update. The new target weights are mostly the old target weights, with a small share \(\tau\) of the live weights mixed in. A small \(\tau\) keeps the target steady but slow to pick up what the live network learns; \(\tau\) equal to one would be a hard copy after every update, which is no target network at all.

6.1 The full training step

Put together, one DQN training step draws a random batch from replay memory, computes targets with the target network, takes one gradient step on the live network, and updates the target network.

\(\displaystyle \begin{aligned} \htmlClass{eqt}{\htmlStyle{color:#196f3d}{y_i}} &= \htmlClass{eqt}{\htmlStyle{color:#7d6608}{r_i}} \\ &\quad + \htmlClass{eqt}{\htmlStyle{color:#2c3e50}{\gamma}} \max_{\htmlClass{eqt}{\htmlStyle{color:#a04000}{a'}}} \htmlClass{eqt}{\htmlStyle{color:#8e44ad}{Q}}(\htmlClass{eqt}{\htmlStyle{color:#2471a3}{s_i'}}, \htmlClass{eqt}{\htmlStyle{color:#a04000}{a'}}; \htmlClass{eqt}{\htmlStyle{color:#5d4037}{\phi'}}) \end{aligned}\)
The target, now from the slow copy \(\phi'\), so it holds still while the live network learns. On the last step of an episode the second part is dropped and the target is the reward alone.
\(\displaystyle \htmlClass{eqt}{\htmlStyle{color:#b03a2e}{\delta_{i}}} = \htmlClass{eqt}{\htmlStyle{color:#196f3d}{y_i}} - \htmlClass{eqt}{\htmlStyle{color:#8e44ad}{Q}}(\htmlClass{eqt}{\htmlStyle{color:#2471a3}{s_i}}, \htmlClass{eqt}{\htmlStyle{color:#a04000}{a_i}}; \htmlClass{eqt}{\htmlStyle{color:#1b4f72}{\phi}})\)
The TD error of the move that was played, from the live network.
\(\displaystyle \htmlClass{eqt}{\htmlStyle{color:#2c3e50}{\mathcal{L}}}(\htmlClass{eqt}{\htmlStyle{color:#1b4f72}{\phi}}) = \frac{1}{\htmlClass{eqt}{\htmlStyle{color:#2c3e50}{B}}} \sum_{i} \htmlClass{eqt}{\htmlStyle{color:#b03a2e}{\delta_{i}}}^{2}\)
The squared gaps, averaged over the batch, as in section 3.1.
\(\displaystyle \htmlClass{eqt}{\htmlStyle{color:#1b4f72}{\phi}} \leftarrow \htmlClass{eqt}{\htmlStyle{color:#1b4f72}{\phi}} - \htmlClass{eqt}{\htmlStyle{color:#2c3e50}{\eta}}\, \nabla_{\htmlClass{eqt}{\htmlStyle{color:#1b4f72}{\phi}}} \htmlClass{eqt}{\htmlStyle{color:#2c3e50}{\mathcal{L}}}\)
One gradient step on the live weights only.
\(\displaystyle \htmlClass{eqt}{\htmlStyle{color:#5d4037}{\phi'}} \leftarrow \htmlClass{eqt}{\htmlStyle{color:#2c3e50}{\tau}}\, \htmlClass{eqt}{\htmlStyle{color:#1b4f72}{\phi}} + (1 - \htmlClass{eqt}{\htmlStyle{color:#2c3e50}{\tau}})\, \htmlClass{eqt}{\htmlStyle{color:#5d4037}{\phi'}}\)
The soft update moves the target network a small share of the way toward the live one.

8 DQN in code

The whole recipe fits in a few short blocks of PyTorch. First the Q-network: readings in, two hidden layers, one move value out per move.

import copy, random
from collections import deque
import torch
import torch.nn as nn, torch.nn.functional as F

class QNetwork(nn.Module):
    def __init__(self, n_inputs, n_moves, hidden=64):
        super().__init__()
        self.body = nn.Sequential(
            nn.Linear(n_inputs, hidden), nn.ReLU(),
            nn.Linear(hidden, hidden), nn.ReLU(),
            nn.Linear(hidden, n_moves),          # one move value per move
        )

    def forward(self, state):
        return self.body(state)                  # readings in, move values out
  1. 1The libraries: PyTorch for the network, a deque for the memory.
  2. 2A multilayer perceptron whose last layer has one output per move.
  3. 3One forward pass fills a whole row of move values, for a whole batch of states at once.

Then the replay memory. A deque with a maximum length drops its oldest item when a new one arrives.

class ReplayBuffer:
    def __init__(self, capacity):
        self.memory = deque(maxlen=capacity)     # the oldest steps fall out first

    def add(self, s, a, r, s_next, done):
        self.memory.append((s, a, r, s_next, done))

    def sample(self, batch_size):
        batch = random.sample(self.memory, batch_size)   # scattered, not in a row
        s, a, r, s_next, done = zip(*batch)
        return (torch.tensor(s, dtype=torch.float32),
                torch.tensor(a).unsqueeze(1),
                torch.tensor(r, dtype=torch.float32).unsqueeze(1),
                torch.tensor(s_next, dtype=torch.float32),
                torch.tensor(done, dtype=torch.float32).unsqueeze(1))
  1. 1The memory holds at most capacity steps.
  2. 2Each move stores one step, with done saying whether the episode ended there.
  3. 3random.sample draws the random batch, which is turned into one tensor per part of the step.

Then one training step, following the card of the full training step line by line.

GAMMA, TAU = 0.99, 1e-3

def learn_step(q_live, q_target, optimizer, batch):
    s, a, r, s_next, done = batch
    with torch.no_grad():                        # the target is not trained
        best_next = q_target(s_next).max(1, keepdim=True)[0]
        y = r + GAMMA * best_next * (1 - done)   # at an episode's end, the reward alone
    q_played = q_live(s).gather(1, a)            # the value of each played move
    loss = F.mse_loss(q_played, y)               # the squared gap, averaged over the batch
    optimizer.zero_grad()
    loss.backward()
    optimizer.step()                             # one gradient step on the live weights
    with torch.no_grad():
        for p, p_t in zip(q_live.parameters(), q_target.parameters()):
            p_t.mul_(1 - TAU).add_(TAU * p)      # the soft update
  1. 1The target from the target network, card line one. max(1) takes the best value across the moves, and (1 - done) is the done mask: it is zero on the last step of an episode, which wipes out the next-state term.
  2. 2gather picks, from each row of move values, the one for the move that was played. Then the loss, card line three: the squared gap, averaged over the batch.
  3. 3The gradient step, card line four: clear old gradients, compute new ones, step the weights.
  4. 4The soft update, card line five, weight by weight.

Last, the loop around it. The target network starts as an exact copy, the agent picks moves epsilon-greedy, and learning waits until the memory holds a full batch.

n_inputs, n_moves, BATCH, LEARN_EVERY = 37, 4, 64, 4   # as in Table 1
buffer, step = ReplayBuffer(100_000), 0
q_live = QNetwork(n_inputs, n_moves)
q_target = copy.deepcopy(q_live)                 # the slow copy starts equal
optimizer = torch.optim.Adam(q_live.parameters(), lr=5e-4)

def act(s, eps):
    if random.random() < eps:
        return random.randrange(n_moves)         # explore
    with torch.no_grad():
        return int(q_live(torch.tensor(s, dtype=torch.float32)).argmax())

# after every move inside the episode loop
buffer.add(s, a, r, s_next, done)
step += 1
if step % LEARN_EVERY == 0 and len(buffer.memory) >= BATCH:
    learn_step(q_live, q_target, optimizer, buffer.sample(BATCH))
  1. 1The settings of Table 1, an empty memory, two networks with equal weights to begin with, and an optimizer on the live one only. Adam is a version of the gradient step that adapts its own size for each weight (Adaptive Optimizers).
  2. 2Epsilon-greedy from the live network.
  3. 3Store every move, and take a training step every few moves once the memory holds a batch.

9 Watching replay at work

To watch replay memory work, go back to the warehouse floor from Q-Learning: a robot drives from its start in the bottom left toward a charging dock in the bottom right. Every move costs a little battery, and a ledge along the bottom row costs a lot and sends the robot back to the start.

Here the robot learns with a very small Q-network instead of a table. Its input switches on the robot’s square and half switches on the squares around it, so a lesson at one square spills onto its neighbours.

The robot sweeps the floor row by row instead of heading for the dock, so steps in a row are very alike. Q-learning still learns the values of best play from these moves, because it is off-policy.

The floor is small enough to work out each square’s exact value under best play. The chart follows the network’s best move value on the square ringed in green against that true value, the dashed line.

The switch picks where each batch comes from. The slider sets the step size: larger steps learn faster but can overshoot, smaller ones are steadier but slower.

With random batches the orange dots scatter and the purple line closes in on the dashed one, faster with large steps. With recent steps the batch is one trail ending at the robot. Small steps then leave the estimate away from the truth at the end, and large steps make it swing and then blow up: the robot gets caught at its start, stepping onto the ledge again and again, so the batch is nearly all that one step and pulls the shared weights one way until the run stops.

12 When to use DQN

DQN fits when the states are too many or too varied for a table, such as sensor readings or screens. It needs a short list of moves, because every target takes the best value over all of them. A move that is an amount, such as how hard to turn a joint, gives no list to take the best of; those worlds use Continuous-Action Actor-Critic methods such as Deep Deterministic Policy Gradient (DDPG). When the states fit in a table, plain Q-Learning is simpler and steadier.

14 What comes next

Two refinements build straight on this page. The max in the target picks whichever next value came out highest by chance, so values lean high; Double DQN lets the live network choose the best next move and the target network score it. Dueling DQN splits the output into how good the state is plus how much each move adds. My banana agent uses both.

DQN learns move values and picks the best one. The other big family learns the policy directly, nudging it toward moves that paid off. That is the next page, Policy Gradients: REINFORCE, Actor-Critic and PPO.
