1From next-token predictor to assistant

1.1Predicting text is not following instructions

A predictor keeps the pattern going

Picture a model that has only ever learned what text comes next. Give it a question and it carries the pattern on, writing more questions instead of an answer, because answering was never what it was trained to do.

Alignment trains the model to answer instead, so its replies do what people want: helpful, honest and harmless.

A pretrained language model is trained only to predict the next word piece, or token, of the text it reads.

The goal is to "follow the user's instructions helpfully and safely".

GPT-3, a large pretrained OpenAI language model, continues the prompt with more questions; InstructGPT, the same model after the training these pages describe, answers it. People wrote prompts and ranked replies to train InstructGPT, then judged fresh replies from both models side by side. People preferred replies from the \(1.3B\) InstructGPT model, where B counts billions of parameters: a parameter is one number the model learns, and the model's weights are its parameters, so \(1.3B\) counts \(1.3\) billion learned numbers, to replies from the \(175B\) GPT-3 model, a model about \(135\) times larger. The same-size \(175B\) InstructGPT model beat the \(175B\) GPT-3 model \(85\) percent of the time, a range of \(82\) to \(88\) percent.

1.2Comparing is easier than writing

Picture \(2\) replies side by side and \(1\) person picking the better one. Writing an ideal reply is slow work, and \(2\) people word it differently, while picking between \(2\) ready replies is fast and stays consistent.

People pick the better reply, and training learns from those picks instead of from written ideals.

Training a model to copy replies people wrote is called behavior cloning; it rarely goes beyond the examples it copies.

2Training a language model by trial and reward

2.1One reply, one run of choices

The language model acts as an agent

Picture the language model as an agent that learns from rewards, not from labeled answers. That is reinforcement learning (RL). The agent is the model itself, the state is the prompt plus the tokens written so far, each move is the next token, the policy is the agent's rule for choosing a move in each state, and the reward is \(1\) number for the whole reply, given at the end.

The model writes a reply one token at a time, and each update makes the replies that earned high rewards more likely.

When it works, the model stops dodging the question and answers it, because answering replies earn the high rewards.

In reinforcement learning generally, a reward is the number handed back after each move, good or bad, but on this page each reply earns \(1\) number, given at the end.

Each token is chosen before any reward arrives. Take the moon-landing reply: each token is \(1\) move, and the reward arrives only when the last token is written.

The rewards can come from people, from another model, or from a program that checks the answer. For the moon-landing question, a reply that answers earns a high reward and one that dodges a low one.

  2. 2This block picks out the log-probabilities of the tokens actually written.

An episode is \(1\) run from the start until it ends. Here an episode is \(1\) written reply.

The return is all the reward still to come, with later rewards counted a little less. Here the return is the reward for the whole reply.

An expected value is the average over everything that can happen by chance, weighted by how likely each outcome is. The agent's goal is to make its expected return as large as possible, averaged over the replies it might write.

2.2Start from supervised fine-tuning

Picture the model first copying replies people wrote, so it learns the shape of a good answer before any reward arrives. That first training is supervised fine-tuning, SFT for short.

SFT trains the model on those replies with the ordinary next-token loss.

DeepSeek-R1-Zero is the exception: DeepSeek is the lab, R1 is its reasoning model, and Zero means no SFT came first, so this first run of R1 writes out its reasoning steps before answering and runs RL straight on the pretrained model. Every other method on these pages starts from the SFT model.

2.3Stay close to the starting model

Drifting away carries a price

Picture the starting model frozen as a reference, and the policy drifting away from it as it chases reward. The KL penalty, a charge for drifting from the reference measured by how different \(2\) reply distributions are, charges the policy at each token for that drift, so a reply the reference would never write costs more.

Training subtracts the penalty from the average reward, with a weight that sets how hard the penalty bites.

The thing that gives the reward is a reward model, a language model with a one-number output, trained on people's comparisons so the reply they preferred scores higher. On questions with a known answer, an answer checker, a program that checks the answer, takes the reward model's place.

Training takes one prompt at a time from the prompt set and lets the policy write a reply to it.

\(1\) step costs \(1\) reply generation and \(1\) scoring pass per prompt and \(1\) update per batch, a group of prompts handled together: the policy writes a reply to each prompt, the reward model scores it, and \(1\) update moves the policy.

The objective pulls the policy \(2\) ways at once: toward replies that earn reward, and back toward the reference whenever the reward tempts it far away.

The far-away reply talks about how far the moon is, the answering reply says people went to the moon and came home, the gentle-landing reply says astronauts landed gently, and the fourth reply dodges with another question. Take the answering reply: the policy gives it its tallest bar while the reference gives it a shorter one, so that reply carries a KL penalty.

Without the penalty, only the reward limits how far the policy drifts.

3One pipeline, several changes

3.1Each method changes one box in the pipeline

Picture \(1\) pipeline: a model fine-tuned on written replies, a reward model trained on people's picks, and a loop that writes fresh replies, scores them and updates the model.

Each method swaps \(1\) box: who labels, what scores, whether the loop runs, or what the reply is judged against. The loop carries a critic, a second network that guesses each state's value, the return expected from it.

Changing the reward model or the critic changes what the loop learns. Each box feeds the next, so changing \(1\) box changes the aligned model.

Reward models: the stage that scores replies

The reward model is a stage of the pipeline, not a method: RLHF trains it from people's comparisons before the RL loop runs, and the loop then uses its scores. It usually starts from the SFT model, with its word-prediction layer replaced by one number.

RLHF: reinforcement learning from human feedback

People compare replies and a reward model learns their preferences, as Christiano et al. introduced it.

The RL loop writes fresh replies with the current model during training, rewards them, and updates the model.

The RL loop compares each reply's reward with the critic's guess, so a reply is pushed up only when it did better than expected.

Constitutional AI: feedback model writes harm labels

A feedback model, a language model that reads a written principle and picks the less harmful reply, writes the harm labels; its list of principles is called a constitution. It updates once per batch of fresh replies and carries the policy, the reference, the reward model and the critic between updates.

RLAIF: reinforcement learning from AI feedback

An AI labeler, an existing language model asked which of \(2\) replies is better, takes the person's place. It updates once per batch of fresh replies and carries the policy, the reference, the reward model and the critic between updates.

DPO: direct preference optimization

DPO trains on the pairs with \(1\) loss, which raises the chosen reply's chance relative to the rejected one. The loss looks at how much more likely the policy thinks the chosen reply is than the rejected one, and pushes that gap wider. It updates once per batch of picked pairs and carries the policy and the reference between updates.

GRPO: replies judged against their group

GRPO, group relative policy optimization, keeps the KL penalty like most methods and drops the critic: it judges each reply by how far its reward sits above or below the average reward of the replies to its prompt, divided by how spread out those rewards are. A reward model or an answer checker scores the replies in each group. The replies to \(1\) prompt are called a group, and the spread is its standard deviation, how far the rewards typically sit from their average. It updates once per batch of groups and carries the policy and the reference between updates, with no critic to carry.

DeepSeek-R1: an answer checker scores reasoning

An answer checker, a program that compares the final answer with the known one and checks the reply's format, takes the reward model's place on reasoning questions such as math and code. R1-Zero uses the same group judgment as GRPO, but it starts from the pretrained model with no SFT, while GRPO starts from SFT. It updates once per batch of groups and carries the policy and the reference between updates, with no critic to carry.

Think tags are the markers <think> and </think> that the model is asked to put around its reasoning.

The full DeepSeek-R1 runs SFT first, on examples gathered \(4\) ways: few-shot prompting, showing the model worked examples before asking, with a long chain of thought, reasoning written out step by step; direct prompting with no examples; R1-Zero's own outputs; and human post-processing of the examples, people checking and fixing the examples by hand.

6In practice: one RLHF step

One step, four networks in memory

Picture one step of RLHF: the policy writes replies, the reward model scores them, the critic guesses their value, and one update moves the policy.

One step runs the RL loop once for each prompt in the batch. PPO, proximal policy optimization, moves the policy. Proximal means the update stays near the old policy: each token's ratio of new to old chance is clipped to \(0.2\) either way, so one batch cannot drag the policy far toward replies the reward model scores too highly. The advantage is how much better each token did than the critic's guess, and the clipped update pushes each token's chance up or down with its advantage. The code below is that step in PyTorch, in \(2\) parts: a helper that turns a model into per-token log-probs, then the step itself. The numbered notes under each code block say what that block does.

import torch
def token_logp(model, ids, mask):                        # per-token log-probs of the reply: (batch, length - 1)
    logp = torch.log_softmax(model(ids).logits, -1)      # log-softmax over the vocab: (batch, length, vocab); .logits holds the scores
    tok = logp[:, :-1].gather(-1, ids[:, 1:, None]).squeeze(-1)  # the chosen tokens: (batch, length - 1)
    return tok * mask[:, 1:]                             # the mask zeroes prompt tokens, keeps reply tokens
def rlhf_step(policy, ref, rm, value, opt, ids, mask, last, old_tok):  # [1] one step on one batch of replies
    tok = token_logp(policy, ids, mask)                    # per-token log-probs of the reply
    val = value(ids)[:, :-1]                               # the critic's guess at each position: (batch, length - 1)
    with torch.no_grad():                                  # [2] scores are targets, no gradient
        ref_tok = token_logp(ref, ids, mask)               # frozen reference, per token
        kl = 0.02 * (tok - ref_tok)                        # per-token KL penalty, beta 0.02
        ret = rm(ids, last)[:, None] - kl.flip(1).cumsum(1).flip(1)  # end reward, minus the KL penalty still to come at each token
    adv = (ret - val.detach()) * mask[:, 1:]               # advantage, zero on prompt tokens
    ratio = torch.exp(tok - old_tok)                       # [3] PPO ratio, per token; the loss clips it to 0.8-1.2
    loss = -torch.min(ratio * adv, torch.clamp(ratio, 0.8, 1.2) * adv).sum() / mask[:, 1:].sum()
    vloss = (((ret - val) ** 2) * mask[:, 1:]).sum() / mask[:, 1:].sum()  # the critic learns from its own error
    (loss + vloss).backward(); opt.step(); opt.zero_grad()  # one update
  1. 1This block takes the policy's per-token log-probabilities from the helper above, and the critic's guess for each token.
  2. 2This block computes the targets without tracking gradients: the frozen reference's per-token log-probabilities, \(1\) reward score per reply, and the return still to come from each token. no_grad runs the code without tracking gradients, so these scores stay fixed targets. last holds the position of each reply's last token, so the reward model scores the finished reply.
  3. 3This block runs the PPO update: the loss takes the smaller of the unclipped and clipped products, and the critic's own loss. The advantage is \(0\) on prompt tokens and both losses average over reply tokens only, so prompt tokens are not trained. old_tok is the old policy's per-token log-probabilities, masked to keep reply tokens only. opt is the optimizer that applies the update.

This step sits inside the training loop, which repeats it over the prompt set. The policy, the frozen reference, the reward model and the critic all sit in memory at once during one step: four networks in memory. InstructGPT ran that loop for \(256k\) episodes. Those episodes covered about \(31k\) prompts, so prompts repeat across episodes. An iteration is \(1\) step of the loop; the batch is \(512\) prompts; a minibatch is \(64\); and an inner epoch is \(1\) pass over each minibatch inside the step.

This page's settings, and what raising or lowering each does, are: \(\beta\) \(0.02\), the KL penalty weight: raising it holds the policy closer to the reference, and lowering it lets the reward win. PPO clip \(0.2\): a larger clip lets \(1\) batch move the policy further, and a smaller clip holds it closer to the old policy. The batch is \(512\) prompts: a larger batch averages the update over more prompts, and a smaller batch over fewer. A minibatch is \(64\) prompts: a larger minibatch uses more memory per update, and a smaller one updates more often. \(1\) inner epoch runs \(1\) pass over each minibatch: more passes squeeze more learning from each batch, and fewer passes learn less from each batch than more passes do. Sampling temperature \(1\) sets how widely the policy samples replies: raising it spreads replies wider, and lowering it narrows them. The value-function learning rate, \(9e-6\), which means \(9\) millionths, for the \(1.3B\) and \(6B\) policies, and \(5e-6\) for the \(175B\) policy, sets how fast the critic's guesses move: raising it moves the guesses faster, and lowering it moves them slower.

Watch for reward hacking: a reward model that likes long replies will push the policy toward long replies whether they are better or not, so check the replies people actually prefer, not just the score. If \(\beta\) is too high the policy barely moves from SFT; if it is too low the policy drifts and hacks the reward model. Watch the logged KL, which should rise slowly, not jump.

TRL, short for Transformer Reinforcement Learning, where a Transformer is the architecture the language model is built from, is an open library from Hugging Face, a company that shares open tools for building language models, and its PPO trainer runs this loop. TRL's GRPO trainer defaults \(\beta\) to \(0.0\), so a few GRPO recipes drop the KL penalty, the exception, not the rule.
