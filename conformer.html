Conformer

Convolution-augmented transformers for speech recognition

Conformer blends CNNs and transformers

Here is the question: how do you build an ASR model that hears both the phoneme edge and the whole sentence? Vanilla transformers are great at global context but clumsy with local detail like phoneme edges and formants. CNNs nail local structure but miss global dependencies. The Conformer, a "convolution-augmented transformer," takes both. And unlike most hybrids, this one actually worked.

Text models get neat little tokens. Speech does not work like that: you get a continuous waveform, typically sampled at 16 kHz. So the first job is turning that wave into features, usually 80-dim filterbank frames, about 100 frames per second of speech. One second of audio becomes a 100 × 80 matrix. Then a linear or convolutional layer projects those features up to the model dimension, the same job an embedding layer does for text. With the model dimension set to 256, the input is 100 × 256, and each row is one frame's "token".

Before the blocks, most systems shrink time itself.

In the Conformer paper (Gulati et al., 2020), the encoder does not feed those frames straight into the blocks. It first processes its input with a convolution subsampling layer, and only then runs the stack of Conformer blocks, so time is reduced before any block runs. The input features there are 80-channel filterbank frames computed with a 10 ms stride, the same 80-dim filterbank frames at about 100 frames per second described above.

Strided subsampling folds neighboring frames together before the first block. The steps:

  1. Choose a stride s, the number of neighboring frames folded together.
  2. Group the input frames into consecutive groups of s.
  3. Each group becomes one surviving output frame, so the output frame count is the input count divided by s.
  4. Each surviving frame is wider than a single input frame, because it carries its whole group.

At the default stride of 2: 40 frames in, 20 frames out.

Why shrink time at all? Attention costs T2, and T is 100 frames a second. Merging neighbors before the first block is the cheapest speedup in ASR. Written as relations, with T input frames and stride s:

$$ \mathrm{output\ length} = \frac{T}{s}, \qquad \mathrm{attention\ cost} \propto \left( \frac{T}{s} \right)^2 $$

T is the number of frames, 100 per second of speech on this page. s is the stride from the steps above. Because the cost follows the square, stride 2 makes it one quarter and stride 4 one sixteenth. The price is resolution: each surviving frame spans s times 10 ms, so a 30 ms phoneme can die inside a single frame at large stride.

The structural difference at a glance. The transformer block runs attention then one full feed-forward, each with a residual skip. Conformer splits the feed-forward into two half-strength halves (each at half strength, so the pair equals one full FFN), sandwiches self-attention and the new convolution module between them, and gives every module its own residual skip as Figure 1 shows. The colors match across the two blocks; the bold borders mark what changed.

The Conformer block calls these two feed-forward networks a macaron-style feed-forward network, so named because the main attention and convolution modules are sandwiched between two FFNs, like the filling in a macaron. They add capacity and non-linearity but don’t mix information across time steps. They scale the FFN by half to match the contribution of one FFN in a vanilla transformer.

The same five lines, written out as static equations. In them, x is the input frame vector, and x̃, x′, x″, x‴ are the frame after each stage:

$$ \tilde{x} = x + \tfrac{1}{2} \cdot \mathrm{FFN}(x) $$

Add a half-strength feed-forward pass to the frame, so the frame gets richer on its own before anything mixes across time. The ½·FFN is that half-strength feed-forward; two halves make one whole.

$$ x' = \tilde{x} + \mathrm{MHSA}(\tilde{x}) $$

Add attention: the frame borrows context from far away frames and adds that to itself. MHSA is multi-head self-attention.

$$ x'' = x' + \mathrm{Conv}(x') $$

Add the convolution module: the frame sharpens its local edges using only its close neighbors. Conv is the convolution module.

$$ x''' = x'' + \tfrac{1}{2} \cdot \mathrm{FFN}(x'') $$

Add the second half-strength feed-forward pass, so the two halves together make one full feed-forward.

$$ y = \mathrm{LayerNorm}(x''') $$

Run layer norm on the result: the frame steadies its scale and leaves the block with the same shape it entered. LayerNorm steadies the frame for the next block, y is the block output, same shape as x, and in every line the + is the residual add: each module's output joins the frame.

The estimate behind the conv share, step by step:

  1. Take a model's reported total as given.
  2. Estimate the convolution module in one block as about 3d², from its two pointwise projections only: one to expand to twice the model dimension before the GLU gate, then one to project back to the model dimension. Biases, LayerNorm, and the depthwise conv's own params are ignored.
  3. Multiply by the number of blocks to get the model's convolution total.
  4. Compare that total with the reported total.
$$ \mathrm{conv\ params\ per\ block} \approx 3d^2, \qquad \mathrm{conv\ params\ per\ model} \approx 3d^2 \times N $$

d is the model dimension from the model list above. N is the block count for that model size: 16, 16, and 17 for S, M, and L. The ≈ marks that this is the stated approximation, not an exact count.

Conformer (M) is 30.7M params and scores 5.0 on test-other, beating a 139M transformer at 5.6. The conv module costs only about 3.1M of those 30.7M. Local detail, bought cheap. That is the whole trick.

Multi-Head Self-Attention with Relative Positional Encoding

So far, the input is a batch of frames, each frame a vector at the model dimension; this is the output from the first FFN and its residual connection. Now, you project these frame vectors into queries, keys, and values, one set per head. Each head gets its own learned projection, sized for the head count: with a model dimension of 256 and 4 heads, each head gets a 64-dim projection, so every head gets its own 64-dim room to work in.

You then compute attention: score every frame against every other frame, divide by the square root of the head dimension so the scores stay in a range softmax can handle, and take a weighted mix of the values. Concatenate the heads, project back with the output projection, and add the residual.

This is almost the same as a vanilla transformer, but instead of sinusoidal encodings, it uses relative positions, which generalize better to long sequences and relative timing. With absolute positional encodings, for each input position, you would add the positional encoding directly to each input. The model is given the known positions, and the query and key themselves get shifted by this absolute index.

With relative positional encoding, we don’t alter the input embeddings directly. Instead, we introduce an extra bias term in the attention score based on the relative distance. The model learns biases based on the relative distances between tokens. Speech is shift-invariant: a phoneme like "ba" at 1 second and 10 seconds should be treated the same. What matters is how far apart the tokens are, not their absolute index.

The relative offset is a learned embedding for how far apart two frames are. In words: the usual query-key match, plus a learned bonus for how far apart the two frames are. Two frames 5 apart get the same bonus no matter where they sit in the utterance. We define a maximum relative distance, and this offset can be anywhere within that range in either direction, where each row corresponds to one head-sized vector.

For a given pair, we look up the relative embedding and perform a dot product with the query, which gets added to the attention scores. The embedding table holds one vector per possible relative offset. You can share this table across all heads.

Written as one line, the score for query frame i against key frame j is the content term plus the position term:

$$ \mathrm{score}(i, j) = \frac{q_i \cdot k_j}{\sqrt{d_k}} + q_i \cdot r_{i-j} $$

qi is the query vector of frame i and kj is the key vector of frame j; each head gets its own learned projection. dk is the head dimension, and dividing by its square root keeps the scores in a range softmax can handle. ri-j is the relative embedding for the offset i minus j, the signed distance between the two frames: the learned embedding for how far apart two frames are. Two pairs with the same offset get the same position term no matter where they sit. The embedding table holds one vector per possible relative offset, within a maximum relative distance, and the table can be shared across all heads.

The convolution module adds local context

Next is the convolution module, which is the big difference from vanilla transformers. This is a depthwise separable convolution used to explicitly model local sequential structure.

The input here is the sequence after attention did its thing: every frame already carries long-range context from the whole utterance. The shape is still a batch of frames at the model dimension. The convolution module now layers local patterns on top: short-term temporal structure that attention is too coarse to catch.

The convolution module looks similar to those in EfficientNet and MobileNet.

  1. First, a LayerNorm normalizes each frame across its channels. Nothing fancy, just steadying the signal before the convolutions touch it.
  2. Then, a pointwise convolution with a Gated Linear Unit (GLU) activation is applied. The pointwise convolution expands the number of channels to twice the model dimension. The GLU works by halving the channels and applying a gated operation, where the second half acts as a learned gate controlling how much of the first half to pass. The output keeps the same shape as the input.
  3. Then, a depthwise convolution is applied along the time axis. Each channel has its own convolution filter (so there is no cross-channel mixing), often a 15-tap kernel, which is 150 ms at 100 frames per second. That is why the code below uses kernel_size=15. This gives each feature map a local receptive field over time. At this point, the representation is channel-local and time-dependent.
  4. The input is padded ('same') such that the output from this step remains the same size as the input. In streaming ASR, you'd switch to causal padding (padding only on the left, so the model doesn't peek into the future).

Normalization Strategy: LayerNorm vs. BatchNorm

Would LayerNorm or BatchNorm work better after the depthwise conv? LayerNorm normalizes each frame across its channels, which would wash away the temporal patterns the conv just learned. BatchNorm normalizes per channel across the batch and time instead, so each channel keeps its identity and the normalization is consistent across time, which keeps the convolution filters stable. A Swish activation follows, letting small negative values pass through instead of clipping them to zero.

BatchNorm also has two modes. During training it normalizes each channel with the current batch's mean and variance, while quietly stockpiling running estimates of both. At inference it ignores the test batch's own stats and normalizes with those stockpiled running stats instead. In streaming, those frozen global stats do not match a live chunk; Streaming: understanding speech before the sentence ends covers the fallout, and What came after Conformer names the fix.

Convolution mixes channels, then FFN finishes the block

The Conformer then applies a BatchNorm and a Swish activation. Finally, another pointwise convolution with dropout is applied, which maps the model dimension back to itself. Lastly, a residual connection is added from the start of the module to its output. Looks redundant, but it is not: the depthwise conv is a per-channel local filter, so it never mixes channels. The pointwise conv after it is where channels finally talk to each other, exactly the cross-channel interaction the depthwise step cannot give you.

This is our convolution block. The output from the convolution block keeps the same shape as the input. After this, another feed-forward network, similar to the one before, is applied to each frame with a residual connection to complete the macaron-style design.

It expands the model dimension to the feed-forward width, applies a non-linearity, projects back to the model dimension with dropout, and adds a half-scaled version of that as a residual. The shape stays a batch of frames at the model dimension, and that is the whole point: same shape in, same shape out, so you can stack as many blocks as your budget allows.

The first FFN before the attention module enriches the frame-level features before they interact globally. The second FFN enriches the representation after it has been mixed both globally and locally. That symmetry is why the block trains more stably than the same pieces stacked in a different order.

The comparison the tool below draws, stated in words: at any probe frame, the convolution reading covers only the probe and the 3 frames on each side: a rigid local window, a magnifying glass on 7 frames, 70 ms at 10 ms per frame, wherever you put it. The real kernel is 15 taps, 150 ms, as taught above. The attention reading covers the whole utterance, redistributing by content like gossip, with weights that sum to 1.0 at every probe position, and it can peak at a similar edge it heard frames earlier. Same probe, two readings: the conv sees the edge and its neighbors, attention remembers the similar edge it heard frames earlier.

The block in PyTorch

Let's build the block piece by piece. First, the macaron FFN. This is just a normal two-layer MLP, but notice the residual is scaled by 0.5. That is the whole macaron trick: two of these add up to one full FFN.


import torch
import torch.nn as nn
import torch.nn.functional as F

class ConformerFFN(nn.Module):
    def __init__(self, d_model, d_ff, dropout=0.1):
        super().__init__()
        self.linear1 = nn.Linear(d_model, d_ff)
        self.linear2 = nn.Linear(d_ff, d_model)
        self.dropout = nn.Dropout(dropout)
        self.activation = nn.SiLU()  # Swish

    def forward(self, x):
        out = self.linear1(x)
        out = self.activation(out)
        out = self.dropout(out)
        out = self.linear2(out)
        out = self.dropout(out)
        return x + 0.5 * out   # Macaron: scale by 0.5

Next, self-attention. I am showing the vanilla version here to keep it readable. The relative positional bias we talked about above slots right into the score computation.


class MHSA(nn.Module):
    def __init__(self, d_model, num_heads, dropout=0.1):
        super().__init__()
        assert d_model % num_heads == 0
        self.h = num_heads
        self.d_k = d_model // num_heads

        self.W_q = nn.Linear(d_model, d_model)
        self.W_k = nn.Linear(d_model, d_model)
        self.W_v = nn.Linear(d_model, d_model)
        self.W_o = nn.Linear(d_model, d_model)
        self.dropout = nn.Dropout(dropout)

    def forward(self, x, mask=None):
        B, T, D = x.shape

        Q = self.W_q(x).view(B, T, self.h, self.d_k).transpose(1, 2)
        K = self.W_k(x).view(B, T, self.h, self.d_k).transpose(1, 2)
        V = self.W_v(x).view(B, T, self.h, self.d_k).transpose(1, 2)

        scores = torch.matmul(Q, K.transpose(-2, -1)) / (self.d_k ** 0.5)
        if mask is not None:
            scores = scores.masked_fill(mask == 0, float("-inf"))
        attn = F.softmax(scores, dim=-1)
        out = torch.matmul(attn, V)

        out = out.transpose(1, 2).contiguous().view(B, T, D)
        return x + self.dropout(self.W_o(out))  # residual

Now the convolution module, the part that makes a Conformer a Conformer. Pointwise conv plus GLU, a depthwise conv over time, BatchNorm plus Swish, then pointwise back. The transpose dance: Conv1d wants channels first.


class ConformerConvModule(nn.Module):
    def __init__(self, d_model, kernel_size=15, dropout=0.1, causal=False):
        super().__init__()
        self.layer_norm = nn.LayerNorm(d_model)
        self.pointwise_conv1 = nn.Conv1d(d_model, 2*d_model, kernel_size=1)
        padding = (kernel_size - 1) if causal else (kernel_size - 1) // 2
        self.depthwise_conv = nn.Conv1d(
            d_model, d_model, kernel_size,
            groups=d_model, padding=padding
        )
        self.causal = causal
        self.batch_norm = nn.BatchNorm1d(d_model)
        self.pointwise_conv2 = nn.Conv1d(d_model, d_model, kernel_size=1)
        self.dropout = nn.Dropout(dropout)

    def forward(self, x):
        residual = x
        x = self.layer_norm(x)
        x = x.transpose(1, 2)  # (B, d_model, T)

        x = self.pointwise_conv1(x)
        A, B = x.chunk(2, dim=1)
        x = A * torch.sigmoid(B)  # GLU

        x = self.depthwise_conv(x)
        if self.causal:
            x = x[:, :, :residual.size(1)]  # trim if causal

        x = self.batch_norm(x)
        x = F.silu(x)
        x = self.pointwise_conv2(x)

        x = x.transpose(1, 2)  # back to (B, T, d_model)
        return residual + self.dropout(x)  # residual

And finally, the whole block. FFN, attention, conv, FFN, with a LayerNorm at the end, which is what most implementations do.


class ConformerBlock(nn.Module):
    def __init__(self, d_model=256, d_ff=1024, num_heads=4, kernel_size=15, dropout=0.1, causal=False):
        super().__init__()
        self.ffn1 = ConformerFFN(d_model, d_ff, dropout)
        self.mhsa = MHSA(d_model, num_heads, dropout)
        self.conv = ConformerConvModule(d_model, kernel_size, dropout, causal)
        self.ffn2 = ConformerFFN(d_model, d_ff, dropout)
        self.final_ln = nn.LayerNorm(d_model)  # often added at block end

    def forward(self, x, mask=None):
        x = self.ffn1(x)
        x = self.mhsa(x, mask)
        x = self.conv(x)
        x = self.ffn2(x)
        return self.final_ln(x)

Streaming: understanding speech before the sentence ends

So how do you make the Conformer run in real time? First, attention has to become streaming attention: restrict how far back each query can look with a fixed window plus a causal mask, so no frame ever waits on the future. The catch: speech is ambiguous without a little right context, so you let each frame peek a fixed number of frames ahead. That peek is paid for in latency, and the mask is exactly where you configure it.

Second, you can split the heads into multiple scales. A phoneme is about 50 ms, a word is about 500: give one head a short leash and another the whole pasture, and the same layer catches both.

Chunked emission itself, stated plainly: in streaming you rent future frames by the look-ahead L. A token is emitted only after its look-ahead frames arrive, so the emitted cursor trails the audio cursor by exactly L frames. The steps:

  1. Audio arrives in chunks of C frames.
  2. A frame may read keys up to the end of its own chunk, plus L look-ahead frames beyond it.
  3. A token is emitted only after its L look-ahead frames have arrived.
  4. So at any moment the emitted cursor trails the audio cursor by exactly L frames.

C is the chunk size in frames, L is the look-ahead in frames, and a frame is 10 ms on this page. Each look-ahead frame is 10 ms of latency, which gives the two relations:

$$ \mathrm{latency} = L \times 10\ \mathrm{ms}, \qquad \mathrm{context\ per\ frame} = C + L\ \mathrm{frames} $$

L and C are as defined in the steps above, and 10 ms is the page's frame duration. The worked example: chunk 4, look-ahead 2: every frame sees its block plus two frames into the future, and those two frames cost 20 milliseconds. Make the look-ahead zero and the grid becomes block-causal: each frame sees its own chunk and nothing after it. Drop the chunk to 1 and you get the true causal triangle: perfectly real-time, flying blind into the future.

How to play
  • The point: give each attention head its own window length, its leash, and one layer covers phoneme edges and word context at the same time.

Why should every head look the same distance? A phoneme is 50 ms, a word is 500. Give head one a short leash and head four the whole pasture. The model gets phoneme edges and word context in the same layer, for free.

The convolution module uses "same" padding, which will need to change to causal padding, and the normalization, as we discussed in depth, needs to change as well.

Stack a few of these blocks and you get rich acoustic embeddings, one per frame. Last step: turn frames into words.

One linear layer maps each frame from the model dimension to the vocabulary size. That gives you a score for every vocab item at every frame. Softmax over the vocab axis turns those raw scores (logits) into probabilities: exponentiate each frame's scores and divide by the total, so every frame's vocabulary probabilities sum to one. Once you have this, you need to use a CTC loss to align the output probabilities with the text.

What came after Conformer

Streaming Conformer (causal + dynamic chunks)

The streaming Conformer is the live-audio version of the same sandwich. The convolution's "same" padding becomes causal padding, so each frame only looks at the past. BatchNorm becomes LayerNorm, because running stats measured over full utterances do not match a live chunk. And the model trains on random chunk sizes, so one model serves any latency budget at decode time. This is the dynamic-chunking line of work behind WeNet's U2 (Zhang et al., 2021), building directly on the streaming attention above.

Branchformer: two branches instead of a sandwich

The Branchformer (Peng et al., ICML 2022) drops the sandwich for two parallel branches in every layer: self-attention for long range, a conv-gated MLP for local detail, combined by learned merge weights. It matches or beats Conformer on the same benchmarks, and the merge weights are a free diagnostic: they show which layers lean local and which lean global.

Squeezeformer: maybe the sandwich is overkill

The Squeezeformer (Kim et al., NeurIPS 2022) asks whether the sandwich is overkill. It uses plain attention-then-conv-then-FFN blocks, no macaron, and adds a Temporal U-Net: downsample the timeline so attention works on a squeezed sequence, then upsample back. Same accuracy at lower compute, because attention no longer pays full price on the full-length timeline.
