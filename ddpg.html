1 Many robot arms reaching for a moving goal

A robot arm needs four real-numbered turning forces at its joints every step, and the Deep Q-Network (DQN) can only pick from a list.

A short list makes the arm jerky, and a fine one grows huge.

Deep Deterministic Policy Gradient (DDPG) trains one network to output the forces and a second to score them.

Both networks learn by trial and error on the arm.

The agent is the learner that picks the moves. (RL Basics) A state is the agent's situation right now. A move, or action, is one choice the agent can make in a state. A reward is the number the world hands back after each move, good or bad. An episode is one run from the start until it ends. (RL Basics)

On a robot, sensing, moving and earning rewards repeat many times every second.

The running example is the Reacher task: a robot arm with two joints whose actions are four torques. A torque is a turning force a motor applies at a joint. On the Reacher each torque is a number from -1 to 1. Each joint can turn about two axes, so each joint gets two torques. Every step the arm senses its state, numbers describing the position, rotation and speed of its parts, and earns a small reward whenever its hand is inside a moving goal. My repo trains 20 such arms side by side. (Continuous-Action RL)

A step with the hand on the goal earns a small reward, any other step earns nothing, and the episode's total reward is the sum of those step rewards. The total reward is averaged over all 20 arms and over a long run of episodes, so one lucky arm or one lucky episode cannot pass the bar.

The return is all the reward still to come, with later rewards counted a little less. (RL Basics)

The task counts as solved once the average return passes a fixed bar (Table 1). Early on the hand circles and earns almost no reward; late in training it stays on the goal.

Table 1. Reacher task facts
FactReacher task
Arms20

import numpy as np
NUM_ARMS = 20

out = env.reset(train_mode=True)
info = out[brain_name]
s = info.vector_observations
returns = np.zeros(NUM_ARMS)
while True:
    actions = np.random.uniform(
        -1, 1, (NUM_ARMS, 4))
    out = env.step(actions)
    info = out[brain_name]
    returns += info.rewards
    s = info.vector_observations
    if any(info.local_done):
        break
  1. 1Resets all 20 arms and reads their states.
  2. 2Steps the arms with random torques in [−1, 1] until any episode ends, adding up rewards.

2 Why DQN cannot drive the arm

A list of torque levels makes the arm jerky, and the list soon grows too long to search, as the Continuous-Action RL page shows.

A move's value \(Q(s,a)\), also called its score, is the return the agent expects if it makes move \(a\) in state \(s\) and plays on from there. (RL Basics) A Q-table keeps one score for every state and move. (Q-Learning)

The arm's joint angles and speeds can take endless values, so such a table could never list them all.

DQN swaps the table for a network.

A Q-network is a neural network that takes the state and outputs one score per move, in place of the table. (Deep Q-Networks (DQN))

DQN plays the move with the best score.

DDPG replaces that search with a network.

A policy is the agent's rule for choosing a move in each state; it may always pick the same move or pick by chance. (RL Basics) The deterministic actor \(\mu_\theta\) is a network with weights \(\theta\) that outputs one action every time, with no random draw.

It writes the four torques straight out, with no list to search.

Equation 1. From picking a list entry to an actor. DQN would score every allowed torque level for the arm and keep the best; DDPG's actor writes the four torques straight out.
\(\displaystyle \htmlStyle{color:#a04000}{a^{*}} = \htmlStyle{color:#5d6d7e}{\arg\max_{a}} \htmlStyle{color:#8e44ad}{Q(s,a)}\)
Replace "search the list for the best" with "a network that answers directly". Line 1 is DQN's pick: \(a^{*}\) is the best action, and \(\arg\max\) picks the move whose score is largest. (RL Basics) \(Q(s,a)\) is the move's value from DQN's Q-network, the score of move \(a\) in state \(s\).
\(\displaystyle \htmlStyle{color:#a04000}{a} = \htmlStyle{color:#a04000}{\mu_{\theta}}( \htmlStyle{color:#2471a3}{s} )\)
Line 2 does line 1's job without a list: the actor \(\mu_\theta\) writes the action straight out from the state \(s\), with \(\theta\) its weights, and the output is the four torques. It builds on DQN's greedy pick and the continuous-action intro (Continuous-Action RL).

3 An actor network and a scoring network

The actor needs a second network to tell it which torques are good.

The critic \(Q_\phi\) is a network with weights \(\phi\) that scores a state and an action together; its score stands for the return the agent expects.

For the Reacher the action is the arm's four torques. The state goes through a first hidden layer, then the critic joins the four torques to it, and the head turns them into one score.

import torch
import torch.nn as nn
import torch.nn.functional as F

S, A = 33, 4
L = nn.Linear
actor = nn.Sequential()
actor.append(L(S, 256))
actor.append(nn.ReLU())
actor.append(L(256, 128))
actor.append(nn.ReLU())
actor.append(L(128, 64))
actor.append(nn.ReLU())
actor.append(L(64, A))
actor.append(nn.Tanh())
  1. 1The tanh function squashes any number into -1 to 1, the torque range. (Continuous-Action RL)

The state goes through a first hidden layer, then the critic joins the four torques to it, and the head turns them into one score.

class Critic(nn.Module):
    def __init__(self):
        super().__init__()
        self.fs = L(S, 256)
        self.f1 = L(256 + A, 128)
        self.f2 = L(128, 64)
        self.out = L(64, 1)

    def forward(self, s, a):
        h = F.relu(self.fs(s))
        h = torch.cat([h, a], 1)
        h = F.relu(self.f1(h))
        h = F.relu(self.f2(h))
        return self.out(h)
  1. 1Builds the layers, with S, A and L from the actor snippet; the action joins after the first layer.
  2. 2Encodes the state, appends the four torques, and outputs one score

The DDPG paper writes \(\theta^\mu\) for the actor's weights and \(\theta^Q\) for the critic's weights.

Exploration noise is a small random nudge added to the actor's actions while it learns, so the agent tries moves it is not sure about.

4 Training the critic from stored steps

Replay keeps a memory of past steps, and training draws random batches from it. (Deep Q-Networks (DQN)) The critic learns from random batches of these steps, so it does not learn only from the arm's last few moves.

The critic learns by being pulled toward a target, the step's reward plus its own score for what comes next, counted a little less. (Continuous-Action RL) That target moves whenever the critic moves.

The discount \(\gamma\) sets how much a reward one step later still counts. (RL Basics) A discount close to 1 keeps far rewards almost fully; a small one counts mostly the reward just earned.

The target network is a slow copy of the Q-network, with weights \(\phi'\), that computes the targets. (Deep Q-Networks (DQN)) Slow means the copy, written with a prime on its weights, is updated only a little at a time. In this family the critic plays the Q-network's part.

This holds the target still while the critic learns.

In DDPG both the actor and the critic have a slow copy, marked by a prime on the weights, and the targets are built from those copies. DQN's target takes a max, the highest of the scores its Q-network gives the next moves.

DDPG's target needs no max, because the slow actor names the next torques.

Equation 2. The critic's target. An arm got this step's reward for its hand being on the goal; the target adds what the slow critic expects from the next state, given the slow actor's next torques.
\(\displaystyle \htmlStyle{color:#0e6b59}{y} = \htmlStyle{color:#0e6b59}{r} + \htmlStyle{color:#5d6d7e}{\gamma}\, \htmlStyle{color:#8e44ad}{Q_{\phi'}}\big(\htmlStyle{color:#2471a3}{s'}, \htmlStyle{color:#a04000}{\mu_{\theta'}}(\htmlStyle{color:#2471a3}{s'})\big)\)
\(y\) is the target. A step's score is its reward plus the discounted score of what comes next, judged by slow copies so the target holds still while the critic learns. \(r\) is the reward stored with this step; \(\gamma\) is the discount, how much a reward one step later still counts; \(s'\) is the next state; a prime on the weights marks the slow copy: \(\theta'\) the slow actor's weights, \(\phi'\) the slow critic's; \(\mu_{\theta'}(s')\) the slow actor's torques there; \(Q_{\phi'}\) the slow critic scoring them. The code also drops the future score when the episode ends. It builds on the target idea from RL Basics, DQN's target network (Deep Q-Networks (DQN)), and Equation 1 line 2, with the max replaced by "ask the slow actor".

Equation 3 pulls the critic's score for each stored step toward its target.

A batch is a handful of remembered steps trained on together; the loss averages how far their scores are from their targets. (Deep Q-Networks (DQN))

The critic takes the batch, scores each stored step, and moves each score toward its target.

Equation 3. The critic's loss. Across a batch of stored arm steps, the critic's score for the torques actually used is pulled toward Equation 2's target.
\(\displaystyle \htmlStyle{color:#8e44ad}{L(\phi)} = \htmlStyle{color:#5d6d7e}{\mathbb{E}}\big[(\htmlStyle{color:#0e6b59}{y} - \htmlStyle{color:#8e44ad}{Q_\phi(s,a)})^2\big]\)
Shrink the gap between what the critic says and what the target says. \(Q_\phi(s,a)\) is the score of the critic being trained for the stored torques; \(\mathbb{E}\) is the average over the batch; the square counts misses either way. The gap inside the square is the TD error: The TD (temporal difference) error \(\delta\) is how much one step surprised the agent, the target minus the current guess. (RL Basics) This is DQN's squared TD error with the slow actor's next torques in place of the max. It builds on Equation 2 and the TD error.

In code, both equations run on one random batch at a time.

@torch.no_grad()
def td_target(r, s_next, done):
    a2 = actor_target(s_next)
    q2 = critic_target(s_next, a2)
    keep = 1 - done
    return r + gamma * keep * q2

def critic_update(batch):
    s, a, r, s_next, done = batch
    y = td_target(r, s_next, done)
    q = critic(s, a)
    loss = F.mse_loss(q, y)
    critic_opt.zero_grad()
    loss.backward()
    critic_opt.step()
  1. 1keep is zero where an arm's episode ended, so no future value is added there
  2. 2Moves the critic toward y by mean squared error. learn() in DDPG's full loop in PyTorch calls it, and the setup block there creates critic, critic_opt, gamma and the two target copies.

5 Moving the actor uphill on the critic

A policy gradient is any rule that moves the actor's weights to raise the return; this one is deterministic because the actor has no random draw.

The rule below uses the critic's slope to move the actor.

Equation 4. The actor climbs the critic. For one arm the critic says a slightly harder elbow torque would score higher; the actor's weights change so it outputs that harder torque in this state.
\(\displaystyle \htmlStyle{color:#8e44ad}{g} = \htmlStyle{color:#5d6d7e}{\nabla_a} \htmlStyle{color:#8e44ad}{Q_\phi}( \htmlStyle{color:#2471a3}{s}, \htmlStyle{color:#a04000}{a} )\)
Ask the critic which way the score rises for the torques the actor picked, then pass that direction back into the actor's weights. Line 1 defines \(g\), the critic's slope with respect to the torques, taken at the actor's pick \(a = \mu_\theta(s)\): the uphill direction.
\(\displaystyle \htmlStyle{color:#a04000}{\nabla_\theta J} \htmlStyle{color:#5d6d7e}{\approx} \htmlStyle{color:#5d6d7e}{\mathbb{E}}\big[\,\htmlStyle{color:#8e44ad}{g}\,\htmlStyle{color:#a04000}{\nabla_\theta \mu_\theta}( \htmlStyle{color:#2471a3}{s} )\big]\)
Line 2 moves the actor's weights along that direction: \(\nabla_\theta \mu_\theta(s)\) is how the actor's torques move when its weights move, and the product is the chain rule. \(J\) is the actor's expected return, the quantity the actor's weights are moved to raise. \(\approx\) because the states come from stored steps, not from the states the current actor would reach. The left side is the direction in the actor's weights that raises \(J\); because the critic's score stands for the return, climbing the critic raises \(J\), so the actor climbs the critic trained by Equation 3. It builds on the policy gradient (Policy Gradient Methods), Equation 1 line 2, and Equation 3.
def actor_update(batch):
    s = batch[0]
    q = critic(s, actor(s))
    actor_loss = -q.mean()
    actor_opt.zero_grad()
    actor_loss.backward()
    actor_opt.step()
  1. 1Takes the states of the same minibatch; the actor's loss is minus the critic's score of its action, and the mean is the average over the batch.
  2. 2Updates only the actor. Backward also leaves gradients on the critic's weights; critic_update zeroes them before the critic's next step. learn() in DDPG's full loop in PyTorch calls it, and actor_opt is created there.

8 DDPG's full loop in PyTorch

An update is one gradient step on one sampled batch. The arms act every step; learning happens in bursts of updates; the slow copies blend after every update.

Table 2. How often my repo learns
SettingRaising itLowering it
Environment steps between learning bursts: 256fewer, larger bursts, staler datamore frequent learning, more compute
Updates per burst: 64more reuse of each step, the critic can overfitcheaper, slower learning

The code below runs the schedule of Figure 9: act and store every step ①, and every so often learn in a burst of updates on random batches ②, each followed by the slow copies moving a little toward the networks being trained ③. The first block sets up the pieces that Training the critic from stored steps and Moving the actor uphill on the critic use.

import random
from collections import deque
from copy import deepcopy
import numpy as np
import torch
from torch.optim import Adam

critic = Critic()
actor_target = deepcopy(actor)
critic_target = deepcopy(critic)
pairs = [(actor_target, actor),
         (critic_target, critic)]
actor_opt = Adam(
    actor.parameters(), lr=1e-3)
critic_opt = Adam(
    critic.parameters(), lr=1e-3)
gamma, tau = 0.99, 1e-3
buf = deque(maxlen=100_000)
last100 = deque(maxlen=100)
  1. 1Imports for the buffer, the target copies and the optimizers.
  2. 2Makes the critic from the Critic class of An actor network and a scoring network, a slow target copy of each network, and pairs to match each target copy with its live network.
  3. 3An Adam optimizer (a gradient step that adapts its size per weight) for each, the discount, and how much of the weights of the networks being trained each slow copy takes in per update.
  4. 4The memory size from the settings table on Training DDPG, and a record of recent episode returns.
def to_tensor(rows):
    arr = np.array(rows)
    return torch.tensor(
        arr, dtype=torch.float32)

def store(s, act, info):
    obs = info.vector_observations
    r = info.rewards
    done = info.local_done
    buf.extend(
        zip(s, act, r, obs, done))
    return obs

@torch.no_grad()
def soft_update(tgt, live):
    dst = list(tgt.parameters())
    src = list(live.parameters())
    for t, p in zip(dst, src):
        t.lerp_(p, tau)
  1. 1Turns a list of rows into one tensor of decimal numbers, for the actor and for sampled minibatches.
  2. 2Stores one transition per arm (state, torques, reward, next state obs, episode-end flag) and returns the next states.
  3. 3Moves every target weight a share of the way toward its live weight.
def learn():
    if len(buf) <= 256:
        return
    rows = random.sample(buf, 256)
    cols = [to_tensor(c)
            for c in zip(*rows)]
    s, a, r, s_next, done = cols
    r = r[:, None]
    done = done[:, None]
    batch = s, a, r, s_next, done
    critic_update(batch)
    actor_update(batch)
    for tgt, live in pairs:
        soft_update(tgt, live)
  1. 1Waits until the memory holds more than one batch
  2. 2Draws a random batch and makes the five tensors, one row per sampled step; r and done become one column so they match the critic's one-score output.
  3. 3Runs critic_update of Training the critic from stored steps, then actor_update of Moving the actor uphill on the critic, on this minibatch. The repo also caps the size of each critic step (in the settings table on Training DDPG)
  4. 4Nudges both target copies.
def solved():
    if len(last100) < 100:
        return False
    return np.mean(last100) >= 30

step = 0
while not solved():
    out = env.reset(
        train_mode=True)
    info = out[brain_name]
    s = info.vector_observations
    returns = np.zeros(NUM_ARMS)
    while True:
        s_tensor = to_tensor(s)
        with torch.no_grad():
            act = actor(s_tensor)
        act = act.numpy()
        out = env.step(act)
        info = out[brain_name]
        s = store(s, act, info)
        returns += info.rewards
        step += 1
        if step % 256 == 0:
            for _ in range(64):
                learn()
        if any(info.local_done):
            break
    last100.append(returns.mean())
  1. 1The loop runs until the average return passes the solve bar in Table 1.
  2. 2Each episode resets all 20 arms and zeroes their total rewards, as in Many robot arms reaching for a moving goal; step counts steps across episodes.
  3. 3Every step all 20 arms act and store one transition each. The repo adds exploration noise, a small random nudge so the arm tries new moves, inside its act step, which this listing leaves out, taught in the noise section of Training DDPG: Target Networks, Replay and Noise.
  4. 4Every so often, a burst of updates runs (Table 2).

9 DDPG across many physics tasks

One algorithm, one network shape and one set of settings learned more than 20 simulated physics tasks: cartpole swing-up, manipulation, legged locomotion and driving, from joint readings and, for many tasks, from camera pixels.

The same settings learned all the tasks, and some policies were competitive with a method that works out its moves from an exact copy of the physics and its derivatives.

My own run solved the 20-arm Reacher (DDPG solving the many-arm Reacher).

10 When DDPG fits and how it fails

Twin Delayed DDPG (TD3), a later method, fixes its habit of scoring some torques too high.

DDPG fits when actions are continuous, old steps must be reused, and the simplest actor-critic for torques is wanted.

Soft Actor-Critic (SAC), another later method, learns how much to explore instead of relying on hand-tuned noise.

DDPG explores only through noise, of a kind chosen by hand, added to the actor's chosen torques.

Each of these fixes matches a row of the table below.
