MoCo: Momentum Contrast

MoCo learns from a small batch: a queue of past keys stands in for a huge batch, and a slowly changing encoder copy keeps those keys matching.

1 A queue replaces the giant batch

Contrastive learning is dictionary look-up: a query looks up its key in a dictionary of candidates. MoCo builds a dynamic dictionary with a queue and a second encoder that changes slowly.

MoCo (Momentum Contrast, He et al. 2020) gets many negatives from a small batch by keeping recent batches' embeddings in a queue. SimCLR's negatives come from the batch (InfoNCE page Figure 5 shows the lower ceiling of a small batch). In MoCo the anchor, the view that gets gradients, is called the query; its other view is the positive key, and 65,536 queued keys are the negatives. The loss is the same InfoNCE with \(M = 65{,}537\) candidates, at \(\tau = 0.07\).

MoCo runs every step: 256 keys go in and the oldest 256 leave, and the queue and the key encoder are the state carried between steps.

2 The momentum encoder

The key encoder is an exponential moving average (EMA) of the query encoder: after every step it keeps most of its old weights and takes a small share from the query encoder. MoCo sets this out in Algorithm 1, with the settings in Sec. 4 (Training).

In the momentum update, the key encoder, which gets no gradients, trails the query encoder as an exponential moving average (EMA).
\(\displaystyle \htmlStyle{color:#1f6fa8}{\theta _{k}} \leftarrow \htmlStyle{color:#2c3e50}{m}\cdot \htmlStyle{color:#1f6fa8}{\theta _{k}} + (1-\htmlStyle{color:#2c3e50}{m})\cdot \htmlStyle{color:#a84300}{\theta _{q}}\)
The key encoder’s weights \(\theta _{k}\) (theta) are replaced (\(\leftarrow\)) by a blend after every step. The momentum \(m\) is the share of its old weights it keeps. The rest comes from the query encoder’s weights \(\theta _{q}\), the ones gradient descent trains. With \(m\) near 1 the key encoder changes only a little each step, so keys queued many batches ago still match the current encoder; MoCo used \(m = 0.999\), and copying every step (\(m = 0\)) did not converge. Soft target updates in deep RL (DDPG and many DQN variants) use the same moving-average copy, with step size \(1 - m\).

4 MoCo in practice

This snippet runs one MoCo training step, then moves the key encoder toward the query encoder by EMA (exponential moving average, Section 2 eq line 1) and puts the batch’s keys in the queue.

def run(EMBED_DIM, QUEUE_SIZE, MOMENTUM_EMA, TEMPERATURE, INPUT_DIM, LR, MOMENTUM, WEIGHT_DECAY, BATCH, IMG):  # pass your own sizes and settings
    import copy
    import torch
    import torch.nn as nn
    import torch.nn.functional as F

    D, K, M_EMA, TAU = EMBED_DIM, QUEUE_SIZE, MOMENTUM_EMA, TEMPERATURE
    enc_q = nn.Sequential(nn.Flatten(), nn.Linear(INPUT_DIM, D))
    enc_k = copy.deepcopy(enc_q).requires_grad_(False)
    queue = F.normalize(torch.randn(K, D), dim=1)
    opt = torch.optim.SGD(enc_q.parameters(), lr=LR, momentum=MOMENTUM, weight_decay=WEIGHT_DECAY)

    x1, x2 = torch.rand(BATCH, 3, IMG, IMG), torch.rand(BATCH, 3, IMG, IMG)
    q = F.normalize(enc_q(x1), dim=1)              # queries, [BATCH, D]
    with torch.no_grad():
        k = F.normalize(enc_k(x2), dim=1)          # keys, no gradient
    pos = (q * k).sum(dim=1, keepdim=True)         # [BATCH, 1]
    neg = q @ queue.T                              # [BATCH, K]
    logits = torch.cat([pos, neg], dim=1) / TAU
    labels = torch.zeros(len(q), dtype=torch.long) # positive is column 0
    loss = F.cross_entropy(logits, labels)
    opt.zero_grad()
    loss.backward()
    opt.step()

    with torch.no_grad():
        for p_k, p_q in zip(enc_k.parameters(), enc_q.parameters()):
            p_k.mul_(M_EMA).add_(p_q, alpha=1 - M_EMA)
        queue = torch.cat([k, queue[:-len(k)]])    # newest in, oldest out

5 When to use MoCo, and where the same loss runs next

Use MoCo when the batch cannot grow to thousands and a long list of negatives is still wanted. The queue costs memory, 128 numbers per key, and the momentum encoder is the part that must be tuned.

The representations transfer to detection and segmentation.

Image-Text Contrastive Learning (CLIP) comes next, where the same loss runs in both directions between photos and their captions.
