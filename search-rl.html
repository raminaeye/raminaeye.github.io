Search as a Tool Learned by Reward

Masking retrieved words stops the model learning to write Wikipedia.

1 The model cannot know what changed

A language model answers from what it learned in training, and that knowledge has a cutoff. Anything that changed after training, or that the model never saw, is not in its weights. A question about a recent film or a new record needs facts from outside the model, and guessing from memory is the only move a model without a tool has.

Training here is reinforcement learning with retrieval inside the rollout, one rollout per question with several searches, and the retrieved passages so far are the state. A rollout is one full attempt at one question, from the question to the final answer. Nothing carries between questions. This page sits in the second of the three stages of tool-use learning the survey of agentic reinforcement learning maps out: the first stage copies tool use by prompting or fine tuning, the second optimizes outcomes by reward, and the third, tool use across long multi-turn tasks, is still the open frontier.

The older fixes do not teach the search itself. Retrieval augmented generation retrieves once before answering, so a question that needs two facts gets one round of passages and no second chance. Prompting tells the model to search but never teaches it when a search is worth making. The method on this page trains the search by reward: the reward judges the answer, and the model discovers for itself when to call the search engine, what to ask it, and when to stop.

2 Think, search, read, answer

The rollout is a loop with four moves. The model thinks in words, writes a search query when it finds it lacks some knowledge, reads the passage that comes back, and thinks again. The loop repeats until the model writes its final answer.

Tags mark who wrote what. Reasoning goes between <think> tags, the query between <search> tags, the retrieved passage between <information> tags, and the final answer between <answer> tags. When the closing search tag appears, the system pulls the query out, runs it against the search engine, and pastes the passage back between information tags for the model to read. A retriever is the search engine behind the call: it takes a query and returns passages from its collection. A token is a word or word piece the model reads and writes, so a passage is a stretch of retrieved tokens and a thought is a stretch of the model's own tokens.

The rollout stops in one of two ways: the search budget runs out, or the model writes its answer. The search budget is the maximum number of searches allowed in one rollout. The budget is what keeps a model that keeps finding new questions to ask from searching forever.

2.1 The rollout in one line

The rollout is the policy interleaved with the retriever. The model writes, the retriever answers, and the two take turns until the answer lands. That interleaving is the object every equation on this page describes.

Equation 1. The rollout as policy interleaved with retriever. The model writes, the search engine answers, and the two take turns.
\(\displaystyle \begin{aligned}&y \sim \htmlClass{eqt sym-x}{\htmlStyle{color:var(--sym-x)}{\pi_\theta}}(\cdot \mid \htmlClass{eqt sym-r}{\htmlStyle{color:var(--sym-r)}{x}}; \htmlClass{eqt sym-p}{\htmlStyle{color:var(--sym-p)}{\mathcal{R}}}) \\&\quad = \htmlClass{eqt sym-x}{\htmlStyle{color:var(--sym-x)}{\pi_\theta}}(\cdot \mid \htmlClass{eqt sym-r}{\htmlStyle{color:var(--sym-r)}{x}}) \otimes \htmlClass{eqt sym-p}{\htmlStyle{color:var(--sym-p)}{\mathcal{R}}}\end{aligned}\)
The rollout is a joint product. \(y\) is the full rollout, thoughts plus searches plus retrieved passages plus the answer; \(x\) is the question; \(\pi_\theta\) is the policy, the model being trained; \(\mathcal{R}\) is the search engine; \(\otimes\) means interleaved, the model and the search engine taking turns.
\(\pi_\theta\) the policy \(\mathcal{R}\) the search engine \(x\) the question \(y\) the full rollout
The paper writes this rollout in section 3.2, with the search engine as part of the environment the policy acts in.

One rollout in tag form looks like the snippet below. The same shape repeats for every search: think, search, read, think again.

rollout = [
  "<think> director? </think>",
  "<search> director? </search>",
  "<information> by Bong Joon-ho",
  "</information>",
  "<think> born when? </think>",
  "<search> born when? </search>",
  "<information> 14 Sep 1969",
  "</information>",
  "<answer> 1969 </answer>",
]
  1. 1 The model writes these lines: its thinking and its search queries. rollout is the full attempt at one question.
  2. 2 The search engine writes these lines: the retrieved passage. They are read, not trained on, as section 3 shows.
  3. 3 The model writes the answer from what it read, in the form the template asks for.

3 Masking the retrieved words

This section leans on the GRPO page for the group comparison and on the PPO page for the clipped objective. The base objectives are taught there, not here. What this section teaches is the one change the search engine forces on them: the mask.

The problem is that a rollout mixes two authors. The model's own tokens sit next to retrieved tokens from a passage, and the loss is computed over the whole rollout. The loss is the number training pushes down, and tokens in the loss are the ones the model learns from. Without masking, training pushes the model to write retrieved passages itself. A model trained that way learns to write Wikipedia, not to search it.

3.1 The objective with retrieval inside

The training objective is the usual KL regularized reward objective, with the search engine inside the rollout. KL regularized means the objective pays for reward and also pays a penalty for drifting far from a reference model, so training cannot chase reward by forgetting how to write. The reference model is the model before this round of training, kept fixed as an anchor.

Equation 2. The KL regularized RL objective over rollouts that include retrieval. Push the reward up, keep the drift from the reference small.
\(\displaystyle \begin{aligned}&\max_{\htmlClass{eqt sym-x}{\htmlStyle{color:var(--sym-x)}{\pi_\theta}}} \htmlClass{eqt sym-x}{\htmlStyle{color:var(--sym-x)}{\mathbb{E}}} \big[ \htmlClass{eqt sym-r}{\htmlStyle{color:var(--sym-r)}{r_\phi}}(\htmlClass{eqt sym-r}{\htmlStyle{color:var(--sym-r)}{x}}, \htmlClass{eqt sym-x}{\htmlStyle{color:var(--sym-x)}{y}}) \big] \\&\quad - \htmlClass{eqt sym-wait}{\htmlStyle{color:var(--sym-wait)}{\beta}}\, \htmlClass{eqt sym-wait}{\htmlStyle{color:var(--sym-wait)}{\mathbb{D}_{\mathrm{KL}}}} \big[ \htmlClass{eqt sym-x}{\htmlStyle{color:var(--sym-x)}{\pi_\theta}} \,\|\, \htmlClass{eqt sym-x}{\htmlStyle{color:var(--sym-x)}{\pi_{\mathrm{ref}}}} \big]\end{aligned}\)
The objective is a trade. \(\pi_\theta\) is the policy being trained; the average \(\mathbb{E}\) runs over questions from the dataset and rollouts from the policy with the search engine, as in Equation 1; \(r_\phi(x, y)\) is the reward for the rollout, taught in section 4; \(\beta\) sets how strongly the drift penalty counts; \(\mathbb{D}_{\mathrm{KL}}\) is the KL divergence, a measure of how far the policy has drifted from the reference; \(\pi_{\mathrm{ref}}\) is the reference model.
\(\pi_\theta\) the policy \(r_\phi\) the reward \(\beta\) the drift weight \(\mathbb{D}_{\mathrm{KL}}\) the drift measure
The paper writes this objective in section 3.1, with the search engine inside the rollout on both sides of the drift measure.

3.2 The mask

The fix is one indicator that marks every token by its author. The mask is 1 for a token the model wrote and 0 for a retrieved token, and the loss sums only over the ones. The model still reads the passages, since they sit in the rollout and shape what it writes next, but it never gets trained to produce them.

Equation 3. The masking indicator. One for the model's own tokens, zero for retrieved ones.
\(\displaystyle \begin{aligned}&\htmlClass{eqt sym-y}{\htmlStyle{color:var(--sym-y)}{I}}(\htmlClass{eqt sym-y}{\htmlStyle{color:var(--sym-y)}{y_t}}) = \\&\begin{cases} 1, & \text{model token} \\ 0, & \text{retrieved token} \end{cases}\end{aligned}\)
The mask sorts tokens by author. \(y_t\) is token \(t\) of the rollout; \(I(y_t)\) is 1 when the model wrote that token and 0 when it came back from the search engine.
\(I(y_t)\) the mask \(y_t\) one token
The paper writes this masking in section 3.1, and applies it to the KL term too, so the drift measure also ignores retrieved tokens.

3.3 The masked objectives

With the mask in place, the PPO and GRPO objectives change in exactly one way: every sum over tokens runs only over the model's own tokens, and the count that divides the sum counts only those tokens. The ratio and the clip are the ones the PPO page teaches, and the group advantage is the one the GRPO page teaches. The mask is the new part, and it is the same mask in both.

Equation 4. The PPO objective with retrieved token masking. The clipped objective from the PPO page, summed over the model's tokens only.
\(\displaystyle \begin{aligned}&\htmlClass{eqt sym-x}{\htmlStyle{color:var(--sym-x)}{\mathcal{J}_{\mathrm{PPO}}}}(\htmlClass{eqt sym-x}{\htmlStyle{color:var(--sym-x)}{\theta}}) = \htmlClass{eqt sym-x}{\htmlStyle{color:var(--sym-x)}{\mathbb{E}}} \left[ \frac{1}{\sum_t \htmlClass{eqt sym-y}{\htmlStyle{color:var(--sym-y)}{I}}(\htmlClass{eqt sym-y}{\htmlStyle{color:var(--sym-y)}{y_t}})} \right. \\&\quad \left. \sum_{t: \htmlClass{eqt sym-y}{\htmlStyle{color:var(--sym-y)}{I}}(\htmlClass{eqt sym-y}{\htmlStyle{color:var(--sym-y)}{y_t}})=1} \min \big( \htmlClass{eqt sym-p}{\htmlStyle{color:var(--sym-p)}{\rho_t}} \htmlClass{eqt sym-y}{\htmlStyle{color:var(--sym-y)}{A_t}}, \right. \\&\quad \left. \operatorname{clip}(\htmlClass{eqt sym-p}{\htmlStyle{color:var(--sym-p)}{\rho_t}}, 1-\epsilon, 1+\epsilon) \htmlClass{eqt sym-y}{\htmlStyle{color:var(--sym-y)}{A_t}} \big) \right]\end{aligned}\)
The masked PPO objective. \(\mathcal{J}_{\mathrm{PPO}}\) is the objective to push up; the average \(\mathbb{E}\) runs over questions and rollouts with the search engine; the sum runs only over tokens with mask 1, the model's own tokens, and the count in front divides by how many of those there are; \(\rho_t\) is the ratio from the PPO page, the new chance of token \(t\) divided by the chance under the policy that wrote the rollout; \(A_t\) is the advantage, how good token \(t\) turned out to be; \(\operatorname{clip}\) holds the ratio between \(1-\epsilon\) and \(1+\epsilon\).
\(I(y_t)\) the mask \(\rho_t\) the ratio \(A_t\) the advantage \(\epsilon\) the clip width
The paper writes this as its equation 1, in section 3.1. Its ratio compares the current policy against the policy that wrote the rollout, and the masking factor is the new part. The paper prints the denominator as \(\pi_{\mathrm{ref}}\), the reference policy, while this page follows the PPO page and calls it the policy that wrote the rollout.
Equation 5. The GRPO objective with retrieved token masking. The group objective from the GRPO page, with the same mask and the KL term at the end.
\(\displaystyle \begin{aligned}&\htmlClass{eqt sym-x}{\htmlStyle{color:var(--sym-x)}{\mathcal{J}_{\mathrm{GRPO}}}}(\htmlClass{eqt sym-x}{\htmlStyle{color:var(--sym-x)}{\theta}}) = \htmlClass{eqt sym-x}{\htmlStyle{color:var(--sym-x)}{\mathbb{E}}} \left[ \frac{1}{\htmlClass{eqt sym-x}{\htmlStyle{color:var(--sym-x)}{G}}} \sum_{i=1}^{\htmlClass{eqt sym-x}{\htmlStyle{color:var(--sym-x)}{G}}} \right. \\&\quad \left. \frac{1}{\sum_t \htmlClass{eqt sym-y}{\htmlStyle{color:var(--sym-y)}{I}}(\htmlClass{eqt sym-y}{\htmlStyle{color:var(--sym-y)}{y_{i,t}}})} \right.\\&\quad \left. \sum_{t: \htmlClass{eqt sym-y}{\htmlStyle{color:var(--sym-y)}{I}}(\htmlClass{eqt sym-y}{\htmlStyle{color:var(--sym-y)}{y_{i,t}}})=1} \right.\\&\quad \left. \min \big( \htmlClass{eqt sym-p}{\htmlStyle{color:var(--sym-p)}{\rho_{i,t}}} \htmlClass{eqt sym-y}{\htmlStyle{color:var(--sym-y)}{\hat{A}_{i,t}}}, \right. \\&\quad \left. \operatorname{clip}(\htmlClass{eqt sym-p}{\htmlStyle{color:var(--sym-p)}{\rho_{i,t}}}, \right.\\&\quad \left. 1-\epsilon, 1+\epsilon) \htmlClass{eqt sym-y}{\htmlStyle{color:var(--sym-y)}{\hat{A}_{i,t}}} \big) \right]\\&\quad - \htmlClass{eqt sym-wait}{\htmlStyle{color:var(--sym-wait)}{\beta}}\, \htmlClass{eqt sym-wait}{\htmlStyle{color:var(--sym-wait)}{\mathbb{D}_{\mathrm{KL}}}} \big[ \htmlClass{eqt sym-x}{\htmlStyle{color:var(--sym-x)}{\pi_\theta}} \,\|\, \htmlClass{eqt sym-x}{\htmlStyle{color:var(--sym-x)}{\pi_{\mathrm{ref}}}} \big]\end{aligned}\)
The masked GRPO objective. \(G\) is the group size, how many answers the model writes to the same question; \(i\) counts the answers in the group; each answer is scored by the same masked clipped term as the PPO line above, with its own mask \(I(y_{i,t})\) and its own advantage \(\hat{A}_{i,t}\), how much better answer \(i\) scored than the group mean, as taught on the GRPO page; the KL term at the end is the same drift penalty as Equation 2, also masked.
\(G\) the group size \(I(y_{i,t})\) the mask \(\hat{A}_{i,t}\) the group advantage \(\beta\) the drift weight
The paper writes this as its equation 2, in section 3.1, with the KL term added to the loss directly instead of inside the reward.

4 The reward

The reward judges only the final answer, by exact match. Exact match means the predicted answer matches the gold answer as a string: 1 when they match, 0 otherwise. The gold answer is the known right answer from the training data. Nothing pays for searching well, reasoning well, or writing a tidy trace. A rollout earns 1 for landing the right answer and 0 for anything else.

Equation 6. The exact match reward. One for the right answer, zero for anything else.
\(\displaystyle \begin{aligned}&\htmlClass{eqt sym-r}{\htmlStyle{color:var(--sym-r)}{r_\phi}}(\htmlClass{eqt sym-r}{\htmlStyle{color:var(--sym-r)}{x}}, \htmlClass{eqt sym-x}{\htmlStyle{color:var(--sym-x)}{y}}) = \htmlClass{eqt sym-r}{\htmlStyle{color:var(--sym-r)}{\mathrm{EM}}}(\htmlClass{eqt sym-r}{\htmlStyle{color:var(--sym-r)}{a_{\mathrm{pred}}}}, \htmlClass{eqt sym-r}{\htmlStyle{color:var(--sym-r)}{a_{\mathrm{gold}}}}) \\&\quad = \begin{cases} 1, & a_{\mathrm{pred}} = a_{\mathrm{gold}} \\ 0, & \text{otherwise} \end{cases}\end{aligned}\)
The whole reward is the final answer. \(a_{\mathrm{pred}}\) is the answer pulled out of the rollout, from between the answer tags; \(a_{\mathrm{gold}}\) is the known right answer; \(\mathrm{EM}\) is exact match, 1 when the two are the same string and 0 otherwise; \(r_\phi\) is the reward that feeds Equations 2, 4 and 5.
\(r_\phi\) the reward \(a_{\mathrm{pred}}\) the predicted answer \(a_{\mathrm{gold}}\) the gold answer
The paper writes this reward as its equation 3, in section 3.4. It adds no format reward, since the template already keeps the shape, and no learned reward model, since a learned reward can be gamed and costs extra training.

The search behavior is never paid for directly, and that is the point. A rollout that never searches and guesses from memory earns 0 whenever the memory is wrong. A rollout that searches, reads, and lands the answer earns 1. Over many questions, the update pushes the policy toward the moves that earned 1, and searching becomes the habit.

5 Practice

Each search step costs one search call, at training and at inference, and the training step waits on the retriever while the passage comes back (paper section 3.2). More searches mean more facts in the rollout, and a slower step.

The headline setting is retrieved token masking, with retrieved tokens excluded from the loss (paper section 3.1). PPO is the default method (paper section 4.3). Training runs in the veRL reinforcement learning framework, and the official repository carries training scripts for PPO and GRPO alongside the retrieval server.

The official repository is github.com/PeterGriffinJin/Search-R1, verified live. It carries the training pipeline, the retrieval server, the datasets and the trained models.

6 Failure modes

Four failures cover most of what goes wrong. Each has a cause, a visible symptom, and a fix.

6.1 Retrieved words leak into training

Cause: the mask is off, so retrieved tokens sit in the loss next to the model's own words. Symptom: the model starts writing passage-like text as its own reasoning, and training grows unstable. Fix: mask retrieved tokens from the loss (paper section 3.1); the paper's masking study finds training with masking more stable and stronger than without it (paper section 5.4). The toggle in Figure 4 shows what each setting trains on.

6.2 One search for a two-hop question

Cause: the model answers after the first passage, as if one round of retrieval settled the question. Symptom: an answer built on half the facts, right about the first hop and wrong about the second. Fix: the multi-turn rollout lets the model search again after reading (paper section 3.2); the walkthrough in Figure 3 steps through a question that needs two searches, and only the second passage holds the answer.

6.3 The search returns nothing useful

Cause: the query is too vague, or the retriever misses and returns an unrelated passage. Symptom: the model reasons from an empty or wrong passage and lands a confident wrong answer. Fix: the model can rephrase the query and search again within the budget (paper section 3.2), and the budget caps the tries so a rollout that keeps missing still ends.

6.4 The right answer earns zero

Cause: exact match compares strings, so a right answer in different words scores 0. Symptom: good rollouts get no reward, and the update pushes away from moves that were actually right. Fix: the template asks for the answer alone inside the answer tags, with no extra text (paper section 3.3), so the predicted answer comes out in the short form the match expects.

7 What comes next

Search as a tool works because the reward pays for right answers and the mask keeps retrieved words out of the training signal. The tool here was a search engine, called with a query written as text. The next page changes how the calls themselves are written: Tool Calls Written as Code teaches tool calls written as code, so later calls can reuse earlier results as variables instead of starting each call from scratch.
