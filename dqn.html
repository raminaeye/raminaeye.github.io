Some worlds never show the same situation twice, so a list of move values, one per situation, can never be filled. What can stand in for that list, and how do you keep it steady while it learns?

Here the agent is the banana collector, which senses the arena through sensor readings, real numbers that change a little with every step. The arena holds yellow and blue bananas; the collector is paid for each yellow it eats and charged for each blue, until time runs out.

Figure 1 looks down on the arena, with the collector as the blue dot and rays reaching out from it. Take a ray that hits a yellow banana close by: the reading says a yellow banana is near, so the collector turns toward it.

The agent is the learner that picks the moves, as taught in RL Basics. A state is the agent's situation right now; a move, or action, is one choice the agent can make in a state; a reward is the number the world hands back after each move, good or bad, as taught in RL Basics. An episode is one run from the start until it ends, as taught in RL Basics. Each new episode drops fresh bananas around the arena.

1 The banana arena

The collector senses a list of real-valued readings and has a short list of moves.

The return is all the reward still to come, with later rewards counted a little less, as taught in RL Basics. A policy is the agent's rule for choosing a move in each state; it may always pick the same move or pick by chance, as taught in RL Basics. Yellows and blues lie mixed together, so the way to a yellow can pass close to a blue.

A move's value \(Q(s,a)\), also called its score, is the return the agent expects if it makes move \(a\) in state \(s\) and plays on from there, as taught in RL Basics. A Q-table keeps one score for every state and move, as taught in Q-Learning. The collector's readings almost never repeat, so it almost never meets the same state twice.

Epsilon-greedy usually plays the top-scored move and, with chance \(\epsilon\), a random one instead, as taught in RL Basics. The exploring chance shrinks after each episode. Early in training most of its steps are random, so it sees much of the arena before it trusts its scores.

Figure 2 shows how the collector turns its readings into move scores, with one network doing the whole job. The readings go in on the left, the network in the middle mixes them through its layers, and one score per move comes out on the right, the top score naming the move the collector plays. Take readings from a spot near a yellow banana: the score for the move toward it comes out highest, so the collector turns that way.

eps = 1.0   # exploring chance, shrinks after each episode
state = env.reset()
done = False
while not done:
    action = agent.act(state, eps)
    next_state, reward, done = env.step(action)
    agent.step(state, action, reward, next_state, done)
    state = next_state
eps = max(0.01, eps * 0.998)

2 From a Q-table to a network

A network stands in for the table

What. Picture the collector's readings as a list of numbers that changes a little with every step, so no table could hold a score for every list. Function approximation means a network takes that list in and gives back one score per move. Lists that look nearly alike get nearly alike scores, so what is learned in one spot carries to the next.

How. The readings go in, the weights mix them through the layers, and one score per move comes out.

Why. When it works, a spot the collector has never stood in still gets a sensible score.

The features are the numbers a network reads about a state. In the arena two spots with almost the same readings now share one learned score, and a spot never seen before still gets a sensible guess.

The discount \(\gamma\) is a number under one that shrinks the reward of each later step by one more power, as taught in RL Basics. Q-learning's target is the step's reward plus the discounted best move value in the next state, as taught in Q-Learning. So the collector can learn from a single step, without waiting for time to run out.

A network that outputs one score per move is a Q-network, and training it with Q-learning's target is a Deep Q-Network, DQN for short.

2.1 Learning from old steps, off-policy

Best play is the policy that earns the most return; \(Q^{*}\) is each move's value under it, as taught in RL Basics. Off-policy means learning the values of one policy while playing another, as taught in SARSA. So steps taken long ago by an older, more random policy are still fair training data for Q-learning's target.

2.2 Replay memory reuses past steps

Learn from old steps, shuffled

What. Picture the memory as a long row of past steps, oldest on the left and newest on the right. Steps that follow each other look almost the same, so training on them in a row teaches the same lesson many times.

How. Every step joins the row, and each training step draws a batch, a handful from it at random, scattered across the whole row.

Why. When it works, one batch mixes the collector's early wandering with its later runs, so each batch teaches something fresh.

Replay memory, the replay buffer in the code, comes from an early method that reused past steps instead of learning from each step once and throwing it away.

Figure 3 shows the replay memory as a row of past steps, with one random batch ringed inside it. The ringed steps are scattered across the memory instead of taken in a row. Take the ringed batch: its steps come from far-apart moments, spread across the whole row.

2.3 A slow copy for the targets

A slow copy holds the targets still

What. Picture two networks side by side: the live one that learns, and a slow copy that only hands out targets. If the live one also set the targets, each update would move the target it chases.

How. The live network learns from the batch while the slow copy reads the targets. After every update the slow copy takes a tiny share of the live weights and keeps almost all of its own: that small step is the soft update. A hard copy would overwrite it outright instead.

Why. When it works, the targets hold still from one batch to the next, and the live scores climb toward them.

The live network is the Q-network being trained, with weights \(\phi\). The target network is a slow copy of the Q-network, with weights \(\phi'\), that computes the targets.

In the equations below, an arrow means replace the left side with the right side. The original DQN method copies the live weights outright every so often; my repo, Ramin's Value-based-methods repo on GitHub, blends a little after every update.

Figure 4 shows the training loop as four boxes, each one feeding the next around the loop. The collector acts and remembers every step, learns from random past steps every few steps, the slow copy follows the live network a little after every learning step, and random moves get rarer each episode. Take one pass round the loop: the collector moves, the step joins the memory, a batch trains the network, and the slow copy creeps after it.

3 A training step with replay and a slow copy

One training step from memory

What. Picture one training step as a round trip: a handful of remembered steps, a batch, is drawn from memory, each one is scored against a target, and the scores are nudged toward their targets.

How. The slow copy sets each target, the live network gives its score for the move actually played, and the gap between them is the surprise. The loss averages the per-step error costs over the batch, and one gradient step shrinks it.

Why. When it works, each batch pulls the live scores closer to their targets, and the collector eats more yellow than blue as training goes on.

The TD (temporal difference) error \(\delta\) is how much one step surprised the agent, the target minus the current guess, as taught in RL Basics.

The learning rate \(\eta\) sets how big a step each update takes.

5 From a remembered batch to new weights

A plain Q-network.

import random
from collections import deque
import torch
import torch.nn as nn, torch.nn.functional as F

GAMMA = 0.99   # the discount, how much a later reward still counts
TAU = 0.001    # the soft-update share, how far the slow copy moves each update
HIDDEN = 64    # the width of each hidden layer

class QNetwork(nn.Module):
    def __init__(self, n_inputs, n_moves, hidden=HIDDEN):
        super().__init__()
        self.body = nn.Sequential(
            nn.Linear(n_inputs, hidden), nn.ReLU(),
            nn.Linear(hidden, hidden), nn.ReLU(),
            nn.Linear(hidden, n_moves),          # one move value per move
        )

    def forward(self, state):
        return self.body(state)                  # readings in, move values out
  1. 1The libraries: PyTorch for the network, a deque for the memory, random for the draw.
  2. 2The discount \(\gamma\), the soft-update share \(\tau\) and the hidden width, as in the settings table.
  3. 3A multilayer perceptron whose last layer has one output per move. ReLU is the activation after each hidden layer: it passes positive values through and zeroes negative ones.
  4. 4One forward pass fills a whole row of move values, for a whole batch of states at once.

A deque with a maximum length drops its oldest item when a new one arrives.

class ReplayBuffer:
    def __init__(self, capacity):
        self.memory = deque(maxlen=capacity)     # the oldest steps fall out first

    def add(self, s, a, r, s_next, done):
        self.memory.append((s, a, r, s_next, done))

    def sample(self, batch_size):
        batch = random.sample(self.memory, batch_size)   # scattered, not in a row
        s, a, r, s_next, done = zip(*batch)
        return (torch.tensor(s, dtype=torch.float32),
                torch.tensor(a).unsqueeze(1),
                torch.tensor(r, dtype=torch.float32).unsqueeze(1),
                torch.tensor(s_next, dtype=torch.float32),
                torch.tensor(done, dtype=torch.float32).unsqueeze(1))
  1. 1The memory holds at most capacity steps.
  2. 2Each move stores one step, with done saying whether the episode ended there.
  3. 3random.sample draws the random batch, which is turned into one tensor per part of the step. A tensor is a grid of numbers the network reads as one batch.
def td_target(r, s_next, done):
    with torch.no_grad():                        # the target is not trained
        best_next = q_target(s_next).max(1, keepdim=True)[0]
        return r + GAMMA * best_next * (1 - done)
  1. 1The target, from the slow copy. max(1) takes the best value across the moves. done is true when the remembered step ended the episode, so nothing is added after it.

The loss below is the squared error my repo runs. The 2015 DQN paper capped how much each error counted instead, which acts like the Huber loss: a Huber loss is squared error for small misses and straight-line error past a threshold.

def learn_step(q_live, q_target, opt, batch):
    s, a, r, s_next, done = batch
    y = td_target(r, s_next, done)               # the target, from the slow copy
    q_sa = q_live(s).gather(1, a)               # the value of each played move
    loss = F.mse_loss(q_sa, y)                   # squared error, as my repo runs it; the capped error is the Huber loss, defined above
    opt.zero_grad()
    loss.backward()
    opt.step()                                   # one gradient step on the live weights
    with torch.no_grad():
        for p_t, p in zip(q_target.parameters(), q_live.parameters()):
            p_t.mul_(1 - TAU).add_(TAU * p)      # the soft update
  1. 1The target comes from the block above, computed by the slow copy.
  2. 2gather picks, from each row of move values, the one for the move that was played. The loss is the squared-error loss from the training step card.
  3. 3The gradient step: clear old gradients, compute new ones, step the weights.
  4. 4The soft update, weight by weight.

6 Why random batches from memory matter

Here the agent is a warehouse robot that must reach its charging dock. The floor is a grid of cells, one per place the robot can stand. The ledge is the strip of floor between the start and the dock. It starts in one bottom corner and the dock sits in the other.

Each move's reward is minus the battery it uses, so the best total is the one closest to zero. Every move costs a little battery; stepping onto the ledge costs a lot and puts the robot back at the start; only reaching the dock ends the episode. The cheapest way to the dock is the shortest path that never steps onto the ledge.

Here the features say which cells are near the robot's cell. A small network learns the floor, so its estimate of the best move value on the ringed square can be checked against the true best value.

Random batches settle on the true value, while recent-step batches with a large step blow the estimate up.

Figure 6 shows a warehouse robot learning its floor from batches of remembered steps, with the batch and step size under the reader's control. The top row picks the batch, recent steps or random memory, and the step size, small and steady or large and fast, while the floor shows the batch in orange and the chart tracks the best move value on the ringed square against best play. Take the run at rest: random memory with a large step size, and the purple line is still on its way to best play.

8 When a network beats a table

DQN fits when the states are too many or too varied for a table, and the moves come as a short list. When the states fit in a table, plain Q-Learning is simpler and steadier.

10 Refining move scores, and moves that are amounts

10.1 Refining how move scores are computed

Double DQN: the live network picks

What. Picture the slow copy's best score as a lucky guess: among scores that are still guesses, the biggest one is usually the one that guessed too high, so the targets run high.

How. The live network picks the move that looks best in the next state, \(a^* = \arg\max_{a'} Q(s', a'; \phi)\), and the slow copy scores only that move, \(Q(s', a^*; \phi')\), so a lucky guess in the live network is scored by the slow copy instead of by itself.

Why. When it works, the targets stop running high and the scores settle near the returns the collector really earns.

Dueling DQN splits spot from move

What. Picture each move score as two parts added together: how good the spot itself is, and how much this move adds over the rest. Where every move is much the same, learning the spot's worth once teaches all its moves at once.

How. The network outputs the spot's worth \(V(s)\) and one extra number per move, \(A(s,a)\), and each move score is the spot's worth plus its extra number minus the average extra over all moves. The extras stay centred: they average to zero because the mean is subtracted.

Why. When it works, spots the collector visits often get their worth right sooner, and the move scores follow.

Each move score still comes out as one number, and the target's max reads them as they are.

10.2 When a move is an amount

A move that is an amount, like how hard a motor pushes, needs a different method. Continuous-Action RL handles moves that are amounts.

DQN learns move values and picks the best one. The other big family learns the policy directly, nudging it toward moves that paid off. That family is Policy Gradients, read earlier in the series. The next page is Double DQN.
