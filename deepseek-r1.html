DeepSeek-R1: Reasoning from Checkable Rewards

Checking the answer with a program, instead of a learned scorer, grows long step-by-step reasoning.

Before you startGroup Relative Policy Optimization (GRPO)Reward Models from Human PreferencesAligning Language Models with RLKnowledge DistillationRL BasicsDueling DQNConstitutional AI: Critique, Revise and AI Feedback

This page builds on RL Basics and Aligning Language Models with RL. The terms below are the ones this page keeps using.

  • An agent is the learner that picks the moves. A state is the agent’s situation right now; a move, or action, is one choice the agent can make in a state; a reward is the number the world hands back after each move, good or bad. (RL Basics)
  • A token is a word or a piece of a word; a language model writes its reply one token at a time. (Aligning Language Models with RL)
  • Here the agent is the language model. Here the state is the prompt plus the tokens written so far, and the move is the next token. Here the reward is one number for the whole reply, given when the reply ends.
  • RL, short for reinforcement learning, is learning which moves to make from rewards rather than from labelled answers. (RL Basics)
  • A policy is the agent’s rule for choosing a move in each state; it may always pick the same move or pick by chance. The policy is the language model being trained to write replies. (RL Basics, Aligning Language Models with RL)

1Learned scores get gamed

A learned score can be fooled when a model trains against it for a long time, and retraining the scorer costs compute; for math and code, a program can check the answer instead.

The running example is a competition math question with one known final answer. The model writes its reasoning and then its final answer, and a program checks whether that answer matches the known one.

The running example on this page is one long answer to that question, made here to show the method, in the shape of an R1-Zero answer: it starts wrong, stops mid-answer, re-checks its own reasoning, and lands the final answer in its box. The question itself is left unnamed, and it is not the muffin question from the GRPO page. One answer carries the whole page.

GRPO is a reinforcement learning (RL) method that writes a group of answers to each question and pushes each answer up or down by how it scored against the rest of its group.

DeepSeek-R1’s main training step is GRPO, with a program checking each math or code answer.

On the math question, a program marks each answer in a group right when its final answer matches the known one.

The base model is the pretrained model before any fine-tuning; it continues text but does not follow instructions.

Supervised fine-tuning (SFT) trains a model on written example answers with the ordinary loss for predicting the next word. (Aligning Language Models with RL)

DeepSeek-R1 has two routes from the base model, and only one of them uses SFT.

R1-Zero is the first route, GRPO straight on the base model with only a program’s answer and format checks.

R1 is the second route, a staged recipe from the same base model; Figure 2 shows both.

This page calls R1’s two RL stages reasoning RL and all-prompt RL.

R1-Zero came first, and its problems shaped the four stages of R1.

2Reward what a program can check

DeepSeek-R1 trains a language model by letting it write answers and rewarding them.

The answer in Figure 1 is mostly reasoning, with the final answer in its last tokens.

In most of DeepSeek-R1’s training a program computes the reward by checking the finished answer.

DeepSeek-R1 runs this loop on math and code questions whose answers a program can check.

DeepSeek-R1 shows that RL with such program rewards can grow long reasoning, by making answers that pass the checks more likely.

GRPO’s full name is group relative policy optimization.

DeepSeek-R1 runs GRPO on answers it writes as it trains, so every group is fresh.

A reward model is a language model with a one-number output, trained on people’s comparisons so the reply they preferred scores higher. (Reward Models from Human Preferences)

Pushed hard, the policy learns replies the reward model over-scores (Reward Models from Human Preferences).

DeepSeek-R1 uses a program instead of a reward model wherever the answer can be checked.

A boxed answer is the final answer written inside \boxed{...}, so a program can find it.

A program compares the boxed answer with the known one, and runs code against its tests.

Think tags are the markers <think> and </think> that the model is asked to put around its reasoning. (the template)

A second check passes only when the reasoning sits inside think tags.

Rewards like these, computed by a program that checks the answer and the format, are called rule rewards.

Chain of thought is the reasoning text a model writes before its final answer. (Constitutional AI: Critique, Revise and AI Feedback)

R1-Zero’s chains of thought often mixed languages, switching between English and Chinese inside one answer, so the R1 recipe adds a reward for staying in the question’s language (the language reward card).

2.1The template asks only for structure

The template is the fixed prompt wrapped around every question during training.

It asks for reasoning inside think tags, then the answer inside answer tags, a second pair of markers around the final answer.

The long answer’s question is one such question: the template wraps it, and the long answer’s reasoning fills the think tags and its final answer the answer tags.

“The assistant first thinks about the reasoning process in the mind and then provides the user with the answer. The reasoning process and answer are enclosed within <think>...</think> and <answer>...</answer> tags, respectively.”

DeepSeek-R1, Table 1

For math the final answer inside the answer tags is also boxed, and the format check looks only for the think tags.

3Rewards a program can compute

A move’s advantage is how much better it is expected to do than the usual result from that state. (Dueling DQN)

In GRPO, an answer’s advantage is how much better it scored than the average of its group, the answers written for the same question, divided by how far apart the group’s scores are. (Group Relative Policy Optimization (GRPO))

These rule rewards feed that advantage.

The reference model \(\pi_{\mathrm{ref}}\) is a frozen copy of the SFT model. (Aligning Language Models with RL)

KL measures how different two probability distributions are, zero when they match; the KL penalty charges the policy for drifting away from the reference model. (Aligning Language Models with RL)

R1-Zero charges this penalty on every update, at a small strength.

R1-Zero has no SFT model, so for R1-Zero the reference starts as a frozen copy of the base model and is replaced by a copy of the current model every few hundred steps; reasoning RL refreshes its reference the same way.

\(\mathbb{1}[\cdot]\) is one when the check inside the brackets passes and zero otherwise.

The sign \(\in\) means is one of.

With them, a program gives a reward of one for a right boxed answer and one more for reasoning inside think tags, with no network involved.

4.1What runs and how often

R1-Zero runs thousands of RL steps.

Each step writes a group of answers per question and runs only cheap checks, with no reward network.

The questions are like the math question, and each step’s group of answers is like the long answer.

R1 runs its two SFT and two RL stages in order, once each.

The counts are in the setup table.

5The R1 rule rewards in a few lines

These checks are the whole R1-Zero reward: two string checks.

The language check is added in R1’s reasoning RL.

Real checkers normalize answers (fractions, spacing) and match nested braces before comparing; boxed below counts braces so \boxed{\frac{1}{2}} is read whole.

The code below is the checks the R1 recipe uses: the format check on think tags, the accuracy check on the boxed answer, and the language check on the reasoning, which arrives in reasoning RL.

import re
def format_reward(text):                                  # [1] line 2 of the rule reward card
    return float(re.search(r"<think>.+?</think>", text, re.S) is not None)
def boxed(text):                                          # brace-counting reader
    i = text.find("\\boxed{")
    if i < 0: return None
    i, depth, out = i + 7, 1, []
    while i < len(text) and depth:
        depth += {"{": 1, "}": -1}.get(text[i], 0)
        if depth: out.append(text[i])
        i += 1
    return "".join(out) if depth == 0 else None
def accuracy_reward(text, known):                         # [2] line 1 of the rule reward card
    a = boxed(text)
    return float(a is not None and a.strip() == known.strip())
def language_reward(cot_words, is_target_lang):           # [3] line 1 of the language reward card
    return sum(map(is_target_lang, cot_words)) / max(len(cot_words), 1)
def r1_zero_reward(text, known):                          # [4] line 3 of the rule reward card, feeds GRPO
    return accuracy_reward(text, known) + format_reward(text)

8When rule rewards are enough

  • Checkable answers (math, code with tests, logic).
  • A strong base model.
  • For small models, fine-tune on a large reasoner's answers, answers like the long answer, instead of running RL on them.

9Where checkable rewards fall short

Reward hacking is when the policy finds replies that score high without being good (RL Basics).

Dr. GRPO is a corrected GRPO that changes how long answers are weighted (Group Relative Policy Optimization (GRPO)).

A mixture-of-experts model routes each token through a few of many sub-networks.

The paper’s early RL tries on smaller models gave no meaningful gains.

A few-shot prompt places a few worked examples in the prompt, and a zero-shot prompt places none.

The paper found that few-shot prompts made R1 worse, and it advises zero-shot prompts that state the format.

The paper also tried reward models that score each step (Group Relative Policy Optimization (GRPO)) and Monte Carlo tree search, which searches over many partial answers, and set both aside.

Program checks stayed the core of the recipe.

10Rule rewards in context

A rule reward works wherever an answer can be checked by a program, a math answer against the known one or code against its test cases.

The long answer’s lesson generalizes: the GRPO update plus program checks is the method that grows it.

RLHF trains a language model in three stages: supervised fine-tuning first, on replies people wrote, then people's rankings train a learned reward model, and then the language model is trained against the scores that reward model assigns to its answers. GRPO does the reinforcement learning step in DeepSeek-R1, scoring each answer against the other answers in its group, and DeepSeek-R1 uses a program instead of a reward model wherever the answer can be checked, while keeping helpfulness and safety reward models for general prompts.

See Aligning Language Models with RL for the newer methods, including DeepSeek-R1-Zero, and RL Basics for the loop itself.
