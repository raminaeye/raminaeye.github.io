1 Training with rounding on

When PTQ costs too much accuracy, QAT fine-tunes with the rounding switched on, so training learns around it; training with simulated quantization comes from Jacob et al. (2018). A FakeQuantize module rounds and reads back in float during training, so the model feels the rounding while the weights stay float. Each FakeQuantize lets a gradient pass through the rounding, by the straight-through estimator in section 3, which passes the gradient straight through the rounding.

QAT acts on every forward pass of every training step, carries float weights plus moving observer ranges between steps, and ends with a convert to real int8 layers.

The PTQ rows recap the PTQ page; this page teaches only the QAT row.

2 Fake quantization in the training loop

The first listing copies the trained float model in train mode and lets qfx.prepare_qat_fx insert a FakeQuantize wherever the QAT qconfig mapping, the per-tensor choice of observer and grid, as on the PTQ page, asks for one; the second trains as usual with cross-entropy, switches to eval mode and converts. Each FakeQuantize runs the round trip from Quantize one tensor in every forward pass.

import copy, torch
import torch.ao.quantization as tq
import torch.ao.quantization.quantize_fx as qfx

qat_qmap = tq.get_default_qat_qconfig_mapping("x86")
example = (torch.randn(1, 1, 28, 28),)
model = copy.deepcopy(model_fp32)
model.train()
qat_model = qfx.prepare_qat_fx(model, qat_qmap, example)
  1. 1The default QAT mapping for x86 and an example input for tracing.
  2. 2A train-mode copy with fake-quantize modules inserted.
import torch.nn.functional as F

for x, y in train_loader:
    logits = qat_model(x)
    loss = F.cross_entropy(logits, y)
    optimizer.zero_grad()
    loss.backward()
    optimizer.step()
qat_model.eval()
model_int8 = qfx.convert_fx(qat_model)
  1. 1The training loop is ordinary; only the forward pass runs through fake quantization.
  2. 2After training, convert to int8 kernels.

QAT can learn activation clipping, push small weights out of dead zones (the band around zero that all rounds to zero), and learn quantization-friendly distributions.

3 The straight-through estimator

Rounding and clamping (clamping holds a value inside the grid's ends) have no useful gradient, so QAT uses a Straight-Through Estimator (STE): in the backward pass it pretends the rounding output equals its input. The RoundSTE listing below rounds only: it has no clamp, so unlike the FakeQuantize clamp it passes a gradient through for a weight past the grid end.

import torch
from torch.autograd import Function

class RoundSTE(Function):
    @staticmethod
    def forward(ctx, x):
        return torch.round(x)

    @staticmethod
    def backward(ctx, grad):
        return grad  # straight through
  1. 1Forward: real rounding.
  2. 2Backward: pass the gradient through unchanged (the straight-through estimator).

MobileNet is the small, already-efficient model where plain post-training quantization is the risky case, so training with rounding on is what the paper's simulated-quantization training is for: on ImageNet classification in the paper's section 4.2.1 and COCO detection in 4.2.2, on popular CPUs, quantized MobileNets stay close to float on the latency-vs-accuracy tradeoff.

The forward pass uses the rounded weight; the backward pass treats the rounding as if it were not there.
\(\displaystyle q = \operatorname{clamp}(\operatorname{round}\left(\frac{\htmlStyle{color:#2471a3}{w}}{\htmlStyle{color:#2471a3}{s}}\right), -k, k)\)
The float weight \(w\) is divided by the grid step \(s\), rounded to the nearest whole number and clamped to the codes \(-k \text{ to } k\). The result \(q\) is the integer grid index, the whole-number code the weight is stored as. Here \(k = 2^{b-1} - 1\) is the largest code that \(b\) bits hold on a grid symmetric around zero. The equivalent form on the symmetric grid: the paper clamps the value before rounding, this card clamps the rounded code, and both give the same grid.
\(\displaystyle \htmlStyle{color:#a04000}{\hat{w}} = \htmlStyle{color:#2471a3}{s}\cdot q\)
Multiplying the code \(q\) back by the grid step \(s\) gives \(\hat{w}\), the value quantized inference will use, and the layer computes with it. It is the round trip from Post-Training Quantization on the symmetric weight grid, where the zero point is 0. \(\hat{w}\) is the fake-quantized weight.
\(\displaystyle \frac{\partial L}{\partial \htmlStyle{color:#2471a3}{w}} = \frac{\partial L}{\partial \htmlStyle{color:#a04000}{\hat{w}}}\)
Round has zero slope almost everywhere, so the straight-through estimator copies the gradient of the loss \(L\) at \(\hat{w}\) onto \(w\) unchanged, and the optimizer moves the float weight. A weight already past the grid's end gets no gradient, because the clamp holds its \(\hat{w}\) at \(\pm k \cdot s\) however it moves.

A float weight can move for many steps without changing its rounded value, like an input sliding along one flat step of the staircase in Figure 2. Once it crosses a bin edge, the rounded weight jumps a whole level and the loss sees the change. Zero QAT steps is plain PTQ: round the trained weights once and ship them.

4 Watching QAT win accuracy back

To see PTQ and QAT, take handwritten 5s and 8s, 60 of each from the UCI digits set (Alpaydin and Kaynak, 1998), and squeeze each 8×8 image to two numbers with PCA, so each digit becomes a point on a flat map. A small MLP (a feed-forward network) with two hidden layers of 12 units using ReLU (zeroes negatives, passes positives), trained in float with a squared hinge loss, which penalizes every digit that is not safely on its correct side, gets all 120 right. Its decision edge is the line on that map where it switches between calling a digit 5 and calling it 8. Accuracy here counts these same 120 digits, the ones the network trained on.

Rounding to \(b\) bits uses the card's grid in section 3, codes \(-k \text{ to } k\), so it has \(2^{b} - 1\) levels. Each output channel gets its own scale, taken from the float weights, and biases and activations stay in float. Each QAT step trains through the rounding with the same loss and Adam, the optimizer that moves the weights.

4.1 Freezing observers and BatchNorm statistics in QAT

Figure 3 shows the three phases training runs through: warm up, freeze, convert.

QAT starts from the trained FP32 model and fine-tunes it with a small learning rate, freezing the batch-norm statistics and then the observers partway through (static quantization tutorial).

Warm up first (Figure 3): observers learn the scale and zero point while the model trains, then freeze, and training continues on one fixed pattern of quantization noise.

Inside FakeQuantize the observer is usually a MovingAverageMinMaxObserver, which keeps an exponential moving average of the min and max seen in training. A loud batch early in training pushes the observer range wide while later batches are quiet, so the running range should move only a little toward each new batch. The paper, section 3.1, collects activation ranges by exponential moving average and delays activation quantization.

The moving-average observer's update, run once per training batch.
\(\displaystyle \htmlStyle{color:#2471a3}{m_{t}} = (1 - \htmlStyle{color:#8e44ad}{c})\cdot \htmlStyle{color:#2471a3}{m_{t-1}} + \htmlStyle{color:#8e44ad}{c}\cdot \htmlStyle{color:#a04000}{b_{t}}\)
\(m_{t}\) is the running min after batch \(t\). It keeps most of the previous value \(m_{t-1}\); \(c\) is the averaging constant that sets how far each new batch moves it, and \(b_{t}\) is the smallest activation in batch \(t\). The running max updates the same way.

Raising \(c\) makes the range follow the latest batches faster but jump with each noisy batch; lowering it smooths the range but reacts slowly, and \(c\) = 0 freezes it. PyTorch's MovingAverageMinMaxObserver defaults to \(c\) = 0.01 (its averaging_constant, observer source).

Block 1 below freezes BatchNorm statistics, but TinyCNN has no BatchNorm, so on it the block does nothing.

import torch.nn.functional as F
import torch.ao.quantization as tq
import torch.ao.nn.intrinsic.qat as nniqat

for epoch in range(num_epochs):
    if epoch == bn_freeze_epochs:
        # freeze BN running stats
        qat_model.apply(nniqat.freeze_bn_stats)
    if epoch == warmup_epochs:
        # freeze scale and zero point
        qat_model.apply(tq.disable_observer)
    for x, y in train_loader:
        out = qat_model(x)
        loss = F.cross_entropy(out, y)
        optimizer.zero_grad()
        loss.backward()
        optimizer.step()
  1. 1Freeze the batch-norm statistics in a model with fused Conv + BatchNorm. Each keeps its last running mean and variance, so the batch-norm scale folded into the conv weights stops moving.
  2. 2After the warm-up epochs, freeze every observer so scale and zero point stop moving.
  3. 3Training continues with fixed quantization grids.

QAT fits the digits, not the float edge, so where no digits sit the blue shade can stay away from the grey line, as it does at 2 bits. Most starts recover nearly all the accuracy at 3 bits, and a few stay stuck at 2 bits. Drag the sliders and watch the blue edge.

The same trade shows up at scale. Google’s Gemma 3 QAT checkpoints (April 2025) trained against the float model’s own outputs, and afterwards 4-bit rounding raised perplexity far less than it did without QAT. Perplexity measures how surprised a language model is by real text, so lower is better. Meta’s quantized Llama 3.2 1B and 3B models (October 2024) used QAT with LoRA adapters for 4-bit weights. A LoRA adapter is a small pair of trainable matrices added beside a frozen weight matrix, so only a few numbers train. PTQ is cheaper and usually enough at 8 bits; QAT pays off as the bits fall.

5 QAT in practice

  • Every FakeQuantize quantizes and reads back on every forward pass, so each training step is slower than float training.
  • The torchao migration note lives in full on the Post-Training Quantization page; the same successors apply here.
  • Weight ranges differ hugely across output channels, by over a hundredfold, and outliers make every other weight less precise, so PTQ accuracy falls off a cliff (the paper, section 3). QAT moves weights into quantization-friendly ranges, or per-channel scales.
  • Freezing too early: locking the observers before the ranges settle fits the grid to early-training activations that clip later ones. Warm up with observers updating, then freeze (Figure 3).
  • Freezing too late or never: ranges that keep moving make training chase a moving grid. Freeze observers after warm-up and train on one fixed quantization pattern.
  • Weight stuck past the grid end: the FakeQuantize clamp holds it fixed, so it gets no gradient. It needs a large move to re-enter the grid, or a wider range. The toy RoundSTE listing rounds only and has no clamp.
  • Activation quantization switched on too early: ranges estimated before the network is stable exclude many values. Delay activation quantization until training stabilises (the paper, section 3.1); weight quantization runs from the start.

Start QAT from the trained float model with a small learning rate, on the PyTorch tutorial schedule as a starting point. Check the observers’ recorded ranges with Debugging a Quantized Model before converting.

The PyTorch quantization docs tie each path to a different bottleneck (Figure 6).

If accuracy still dropped, which layer lost it? Debugging a Quantized Model traces it layer by layer. Pruning and Knowledge Distillation shrink a model in other ways.
