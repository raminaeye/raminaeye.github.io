Comparing Multitask Learning Methods

Twenty real runs on one landscape: what each method actually does.

On this page

Different questions The scoreboard Where they land Teammates, not rivals

Different methods, different questions

Stepping back, the methods are answering different questions. GradNorm asks "how loud should each task be?" Uncertainty weighting asks the same question but answers it from the data's noise. PCGrad asks "is my step hurting you?" CAGrad asks "how do I help the worst-off task without losing sight of the goal?"

The scoreboard

The full comparison, seven methods across five columns. The "what it edits" column is the real split in the field: some methods only ever touch the loss weights, others only ever reshape the update direction.

Method What it edits Key idea Knobs Guarantee Extra cost / best for
Equal weights n/a Sum the losses and hope none none None. Baseline; fine when tasks are similar in scale, speed, and direction.
Uncertainty loss weights Weight each task by learned homoscedastic uncertainty init σi probabilistic motivation Low. A principled reweighting alternative to GradNorm.
GradNorm loss weights Equalize gradient norms; boost tasks training slowly α, λw none (heuristic) ~5-25%. Scale/speed imbalance, e.g. dense vision tasks.
MGDA update direction Minimum-norm blend of task gradients none converges to some Pareto-stationary point K backward passes + small solve. Theory-minded baselines.
PCGrad update direction Project out the mutually conflicting components none local improvement under the "tragic triad"; arbitrary Pareto point K backward passes. Conflict-heavy problems, multi-task RL.
GradVac update direction Pull each pair's cosine up to its own running target, not a blanket zero β, task subset, granularity none (heuristic) K backward passes. Many unequally-related tasks, e.g. multilingual models.
CAGrad update direction Maximize worst-task improvement within a ball around g0 c ∈ [0,1) converges to a stationary point of L0 (for c < 1) K backward passes + tiny solve. When consistency and the objective matter.

MGDA's paper: Ozan Sener, Vladlen Koltun, Multi-Task Learning as Multi-Objective Optimization. NeurIPS 2018. arXiv:1810.04650

Where they land on the toy

On the toy landscape from the CAGrad page, plotting only where each 20,000-step run ends: GD has three runs stall far above the Pareto set, oscillating, while two reach it. MGDA gets all five into the low-loss region but lands scattered along it: every landing spot is a valid trade-off, yet the initialization does the choosing. PCGrad reaches it on four of five. CAGrad lands two of five exactly on the star, and the rest are still descending when the steps run out (give it the paper's 100,000 steps and all five arrive). As c varies: c = 0 inherits GD's stalled runs, c = 10 inherits MGDA's spread.

Reading the tool below: each point is one run's landing in loss space. The horizontal axis is the final task-1 loss L1, the vertical axis is the final task-2 loss L2. The average loss L0 I keep quoting is their mean: $L_0 = \frac{L_1 + L_2}{2}$. At the star both task losses read -15.0916, so the walk is: L0 = (-15.0916 + -15.0916) / 2 = -30.1832 / 2 = -15.0916. That -15.09 is the floor of this toy: no run can land below the gray curve, because the curve is exactly the set of trade-offs where neither task can improve without hurting the other. The conflict fraction shown on hover is the share of the 20,000 steps where the two task gradients pulled in opposite directions, that is, where their dot product was negative.

Pareto front ★best point (star), L0 ≈ -15.09 GD MGDA PCGrad CAGrad c = 0.5

All four methods ran the same 20,000 Adam steps (learning rate 2e-3) from the same five starts on the paper's §5.1 toy. The paper itself runs 100,000 steps at 1e-3 with a minimum average loss of -15.09. CAGrad at c = 0.5 uses the reference repo's 1/(1+c) rescale, a toy.py convention, not part of the published Algorithm 1.

Teammates, not rivals

Reweighting fixes how loud the tasks are. Surgery fixes the direction they pull. Nothing stops me from doing both: feeding GradNorm's weights into PCGrad's cuts is a common combination, and GradVac gives the pairing a principled form. Zooming out one more level, all of these are multitask optimization methods. They change how the model is trained, not what the model is. Changing the model itself (cross-stitch networks, MTAN) is a separate toolbox.

Comparison done. So which one do I reach for on Monday? That is the field guide's job, and it is next.
