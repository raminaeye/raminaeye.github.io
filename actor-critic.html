  • The policy network looks at the screen and gives one chance per move, \(\pi_\theta(a\mid s)\); learning pushes each move by its credit (REINFORCE and the Baseline).
  • The value network \(V_\phi(s)\) guesses the usual result from a screen; the advantage estimate \(\hat A_t\) is the return minus that guess (REINFORCE and the Baseline).
  • The return is all the reward still to come, each later reward counted a little less by the discount \(\gamma\) (RL Basics).
  • Q-learning’s target puts its own guess for the next state inside it; its TD error is the target minus the current guess (Q-Learning).

Learning from whole games makes each move wait until the game ends to be judged, and then the judgement is noisy.

1 The same Pong paddle

The running example is Atari Pong, as on REINFORCE and the Baseline. The state is the screen, a stack of the last few frames. The moves are up, stay and down; one move is one step. The reward is \(+1\) for a point won, \(-1\) for a point lost, \(0\) on every other step. \(J\), the average points per game, is what learning tries to raise.

2 A critic that judges moves early

In Pong, the screen right after a good return shows the ball heading away, long before the point ends, so a network reading it can judge the move at once.

A critic is a second network that guesses each state’s value, the return expected from it. It is the value network \(V_\phi\) of REINFORCE. The actor is the policy network that picks the moves, and the critic’s guesses score how good they were. Methods built from these two networks are called actor-critic methods (Konda and Tsitsiklis, 2003).

3 One step’s surprise

A move can be scored right after it is made.

The target is the reward after the move plus the critic’s guess of the next screen, counted a little less by \(\gamma\). Putting your own guess for the next state inside the target is called bootstrapping; Q-learning’s target does the same (Q-Learning).

The TD (temporal difference) error \(\delta\) is how much one step surprised the agent: the target minus the current guess. A positive surprise means the move did better than the critic expected, so the actor makes it more likely; a negative one makes it less likely.

\(\displaystyle \begin{aligned}\htmlClass{eqt}{\htmlStyle{color:#6c3483}{\delta_t}} &= \htmlClass{eqt}{\htmlStyle{color:#7d6608}{r_{t+1}}} + \htmlClass{eqt}{\htmlStyle{color:#2c3e50}{\gamma}}\, \htmlClass{eqt}{\htmlStyle{color:#a04000}{V_\phi(s_{t+1})}}\\&\quad - \htmlClass{eqt}{\htmlStyle{color:#a04000}{V_\phi(s_t)}}\end{aligned}\)
The one-step surprise of the move at step \(t\): the reward right after it plus how good the next screen looks, minus how good this screen looked. \(r_{t+1}\) is the reward that follows the move, zero on most Pong steps. \(V_\phi\) is the critic. At the last step of a game there is no next screen, so its guess counts as zero.

\(\delta_t\) can serve as the move’s advantage estimate \(\hat A_t\): one step’s sample of how good the move was, minus the guess of this screen.

A push is biased when, averaged over many games, it points away from the direction that raises \(J\) fastest. The critic’s guess stands in for all the points still to come, so when it is wrong the push trusts a guess that is off the same way every time.

4 Two losses, one for each network

The same surprise teaches both networks: the actor takes it as the credit for the move, the critic as the size of its own mistake.

\(\displaystyle \begin{aligned}&\mathcal{L}_{\text{actor}}(\theta)\\&\;= -\sum_{t} \log \htmlClass{eqt}{\htmlStyle{color:#1f4e9c}{\pi_\theta}}(a_t\mid s_t)\; \htmlClass{eqt}{\htmlStyle{color:#196f3d}{\hat{A}_t}}\end{aligned}\)
The actor loss: the REINFORCE loss, the log chance of the move times its advantage, added over every step in the stretch, so a move that did better than expected is pushed up and one that did worse is pushed down. For now \(\hat A_t\) is the surprise \(\delta_t\); Section 5 and Section 6 build better ones. It is held fixed, so only \(\theta\) changes through this line.
\(\displaystyle \htmlClass{eqt}{\htmlStyle{color:#196f3d}{\hat{R}_t}} = \htmlClass{eqt}{\htmlStyle{color:#196f3d}{\hat{A}_t}} + \htmlClass{eqt}{\htmlStyle{color:#a04000}{V_\phi(s_t)}}\)
The critic’s target for screen \(s_t\): its own guess corrected by the one-step surprise. With \(\hat A_t=\delta_t\) it is the reward plus the discounted guess of the next screen.
\(\displaystyle \begin{aligned}&\mathcal{L}_{\text{critic}}(\phi)\\&\;= \sum_{t} \big(\htmlClass{eqt}{\htmlStyle{color:#196f3d}{\hat{R}_t}} - \htmlClass{eqt}{\htmlStyle{color:#a04000}{V_\phi(s_t)}}\big)^2\end{aligned}\)
The critic loss: the squared gap between the target and the guess, added over every step in the stretch, as in regression. The target is held fixed, so the guess moves toward its target. Only \(\phi\) changes through this line.

Entropy \(\mathcal{H}\) is how undecided the policy is; the entropy bonus rewards staying undecided, so the paddle keeps trying moves it rarely picks (REINFORCE and the Baseline). The whole set of move chances on a screen \(s\) is written \(\pi_\theta(\cdot\mid s)\). One loss holds all three parts, so one optimiser step trains both networks.

\(\displaystyle \begin{aligned}&\mathcal{L}=\mathcal{L}_{\text{actor}}+c_V\,\mathcal{L}_{\text{critic}}\\&\quad-c_H\sum_{t}\htmlClass{eqt}{\htmlStyle{color:#0e6d80}{\mathcal{H}}}\big(\htmlClass{eqt}{\htmlStyle{color:#1f4e9c}{\pi_\theta}}(\cdot\mid s_t)\big)\end{aligned}\)
The actor loss, the critic loss and the entropy bonus in one sum, with the entropy bonus added over every step in the stretch. \(c_V\) is the critic-loss weight: raising it makes the critic learn faster but can crowd out the actor, lowering it leaves the critic behind. \(c_H\) is the entropy weight: raising it keeps the paddle undecided longer, lowering it lets it commit sooner.

5 Trusting a few real steps first

One step leans on the critic, so a wrong critic gives a wrong push. The return of REINFORCE leans on nothing but real rewards, so it has no bias from the critic, but is noisy. In between, count a few real rewards and only then trust the critic: that count is its lookahead, \(n\) steps long.

\(\displaystyle \begin{aligned}\htmlClass{eqt}{\htmlStyle{color:#196f3d}{\hat{A}^{(n)}_t}}&=\sum_{k=0}^{n-1}\htmlClass{eqt}{\htmlStyle{color:#2c3e50}{\gamma}}^{k}\,\htmlClass{eqt}{\htmlStyle{color:#7d6608}{r_{t+k+1}}}\\&\quad+\htmlClass{eqt}{\htmlStyle{color:#2c3e50}{\gamma}}^{n}\,\htmlClass{eqt}{\htmlStyle{color:#a04000}{V_\phi(s_{t+n})}}\\&\quad-\htmlClass{eqt}{\htmlStyle{color:#a04000}{V_\phi(s_t)}}\end{aligned}\)
The \(n\)-step advantage estimate: the \(n\) real rewards after the move, each counted a little less, then the critic’s guess of the screen \(n\) steps ahead, minus its guess of this screen. With \(n=1\) it is the surprise \(\delta_t\). With \(n\) reaching the end of the game it is the return minus the guess, the advantage estimate of REINFORCE.

A longer lookahead has less bias but adds up more random rewards, so it is noisier.

6 Blending every lookahead with one knob

GAE (generalized advantage estimation; Schulman and colleagues, 2016) blends short and long lookaheads into one advantage estimate \(\hat A_t\). \(\lambda\) (lambda) sets how slowly the long lookaheads fade.

Add the surprises of a few steps. Each screen’s guess in between is added once and taken away once at the same weight, so it cancels, leaving the real rewards and the guess at the far end.

\(\displaystyle \htmlClass{eqt}{\htmlStyle{color:#196f3d}{\hat{A}_t}}=\sum_{l=0}^{\infty}(\htmlClass{eqt}{\htmlStyle{color:#2c3e50}{\gamma}}\htmlClass{eqt}{\htmlStyle{color:#2c3e50}{\lambda}})^{l}\,\htmlClass{eqt}{\htmlStyle{color:#6c3483}{\delta_{t+l}}}\)
GAE adds the surprise of every step ahead, the one \(l\) steps on weighted by \(\gamma\lambda\) once for each step. The sum stops at the end of the game, where the surprises stop. With \(\lambda=0\) only \(\delta_t\) is left; with \(\lambda=1\) the guesses all cancel and it is the return minus the guess.

Low \(\lambda\) trusts the critic soon, so the push is steady but biased when the critic is wrong. High \(\lambda\) trusts the real rewards, so the bias fades but the push spreads more. The spread is how much the push changes from one stretch of play to the next.

7 Many games at once

One game at a time gives long runs of very similar screens, so a few updates in a row all pull the same way (Deep Q-Networks (DQN)). Policy gradients are on-policy: they learn about the same policy that is playing, counting each move as often as the current policy plays it. Old play holds too many moves the old policy liked, so averaging over it pushes by the wrong amounts, and the replay memory of DQN is ruled out (Deep Q-Networks (DQN)).

Instead, many copies of the game run side by side, each played by a worker with the current network, so one update sees varied screens.

A3C is asynchronous advantage actor-critic (Mnih and colleagues, 2016): workers update the shared network as soon as each is ready. A2C is advantage actor-critic, the synchronous version: all workers wait, then update as one batch.

In A3C each worker plays a few steps, works out its own update and applies it, without waiting for the others. A worker’s update may then be applied to weights the other workers have already changed.

A2C waits for every worker and joins their steps into one batch, the group of steps an update learns from, then makes one update, so every worker plays the next steps with the same new weights. It was made popular by OpenAI Baselines, a set of reference implementations, and it is the one the code in Section 9 builds.

9 Actor-Critic in PyTorch

A toy A2C for Pong, to read rather than run; Pong has six buttons and we keep the three that move the paddle. The code uses gymnasium, the library that runs the games, and ale_py, the Atari game set it loads.

import gymnasium as gym, ale_py
import torch
from torch import nn
from torch.distributions import Categorical

gym.register_envs(ale_py)
MOVES = [2, 0, 3]   # Atari action numbers: 2 moves the paddle up, 0 stays, 3 moves it down
n_envs, n_steps, gamma, lam, c_v, c_h = N_ENVS, N_STEPS, DISCOUNT, LAMBDA, C_VALUE, C_ENTROPY

def make_pong():
    env = gym.make("ALE/Pong-v5", frameskip=1)   # the emulator itself skips no frames
    env = gym.wrappers.AtariPreprocessing(env, frame_skip=4)   # each chosen move repeats for 4 frames
    return gym.wrappers.FrameStackObservation(env, 4)
envs = gym.vector.SyncVectorEnv([make_pong] * n_envs,
    autoreset_mode=gym.vector.AutoresetMode.SAME_STEP)

class ActorCritic(nn.Module):
    def __init__(self):
        super().__init__()
        self.body = nn.Sequential(
            nn.Conv2d(FRAMES, C1, 8, stride=4), nn.ReLU(),
            nn.Conv2d(C1, C2, 4, stride=2), nn.ReLU(),
            nn.Flatten(), nn.Linear(FLAT, HIDDEN), nn.ReLU())
        self.policy_head = nn.Linear(HIDDEN, N_MOVES)   # actor: up, stay, down
        self.value_head = nn.Linear(HIDDEN, 1)    # critic: V_phi(s)
    def forward(self, x):
        h = self.body(x)
        return self.policy_head(h), self.value_head(h).squeeze(-1)   # squeeze drops the extra size-one axis, so each screen gets one guess

def compute_gae(rewards, values, dones, gamma, lam):
    # dones[t] = 1 if the game ended right after move t
    # values has one extra entry: the guess of the screen after the last move
    adv, gae = torch.zeros_like(rewards), 0.0
    for t in reversed(range(len(rewards))):
        delta = rewards[t] + gamma * values[t + 1] * (1 - dones[t]) - values[t]
        gae = delta + gamma * lam * (1 - dones[t]) * gae
        adv[t] = gae
    return adv

net = ActorCritic()
opt = torch.optim.RMSprop(net.parameters(), lr=LEARNING_RATE, eps=EPS_FLOOR)   # eps is a tiny floor that keeps the update from dividing by zero
obs, info = envs.reset()
while True:
    R, D, logps, Vs, ents = [], [], [], [], []
    for _ in range(n_steps):                          # every game plays a few steps
        x = torch.as_tensor(obs, dtype=torch.float32) / 255
        logits, v = net(x)
        dist = Categorical(logits=logits)   # turns the raw outputs into the move chances
        a = dist.sample()
        obs, r, term, trunc, info = envs.step([MOVES[i] for i in a.tolist()])
        logps.append(dist.log_prob(a)); Vs.append(v); ents.append(dist.entropy())
        R.append(torch.as_tensor(r, dtype=torch.float32))   # r_{t+1}: the reward after move t
        D.append(torch.as_tensor(term | trunc, dtype=torch.float32))
    with torch.no_grad():
        _, v_last = net(torch.as_tensor(obs, dtype=torch.float32) / 255)
    V = torch.stack(Vs)
    values = torch.cat([V.detach(), v_last.unsqueeze(0)])
    adv = compute_gae(torch.stack(R), values, torch.stack(D), gamma, lam)
    returns = adv + V.detach()
    actor_loss = -(torch.stack(logps) * adv.detach()).mean()
    critic_loss = (returns.detach() - V).pow(2).mean()
    loss = actor_loss + c_v * critic_loss - c_h * torch.stack(ents).mean()
    opt.zero_grad(); loss.backward()
    nn.utils.clip_grad_norm_(net.parameters(), GRAD_CAP)
    opt.step()
  1. 1Copies of Pong in one batch, each played by the same network; a finished game restarts within the same step, so every step is a real move.
  2. 2One shared body with two outputs: the actor’s raw outputs, called logits, for the three moves, and the critic’s guess \(V_\phi(s)\).
  3. 3GAE, added up backward: each step’s surprise delta, then the blend; (1 - dones[t]) drops the next guess when the game ended.
  4. 4The stretch of play: the network and its RMSProp optimizer (Adaptive Optimizers: AdaGrad, RMSProp and Adam) are built first, then each game plays a few steps and the moves, rewards and guesses are collected for the two losses.
  5. 5The two losses: returns is \(\hat R_t\), and detach() holds \(\hat A_t\) and \(\hat R_t\) fixed. The code averages over steps where the equations sum; only the step size changes.
  6. 6The whole loss, then one step with the optimizer built in code section 4; clip_grad_norm_ caps the size of the gradient (Backpropagation and Gradient Checking).

10 How λ trades bias for spread

At each numbered spot the paddle chooses between two moves: the helpful move, which sends it back well, and the other, which sends it back badly. The critic has the two moves backwards: after the helpful move it guesses too low, after the other too high. The true value is what the critic would guess knowing the points still to come exactly. The true push is the push with no bias from the critic.

11 Actor-Critic in practice

The learning rate \(\eta\), the lr in the code, sets how big a step each update takes (Q-Learning).

One update runs the network forward over one batch of steps, then one backward pass; the memory it holds grows with that batch.

14 Using each stretch of play once

Each stretch of play feeds a single update and is then thrown away, so could the same batch be reused without the pushes going wrong? Proximal Policy Optimization (PPO) sets out to answer that.
