1 WordPiece merges pairs that belong together

WordPiece grows a vocabulary bottom up, like BPE: start from single characters and add one merged piece at a time. The difference is which pair it merges. BPE takes the most frequent pair, so it favours pairs of very common pieces even when they only happen to sit side by side. WordPiece takes the pair whose parts belong together: pairs that appear together far more often than their parts would meet by chance.

Schuster and Nakajima (2012) built WordPiece for Japanese and Korean voice search; Google’s translation system (Wu et al., 2016) and BERT (Devlin et al., 2019) used it (References 1 to 3). Like BPE it trains once, before the model; splitting text runs on every call and keeps no state.

2 The score

The original WordPiece trainer adds the piece that raises the likelihood of the training text the most under a language model over the current pieces (References 1, 2). That gain grows both with how strongly a pair sticks together and with how often it occurs. Google never released this trainer. The score below is Hugging Face’s reconstruction, which keeps only the first part, how strongly the pair sticks together (Reference 4).

The pair count divided by the counts of both parts, then the same pick step as BPE.

\(\displaystyle \htmlClass{eqt sym-s}{\htmlStyle{color:#117864}{s(a,b)}} = \frac{\htmlClass{eqt sym-c}{\htmlStyle{color:#1f6aa5}{c(a,b)}}}{c(a)\,c(b)}\)
\(c(a,b)\) is the pair count from line 1 of the BPE card: how often piece \(a\) sits right before piece \(b\). \(c(a)\) and \(c(b)\) are how often each piece appears at all. Dividing by both asks whether the pair shows up together more than its parts’ own counts would predict, so a pair of very common pieces scores low even with a high count.
\(\displaystyle (a^{*},b^{*}) = \operatorname*{arg\,max}_{(a,b)} \htmlClass{eqt sym-s}{\htmlStyle{color:#117864}{s(a,b)}}\)
The same pick step as BPE, ranked by the score \(s\) instead of the count: merge the winning pair \(a^{*}\), \(b^{*}\) into one new piece, count again, repeat until the vocabulary has the target size.
\(\displaystyle \htmlClass{eqt sym-s}{\htmlStyle{color:#117864}{s(a,b)}} \propto \frac{P(ab)}{P(a)\,P(b)}\)
Read each count over the corpus as a probability: \(P(ab)\) for the pair, \(P(a)\) and \(P(b)\) for each piece. If the two pieces were independent, they would meet with probability \(P(a)\,P(b)\). So the score is how many times more often the pair appears together than chance predicts. It leaves out how often the pair occurs, which the original likelihood gain also counts.

3 The ## prefix and the vocabulary

BERT marks every piece that continues a word with ##; the first piece of a word carries no mark. So able at the start of a word and ##able in the middle are two different entries, and decoding drops the marks and joins. Google’s translation system marks the other side instead: a _ at the start of each word only (Reference 2).

4 How BERT splits text: longest match first

BERT does not replay the merges. Its reference tokenizer, and Hugging Face’s WordPiece model, use greedy longest match first: take the longest vocabulary entry that matches the start of the word, then the longest ## entry that matches the rest, and so on to the end. If at some point nothing matches, the whole word becomes the unknown token [UNK], not just the missing part (References 4, 6). The original WordPiece segmenter instead replayed its learned pairs, as BPE does (Reference 1). The tool runs the bert-base-uncased vocabulary on antidisestablishmentarianism.

6 WordPiece in practice

A trained WordPiece tokenizer ships as one file, BERT’s vocab.txt, one entry per line, and no merge list, because longest match only needs the entries. BERT’s tokenizer first lowercases (for uncased models), strips accents and splits on spaces and punctuation, then runs longest match on each word; a word longer than 200 characters becomes [UNK] without a search (max_input_chars_per_word, Reference 6). Longest match tries shorter and shorter prefixes, so a long word costs more lookups than a short one.

Code 1 is the score and BERT’s encoder in plain Python.

from collections import Counter

def wordpiece_scores(word_freqs):
    piece, pair = Counter(), Counter()
    for word, freq in word_freqs.items():
        units = [word[0]] + ["##" + ch for ch in word[1:]]
        for u in units:
            piece[u] += freq
        for a, b in zip(units, units[1:]):
            pair[a, b] += freq
    return {(a, b): n / (piece[a] * piece[b]) for (a, b), n in pair.items()}

scores = wordpiece_scores(Counter("decode decode encode encoder models".split()))
print(max(scores, key=scores.get))

def encode_longest_match(word, vocab, unk="[UNK]"):
    pieces, start = [], 0
    while start < len(word):
        end = len(word)
        while end > start:
            piece = word[start:end] if start == 0 else "##" + word[start:end]
            if piece in vocab:
                break
            end -= 1
        if end == start:
            return [unk]
        pieces.append(piece)
        start = end
    return pieces
  1. 1Line 1 of the card: count every piece and every adjacent pair over the ##-marked units, then divide.
  2. 2Line 2: the pair with the highest score is the next merge.
  3. 3The rule of Figure 3: shrink the candidate until it is in the vocabulary; if nothing matches, the whole word is [UNK].

Code 2 trains a BERT-style WordPiece vocabulary with Hugging Face tokenizers (Reference 5).

from tokenizers import Tokenizer, models, normalizers, pre_tokenizers, trainers, decoders

tokenizer = Tokenizer(models.WordPiece(unk_token="[UNK]"))
tokenizer.normalizer = normalizers.BertNormalizer(lowercase=True)
tokenizer.pre_tokenizer = pre_tokenizers.BertPreTokenizer()
trainer = trainers.WordPieceTrainer(
    vocab_size=30522,
    special_tokens=["[PAD]", "[UNK]", "[CLS]", "[SEP]", "[MASK]"],
    continuing_subword_prefix="##",
)
tokenizer.train(["corpus.txt"], trainer=trainer)
tokenizer.decoder = decoders.WordPiece(prefix="##")
  1. 1A WordPiece model with BERT’s cleanup: lowercase, strip accents, split on spaces and punctuation.
  2. 2The vocabulary size of bert-base-uncased, BERT’s special tokens and the ## mark.
  3. 3Train, then decode by dropping ## and joining.
