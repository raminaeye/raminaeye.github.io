Aligning Language Models with RL

RLHF, reinforcement learning from human feedback, turns people's rankings of answers into a reward and trains a language model to earn it.

Why RLHF

A large language model (LLM) is a neural network trained to predict the next token, a word or piece of a word, of web text. People want something else from it: to "follow the user's instructions helpfully and safely". Ouyang et al. 2022 call next-token prediction misaligned with that goal, and built InstructGPT by tuning OpenAI's pretrained GPT-3 model with RLHF. Alignment means acting the way the user intends.

Writing the ideal answer is slow; picking the better of two takes seconds. Copying written answers alone has limits (why copying an expert falls short, on the RL page), so RLHF also learns from people's rankings of the model's own attempts. The idea comes from Christiano et al. 2017, which trained Atari video game and simulated-robot agents from people picking the better of two short clips.

The language model as an agent

The figure maps each part of the reinforcement learning loop onto a language model writing an answer.

Each token is a move, but the score arrives once: one prompt, one response, one score, then the episode ends (Ouyang et al. 2022, Section 3.5). The toy code runs one episode.

state = prompt_tokens                  # the state: prompt plus tokens so far
for t in range(max_tokens):
    probs = policy(state)              # the policy: next-token probabilities
    token = torch.multinomial(probs, 1)  # the action: one sampled token
    state = torch.cat([state, token])
    if token == end_token: break       # the episode ends with the answer
score = reward_model(state)            # the reward model's one score, at the end

RLHF in three stages

Supervised fine-tuning (SFT) teaches by example, a reward model (RM) learns a score from people's rankings, and RL with PPO, proximal policy optimization (Schulman et al. 2017), raises that score.

Stage 1, supervised fine-tuning

The pretrained model is fine-tuned on answers written by hired labelers, with the usual next-token loss. Stage 3 starts from this SFT model and measures drift against it.

Stage 2, the reward model

Labelers rank 4 to 9 answers to one prompt, and every pair in the ranking becomes a training example. The reward model is a language model whose last layer outputs one number, and it learns to score the preferred answer of each pair higher.

The reward-model loss for one ranked pair, averaged over all pairs.
loss = −log sigmoid(r(x, yw) − r(x, yl))
r(x, yw) is the reward model's score for the answer people preferred (w for won) to prompt x, and r(x, yl) its score for the other answer (l for lost). The sigmoid turns their gap into a number between 0 and 1, the reward model's guess of the chance people prefer yw. The log and the minus sign turn a guess near 1 into a loss near 0, so the loss is small when the preferred answer scores clearly higher and large when the pair is backwards.
import torch, torch.nn.functional as F
# toy reward model: 16 numbers for one prompt plus answer -> one score
reward_model = torch.nn.Linear(16, 1)
chosen = torch.randn(8, 16)      # 8 pairs: the preferred answers
rejected = torch.randn(8, 16)    # the other answer of each pair
r_w = reward_model(chosen).squeeze(-1)     # r(x, y_w), shape (8,)
r_l = reward_model(rejected).squeeze(-1)   # r(x, y_l), shape (8,)
loss = -F.logsigmoid(r_w - r_l).mean()
loss.backward()

Stage 3, RL with PPO

The policy, a copy of the SFT model, answers a fresh prompt, the frozen reward model scores it, and PPO (an actor-critic method from Reinforcement Learning Methods) updates the policy to raise the score, with a penalty for drifting from the SFT model.

What stage 3 maximizes, averaged over prompts and the answers the policy samples for them.
objective = r(x, y) − β · log π(y | x)πSFT(y | x)
r(x, y) is the reward model's score for answer y to prompt x. π(y | x) is the chance the policy being trained writes that answer, and πSFT(y | x) the chance the frozen SFT model would. The log of their ratio, averaged over answers, is the KL divergence, a measure of how far the policy has drifted. β (beta), 0.02 by default in InstructGPT, sets how hard drift is penalized.
import torch
T = 12                          # tokens in one sampled answer
logp = torch.randn(T) - 2       # toy log pi(token | text so far), policy
logp_sft = torch.randn(T) - 2   # toy log pi_SFT(token | text so far)
score = torch.tensor(1.3)       # toy r(x, y) from the frozen reward model
beta = 0.02
reward = -beta * (logp - logp_sft)   # drift penalty at every token
reward[-1] += score                  # the score arrives once, at the end
objective = reward.sum()   # = score - beta * log(pi(y|x) / pi_SFT(y|x))

The drift term splits into one piece per token, which is the drift penalty in the reward row of the loop figure. PPO raises the objective in small steps: once a token's probability has moved more than a small band from its value before the update (20 percent in Schulman et al. 2017), the update stops being rewarded for pushing it further.

Reward over-optimization

On the Reinforcement Learning (RL) page my banana agent learns the loophole, not the job. A reward model is a learned scoreboard with loopholes too, and stage 3 hunts for them. Gao et al. 2022 measured this with a reward model standing in for people:

PartOver-optimization setup (Gao et al. 2022)
Stand-in for peoplea fixed 6B "gold" reward model, the one from InstructGPT
Proxy reward models (what training sees)3M to 3B parameters (M = million), trained on the gold model's preferences
Policy1.2B parameters, trained with PPO against one proxy, no drift (KL) penalty in the main runs
Measuredgold and proxy reward model scores as the policy drifts from its starting model, drift measured by KL divergence

The proxy reward model score kept rising. The gold score rose, peaked, then fell. Adding a drift (KL) penalty did not lift the gold curve: at the same amount of drift the gold score came out about the same, so the penalty acted like stopping training early, possibly sensitive to settings (Section 3.6). It helps you stop before the drop; it does not remove the drop.

proxy reward model score (what training sees)gold score (stand-in for people)

Training sees the top curve; people would feel the bottom one.

Newer alignment methods

Newer methods drop parts of the RLHF pipeline. DPO, direct preference optimization (Rafailov et al. 2023), trains the language model directly on a fixed set of preference pairs collected beforehand, with a simple classification loss, and samples nothing during training. GRPO, group relative policy optimization (Shao et al. 2024), is PPO with the limited update kept and the critic (the network that predicts how good an answer will be) dropped: it samples a group of answers to one question and judges each against the group average.

When an answer can be checked automatically, a rule replaces the reward model. DeepSeek-R1-Zero (DeepSeek-AI 2025, Section 2.2.2) used GRPO and checked a final math answer against the known one, ran code against set test cases, and required reasoning inside marked tags, with no learned reward model, because a learned one could be gamed.

On the Reinforcement Learning Methods map, PPO-based RLHF is actor-critic and on-policy, learning from answers the current policy just wrote, while DPO learns from pairs collected beforehand; Shao et al. 2024 (Section 5.2.1) sort these methods by the same split, data sampled online from the current policy or collected offline beforehand.
