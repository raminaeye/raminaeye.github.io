Regularization and Data Augmentation

The model overfits. Here is how you fight it.

The curves told you the model overfits: training error sinks, test error climbs. Now what? You fight overfitting two ways: constrain the model so it cannot memorize, or grow the data so there is less worth memorizing. This page is the full toolkit for both.

Fight overfitting two ways: constrain the model, grow the data

Regularization: Dropout

Dropout zeroes each activation with probability p on every forward pass (one run of an input through the network), so each pass trains a slightly different, thinned sub-network and no single neuron can be leaned on. The mask is a Bernoulli draw: a weighted coin flip per neuron that lands on "keep" with probability 1 − p.

Dropout in one line: mask the activation, then rescale the survivors.
ã = (m · a) · 11 − p
a is the activation before the mask, one number per neuron. m is the mask, 1 for a kept unit and 0 for a dropped one, and p is the dropout rate. Each · is a multiplication. The fraction scales the survivors up so the expected activation stays the same, and ã (a-tilde) is the result.

The same thing in PyTorch. At inference time, when the trained model runs on new data, we don't drop anything: the full network runs, and the training-time rescale already matches its scale.

import torch

p = 0.2
a = torch.randn(12)                                # one hidden layer: one number per neuron
m = torch.bernoulli(torch.full_like(a, 1 - p))     # 1 = keep, 0 = drop
a_tilde = m * a / (1 - p)                          # mask, then rescale the survivors

drop = torch.nn.Dropout(p)                         # the built-in layer
drop.train(); y_train = drop(a)                    # training: masks and rescales
drop.eval();  y_test = drop(a)                     # inference: y_test equals a

Dropout also acts like noise injection in the hidden layers: the noise forces the model to learn features that survive small disturbances. It's less common in CNNs (convolutional neural networks) and transformers (networks built on attention). Its relatives drop bigger or smaller pieces on each pass: DropPath switches off a whole branch route, Stochastic Depth skips whole layers (they rejoin at test time), and DropConnect zeroes single weights while the units stay on.

The tool below is a toy: twelve hidden units with fixed activations, and each draw is an independent random mask at the chosen rate.

A higher rate drops more units and scales the survivors up harder, so on average the total signal stays at the dashed no-dropout mark.

L1 vs. L2 Regularization

Because we want a model to generalize, we don't want it to overfit, so we regularize it. One way to do that is to discourage very large weights by adding a penalty to the loss.

L2 regularization adds the squared weights to the loss. The penalty grows quadratically, so the optimizer keeps the weights small and spread out instead of letting one dominate; its budget is a ball around the origin. L2 produces shrinkage: weights spread out but stay non-zero.

The L2 penalty: add the squared weights to the loss.
L ← L + λ·Σi wi2
The arrow replaces the loss L with itself plus the penalty. λ (lambda) is the penalty strength, Σi adds up over every weight i, and wi2 is one weight squared. A weight twice as large costs four times as much.

L1 regularization uses absolute values instead, and its budget is a diamond. It produces sparsity; the gradients below show why.

The L1 penalty: add the absolute weights to the loss.
L ← L + λ·Σi |wi|
λ, Σi and wi mean the same as in the L2 line. The bars mean absolute value, the weight's size with its sign dropped, so every weight costs its size, big or small.
The push each penalty puts on one weight: its gradient.
∂∂wi λwi2 = 2λwi
The stacked ∂ fraction is the slope of the penalty as wi changes. The L2 push is proportional to the weight, so it fades as the weight shrinks and the weight never quite reaches zero.
∂∂wi λ|wi| = λ·sign(wi)
sign(wi) is +1 for a positive weight and −1 for a negative one; the slope of |wi| is undefined at zero. The L1 push has the same size whatever the weight, so small weights get dragged all the way to zero, and the optimizer may stop there.

The answer inside a budget is the first point the loss contours (rings of equal loss) touch as they spread from the unpenalized best fit. A circle's curved edge is usually touched with both weights nonzero, so L2 shrinks but does not delete. A diamond's corners sit on the axes, so the touching point is usually a corner and one weight lands exactly on zero: sparsity you can read off the picture.

Same loss contours, different budget shape, different answer. Round budget, both weights survive. Pointy budget, one weight goes to zero.

Data Augmentation for Wearables

Regularization adjusts the model to cut the estimation error (how far the model's estimates land from the true values). What about the data? Beyond adding noise, scaling, and rotations, here are realistic ways to grow data from wearables.

  • Channel Dropout: Randomly drop sensors during training to mimic lost contact or misalignment, so the model stays robust across subsets of sensors.
  • Channel Shuffling: Permute sensors within a local neighborhood to mimic the band shifting along the arm.
  • Spatial Mixing: Replace a sensor with a weighted average of its same-type neighbors to simulate the displacement blur of a shifted band.
  • Rotation Augmentation: Apply a 3D rotation to mimic the band worn twisted or at a different angle. The band has three axes: x along the arm toward the hand, y sideways out of the wrist, z up out of the skin.
  • Twisting vs. sliding: Twisting the band around the arm keeps x and rotates y and z. Sliding leaves the band's axes alone; the sensors just capture slightly different signals. That's why we rotate the readings into what the band would see if it had been twisted.

Rotation augmentation: roll, pitch, and yaw

Rotation around x is roll (like turning a doorknob), around y is pitch (pointing the hand up or down), and around z is yaw (swinging the hand left and right).

The general rotation: one rotation per axis, multiplied together, applied to each sensor vector.
v′ = Rz(ψ) Ry(θ) Rx(φ) v
v is one sensor reading as a 3D vector in the band's x, y, z axes, and v′ (v-prime) is the rotated reading. Rx(φ) rotates by the roll angle φ (phi) around x, Ry(θ) by the pitch angle θ (theta) around y, and Rz(ψ) by the yaw angle ψ (psi) around z. The matrices apply right to left: roll first, yaw last.
from scipy.spatial.transform import Rotation

# acc: [time, 3] readings in the band's x, y, z axes; angles in degrees
rot = Rotation.from_euler('xyz', [roll, pitch, yaw], degrees=True)  # Rz @ Ry @ Rx
acc_rotated = rot.apply(acc)                                         # rotate every reading

Augmentations that mimic real sensor variation

  • Random Scaling: Multiply the signals by random factors to mimic changes in strap tightness or skin-electrode impedance (how much the skin-sensor contact holds back the tiny electrical signal; higher means weaker and noisier).
  • Temporal Jitter: Shift or stretch signals slightly in time to mimic the latency (delay) that altered placement introduces.
  • Cross-modal Masking: Temporarily drop one modality (one sensor type) so the model generalizes when only some signals are available.

Several of these are one line each on a window of samples:

import numpy as np

rng = np.random.default_rng()
# x: [channels, time], one window from the wearable
x = x * (rng.random(x.shape[0]) > p_drop)[:, None]          # channel dropout
i = rng.integers(x.shape[0] - 1)
x[[i, i + 1]] = x[[i + 1, i]]                                # channel shuffling: swap neighbors
x = x * rng.uniform(s_lo, s_hi, size=(x.shape[0], 1))        # random scaling per channel
x = np.roll(x, rng.integers(-max_shift, max_shift + 1), axis=1)  # temporal jitter: shift

Handling Class Imbalance

Class imbalance makes the model overfit to easy, frequent samples. You can oversample minority classes, undersample majority classes, or augment minority classes more. SMOTE (Synthetic Minority Over-sampling Technique) oversamples without duplicating: it uses k-NN (k-nearest neighbors, the classifier from the kNN page) to find a nearby minority sample and interpolates a new one on the line between them.

SMOTE: a new minority sample at a random point on the line to a neighbor.
xnew = xi + u · (xnn − xi)
xi is a minority sample, xnn one of its nearest minority neighbors, and u a random number between 0 and 1 that sets how far along the line the new sample xnew lands.

Loss-level techniques reweight instead. Class-weighted loss weights the minority class higher, and balanced batch sampling gives each batch (a group of examples processed together) roughly the same class representation:

import torch
from torch.utils.data import DataLoader, WeightedRandomSampler

counts = torch.bincount(y_train)                     # examples per class
class_w = counts.sum() / counts.float()              # rarer class, bigger weight
# use one or the other: both together correct the imbalance twice
weighted_ce = torch.nn.CrossEntropyLoss(weight=class_w)   # class-weighted loss
sampler = WeightedRandomSampler(class_w[y_train], num_samples=len(y_train))
loader = DataLoader(train_set, batch_size=batch_size, sampler=sampler)  # balanced batches

Focal loss focuses training on hard-to-classify examples by down-weighting the easy ones the model already classifies confidently, so they stop dominating the loss:

Focal loss: cross-entropy, scaled down for confident examples.
FL = −(1 − pt)γ log pt
pt is the probability the model gives the true class, and −log pt is the usual cross-entropy. γ (gamma) sets how hard easy examples are down-weighted: a confident example has pt near 1, so its factor (1 − pt)γ is near 0 and it barely counts.

Curriculum learning starts with balanced, easy examples and gradually adds hard or imbalanced ones, so the model learns the pattern before the hard cases arrive.

Clean the data before the model sees it

Regularization constrains the model. The other half of the fight is the data itself: wearable signals arrive noisy, drifting, and sometimes missing entirely. Clean it before the model sees it.

Preprocessing Sensory Data

Preprocessing comes first. Wearable signals pick up powerline interference (hum from the wiring around the sensor), baseline drift (the slow wandering of the zero level), and impedance problems where the sensor meets the skin. A little signal processing keeps the most information without the noise.

  • Band-pass filtering: Keeps one band of frequencies, dropping low-frequency drift and high-frequency noise.
  • Notch filtering: Cuts one narrow band, the powerline hum, and leaves the frequencies around it alone.
  • Rectification and enveloping: Take the absolute value, then low-pass it to trace how strong the signal is.
  • Z-scoring: Per channel, subtract the average and divide by the spread, to reduce amplitude differences across subjects and sessions.
import numpy as np
from scipy.signal import butter, iirnotch, filtfilt

# x: [channels, time], sampled at fs Hz
b, a = butter(4, [f_lo, f_hi], btype='bandpass', fs=fs)
x = filtfilt(b, a, x, axis=-1)                         # band-pass
b, a = iirnotch(f_line, Q, fs=fs)
x = filtfilt(b, a, x, axis=-1)                         # notch out the powerline hum
b, a = butter(4, f_env, btype='lowpass', fs=fs)
env = filtfilt(b, a, np.abs(x), axis=-1)               # rectify, then envelope
z = (env - env.mean(-1, keepdims=True)) / env.std(-1, keepdims=True)  # z-score per channel

You can also extract time, frequency, and time-frequency domain features (how the signal unfolds, which frequencies it holds, and how that frequency makeup changes over time), or let CNN and LSTM layers learn the features in the model (LSTM: long short-term memory, a recurrent layer that carries a gated memory across a sequence).

Handling Missing Data and Fusing Modalities

Bluetooth packet loss or sweat-raised impedance can leave missing signals: dropped or unreliable channels. Detect channels that have flatlined (gone dead flat) or saturated (pegged at the top of their range), and fill them from spatial or temporal neighbors. A wide range of augmentations also helps.

import numpy as np

# x: [channels, time]; x_max: the sensor's top value
flat = x.std(axis=1) < eps                         # flatlined channels
sat = (np.abs(x) >= x_max).mean(axis=1) > frac     # mostly pegged at the top
valid = ~(flat | sat)                               # binary mask of usable channels
for c in np.where(~valid)[0]:                       # fill from spatial neighbors
    nbrs = [n for n in (c - 1, c + 1) if 0 <= n < len(x) and valid[n]]
    if nbrs: x[c] = x[nbrs].mean(axis=0)

Feed the model that binary mask and it learns to ignore the missing channels. Attention, a learned score for how much each input counts, can weight the more reliable sensors, learned end-to-end (as one system from raw input to prediction).

You can combine modalities, so one can cover for another. Concatenating them into one encoder (the part that compresses a signal into features) assumes they align in time and scale. More commonly, separate encoders produce latent features (compressed representations) that are concatenated and fed to a joint decoder (the network that makes the final prediction).

With cross-modal attention instead, the model learns how much to trust each modality in context, and can line up modalities that react at different times. One sensor's features form the query (what to look for); the other's form the keys (what each offers) and values (the features passed along). A missing or noisy modality gets down-weighted.

import torch.nn as nn

attn = nn.MultiheadAttention(embed_dim=d, num_heads=n_heads, batch_first=True)
# feat_a: [batch, T_a, d] from encoder A; feat_b: [batch, T_b, d] from encoder B
fused, weights = attn(query=feat_a, key=feat_b, value=feat_b,
                      key_padding_mask=b_missing)   # True marks B steps to ignore

The mask handles a partly missing B. If every B step in a row is masked, that row can come out as NaN; one fix is to keep one always-valid token in B.

Separate encoders are more flexible, since each specializes in its own signal. Very late fusion, separate models per modality with their outputs fused, would not really solve the missing signal problem.

You can try foundation-style models: train once on a large cohort of users, then fine-tune (train a little more) on each new user's calibration set, a small labeled sample from that person. A shared encoder with lightweight subject-specific heads (small output layers, one per task or user) can be fine-tuned for new users.

Constrain the model, grow the data, clean the pipeline: the model can no longer just memorize. But the loss has to go down first, and choosing the size and direction of each training step so the walk descends steadily is the job of Optimizers.
