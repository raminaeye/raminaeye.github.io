Introduction to AI Agents

A language model that reasons, acts with tools, and learns from what comes back.

1 What an agent is

A chatbot answers a question and stops. An agent does not stop at the answer. It reads the task, thinks about what to do, does something in the world, reads what comes back, and thinks again. That loop is the whole idea of this section.

A language model is a model trained on text that writes the next words. A tool is a way for the model to act outside its own text: searching the web, doing arithmetic, running code, calling an API. What a tool sends back is called an observation. An agent is a language model running in a loop with tools, deciding for itself what to do next.

An agent runs at inference, once per task. Training taught it how to reason and when to call tools. The loop itself runs while it works, and the history so far is the state it carries from one turn to the next.

2 One step or many

Not every use of a language model is an agent. There are two shapes, and the difference is how many steps the task takes.

In the single step case the model gets one prompt, writes one reply, and gets one reward for it. Aligning a chatbot is this shape: the reply is the whole task. In the multi step case the model acts many times in a world that changes as it acts, and a world it only partly sees. Each move changes what happens next, so the model has to plan over turns, not just over words.

The agentic RL survey this section follows writes the decision down as one tuple with seven parts. In the single step case the horizon is one step, so there is nothing left to plan over. In the multi step case every part matters.

\(\displaystyle \langle \htmlClass{eqt}{\htmlStyle{color:#2471a3}{\mathcal{S}}}, \htmlClass{eqt}{\htmlStyle{color:#8e44ad}{\mathcal{O}}}, \htmlClass{eqt}{\htmlStyle{color:#a04000}{\mathcal{A}}}, \htmlClass{eqt}{\htmlStyle{color:#2c3e50}{\mathcal{P}}}, \htmlClass{eqt}{\htmlStyle{color:#7d6608}{\mathcal{R}}}, \htmlClass{eqt}{\htmlStyle{color:#0e6b59}{T}}, \htmlClass{eqt}{\htmlStyle{color:#c0392b}{\gamma}} \rangle\)
Seven parts name the whole decision. \(\mathcal{S}\) is the state space, everything that could be true about the world. \(\mathcal{O}\) is the observation space, what the agent can actually see of it. \(\mathcal{A}\) is the action space, every move it can make, including words and tool calls. \(\mathcal{P}\) is the transition function, how the world changes after a move. \(\mathcal{R}\) is the reward function, how good each outcome is. \(T\) is the horizon, how many steps the task runs. \(\gamma\) is the discount factor, how much a later reward still counts, as in RL Basics.

Six names from reinforcement learning will keep appearing in this section. Each is one sentence here, and each has its own page.

  • PPO keeps each policy update close to the policy before it, so training does not jump away from what already worked.
  • GRPO writes a group of answers to one question and rewards the ones that beat the group average.
  • RLHF trains a reward model from human preferences, then trains the policy against it.
  • RLAIF is the same setup, with AI judgements standing in for human ones.
  • Constitutional AI has the model critique and revise its own output against a written set of principles.
  • DPO skips the reward model and learns straight from pairs of preferred and rejected answers.

3 The families

Thirteen families, one loop each. Every family below runs the loop of Figure 1 and changes one part of it. Each row says what that family adds. Section 6 steps through the whole map, one family at a time.

  • Think, then answerChain of Thought: Thinking Before Answering

    Showing the steps before the answer lets the model work through a problem instead of guessing.

  • Think, then actReAct: Thinking and Acting in One Loop

    Thoughts stop the model guessing from memory and let facts steer the next move.

  • Teach itself toolsToolformer: A Model That Teaches Itself to Use Tools

    A tool call is kept only when its answer makes the next words easier to predict.

  • Route to expertsMRKL: Routing Requests to the Right Expert

    A wrong handoff sends the exact tool the wrong numbers.

  • Think longReasoning Models: Long Thinking Inside an Agent

    Rewarding only a correct final answer can still teach a model to pause and check itself.

  • Fix its own codeReTool: Teaching Code Tools with a Cold Start

    Seeing an error message can teach the model to fix its own code.

  • Learn tools by rewardToRL: Discovering Tool Use by Reward Alone

    A tool result that disagrees with hand reasoning is a signal, not noise.

  • Learn search by rewardSearch as a Tool Learned by Reward

    Masking retrieved words stops the model learning to write Wikipedia.

  • Code as tool languageTool Calls Written as Code

    Code lets later tool calls reuse earlier results as variables.

  • Fewer callsPaying for Fewer Tool Calls

    The same right answer is worth more when it costs fewer tool calls.

  • Judge the callJudging Tool Calls

    A good judge must spot one wrong argument in an otherwise perfect call.

  • One protocolWiring Tools with a Protocol

    One standard way to plug tools in beats a custom connector for every pair.

  • Pick the patternBuilding Agents That Work

    The shape of the task picks the pattern, not the other way round.

4 What the model has to learn

Six capabilities make an agent. Three are taught here, in brief. The other three point at the pages that teach them.

4.1 Planning

Planning is breaking a goal into steps and choosing the order to run them in. A plan is not a script: when a step fails, the agent re-plans from where it actually is instead of starting over.

4.2 Tool use

Tool use is knowing when a tool would help, which tool to call, what to pass it, and what to do with what comes back. The call itself is small: a name plus its arguments, and the result the tool returns.

Tool use is learned in three stages. First comes imitation: prompting, as in ReAct, and fine tuning, as in Toolformer, copy tool use from examples. Then comes tool-integrated RL: the model learns from the outcome, as in ReTool, ToRL and Search as a Tool Learned by Reward. The open frontier is long-horizon tool use over many turns, where it is still hard to say which call in a long chain deserves the credit.

4.3 Memory

Memory is what the agent keeps between turns. It is not a pile of notes the model dumps text into. It is a part of the agent the agent itself controls, deciding what to store, when to retrieve, and what to forget.

Memory has no page of its own in this section. It is taught here as a capability, and Building Agents That Work names it as an open direction.

4.4 Reasoning

Reasoning is thinking before acting, in words. DeepSeek-R1: Reasoning from Checkable Rewards showed that rewarding only a correct final answer can still teach a model to pause and check itself. The full story is in Reasoning Models: Long Thinking Inside an Agent.

4.5 Self-improvement

Self-improvement is learning from reward. RL Basics teaches learning from reward, and Group Relative Policy Optimization (GRPO) teaches learning from the group's own answers.

4.6 Perception

Perception is reading the world: images, screens, sounds. This section stays with text and tool results, so perception is out of scope here, stated plainly.

5 When not to build an agent

Start with the simplest thing that works. A single call answers a fixed question. A chain of calls answers one that splits into fixed steps. Build an agent only when the task needs the model to decide what happens next, because an agent trades latency and cost for performance on open-ended problems.

Anthropic's guide notes that the tooling landscape it describes has changed since December 2024, and points to Claude Managed Agents as the current approach. The full decision, with the patterns to pick from, is in Building Agents That Work.
