Image-Text Contrastive Learning (CLIP)

On this page

1 Web captions are the labels 2 Two encoders share one embedding space 3 The diagonal holds the true pairs 4 Zero-shot classification asks which caption fits 5 CLIP in practice 6 References

In Contrastive Learning, each view picks its positive, the other view of the same image, out of a batch with InfoNCE. CLIP (Contrastive Language-Image Pre-training, Radford et al. 2021) uses the same loss between a photo and its caption. It trains an image encoder and a text encoder so that, every training step, each photo in the batch picks its own caption and each caption its own photo, using captions people already wrote on the web. The two trained encoders then classify new photos by caption, with no extra training.

1 Web captions are the labels

The web already pairs photos with text, so asking which caption goes with which photo needs no annotator.

Asking only which whole caption fits a photo learned about 4 times more efficiently than predicting the caption's words as a bag (the words without their order), in the paper's Fig. 2.

2 Two encoders share one embedding space

The image encoder and the text encoder run separately, and their outputs meet only when they are compared.

Each encoder's output goes through a linear projection into one shared space and is scaled to length 1. Nothing crosses between the towers, unlike Cross-Attention, where one stream reads the other; that is what lets CLIP encode each caption once and reuse it. The Q-Former's image-text contrastive stage keeps its queries and text apart the same way.

3 The diagonal holds the true pairs

CLIP trains each photo to pick its own caption out of the batch, and each caption to pick its own photo. A batch holds N photos and their captions. Their scores form an N by N table, rows for photos and columns for captions. Unlike SimCLR's view-by-view table, whose diagonal is each view against itself, the true pairs here sit on the diagonal and the other N²−N pairings are wrong. Each row is Categorical Cross Entropy with the true caption as the class.

Score every photo against every caption, then make each row pick its true caption and each column its true photo; the loss averages both.
si,j = Ii · Tjτ
si,j scores photo i against caption j. I is the image encoder’s output. T is the text encoder’s output. Each passes through a linear projection into one shared space and is scaled to length 1, so their dot product · is a cosine between −1 and 1. The temperature τ divides it. Cosines alone span too narrow a range for a confident softmax; a small τ stretches the gaps, so the true caption can win clearly and the hardest wrong captions get most of the push. A large τ flattens every share toward 1/N.
ℓiimg = −log exp(si,i)Σj exp(si,j)
Photo i picks its caption out of all N. exp raises e (about 2.718) to each score, so every term is positive; the top is its own caption’s term, and Σj adds the terms of every caption in row i. The fraction is the photo’s softmax share for its true caption, and minus its log is near 0 when that caption wins and grows as it loses. This is InfoNCE with the row’s N captions as the candidates.
ℓjtxt = −log exp(sj,j)Σi exp(si,j)
Caption j picks its photo out of all N the same way, summing down column j instead of along a row. The softmax now runs over photos, so it penalizes a caption that scores high with the wrong photo.
L = 12N Σi=1N (ℓiimg + ℓitxt)
The loss L averages the 2N terms, one per photo and one per caption; the paper calls it a symmetric cross entropy. Rows catch a photo that picks the wrong caption, and columns catch a caption that picks the wrong photo. One wrong caption can win a photo’s row while that caption’s own column still picks its photo, so the two directions catch different mistakes and both encoders are corrected from both sides.

3.1 The temperature is learned

CLIP learns τ as one more weight, updated by every gradient step with the encoders. It starts at 0.07, a score multiplier of about 14.3, and the multiplier is capped at 100 (τ = 0.01) because larger ones made training unstable. Knowledge Distillation uses the same temperature in the opposite direction, raising it to soften a teacher’s output probabilities.

The snippet defines the loss L and calls it on toy features. Look inside clip_loss: both sides are projected and scaled to length 1, the learned multiplier 1/τ is capped, and cross entropy runs along the rows, then down the columns.

import torch
import torch.nn.functional as F

def clip_loss(img_feat, txt_feat, proj_img, proj_txt, log_scale):
    I = F.normalize(img_feat @ proj_img, dim=1)   # [N, D]
    T = F.normalize(txt_feat @ proj_txt, dim=1)
    scale = log_scale.exp().clamp(max=100.0)      # 1/τ, capped
    s = scale * I @ T.T                           # [N, N]
    diag = torch.arange(len(s))                   # true pairs
    l_img = F.cross_entropy(s, diag)
    l_txt = F.cross_entropy(s.T, diag)
    return (l_img + l_txt) / 2

N, D_IMG, D_TXT, D = 8, 2048, 512, 64
img_feat, txt_feat = torch.randn(N, D_IMG), torch.randn(N, D_TXT)
proj_img = torch.randn(D_IMG, D, requires_grad=True)
proj_txt = torch.randn(D_TXT, D, requires_grad=True)
log_scale = torch.tensor(1 / 0.07).log().requires_grad_()
L = clip_loss(img_feat, txt_feat, proj_img, proj_txt, log_scale)

  4. 4Each caption picks its photo, eq line 3.

4 Zero-shot classification asks which caption fits

To classify a photo with no training on the task, zero-shot, write each class as a caption and ask which caption the photo matches best.

The snippet uses OpenAI’s clip package. Look at the no_grad block: the four prompts become the rows of W once, the photo becomes h, and the last line picks the class whose caption fits best. The trained multiplier of 100 is skipped, since it cannot change the winner.

import clip
import torch
import torch.nn.functional as F
from PIL import Image

device = "cuda" if torch.cuda.is_available() else "cpu"
model, preprocess = clip.load("RN50", device=device)
names = ["dog", "cat", "car", "tree"]
prompts = [f"a photo of a {c}." for c in names]
tokens = clip.tokenize(prompts).to(device)
photo = Image.new("RGB", (224, 224))       # toy photo
x = preprocess(photo).unsqueeze(0).to(device)
with torch.no_grad():
    W = F.normalize(model.encode_text(tokens), dim=-1)  # [4, D]
    h = F.normalize(model.encode_image(x), dim=-1)      # [1, D]
pred = names[(h @ W.T).argmax()]
  1. 1Loads a trained CLIP.
  2. 2Class names become caption prompts, the text side of Figure 5.
  3. 3One preprocessed photo.
  4. 4Text rows W and photo embedding h, with no gradients.
  5. 5The best-matching caption is the class.

The class matrix W works like a linear probe's weights with no bias, written by the text encoder from class names instead of learned from labeled photos (sec. 3.1.2).

5 CLIP in practice

One training step runs both towers on a batch of photo and caption pairs, scores them with clip_loss, and updates the towers, both projections and the temperature together. It reuses clip_loss, the sizes and the parameters from the loss snippet in Section 3.1; small stand-ins replace the ResNet and the Transformer.

import torch
import torch.nn as nn

VOCAB, CTX = 49408, 76
image_tower = nn.Sequential(nn.Flatten(), nn.Linear(3 * 64 * 64, D_IMG))
text_tower = nn.EmbeddingBag(VOCAB, D_TXT)      # stand-in Transformer
params = [*image_tower.parameters(), *text_tower.parameters(),
          proj_img, proj_txt, log_scale]
opt = torch.optim.AdamW(params, lr=5e-4, weight_decay=0.2)

photos = torch.rand(N, 3, 64, 64)               # one batch of pairs
tokens = torch.randint(0, VOCAB, (N, CTX))
L = clip_loss(image_tower(photos), text_tower(tokens),
              proj_img, proj_txt, log_scale)
opt.zero_grad()
L.backward()
opt.step()
