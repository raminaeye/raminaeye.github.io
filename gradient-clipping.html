1 What clipping fixes

An exploding gradient is a gradient that suddenly becomes very long, usually from one unlucky batch or one steep cliff in the loss surface. The optimizer’s step is proportional to it, so a single such step can throw the weights far from where training was going, and the loss jumps or turns into NaN (not a number).

Pascanu, Mikolov and Bengio (2013) showed why this happens in recurrent networks: backpropagation through time multiplies the gradient by the recurrent weight matrix once per time step, so it can grow exponentially, and explosion needs the matrix’s largest singular value to be above one for a tanh network (in general, above one over the activation’s largest slope) (RNN Basics, section 2.1). Their fix, rescaling any gradient longer than a threshold, became standard far beyond RNNs: transformers and large language models clip every step; LLaMA clipped at 1.0 (Touvron and others 2023).

2 Norm clipping and value clipping

Two ways to cap a gradient
\({\displaystyle \htmlStyle{color:#c0392b}{\hat g} \leftarrow \htmlStyle{color:#c0392b}{\hat g}\cdot \min\!\Big(1,\ \frac{\htmlStyle{color:#a04000}{\tau}}{\lVert \htmlStyle{color:#c0392b}{\hat g}\rVert}\Big)}\)
Norm clipping: if the gradient vector \(\hat g\) is longer than the threshold \(\tau\) (tau), shrink the whole vector so its length is exactly \(\tau\); if it is shorter, the minimum picks one and nothing changes. Every coordinate is scaled by the same factor, so the direction is kept and only the length is capped (Vectors and Matrices).
\({\displaystyle \htmlStyle{color:#c0392b}{g_i} \leftarrow \operatorname{clip}\big(\htmlStyle{color:#c0392b}{g_i},\ -\htmlStyle{color:#a04000}{\tau},\ \htmlStyle{color:#a04000}{\tau}\big)}\)
Value clipping: cap each coordinate \(g_i\) separately to lie between \(-\tau\) and \(\tau\). Large coordinates are cut while small ones are not, so the vector’s direction turns toward the corners of a box. It is simpler but changes where the step points.
\({\displaystyle \lVert \htmlStyle{color:#c0392b}{g}\rVert = \sqrt{\sum_k \lVert \htmlStyle{color:#c0392b}{g^{(k)}}\rVert^{2}}}\)
The length used for norm clipping is the global norm: the square root of the sum of every parameter tensor’s squared length, so the whole model’s gradient is treated as one long vector. Clipping per tensor instead would scale layers differently and again change the direction.

5 Choosing the threshold

The threshold should sit above the gradient lengths of ordinary batches and below the spikes, so it only acts on the rare bad step. Too high and it never fires; too low and it clips every step, which shortens every step like a smaller learning rate and slows training. Pascanu and others suggest setting \(\tau\) from the average norm over a large number of updates, and found training not very sensitive to the exact value. In practice, log the global norm, which clip_grad_norm_ returns, for a short run and set \(\tau\) a little above its typical value. Mikolov (2012) had already clipped gradients to train recurrent language models. Large language model recipes commonly use a norm of 1.0 with AdamW.

6 When to use it

Clip whenever a single bad batch can wreck training: recurrent networks, which explode through time; large transformers and language models, where rare loss spikes are a known risk; reinforcement learning, where targets jump; and mixed-precision runs. It costs almost nothing, so most large-model recipes turn it on by default. It does not fix a learning rate that is too high on every step; if it clips nearly every step, lower the rate instead.

7 When it runs and what it carries

Clipping sits between backward() and opt.step(), once per training step, and carries no state: it reads the gradients, rescales them in place and is done. With mixed precision the gradients are still multiplied by the loss scale at that point, so they must be unscaled first, or the threshold is compared with the wrong length.

8 Clipping in PyTorch

import torch
import torch.nn.functional as F
from torch.nn.utils import clip_grad_norm_
from torchvision import datasets, models, transforms
data = datasets.CIFAR10('.', download=True,
    transform=transforms.ToTensor())
loader = torch.utils.data.DataLoader(data, batch_size=128)
net = models.resnet18(num_classes=10)
opt = torch.optim.SGD(net.parameters(), lr=0.1)
x, y = next(iter(loader))
loss = F.cross_entropy(net(x), y)
loss.backward()
clip_grad_norm_(net.parameters(), 1.0)
opt.step()  # after the clip
  1. 1A ResNet-18 for the ten CIFAR-10 image classes, its optimizer, and batches of 128 images.
  2. 2One batch, its cross-entropy loss (the standard classification loss) and its gradients.
  3. 3Gradient length capped at \(\tau\), the norm clipping line.
  4. 4Steps with the clipped gradient.
from torch.nn.utils import clip_grad_norm_, clip_grad_value_
norm = clip_grad_norm_(net.parameters(), max_norm=1.0)  # returns the norm before clipping
print(f"grad norm {norm.item():.3f}")                    # log it to choose the threshold
clip_grad_value_(net.parameters(), clip_value=0.5)       # or cap each value instead
scaler = torch.amp.GradScaler()                          # mixed precision:
scaler.scale(loss).backward()
scaler.unscale_(opt)                                     # unscale before measuring
clip_grad_norm_(net.parameters(), 1.0)
scaler.step(opt); scaler.update()

9 Clipping in a multitask model

With several task losses, clipping the summed gradient caps the total but lets one exploding task dominate the direction up to the cap; clipping before or after a gradient balancer changes what is capped. That interaction is covered in Gradient Balancing Inside the Training Loop, section 10, and the through-time case in RNN Basics, section 2.2.
