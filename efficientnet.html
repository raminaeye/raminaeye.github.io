Grow depth, width and image size together with one coefficient, so a bigger network stays in balance.

Scaling is applied once, at design time. The coefficient \(\phi\) picks a model before training and nothing changes while it trains. The family B0 to B7 comes from raising \(\phi\) step by step.

1 Bigger is not better in one direction

A network has three dimensions to grow: depth, width and image size. Growing only one stops paying off, because a larger image needs more layers to widen the receptive field and more channels to hold its finer detail. EfficientNet grows all three together with one coefficient, so a bigger network stays in balance.

B0 scaled to about 1.8B FLOPs (billions of multiply-add operations) four ways, ImageNet top-1 measured (ImageNet is a labeled photo set with 1,000 classes; top-1 accuracy is the share of test photos whose highest-scoring class is right), from the paper Table 7. B0 itself is 77.3% at 0.4B FLOPs. Depth only (d = 4) reaches 79.0% at 1.8B, width only (w = 2) 78.9% at 1.8B, resolution only (r = 2) 79.1% at 1.9B, and compound (d = 1.4, w = 1.2, r = 1.3) 81.1% at 1.8B. The Table 7 compound model is not a phi step: its d, w and r are 1.4, 1.2 and 1.3, not the 1.2, 1.1 and 1.15 bases.

2 The baseline B0

B0 was found by neural architecture search over the MnasNet search space, a search over mobile-sized blocks, optimizing accuracy and FLOPs together (paper section 4; Neural Architecture Search teaches the search itself in full). B0 is built from MobileNetV2 inverted residual blocks with SiLU, a smooth activation that lets small negative values through instead of cutting them off like ReLU6, and the squeeze-and-excitation step. The scaling method is only as good as the baseline it starts from.

3 Compound scaling: one coefficient, three multipliers

The grid search at \(\phi\) = 1 found \(\alpha\) = 1.2, \(\beta\) = 1.1 and \(\gamma\) = 1.15 (paper section 4, step 1; the formulation is paper section 3.3), and the three bases then stay fixed. The letter \(\alpha\) here is the EfficientNet depth base, 1.2, not the MobileNet width multiplier \(\alpha\) from page 1. Width and resolution use smaller bases than depth because compute grows with the square of width and of resolution.

Start from the baseline B0: phi 0, no scaling yet.

Compound scaling grows depth, width and image size with one coefficient.
\(\phi\) = 0 is B0 itself, no scaling yet.
\(\displaystyle \htmlStyle{color:#2471a3}{\text{depth multiplier}} = 1.2^{\phi}\)
Each step of the coefficient \(\phi\) multiplies the number of layers by 1.2, so depth grows exponentially in \(\phi\).
\(\displaystyle \htmlStyle{color:#a04000}{\text{width multiplier}} = 1.1^{\phi}\)
Each step multiplies the number of channels by 1.1. The base is smaller than depth's because compute grows with the square of width, so a small width step already costs as much as a larger depth step.
\(\displaystyle \htmlStyle{color:#7d3c98}{\text{resolution multiplier}} = 1.15^{\phi}\)
Each step multiplies the image side by 1.15, a smaller base than depth's for the same reason as width: compute grows with its square.
\(\displaystyle \alpha \cdot \beta^{2} \cdot \gamma^{2} \approx 2\)
Compute grows in proportion to depth but with the square of width and of resolution, so the product of the three bases, with width and resolution squared, is the FLOPs growth per phi step. The paper's bases make the product about 2, so each step of \(\phi\) about doubles the FLOPs (floating-point operations) while the three parts grow in balance. \(\alpha\), \(\beta\) and \(\gamma\) are the depth, width and resolution bases (1.2, 1.1 and 1.15 for B0), named in the prose as the paper's grid-searched constants, not multiplied out on the page.

  1. 1Builds B4 with random weights; each block is MobileNetV2’s inverted residual with SiLU and the squeeze-and-excitation step of Squeeze-and-Excitation, and training skips blocks at random with probability up to 0.2 (stochastic depth).

The block below shows only what differs from the page 1 InvRes snippet: SiLU in place of ReLU6, the SE call, and stochastic depth. The SE step is the gate of Squeeze-and-Excitation, not re-explained here. 

import torch
import torch.nn as nn
from functools import partial
from torchvision.ops import (
    StochasticDepth as SD)

C2 = partial(
    nn.Conv2d, bias=False)
BN = nn.BatchNorm2d
Pool = nn.AdaptiveAvgPool2d
Seq = nn.Sequential

class MBConv(nn.Module):
    def __init__(
            self, c, t=6, p=0.2):
        super().__init__()
        h = c * t  # wide middle
        self.expand = Seq(
            C2(c, h, 1), BN(h),
            nn.SiLU())
        self.depthwise = Seq(
            C2(h, h, 3, 1, 1,
               groups=h),
            BN(h), nn.SiLU())
        self.se = Seq(
            Pool(1),
            C2(h, h // 4, 1),
            nn.SiLU(),
            C2(h // 4, h, 1),
            nn.Sigmoid())
        self.project = Seq(
            C2(h, c, 1), BN(c))
        self.drop = SD(
            p, mode="row")

    def forward(self, x):
        y = self.expand(x)
        y = self.depthwise(y)
        y = y * self.se(y)
        y = self.project(y)
        # stride 1, same width:
        # the shortcut applies
        return x + self.drop(y)
  1. 1Expands with a 1×1 and SiLU, the same widening as page 1 but with SiLU in place of ReLU6.
  2. 2Filters the wide map depthwise, the cheap half of the split.
  3. 3The SE call: squeeze to a quarter of the channels, score them, rescale (Squeeze-and-Excitation).
  4. 4Projects back with no activation, then stochastic depth drops the whole branch at random with probability up to 0.2 while training.
  5. 5Adds the shortcut around the branch; it applies when stride is 1 and the width is unchanged.

The paper reports B0 and B1 a little differently in different tables. Cite the table every number comes from: B0 is 77.1% in Table 2 and 77.3% in Table 7, and B1 is 79.1% in Table 2 and 78.8% in Table 4.

6 Failure modes and tips

Each failure here comes from scaling used where its setup does not hold.

Scaling one dimension alone. Symptom: accuracy stops rising as the model grows. Cause: depth, width or resolution alone saturates. Fix: scale all three with one \(\phi\).

Bases carried to a different baseline. Symptom: the scaled model underperforms the paper's family. Cause: the B0 bases do not transfer automatically to a different baseline; they were grid-searched for B0 (paper section 4, step 1). Fix: search the bases on the small model first, then freeze them.

A B size that does not match the paper. Symptom: layer counts or channel counts differ from the released model. Cause: reproducing a B size needs the torchvision rounding rules, layer counts rounded up and channels to multiples of 8, or the counts will not match. Fix: apply the rounding rules from torchvision/efficientnet.py.

Two tables quoted as one. Symptom: the same model shows two accuracies in one comparison. Cause: the paper's own tables disagree slightly, so mixing Table 2 and Table 7 numbers in one comparison misleads; B0 is 77.1% in Table 2 and 77.3% in Table 7, and B1 is 79.1% in Table 2 and 78.8% in Table 4. Fix: check which table a quoted accuracy comes from, and cite it.
