  • The agent picks the moves. A state is its situation right now, a move (or action) is one choice it can make, and a reward is the number the world hands back after each move (RL Basics).
  • An episode is one run from the start until it ends. A policy is the agent’s rule for choosing a move in each state (RL Basics).
  • The return is all the reward still to come, later rewards counted a little less; the discount \(\gamma\) sets how much less (RL Basics).
  • A state’s value \(V(s)\) is the return the agent expects from state \(s\). A move’s value \(Q(s,a)\) is the return it expects after making move \(a\) in state \(s\) (RL Basics).

How can a Pong paddle learn which moves to make from nothing but the points it wins and loses? This page gives the simplest answer: play whole games, then make each move more likely or less likely by the points that followed it.

1 A Pong paddle that learns from points

In Atari Pong each player moves a paddle up and down to hit the ball back past the other. The state is the screen, a stack of the last few frames so the ball’s direction shows. The moves are up, stay and down, one every few frames; one such move is one step. The reward is +1 for a point won, −1 for a point lost and 0 on every other step. One episode is one full game. \(J\) is the average points per game, points won minus points lost: the number learning tries to raise.

2 A network that outputs move chances

Value methods such as Q-Learning and Deep Q-Networks (DQN) learn how good every move is, then play the best one. This page learns the choice itself: one chance per move on each screen.

The network that does this is the policy network. For Pong it gives three raw outputs, one per move, and a softmax (Softmax, Temperature and Decoding) turns them into three chances that add to one. Its weights are written \(\theta\) (theta), and the chance it gives move \(a\) on screen \(s\) is \(\pi_\theta(a\mid s)\).

3 Make the moves before won points more likely

Pushing a move up means a small change to \(\theta\) that raises that move’s chance on that screen; the other two drop, since the three add to one. Over many games, moves that tend to come before won points rise.

A method that learns this way is a policy-gradient method: it nudges \(\theta\) so each move played becomes more or less likely, in proportion to the move’s credit for how well it turned out. Positive credit pushes the move up, negative credit pushes it down. Policy-gradient methods differ in the credit they use; this page is about picking a good one.

4 Weighting each move by the points that followed

A move can only affect the points that come after it, so its credit should count just those.

REINFORCE (Williams, 1992) plays one full game with the current chances, works out the return \(G_t\) of every step \(t\), and pushes each move by its own \(G_t\): the return is the move’s credit. Learning from finished games, rather than from a network’s guess of what comes next, is called Monte Carlo learning.

To turn this into a loss to minimise, reuse the classification loss of supervised learning: cross-entropy, with the move actually played as the label, scaled by the return that followed it. Cross-entropy works on the log of each move’s chance, and the return stays fixed while the gradient flows: it is a number from the game just played, not something the weights decide.

Why the log? A move played often gets pushed often, just because it is common. The log undoes that. The slope of a log chance equals the slope of the chance divided by the chance. So the more common a move is, the smaller each of its pushes (Policy Gradients: REINFORCE, Actor-Critic and PPO).

\(\displaystyle \htmlClass{eqt}{\htmlStyle{color:#196f3d}{G_t}} = \sum_{k=t}^{T-1} \htmlClass{eqt}{\htmlStyle{color:#2c3e50}{\gamma}}^{\,k-t}\, \htmlClass{eqt}{\htmlStyle{color:#7d6608}{r_{k+1}}}\)
The return of step \(t\): from this step to the end of the game, add up the points won and lost after each move, later ones counting less. \(T\) is the step at which the game ends. \(r_{k+1}\) is the reward that follows the move at step \(k\): zero on most steps, +1 or −1 when a point ends. \(\gamma\), between zero and one, shrinks each reward once more for every step it lies ahead.
\(\displaystyle \begin{aligned}&\mathcal{L}_G(\theta)\\&\;= -\sum_{t} \log \htmlClass{eqt}{\htmlStyle{color:#1f4e9c}{\pi_\theta}}(a_t\mid s_t)\; \htmlClass{eqt}{\htmlStyle{color:#196f3d}{G_t}}\end{aligned}\)
The REINFORCE loss: cross-entropy on each move taken, scaled by its return. \(\log\pi_\theta(a_t\mid s_t)\) is the log chance of the move taken at step \(t\). \(G_t\) is held fixed; no gradient flows through it. The minus sign turns raising \(J\) into a loss to minimise. One gradient step then pushes every move by its own return.

5 Why one game is a noisy judge

The true push is an average over every game the paddle could play. REINFORCE estimates it from the one game it just played, so each update carries that game’s luck. Figure 4 shows what that does.

  1. The paddle goes down while the ball comes in high, a bad move.
  2. The paddle wins the points after it anyway, so its return is high.
  3. Every move is pushed up by about the same amount.

6 Subtracting the usual result

From a screen where the ball is already past the paddle, the next point is almost always lost, so every move there gets a push down, even the best one. What matters is whether a move did better or worse than usual from that screen. A baseline is that usual result, subtracted from the return so the push is less noisy.

A second network learns it: the value network. It looks at the screen and outputs one number, \(V_\phi(s)\), its guess of the usual result. \(\phi\) (phi) stands for its weights, as \(\theta\) does for the policy network.

The return minus that guess is the move’s advantage: how much better than usual it did. From one game it is only an estimate, so it gets a hat: \(\hat A_t\).

\(\displaystyle \htmlClass{eqt}{\htmlStyle{color:#196f3d}{\hat{A}_t}} = \htmlClass{eqt}{\htmlStyle{color:#196f3d}{G_t}} - \htmlClass{eqt}{\htmlStyle{color:#a04000}{V_\phi(s_t)}}\)
The points that followed, minus what usually follows this screen. That usual result is the screen’s value \(V(s)\). The hat means “estimate”: one game is one sample, a single draw from all the games the paddle could have played, standing in for their average. \(G_t\) is one game’s sample of \(Q(s_t,a_t)\), so \(G_t\) minus the value is one game’s sample of the advantage.
\(\displaystyle \begin{aligned}&\mathcal{L}_{\hat A}(\theta)\\&\;= -\sum_{t} \log \htmlClass{eqt}{\htmlStyle{color:#1f4e9c}{\pi_\theta}}(a_t\mid s_t)\; \htmlClass{eqt}{\htmlStyle{color:#196f3d}{\hat{A}_t}}\end{aligned}\)
The baseline loss: the REINFORCE loss with \(\hat A_t\) in place of \(G_t\). Moves that beat the usual result are pushed up, those that fell short are pushed down. \(\hat A_t\) is held fixed, as \(G_t\) was.
\(\displaystyle \begin{aligned}&\mathcal{L}_V(\phi)\\&\;= \sum_{t} \big(\htmlClass{eqt}{\htmlStyle{color:#196f3d}{G_t}} - \htmlClass{eqt}{\htmlStyle{color:#a04000}{V_\phi(s_t)}}\big)^2\end{aligned}\)
The value loss: the squared gap between the real return and the guess, as in regression. Only \(\phi\) changes through this line.

A push is biased when, averaged over many games, it points somewhere other than the direction that raises \(J\).

The baseline must depend only on the screen, never on the move made there. Then subtracting it adds no bias: each move’s push follows the slope of its log chance, and over all the moves those slopes add to the slope of the chances’ sum. The chances always sum to one, so that slope is zero, and on average the baseline’s pushes cancel.

7 Keeping the paddle undecided

Early on the paddle wins a few points by staying still, and REINFORCE keeps pushing ‘stay’ until the other moves are almost never tried, so it never finds out that moving up wins more.

Entropy \(\mathcal{H}\) is how undecided the policy is: high when the moves are about equally likely, zero when one move is certain (KL Divergence). The entropy bonus rewards the policy for staying undecided, so it keeps trying moves it rarely picks. The full loss below adds it as its last term.

\(\displaystyle \begin{aligned}&\htmlClass{eqt}{\htmlStyle{color:#0e6d80}{\mathcal{H}}}\big(\htmlClass{eqt}{\htmlStyle{color:#1f4e9c}{\pi_\theta}}(\cdot\mid s)\big)\\&\quad=-\sum_{a}\htmlClass{eqt}{\htmlStyle{color:#1f4e9c}{\pi_\theta}}(a\mid s)\\&\qquad\times\log \htmlClass{eqt}{\htmlStyle{color:#1f4e9c}{\pi_\theta}}(a\mid s)\end{aligned}\)
One number for how undecided the paddle is between up, stay and down on this screen. \(\pi_\theta(\cdot\mid s)\) is the whole set of move chances on screen \(s\). The sum runs over the three moves, each chance times its log; a log of a chance below one is negative, so the minus makes \(\mathcal{H}\) positive.
\(\displaystyle \begin{aligned}&\mathcal{L}_{\text{total}}\\&\;=\mathcal{L}_{\hat A}(\theta)+\mathcal{L}_V(\phi)\\&\qquad-c_H\sum_{t}\htmlClass{eqt}{\htmlStyle{color:#0e6d80}{\mathcal{H}}}\big(\htmlClass{eqt}{\htmlStyle{color:#1f4e9c}{\pi_\theta}}(\cdot\mid s_t)\big)\end{aligned}\)
One loss for one optimiser step: the baseline loss pushes toward good moves, the value loss fits the value network, and the last term charges a small price for becoming too certain. \(c_H\) is the entropy weight. Raising it keeps the paddle undecided longer, trying more and settling slower; lowering it lets the paddle commit sooner. The value loss changes only \(\phi\); the rest changes only \(\theta\).

8 Step through one REINFORCE update

Put together, one update has four ideas: the return, the advantage, the value fit and the entropy bonus.

9 REINFORCE in PyTorch

A toy REINFORCE for Pong, to read rather than run. Pong has six actions; we keep up, stay and down. The wrappers prepare the screen: AtariPreprocessing turns each frame grey and smaller, FrameStackObservation stacks four frames so the ball’s direction shows, and Categorical draws a move from the policy’s chances. MOVES holds Pong’s own codes for up, stay and down.

import gymnasium as gym, ale_py
import torch
from torch import nn
from torch.distributions import Categorical

gym.register_envs(ale_py)
env = gym.make("ALE/Pong-v5", frameskip=1)
env = gym.wrappers.AtariPreprocessing(env, frame_skip=4)
env = gym.wrappers.FrameStackObservation(env, 4)
MOVES = [2, 0, 3]   # up, stay, down
gamma, c_h = DISCOUNT, C_ENTROPY

def returns_to_go(rewards, gamma):
    G, out = 0.0, []
    for r in reversed(rewards):
        G = r + gamma * G
        out.insert(0, G)
    return torch.tensor(out)

def body():
    return nn.Sequential(
        nn.Conv2d(FRAMES, C1, 8, stride=4), nn.ReLU(),
        nn.Conv2d(C1, C2, 4, stride=2), nn.ReLU(),
        nn.Flatten(), nn.Linear(FLAT, HIDDEN), nn.ReLU())

policy = nn.Sequential(body(), nn.Linear(HIDDEN, N_MOVES))   # up, stay, down
value = nn.Sequential(body(), nn.Linear(HIDDEN, 1))    # V_phi(s)
opt = torch.optim.Adam([*policy.parameters(), *value.parameters()], lr=LEARNING_RATE)

for episode in range(N_EPISODES):                       # repeat: one game, one update
    s, info = env.reset()
    states, moves, rewards, done = [], [], [], False
    while not done:                                 # one whole game
        x = torch.as_tensor(s, dtype=torch.float32).unsqueeze(0) / 255
        with torch.no_grad():
            a = Categorical(logits=policy(x)).sample()
        s, r, terminated, truncated, info = env.step(MOVES[a.item()])
        states.append(x); moves.append(a)
        rewards.append(r)   # r_{t+1}: the reward after move t
        done = terminated or truncated
    S, M = torch.cat(states), torch.cat(moves)
    dist = Categorical(logits=policy(S))   # softmax of the logits
    logp = dist.log_prob(M)
    G = returns_to_go(rewards, gamma)
    V = value(S).squeeze(-1)
    value_loss = (G - V).pow(2).sum()
    adv = (G - V).detach()
    pg_loss = -(logp * adv).sum()
    loss = pg_loss + value_loss - c_h * dist.entropy().sum()
    opt.zero_grad(); loss.backward(); opt.step()
  1. 1The return of every step, added up backward from the last reward.
  2. 2The policy network’s logits, its raw outputs before the softmax; logp is the log chance of each move taken, as in the REINFORCE loss.
  3. 3The value loss: the value network’s guess for every screen and its squared gap to the return.
  4. 4The advantage and the baseline loss: adv is \(\hat A_t\), held fixed by detach(), and pg_loss is \(\mathcal{L}_{\hat A}\).
  5. 5The total loss, with dist.entropy() as the entropy line; loss.backward() works out every gradient (Backpropagation and Gradient Checking) and opt.step() takes one Adam step (Adaptive Optimizers: AdaGrad, RMSProp and Adam).

10 How a baseline narrows the spread

The learning rate \(\eta\), the lr in the code, sets how big a step each update takes (Q-Learning).

A less noisy push makes separate training runs end closer together. How far apart they end is the spread. A baseline set above the usual result makes most pushes point the wrong way, so the runs spread out again. In the tool below, one step plays a batch of finished games, each with its own update. The tool sets its own win chances, for illustration: up is the most likely winner, then stay, then down.

Each update runs once per finished game, and the only state carried between updates is the two networks’ weights.

  • Normalize the advantages: shift and scale them so each update’s advantages average zero and have a spread of one.
  • Average several games into one update, so the update then runs once per batch of games instead of once per finished game.

12 When REINFORCE fits

REINFORCE fits short games, because over a long game each push is very noisy. It is the simplest method to learn the idea.

14 Judging each move before the game ends

What if the value network’s guess stood in for the points still to come, so each move could be judged a few steps later instead of at the end of the game?

Judging each move before the game ends is the idea behind Actor-Critic, and Proximal Policy Optimization (PPO) builds on that.
