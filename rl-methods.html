RL Method Families: Values, Policies and Models

Learn how good things are, what to do, or how the world works. Which kind of learning each family of methods does, and when to reach for it.

A learner can get better from rewards in more than one way. It can learn how good each situation is, learn what to do directly, or learn how the world responds and plan with that. Which of these should a method learn, and what goes wrong with each?

The agent is the learner that picks the moves, as taught in RL Basics. A state is the agent's situation right now; a move, or action, is one choice the agent can make in a state; a reward is the number the world hands back after each move, good or bad, as taught in RL Basics. Here the agent is a warehouse robot that must reach its charging dock. It starts in one bottom corner and the dock sits in the other.

The floor is a grid of cells, one per place the robot can stand. It knows only which cell it stands in, not where each move leads or what it costs.

An episode is one run from the start until it ends, as taught in RL Basics. The ledge is the strip of floor between the start and the dock. Reaching the dock can take many moves.

Each move's reward is minus the battery it uses, so the best total is the one closest to zero. Every move costs a little battery; stepping onto the ledge costs a lot and puts the robot back at the start; only reaching the dock ends the episode. The cheapest way to the dock is the shortest path that never steps onto the ledge.

Figure 1 shows the floor the robot learns on, a grid of cells with the start in one corner, the dock in the other, and the ledge between them. Pale cells are floor, the pink strip is the ledge, and the green cell is the dock. The robot starts at the dot; every move costs a little battery, but the ledge costs a lot and sends it back. Take a robot one cell from the dock with the ledge in between: the short way crosses the ledge and pays a lot, so the cheap way goes around.

1 What an agent can learn

RL, short for reinforcement learning, is learning which moves to make from rewards rather than from labelled answers, as taught in RL Basics. Nobody shows the robot the route to the dock; it finds one only by trying steps.

The return is all the reward still to come, with later rewards counted a little less, as taught in RL Basics. A policy is the agent's rule for choosing a move in each state; it may always pick the same move or pick by chance, as taught in RL Basics. Next to the dock little battery is left to spend, so the return there is the best on the floor.

A state's value \(V(s)\) is the return the agent expects from state \(s\), as taught in RL Basics. A move's value \(Q(s,a)\), also called its score, is the return the agent expects if it makes move \(a\) in state \(s\) and plays on from there, as taught in RL Basics. A robot that starts far from the dock passes many cells before it reaches it, while one that starts beside it is nearly there.

A model is the agent's learned guess of where a move leads and what it pays. Each of the three looks different on the floor, a shade per cell, an arrow per cell or a guessed next cell per move.

The robot starts with all three empty and fills them in from its own steps.

A model-free method learns values or a policy straight from real steps, with no model of the world. A model-based method also learns a model and practises inside it before acting for real. A route tried in its head costs the robot no battery, but it is only as good as its guesses.

Sample efficiency is how much an agent learns from each real step. Model error is where the model's guess differs from the real world, so plans built on it go wrong. A robot that only ever tried safe steps has a model that knows nothing about the ledge.

2 Values, policies and models as equations

A network's weights are the numbers training adjusts; in this series value weights are written \(\phi\) and policy weights \(\theta\), as taught in Gradient Descent. On the floor, training changes the robot's numbers a little after every step it takes.

An expected value is the average over everything that can happen by chance, weighted by how likely each outcome is, as taught in Probability and Bayes Rule. The sign \(\mathbb{E}\) marks an expected value, as taught in Probability and Bayes Rule. The robot's scores are such averages, learned from the steps it really takes.

Take the warehouse robot standing in a cell next to the ledge.

The average is built as a sum: take each future after this cell and move, multiply that future's return by its chance, and add the products up. \(\htmlStyle{color:#0e6b59}{G_t}\) is the return from step \(t\), minus the battery still to be spent, later moves counted a little less. The bar holds the start fixed.
Example. Take the robot in the cell beside the ledge, eyeing the move toward the dock: the learned score for that move is the return it expects from the dock side, not from the ledge.

Intuition. A policy is a rule for choosing: in each cell it says how likely each move is. The second line writes that rule as chances.
The mathematics. This line says \(\htmlStyle{color:#a04000}{\pi_{\theta}}(a \mid s)\) is the chance of move \(a\) in cell \(s\). \(\htmlStyle{color:#a04000}{\pi_{\theta}}\) is a rule that takes a cell \(s\) and gives one number per move \(a\): the chance the robot picks that move there. The bar reads given \(s\): each cell has its own set of chances. The chances over all the moves in one cell add to one, so the policy always picks some move. \(\htmlStyle{color:#a04000}{\theta}\) are the policy weights, the numbers training adjusts; changing \(\htmlStyle{color:#a04000}{\theta}\) changes the chances the policy gives each move.
Example. Take the robot beside the ledge: the policy gives the move toward the dock a high chance and the step onto the ledge a low one, so the robot usually walks on.

Intuition. A model guesses what a move does: where it lands and what it pays. The third line writes that guess as chances.
The mathematics. This line says \(\htmlStyle{color:#0e6b59}{\hat{p}}(s_{t+1}, r_{t+1} \mid s_t, a_t)\) is the chance of landing in the next cell \(s_{t+1}\) with the next reward \(r_{t+1}\). \(\htmlStyle{color:#0e6b59}{\hat{p}}\) takes the cell now \(s_t\) and the move \(a_t\), and returns one number per landing and reward. The bar reads given this cell and move. Moves are chancy, so the model gives a chance per landing. \(r_{t+1}\) is minus the battery the move uses: a little for an ordinary move, a lot for the ledge. The hat marks a learned guess from the robot's own steps.
Example. Take the robot beside the ledge stepping toward the dock: the model gives a high chance of landing on the dock and a small chance of slipping onto the ledge.
Take the robot standing in the cell next to the ledge, with the dock just past the ledge. The value line scores the move toward the dock by the return it expects from there, the policy line gives that move a high chance and the move onto the ledge a low one, and the model line gives the chance the move toward the dock lands the robot on the dock and the chance it lands on the ledge instead. Together the three lines say one thing: a value method scores each move, a policy method chances each move, and a model method chances each landing and reward.

The warehouse robot can learn any of the three from the same steps on the floor.

3 What each RL method learns and fixes

Q-Learning keeps a score for every move in every cell and fills the scores in from its own steps. SARSA scores the moves the robot really plays, random ones included, so its route keeps away from the ledge. On the warehouse floor a table of scores is small enough to keep, because the floor has few cells and few moves.

Deep Q-Networks (DQN) compute the move scores with a neural network, for worlds whose states never repeat. Double DQN lets a second network score the move the first one picked, so the scores stop climbing higher than the robot really earns. A robot that saw the floor through a camera would need such a network, because no two camera pictures are exactly alike.

Dueling DQN splits each move's score into how good the cell is plus what the move adds. Policy gradient methods learn the choice itself, the chance of each move in each cell, and in their simplest form they learn only once an episode's return is known. Actor-critic methods add a second network that judges each step, so the policy need not wait for the episode to end. On this floor most cells have one clearly best move, so one arrow per cell is all the robot needs to act.

Continuous-action methods learn moves that are amounts, such as how hard to push. Model-based methods learn where moves lead and what they pay, and practise inside that model. Multi-agent methods train several learners that share one world. The warehouse robot's moves are a short list, its floor is small, and it works alone.

Aligning a language model trains a policy that writes text, using a reward for its replies. A chat model is far from the warehouse floor, yet it learns from rewards in the same loop.
