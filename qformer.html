BLIP-2 lets a frozen language model describe images and answer questions on them. A frozen image encoder reads the picture, a small trained Q-Former compresses it into 32 vectors, and these precede the language model's text. The Q-Former trains in two pretraining stages on image-caption pairs, then runs once per image at inference, before the language model writes.

BLIP-2 builds on BLIP: it reuses BLIP's three objectives, contrastive, matching and captioning, taught in BLIP: One Model, Three Objectives, CapFilt.

Cross-attention takes queries from one stream and keys and values from another; learned queries are vectors trained like weights, and a mask blocks chosen query and key pairs.

32 learned queries read the frozen image features and return 32 vectors.
\(\displaystyle \htmlStyle{color:#117a65}{Z} = \text{CrossAttn}(\htmlStyle{color:#7d3c98}{Q}, \htmlStyle{color:#a04000}{X_{\text{img}}})\)
The Q-Former's output \(Z\) is 32 vectors that summarize the image for the language model. It is ordinary Cross-Attention: the 32 learned queries \(Q\) ask, and the frozen image features \(X_{\text{img}}\) answer as keys and values. The output takes its row count from the queries, so \(Z\) has 32 rows whatever the image size; training moves the queries and the Q-Former's weights, never the image encoder in pre-training.

1 Two frozen models need a small trainable module between them

BLIP's three objectives, contrastive, matching and captioning, are taught in BLIP: One Model, Three Objectives, CapFilt. BLIP-2 (Li et al. 2023) keeps the image encoder and the large language model (LLM) frozen, to save compute and avoid catastrophic forgetting (new training wiping out old knowledge), and trains a small module between them in two stages. Stage 1 pulls out the image features most relevant to the text with BLIP's three objectives, the captioning loss renamed ITG (image-grounded text generation).

2 Inside the Q-Former, 32 learned queries read the image

The Q-Former (Querying Transformer) has 32 learned queries of size 768 and two submodules, an image transformer and a text transformer, that share only self-attention.

  • Only the image transformer's queries read the frozen image features, through cross-attention every other block.
  • The text transformer reads a caption (encoder) or writes one (decoder).

It starts from BERT-base weights, with cross-attention random.

Its self-attention mask is one of the three masks of Section 3.

One Q-Former block in PyTorch, LayerNorms left out; queries and text go in and come out the same shape.

import torch
import torch.nn as nn

N_Q, D, D_IMG, D_FF, H = 32, 768, 1024, 3072, 12
MHA = nn.MultiheadAttention
self_attn = MHA(D, H, batch_first=True)
cross = MHA(D, H, kdim=D_IMG, vdim=D_IMG, batch_first=True)

def ffn():
    up, down = nn.Linear(D, D_FF), nn.Linear(D_FF, D)
    return nn.Sequential(up, nn.GELU(), down)

ffn_q, ffn_t = ffn(), ffn()  # image and text transformers

def block(x, img, allowed):  # x (B, N_Q + T, D)
    mask = ~allowed  # True = blocked
    x = x + self_attn(x, x, x, attn_mask=mask)[0]
    q, t = x[:, :N_Q], x[:, N_Q:]
    q = q + cross(q, img, img)[0]  # only queries read img
    q, t = q + ffn_q(q), t + ffn_t(t)
    return torch.cat([q, t], dim=1)

  2. 2One FFN for each transformer, the two FFN boxes of Figure 3.
  3. 3Masked self-attention over queries and text, the shared self-attention of Figure 3.
  4. 4Only the 32 query rows read the image, the Q-Former card in the intro, line 1.
  5. 5Each transformer through its own FFN, out to \(Z\) in Figure 3.

The output \(Z\) is smaller than the frozen features, so the queries keep only what the text needs.

How many feature vectors a ViT with 14-pixel patches gives for a square image \(P\) pixels wide.
\(\displaystyle \htmlStyle{color:#a04000}{N} = (\frac{P}{14})^{2} + 1\)
A bigger image gives the ViT more feature vectors, growing with the square of its width. \(\frac{P}{14}\) is the number of 14-pixel patches per side; squaring it counts every patch, and the +1 is one summary vector. BLIP-2 takes its features from the giant ViT, so each feature vector is wider than the figure's, while the Q-Former output stays 32 by 768 whatever the image size.

3 One set of weights learns three objectives from three masks

Stage 1 trains all three objectives at once, each with its own mask over queries and text, so the queries cannot copy the caption and must carry what it needs. Contrastive (ITC) keeps queries and text apart, so each side builds its own summary to compare. Matching (ITM) lets everything see everything, and a head says matched or not. Generation (ITG) lets text see the queries and earlier text, so the queries must carry what the caption needs.

In the contrastive score, \(t\) is the output of the text's first token, a summary token.

The generation objective starts the text with a [DEC] token instead of [CLS], to signal decoding (BLIP-2 section 3.2). Negatives come from the batch itself, not from BLIP's momentum queue (BLIP-2 section 3.2). The matching head scores every query and averages the 32 scores (BLIP-2 section 3.2).

The contrastive similarity between an image and a caption.
\(\displaystyle s(I, C) = \max_{i} \operatorname{sim}(\htmlStyle{color:#1f618d}{z_{i}}, \htmlStyle{color:#2c3e50}{t})\)
An image \(I\) and a caption \(C\) score as high as their best-matching query. sim compares query output \(z_{i}\) with the caption summary \(t\): both are projected and normalized to length 1, then dotted, so the score is the cosine of the angle between them. \(\max_{i}\) keeps the best of the 32 instead of an average, so one query that found the caption's subject is enough, and different queries are free to specialize in different image parts. Training raises this score for matched pairs and lowers it for the other captions in the batch, the InfoNCE loss, the contrastive loss that picks the true pair out of the batch. BLIP compares one image vector with one text vector (BLIP, Section 2).

The generation mask for 32 queries and 6 text tokens.

import torch

N_Q, N_TXT = 32, 6
pos = torch.arange(N_Q + N_TXT)
is_query = pos < N_Q
row_q, col_q = is_query[:, None], is_query[None, :]
past = pos[None, :] <= pos[:, None]  # column <= row
text_sees = col_q | past
allowed = (row_q & col_q) | (~row_q & text_sees)
print(allowed.shape)  # (N_Q + N_TXT, N_Q + N_TXT)

4 The second stage feeds the language model soft prompts

In Stage 2, one fully connected (FC) layer projects \(Z\)'s 32 vectors to the LLM's embedding size, and they precede the text as soft visual prompts (vectors that act like extra words); only the Q-Former and the FC layer train.

OPT (decoder-only) trains with the next-token loss \(L\); FlanT5 (encoder-decoder) trains with a prefix loss, where the caption's first part goes into the encoder with the prompts and the decoder writes the rest.

The decoder-only (OPT) loss, predicting each caption token with the 32 prompts in front.
\(\displaystyle L = -\frac{1}{T}\sum_{t=1}^{T} \ell_{t}\)
The loss \(L\) is low when the frozen LLM, reading the 32 prompts, predicts the caption well. It averages a per-token term \(\ell_{t}\) over the \(T\) caption tokens, and the minus sign turns higher log probabilities into lower loss; averaging keeps long and short captions on one scale. BLIP's captioning loss has the same shape, with the image in place of the prompts (BLIP, Section 2).
\(\displaystyle \ell_{t} = \log P(\htmlStyle{color:#2c3e50}{w_{t}} | \htmlStyle{color:#117a65}{p_{1}\dots p_{32}}, \htmlStyle{color:#2c3e50}{w_{<t}})\)
Each term is the log of the probability the LLM gives the true caption token \(w_{t}\), seeing the prompts \(p_{1}\ \text{to}\ p_{32}\) and the caption so far. A probability of 1 gives 0, and a probability near 0 gives a large negative number, which line 1's minus sign turns into a large loss. The LLM itself is frozen, so the only way to lower \(L\) is for the Q-Former to write prompts that carry what the caption needs.

Stage 2 with OPT-125M as the frozen LLM and random \(Z\) as the Q-Former output.

import torch
import torch.nn as nn
from transformers import AutoModelForCausalLM

NAME, IGNORE = "facebook/opt-125m", -100
llm = AutoModelForCausalLM.from_pretrained(NAME)
llm.requires_grad_(False)  # frozen, gradients still pass
proj = nn.Linear(768, llm.config.hidden_size)  # FC layer
embed = llm.get_input_embeddings()

Z = torch.randn(2, 32, 768)  # Q-Former output (B, N_Q, 768)
ids = torch.randint(100, 2000, (2, 8))  # caption token ids
B, N_Q = Z.shape[:2]
x = torch.cat([proj(Z), embed(ids)], dim=1)
skip = torch.full((B, N_Q), IGNORE)
labels = torch.cat([skip, ids], dim=1)
L = llm(inputs_embeds=x, labels=labels).loss  # mean
L.backward()  # reaches proj only in this snippet

  3. 3-100 labels keep the 32 prompts out of the loss, which covers only the \(T\) caption tokens of the loss card in Section 4, line 1.

5 What BLIP-2 proves, and what it costs

BLIP-2 beats Flamingo80B on zero-shot VQAv2, while Flamingo80B leads on OK-VQA; both are visual question answering benchmarks.

The paper's guess is that OK-VQA leans on outside knowledge, and Flamingo80B's larger language model holds more of it than the smaller FlanT5-XXL (BLIP-2 section 4).

6 Where BLIP-2 falls short

  • Few-shot examples in the prompt do not help; the paper blames one image-text pair per training sample.
  • Answers go wrong when the LLM's knowledge is wrong or stale, or its reasoning slips.
  • A frozen LLM also brings offensive output, social bias and private-data leaks.
  • Skipping Stage 1 breaks the bridge: without representation learning, OPT suffers catastrophic forgetting and performance degrades as training proceeds (BLIP-2 section 4.1, its Figure 5).
  • Fine-tuning unfreezes the image encoder while the language model stays frozen, for captioning and for VQA (BLIP-2 sections 4.2 and 4.3).

7 Two Hugging Face calls run the whole pipeline

On the released OPT-2.7B checkpoint, an image and a question go in and an answer comes out.

import torch
from PIL import Image
from transformers import Blip2Processor
from transformers import Blip2ForConditionalGeneration

CKPT = "Salesforce/blip2-opt-2.7b"
processor = Blip2Processor.from_pretrained(CKPT)
model = Blip2ForConditionalGeneration.from_pretrained(CKPT, dtype=torch.float16)
model = model.to("cuda")
print(model.config.num_query_tokens)  # 32

image = Image.open("photo.jpg").convert("RGB")
question = "Question: what is in the picture? Answer:"
inputs = processor(image, question, return_tensors="pt")
inputs = inputs.to("cuda")
inputs["pixel_values"] = inputs["pixel_values"].to(torch.float16)
ids = model.generate(**inputs, max_new_tokens=20)
print(processor.batch_decode(ids, skip_special_tokens=True))
