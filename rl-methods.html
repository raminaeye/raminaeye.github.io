RL Method Families

Learn a score for every move, learn the move itself, learn both, or plan with a model.

1 Four method families

Every RL method runs the reinforcement learning loop; what differs is what the agent learns to pick its move. A value is an estimate of how much future reward to expect; a policy is the rule that picks the move. Some methods also learn, or are handed, a model that predicts what each move will do, and plan with it (model-based); methods without one are model-free. Actor-critic methods learn both a policy, the actor, and a value, the critic. Families also differ in how often they learn, from every step to once per batch.

2 What each family stores

Given one state, a value-based agent outputs a score per move, a policy-based one move probabilities, and an actor-critic probabilities plus the critic’s score of the state.

3 Value-based methods

A value-based agent keeps a score, a Q-value, for every move in every state: the future reward it expects from that move and good play after. It mostly plays the highest score, explores with a small chance ε (ε-greedy) and updates as in RL Basics. Q-learning (Watkins and Dayan 1992) keeps these scores in a table, one row per state:

Q-learning moves the score of the move played a little toward a target built from that step.
target = r + γ · max Q(s′, a′)
The target is the reward r the move earned plus the highest score in the state s′ it led to, max Q(s′, a′) over every move a′ there. The discount γ, from 0 to 1 and often just below 1, shrinks that future score for the delay (the discount plot in RL Basics).
Q(s, a) ← Q(s, a) + α · (target − Q(s, a))
The score of move a in state s moves a fraction α, the learning rate, of the way toward the target (the arrow means replace with).

In the cliff walk of Sutton and Barto’s RL textbook (2018, Example 6.6), a 4 × 12 grid, an episode runs from start S to goal G, the two ends of the bottom row, past the cliff between them. Every step costs −1; the cliff costs −100 and a return to S. The code runs tabular Q-learning on gymnasium’s CliffWalking.

import random
import numpy as np
import gymnasium as gym

alpha, gamma, eps = 0.5, 1.0, 0.1   # values from the book's cliff code
env = gym.make("CliffWalking-v1")
Q = np.zeros((48, 4))   # 48 squares, 4 moves

def epsilon_greedy(Q, s):
    if random.random() < eps:
        return random.randrange(4)
    return int(Q[s].argmax())

for episode in range(500):
    s, info = env.reset()
    done = False
    while not done:
        a = epsilon_greedy(Q, s)
        s_next, r, terminated, truncated, info = env.step(a)
        best_next = 0.0 if terminated else Q[s_next].max()
        Q[s, a] += alpha * (r + gamma * best_next - Q[s, a])
        s, done = s_next, terminated or truncated
  1. 1Sets α, γ and ε and an all-zero Q-table for the 48-square cliff.
  2. 2Defines ε-greedy move choice.
  3. 3Starts an episode, picks a move and steps the environment.
  4. 4Target and update, eq card in Section 3, lines 1 and 2.
  5. 5Moves on to the next state.

4 On-policy and off-policy

An off-policy method learns about a policy other than the one making its moves. Q-learning is off-policy because its target scores the best move in s′, whatever the agent plays next, so it learns best-move values while exploring. SARSA, named for the five things one update uses (State, Action, Reward, next State, next Action), changes that one term (the RL textbook, section 6.4):

SARSA scores the move it will really play next, not the best one.
targetSARSA = r + γ · Q(s′, a′next)
a′next is the move ε-greedy really picks in s′, random moves included. SARSA learns the values of the policy it runs, so it is on-policy.

The SARSA inner loop picks a_next first; env, Q and epsilon_greedy come from Section 3’s code.

for episode in range(500):
    s, info = env.reset()
    a = epsilon_greedy(Q, s)
    done = False
    while not done:
        s_next, r, terminated, truncated, info = env.step(a)
        a_next = epsilon_greedy(Q, s_next)   # really played
        q_next = 0.0 if terminated else Q[s_next, a_next]
        Q[s, a] += alpha * (r + gamma * q_next - Q[s, a])
        s, a = s_next, a_next
        done = terminated or truncated
  1. 1Starts an episode and picks the first move.
  2. 2Steps, then picks a′next, the move the agent will really play.
  3. 3SARSA target, eq card in Section 4, line 1, then the update from Section 3, line 2.
  4. 4Carries the next state and move into the next step.

Both agents explore with ε 0.1.

5 Deep Q-networks

DQN, deep Q-network (Mnih et al. 2015), replaces the table with a neural network that outputs one score per move. Two fixes keep it from oscillating or diverging:

  • Experience replay trains on random batches from a replay buffer, a memory of past steps, so nearly identical steps do not arrive in a row. Those steps came from older policies, so replay needs an off-policy method.
  • A target network, a frozen copy of the network, computes the targets and is recopied every C updates, so targets hold still between copies.

Among noisy scores the highest is usually one that came out too high, so the max makes Q-learning and DQN overestimate (van Hasselt et al. 2016). Double DQN fixes the target:

Double DQN splits picking the next move from scoring it.
targetDQN = r + γ · max Q−⁠(s′, a′)
Q− is the frozen copy. The same scores both pick the best move and value it, so a score that came out too high is the one picked and used.
a* = argmax Q(s′, a′)
The learning network Q picks the move. argmax returns the move a′ with the highest score, not the score itself.
targetDouble = r + γ · Q−⁠(s′, a*)
The frozen copy values that move. A score inflated in one network is less often inflated in the other, so the target is inflated less often.

Dueling DQN (Wang et al. 2016) changes the network instead, splitting it into two streams:

A dueling network adds a state value and an advantage per move.
Q(s, a) = V(s) + A(s, a) − meana′ A(s, a′)
V(s) is how good the state is overall; A(s, a), the advantage, is how much better move a is than the average move. Subtracting the mean advantage over all moves a′ makes the split unique, since otherwise any amount could shift between V and A. V learns from every step, which helps when many moves score about the same.

My banana network uses both (the DQN page draws the two streams).

One DQN update; for Double DQN, pick the next move with q_net and score it with target_net.

import random
import torch
import torch.nn.functional as F

gamma, batch_size, C = 0.99, 32, 10_000   # DQN paper

def dqn_update(q_net, target_net, optimizer, buffer, n_updates):
    batch = random.sample(buffer, batch_size)
    s, a, r, s_next, done = map(torch.tensor, zip(*batch))
    with torch.no_grad():
        best_next = target_net(s_next).max(1).values
        target = r + gamma * best_next * (1 - done.float())
    q_sa = q_net(s).gather(1, a.unsqueeze(1)).squeeze(1)
    loss = F.smooth_l1_loss(q_sa, target)   # Huber
    optimizer.zero_grad()
    loss.backward()
    optimizer.step()
    if n_updates % C == 0:
        target_net.load_state_dict(q_net.state_dict())
  1. 1Samples 32 stored steps from the replay buffer.
  2. 2Target from the target network Q−, first eq card in Section 5, line 1.
  3. 3Huber loss (squared for small errors, linear for large) between Q(s, a) and the target, then one gradient step.
  4. 4Copies the network into Q− every C updates.

6 Policy-based methods

A policy-based agent skips the scores. Its network turns the state into a probability for each move, and the agent samples from them. Sampling matters when any fixed move can be beaten, as in rock-paper-scissors, where the best play is each move a third of the time (Prisner 2014).

REINFORCE (Williams 1992), the simplest policy-based method, learns once per episode: at the end, every move becomes more likely in proportion to the return that followed it, the reward collected from that move on:

REINFORCE makes each move more likely in proportion to the reward that came after it.
loss = −Σt log π(at |⁠ st) · Gt
π(at | st) is the probability the policy gave the move it made at step t (the bar reads "given"). Gt is the return from step t on, each later reward shrunk once per step of delay by the discount γ. log, the logarithm, makes the gradient that of π divided by π, which divides out how often a move is sampled, so a move is not pushed up just for being picked often. Σt adds over the episode. The minus sign makes it a loss: moves before a large return become more likely, moves before a negative one less likely.

One REINFORCE episode on gymnasium’s CartPole:

import gymnasium as gym
import torch
from torch.distributions import Categorical

gamma = 0.99
env = gym.make("CartPole-v1")
policy = torch.nn.Sequential(
    torch.nn.Linear(4, 128), torch.nn.ReLU(),
    torch.nn.Linear(128, 2))
optimizer = torch.optim.Adam(policy.parameters(), lr=1e-2)

s, info = env.reset()
log_probs, rewards, done = [], [], False
while not done:
    dist = Categorical(logits=policy(torch.as_tensor(s)))
    a = dist.sample()
    s, r, terminated, truncated, info = env.step(a.item())
    log_probs.append(dist.log_prob(a))
    rewards.append(r)
    done = terminated or truncated
G, returns = 0.0, []
for r in reversed(rewards):
    G = r + gamma * G
    returns.insert(0, G)
G_t = torch.tensor(returns)
loss = -(torch.stack(log_probs) * G_t).sum()
optimizer.zero_grad()
loss.backward()
optimizer.step()
  1. 1Sets γ, CartPole and a small policy network with its optimizer.
  2. 2Plays one full episode, keeping each move's log-probability and reward.
  3. 3Computes the return Gt backward from the last reward.
  4. 4The loss from the first eq card in Section 6, then one gradient step.

Its weakness is noise: Gt includes the luck of every later reward, so updates vary a lot between episodes. Two additions help (the RL textbook, section 13.4):

A baseline steadies the update, and an entropy bonus keeps the policy exploring.
At = Gt − b(st)
The baseline b(st) is any guess that depends on the state but not on the move, usually a learned guess of the return from st. At says how much better the return was than that guess.
loss = −Σt log π(at |⁠ st) · At
The same loss as REINFORCE with At in place of Gt. On average the baseline does not change the gradient, so the method still moves the same way; it only lowers the variance of each update.
H(π(· |⁠ s)) = −Σa π(a |⁠ s) · log π(a |⁠ s)
H, the entropy, measures how spread out the move probabilities are: largest when every move is equally likely, zero when one move is certain. The dot in π(· | s) stands for all moves at once, and Σa adds over them.
losstotal = loss − β · Σt H(π(· |⁠ st))
β is a small weight. Subtracting the entropy rewards keeping options open, so the policy does not lock onto one move too early.

7 Actor-critic methods

In actor-critic, the actor is the REINFORCE policy; the critic V(s) is a learned baseline: it estimates the return from a state, and by also scoring the state a move led to, judges each move after one step, not at the episode's end (the RL textbook, section 13.5):

In one actor-critic update the critic's estimate is the baseline, and the actor's move is judged against it.
A(s, a) = Q(s, a) − V(s)
The advantage again, from the dueling network: how much better move a is than the critic expects from state s.
A ≈ δ = r + γ · V(s′) − V(s)
≈ reads "is estimated by". One real reward plus the guess from the next state, minus the guess from this one. δ is the TD error (temporal difference), how much one step changed the guess. REINFORCE with a baseline used G − V(s) instead, which waits for the episode's end; δ is less noisy, but only as good as the critic.
actor loss = −log π(a |⁠ s) · A
The REINFORCE line with the advantage in place of the return: the move gets more likely only if it beat the guess.
critic loss = (r + γ · V(s′) − V(s))2
δ squared, so a miss in either direction counts. Making it smaller pulls V(s) toward one real reward plus the guess at s′, which is held fixed as the target.

One update on the last B steps the current policy played, where no_grad holds V(s′) fixed.

import torch
from torch.distributions import Categorical

gamma = 0.99

def actor_critic_update(actor, critic, optimizer, batch):
    s, a, r, s_next, done = batch   # tensors, B steps each
    v_s = critic(s).squeeze(-1)
    with torch.no_grad():
        v_next = critic(s_next).squeeze(-1)
    delta = r + gamma * v_next * (1 - done) - v_s
    A = delta.detach()
    log_pi = Categorical(logits=actor(s)).log_prob(a)
    actor_loss = -(log_pi * A).mean()
    critic_loss = delta.pow(2).mean()
    optimizer.zero_grad()
    (actor_loss + critic_loss).backward()
    optimizer.step()
  1. 1Critic values and δ, eq card in Section 7, line 2.
  2. 2Actor loss with A = δ, line 3, the up arrow in Figure 8.
  3. 3Critic loss, line 4, the arrow in Figure 8 that trains the critic.
  4. 4One gradient step on both losses.

A3C, asynchronous advantage actor-critic (Mnih et al. 2016), runs many workers on copies of the world, all updating one shared network; their varied experience steadies learning without replay. In place of the one-step δ it uses an n-step return and adds the entropy bonus. A2C, advantage actor-critic, is the synchronous version: all copies step, then make one joint update. Both are on-policy.

8 PPO clipping

PPO, proximal policy optimization, is actor-critic that reuses each on-policy batch for several updates but stops rewarding any change that moves the policy far from the one that collected it. Without that stop, the old batch’s advantages keep raising likely moves until performance collapses (Schulman et al. 2017):

PPO stops rewarding a change once the new policy leaves a band around the old one.
ratio = πnew(a |⁠ s)πold(a |⁠ s)
How much more likely (above 1) or less likely (below 1) the policy being trained makes the move than πold, the policy that collected the batch.
clipped = clip(ratio, 1 − ε, 1 + ε)
clip holds the ratio inside the band from 1 − ε to 1 + ε. ε here is the band's half-width, 0.2 in the paper, not the exploration chance.
objective = min(ratio · A, clipped · A)
min keeps the smaller of the plain and clipped terms. Past the band, moving the ratio further earns nothing, while a change that hurts still counts in full. Training makes the objective larger; the loss is its negative.

One PPO update over a rollout, the steps just played, EPOCHS passes over shuffled minibatches:

import torch
from torch.distributions import Categorical

EPS_CLIP, EPOCHS, MINIBATCH = 0.2, 4, 128   # CleanRL ppo.py

def ppo_update(actor, optimizer, s, a, old_log_pi, A):
    old_log_pi, A = old_log_pi.detach(), A.detach()
    for epoch in range(EPOCHS):
        for mb in torch.randperm(len(s)).split(MINIBATCH):
            dist = Categorical(logits=actor(s[mb]))
            ratio = torch.exp(dist.log_prob(a[mb]) - old_log_pi[mb])
            clipped = ratio.clamp(1 - EPS_CLIP, 1 + EPS_CLIP)
            objective = torch.min(ratio * A[mb], clipped * A[mb])
            loss = -objective.mean()
            optimizer.zero_grad()
            loss.backward()
            optimizer.step()
  1. 1Freezes old log-probabilities and advantages; loops over epochs and minibatches.
  2. 2Ratio, eq card in Section 8, line 1.
  3. 3Clip, line 2, the band in Figure 10.
  4. 4Objective, line 3, turned into a loss.
  5. 5One gradient step per minibatch.

The paper’s full loss adds the critic’s loss and an entropy bonus. PPO drives RLHF in Aligning Language Models with RL.

9 Continuous actions

A continuous action is any real number in a range rather than a pick from a list, like the four joint torques of my Reacher arm (RF-DDPG repo). DDPG, deep deterministic policy gradient (Lillicrap et al. 2016), has a critic Q(s, a) that scores a state with an action, and an actor μ(s) that outputs one action and is trained to raise that score. It is off-policy, with replay and slowly updated (Polyak-averaged) target copies (the DDPG page).

One DDPG update on a replayed batch:

import torch
import torch.nn.functional as F

gamma, tau = 0.99, 0.001   # DDPG paper

def ddpg_update(nets, opt_actor, opt_critic, batch):
    actor, critic, actor_t, critic_t = nets
    s, a, r, s_next, done = batch   # 64 steps, shape (B, 1)
    with torch.no_grad():
        q_next = critic_t(s_next, actor_t(s_next))
        target = r + gamma * (1 - done) * q_next
    critic_loss = F.mse_loss(critic(s, a), target)
    opt_critic.zero_grad()
    critic_loss.backward()
    opt_critic.step()
    actor_loss = -critic(s, actor(s)).mean()
    opt_actor.zero_grad()
    actor_loss.backward()
    opt_actor.step()
    for net, net_t in ((actor, actor_t), (critic, critic_t)):
        for p, p_t in zip(net.parameters(), net_t.parameters()):
            p_t.data.copy_(tau * p.data + (1 - tau) * p_t.data)
  1. 1Unpacks the four networks and 64 replayed steps.
  2. 2Target from the target networks, eq card in Section 3, line 1, with the actor’s action in place of the max.
  3. 3Critic step toward the target.
  4. 4Actor step that raises the critic's score of the actor's own action.
  5. 5Soft update of both target networks by τ.

DDPG inherits Q-learning's overestimation. TD3, twin delayed DDPG (Fujimoto et al. 2018), makes three changes, two in the target:

TD3 smooths the next action, then trusts the lower of two critics.
ã = μ−⁠(s′) + clip(noise, −c, c)
μ− is the slowly updated copy of the actor. Small random noise, clipped to stay within c of zero (standard deviation 0.2, c = 0.5 in the paper), is added to its action, so the target cannot rest on one narrow, too-high peak of the critic.
qmin = min(Q1−⁠(s′, ã), Q2−⁠(s′, ã))
Two critics learn side by side, and qmin is the smaller of their slowly updated copies' scores for that action.
target = r + γ · qmin
Using the lower score counters overestimation instead of adding to it.

The third change updates the actor and target copies once per two critic updates (DDPG variants).

SAC, soft actor-critic (Haarnoja et al. 2018), has a stochastic actor, one that outputs a spread of actions, and puts the entropy into the goal:

SAC is paid for reward and for keeping its actions spread out.
objective = Σt E[rt + α · H(π(· |⁠ st))]
E, the expectation, averages over the states and actions the policy meets. H is the entropy from Section 6, now earned at every step. α, the temperature (not the learning rate from Q-learning), sets how much spread is worth against reward.

It is off-policy with replay.

10 Model-based methods

A model predicts the next state and reward from a state and a move; planning uses it to look ahead or practise without the real world. Dyna (Sutton 1991) adds n imagined Q-learning steps from a remembered model after each real one (Dyna-Q, the RL textbook, section 8.2). The code runs one Dyna-Q step on the book’s 6 by 9 maze. env_step(s, a) is the maze’s rule, returning (r, s_next).

import random
import numpy as np

alpha, gamma, eps, n = 0.1, 0.95, 0.1, 5   # book's maze
Q = np.zeros((54, 4))   # 6 x 9 squares, 4 moves
model = {}              # (s, a) -> (r, s_next)
GOAL = 8                # top-right square, episode ends

def q_update(s, a, r, s_next):
    future = 0.0 if s_next == GOAL else Q[s_next].max()
    Q[s, a] += alpha * (r + gamma * future - Q[s, a])

def dyna_step(env_step, s):
    if random.random() < eps:
        a = random.randrange(4)
    else:
        a = int(Q[s].argmax())
    r, s_next = env_step(s, a)
    q_update(s, a, r, s_next)
    model[(s, a)] = (r, s_next)
    for _ in range(n):
        (s_m, a_m), (r_m, s_m_next) = random.choice(list(model.items()))
        q_update(s_m, a_m, r_m, s_m_next)
    return s_next
  1. 1Sets the book's maze values, the Q-table, an empty model and the goal square.
  2. 2The Q-learning update, eq card in Section 3, line 2, with no future past the goal.
  3. 3Picks a move ε-greedily and takes one real step.
  4. 4Learns from the real step and stores it in the model.
  5. 5Replays n stored steps from the model, the imagined steps in Figure 11.

Imagined steps cut the real episodes Dyna-Q needs (the RL textbook, Example 8.1).

AlphaZero (Silver et al. 2018) uses a game's rules for a tree search, a look-ahead over move sequences that a network steers, and learns from games against itself. MuZero (Schrittwieser et al. 2020) learns the model instead:

AlphaZero searches with the real rules; MuZero searches with a learned model.
(p, v) = f(s)
In AlphaZero, from a position s, one network f gives p, a probability for each move, and v, the predicted result. The rules produce each next position in the search.
z0 = repr(observation)
MuZero first uses a representation network, repr, to turn what the agent sees into z0, a hidden state (a vector of numbers).
(r, zk+1) = dynamics(zk, a)
The dynamics network stands in for the rules: from hidden state zk and move a, it predicts the reward and the next hidden state.
(p, v) = f(zk)
The same move probabilities and value as AlphaZero, read from the hidden state. The hidden state only has to predict rewards, moves and values, never to redraw the screen.

World Models (Ha and Schmidhuber 2018) train a small controller inside a learned model of the game, then run it for real. Making the model's predictions more random kept the controller from exploiting the model's errors. Dreamer (Hafner et al. 2020) learns a compact hidden-state model from replayed experience and trains its actor and critic on imagined runs inside it.

11 Choosing a method

Two facts usually decide: whether actions are a short list (discrete) or real numbers, and what a real step costs.

WhenReach forBecause
Few states, fits in a tableQ-learning, or SARSA if exploring mistakes are costlySARSA keeps clear of where its own random moves could drop it
Short list of moves, many numbers or pixels inDQN with Double and DuelingOff-policy, so replay reuses every step
Continuous actions, real steps costlyTD3 or SACOff-policy with replay, and steadier than DDPG
Many cheap copies of a simulatorPPO or A2CSimple on-policy updates from fresh data; PPO's clip keeps each update small
