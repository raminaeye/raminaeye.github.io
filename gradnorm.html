GradNorm (Gradient Normalization)

Learn one loss weight per task, its volume knob, so every task trains at the same pace. No hand-tuned task weights.

Introduction to Multitask Learning named three failures that break the naive sum, which adds the task losses (the error scores the tasks are trying to lower) as they are. GradNorm takes on the first two, scale and speed: it watches how training is going and turns each task's volume until nobody is falling behind.

One loud task drowns out the rest

Picture several tasks sharing one trunk, the shared part of the model that every task trains, with a small part of its own on top. Each task reports a loss, but the losses sit on very different scales: a depth loss near 800, from the task that predicts how far away each point in the scene is, a classification loss near 2. Add them up as-is and the big one dominates the sum. And even after you fix the scales, one task can still dominate: its gradients, the arrows that point where that task's loss rises fastest in the shared parameters (the numbers training adjusts; training steps the other way), are simply larger, so the shared parameters move mostly for it. Hand-tuned weights go stale when the tasks' fortunes change mid-training.

GradNorm is a loss-weighting method. It changes how loud each loss is. Gradient methods, such as PCGrad, GradVac and CAGrad, instead edit the gradients' directions.

The key fact is that a task dominates training through large gradients, so gradient size is the thing to measure and even out. This bites hardest when one network learns several dense tasks at once, tasks that make a prediction for every pixel of an image, for example segmentation (labeling each part of an image by what it shows), depth, and surface normals (the direction each point on a surface faces) together.

Turn down the loud tasks, turn up the ones that are behind

Picture K tasks, K being the number of tasks, all pushing on the shared trunk at once. The task with the biggest gradient moves the trunk the most, and a task that has nearly finished learning keeps pushing just as hard. GradNorm gives each task a volume knob, a weight that multiplies its loss, and keeps turning the knobs so that (a) every task's gradient is about equally large, and (b) a task that is falling behind gets turned up for a while. A strength dial sets how hard GradNorm pushes for equal progress.

Measure loudness where the tasks fight

Every training step, each task's gradient is a list of numbers, one per shared parameter. If task 1's list is full of small numbers and task 2's is full of huge ones, the sum looks like task 2's list. GradNorm's answer is to adjust the knobs a little every step using three measurements. Loudness is read at the last shared layer W. The tasks fight over every shared layer, but Chen and colleagues, who introduced GradNorm in 2018, read only this one to keep the extra cost small. Progress and pace are read from the losses.

How loud is each task

Each task's loudness at each step is the length of the gradient of its weighted loss, measured at the last shared layer. The gradient of a weighted loss is just the weight times the gradient of the loss, so loudness is knob times raw gradient length. Turning the knob up makes the task louder by exactly that much. That is the lever GradNorm pulls. The average loudness across tasks is the reference volume everyone is compared against.

How loud each task is right now.
GW(i) = ‖∇W wiLi‖
Task i's loudness GW(i) is the length, the norm, of the gradient of its weighted loss, measured at the last shared layer W: ∇W is the gradient with respect to the parameters of W, and wiLi is task i's loss times its knob.

How much progress each task has made

Progress is the current loss divided by the loss at the start of training, a ratio with no units. The division is what makes tasks comparable: a depth loss near 800 and a classification loss near 2 cannot be compared directly, but “how much of my journey is left?” means the same thing for both. Chen and colleagues call this ratio the inverse training rate, because a small ratio means the task learned fast.

How much progress each task has made.
Li(t) = Li(t)Li(0)
Task i's progress ratio Li(t) is its loss at training step t divided by its loss at step 0, the start of training.

How each task's progress compares with the group

Next, each task's progress ratio is divided by the group average. A value of 1 means on pace; 0.5 means ahead; 1.5 means behind and needing attention. The speed problem is tasks falling out of sync, and you only spot that by comparing each task to the group. If all tasks move at the same speed, every value stays at 1, the extra push for tasks that are behind does nothing, and GradNorm only evens out loudness. That push acts only when tasks drift apart.

How each task's progress compares with the group.
ri(t) = Li(t)1K Σj Lj(t)
Task i's pace ri(t) is its progress ratio divided by the group average. Σj adds up the progress ratio of every task j, and dividing by K, the number of tasks, turns that sum into the average.

Tasks that are behind get a louder target

Each task gets a target loudness, the average loudness across tasks boosted for whoever is behind. That one rule makes two fixes. The average pulls everyone toward the same volume, fixing the scale problem. The boost turns the volume up for tasks that are behind, fixing the speed problem. A strength dial, written α in the target equation, sets how hard the boost pushes.

Each task's target loudness.
Ti = ḠW[ri]α
Each task's target Ti is the average loudness ḠW times [ri]α, which is ri raised to the power α.

Then GradNorm penalizes the gap between each task's actual loudness and its target. It lowers this penalty with an ordinary optimizer (Chen and colleagues used Adam, which scales each parameter's step by its own running gradient size), but the things being adjusted are the knobs, not the network.

The gap penalty.
Lgrad = Σi |GW(i) − Ti|
The rebalancing loss Lgrad adds up, over every task, how far its actual loudness is from its target Ti. The bars drop the sign, so a task counts the same whether it sits above or below its target. Σi is the sum over every task i.

Three details of how the knobs are updated matter.

  1. The penalty updates only the weights. The network still takes its usual step on the weighted task losses. Updating the knobs is cheap, one small nudge to each of the K numbers per step.
  2. The target is held fixed. Chen and colleagues treat the target as a constant the knobs cannot move. Otherwise shrinking every knob together would shrink the target too, lowering the penalty without balancing anything.
  3. The weights are rescaled to sum to K after every update. Without this, the weight sum wanders. Renormalizing pins it to K, so one task gets louder only if another gets quieter. In Chen's words, it is done “to decouple gradient normalization from the global learning rate”, the step size you set for the network.
The fixed weight budget.
Σi wi = K
The task weights wi always sum to K, the number of tasks, so turning one up means turning another down.

Because GradNorm re-measures after every correction, the starting weights do not have to be lucky.

The listing starts after the forward pass, the run through the model that produces the losses. The task weights have their own learning rate, separate from the network's.

# after the forward pass: losses = [L_1..L_K]; w = trainable task weights
G      = [norm(grad(w[i] * losses[i], W)) for i in range(K)]  # loudness per task
ratio  = losses / losses_0            # progress so far, unit-free
r      = ratio / mean(ratio)           # who is behind the pack? (r > 1 = behind)
target = const(mean(G) * r ** alpha)  # average loudness, boosted for laggards, held fixed
L_grad = sum(abs(G - target))         # how far each norm is from its target
w = w - lr_w * grad(L_grad, w)        # nudge ONLY the weights
w = w * K / sum(w)                    # fixed budget: one task up, another down

Each line is one of the page's equations in code, plus one line that nudges the weights against the gap penalty's gradient.

Four steps, repeated every batch

GradNorm runs as a loop on every batch, the small group of training examples one training step learns from: measure, set targets, nudge the weights, rescale the weights, then measure again. The walkthrough after the loop diagram draws loudness on a log scale, where equal distances mean equal multiples, so loudness 3 and 300 fit on one axis. Its two tasks: task 1 is quiet and behind (loudness 3, progress 0.95), task 2 is loud and ahead (loudness 300, progress 0.40), and the weights move by plain gradient descent.

The quiet task catches up

Chen and colleagues built two toy systems, deliberately tiny artificial setups made to show one effect cleanly, one with 2 tasks and one with 10, each task's target outputs multiplied by a different scale σ, so its squared loss grows with σ squared. Here σ means only that loss scale, not the noise level it names on the Uncertainty Weighting page.

The small-scale tasks end with larger weights than the big-scale ones, the rebalancing the replay in “GradNorm rebalancing frees the quiet task” reproduces. On the task-normalized loss (each task's loss divided by its starting loss, so big and small scales compare fairly, summed into one curve per method), GradNorm finishes below equal weights in both toys. The toys differ only in loss scale, so evening out loudness does all the work.

The paper's caption for the whole figure reads “Gradient Normalization on a toy 2-task (top) and 10-task (bottom) system. Diagrams of the network structure with loss scales are on the left, traces of wi(t) during training in the middle, and task-normalized test loss curves on the right. α=0.12 for all runs.”

GradNorm rebalancing frees the quiet task

This replay is a schematic model, not a real network. Two tasks start at loss 1, and the second task's gradient starts 300 times louder by default. Every step, each task's loss shrinks by about 2 percent times its share of the total loudness, so under equal weights the quiet task's loss barely moves for the first hundred steps. GradNorm, with α at 0.5 and weights kept above 0.02 and summing to 2, turns the quiet task up within those steps, and its loss starts falling much sooner.

GradNorm restores the step's direction after a loss is rescaled

GradNorm sits on both sides of the backward pass: its knobs w multiply the losses, and it reads each task's gradient size at W, the last shared layer.

# each task's gradient size at W
G = torch.stack([torch.autograd.grad(
        w[k] * L[k], W,
        retain_graph=True,
        create_graph=True)[0].norm()
     for k in range(K)])
# pace vs the group; L0 is step 0's
r = (L.detach() / L0)
r = r / r.mean()
target = (G.mean() * r ** alpha)
target = target.detach()
# a loss rescaled from the start:
# its w moves until G is on target,
# so the step's direction returns
w.grad = torch.autograd.grad(
    (G - target).abs().sum(), w)[0]
opt_w.step()
# knobs sum to K: your lr is safe
with torch.no_grad():
    w.mul_(K / w.sum())

Gradient Balancing Inside the Training Loop works through these effects in its sections “GradNorm keeps its task weights summing to the task count” and “Adam cancels a steady scale, and absorbs a sudden change only slowly”.

When GradNorm helps and when it does not

GradNorm has two settings. The more the tasks differ, the higher the best strength dial α: Chen uses 0.12 on toy tasks that differ only in loss scale, and about 1.5 on NYUv2, a dataset of indoor scenes, where one network learns depth, surface normals and room-layout keypoints. The second setting is the knobs' own learning rate. Chen updates the task weights with Adam at 0.025, while the NYUv2 network starts at 0.00002, so the weights move far faster than the network. Weights that keep swinging mean one of the two is too high.

The three charts below come from the replay in “GradNorm rebalancing frees the quiet task”, with the loud task's scale set to 30, over 200 steps.

Strength dial at 0 switches the behind-task boost off

Gradient sizes are evened out, so the weight still climbs, but being behind adds no extra boost.

Strength dial at 0.5 rebalances steadily

The gap above the α = 0 line is the extra boost for being behind.

Strength dial at 2.0 rebalances aggressively

The weight climbs fastest and overshoots a little before it settles. In the paper, values above this turned one network's weights unstable.

Reach for it when your tasks have very different loss scales or learning speeds. The classic case is dense prediction, a prediction for every pixel or point in the input rather than one answer for the whole input (segmentation, depth and surface normals together).

It costs one extra gradient read per task, a backward pass that stops at the last shared layer W. Chen and colleagues measured only about 5% more training time on NYUv2.

Keep in mind that GradNorm is a heuristic, a practical rule of thumb with no proof that training settles, and it says nothing about gradient direction. Two perfectly balanced gradients can still point against each other.

GradNorm sets the volume by watching pace, who is falling behind right now. What if the right volume is knowable from the data itself? Some tasks are just noisier, and a noisy task should count less. That is the Uncertainty Weighting page's whole idea.

The two weighting methods, the volume knobs that learn each task's loss weight (GradNorm and Uncertainty Weighting), and the four gradient methods, PCGrad, GradVac, CAGrad, and MGDA, which stops at a Pareto-stationary point (where no small step lowers every task's loss at once), side by side:

MethodThe question it answers
GradNorm (this page)How loud should each task be, to keep progress balanced? (learned, driven by training dynamics)
