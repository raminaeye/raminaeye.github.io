Introduction to Multitask Learning

Training one model on several tasks, the three common ways it goes wrong, and which methods fix each.

On this page

1One model, several tasks

Multitask learning trains one model on several tasks at once. A shared trunk of layers feeds one small head per task, each task has a loss (a number that scores how badly the model does that task), and training lowers the sum of the losses. Training on that sum can go wrong in three common ways. The fixes fall into two families: methods that learn a weight for each task’s loss, and methods that combine the tasks’ gradients (Section 3.1) afresh at every step (Figure 1).

2Why sharing one trunk helps

  1. One trunk instead of one model per task needs less memory and compute.
  2. Each task’s labels give the shared trunk extra training signal that can help the other tasks.
  3. A trunk that must serve several tasks is pushed toward features that hold across them, so it overfits less to one dataset’s quirks.

Caruana (1997) tested the extra-signal benefit with a robot’s camera: a small network looked at a horizontal strip of pixels from each door image to find the doorknob and to tell single from double doors, once alone and once with eight extra tasks that locate and measure the doorway, the door jambs and the door edges. Error is root-mean-squared error (RMSE) on test images, compared against the best of three single-task networks.

Scene understanding is a standard use: one network predicts segmentation (a label for every pixel), depth and surface normals (the direction each surface faces) (Vandenhende et al., 2022).

3Shared and task-specific parameters

The trunk-and-heads design is called hard parameter sharing. Ruder (2017) calls it the most common approach to multitask learning in neural networks and says it greatly reduces the risk of overfitting, the third benefit in Section 2.

The trunk’s parameters, the weights training adjusts, are θsh. Task i’s head has its own parameters θi, and K is the number of tasks. Each step, task i’s loss Li is averaged over a batch, the small set of examples the model sees in that step. θ stands for all parameters, trunk and heads together.

3.1A task gradient has one entry per shared weight

Task i’s gradient gi lists how fast its loss Li changes with each shared weight: it points where Li rises fastest, and its length says how fast. With one number per shared weight, a trunk with millions of weights gives a vector with millions of entries. Every arrow on this page is a 2D drawing of such vectors; two vectors always lie in one plane, so the lengths and angles drawn are exact. How each gi is computed in PyTorch is on Gradient Balancing Inside the Training Loop.

4Train on the weighted sum of the losses

Give each task loss a weight, add them into one total, and step every parameter downhill on that total.
L(θ) = Σi wi Li(θ)
The total loss L adds each task’s loss Li times its loss weight wi; Σi means add over the tasks i = 1 to K. Raising wi makes task i count for more in every step, lowering it shrinks the task’s share of each step, at 0 the task drops out of training, and every weight at 1 gives the plain sum.
θ ← θ − η∇L(θ)
Each step of gradient descent replaces the parameters θ (← reads “becomes”) by themselves minus η times ∇L, the gradient of the total over all parameters; the gradient points uphill, so subtracting it, a step against ∇L, moves downhill. The step size η (the learning rate) sets how far each step goes: larger moves faster but can overshoot and make the loss jump, smaller is steadier but slower; PyTorch’s SGD defaults to 0.001 (Optimizers from SGD to Adam). The methods in this series keep this step and change the weights inside L or the direction the step takes.

5Three common causes of negative transfer

When tasks are trained together on the plain sum, a task can end up worse than a separate model trained on that task alone; this is called negative transfer. Every task’s gradient changes the same trunk weights, so one task’s update can undo another’s. Three common causes, each with a different fix, are shown in Figure 1.

5.1Losses on different scales

Multiplying a loss by a number multiplies its gradient by the same number, so a loss measured on a larger scale, such as a loss near 600 next to one near 0.4, usually has a far longer gradient and so decides most of the step. It also makes up almost all of the total loss (Figure 6).

Hand-tuned weights wi can fix this, but the tuning has to be redone whenever the tasks change.

5.2Tasks learn at different speeds

When one task is nearly solved early and another keeps improving, weights that were fair at the start are unfair later, so the balance has to change during training.

5.3Task gradients can point in conflicting directions

The cosine of the angle between two task gradients measures how much they point the same way. Past a right angle, part of each gradient works against the other; when that opposition is strong enough, a step against their sum raises one task’s loss (Section 7 gives the exact condition). Loss weights can pick a step that helps both tasks at one moment. A fixed weight keeps the same factor for all of training while the gradients’ lengths and angle change, so a setting that helps both tasks early can hurt one of them later. A combination chosen afresh at every step can be picked to help both whenever such a step exists.

6Four vector operations on gradients

Two of the failures in Section 5, scale and direction, come down to the lengths and angles of task gradients. Sections 6.1 to 6.4 give the four operations that measure them.

6.1The norm is a gradient’s length

The norm of a gradient is its length, the measure behind the scale failure of Section 5.1.

‖v‖ = √v12 + v22 + … + vn2
For a vector v with entries v1 to vn, square each entry, add, and take the square root: Pythagoras’s theorem over all n entries, where for a gradient n is the number of shared weights.

6.2The dot product and the cosine

The dot product and the cosine say whether two gradients point the same way, the measure behind the direction failure of Section 5.3.

⟨u, v⟩ = Σj uj vj
Multiply matching entries uj and vj and add over all j.
⟨u, v⟩ = ‖u‖ ‖v‖ cos ψ
The same number equals both lengths times cos ψ, where ψ (psi) is the angle between the vectors. Lengths are positive, so the dot product’s sign is the sign of cos ψ: positive when the vectors lean the same way, zero at a right angle, negative when they lean apart.
cos ψ = ⟨u, v⟩‖u‖ ‖v‖
Dividing by both lengths removes scale: a long and a short gradient pointing the same way have cosine 1, which is why the cosine is the standard check for conflicting directions and the norm the check for scale.

6.3Projecting one gradient onto another

Projection splits one gradient into the part along another gradient and the part at a right angle to it.

proj = ⟨g1, g2⟩‖g2‖2 g2
The fraction is one number: how many copies of g2 make up g1’s part along it. It is negative when the two point apart, and then the projection points against g2.
g1 − proj ⟂ g2
Subtracting the projection leaves the remainder; ⟂ means “at a right angle to”, so the remainder’s dot product with g2 is 0.

Figure 11. The projection lies along g2; the remainder is at a right angle.

PCGrad and GradVac build on this projection.

6.4A convex combination is a weighted average

A convex combination mixes the task gradients with weights that are zero or more and add to one; the plain average gives every task 1/K.

d = Σi wi gi
d is the combined direction. Each gi is the gradient of its own loss, so d is the gradient of the weighted sum of Section 4 with these weights: choosing a combination is choosing loss weights for one step.
wi ≥ 0,   Σi wi = 1
The weights are shares of a whole, so for two tasks the tip of d lies on the segment joining the two gradient tips.

7Whether a step helps each task

Each method in this series steps against some direction d over the shared weights; whether that step helps task i depends on the dot product of gi with d.

si = ⟨gi, d⟩
Task i’s score si is the dot product of its gradient with d, a measure of how much d agrees with gi. It is positive when d leans the same way as gi, and then a step against d lowers task i’s loss.
Li(θsh − η d) ≈ Li(θsh) − η si
For a small step size η, stepping the shared weights against d, with the heads held fixed, changes task i’s loss by about η times its score: down when si is positive, up when it is negative. ≈ means “close to, for small η”.
d = 12(g1 + g2)
This is the plain average of the two task gradients, the direction that equal loss weights give.
s2 = 12⟨g1, g2⟩ + 12‖g2‖2
Put the average into task 2’s score: half its dot product with g1 plus half its own squared length. The squared length is never negative, so only a negative dot product can pull the score below zero.
s2 < 0  ⇔  ⟨g1, g2⟩ < −‖g2‖2
⇔ means “exactly when”: the average hurts task 2 only when the dot product is more negative than task 2’s own squared length. Task 1 works the same way with ‖g1‖2, so at a right angle, where the dot product is 0, both tasks gain.

MGDA builds on this score.

8Which method fixes which failure

Each failure from Section 5 leaves a different signal in the logged gradients or losses.

Whichever method you use, the loss scale still sets the gradients going in, and the optimizer and gradient clipping (capping a gradient’s length) still change the combined gradient coming out; Gradient Balancing Inside the Training Loop shows how.
