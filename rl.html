Reinforcement Learning (RL)

No answers, just a score. The agent figures out the rest.

What if you could not show the model the answer? No labels, no examples of correct behavior, no dataset at all. Just a world, a few buttons, and a scoreboard. Would anything learn?

Yes, and it is a little unsettling how well. That is reinforcement learning: the agent tries things, the world keeps score, and the strategy slowly bends toward whatever scores. It is how my own code learned to collect bananas, swing a robot arm, and rally a tennis ball, and I barely told it anything beyond what counts as winning.

The loop

The whole field fits in five nouns. The state is what the agent sees right now. The action is what it can do about it. The reward is the score for what just happened. The next state is the world after the action lands. And the policy is the agent's strategy, the thing being learned, usually a neural net.

Walk it with the banana collector, a Unity ML-Agents environment from my Value-based-methods repo. The agent looks at the field (state), picks a direction (action), steps onto a yellow banana (+1 reward, happy) or a blue one (-1, sad), and the world updates. Then it does it again. And again. A few million times, each time nudging the policy a hair toward whatever produced the +1s.

The banana collector, up close

Let me show you the actual gym before we talk about learning. Forget the toy grid below for a minute; here is the real one.

Picture a square arena seen from above. The floor is scattered with bananas: yellow ones worth +1, blue ones worth -1. A little collector agent roams it, trying to run up the score. That is the whole world.

Now the part that bends people's brains. The network never sees the pretty arena. It sees 37 numbers. Thirty-seven plain floats: the agent's own position and velocity, plus the relative positions and velocities of things nearby. That is the full description of reality the network gets. No camera, no picture of a banana. Just 37 numbers and a job.

The job comes as a menu, not a dial. Four moves: forward, back, left, right. No "a little to the left", no steering wheel. The network picks one of the four, the body executes it, and the world rolls on.

Training happens in episodes. One episode is a fixed stretch of time in the arena; the agent roams, bananas get eaten, the score adds up, and then the world resets. Score is everything: yellow +1, blue -1, summed up at the end. There is no demonstration of the correct path, because nobody knows what the correct path is.

The bar I had to clear in my repo: an average score of 14 across episodes. Fourteen net yellows, give or take, before the clock runs out. I got there by running python env.py 1 in my Value-based-methods repo, which trains the agent against this exact arena. Everything else on this page is commentary on those 37 numbers, those 4 moves, and that +1/-1 scoreboard.

How it learns: one line

The learning rule fits in one line, and the tool below walks it one update at a time. Read it term by term:

$$ Q \leftarrow Q + \alpha \, (r + \gamma \max Q' - Q) $$
  1. $Q$ is the old guess: how good the agent thought this move was.
  2. $\alpha$ is the step size: how fast it changes its mind.
  3. $r$ is the reward it just saw: +1, -1, or 0.
  4. $\gamma$ is the discount: how much tomorrow matters versus today. My repo uses 0.99.
  5. $\max Q'$ is the best guess about the next situation. The agent learns from its own future estimates, which is the wild part.

In plain words: move the old guess a little toward (what just happened plus what the future looks like). That is it. That is the engine.

Roll the dice, then stop

Here is the dilemma the agent cannot escape. The Q-values say forward is worth 0.82. Should it always step forward? If it does, it never learns that right might be better. If it rolls the dice every turn, it never uses what it knows. Pure exploitation freezes early. Pure exploration never cashes in.

The fix is a coin flip with a knob, and the knob is called epsilon. With probability epsilon the agent rolls the dice and picks a random move; otherwise it takes the best Q. Five lines:

import random

def pick_action(q_values, epsilon):
    if random.random() < epsilon:
        return random.choice([0, 1, 2, 3])  # explore: roll the dice
    return max(range(4), key=lambda a: q_values[a])  # exploit: best Q

And the knob turns itself down. In my banana runs epsilon starts at 1.0 (total dice; the agent knows nothing anyway, so why not) and decays toward 0.01, where it mostly exploits and only occasionally tries something odd. Decay the explorer into a hunter. Skip this and start at epsilon 0, and the agent latches onto the first thing that ever scored and never lets go. I have watched that too.

From flailing to banana hunter

Put it all together and here is what a real training run looks like. I have watched this one many times and it never gets old.

Episode 1 is pure chaos. Epsilon is 1.0, so the agent flails: it spins in place, eats blue bananas like it is a hobby, wanders into walls. The score is garbage. Correct. It should be garbage.

But every step runs the one-line update, and something quiet happens: the Q-values for "step onto yellow" drift up, the Q-values for "step onto blue" drift down. Yellow and blue separate in the network's head before they separate in its behavior.

As epsilon decays, the flailing narrows. The agent starts finishing episodes with scores that climb, noisily, run to run. Real training curves look like a storm, not a staircase. Mine did. That noise is normal; every episode is a different dice sequence.

And then one day the behavior tips: it hunts. It turns toward yellow, ignores blue, strings pickups together. The average over episodes crosses 14, which is the bar my repo demanded. That is the solved agent. Not perfect, not clever. Just a loop that ran a few million times and landed on "yellow good, blue bad, and here is how to move".

Why this is hard

If the loop is that simple, why did it take the field decades? Because three things about it are quietly brutal, and every algorithm on the next three pages exists to survive one of them.

First, credit assignment. The +1 arrives steps after the move that earned it. The agent turned left, then forward, then forward again, then ate the banana. Which move gets the credit? All of them, a little, fading with distance: that is what the gamma in the update is for. It smears the reward backward across the moves that led to it. Get the smearing wrong and the agent learns superstitions, like a pigeon that thinks flapping caused the food pellet.

Second, exploration. You cannot learn what you never try, and trying costs blue bananas. Play it safe and you freeze on the first thing that ever scored. Flail forever and you never cash in. Epsilon is the compromise, and tuning it is half the craft. Every RL practitioner has a story about an agent that was either too timid or too drunk. Mine is the corner-vibrator.

Third, hunger. The loop needs millions of steps. My banana agent needed thousands of episodes; the arm needed twenty copies of itself training in parallel. This is why nobody trains RL on the real robot first. You train in simulation, where crashing is free, and then you hold your breath and transfer. Sample inefficiency is the tax RL pays for learning from scratch, and the whole field is, in some sense, a long argument about how to lower it.

How to play
  • The point: Reinforcement learning is a loop, not a dataset. This tool runs one full turn of it: look, value the moves, pick, get paid, learn. The insight is the last step, where a single number visibly updates.
  • What you'll see: Play walks one banana step in five stages, about 2.2 seconds each. The agent moves on the grid, the reward pops, and the picked Q-bar grows or shrinks as the update lands.
  • Try this: try epsilon at 0.00: it always exploits, marching forward to the yellow banana for +1 while the forward bar grows. Then try epsilon at 1.00: every pick is a dice roll, and you will catch it wandering into the blue banana for -1 while the picked bar shrinks. How to play
  • The point: The reward is the specification. The agent optimizes the letter of the law, not your intent. Two scoreboards on the same world produce opposite agents.
  • What you'll see: Play runs both arenas at once. Left: the agent hunts yellow bananas, each pickup pops +1, the score climbs. Right: the agent finds the loophole, vibrates in a corner, never touches a banana, and the score still ticks up. Scripted behaviors, labeled as illustrative, honest about being toys.
  • Try this: drag the loophole payout up and run again. The right agent's corner-vibrating score climbs faster, which is exactly the problem: a bigger loophole is a better reason to never hunt. Then ask of the left scoreboard: what behavior does it reward that is not the job? Nothing. That is the test.

The agent is a clever lawyer

Here is the gotcha that bites everyone exactly once: the agent does not learn what you meant. It learns what you rewarded. If the reward has a loophole, the agent will find it and exploit it with zero shame. You just watched one vibrate in a corner. Mine did it on the real arena before I fixed the scoreboard.

So design the reward like the agent is a clever lawyer, because it is. Ask not "does this reward sound right" but "what is the dumbest way to score without doing the job". If you can find it in ten seconds, the optimizer will find it in ten thousand.

One loop, three brains

This page was the loop every RL method shares. Now the three brains I actually built on it, and how they differ from each other:

  • DQN, the menu judge. For each of the 4 moves, keep a score. Pick the highest. That is all of Deep Q-Networks: a scoreboard over a menu. Works when the menu is small and discrete, like four moves in a banana arena.
  • DDPG, the actor and the critic. A robot arm's torques are continuous, and you cannot argmax over infinity. So DDPG splits the brain: an actor network outputs the move directly, and a critic network judges how good it was. Same loop, no menu.
  • Tennis, the moving target. Two rackets, the same DDPG machinery in each, but the world moves because the opponent is learning too. Your practice partner gets better every episode, so standing still is falling behind.
