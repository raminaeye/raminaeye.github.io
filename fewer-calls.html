Paying for Fewer Tool Calls

The same right answer is worth more when it costs fewer tool calls.

1 Right answers that cost too much

Are Giuseppe Verdi and Ambroise Thomas both opera composers? Two models answer yes. One searches three times to get there. The other searches not at all. The answers match, but the bills do not: every search costs time, compute, and money, and each one leans on the outside world.

Training here is reinforcement learning with the efficiency reward: under PPO, one rollout per question, and the trajectory so far is the state. A rollout is one full attempt at a question. This page sits in the second of the three stages the survey of agentic reinforcement learning maps out: copying tool use, optimizing outcomes by reward, and long multi-turn tool use, still open.

Leaning on tools instead of reasoning has a name in the paper: cognitive offloading. The model offloads its thinking onto the search engine, and uses its own reasoning less. The fix is not to ban tools. It is to charge for them, so the model calls one only when the answer is worth the price.

Everything the reward judges is one trajectory: a run of reasoning, tool calls, and observations, ending in an answer.

Equation 1. The trajectory. Reasoning, tool call, and observation, step after step.
\(\displaystyle \begin{aligned}&\htmlClass{eqt sym-x}{\htmlStyle{color:var(--sym-x)}{\tau_k}} = (\htmlClass{eqt sym-y}{\htmlStyle{color:var(--sym-y)}{r_1}}, \htmlClass{eqt sym-p}{\htmlStyle{color:var(--sym-p)}{tc_1}}, \htmlClass{eqt sym-r}{\htmlStyle{color:var(--sym-r)}{o_1}}), \\&\quad (\htmlClass{eqt sym-y}{\htmlStyle{color:var(--sym-y)}{r_2}}, \htmlClass{eqt sym-p}{\htmlStyle{color:var(--sym-p)}{tc_2}}, \htmlClass{eqt sym-r}{\htmlStyle{color:var(--sym-r)}{o_2}}), \dots, \\&\quad (\htmlClass{eqt sym-y}{\htmlStyle{color:var(--sym-y)}{r_k}}, \htmlClass{eqt sym-p}{\htmlStyle{color:var(--sym-p)}{tc_k}}, \htmlClass{eqt sym-r}{\htmlStyle{color:var(--sym-r)}{o_k}})\end{aligned}\)
The trajectory to step \(k\). \(\tau_k\) is the whole trajectory so far; each step \(i\) holds three parts: \(r_i\) is the reasoning the model wrote, \(tc_i\) is the tool call it made, and \(o_i\) is the observation that came back. A step with no tool call leaves \(tc_i\) and \(o_i\) empty.
\(\tau_k\) the trajectory \(r_i\) the reasoning \(tc_i\) the tool call \(o_i\) the observation
The paper writes this trajectory as its equation 1, in section 3.1.

2 The optimal number of calls

For each question and each model, there is an optimal number of tool calls: the smallest count that still reaches the right answer. It is not one number for the whole dataset. A question the model can answer from memory needs zero calls. A question about something new needs one or more. And a stronger model needs fewer calls than a weaker one on the same question.

A fixed recipe cannot set that number. Supervised fine-tuning teaches one policy for every question, so it cannot spend zero calls on one question and three on the next. Reinforcement learning can, because the reward depends on what this trajectory did: the same right answer earns more when it cost fewer calls.

Equation 2. The cheapest trajectory among the correct ones. Among all the ways to reach the right answer, take the one that calls the least.
\(\displaystyle \begin{aligned}&\arg\min_{\htmlClass{eqt sym-x}{\htmlStyle{color:var(--sym-x)}{\tau}}} \htmlClass{eqt sym-r}{\htmlStyle{color:var(--sym-r)}{\mathrm{Cost}}}(\htmlClass{eqt sym-x}{\htmlStyle{color:var(--sym-x)}{\tau}}) \\&\quad \text{subject to} \quad \htmlClass{eqt sym-x}{\htmlStyle{color:var(--sym-x)}{\mathcal{M}}}(\htmlClass{eqt sym-y}{\htmlStyle{color:var(--sym-y)}{q}}, \htmlClass{eqt sym-x}{\htmlStyle{color:var(--sym-x)}{\tau}}) = \htmlClass{eqt sym-r}{\htmlStyle{color:var(--sym-r)}{\hat{a}}}\end{aligned}\)
The cheapest correct trajectory wins. \(\mathcal{M}\) is the model, \(q\) is the question, and \(\hat{a}\) is the correct answer. \(\mathcal{M}(q, \tau)\) is the answer the model reaches by following trajectory \(\tau\). \(\mathrm{Cost}(\tau)\) counts the tool calls in \(\tau\). The line says: among all trajectories that reach the right answer, take the one with the smallest cost.
\(\tau\) a trajectory \(\mathrm{Cost}(\tau)\) the call count \(\mathcal{M}\) the model \(q\) the question \(\hat{a}\) the right answer
The paper writes this objective as its equation 2, in section 3.1.

The catch is that the optimal number is unknown before training. Nobody hands the model a budget per question. The next section shows how the reward estimates it from the model's own attempts.

3 Paying for efficiency

This section leans on the PPO page for the clipped objective and on the GRPO page for the group comparison. What it teaches is the one change efficiency forces on the reward.

3.1 The objective and the baseline reward

The training objective is the usual one: push the reward up, and keep the policy close to the reference it started from. The environment sits inside the rollout: the policy writes, the tools answer, and the policy writes again.

Equation 3. The KL regularized RL objective with the environment inside the rollout. Push the reward up, keep the drift from the reference small.
\(\displaystyle \begin{aligned}&\max_{\htmlClass{eqt sym-x}{\htmlStyle{color:var(--sym-x)}{\pi_\theta}}} \htmlClass{eqt sym-x}{\htmlStyle{color:var(--sym-x)}{\mathbb{E}}} \big[ \htmlClass{eqt sym-r}{\htmlStyle{color:var(--sym-r)}{r_\phi}}(\htmlClass{eqt sym-y}{\htmlStyle{color:var(--sym-y)}{q}}, \htmlClass{eqt sym-x}{\htmlStyle{color:var(--sym-x)}{y}}) \big] \\&\quad - \htmlClass{eqt sym-wait}{\htmlStyle{color:var(--sym-wait)}{\beta}}\, \htmlClass{eqt sym-wait}{\htmlStyle{color:var(--sym-wait)}{\mathbb{D}_{\mathrm{KL}}}} \big[ \htmlClass{eqt sym-x}{\htmlStyle{color:var(--sym-x)}{\pi_\theta}}(\htmlClass{eqt sym-x}{\htmlStyle{color:var(--sym-x)}{y}} \mid \htmlClass{eqt sym-y}{\htmlStyle{color:var(--sym-y)}{q}}; \htmlClass{eqt sym-p}{\htmlStyle{color:var(--sym-p)}{\mathcal{E}}}) \, \\&\quad \|\, \htmlClass{eqt sym-x}{\htmlStyle{color:var(--sym-x)}{\pi_{\mathrm{ref}}}}(\htmlClass{eqt sym-x}{\htmlStyle{color:var(--sym-x)}{y}} \mid \htmlClass{eqt sym-y}{\htmlStyle{color:var(--sym-y)}{q}}; \htmlClass{eqt sym-p}{\htmlStyle{color:var(--sym-p)}{\mathcal{E}}}) \big]\end{aligned}\)
The objective is a trade. \(\pi_\theta\) is the policy being trained; the average runs over questions and rollouts with the environment; \(r_\phi(q, y)\) is the reward for the rollout; \(\beta\) sets how strongly the drift penalty counts; \(\mathbb{D}_{\mathrm{KL}}\) is the KL divergence, a measure of how far the policy has drifted from the reference; \(\pi_{\mathrm{ref}}\) is the reference model; \(\mathcal{E}\) is the environment the policy calls tools in.
\(\pi_\theta\) the policy \(\mathbb{E}\) the average \(r_\phi\) the reward \(\beta\) the drift weight \(\mathbb{D}_{\mathrm{KL}}\) the drift measure \(\pi_{\mathrm{ref}}\) the reference \(\mathcal{E}\) the environment
The paper writes this objective as its equation 3, in section 3.2.

The baseline reward pays for one thing only: the right answer.

Equation 4. The correctness only baseline reward. One for the right answer, zero otherwise.
\(\displaystyle \begin{aligned}&\htmlClass{eqt sym-r}{\htmlStyle{color:var(--sym-r)}{r_\phi}}(\htmlClass{eqt sym-y}{\htmlStyle{color:var(--sym-y)}{q}}, \htmlClass{eqt sym-x}{\htmlStyle{color:var(--sym-x)}{y}}) = \htmlClass{eqt sym-r}{\htmlStyle{color:var(--sym-r)}{r_{\mathrm{correct}}}} = \\&\begin{cases} 1, & \text{if } \htmlClass{eqt sym-x}{\htmlStyle{color:var(--sym-x)}{a}} = \htmlClass{eqt sym-r}{\htmlStyle{color:var(--sym-r)}{\hat{a}}} \\ 0, & \text{otherwise} \end{cases}\end{aligned}\)
The baseline reward. \(r_\phi(q, y)\) is the reward for the rollout; \(a\) is the answer the model extracted from its response, and \(\hat{a}\) is the correct answer. The reward is 1 when they match and 0 otherwise. Nothing in it counts the calls.
\(r_\phi\) the reward \(a\) the model's answer \(\hat{a}\) the right answer
The paper writes this reward as its equation 4, in section 3.2.

That reward cannot tell a cheap right answer from an expensive one. A trajectory that searches three times and a trajectory that searches not at all earn the same, so training never learns to prefer the cheaper one.

3.2 The PPO form

PPO trains on one trajectory per question, so there is no group to compare with. The PPO form scores the call count directly, with a cosine curve that falls as the calls rise. The smooth constant \(c\) sets how fast it falls: a smaller \(c\) punishes extra calls faster, a larger \(c\) tolerates more of them.

Equation 5. The tool reward in the PPO form. More calls, less reward, on a falling cosine curve.
\(\displaystyle \htmlClass{eqt sym-r}{\htmlStyle{color:var(--sym-r)}{r_{\mathrm{tool}}}} = \cos\left(\frac{\htmlClass{eqt sym-x}{\htmlStyle{color:var(--sym-x)}{m}} \pi}{2\htmlClass{eqt sym-x}{\htmlStyle{color:var(--sym-x)}{m}} + \htmlClass{eqt sym-wait}{\htmlStyle{color:var(--sym-wait)}{c}}}\right)\)
The PPO tool reward. \(m\) is the number of tool calls in this trajectory, and \(c\) is the smooth constant that sets how fast the reward falls. With no calls the cosine is at its highest, and each extra call lowers it. A smaller \(c\) punishes extra calls faster; a larger \(c\) tolerates more of them.
\(r_{\mathrm{tool}}\) the tool reward \(m\) the call count \(c\) the smooth constant
The paper writes this reward as its equation 5, in section 3.3.

With no calls the reward is at its highest, and every call lowers it. The curve never rises again, so fewer calls always earn more under this form.

3.3 The GRPO form

GRPO trains on a group of trajectories per question, so the optimal count can be estimated from the group itself. Take the trajectories that reached the right answer, count their calls, and take the smallest. That minimum is \(n\), the local estimate of the optimal count. The estimate improves as training finds cheaper correct answers.

Equation 6. The tool reward in the GRPO form. The reward peaks at the optimal count and falls on both sides.
\(\displaystyle \begin{aligned}&\htmlClass{eqt sym-r}{\htmlStyle{color:var(--sym-r)}{r_{\mathrm{tool}}}} = 1, \text{ if } \htmlClass{eqt sym-x}{\htmlStyle{color:var(--sym-x)}{m}} = \htmlClass{eqt sym-y}{\htmlStyle{color:var(--sym-y)}{n}} = 0, \\&\cos\left(\frac{\htmlClass{eqt sym-x}{\htmlStyle{color:var(--sym-x)}{m}} \pi}{2\htmlClass{eqt sym-x}{\htmlStyle{color:var(--sym-x)}{m}} + \htmlClass{eqt sym-wait}{\htmlStyle{color:var(--sym-wait)}{c}}}\right), \text{ if } \htmlClass{eqt sym-y}{\htmlStyle{color:var(--sym-y)}{n}} = 0, \\&\sin\left(\frac{\htmlClass{eqt sym-p}{\htmlStyle{color:var(--sym-p)}{f}}(\htmlClass{eqt sym-x}{\htmlStyle{color:var(--sym-x)}{m}}, \htmlClass{eqt sym-y}{\htmlStyle{color:var(--sym-y)}{n}}) \pi}{2\htmlClass{eqt sym-y}{\htmlStyle{color:var(--sym-y)}{n}}}\right), \text{ else}, \\&\htmlClass{eqt sym-p}{\htmlStyle{color:var(--sym-p)}{f}}(\htmlClass{eqt sym-x}{\htmlStyle{color:var(--sym-x)}{m}}, \htmlClass{eqt sym-y}{\htmlStyle{color:var(--sym-y)}{n}}) = 0, \text{ if } \htmlClass{eqt sym-x}{\htmlStyle{color:var(--sym-x)}{m}} = \htmlClass{eqt sym-y}{\htmlStyle{color:var(--sym-y)}{n}} = 0, \\&\htmlClass{eqt sym-x}{\htmlStyle{color:var(--sym-x)}{m}}, \text{ if } \htmlClass{eqt sym-y}{\htmlStyle{color:var(--sym-y)}{n}} = 0, \\&\frac{2\htmlClass{eqt sym-y}{\htmlStyle{color:var(--sym-y)}{n}}\htmlClass{eqt sym-x}{\htmlStyle{color:var(--sym-x)}{m}}}{\htmlClass{eqt sym-x}{\htmlStyle{color:var(--sym-x)}{m}} + \htmlClass{eqt sym-y}{\htmlStyle{color:var(--sym-y)}{n}}}, \text{ else}.\end{aligned}\)
The GRPO tool reward. \(n\) is the optimal count, estimated as the smallest call count among the group's correct trajectories, and \(m\) is the call count in this trajectory. \(f(m, n)\) remaps \(m\) onto the range from zero to twice \(n\). The sine peaks when \(m\) equals \(n\), so the highest reward goes to the trajectory that uses exactly the optimal count. Falling short of \(n\) or going over it both earn less. When \(n\) is zero, the form falls back to the cosine curve of Equation 5.
\(r_{\mathrm{tool}}\) the tool reward \(n\) the optimal count \(m\) the call count \(f(m, n)\) the remap \(c\) the smooth constant
The paper writes this reward as its equation 6, in section 3.3.

The sine curve peaks exactly at the optimal count: when the call count \(m\) equals \(n\), the reward is at its highest. Going over costs, and falling short costs too, because a trajectory that skips a needed call earns less than one that makes it.

3.4 The final reward

The tool reward does not add to the correctness reward. It multiplies it.

Equation 7. The final reward as efficiency times correctness. The tool reward scales the correctness reward, never replaces it.
\(\displaystyle \htmlClass{eqt sym-r}{\htmlStyle{color:var(--sym-r)}{r^{\mathrm{tool}}_\phi}}(\htmlClass{eqt sym-y}{\htmlStyle{color:var(--sym-y)}{q}}, \htmlClass{eqt sym-x}{\htmlStyle{color:var(--sym-x)}{y}}) = \htmlClass{eqt sym-wait}{\htmlStyle{color:var(--sym-wait)}{\alpha}}\, \htmlClass{eqt sym-r}{\htmlStyle{color:var(--sym-r)}{r_{\mathrm{tool}}}}\, \htmlClass{eqt sym-r}{\htmlStyle{color:var(--sym-r)}{r_\phi}}(\htmlClass{eqt sym-y}{\htmlStyle{color:var(--sym-y)}{q}}, \htmlClass{eqt sym-x}{\htmlStyle{color:var(--sym-x)}{y}})\)
The whole reward for one rollout. \(\alpha\) is a scale on the tool reward, and the paper sets it to 1. \(r_{\mathrm{tool}}\) is the efficiency part from Equation 5 or 6, and \(r_\phi\) is the correctness part from Equation 4. A wrong answer makes \(r_\phi\) zero, which zeroes the whole reward; a right answer is scaled by how efficiently it was reached.
\(r^{\mathrm{tool}}_\phi\) the final reward \(\alpha\) the scale \(r_{\mathrm{tool}}\) the efficiency part \(r_\phi\) the correctness part
The paper writes this reward as its equation 7, in section 3.3.

Multiplication is what stops the cheating. A wrong answer zeroes the whole reward, however few calls it used, so the model cannot earn by calling less and answering wrong. An added reward was tried, and the model earned by calling less without a correct answer. The multiplied form pays for efficiency only when the answer is right.

4 Tool productivity

A reward per trajectory does not say how efficient a model is across a whole test set. Tool productivity is the paper's answer: right answers divided by tool calls, counted over every question.

Equation 8. Tool productivity. Right answers per tool call, across the whole test set.
\(\displaystyle \begin{aligned}&\htmlClass{eqt sym-y}{\htmlStyle{color:var(--sym-y)}{\mathrm{TP}}} = \sum_{i=1}^{\htmlClass{eqt sym-x}{\htmlStyle{color:var(--sym-x)}{N}}} \htmlClass{eqt sym-r}{\htmlStyle{color:var(--sym-r)}{\mathbb{I}}}\{\htmlClass{eqt sym-x}{\htmlStyle{color:var(--sym-x)}{y_i}} = \htmlClass{eqt sym-x}{\htmlStyle{color:var(--sym-x)}{\hat{y}_i}}\} \\&\quad \Big/ \sum_{i=1}^{\htmlClass{eqt sym-x}{\htmlStyle{color:var(--sym-x)}{N}}} \htmlClass{eqt sym-p}{\htmlStyle{color:var(--sym-p)}{tc_i}}\end{aligned}\)
Tool productivity over a test set. \(N\) is the number of questions; \(y_i\) is the right answer to question \(i\), and \(\hat{y}_i\) is the answer the model gave; the indicator \(\mathbb{I}\) is 1 when they match and 0 otherwise, so the top counts the right answers; \(tc_i\) is the number of tool calls the model used on question \(i\), so the bottom counts all the calls. More right answers per call means higher productivity.
\(\mathrm{TP}\) tool productivity \(N\) the question count \(\mathbb{I}\) the match indicator \(tc_i\) calls on question i
The paper defines this metric in section 4.1.

A model that answers more questions per call is more productive, even if another answers slightly more overall. 5 Practice

Each question costs the calls the model still makes, fewer than the baseline, at training and at inference. Training gets cheaper too, with less waiting on tools and shorter answers.

The final reward is efficiency times correctness (paper section 3.3), with the scale set to 1 and the smooth constant set to the maximum turns (paper section 4.1).

The paper releases no official implementation. The method needs only minimal changes to the standard reinforcement learning pipeline (paper section 1), and it reuses the Search-R1 and ToRL settings (paper section 4.1), which the Search as a Tool and ToRL pages teach.

6 Failure modes

Four failures cover most of what goes wrong, each with a cause, a visible symptom, and a fix.

6.1 Calling less without answering right

Cause: the efficiency reward pays for fewer calls, so a model can chase the efficiency part and neglect the answer. Symptom: the reward climbs while the answers get worse. Fix: the multiplied final reward (paper section 3.3), which zeroes the reward when the answer is wrong.

6.2 Skipping a tool the question needs

Cause: the penalty for calls pushes the model to answer from memory even when memory is not enough. Symptom: wrong answers on questions that a single search would have settled. Fix: the optimal count is per question, so a needed call still earns the peak reward when the group minimum says the question needs it (paper section 3.3).

6.3 A rough optimum early in training

Cause: the optimal count is only estimated from the group minimum, and early groups may never find the cheapest correct answer. Symptom: the reward peaks at the wrong count, and the model is pushed toward too many or too few calls. Fix: update the estimate across epochs as cheaper correct answers appear (paper section 3.3), and use the global approximation, the estimate refined across epochs, which the paper finds more stable (paper section 4.1).

6.4 A mis-set penalty

Cause: the smooth constant \(c\) is set without regard to the task. Symptom: a \(c\) that is too small punishes needed calls and starves the model of tools, while a \(c\) that is too large tolerates overuse and the calls creep back. Fix: set \(c\) to the maximum turns the task allows (paper section 4.1).
