Uncertainty Weighting

Set each task's loss weight from the data's noise. Noisy tasks count less, automatically.

On the GradNorm page I set each task's loss weight, its volume, by watching training dynamics. Here I set them from the data itself: some tasks are just noisier than others, and a noisy task should count less. The model learns exactly how much less.

Hand-tuning the weights is slow and costly

Take scene understanding on Cityscapes, a benchmark dataset of street scenes: one monocular (one camera) image in, three tasks out. Per-pixel depth is a regression task, which means it predicts a number on a scale, how far away each pixel is. Instance segmentation, telling individual objects apart pixel by pixel, is regression too: for each pixel the model predicts an arrow pointing to the center of the object it belongs to. Semantic segmentation, labeling every pixel by what it shows, is a classification task, which means it picks which label fits. Different units, different scales, one shared representation, meaning one learned picture of the image that all three tasks read from.

The problem is that the loss weights strongly affect performance, and tuning them by hand is a difficult and expensive process. That can make multitask learning prohibitive in practice.

The way out, proposed by Kendall and colleagues in 2018 when they introduced uncertainty weighting, is to derive the weights from how uncertain each task is, instead of guessing them. One number per task, its task uncertainty, is learned as a parameter during training, and it tells the model how much to trust each loss.

Set how loud each loss is, before touching gradients

GradNorm sets the loss weights from the size of each task's gradient, the arrow that says how each shared parameter should move to lower that task's loss. It measures those sizes during training, watching who falls behind. Uncertainty weighting also sets how loud each loss is, but it reads a different signal, how noisy each task's data is, and it never measures a gradient. It answers with a principle from probabilistic modeling, which treats each task's output as a probability spread over possible answers rather than one fixed answer: a loss that is inherently noisier should count less.

Turn down the tasks you can't trust

Think of each task's output as a measurement. Some measurements are crisp: given the same image, the right answer barely changes. Others are inherently fuzzy: predicting the exact depth of every pixel has a floor of guesswork no model can beat, because the information simply is not in the image. That irreducible fuzziness is task uncertainty: one learned number per task, bigger means noisier. A task with high uncertainty is one where even a perfect model would still spread probability over several answers.

If a task is that noisy, pushing hard on its loss is partly pushing on noise: the model chases fluctuations it cannot remove. So turn the volume down on exactly those tasks, by an amount tied to how noisy they are. Each task gets a weight that shrinks as its noise grows, quadratically: a task twice as noisy counts four times less. The noise levels are learned as parameters during training, not set by hand.

Then each task pays a small honesty price for claiming to be noisy. The model may quiet a task, but it pays a price for the privilege, so it only quiets tasks that truly are noisy. Without the price, the cheapest move would be inflating every noise level to infinity and paying nothing. And a confident task gets a small rebate for claiming to be easy.

The noisier a task is, the smaller its weight

One training step, priced in two forms: each task's loss is discounted by its learned noise, plus an honesty price that keeps the noise honest. The first line is regression, the second classification.
L = Σi (Li2σi² + log σi)
The total bill L is Σi, the sum over all tasks i, of two parts per task. The first part is task i's loss Li, how wrong task i is, divided by twice its squared noise, where σi (read as sigma) is task i's learned noise level. So the noisier task gets the smaller share, and a task twice as noisy counts four times less. The second part is log σi, the honesty price. Log is the logarithm. It grows far more slowly than the noise itself, and it goes negative when the noise is below 1, which is the small rebate a confident task gets.
L ≈ Σi (Liσi² + log σi)
The classification line is an approximation, so it uses ≈, approximately equal: Kendall and colleagues reach it with a simplifying step that is exact only when σi is 1. It reads the same way as the first line, and only the denominator changes: the factor of one half belongs only to regression, so in this line the classification weight is double the same-sigma regression weight. The honesty price log σi works the same for both. Σi again names the sum over all tasks.

The depth-noise slider tool prices depth and instance by the regression line and semantics by the classification line. Only depth's noise moves, and the other two keep fixed noise levels, σ = 0.70 for semantics and σ = 1.50 for instance. The bars show each task's discounted loss as a share of the three discounted losses added together; the honesty prices count toward the total bill but not toward those shares.

One training step: measure, price, learn

One training step ends with one backward pass, the pass that works out a gradient for every parameter, showing which way each one should move to lower the total, and then an optimizer step, where the optimizer is the routine that applies those updates to the parameters. The listing keeps each task's noise in log form, as log σ, the logarithm of that task's σ. Kendall and colleagues store log σ² instead, which is the same number doubled. The exponential function undoes the log, so applying it to twice log σ gives σ squared back, and log σ itself is what the total line adds as the honesty price.

# log_sigma = learnable vector, one entry per task, init 0
# (regression form shown; classification uses w_i = 1 / sigma2, no 1/2)
total = 0
for i in range(K):
    sigma2 = exp(2 * log_sigma[i])   # sigma_i^2, always positive
    w_i = 1 / (2 * sigma2)           # the volume knob, the task's loss weight
    total += w_i * losses[i] + log_sigma[i]  # loss + the honesty price
backward(total)   # one pass updates network AND log_sigma
step(optimizer)   # network and sigmas learn together

There is no separate tuning loop. The method adds one learned noise level per task to the loss, and those noise levels get their gradients from the same backward pass as the network.

Task uncertainties fall fast, then keep drifting down

Kendall and colleagues trained one network on the three Cityscapes tasks for a hundred thousand iterations, where one iteration is one training step. Each task gets one column of the figure: the top plot tracks its loss, and the bottom plot tracks its learned uncertainty, plotted as σ², the noise level squared. All three uncertainties fall fast early in training and then keep drifting down slowly for the rest of the run; the instance task's keeps falling the longest. Nobody set them by hand.

The paper's caption for the whole figure reads “Learning task uncertainty. These training plots show the losses and task uncertainty estimates for each task during training. Results are shown for the final model, trained on the fullsize CityScapes dataset.”

Sigma absorbs loss scale and sets the effective learning rate

Uncertainty weighting acts through the loss, before the backward pass, and one optimizer step then trains the network and the log sigmas together. Sigma absorbs a change in a loss's scale. A batch is the small group of training examples used for one step, and a loss can average over the batch's examples, a batch mean, or add them up, a batch sum, which is larger by the number of examples. In the regression form the best sigma squared equals the loss, so switching a loss from a batch mean to a batch sum grows its sigma to match, and the weighted term stays the same.

As a task's sigma drifts down, its weight rises. Under SGD, stochastic gradient descent, each parameter steps by the learning rate, a step size set by hand, times its gradient. The task's weight multiplies its gradient, so that task's effective learning rate, the learning rate times its weight, rises with it.

Gradient Balancing Inside the Training Loop works through these effects, and what Adam (an optimizer that scales each parameter's step by its own running gradient size) and weight decay (a pull that shrinks every learned number a little each step) do to the log sigmas, in its sections “As sigma falls, a task's effective learning rate rises under SGD” and “Weight decay skips the balancer, unless it decays the balancer's own numbers”.

When weighting is enough, and when it isn't

Step back. GradNorm and uncertainty weighting are both scale methods: they change how loud each loss is, never what the gradients say. GradNorm learns the volumes from training dynamics, boosting whichever task falls behind. Uncertainty weighting sets them from the data, turning down whichever task is inherently noisy. Both were tested against fixed weights found by search, training with many candidate weight sets and keeping the best. Kendall and colleagues trained on the three Cityscapes tasks at a reduced image size and compared uncertainty weighting with an equal-weight sum and with near-optimal fixed weights from a grid search, which tries candidate values on a systematic grid; uncertainty weighting scored better than both on all three tasks. Chen and colleagues, who introduced GradNorm, instead drew 100 sets of random fixed weights and trained one network with each on NYUv2, a dataset of indoor scenes, with depth, surface normals (the direction each surface faces) and room layout keypoints (the corners where walls, floor and ceiling meet) as the tasks, and the best of them still fell short of GradNorm.

Uncertainty weighting can also be stacked with a steering method, because it only ever sees losses. Weight the losses by learned uncertainty, then run a steering method on the resulting gradients, such as PCGrad, which cuts the part of one task's gradient that fights another, or CAGrad, which favors the worst-off task in each step. The learned noise levels handle scale while the steering method handles direction.

And that is the boundary. Neither weighting method fixes direction. Two tasks can be perfectly weighted by noise and still have gradients that point against each other. Uncertainty weighting never looks at gradients at all; GradNorm measures only their lengths, never their angles. GradNorm also has no proof that training settles to a stable end point, and equal loudness does not mean the tasks agree.

The Pareto front is the curve of trade-offs where no task can get better without another task getting worse, so a run that lands on it has no free improvement left for any task. The two weighting methods, the volume knobs that learn each task's loss weight (GradNorm and Uncertainty Weighting), the three steering methods (PCGrad, GradVac, and CAGrad), and MGDA, which lands on the Pareto front, side by side:

MethodThe question it answers
GradNormHow loud should each task be, to keep progress balanced? (learned, driven by training dynamics)
Uncertainty Weighting (this page)How loud should each task be, given how noisy it inherently is? (learned, driven by the data)
PCGradHow should the directions be edited so tasks stop fighting?
GradVacHow should each pair of tasks be nudged back to the agreement level where it learns best?
CAGradHow do we protect the worst-off task and stay near the average, with a guarantee?
MGDAWhat direction helps every task at once, and where does the run land on the Pareto front?

The volume knobs are balanced. But what if the directions themselves fight? That is the PCGrad page's question.
