Q-learning uses each real step once, then throws it away. Dyna-Q also writes each real step into a model: a table of “here, this move, gave this reward and led there”. After every real step it replays a few remembered steps from the model through the same Q-learning update. The reward found at the charging dock spreads back across the floor in a few trips instead of many. The model must stay right: if the floor changes, stale memories mislead the robot.

1 Each real experience is used once

Q-learning, the method of the Q-Learning page, learns from each real experience once and then throws it away, so learning a route takes a long time.

The running example is the warehouse robot again, on a floor laid out like the maze in the book.

A few short rows of shelving racks stand on the floor as walls.

The agent is the learner that picks the moves. (RL Basics) A state is the agent’s situation right now; a move, or action, is one choice the agent can make in a state; a reward is the number the world hands back after each move, good or bad. (RL Basics)

Here the robot is the agent: the floor is a grid of cells, and each move takes the robot one cell.

The robot starts in the start bay, on the left edge of the floor, and the dock sits in the far corner.

A real step is one move made in the real world, with the reward and the next state it brings.

On this floor the racks block the way, steps cost nothing, only reaching the dock pays, and there is no ledge, as in the textbook’s maze; the floor of the Q-Learning page charged battery for every move and had a ledge.

An episode is one run from the start until it ends. (RL Basics) A trip is one episode, from the start to the goal. Here the goal is the dock.

In the textbook’s maze the first trips wander a long time before the robot finds it.

The return is all the reward still to come, with later rewards counted a little less. (RL Basics) The discount \(\gamma\) sets how much a reward one step later still counts. (RL Basics)

Because later rewards count a little less, the dock is worth more when it is reached sooner, so short routes win.

A move’s value \(Q(s,a)\), also called its score, is the return the agent expects if it makes move \(a\) in state \(s\) and plays on from there. (RL Basics) A Q-table keeps one score for every state and move. (Q-Learning)

Each score in the table is the robot’s current guess of that move’s value \(Q(s,a)\); after each real step, Q-learning’s update nudges the stored score of the move just made toward what the step showed.

The score moves back one cell per real visit, so many trips pass before the dock’s reward spreads back as scores to the start bay.

Dyna-Q finds a route with far fewer real experiences.

2 Remembering and replaying steps

Epsilon-greedy usually plays the top-scored move and, with chance \(\epsilon\), a random one instead. (RL Basics)

The robot picks every real move this way.

A model is the agent’s learned guess of where a move leads and what it pays. (Value-Based RL) Planning means using a model to try moves in imagination instead of in the real world. (Model-Based RL)

A Dyna planning step replays a remembered step from the model through the same Q-learning update, as if it happened again.

That update is the nudge described above, written out in full in the Q update card below.

After each real step the robot writes down where the move led and what it paid, under that cell and move; on this floor the same move from the same cell always gives the same result, so one entry per cell and move is enough.

Then it picks cells and moves it has already tried, looks up what happened, and nudges their scores as if it had made those steps again.

In Figure 1 these written-down steps fill the box “memory of steps”, and real and remembered steps both feed the box “learn from it”.

An imagined step is one move tried inside the model. (Model-Based RL)

In Dyna-Q each imagined step is one remembered step replayed.

Figure 3 shows one replay carrying the dock’s score one cell further back.

The number of imagined steps per real step is written \(n_{\text{plan}}\); the book writes \(n\).

Raising it carries the dock’s reward back faster for each real step, at more computing, and with none Dyna-Q is plain Q-learning.

3 The Q update and the model update

Q-learning’s target is the step’s reward plus the discounted best score in the next state. (Q-Learning) Bootstrapping means putting your own current guess for the next state inside the target. (Actor-Critic)

On a planning step the same guess of the next cell comes from the model’s remembered landing cell, so the second line of the card below serves real and remembered steps alike.

The TD (temporal difference) error \(\delta\) is how much one step surprised the agent, the target minus the current guess. (RL Basics) The learning rate \(\eta\) sets how big a step each update takes. (RL Basics)

Each real step nudges one table entry by a learning-rate share of its TD error.

5 Dyna-Q in NumPy

One Dyna-Q step on the warehouse floor. env_step(s, a) is the real floor; it returns the reward, the next cell and whether the robot reached the dock.

import random
import numpy as np

ROWS, COLS = MAZE_ROWS, MAZE_COLS
eta, gamma = LEARNING_RATE, DISCOUNT
epsilon, n_plan = EXPLORATION, N_PLAN
Q = np.zeros((ROWS * COLS, N_MOVES))
model = {}
# start bay: the square where the robot starts
s = START_SQUARE
  1. 1The setup: the Q-table starts at zero, the model starts empty, and the settings come from the book. The settings are in the table under Dyna-Q in practice.
# one real step
if random.random() < epsilon:
    a = random.randrange(4)
else:
    a = int(np.argmax(Q[s]))
r, s_next, done = env_step(
    s, a)
future = (0.0 if done else
    gamma * Q[s_next].max())
Q[s, a] += eta * (r
    + future - Q[s, a])
  1. 1The Q update card, lines 1 to 4 (a step that reached the dock leaves out line 2).
# remember the step
model[(s, a)] = (
    r, s_next, done)
s = s_next
  1. 1Line 1 of the model card.
# planning: replay steps
for _ in range(n_plan):
    s_, a_ = random.choice(
        list(model))
    r_, s2_, d_ = model[
        (s_, a_)]
    fut = (0.0 if d_ else
        gamma * Q[s2_].max())
    Q[s_, a_] += eta * (r_
        + fut - Q[s_, a_])
  1. 1Lines 2 to 4 of the model card, \(n_{\text{plan}}\) times.

7 Dyna-Q in practice

Every real step gives one real update and then the planning updates, so the robot learns from each real step many times over. The robot carries two tables: the Q-table of scores and the model table of remembered steps.

Table 1. Settings of the book’s maze (Sutton and Barto, Example 8.1)
SettingValueRaising itLowering it
Learning rate \(\eta\)0.1Learns faster from each step but jumps around moreSteadier but slower; the dock’s reward spreads back more slowly
Discount \(\gamma\)0.95Later rewards count for more, so a far-off dock still pullsOnly near rewards matter; the robot grows shortsighted
Exploration \(\epsilon\)0.1More exploring; the robot tries new moves more oftenLess exploring; the robot mostly repeats its best move so far
Imagined steps per real step \(n_{\text{plan}}\)0, 5, 50More imagined steps per real step; faster learning at more computingFewer imagined steps; closer to plain Q-learning
Maze6 by 9, with walls, start and goalMaking the floor bigger, or adding walls, takes more trips to learnA smaller floor is learned in fewer trips
Runs averaged30 runsAveraging more runs smooths the curvesFewer runs leave the curves noisier

The model is a dict keyed by cell and move: each entry holds the reward and the next cell that move gave. Planning samples only pairs already seen, never a move never tried, and uses the same learning rate for real and imagined updates. A remembered step that reached the dock leaves out the second line of the Q update card above, the same rule as for a real step onto the dock.

7.1 Planning steps against trips to the dock

The book runs the maze with each setting of \(n_{\text{plan}}\) and repeats every run many times.

With planning a good route forms within a few trips instead of many.

8 When a table model is enough

Dyna-Q suits a small floor with a countable set of cells, rules that are unknown but do not change, and real steps that cost more than computing.

Against Q-learning it reaches the same answer with far fewer real steps.

A Q-network is a neural network that takes the state and outputs one score per move, in place of the table. (Deep Q-Networks)

The Deep Q-Networks page uses one so it can learn from large inputs such as screens.

Dyna-Q needs a table, and for large inputs its model must be a network too.

9 Stale and noisy models

The book’s fix for a changed floor is Dyna-Q+, which adds a small bonus in its planning updates for moves not tried for a long time.

So the robot goes back now and then and re-checks old aisles.
