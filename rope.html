Turn each query and key by its position, and the score depends only on how far apart the two tokens are. RoPE runs in every attention layer on every forward pass, in training and generation, and carries nothing between steps except the fixed turning speeds. One rotation per query and key in every attention layer, done as an elementwise multiply and add over the \(d\) coordinates with no added weights.

A query is what a token looks for, a key is what another token offers; the score between them is their dot product, which multiplies matching entries and adds them.

1 The score should depend on the gap, not the address

Take the words "not" and "good" in a review: "not" two words before "good" means the same thing wherever the pair sits in the sequence, early or late. An encoding that adds a position vector to each token cannot promise that: the same pair at two addresses gets two different vectors. RoPE encodes the absolute position with a rotation matrix and at the same time puts the relative distance into the attention score.

That is the idea the next section builds: turn each query and key, and let the turns cancel except for the gap.

2 One turning speed per pair

Each pair of coordinates in a query or key gets its own turning speed, fastest for the first pair and ever slower after, the same fast-to-slow spread as the sinusoidal encoding's pairs.

A turning speed for each pair.
\(\displaystyle \htmlClass{eqt}{\htmlData{k=theta}{\htmlStyle{color:#117a65}{\theta_{p}}}} = 10000^{-2(p-1)/d}\)
Each pair of coordinates gets its own turning speed \(\theta_{p}\), in radians per position. \(d\) is the query or key size, so there are \(d\)/2 pairs.
\(\displaystyle \htmlClass{eqt}{\htmlData{k=pair}{p = 1, 2, \dots , d/2}}\)
The pair index runs over all \(d\)/2 pairs. The first pair turns fastest; later pairs turn ever slower.

The base sets every pair's turn per position. A larger base turns every pair after the first slower, so the relative turn between two positions grows more slowly with distance and the score decays less, so far pairs stay alike and the effective reach is longer; a smaller base turns faster and wraps sooner. At base 1 every pair turns alike; at infinite base every pair but the first stops turning, so only one fast pair carries position and the pattern repeats after a full turn. Default 10000, the same constant that sets the slowest wave of the sinusoidal encoding; rope_theta in Hugging Face.

3 Rotate the query and the key, then take the score

The rotation matrix \(R_{m}\) is block diagonal, blocks down the diagonal with zeros elsewhere: each pair turns by \(m\) times its speed, and the matrix is orthogonal, so turning keeps every vector's length and only turns it (RoFormer section 3.2.2, eq 15 and eq 16). The two rotations combine into one rotation by the gap, so the same pair scores the same wherever it sits.

The score after rotation.
\(\displaystyle (\htmlClass{eqt}{\htmlData{k=rotq}{\htmlStyle{color:#1f618d}{R_{m}}\htmlStyle{color:#7d3c98}{q}}}) \htmlClass{eqt}{\htmlData{k=dot}{\cdot}} (\htmlClass{eqt}{\htmlData{k=rotk}{\htmlStyle{color:#1f618d}{R_{n}}\htmlStyle{color:#a04000}{k}}})\)
The query at position \(m\) and the key at position \(n\), each turned by its own rotation, and the dot between them is the score: it multiplies matching entries and adds them, so a key that lines up with the query scores high. \(R_{m}\) turns every pair \(p\) of the query by \(m\) times \(\theta_{p}\); \(R_{n}\) does the same for the key.
\(\displaystyle = \htmlStyle{color:#7d3c98}{q}^{\htmlClass{eqt}{\htmlData{k=transpose}{\htmlStyle{color:#7d3c98}{T}}}} \htmlStyle{color:#1f618d}{R_{n-m}} \htmlStyle{color:#a04000}{k}\)
The score after rotation depends only on how far apart the two tokens are. The two rotations combine into one rotation by the gap \(n - m\), so the same pair scores the same wherever it sits. The raised \(T\) is the transpose: it turns the query column into a row so the dot product can be written as a matrix product. This line shows the rotation part only; the full score carries the \(W_{q}\) and \(W_{k}\) projections and the \(1/\sqrt{d}\) scaling (RoFormer eq 2 and eq 16).

Values carry no position information: the paper rotates queries and keys only, so a layer's output holds no explicit position (ALiBi paper section 2.2, describing RoPE).

5 The rotation at work

Figure 3. Moving both arrows keeps the angle and the score; moving only the key changes the gap and the score.

Both moved together, so the gap between them stays the same.

Far pairs can still score high in principle. The paper's section 3.3 states the long-term decay property loosely, that the inner product decays as the relative position grows, and refers to section 3.4.3 for the proof. What section 3.4.3 proves is that the average size of the bound terms decays as the relative distance grows. That caps how large a far pair's score can be; it does not prove that every score falls smoothly with distance, since the score itself is a sum of cosines that oscillates with distance.

RoPE as Hugging Face's Llama code writes it; shape (\(B\), \(h\), \(T\), \(d_{k}\)) goes in and comes out. This is the form in modeling_llama.py. 

import torch
import torch.nn.functional as F

B, h, T, d_k, BASE = BATCH, HEADS, SEQ_LEN, HEAD_DIM, ROPE_BASE
inv_freq = BASE ** -(torch.arange(0, d_k, 2) / d_k)
angles = torch.arange(T)[:, None] * inv_freq  # (T, d_k/2)
emb = torch.cat((angles, angles), dim=-1)     # (T, d_k)
cos, sin = emb.cos(), emb.sin()
  1. 1Block A, step 1: The speeds \(\theta_{p}\), one per pair, times each position, eq card in Section 2, line 1.

The rotation below is the efficient realization: x times cos plus rotate_half(x) times sin (RoFormer section 3.4.2, eq 34, which pairs neighbouring coordinates). 

def rotate_half(x):
    x1, x2 = x.chunk(2, dim=-1)
    return torch.cat((-x2, x1), dim=-1)

q, k, v = torch.randn(3, B, h, T, d_k)
q = q * cos + rotate_half(q) * sin
k = k * cos + rotate_half(k) * sin
  1. 1Block B, step 1: Pairs coordinate \(c\) with \(c + d_{k}/2\) and turns each pair a quarter turn, part of the rotation \(R_{m}\), eq card in Section 3, line 3.
  2. 2Block B, step 2: Rotates \(q\) and \(k\) by their positions, eq card in Section 3, line 3.

Where it is used: GPT-J uses the rotary method (ALiBi paper section 4); Llama uses it in Hugging Face form.

6 Failure modes and tips

The Hugging Face pairing and the RoFormer pairing differ: Hugging Face pairs coordinate \(c\) with \(c + d_{k}/2\), RoFormer pairs neighbours. Loading a checkpoint with the wrong pairing scrambles every score, so keep the checkpoint's pairing.

A base of 1 turns every pair alike, so the encoding loses its fast-to-slow spread and distant pairs wrap onto near ones. Keep the default unless a paper you are following ablates it.

Rotating the values too would put position into every layer output, which the paper deliberately avoids. Rotate queries and keys only.

Check rope_theta in the config before loading a checkpoint; check the pairing function matches the checkpoint.
