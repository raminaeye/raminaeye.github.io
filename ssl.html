Self-Supervised Learning

You know me, I am gonna talk about learning without labels now! How do you teach a model when you have no labels and labeling would cost you a fortune?

Labels are expensive, but unlabeled data has structure

An encoder is a network that turns an input, such as a photo, into a list of numbers, a vector; that vector is the input's embedding. A good encoder puts photos of similar things at nearby embeddings.

You can download a million images in an afternoon; labeling them takes months. Labels are expensive. Structure is free. Self-supervised learning (SSL) trains the encoder on the unlabeled pile alone and brings in a small labeled set only at the end.

Pretext tasks turn unlabeled data into questions with answers

With no labels, the question has to come out of the data. Doersch and colleagues call such a made-up question a pretext task: its answer is hidden in the data, and the encoder can only answer it well by learning what the data shows.

CPC (Contrastive Predictive Coding) predicts the vectors of later steps of a sequence such as speech, not the raw samples. SimCLR (a simple framework for contrastive learning) matches each image's two views against the other images in the same batch, the group processed together in one step. MAE (masked autoencoder) hides most of an image's patches and rebuilds their pixels.

Most methods here build the question from views. An augmentation is a random edit of an input (crop, recolor, blur), and a view is the edited copy it produces. Two views of one photo look different but show the same thing.

Three families of methods learn without labels

When the question is "same photo?", the two views form a positive pair and views of other images are negatives. Pulling positives together hides a trap: an encoder that outputs one vector for every input matches every pair and has learned nothing. That failure is collapse, and the families differ in how they stop it.

  • Contrastive methods also push negatives away, so one shared vector costs loss.
  • Non-contrastive methods use no negatives at all. One branch learns to match a second branch, the target, which the match itself never changes: a slowly updated copy of the encoder in some methods, the same encoder with training cut off on that side in others.
  • Masked modeling hides part of the input and rebuilds it; a constant output rebuilds nothing.

A quieter collapse, embeddings spread along only a few directions, is on Self-Supervised Learning Failure Modes and Checks with the other ways SSL breaks.

A linear probe measures what a frozen encoder learned

After pretraining I still need a number for how good the embeddings are. The standard check is a linear probe: freeze the encoder, so its weights no longer change, and train one linear layer on top to predict the labels. If one straight cut separates the classes, the encoder already sorted the images by content.

The linear probe, a frozen encoder followed by one trainable linear layer.
h = f(x)
Read it as: the embedding h is the frozen encoder f applied to the image x, so h is fixed for each image.
ŷ = softmax(Wh + b)
Read it as: the weight matrix W and bias vector b give one score per class, and softmax turns the scores into probabilities ŷ (y-hat) that add up to 1; only W and b train.

In the listing, the first line after the import freezes f and clf holds W and b. The cross-entropy loss is small when the true class gets a high probability, and it applies the softmax itself. lr is the learning rate, how big each weight update is.

import torch, torch.nn.functional as F
encoder.eval().requires_grad_(False)          # freeze the pretrained encoder
clf = torch.nn.Linear(feat_dim, num_classes)  # the only layer that trains
opt = torch.optim.SGD(clf.parameters(), lr=lr)
for x, y in labeled_loader:
    with torch.no_grad():
        h = encoder(x)                        # frozen features
    loss = F.cross_entropy(clf(h), y)
    opt.zero_grad(); loss.backward(); opt.step()

Fine-tuning instead trains every weight, the encoder included, so the features themselves move; semi-supervised fine-tuning does it with labels on only 1% or 10% of the training images. Here are a probe and fine-tuning on 24 toy embeddings of two classes.

Self-supervised features come close to supervised ones

Every row pretrains a ResNet-50 encoder (a 50-layer image network) on ImageNet (about 1.28 million photos in 1000 classes) without labels, then trains a linear probe with all the labels and reports top-1 accuracy, the share of test images whose most likely class is right. SimCLR and BYOL pretrained for 1000 epochs (passes over the training set), MoCo v2 for 800; the supervised row is a ResNet-50 trained with labels for 90 epochs.

Linear probe, ImageNet top-1, ResNet-50
MethodImageNet top-1
Supervised: trained with labels (reference)76.5%
SimCLR: two views, other images as negatives (batch 4096)69.3%
MoCo v2 (Momentum Contrast): negatives from a queue of past batches (batch 256)71.1%
BYOL (Bootstrap Your Own Latent): a slowly updated copy as target, no negatives (batch 4096)74.3%

BYOL never saw a label in pretraining, yet one linear layer on its frozen features lands about two points below the supervised row (against the stronger 78.9% supervised baseline BYOL also cites, the gap is wider).

With labels on only 1% of ImageNet, fine-tuning the BYOL encoder reaches 53.2% top-1, against 25.4% for a ResNet-50 trained on that same 1% alone. That is the real use case: pretrain on the unlabeled mountain, label a thimbleful, fine-tune.
