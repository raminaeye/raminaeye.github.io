Regularization: Methods Against Overfitting

1 Overfitting in one picture

A wristband gesture classifier has many weights and only a few recorded windows of each gesture. Training lowers its loss on those windows, and with enough weights it starts fitting each recording’s quirks: one person’s strap position, one session’s noise. The training loss keeps falling while the loss on held-out windows turns up. That gap is overfitting; Understanding Model Errors covers it in full. Regularization is any change that narrows the gap without needing new labels.

2 Three ways to fight overfitting

Every method in this series belongs to one of three families. Each method has its own page.

Cleaning the signal is not regularization: it removes what is never the signal, such as power-line hum, and runs the same way on every split and in live use. More real recordings can only help, while synthetic edits (Data Augmentation, Mixup) imitate more data and can be overdone once the copies stop looking real.

3 The families as equations

Start from what the gesture classifier minimizes, then see how each family changes it.

The training loss, then the two ways to change it.
\(\displaystyle {\begin{aligned}&\htmlClass{eqt sym-loss}{\htmlStyle{color:var(--sym-loss)}{\mathcal{L}_{\text{data}}}}(\theta) = \\ &\quad \frac{1}{N} \sum_{n=1}^{N} \htmlClass{eqt sym-loss}{\htmlStyle{color:var(--sym-loss)}{\ell}}\big(f_\theta(\htmlClass{eqt sym-x}{\htmlStyle{color:var(--sym-x)}{x_n}}),\, y_n\big)\end{aligned}}\)
The base loss: training lowers the average mistake on the recorded windows, and nothing stops it from fitting their quirks. \(f_\theta\) is the classifier with weights \(\theta\); \(\htmlClass{eqt sym-x}{\htmlStyle{color:var(--sym-x)}{x_n}}\) is one recorded window and \(y_n\) its gesture label; \(\htmlClass{eqt sym-loss}{\htmlStyle{color:var(--sym-loss)}{\ell}}\) is the loss on one example (cross-entropy here); \(N\) is the number of training windows.
\(\displaystyle {\begin{aligned}\htmlClass{eqt sym-loss}{\htmlStyle{color:var(--sym-loss)}{\mathcal{L}_{\text{total}}}}(\theta) &= \htmlClass{eqt sym-loss}{\htmlStyle{color:var(--sym-loss)}{\mathcal{L}_{\text{data}}}}(\theta) \\ &\quad + \htmlClass{eqt sym-lambda}{\htmlStyle{color:var(--sym-lambda)}{\lambda}}\, R(\theta)\end{aligned}}\)
Limit the model: take line 1 and add a charge for the model itself. \(R\) is a cost on the model, the size of its weights on L1 and L2 Regularization, and \(\htmlClass{eqt sym-lambda}{\htmlStyle{color:var(--sym-lambda)}{\lambda}}\) is how much that cost counts. Training now trades a little fit for a simpler model. Dropout limits the model too, as noise inside it rather than a written term.
\(\displaystyle {\begin{aligned}&\htmlClass{eqt sym-loss}{\htmlStyle{color:var(--sym-loss)}{\mathcal{L}_{\text{aug}}}}(\theta) = \frac{1}{N} \sum_{n} \mathbb{E}_{t \sim \mathcal{T}} \Big[ \\ &\qquad \htmlClass{eqt sym-loss}{\htmlStyle{color:var(--sym-loss)}{\ell}}\big(f_\theta(t(\htmlClass{eqt sym-x}{\htmlStyle{color:var(--sym-x)}{x_n}})),\, y_n\big) \Big]\end{aligned}}\)
Widen the data: take line 1 and replace each recorded window by the average over its label-keeping edits. \(\mathcal{T}\) is the set of edits (a twisted band, a masked spectrogram band), \(t\) one edit drawn from it, and \(\mathbb{E}\) the average over those draws; the label \(y_n\) is unchanged. The model is now scored on a neighbourhood around each example, the vicinal view of Chapelle et al. (2000) that the mixup paper uses, so it cannot memorize the single point. Edits help only while they keep the label true and the copy realistic; pushed too far they erase the signal.
So one family adds a cost to the loss, the other changes what the loss is averaged over. Data Augmentation and Mixup (which also edits the label) work on line 3; Class Imbalance reweights the terms of its sum.

4 Early stopping: limit training time

The third family needs no new term at all. Watch the validation loss each epoch, stop when it has not improved for a while, and keep the weights from the best epoch: the marker in Figure 1. A patience counter says how many epochs without improvement to wait, and a saved checkpoint holds the best weights.

Keep the weights from the epoch that did best on held-out windows.
\(\displaystyle {t^{\star} = \arg\min_{t}\ \htmlClass{eqt sym-loss}{\htmlStyle{color:var(--sym-loss)}{\mathcal{L}_{\text{val}}}}(\theta_t)}\)
Builds on line 1 of Section 3, measured on validation windows. \(\theta_t\) is the weights after epoch \(t\); \(\htmlClass{eqt sym-loss}{\htmlStyle{color:var(--sym-loss)}{\mathcal{L}_{\text{val}}}}\) is that average computed on the validation windows; \(t^{\star}\) is the best epoch. Of all the weights training passed through, keep the ones that did best on data it never trained on.
So the number of epochs becomes a setting chosen on validation, like the penalty strength.

It costs one validation pass per epoch and carries two things between epochs: the best weights and the counter. Prechelt (1998) compares stopping rules of this kind.

best, wait = float("inf"), 0
for epoch in range(max_epochs):
    val = evaluate(net, val_loader)
    if val < best:
        best, wait = val, 0
        torch.save(net.state_dict(), "best.pt")
    else:
        wait += 1
    if wait >= patience: break
net.load_state_dict(torch.load("best.pt"))
  1. 1One validation pass per epoch (training step not shown).
  2. 2Save on improvement, count otherwise, stop at the patience; then reload the best weights, the \(t^{\star}\) of the card.

5 Where each method plugs into training

Augmentation lives in the data pipeline, dropout in the model, weight decay in the optimizer step and class weights in the loss. The first snippet builds three once: a classifier net with dropout, AdamW, and a loss weighting the rare class higher.

import torch
from torch import nn
net = nn.Sequential()
net.append(nn.Linear(8, 64))
net.append(nn.ReLU())
net.append(nn.Dropout(p=0.5))
net.append(nn.Linear(64, 3))
# AdamW default decay: 0.01
ps = net.parameters()
opt = torch.optim.AdamW(ps)
w = torch.tensor([1., 1., 5.])
loss_fn = nn.CrossEntropyLoss(w)
  1. 1Classifier with dropout.
  2. 2AdamW, which carries weight decay (Optimizers in Practice).
  3. 3Loss weighting the rare class higher.

The second runs one step on a small batch; jitter stands in for augmentation (really in the dataset’s __getitem__), and net.train() and net.eval() switch dropout on and off.

x = torch.randn(32, 8)
noise = torch.randn_like(x)
x = x + 0.05 * noise  # jitter
y = torch.randint(3, (32,))
net.train()  # dropout on
loss = loss_fn(net(x), y)
opt.zero_grad()
loss.backward()
opt.step()  # also decays
net.eval()  # dropout off
  1. 1One batch, jittered (data pipeline).
  2. 2Dropout on, weighted loss.
  3. 3Backward and step, which decays the weights.
  4. 4Dropout off before evaluation.

6 The tool: two ways to close the gap

The capacity tool on Understanding Model Errors shows the gap growing with model size. Here the model is fixed and two remedies compete: a penalty that limits the model, and more real recordings.

trainingvalidation
final validation losslow → high

Figure 3. Illustrative curves. A penalty closes the gap but too much lifts both; more data shrinks it.

Raise the penalty and the gap closes, then both curves lift together as the model underfits; lower it and the gap reopens. Raise the real data and the validation curve comes down while the training curve rises slightly, until they meet; pushing it all the way never makes validation worse. A penalty and synthetic edits can be overdone; real data cannot.
