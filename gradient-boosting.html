Gradient Boosting

Boosting adds small trees one after another, each fitted to what the model still gets wrong, which is a gradient descent step taken by trees.

1 Fixing mistakes one small tree at a time

A random forest averages trees that are each already complex: that cuts their variance, but not their bias. Small trees are biased; one shallow tree misses most of the pattern. Boosting removes that bias by adding small trees in sequence, each aimed at the mistakes the earlier ones left. Figure 1 contrasts the two; the highlighted lower half is this page’s map: start from one guess, measure what is left, fit a small tree to it, take a small step, repeat.

The \(M\) rounds run strictly in sequence. Each round computes one residual per training window, fits one small tree to the residuals, and adds it with a shrunken weight. The state carried between rounds is the running prediction \(F\) for every training window. With early stopping, the held-out loss is checked every round and training stops when it has not improved for a set number of rounds. Prediction sums the \(M\) small trees.

The first boosting method in wide use was AdaBoost (Freund and Schapire, 1997). Each round reweights the windows so the misclassified ones count more, and each tree’s vote is weighted by how accurate it was. Friedman, Hastie and Tibshirani (2000) showed that AdaBoost is stagewise additive modelling with an exponential loss: it adds one model at a time, each fitted to lower a loss that grows exponentially with how wrong a window is. That let Friedman (2001) recast boosting as gradient descent on any differentiable loss, the method on this page. AdaBoost is rarely the first choice now: its exponential loss puts very large weight on badly wrong windows, so mislabelled windows pull hard, while the log loss used below grows only linearly for them (the Elements of Statistical Learning, section 10.6).

2 Residuals: what is still wrong

Take the smartphone activity windows with moving as 1 and still as 0. Before any tree exists, the model calls every window the same, so moving windows are under-called and still ones over-called. Each window’s leftover, its residual, is how far its truth is from the current guess: positive for an under-called moving window, negative for an over-called still one.

Boosting starts from the single best constant, and measures what is still wrong at every window.
\(\displaystyle \htmlStyle{color:#6c3483}{F_0(x)} = \arg\min_{c} \sum_{i=1}^{N} L\!\left(\htmlClass{eqt sym-target}{\htmlStyle{color:var(--sym-target)}{y_i}}, c\right)\)
Before any tree, the model \(F_0\) predicts one constant \(c\) for every window: the constant with the lowest total loss \(L\) over the \(N\) labels \(y_i\). For squared error that is the mean label; for log loss it is the log-odds of the classes, the logarithm of the ratio of moving to still windows, scikit-learn’s starting point for classifiers (Friedman 2001, Algorithm 1, line 1).
\(\displaystyle \htmlStyle{color:#c0392b}{r_i} = \htmlClass{eqt sym-target}{\htmlStyle{color:var(--sym-target)}{y_i}} - \htmlStyle{color:#6c3483}{F(x_i)}\)
The residual \(r_i\) is what is still wrong at window \(i\), with its sign: the truth minus the current prediction \(F(x_i)\). The next tree is trained to predict these. This is the squared-error case; Section 3, line 2 says what replaces it for other losses.
So the first guess is the same for every window, and the residuals mark where and in which direction it is wrong; the next tree is aimed at them.

3 Each tree is a gradient descent step

Collect the model’s predictions for all \(N\) training windows into one long vector. The total loss is a surface over that vector, and gradient descent would move each prediction a little way downhill (The gradient descent update). The downhill direction for window \(i\) turns out to be its residual. A tree cannot move each window freely, but a tree fitted to the residuals points roughly downhill and also works on windows it has never seen (Figure 3).

Builds on the gradient descent update (Gradient Descent) and the mean squared error cost (Linear Regression)

The residual is the downhill direction of the loss, a small tree approximates it, and the model takes a short step along that tree.
\(\displaystyle L\!\left(\htmlClass{eqt sym-target}{\htmlStyle{color:var(--sym-target)}{y_i}}, \htmlStyle{color:#6c3483}{F}\right) = \tfrac{1}{2}\left(\htmlClass{eqt sym-target}{\htmlStyle{color:var(--sym-target)}{y_i}} - \htmlStyle{color:#6c3483}{F(x_i)}\right)^2\)
Squared error on one window: zero when the prediction equals the truth, growing with the square of the miss.
\(\displaystyle \htmlStyle{color:#c0392b}{r_i} = -\left.\frac{\partial L(y_i, F)}{\partial F}\right|_{F = F_{m-1}(x_i)} = \htmlClass{eqt sym-target}{\htmlStyle{color:var(--sym-target)}{y_i}} - \htmlStyle{color:#6c3483}{F_{m-1}(x_i)}\)
The negative gradient of line 1 with respect to the prediction, taken at the model after round \(m-1\), is exactly the residual of Section 2, line 2. Fitting a tree to residuals is therefore a gradient descent step on the predictions. For any other loss the tree fits this negative gradient, which Friedman calls the pseudo-residual (Algorithm 1, line 3).
\(\displaystyle \htmlStyle{color:#c0392b}{r_i} = \htmlClass{eqt sym-target}{\htmlStyle{color:var(--sym-target)}{y_i}} - \sigma\!\left(\htmlStyle{color:#6c3483}{F_{m-1}(x_i)}\right)\)
For classification with log loss (The cross-entropy loss), where \(\sigma\) is the sigmoid that turns a score into a probability, the negative gradient is the label minus the predicted probability. It has the same shape as line 2, so classification boosting fits its trees to these.
\(\displaystyle \htmlStyle{color:#196f3d}{f_m} = \arg\min_{f} \sum_{i=1}^{N} \left(\htmlStyle{color:#c0392b}{r_i} - f(x_i)\right)^2\)
Round \(m\) grows a small regression tree \(f_m\) that predicts the residuals as well as it can, using the spread impurity of Regression trees (Friedman 2001, Algorithm 1, line 4). Once the tree is grown, each leaf gets its own best step: for squared error that is the mean residual in the leaf; Friedman’s Algorithm 1 adds this step search as its line 5, and for log loss scikit-learn takes it as one Newton step per leaf, a step sized by both the slope and the curvature of the loss, the idea XGBoost and LightGBM build on.
\(\displaystyle \htmlStyle{color:#6c3483}{F_m(x)} = \htmlStyle{color:#6c3483}{F_{m-1}(x)} + \htmlStyle{color:#b9770e}{\nu}\, \htmlStyle{color:#196f3d}{f_m(x)}\)
The model moves a fraction \(\nu\) of the way toward the new tree’s correction. \(\nu\) is the learning rate, scikit-learn’s learning_rate, and Friedman’s shrinkage. Raising it fits in fewer rounds and overfits sooner; lowering it needs more rounds and usually generalizes better, with diminishing returns. At one there is no shrinkage.
\(\displaystyle \htmlStyle{color:#6c3483}{F_M(x)} = \htmlStyle{color:#6c3483}{F_0(x)} + \htmlStyle{color:#b9770e}{\nu} \sum_{m=1}^{M} \htmlStyle{color:#196f3d}{f_m(x)}\)
After \(M\) rounds the model is the first guess plus every tree’s shrunken correction.
So each round is one step of gradient descent on the predictions: compute the downhill direction, which is the residual, let a small tree approximate it, and move a fraction of the way.

Boosting by hand with squared error; NU is the learning rate \(\nu\).

import numpy as np
from sklearn.tree import DecisionTreeRegressor
Tree = DecisionTreeRegressor
NU, M = 0.1, 200
F = np.full(len(y), y.mean())
for m in range(M):
    r = y - F
    f = Tree(max_depth=3)
    f.fit(X, r)
    F = F + NU * f.predict(X)
  1. 1Starts every window at the mean label, \(F_0\) of Section 2, line 1.
  2. 2The residuals, Section 2, line 2 and Section 3, line 2.
  3. 3A small regression tree fitted to them, Section 3, line 4.
  4. 4The shrunken step of Section 3, line 5. A larger NU fits in fewer rounds and overfits sooner.

4 Learning rate and number of rounds

Two settings decide how boosting ends: the step size \(\nu\) and the number of rounds \(M\). Friedman (2001, section 5) compared several shrinkage values, from no shrinkage down to small steps. Smaller steps needed more rounds and gave better accuracy, with diminishing returns, and overfitting appeared sooner for larger steps. Tool 1 shows the same trade on illustrative windows with log loss, Section 3, line 3: the shading is the predicted probability \(\sigma(F)\) of moving. Its three buttons set \(\nu\) from small to large, and red rings mark windows the model still gets badly wrong.

Early stopping reads that held-out curve for you: keep a share of the training windows aside, check their loss after every round, and stop once it has not improved for a set number of rounds. Set many rounds and let early stopping choose; tune \(\nu\) and the rounds together, because a smaller step needs more rounds.

5 Boosting in practice with scikit-learn

Histogram gradient boosting on UCI HAR’s own split of volunteers (Anguita et al., 2013), with early stopping on a tenth of the training windows.

import numpy as np
from sklearn.ensemble import HistGradientBoostingClassifier as HGB
root = "UCI HAR Dataset/"
def load(part):
    X = np.loadtxt(root + part + "/X_" + part + ".txt")
    y = np.loadtxt(root + part + "/y_" + part + ".txt")
    return X, y.astype(int)
Xtr, ytr = load("train")
Xte, yte = load("test")
boost = HGB(learning_rate=0.1, max_iter=500, early_stopping=True,
            validation_fraction=0.1, n_iter_no_change=10)
boost.fit(Xtr, ytr)
acc = boost.score(Xte, yte)
  1. 1Loads the training and test volunteers’ windows, 561 features each.
  2. 2learning_rate is \(\nu\); up to 500 rounds, stopping when the held-out tenth has not improved for 10 rounds.
  3. 3Fits the rounds in order.
  4. 4Test accuracy on the held-out volunteers.

HistGradientBoostingClassifier bins each feature into at most 255 bins for speed and handles missing values natively; its rounds run in order, and early stopping turns on by itself above 10,000 training windows. The scikit-learn guide describes it as inspired by LightGBM, and its leaf values use per-leaf curvature: both ideas are explained on XGBoost and LightGBM.

A well-known field use is click prediction at Facebook (He et al., ADKDD 2014): boosted trees turned each ad impression into a set of leaf indicators, and a logistic regression on those features beat either method alone.

7 Two prices and faster splits

Plain gradient boosting steps along the slope of the loss but ignores how curved it is, and nothing in its objective charges for a bigger tree. What if each leaf’s step used the curvature too, and every leaf had a price? That is XGBoost and LightGBM.
