1 One learning rate cannot fit every direction

In a real network some directions of the loss are far steeper than others. The steep ones cap how large the learning rate can be before training swings out of control (SGD, Momentum and Nesterov), so along the flat ones the weights crawl.

A language model’s embedding table shows this at full scale: a frequent token’s row gets a gradient every batch, a rare token’s row almost never, and one rate cannot suit both (AdaGrad, Duchi and others 2011, starts from exactly this case). Recommender embeddings have the same shape (Recommender Systems).

Plain gradient descent, recap
\({\displaystyle \htmlStyle{color:#2c3e50}{\theta} \leftarrow \htmlStyle{color:#2c3e50}{\theta} - \htmlStyle{color:#7d3c98}{\alpha}\, \htmlStyle{color:#c0392b}{g}}\)
Every weight \(\theta\) moves against its gradient \(g\), and the same learning rate \(\alpha\) multiplies every coordinate. So a coordinate with a big gradient takes a big step and one with a small gradient a small step, whether or not it has far to go.

2 One idea, three ways to measure size

The adaptive optimizers keep one size estimate per weight and divide by it.

The shared form of every adaptive optimizer
\({\displaystyle \htmlStyle{color:#2c3e50}{\theta_i} \leftarrow \htmlStyle{color:#2c3e50}{\theta_i} - \htmlStyle{color:#7d3c98}{\alpha}\, \frac{\htmlStyle{color:#1f618d}{u_i}}{\htmlStyle{color:#0e6b59}{s_i}}}\)
Each coordinate \(i\) moves by its push \(u_i\) divided by its own size estimate \(s_i\), built from that coordinate’s own past gradients, and \(\alpha\) is the distance per unit of push. Steep and flat directions now take comparable steps: the step stops depending on how steep a direction is and starts depending on how steady its gradient is. The three members, AdaGrad, RMSProp, Adam, differ only in what they use for \(u\) and \(s\); each page fills them in.

Each method keeps the one above and adds one change; every card opens its page.

  • AdaGrad measures size from all past gradients, so rare weights keep long steps.
  • RMSProp measures it from recent gradients, so steps do not die out (Hinton and others 2012).
  • Adam divides the recent average direction by the recent size, with a fix for the zero start (Kingma and Ba 2015).
  • Nadam is Adam with a look-ahead, taught as Adam’s last section.

4 Which one to start with

Adam, or AdamW when weight decay matters, is the default for transformers and most deep networks; LLaMA, for one, was trained with AdamW (Touvron and others 2023). RMSProp appears in reinforcement learning, as in the original DQN (Mnih and others 2013). AdaGrad suits sparse features, as in GloVe word vectors (Pennington and others 2014). SGD with momentum still trains many image classifiers (SGD, Momentum and Nesterov). The extra memory each one needs is part of the choice.

Swapping one for another is one line in PyTorch.

import torch
model = torch.nn.Linear(16, 4)
ps = list(model.parameters())
opt = torch.optim.SGD(ps, lr=1e-3, momentum=0.9)
# all three follow the shared form; only the size estimate s differs
opt = torch.optim.Adagrad(ps, lr=1e-2)
opt = torch.optim.RMSprop(ps, lr=1e-2)
opt = torch.optim.Adam(ps, lr=1e-3)
  1. 1A model, its parameters as a list (so they can be passed more than once), and SGD with momentum.
  2. 2The three adaptive optimizers, each with its PyTorch default rate.
