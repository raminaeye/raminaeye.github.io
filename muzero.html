AlphaZero chose each move by trying moves with the game’s exact rules; Atari gives no rules, only screens and points. MuZero learns three functions: encode the screens into a hidden state, step that hidden state forward for a move, and read off move chances and value. The AlphaZero search runs on hidden states instead of real positions, with small changes to its selection rule. Training unrolls the learned model a few moves along stored real games and asks it to match the real rewards, value targets and search choices. The hidden state never has to rebuild the screen; it keeps only what planning needs, and training checks its predictions only for the few moves it unrolls.

1 A video game gives no rules to plan with

AlphaZero chose what to play by trying out lines of play with the game’s exact rules, but many video games give no rules, only screens and points. Atari is a set of classic video games, seen only as screen images. Each game draws a fresh screen many times a second.

The running example is Breakout, an Atari game in which a paddle at the bottom bounces a ball into a wall of bricks, and each broken brick earns points. MuZero learned to play Breakout and the other Atari games from screens and points alone. The bricks sit in coloured rows across the top of the screen.

The agent is the learner that picks the moves. (RL Basics) A state is the agent’s situation right now; a move, or action, is one choice the agent can make in a state; a reward is the number the world hands back after each move, good or bad. (RL Basics) Here the agent is the program that slides the paddle left or right. Each frame shows the paddle, the ball and the bricks left.

A real step is one move made in the real environment, with the reward and the next state it brings. An observation is what the agent senses at one moment. (RL Basics) Here the observation is the game screen. The agent sees only these screens and the points total, never the code of the game.

A model is the agent’s learned guess of where a move leads and what it pays. (Model-Based RL) A model can be given, like the exact rules of a board game, or learned from the agent’s own steps. (Model-Based RL) Nobody hands MuZero the rules of Breakout, so its model has to be learned from play.

RL, short for reinforcement learning, is learning which moves to make from rewards rather than from labelled answers. (RL Basics) In Breakout most moves earn nothing, and rewards come only when the ball breaks a brick. The paddle can only slide left and right along the bottom of the screen.

Model-based RL means the agent uses a model of the world to practise in its head, so it needs fewer real steps. (Model-Based RL) Model-free agents learn only from real play, with no model of the game. Earlier model-based agents that learned to predict the screen fell well short of the best model-free agents on Atari. Predicting the whole next screen spends a model’s effort on details that do not change the points.

Planning means using a model to try moves in imagination instead of in the real world. (Model-Based RL) An imagined step is one move tried inside the model; an imagined rollout is a run of them, each starting where the last one ended. (Model-Based RL) MuZero plans with imagined steps too, but its model never draws a screen.

Looking ahead, or search, means trying several moves in the model, then their replies, before choosing one for real. (Model-Based RL) MuZero looks ahead before every move, inside its learned model.

2 A learned model of only what planning needs

MuZero picks each Breakout move by searching inside its learned model, then trains on what that search found.

A policy is the agent’s rule for choosing a move in each state; it may always pick the same move or pick by chance. (RL Basics) The return is all the reward still to come, with later rewards counted a little less. (RL Basics) A state’s value \(V(s)\) is the return the agent expects from state \(s\). (RL Basics) MuZero’s model is trained only to predict the reward, the value and the search’s choice of move, so it may drop any screen detail that does not help choose a move.

MuZero keeps AlphaZero’s search, its network’s two outputs and its loss; what changes is where the positions come from. A learned hidden state is a summary of the position that the model invents for planning; it need not look like the observation. The screen goes in once; after that, planning works only on hidden states.

MuZero’s representation function turns observations into a hidden state, its dynamics function steps that state forward for one move and predicts the reward, and its prediction function reads off move chances and a value. The dynamics and prediction functions run again and again during a search, once for each new position it reaches; the representation function runs once per real move.

2.1 Running the model forward along a real game

Unrolling the model means feeding it its own predicted state again and again, one imagined move at a time, along moves that were really played. The unroll length \(K\) is how many moves one unroll runs, and \(k\) counts its steps from \(0\) to \(K\). Training does this on stored stretches of real play, so every imagined step has a real step to be checked against.

The value target \(y_t\) is what the value prediction at real step \(t\) is trained toward. An n-step return adds the next n real rewards, then a value estimate for the rest. (Actor-Critic) In Atari MuZero uses an n-step return as the value target; in board games it uses the game’s result.

3 The three functions and how they are trained

In a board game a legal move is a move the rules allow, and the player to move is the one whose turn it is. In Breakout every paddle move is allowed, and the agent is always the one to move. In Breakout the ball speeds up as the game goes on.

One network gives two quick judgements of a position: the policy head gives a chance for each legal move, and the value head estimates the game result the player to move can expect from here, anywhere from a loss through a draw to a win. (AlphaZero) The prediction function carries both heads, on hidden states.

In Atari the value head instead estimates the discounted rewards still to come.

The discount \(\gamma\) sets how much a reward one step later still counts. (RL Basics) The game result \(z\) is a win, a draw or a loss, seen from the player whose turn it is. (AlphaZero) The value target mixes real rewards with a later value, or uses the result in board games.

The loss also needs what the search chose at each stored move.

A tree search tries moves from the current position, then the replies to them; the current position is the root, and the newest position at the end of a path is a leaf. (AlphaZero) From each position the tree fans out, because every reply opens new branches.

Monte Carlo tree search runs many simulations, each one pass from the root down to a new leaf and back up, and counts which moves they went through. (AlphaZero) A simulator is a program that applies the rules exactly, so a search can step through positions without playing them for real. (AlphaZero) MuZero’s search steps hidden states with its dynamics function instead of a simulator.

The visit count \(N(s,a)\) is how many simulations went through move \(a\) in position \(s\). (AlphaZero) The search policy is each move’s share of the root’s visits, a better policy than the network’s first guess. (AlphaZero) The loss compares the model’s move chances with those shares.

Equation 3. The loss. At each unrolled step the model must predict the real reward, the value target and what the search chose.
\(\displaystyle \begin{aligned} \ell &= \sum_{k=1}^{K} \ell^{r}\big(\htmlStyle{color:var(--sym-reward)}{r_{t+k}},\, \htmlStyle{color:var(--sym-reward)}{\hat r^{k}}\big) \\ &\quad + \sum_{k=0}^{K} \ell^{v}\big(\htmlStyle{color:var(--sym-statevalue)}{y_{t+k}},\, \htmlStyle{color:var(--sym-statevalue)}{v^{k}}\big) \\ &\quad + \sum_{k=0}^{K} \ell^{p}\big(\htmlStyle{color:var(--sym-policy)}{\boldsymbol{\pi}_{\text{search},\,t+k}},\, \htmlStyle{color:var(--sym-policy)}{\mathbf{p}^{k}}\big) \\ &\quad + \htmlStyle{color:var(--sym-discount)}{c_{\text{L2}}}\,\lVert\htmlStyle{color:var(--sym-model)}{\theta}\rVert^2 \end{aligned}\)
Take a stored stretch of a real game, unroll the model K moves along the moves actually played, and compare at every step. At each unrolled step the model must predict the real reward, the value target and what the search chose; nothing asks it to predict the screen. Row 1, \(\ell^r\), compares the real reward after the k-th move with the predicted one, starting at \(k = 1\) because a reward only exists after a move; row 2, \(\ell^v\), compares the value with the target of the value-target card at that later time; row 3, \(\ell^p\), compares the move chances with the stored search policy. Nothing in these rows asks for the screen. Row 4 is the L2 penalty, a small pull of every weight toward zero, as on AlphaZero; the paper writes \(c\). In Atari, reward and value are shrunk with a signed square-root transform onto a smaller scale so huge rewards and values do not swamp small ones, then sorted into buckets, each bucket a range of reward or value, and the network predicts chances over the buckets like a classifier. The bucket rows are trained with cross-entropy (Cross-Entropy Loss), a loss that is lower when the predicted chances put weight on the bucket the real reward or value falls into. The policy row is trained with cross-entropy too, a loss that is lower when the predicted chances put weight where the search’s chances put weight. In board games the value uses squared error and there is no reward term, and the policy row is cross-entropy everywhere. Superscript \(k\) means predicted after k imagined moves; subscript \(t + k\) means the real target at that later time. This builds on the value and policy rows of AlphaZero’s training-loss card (AlphaZero), the dynamics line of the model card (reward row) and the value-target card (\(y\)).

The paper writes \(u\) for real rewards.

4 Stepping through planning and training

Planning runs the same search, move by move, on hidden states.

The prior \(P(s,a)\) is the network’s first guess of how good each move is, before any search. (AlphaZero) A move’s value \(Q(s,a)\), also called its score, is the return the agent expects if it makes move \(a\) in state \(s\) and plays on from there. (RL Basics) In the tree, Q is the average value found below the move so far. The search keeps the prior and Q on every move in the tree.

AlphaZero’s selection rule, PUCT (predictor plus upper confidence bounds applied to trees), runs on hidden states with small changes. PUCT steers each simulation toward moves that have looked good so far, plus a bonus for moves the prior likes that the search has rarely tried. (AlphaZero) MuZero’s version lets the size of the exploration bonus grow slowly as a position gathers visits, and rescales the move values found so far to the range seen in the tree, because Atari values have no fixed range.

The backup carries a new leaf’s value back up the path, flipping its sign at each level because the players take turns. (AlphaZero) In Breakout there is one player, so nothing flips; each step up the path adds that move’s predicted reward, discounted, to the value carried up. Only in Go, chess and shogi does the sign flip.

5 MuZero in PyTorch

The three MuZero functions and one unrolled training loss; the search is AlphaZero’s.

import torch
import torch.nn.functional as F
from torch import nn

class Repr(nn.Module):
    def __init__(self, obs_dim, hidden=256):
        super().__init__()
        self.trunk = nn.Sequential(nn.Linear(obs_dim, hidden), nn.ReLU())

    def forward(self, obs):
        return self.trunk(obs)

class Dyn(nn.Module):
    def __init__(self, hidden=256, n_moves=4):
        super().__init__()
        self.n_moves = n_moves
        self.trunk = nn.Sequential(nn.Linear(hidden + n_moves, hidden), nn.ReLU())
        self.reward = nn.Linear(hidden, 1)
        self.next = nn.Linear(hidden, hidden)

    def forward(self, s, a):
        h = self.trunk(torch.cat([s, F.one_hot(a, self.n_moves).float()], dim=-1))
        return self.reward(h), self.next(h)

class Pred(nn.Module):
    def __init__(self, hidden=256, n_moves=4):
        super().__init__()
        self.trunk = nn.Sequential(nn.Linear(hidden, hidden), nn.ReLU())
        self.policy = nn.Linear(hidden, n_moves)
        self.value = nn.Linear(hidden, 1)

    def forward(self, s):
        h = self.trunk(s)
        return self.policy(h), self.value(h)

  2. repr_, pred and dyn are one of each class above, made once before training.
y = sum(gamma**i * r[t + 1 + i] for i in range(n)) + gamma**n * nu[t + n]

def scale_grad(x, frac):
    return x * frac + x.detach() * (1 - frac)

s = repr_(obs[t])
loss = 0.0
for k in range(K + 1):
    w = 1.0 if k == 0 else 1.0 / K
    logits, v = pred(s)
    loss = loss + w * (ce(logits, pi[t + k]) + mse(v, y[t + k]))
    if k < K:
        s = scale_grad(s, 0.5)
        r_hat, s = dyn(s, a[t + k])
        loss = loss + mse(r_hat, r[t + k + 1]) / K

The snippet uses squared error for value and reward as a simplification; the Atari form uses cross-entropy over buckets for both, as the loss card says.
  2. ce is cross-entropy, mse is squared error, pi is the search policy at that step, and logits are the raw move scores before they become chances.

a[t + k] is the move played at step t + k and r[t + k + 1] the reward that followed it; the paper writes that move as \(a_{t+k+1}\) and its reward as \(u_{t+k+1}\). In board games the reward term is dropped.

6 How far training checks the learned model

Each imagined step starts from the last imagined state, so a small model error grows the further ahead the agent imagines. (Model-Based RL) MuZero’s training checks the model only along short unrolls of real play, the trained length K.

A search can imagine more moves ahead than the K steps training checks, so what happens past K matters.

In the paper’s search-length studies, searches far longer than in training still matched a search with the true rules in Go, but in Atari longer searches stopped helping, perhaps because that model was less accurate.

7 MuZero in practice

In every game, each move runs one search on hidden states, with fewer simulations per move in Atari than in board games. Replay keeps a memory of past steps, and training draws random batches from it. (Deep Q-Networks) Training runs continually on games kept in a replay buffer, each sample unrolled K moves. The copy that plays the games is refreshed from the training network at a fixed interval. In self-play the same network plays both sides, so its opponent improves exactly as fast as it does. (AlphaZero) In Atari this is not self-play, since there is one player.

A longer K teaches the model to stay right further ahead but costs more per sample. More simulations give stronger moves at more computing; in Atari the gains level off. A larger n leans more on real rewards, a smaller one more on the value estimate.

The paper scales down the later steps’ losses and the gradient entering the dynamics, so training stays steady however far the model unrolls, and predicts value and reward on the buckets of the loss card.

7.1 Atari and board games against the best agents of the time

A distributed agent runs many copies that play in parallel and feed one learner. Many copies gather far more play per hour than one copy can.

Recurrent Replay Distributed Deep Q-Network (R2D2) is a distributed Deep Q-Network, the neural-network form of Q-learning, with a memory that carries from one step to the next, the best model-free Atari agent then. MuZero was measured against it on every game of the standard Atari set.

MuZero beat the best model-free agent on Atari.

Elo is a playing-strength rating in which a gap between two players means a predictable win rate. In Go MuZero slightly exceeded AlphaZero, and in chess and shogi it matched it.

MuZero beat R2D2 on most of the Atari games, and it did so on fewer training frames than R2D2.

In Go, a model trained with short searches kept improving when searches at test time were far longer, and matched a search that was given the exact rules.

In Atari, longer searches stopped helping, perhaps because that model was less accurate.

8 Planning without a simulator

  • MuZero fits when no simulator or rules are available, and there is computing for a search at every step.
  • Against AlphaZero: the same strength where rules exist, and it works where they do not.
  • Against model-free value methods: on one game, Ms. Pacman, the paper’s comparison with a Q-learning variant inside the same framework shows the Q-learning variant learning slower and reaching a lower level of play.

10 From searching a model to learning inside it

MuZero still searches at every move. Can an agent learn its behaviour entirely inside the model, with actions that are amounts with any value, like the turning forces at a walking robot’s joints?

World Models and Dreamer take that step: they learn behaviour inside the model itself.
