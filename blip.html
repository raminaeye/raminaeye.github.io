1 The problem BLIP solves

Some models understand images and text together, and others write text about images, but one model rarely did both well. An understanding model could match a caption to a picture but not write one; a generation model could write but not retrieve. And both learned from web captions, which often miss the picture.

BLIP (Li et al. 2022) fixes both at once. It trains one text model three ways, so the same weights match, compare and caption: it retrieves captions for a COCO photo, writes a caption for it, and answers a question about it. The two ideas are called MED, one text model trained three ways, and CapFilt, the model cleaning its own captions, in the paper BLIP: Bootstrapping Language-Image Pre-training for Unified Vision-Language Understanding and Generation.

A ViT (vision transformer, which cuts an image into patch tokens) reads the image. CapFilt runs once, before pre-training, over the web images; the three losses run together at every pre-training step, on image-caption pairs.

2 One text model, three objectives, almost all weights shared

BLIP trains one multimodal mixture of encoder-decoder (MED) on image-caption pairs. One text Transformer, started from BERT-base (a 12-layer text encoder), runs in three modes.

2.1 The three modes

The unimodal encoder reads the caption alone and trains with the image-text contrastive loss (ITC), which pulls a matched image vector and caption vector together and pushes the batch's other captions apart, as in Image-Text Contrastive Learning (CLIP) (Radford et al., 2021). The image-grounded encoder also reads the image and trains with the image-text matching loss (ITM), a head that says matched or not. The image-grounded decoder writes the caption under causal self-attention and trains with the language modeling loss (LM).

BLIP's three passes over one image and caption, with one self-attention and one cross-attention layer standing in for the text Transformer, plus the decoder's own causal self-attention.

import torch
import torch.nn as nn

D, N_PATCH, N_TXT, H = WIDTH, N_PATCHES, N_TEXT, N_HEADS
img = torch.randn(1, N_PATCH, D)  # ViT patch features
txt = torch.randn(1, N_TXT, D)    # caption token vectors
self_attn = nn.MultiheadAttention(D, H, batch_first=True)
causal_self_attn = nn.MultiheadAttention(D, H, batch_first=True)
cross = nn.MultiheadAttention(D, H, batch_first=True)
causal = torch.ones(N_TXT, N_TXT, dtype=torch.bool).triu(1)

itc, _ = self_attn(txt, txt, txt)  # ITC, text only
itm, _ = cross(itc, img, img)      # ITM, reads img
y, _ = causal_self_attn(txt, txt, txt, attn_mask=causal)
lm, _ = cross(y, img, img)         # LM, causal, reads img

2.2 What is shared and what is not

The encoder and the decoder share all parameters except for self-attention (BLIP section 3.2): the embedding layers, the cross-attention layers and the feed-forward networks are one set of weights. Self-attention stays separate because encoding looks both ways while decoding may only look back. A first token tells the model which mode it is in: [Encode] for matching, [Decode] for writing (BLIP section 3.1).

2.3 The three losses

Each image-caption pair needs one forward pass through the image encoder and three through the text model, one per loss (BLIP section 3.2). The contrastive loss compares the image and caption summaries; it learns from a momentum encoder, a slow copy of the model whose soft targets keep captions that may also match from being fully punished. The matching loss asks a head whether the pair matches, and it trains on hard negatives, wrong captions that scored high. The captioning loss predicts each word from the image and the words so far, with label smoothing of 0.1.

An image and a caption score as high as the match between their two summary vectors.

3 The model cleans its own captions

Web captions (alt-text) often miss the picture. CapFilt (captioning and filtering) cleans them with two copies of the MED, each fine-tuned on COCO's human-written captions.

The captioner, the decoder fine-tuned with LM, writes one caption per web image by nucleus sampling (each word drawn from the likeliest words covering 90% of the probability; a higher share allows rarer words and more varied captions, a lower one stays with safe common words); the filter, the encoder fine-tuned with ITC and ITM, drops captions its ITM head calls unmatched. The gain is measured by text recall@1, how often an image's top-ranked caption is the right one.

3.1 Captioner and filter

Both are fine-tuned copies of the same pre-trained model, trained on COCO's human-written captions. The filter drops captions its matching head calls unmatched, from the web texts and from the synthetic ones alike. More diverse captions give larger gains (BLIP section 1): the synthetic captions add words the web texts never used.

3.2 What CapFilt buys and where it breaks

CapFilt buys cleaner training data: the filter throws out captions that do not match, and the captioner adds captions the web never wrote. It breaks in two places. The filter sometimes keeps a wrong caption, and the model then learns a wrong match. And the captioner sometimes writes safe generic captions (beam search writes the caption the dataset repeats most), which teach the next model little.

5 In practice

The released code and checkpoints live in the salesforce/BLIP repo, with the pre-trained models the paper reports. BLIP-2 builds on this page: it freezes the image encoder and the language model and trains a small Q-Former between them, in BLIP-2 and the Q-Former.
