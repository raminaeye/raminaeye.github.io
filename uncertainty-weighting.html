Uncertainty Weighting

Set each task's volume from the data's noise. Noisy tasks count less, automatically.

GradNorm sets the volumes by watching training dynamics. This page sets them from the data itself: some tasks are just noisier than others, and a noisy task should count less. The model learns exactly how much less.

The paper behind the pricing

The paper

Alex Kendall, Yarin Gal, Roberto Cipolla

Multi-Task Learning Using Uncertainty to Weigh Losses for Scene Geometry and Semantics.

CVPR 2018 · arXiv:1705.07115

The authors were working on scene understanding for robotics, where slow computation is not an option. A scene-understanding system has to see geometry and semantics at the same time: per-pixel depth (a regression task), plus semantic and instance segmentation (classification tasks). Different units, different scales, one shared representation.

Their practical case for combining them: one model cuts the computation, and cues from one task, like depth, can regularize and improve another, like segmentation. Their network takes a single monocular image and produces all three outputs jointly.

But there was a wall: performance depends strongly on the relative weighting between the tasks' losses, and tuning those weights by hand is, in their words, a difficult and expensive process, making multi-task learning prohibitive in practice. Their contribution is a principled alternative: derive the weights from each task's homoscedastic uncertainty, a per-task noise level learned during training, so the model learns how much to trust each loss instead of you guessing.

The intuition

GradNorm, the method above, steps in after the losses exist. It takes the gradients as given and repairs their loudness, watching who falls behind. This idea is older and quieter, and it works one level earlier. Instead of asking how to fix conflicting gradients, it asks how loud each loss should be in the first place. And it answers with a principle from probabilistic modeling: a loss that is inherently noisier should count less.

Some tasks are just harder to be sure about

Think of each task's output as a measurement. Some measurements are crisp: given the same image, the right answer barely changes. Is this a cat or a dog. Some are inherently fuzzy: predicting the exact depth of every pixel has a floor of guesswork no model can beat, because the information simply is not in the image. Kendall, Gal, and Cipolla call this irreducible fuzziness task uncertainty, written \(\sigma_i\). A task with high \(\sigma_i\) is one where even a perfect model would still spread probability over several answers.

Here is the key move. If a task is that noisy, pushing hard on its loss is partly pushing on noise: the model chases fluctuations it cannot remove. The sensible thing is to turn the volume down on exactly those tasks, by an amount tied to how noisy they are. Each task gets a weight of \(1/(2\sigma_i^2)\) for regression, and \(1/\sigma_i^2\) for classification (the likelihood gives no 1/2 there). Either way, a task twice as noisy counts four times less. And the \(\sigma_i\) are learned as parameters during training, not set by hand.

The objective, in plain words

The plain-words version first. The total loss is a sum over tasks. Each task's own loss gets divided by its noise squared, so a noisier task contributes a smaller share, and then each task pays a small honesty tax for claiming to be noisy. Regression and classification price the noise slightly differently: the Gaussian likelihood behind regression brings a factor of 1/2 that the classification form does not have.

$$\begin{aligned} \text{regression:}\qquad L_{\text{total}} &= \sum_i \left( \frac{L_i}{2\sigma_i^2} + \log \sigma_i \right) \\ \text{classification:}\qquad L_{\text{total}} &= \sum_i \left( \frac{L_i}{\sigma_i^2} + \log \sigma_i \right) \end{aligned}$$

Two likelihoods, two objectives. The 1/2 belongs only to regression: keep the two forms separate.

  1. \(L_i\) is task \(i\)'s usual loss, the same number you already compute. In the worked example below I set every \(L_i\) to 1.0, so only the pricing shows.
  2. \(\sigma_i\) is the learned noise level of task \(i\): one number per task, bigger means noisier. The example uses \(\sigma = (0.7, 1.5, 2.4)\).
  3. \(1/(2\sigma_i^2)\) is the volume knob (\(1/\sigma_i^2\) for classification). As \(\sigma_i\) grows, the task is turned down, quadratically.
  4. \(\log \sigma_i\) is the penalty that keeps the model honest. Without it, the model could make every task free by inflating every \(\sigma_i\) to infinity. The log term charges a price for saying "this task is noisy", so a task only gets turned down if it genuinely is.

The point: the model is allowed to quiet a task, but it has to pay \(\log \sigma_i\) for the privilege, so it only quiets tasks that truly are noisy.

The pricing, worked by hand

Three tasks, equal losses \(L_i = 1.0\), noise levels \(\sigma = (0.7, 1.5, 2.4)\), regression form. One computation per line:

  1. Task 1, noise squared: \(\sigma_1^2 = 0.7^2 = 0.49\).
  2. Task 1, volume: \(1/(2 \times 0.49) \approx 1.0204\).
  3. Task 1, honesty price: \(\log 0.7 \approx -0.3567\).
  4. Task 1, total bill: \(1.0204 - 0.3567 = 0.6637\).
  5. Task 2, noise squared: \(\sigma_2^2 = 1.5^2 = 2.25\).
  6. Task 2, volume: \(1/(2 \times 2.25) \approx 0.2222\).
  7. Task 2, honesty price: \(\log 1.5 \approx 0.4055\).
  8. Task 2, total bill: \(0.2222 + 0.4055 = 0.6277\).
  9. Task 3, noise squared: \(\sigma_3^2 = 2.4^2 = 5.76\).
  10. Task 3, volume: \(1/(2 \times 5.76) \approx 0.0868\).
  11. Task 3, honesty price: \(\log 2.4 \approx 0.8755\).
  12. Task 3, total bill: \(0.0868 + 0.8755 = 0.9623\).
  13. Grand total: \(0.6637 + 0.6277 + 0.9623 \approx 2.2537\).

Task 3 is about 3.4 times noisier than task 1, and its weight is about 12 times smaller. That is the square doing its job. Notice the third bill: the tiny weight is partly paid back by the large log price. The model still quieted the task, because the noise was real.

Same noise, classification form: task 1's weight would be \(1/0.49 \approx 2.0408\), exactly double. No 1/2 anywhere in that form.

Algorithm 2: one training step

  1. Forward pass; compute each task loss \(L_i\).
  2. Form the total \(L_{\text{total}} = \sum_i (L_i/(2\sigma_i^2) + \log \sigma_i)\), the regression form; classification drops the 1/2.
  3. Backpropagate \(L_{\text{total}}\) once. The gradient reaches both the network and the \(\log \sigma_i\) values, since they are learnable.
  4. Step the network and the \(\log \sigma_i\) together with the same optimizer.
# log_sigma = learnable vector, one entry per task, init 0
# (regression form shown; classification uses w_i = 1 / sigma2, no 1/2)
for i in range(K):
    sigma2 = exp(2 * log_sigma[i])   # sigma_i^2, always positive
    w_i = 1 / (2 * sigma2)           # the volume knob
    total += w_i * losses[i] + log_sigma[i]  # loss + the honesty price
backward(total)   # one pass updates network AND log_sigma
step(optimizer)   # network and sigmas learn together

The loop is deliberately boring: no second optimizer, no gradient editing, no extra backward pass. Paste the loss, add one vector of parameters, done. In practice the \(\sigma_i\) are learned as \(\log \sigma_i\), an unconstrained number that is easier for the optimizer, exponentiated inside the loss. It is the cheapest method in this series to adopt.

When weighting is enough, and when it isn't

Step back. GradNorm and uncertainty weighting are both scale methods: they change how loud each loss is, never what the gradients say. GradNorm learns the volumes from training dynamics, boosting whichever task falls behind. Uncertainty weighting sets them from the data, turning down whichever task is inherently noisy. On multi-task vision benchmarks, both matched or beat hand-tuned and grid-searched weights.

The two methods even compose, because uncertainty weighting only ever sees losses. Weight the losses by learned uncertainty, then run PCGrad or CAGrad on the resulting gradients: the \(\sigma_i\) handle scale while the surgery handles direction.

And that is the boundary. Neither method fixes direction. Two tasks can be perfectly weighted by noise and still have gradients that point against each other. Uncertainty weighting never looks at gradients at all; GradNorm measures only their lengths, never their angles. GradNorm is also a heuristic with no convergence guarantee: equal loudness does not mean the tasks agree.

The two volume knobs and the two steering methods, side by side:

MethodThe question it answers
GradNormHow loud should each task be, to keep progress balanced? (learned, driven by training dynamics)
UncertaintyHow loud should each task be, given how noisy it inherently is? (learned, driven by the data)
PCGradHow should the directions be edited so tasks stop fighting?
CAGradHow do we protect the worst-off task and stay near the average, with a guarantee?

The volume knobs are balanced. But what if the directions themselves fight? That is the next page's question.
