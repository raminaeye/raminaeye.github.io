FlashAttention

FlashAttention computes exactly the same attention output, but in tiles that stay in the GPU's fast on-chip memory, so the \(n\) by \(n\) score table never travels to slow memory.

1 The score table's trips to memory set the time

A GPU has two memories: HBM, large and slow, and SRAM, a small fast on-chip memory of size \(M\). Standard attention writes the score table to HBM and reads it back, and Dao et al. (2022) found that this traffic, not the arithmetic, sets the time.

Standard attention as three stored steps.
\({\displaystyle \htmlClass{eqt sym-s}{\htmlStyle{color:#9a6400}{S}}=\frac{\htmlClass{eqt sym-q}{\htmlStyle{color:#7d3c98}{Q}}\htmlClass{eqt sym-k}{\htmlStyle{color:#a04000}{K}}^{\top}}{\sqrt{d_k}}}\)
Picture GPT-2 training on long text. Every query is scored against every key; the scores fill \(S\), an \(n\) by \(n\) table that the standard kernel writes to HBM. \(d_k\) is the number of entries in each key; dividing by its square root keeps the scores from growing with the head size.
\({\displaystyle \htmlClass{eqt sym-p}{\htmlStyle{color:#117a7a}{P}}=\mathrm{softmax}(\htmlClass{eqt sym-s}{\htmlStyle{color:#9a6400}{S}})}\)
The standard kernel reads \(S\) back, turns each row into weights that sum to one, and writes the weights \(P\), a second table of the same size, to HBM again.
\({\displaystyle \htmlClass{eqt sym-o}{\htmlStyle{color:#117a7a}{O}}=\htmlClass{eqt sym-p}{\htmlStyle{color:#117a7a}{P}}\htmlClass{eqt sym-v}{\htmlStyle{color:#a04000}{V}}}\)
It reads \(P\) back once more to average the values. These three lines are the attention line of Transformer Cost and Efficiency written as stored steps; the two round trips of the tables are the traffic FlashAttention removes.

2 Compute the table one tile at a time

FlashAttention splits the table into tiles and scores one tile at a time inside SRAM. Each tile is sized so a block of queries, a block of keys, a block of values and the matching block of outputs fit in on-chip memory together.

The tiles are never stored, so the traffic changes shape. The card below compares the two kernels.

Traffic to and from HBM in the forward pass (Dao et al. 2022, Theorem 2); the sign \(\sim\) reads "grows like".
Standard attention
\({\displaystyle \text{traffic}\;\sim\;\htmlClass{eqt sym-n}{\htmlStyle{color:#9a6400}{n}}\,\htmlClass{eqt sym-d}{\htmlStyle{color:#1f618d}{d}}+\htmlClass{eqt sym-n}{\htmlStyle{color:#9a6400}{n}}^{2}}\)
“Grows like” means the traffic rises in proportion to the expression as \(n\), \(d\) or \(M\) change, ignoring fixed factors. Standard attention reads the inputs, \(n\) rows of \(d\) numbers, then writes and reads the whole \(n\) by \(n\) table.
FlashAttention
\({\displaystyle \text{traffic}\;\sim\;\frac{\htmlClass{eqt sym-n}{\htmlStyle{color:#9a6400}{n}}^{2}\htmlClass{eqt sym-d}{\htmlStyle{color:#1f618d}{d}}^{2}}{\htmlClass{eqt sym-m}{\htmlStyle{color:#1e8449}{M}}}}\)
In the 2022 loop order (section 7), each block of keys and values is read once and the queries and outputs are re-read once per block. The number of blocks grows like \(nd/M\), and each pass moves on the order of \(nd\) numbers. For typical head sizes, \(d^2\) is many times smaller than the on-chip memory \(M\), so this is a fraction of the standard traffic.

3 A running maximum and sum make tiles exact

Softmax needs a whole row: its maximum (subtracted so exp never overflows) and its sum. A tile sees only part of the row, so each row keeps a running maximum, a running sum and a running output, and fixes them up when a later tile brings a bigger score.

The running softmax over key tiles \(j\) for one block of query rows, as FlashAttention-2 runs it.
\({\displaystyle \htmlClass{eqt sym-m}{\htmlStyle{color:#b03a2e}{m_0=-\infty}}}\)
Each row of the query block starts with no maximum yet,
\({\displaystyle \htmlClass{eqt sym-l}{\htmlStyle{color:#1f618d}{\ell_0=0}}}\)
an empty sum,
\({\displaystyle \htmlClass{eqt sym-ot}{\htmlStyle{color:#117a7a}{\tilde O_0=0}}}\)
and an empty output.
\({\displaystyle \htmlClass{eqt sym-s}{\htmlStyle{color:#9a6400}{r_j}}=\max \htmlClass{eqt sym-s}{\htmlStyle{color:#9a6400}{S_j}}}\)
Key tile \(j\) brings the scores \(S_j\); \(r_j\) is the largest score in each of their rows.
\({\displaystyle \htmlClass{eqt sym-m}{\htmlStyle{color:#b03a2e}{m_j}}=\max(\htmlClass{eqt sym-m}{\htmlStyle{color:#b03a2e}{m_{j-1}}},\htmlClass{eqt sym-s}{\htmlStyle{color:#9a6400}{r_j}})}\)
\(m_j\) is the largest score this row has seen so far: the old maximum or the tile’s, whichever is bigger. Softmax subtracts it before taking exp, so exp never overflows.
\({\displaystyle \htmlClass{eqt sym-resc}{\htmlStyle{color:#b03a2e}{c_j}}=e^{\htmlClass{eqt sym-m}{\htmlStyle{color:#b03a2e}{m_{j-1}}}-\htmlClass{eqt sym-m}{\htmlStyle{color:#b03a2e}{m_j}}}}\)
\(c_j\) is the rescale factor. It equals one while the maximum stays put, and drops below one when a tile brings a bigger score.
\({\displaystyle \htmlClass{eqt sym-p}{\htmlStyle{color:#9a6400}{P_j}}=e^{\htmlClass{eqt sym-s}{\htmlStyle{color:#9a6400}{S_j}}-\htmlClass{eqt sym-m}{\htmlStyle{color:#b03a2e}{m_j}}}}\)
\(P_j\) holds the tile’s exp terms: each score minus the row’s running maximum, then exponentiated.
\({\displaystyle \htmlClass{eqt sym-l}{\htmlStyle{color:#1f618d}{\ell_j}}=\htmlClass{eqt sym-resc}{\htmlStyle{color:#b03a2e}{c_j}}\,\htmlClass{eqt sym-l}{\htmlStyle{color:#1f618d}{\ell_{j-1}}}+\textstyle\sum \htmlClass{eqt sym-p}{\htmlStyle{color:#9a6400}{P_j}}}\)
\(\ell_j\) is the running softmax denominator. The factor scales the old sum so every term shares the new maximum; then the sum along each row of \(P_j\) is added.
\({\displaystyle \htmlClass{eqt sym-ot}{\htmlStyle{color:#117a7a}{\tilde O_j}}=\htmlClass{eqt sym-resc}{\htmlStyle{color:#b03a2e}{c_j}}\,\htmlClass{eqt sym-ot}{\htmlStyle{color:#117a7a}{\tilde O_{j-1}}}+\htmlClass{eqt sym-p}{\htmlStyle{color:#9a6400}{P_j}}\htmlClass{eqt sym-v}{\htmlStyle{color:#a04000}{V_j}}}\)
\(\tilde O_j\) is the running output before division. The same factor scales it with the sum, each row by its own factor, so the stored numbers change but the weights they stand for do not: each weight is an exp term divided by the sum, and both shrank together.
\({\displaystyle \htmlClass{eqt sym-o}{\htmlStyle{color:#117a7a}{O}}=\htmlClass{eqt sym-ot}{\htmlStyle{color:#117a7a}{\tilde O_{\text{last}}}}/\htmlClass{eqt sym-l}{\htmlStyle{color:#1f618d}{\ell_{\text{last}}}}}\)
Dividing by the sum once, after the last tile, gives exactly \(\mathrm{softmax}(S)V\), the same output as the three stored steps.

The same idea on one row of scores split into two tiles.

import numpy as np

TILE = 4
s = np.random.randn(2 * TILE)  # one row of scores
tile1, tile2 = s[:TILE], s[TILE:]
m1, m2 = tile1.max(), tile2.max()
sum1 = np.exp(tile1 - m1).sum()
sum2 = np.exp(tile2 - m2).sum()

m = max(m1, m2)
total = sum1 * np.exp(m1 - m) + sum2 * np.exp(m2 - m)
full = np.exp(s - m).sum()
print(np.allclose(total, full))  # True
  1. 1Each tile's own maximum and sum, the maximum line and the sum line of the card above.
  2. 2Both sums rescaled to the shared maximum by the factor line, which is exactly what a later, bigger maximum triggers.
  3. 3The rescaled total equals the full row's sum, so the final division gives the true softmax.

5 The backward pass recomputes instead of storing

Training also needs the backward pass, which uses the weights \(P\). Instead of reading a stored table, FlashAttention rebuilds each tile from \(Q\), \(K\), \(V\) and the saved per-row number, the logsumexp \(m+\log\ell\) (the log of the softmax denominator, from which every weight of the row follows), so it does more arithmetic and far less traffic. The 2022 paper proves the same traffic growth as the second line of the section 2 card for the backward pass (its Theorem 5).

7 What changed from the 2022 original

The 2022 FlashAttention ran the loops the other way round: keys and values outside, queries inside. It renormalized the output block at every tile, saved both \(m\) and \(\ell\) for the backward pass, and ran in parallel over batch and heads only. FlashAttention-2 (Dao 2023) swaps the loops, so each query block runs on its own and blocks run in parallel along the sequence; it divides by \(\ell\) once at the end, saves only the logsumexp (one number per row from which the backward pass rebuilds the softmax), and splits work better inside the GPU. The math and the exact output are the same.

8 Why the memory traffic matters

FlashAttention does slightly more arithmetic but moves far less data and so runs faster.

The second version is faster because query blocks run in parallel and the output is divided once.

9 Using it

PyTorch's fused attention call routes to FlashAttention-2 when the inputs allow it.

import torch
import torch.nn.functional as F
from torch.nn.attention import sdpa_kernel, SDPBackend

q, k, v = torch.randn(3, 8, 16, 1024, 64, device="cuda", dtype=torch.bfloat16)
with sdpa_kernel(SDPBackend.FLASH_ATTENTION):
    out = F.scaled_dot_product_attention(q, k, v, is_causal=True)
  1. 1Queries, keys and values in bf16 on the GPU; the FlashAttention-2 CUDA kernels take fp16 and bf16, the two 16-bit number formats.
  2. 2Forces the flash backend. If it cannot run on these inputs, the call fails, and PyTorch warns why.
  3. 3One fused call computes the three lines of the first card without storing \(S\) or \(P\).
WhenEvery attention call PyTorch routes to it, in the training forward and backward passes and in full-prompt passes, the setting it was designed and measured for.
KeepsOne number per row, the logsumexp, for the backward pass, so this memory grows in a straight line with \(n\). The 2022 original kept two, \(m\) and \(\ell\).
KernelPyTorch's scaled dot-product attention picks among FlashAttention-2, memory-efficient attention and a C++ math path; its docs say it "attempts to automatically select the most optimal implementation". On NVIDIA GPUs the FlashAttention-2 kernels take fp16 and bf16.
Block sizeThe 2022 paper found runtime falls as the block size grows until, beyond about 256, other factors dominate; larger blocks no longer fit on chip.
CodeF.scaled_dot_product_attention (PyTorch docs), flash-attention (Dao-AILab).
