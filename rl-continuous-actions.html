1 Robot arms set real-numbered turning forces

1.1 A robot arm that turns at its joints

A robot arm must set real-numbered turning forces at its joints every step. This page shows why picking from a fixed list of choices, as the Deep Q-Network (DQN) does when it scores every choice and keeps the best, fails, and what every method that replaces it shares. A short list makes the arm jerky, and a fine one grows huge.

The agent is the learner that picks the moves. (RL Basics) A state is the agent’s situation right now; a move, or action, is one choice the agent can make in a state; a reward is the number the world hands back after each move, good or bad. (RL Basics) On a robot, sensing, moving and earning rewards repeat many times every second.

The running example is the Reacher task: a robot arm with two joints whose actions are four torques. A torque is a turning force a motor applies at a joint. On the Reacher each torque is a number from -1 to 1. Each joint can turn about two axes, so each joint gets two torques. Every step the arm senses its state, numbers describing the position, rotation and speed of its parts, and earns a small reward whenever its hand is inside a moving goal.

A continuous action is a real number, or a list of them, that can take any value in a range, like a torque, instead of one choice from a list. Each of the four torques can take any value in its range, so there is no list of choices to score.

1.2 A list of torque levels is jerky and huge

The return is all the reward still to come, with later rewards counted a little less. (RL Basics) A move’s value \(Q(s,a)\), also called its score, is the return the agent expects if it makes move \(a\) in state \(s\) and plays on from there. (RL Basics) A Q-table keeps one score for every state and move. (Q-Learning) The arm’s joint angles and speeds can take endless values, so such a table could never list them all.

DQN swaps the table for a network. A Q-network is a neural network that takes the state and outputs one score per move, in place of the table. (Deep Q-Networks (DQN)) DQN plays the move with the best score.

On the arm, a list of moves can only come from chopping each torque into a few levels. Few levels make the arm move in jerks, and each extra torque multiplies the list, so it soon grows too long to search. The paper that introduced Deep Deterministic Policy Gradient (DDPG) makes the same point with a seven-joint arm: even a coarse list of levels per joint multiplies into a list far too long to search well.

2 What every continuous-action method shares

2.1 One network scores the state and the torques together

Every method here uses two networks. The critic \(Q_\phi\) is a network with weights \(\phi\) that scores a state and an action together; its score stands for the return the agent expects. For the Reacher the action is the arm’s four torques. The critic takes the torques as an input, unlike DQN’s one output per move in its list. So one network can score any set of torques the arm might send, even ones it has never tried.

2.2 A second network outputs the torques

A policy is the agent’s rule for choosing a move in each state; it may always pick the same move or pick by chance. (RL Basics) Here the policy is a network that must output a whole set of real numbers. An actor is the policy network that picks the action; the critic’s guesses are used to score how good it was. (Actor-Critic: A2C and A3C) The actor’s torques go straight to the arm’s motors at every step.

A deterministic actor outputs one set of torques every time. With no randomness of its own it would never try anything new, so exploring needs noise added from outside. DDPG and Twin Delayed DDPG (TD3) use this kind of actor. Such an actor is cheap to run on a robot, since it needs no random draw.

A stochastic actor draws its torques at random from a bell curve, most often near its centre. Soft Actor-Critic (SAC) uses this kind. Either way, the actor’s torques are the action the critic scores.

2.3 Learning from stored steps

Off-policy means learning the values of one policy while playing another. (SARSA: Learning the Value of the Moves You Play) For this family that means learning from steps an older version of the agent took. Replay keeps a memory of past steps, and training draws random batches from it. (Deep Q-Networks (DQN)) The critic trains on random batches of those stored steps, so it does not learn only from the arm’s last few moves.

The critic learns by being pulled toward a target, the step’s reward plus its own score for what comes next, counted a little less. That target moves whenever the critic moves. Every method here holds that target still by building it from slow copies of its networks, copies updated only a little at a time (taught on Training DDPG).

The actor learns by changing its torques in the direction that raises the critic’s score; the DDPG page shows how. On the arm, the actor’s torques improve only as the critic’s scores improve.

The two lines below show the difference in code, and the name q_net stands for the Q-network.

q_net(state).argmax()
torch.tanh(actor(state))
  1. 1Picks an entry from a list. \(\arg\max\) picks the move whose score is largest. (RL Basics)
  2. 2Gives four torques. The tanh function squashes any number into -1 to 1, the torque range.

3 Continuous-action methods side by side

Proximal Policy Optimization (PPO) is another way to train an actor that draws its torques from a bell curve; it makes small, careful updates and learns only from fresh steps. These methods differ mainly in how they keep the critic from scoring torques above the return the arm really earns, and how they explore.

Two of these methods keep two critics because a single critic tends to score some torques too high. DQN’s target takes a max, the highest of the scores its Q-network gives the next moves. Overestimation means the values climb above the return the agent really earns, because a max over noisy guesses picks lucky ones. (Double DQN) In DDPG and TD3 the actor plays the role of the max, because it learns to pick the torques the critic scores highest; SAC’s actor does the same while keeping its bell wide.

Multi-agent DDPG (MADDPG) trains several agents together, and each agent’s critic sees what all the agents do. Here there is only one arm, so a single critic scores all of its moves. TD3 and SAC both train two critics and trust the lower of their two scores, and TD3 also updates its actor less often.

Entropy \(\mathcal{H}\) is how undecided the policy is; for a bell of torques, it is how wide the bell is. That is the width SAC rewards its actor for keeping.
