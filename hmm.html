Hidden Markov Models (HMM)

A Markov chain is a sequence of states where each step picks the next state by fixed chances. Hide the state, show only what it emits, and you have an HMM, the model behind decades of speech recognition.

1 From a chain you see to a chain you guess

A hidden Markov model (HMM) is a Markov chain whose state you never see, only what each state emits. Given a sequence it answers three questions, as Rabiner (1989) organizes them: how likely the sequence is (the forward pass), which hidden state made each step (Viterbi), and which chances make the sequence most likely (Baum-Welch, which is EM). Baum-Welch fits once, offline, over the training sequences; after that, scoring or decoding a new sequence is one pass over it.

2 In a Markov chain, tomorrow depends only on today

Take a toy weather model in which sunny days and rainy days both tend to repeat (Figure 2). Nothing before today matters, which is the Markov assumption (the independence idea from Probability and Bayes Rule).

A Markov chain is fully described by one table of next-step chances, and that table alone fixes the long-run share of days in each state.
\(\displaystyle A_{ij} = P(z_{t+1} = j \mid z_{t} = i)\)
\(z_{t}\) is the state on day \(t\). \(A_{ij}\) is the chance that state \(i\) today becomes state \(j\) tomorrow. Only today’s state sits right of the bar, which is the Markov assumption written out. Row \(i\) lists everywhere \(i\) can go next, so each row adds to 1, and a large number on the diagonal means a sticky state.
\(\displaystyle \htmlStyle{color:#0e6b59}{s} = \htmlStyle{color:#0e6b59}{s} A\)
\(s\) is a row of shares, the fraction of days in each state. Multiplying it by \(A\) gives the next day’s shares: each new share adds today’s shares times the chance of moving there. The long-run row is the one that one more step leaves unchanged, so flow out of each state equals flow in. A state that is harder to leave ends up holding more of the days, and the long-run \(s\) is the same whatever the first day was.

Figure 3. Stickier weather gives longer runs but leaves the long-run rainy share where it was.

This snippet simulates the chain from \(A\) alone and prints the share of rainy days; it settles on the long-run share that one more step leaves unchanged.

import numpy as np
SUNNY, RAINY = 0, 1
A = np.array([[0.8, 0.2], [0.4, 0.6]])
rng = np.random.default_rng(1)
days = [SUNNY]
for _ in range(999):
    days.append(rng.choice(2, p=A[days[-1]]))
print(np.mean(np.array(days) == RAINY))  # the long-run rainy share

3 Hide the state and you get the dishonest casino

Hide which die is in use, and you get an HMM. A dealer mostly rolls a fair die but sometimes swaps in a loaded one that rolls six half the time (the occasionally dishonest casino, Durbin et al. 1998). You see the rolls, never the die.

An HMM keeps the hidden chain and adds two tables: what each hidden state emits, and where the chain starts.
\(\displaystyle B_{j}(o) = P(\text{roll } o \mid z_{t} = j)\)
\(o\) is a die face. \(B\) is the emission table, and \(B_{j}(o)\) is the chance that die \(j\) rolls face \(o\). A face that one die rolls far more often than the other is evidence for that die, and ratios like that are what let the model tell the dice apart.
\(\displaystyle \pi _{j} = P(z_{1} = j)\)
\(\pi\) is the start. \(\pi _{j}\) is the chance the first roll uses die \(j\), one half each here. It shapes only the first roll; after that \(A\) takes over.

4 How likely are these rolls? The forward pass

Adding up every possible die sequence is hopeless: every extra roll doubles their number.

The forward pass gives the chance of all the rolls by keeping one running total per die per roll, so the work grows with the number of rolls, not with the number of die sequences.
\(\displaystyle \htmlStyle{color:#7d3c98}{\alpha _{1}(j)} = \pi _{j} B_{j}(o_{1})\)
\(o_{t}\) is the face shown at roll \(t\). \(\alpha _{t}(j)\) is the chance of the rolls up to \(t\), ending with die \(j\) at roll \(t\). The first roll has no previous die, so it is just the start chance times the chance that die \(j\) rolls \(o_{1}\).
\(\displaystyle \htmlStyle{color:#7d3c98}{\alpha _{t}(j)} = [\sum_{i} \htmlStyle{color:#7d3c98}{\alpha _{t-1}(i)} A_{ij}] B_{j}(o_{t})\)
To end in \(j\) at roll \(t\), the chain sat in some die \(i\) at roll \(t - 1\) and stepped to \(j\). Adding those incoming paths, each times its step chance \(A_{ij}\), gathers every path into \(j\) at once, and \(B_{j}(o_{t})\) then scores the new roll. Each cell needs only the column before, so the work grows by one column per roll while the number of paths doubles with every roll. With \(N\) hidden states and \(T\) rolls that is about \(N^{2} T\) steps.
\(\displaystyle P(o_{1}, \dots , o_{T}) = \sum_{j} \htmlStyle{color:#7d3c98}{\alpha _{T}(j)}\)
\(T\) is the last roll. Adding the last column over both dice gives the chance of all the rolls, with every die sequence included.

CTC, the speech recognition loss that adds up every way to line a transcript up with the audio, fills the same kind of table over label positions. The totals shrink with every roll, since each one multiplies in more chances below 1, so real code works in logs (see Maximum Likelihood Estimation) or rescales each column.

This snippet runs the forward pass in logs on nine rolls and prints the log chance of all of them.

import numpy as np
from scipy.special import logsumexp
logA = np.log([[0.95, 0.05], [0.10, 0.90]])
logB = np.log([[1/6] * 6, [0.1] * 5 + [0.5]])
pi = np.array([0.5, 0.5])
o = np.array([3, 1, 4, 2, 5, 3, 6, 6, 6]) - 1
log_a = np.log(pi) + logB[:, o[0]]
for t in range(1, len(o)):
    log_a = logsumexp(log_a[:, None] + logA, axis=0) + logB[:, o[t]]
print(logsumexp(log_a))  # log P(rolls)

  3. 3Fills each next column from the last, line 2, in logs.
  4. 4Adds the last column to get the chance of the rolls, line 3.

5 Which die when? Viterbi keeps the best path into each cell

The Viterbi algorithm (Viterbi 1967) answers the second question, which die made each roll. It fills the same table as the forward pass but keeps only the best path into each cell, a max in place of the sum, and remembers which cell that path came from. At the last roll it walks those remembered choices back and reads off one die per roll.

Figure 7. Darker cell, better die so far; three sixes flip the path at roll 7.

Viterbi finds the single most likely die sequence by filling the same table with max in place of the sum.
\(\displaystyle \htmlStyle{color:#c0392b}{\delta _{1}(j)} = \pi _{j} B_{j}(o_{1})\)
\(\delta _{t}(j)\) (delta) is the chance of the single best path that ends with die \(j\) at roll \(t\). It starts exactly like \(\alpha\), since one roll has only one path into each die.
\(\displaystyle \htmlStyle{color:#c0392b}{\delta _{t}(j)} =\)
\(\displaystyle \max _{i} [\htmlStyle{color:#c0392b}{\delta _{t-1}(i)} A_{ij}] B_{j}(o_{t})\)
Keep only the best incoming path, from whichever die \(i\) gives the largest value, and remember that \(i\). A sum lets many weak paths add up; max keeps one, so \(\delta\) answers which path while \(\alpha\) answers how likely overall. At the end, follow the remembered choices back from the best last cell.

This snippet runs Viterbi on the same nine rolls and prints the best die per roll.

import numpy as np
logA = np.log([[0.95, 0.05], [0.10, 0.90]])
logB = np.log([[1/6] * 6, [0.1] * 5 + [0.5]])
o = np.array([3, 1, 4, 2, 5, 3, 6, 6, 6]) - 1
log_delta = np.log([0.5, 0.5]) + logB[:, o[0]]
back = []
for t in range(1, len(o)):
    scores = log_delta[:, None] + logA
    back.append(scores.argmax(axis=0))
    log_delta = scores.max(axis=0) + logB[:, o[t]]
path = [int(log_delta.argmax())]
for ptr in reversed(back):
    path.append(int(ptr[path[-1]]))
print(path[::-1])  # best die per roll, 0 = fair
  1. 1Sets the same casino and rolls.
  2. 2Starts \(\delta_{1}\), eq card in Section 5, line 1.
  3. 3Keeps the best path into each cell and its back pointer, lines 2 and 3.
  4. 4Follows the back pointers from the last roll, the path drawn in Figure 7.

6 How sure at each roll? Forward times backward

Viterbi gives one best path. Sometimes you want a chance for every roll instead: how likely is it that the loaded die made roll \(t\)? Run the table backward as well and combine the two.

A forward and a backward pass together give, for every roll, the chance that each die made it, using the rolls both before and after.
\(\displaystyle \htmlStyle{color:#a04000}{\gamma _{t}(j)} = \frac{\alpha _{t}(j) \beta _{t}(j)}{P(o_{1}, \dots , o_{T})}\)
\(\gamma _{t}(j)\) is the chance die \(j\) was in use at roll \(t\), given every roll. \(\alpha\) covers the rolls up to \(t\). \(\beta _{t}(j)\), from a backward pass, is the chance of the rolls after \(t\) given die \(j\) at \(t\). Their product is the joint chance of die \(j\) at \(t\) and all the rolls, and dividing by the chance of all the rolls is the same flip as Bayes rule. A run of sixes just after \(t\) raises \(\beta\) for loaded, so a roll can look loaded because of what follows it, which the forward pass alone cannot see.

On 30 rolls, the model’s switch chance matters. Fair goes to loaded with chance \(q\) and back with \(2q\); the dealer’s real \(q\) is 0.05.

Figure 8. A low \(q\) almost never switches dice; a high \(q\) switches often, jumping to loaded at lone sixes.

7 Baum-Welch learns the numbers with EM

If \(A\) and \(B\) are unknown, learn them from the rolls with EM, Expectation-Maximization, here called Baum-Welch (Baum et al. 1970). The E step runs forward and backward to get soft counts; the M step divides counts. The updates are essentially EM’s, so the likelihood never drops and the fit can stop at a local peak.

Each Baum-Welch round re-estimates \(A\) as the expected share of steps out of \(i\) that go to \(j\).
\(\displaystyle A_{ij} \leftarrow\)
\(\displaystyle \frac{\text{expected steps from } i \text{ to } j}{\text{expected steps out of } i}\)
Both counts come from the forward and backward tables: each possible step is counted at its chance, not as 0 or 1. It is the counting formula of maximum likelihood with soft counts in place of seen ones, so if the tables say the chain mostly stayed put, the stay chances in \(A\) come out large.

The official hmmlearn casino example fits 50 times from random starts and keeps the best fit.

8 HMMs in practice

With hmmlearn the three questions are three calls on rolls stored as one column, and the fit runs from several starts as Section 10 advises; several sequences are stacked into one array, and lengths says where each one ends, so no step is counted across the join.

import numpy as np
from hmmlearn import hmm
casino = hmm.CategoricalHMM(n_components=2)
casino.startprob_ = np.array([0.5, 0.5])
casino.transmat_ = np.array([[0.95, 0.05], [0.10, 0.90]])
casino.emissionprob_ = np.array([[1/6] * 6, [0.1] * 5 + [0.5]])
rs = np.random.RandomState(1)
X1, _ = casino.sample(300, random_state=rs)
X2, _ = casino.sample(200, random_state=rs)
X, lengths = np.concatenate([X1, X2]), [len(X1), len(X2)]
best_score, model = -np.inf, None
for seed in range(10):
    candidate = hmm.CategoricalHMM(n_components=2, n_iter=50, random_state=seed)
    candidate.fit(X, lengths)
    score = candidate.score(X, lengths)
    if score > best_score:
        best_score, model = score, candidate
log_prob, path = model.decode(X2)
gamma = model.predict_proba(X2)
print(model.transmat_.round(2), log_prob)

9 HMMs in speech

Classic speech recognizers model each word or sound unit as a chain of left-to-right states that can stay or move on, never back. A Gaussian mixture under each state scores the sound frames, often MFCCs (see MFCC and Other Audio Features), and Viterbi finds the best path. Hinton et al. (2012) showed deep neural networks (see Multilayer Perceptrons) beating those mixtures as the frame scorers on many benchmarks, and CTC later dropped the explicit HMM while keeping a forward table.

10 Common traps

  • Long sequences drive the totals to zero (underflow); work in logs or rescale each column.
  • Baum-Welch climbs to the nearest local peak; use several starts and keep the best.
  • Fair and loaded can swap names between runs (label switching).
  • The Markov assumption has a short memory: it forgets everything older than one step.
  • A zero in \(A\) or \(B\) rules out every path through it; smooth the counts.
  • Too many states for the data overfit, as with too many mixture components.

11 What if the structure is a direction, not a hidden state?

Mixtures and HMMs look for hidden groups. Principal Component Analysis looks for the few directions along which the data stretches most.
