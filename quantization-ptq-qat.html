1 When the ranges get fixed

A ResNet50 trained on ImageNet has to run on a phone, so its weights and activations must be stored as 8-bit codes. Each float value becomes a whole-number code and is read back, and the grid it is read back on must fit the values the model actually sees. Post-Training Quantization (PTQ) quantizes a trained model once, with no retraining, and the only question is when each activation range gets fixed.

The round trip from Quantization Basics, run on every weight and activation.
\(\displaystyle \htmlStyle{color:#a04000}{x_{q}} = \operatorname{round}\left(\frac{\htmlStyle{color:#2471a3}{x}}{\htmlStyle{color:#2471a3}{s}}\right) + \htmlStyle{color:#5d6d7e}{z}\)
The scale \(s\) is one grid step, so \(x/s\) counts steps and round picks the nearest integer; the zero point \(z\) shifts the count so float 0 lands on an integer.

A code outside the 8-bit grid is clipped to the nearest end. The full three-line round trip lives in Quantize one tensor.

The listings use PyTorch's torch.ao.quantization (now marked deprecated, see Quantization in practice).

Dynamic PTQ acts every batch at inference and carries only quantized weights between steps; static PTQ acts once before deployment and carries baked-in ranges after that. Section 2 teaches the per-batch mode, and section 3 teaches the once-before-deployment mode.

2 Dynamic quantization

Dynamic quantization is the low-effort option: the weights are quantized once after training. Activations arrive in float32 and get quantized to int8 on the fly, per batch. Each batch sets its own range and drops it after.

One call to quantize_dynamic takes a trained float model, returns qmodel, and swaps every nn.Linear for an int8 version (PyTorch's qint8, signed integers −128 to 127; quint8 is the unsigned 0 to 255 type).

import torch.nn as nn
import torch.ao.quantization as tq

model.eval()
layers = {nn.Linear}  # default dtype qint8
qmodel = tq.quantize_dynamic(model, layers)
  1. 1Inference mode.
  2. 2Swaps every linear layer for a dynamic int8 version.

It helps most on CPUs, for LSTMs (recurrent networks that read a sequence one step at a time; see Gated RNNs: GRU and LSTM) and Linear-heavy models such as Transformers. In our run of the companion notebook, on its small MNIST (handwritten-digit) CNN (convolutional neural network), accuracy barely moved (Figure 2).

Why not CNNs? PyTorch's dynamic quantization does not cover Conv2d, and it pays off only when loading weights dominates run time. In a CNN, the activation maps dominate, and dynamic quantization keeps those activations in float32. Static quantization keeps them int8, which is why Figure 10 sends CNNs to static PTQ (Static quantization).

3 Static quantization

Static quantization runs everything in int8: weights and activations. The activations' range is measured once, before deployment: calibration runs some inputs through the model (no labels needed) and records each activation's range. It suits CNNs on phones and small boards.

The listings on this page and on Debugging a Quantized Model share one toy model, TinyCNN, on 1×28×28 MNIST images, defined in the next listing.

import torch.nn as nn

class TinyCNN(nn.Module):
    def __init__(self):
        super().__init__()
        # 1x28x28 -> 8x26x26
        self.conv1 = nn.Conv2d(1, 8, 3)
        self.relu1 = nn.ReLU()
        self.pool = nn.MaxPool2d(2)
        self.fc = nn.Linear(8 * 13 * 13, 10)

    def forward(self, x):
        h = self.relu1(self.conv1(x))
        h = self.pool(h)
        return self.fc(h.flatten(1))
  1. 1One 3x3 convolution with 8 channels, ReLU, 2x2 pooling, and a 10-class linear layer.
  2. 2Forward pass: convolution, ReLU, pooling, flatten, classify.

Calibration is a measuring pass: real inputs flow through the model once, and each observer notes the range of values it actually sees, so the grid is fitted to the activations the model will meet in use.

Calibration needs an observer, a small module PyTorch inserts after a tensor that records its min and max (or its histogram) and computes \(s\) and \(z\) from them as in Scale and zero point. In the eager-mode listing below (eager mode places stubs, the quantize and dequantize markers at the model's entry and exit, and fusions by hand; FX, PyTorch's graph-tracing toolkit, automates them), the backend is the library that runs the int8 ops ("x86" on Intel and AMD CPUs, "qnnpack" on ARM).

import copy, torch
import torch.ao.quantization as tq

fp32 = copy.deepcopy(model_fp32).eval()
model = tq.QuantWrapper(fp32)
pair = [["conv1", "relu1"]]
tq.fuse_modules(fp32, pair, inplace=True)
model.qconfig = tq.get_default_qconfig("x86")
# insert observers
tq.prepare(model, inplace=True)
# calibrate
with torch.no_grad():
    for x, _ in calib_loader:
        model(x)
# swap in int8 modules
tq.convert(model, inplace=True)
  1. 1Float copy wrapped with quant and dequant stubs; conv1 and relu1 fused into one op (walkthrough step 2).
  2. 2Default x86 QConfig, then observers inserted (walkthrough step 3).
  3. 3Calibration: run real batches so the observers record ranges (walkthrough step 4).
  4. 4Replaces each module with its int8 version (walkthrough step 5).

In our run of the companion notebook, on its larger fused MNIST CNN trained for 10 epochs, accuracy held and the model shrank to a quarter of its size (Figure 3).

3.1 Fuse first

Fusing Conv + BatchNorm (a layer that rescales each batch of activations to a steady range) + ReLU (which zeroes negatives and passes positives) into a single op before quantizing saves memory traffic, runs faster, and removes the rounding step between the three (Figure 4). At inference the batch norm's scale and shift fold into the convolution's weights. Dynamic mode has no fusion step.

3.2 QConfig sets the grid per tensor or per channel

Figure 5 shows that choice: one shared scale, or one per channel.

A QConfig tells PyTorch how to quantize each tensor: symmetric or asymmetric (both drawn in Scale and zero point), and per-tensor (one scale for the whole tensor) or per-channel (one scale per channel, a channel being the output of one convolution filter; Figure 5).

Per-channel gives each narrow channel its whole grid, for a few extra numbers per layer and a backend that supports it. PyTorch's x86 default uses per-channel weights and per-tensor activations (qconfig source).

import torch.ao.quantization as tq

# quint8 activations
act = tq.MinMaxObserver
# int8, one scale per output channel
wt = tq.default_per_channel_weight_observer
qc = tq.QConfig(act, wt)
model.qconfig = qc
  1. 1Activation observer: per-tensor min-max, unsigned 8-bit.
  2. 2Weight observer: per-channel, signed 8-bit.
  3. 3Both go into one QConfig on the model.

3.3 Calibration data

A few hundred real inputs are usually enough. The observer only knows the values calibration showed it (Figure 6): if the set is too small or does not look like production, it learns the wrong ranges and either clips real activations or wastes resolution (Figure 9).

3.4 Histogram observers

One outlier stretches a min-max range over every bin (A real weight histogram). A histogram observer applies the mean squared error (MSE) strategy from Where the range should end (Nagel et al., 2021) to activations: it builds a histogram of what it sees, tries many clipping ranges, and keeps the one with the smallest round-trip error.

The observer keeps the clipping range \(r\) whose round trip, on the recap line in section 1, loses the least.
\(\displaystyle \text{range} = \operatorname{argmin}_{r} \lVert \htmlStyle{color:#2471a3}{x} - \htmlStyle{color:#a04000}{\hat{x}}_{r} \rVert^{2}\)
\(x\) is what the observer saw during calibration and \(\hat{x}_{r}\) is the same values quantized with range \(r\) and read back. Squaring the gaps makes one clipped outlier cost far more than many small rounding misses, so the winner clips only the rare extreme values.

The QConfig below, as in Static quantization, swaps in a histogram observer for activations and keeps per-channel MinMax weights.

import torch.ao.quantization as tq

# quint8, MSE range from histogram
act = tq.HistogramObserver
# int8, one scale per output channel
wt = tq.default_per_channel_weight_observer
qc = tq.QConfig(act, wt)
model.qconfig = qc
  1. 1Activations get the histogram observer, which picks the range that minimizes the error in the card above.
  2. 2Weights keep the per-channel signed 8-bit observer from 2.2.
  3. 3Both go into one QConfig on the model.

It matters most when activations have long tails, skew, or several peaks.

On ImageNet image classification, ResNet50 with weights and activations quantized to 8 bits by post-training quantization, following the five-rule guideline below (Hu, Zeng and Wu, 2023) with no additional training, keeps ResNet50 essentially at full-precision accuracy. The guideline is: a KL-divergence scale with a tolerance coefficient for activation scales; MinMax scales for weights; channel-wise quantization for weights; unsigned quantization for positive activations; and addition inputs in residual branches kept in floating point rather than quantized.

3.5 Keeping tensors quantized between layers

Every quant-dequant boundary moves data from int8 to float and back, which kills performance and breaks layer fusion (Figure 7). ReLU, pooling and many elementwise ops quantize safely, so everything between the entry and exit stubs can stay int8. In eager mode the listing below places the stubs by hand, as QuantWrapper did above; FX inserts them itself.

import torch.nn as nn
import torch.ao.quantization as tq

class QuantTinyCNN(nn.Module):
    def __init__(self):
        super().__init__()
        self.quant = tq.QuantStub()
        self.body = TinyCNN()
        self.dequant = tq.DeQuantStub()

    def forward(self, x):
        h = self.body(self.quant(x))
        return self.dequant(h)
  1. 1A quant stub at the entry, the float network, a dequant stub at the exit.
  2. 2Inputs are quantized once and outputs dequantized once.

3.6 FX graph mode

FX, PyTorch's graph-tracing toolkit, turns the model into a graph, so FX quantization applies the qconfig to every nested layer, inserts the observers and stubs, and fuses layers itself.

In the FX version, qfx.prepare_fx traces model_fp32 with one example input and inserts observers, calibration fills them, and qfx.convert_fx returns the int8 model. To check where FX put the observers, see Read the FX graph table.

import torch
import torch.ao.quantization as tq
import torch.ao.quantization.quantize_fx as qfx

example = (torch.randn(1, 1, 28, 28),)
qmap = tq.get_default_qconfig_mapping("x86")
model = model_fp32.eval()
prep = qfx.prepare_fx(model, qmap, example)
# calibrate
with torch.no_grad():
    for x, _ in calib_loader:
        prep(x)
model_int8 = qfx.convert_fx(prep)
  1. 1FX traces the model and inserts observers from the default mapping.
  2. 2Calibration batches fill the observers.
  3. 3Converts to int8 kernels.

4 Static quantization in practice

  • Static PTQ costs one no-grad forward pass over the calibration set. PyTorch's accuracy guide asks for at least 100 samples with several per class (Quantization Accuracy Debugging).
  • PyTorch now marks torch.ao.quantization eager and FX quantization for migration to torchao (quantize_ for eager, prepare_pt2e and convert_pt2e for graph mode) and plans to delete it in a future release (PyTorch 2.15 quantization docs). The ideas on this page carry over unchanged; the import paths do not.
  • A model left in train mode during calibration keeps dropout and batch-norm updates on, and the ranges come out wrong.

What goes wrong, and the fix.

  • Calibration set too small or unlike production: the observers never saw the loud values, so real activations clip at deployment. Recalibrate on a larger, production-like set; calibration needs no labels, so production inputs can be used.
  • Model left in train mode during calibration: dropout and BatchNorm updates stay on, so the ranges shift from run to run. Call model.eval() before calibration.
  • Dynamic quantization on a CNN: activation maps dominate run time while dynamic keeps them in float32, with no Conv2d coverage, so there is no speedup despite smaller weights. Use static PTQ.
  • Per-tensor scale on a layer with one wide channel: a shared scale stretched by one channel leaves narrow channels almost no grid ticks (Figure 5). Use per-channel weight scales.
  • Quant-dequant hops between layers: stubs placed per layer instead of only at entry and exit add conversions and block fusion (Figure 7). Keep stubs at entry and exit only.

Fuse before quantizing. Check where FX put the observers in Debugging a Quantized Model. Ranges are baked in after convert, so a bad calibration means calibrating again.

The PyTorch quantization docs tie each path to a different bottleneck (Figure 10).

When static PTQ loses too much accuracy, what then? Quantization-Aware Training trains with the rounding switched on, so the model learns around it.
