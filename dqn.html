Deep Q-Networks (DQN)

One value per move, learned with a network, a replay buffer and a target network.

In reinforcement learning an agent tries moves, receives a score, and learns which moves lead to a higher score.

The running example is an agent that collects bananas in a Unity ML-Agents arena (ML-Agents is a toolkit for building game-like training environments in the Unity game engine); the code is in the Value-based-methods repo. The agent picks one of four moves (forward, backward, turn left, turn right) and gets +1 for a yellow banana and −1 for a blue one.

A Deep Q-Network (DQN) learns one number per move, the Q-value: how much future score that move is worth in the current situation. A neural network maps what the agent senses to those numbers, the agent takes the move with the biggest one, and training pushes each number toward the reward that followed plus the value of the next situation.

DQN acts every step but learns only every fourth step (Figure 1).

1 The banana arena

The world is a square room of yellow and blue bananas. The episode score is yellows minus blues when a fixed clock runs out.

The agent senses the room as 37 numbers: its velocity plus ray sensors, each reporting the distance to the nearest yellow banana, blue banana or wall.

The arena counts as solved when the average score over 100 consecutive episodes reaches 13 (the Udacity project's solve rule). The repo's training script would stop early at a stricter average of 17.0; the run in Figure 9 plays all 1,600 episodes.

One episode in code. brain_name is the key of the arena's one agent in the output of env; agent holds the network and the replay buffer (Section 6) and learns every fourth agent.step call; eps is the chance of a random move (Section 3).

DECAY, EPS_MIN = 0.998, 0.01

out = env.reset(train_mode=True)
info = out[brain_name]
s = info.vector_observations[0]
score = 0
while True:
    a = agent.act(s, eps)
    out = env.step(a)
    info = out[brain_name]
    r = info.rewards[0]
    obs = info.vector_observations
    s_next = obs[0]
    d = info.local_done[0]
    agent.step(s, a, r, s_next, d)
    score += r
    s = s_next
    if d:
        break
eps = max(eps * DECAY, EPS_MIN)
  1. 1Resets the arena and reads the first 37-number state.
  2. 2Plays one episode: act, observe the reward, the next state and the episode-end flag d, and pass all five to the agent.
  3. 3Decays ε once per episode, never below EPS_MIN.

2 Q-values and Q-learning

The RL Basics page introduced Q-values: one number for every situation and move, the expected score of that move there. Q-learning keeps them in a table and corrects one entry after every move.

A policy is the rule that turns a situation into a move; DQN's policy is to take the move with the biggest Q-value.

After each move, the table entry for that move shifts part of the way toward what actually happened plus the best guess about what comes next.
Q(s,a) ← Q(s,a) + α[r + γ·max Q(s′,a′) − Q(s,a)]
The table's guess Q(s,a) is the score for move a in situation s. The bracket is the miss: the reward r just earned plus γ times max Q(s′,a′), the best guess from the next situation s′, minus the current guess. γ, the discount between 0 and 1, makes later rewards count less than immediate ones. α, the learning rate (alpha in the code below), moves the guess only that share of the way, so one lucky or unlucky step cannot overwrite everything learned so far. Because the target uses the max over next moves, the update learns the value of acting well next, whatever the agent actually does next.

Tabular Q-learning in a few lines. N_MOVES is 4 and s_next is the state after the move.

import random

if random.random() < epsilon:
    a = random.randrange(N_MOVES)
else:
    row = Q[s]
    a = row.index(max(row))
best = max(Q[s_next])
target = r + gamma * best
td = target - Q[s][a]
Q[s][a] += alpha * td
  1. 1Epsilon-greedy: a random move with probability ε, else the move with the highest Q.
  2. 2Q-update: moves Q[s][a] a step α toward the target (eq card in Section 2, line 1).

3 Epsilon-greedy exploration

An agent that always takes its best-known move never tries anything new. So with probability epsilon, ε, it takes a random move instead.

Epsilon starts at 1.0, all random, and falls toward a floor of 0.01.

After every episode, epsilon shrinks by the same small factor, so random moves fade out slowly.
ε ← ε · 0.998
ε, epsilon, is the probability of a random move. Multiplying it by 0.998 after each episode removes 0.2 percent of what is left. The share is the same every episode, so the steps shrink from 0.002 at the start to under 0.0001 by the end: exploration fades instead of switching off.
0.9981600 ≈ 0.04
Sixteen hundred of those shrinks, starting from 1.0, leave ε at about 0.04, still above the 0.01 floor: late in training the agent takes a random move about once in 25 steps.

Random moves still teach the agent, because Q-learning is off-policy: the target uses the best next move (the max in the update), whatever move the agent actually takes.

5 Fixed versus decaying epsilon

In the race one agent keeps epsilon at 1.0 forever and the other shrinks it after every episode down to a floor.
εfixed = 1.0
The fixed agent's εfixed stays at 1.0, so every move it makes is random. Its table still learns, but it never uses what it learns.
εdecay ← max(εdecay · 0.97, 0.01)
The decaying agent's εdecay is multiplied by a decay factor after each episode (0.998 in the repo, 0.97 in this race so it finishes fast), and max keeps the larger of that product and 0.01, so it stops at the floor of one random move in a hundred instead of reaching zero. Early on it explores as much as the fixed agent; later it mostly takes its best-known move.

6 From a Q-table to a Deep Q-Network

Tabular Q-learning (Watkins, 1989) needs one row per situation; 37 continuous numbers make too many for a table.

DQN (Mnih et al., 2015) replaces the Q-table with a neural network: 37 numbers in, four Q-values out. The update rule and the take-the-max choice stay the same.

The network estimates values for unseen situations by similarity to seen ones. That sharing makes training unstable in two ways, and DQN adds one fix for each.

The DQN paper learned control from raw screen pixels with a convolutional network (layers that scan the input for small local patterns), trained with Q-learning and stabilized by both fixes (Figure 5). The banana agent feeds 37 numbers instead of pixels.

6.1 Experience replay

The first fix is experience replay. Consecutive steps are almost identical, so training on them in order fits one corner of the arena and forgets the rest.

A replay buffer stores past steps, and training draws random batches from it (Figure 6).

import random
from collections import deque

BUFFER_SIZE = 100_000
BATCH = 64
buf = deque(maxlen=BUFFER_SIZE)
buf.append((s, a, r, s_next, d))
batch = random.sample(buf, BATCH)
  1. 1Creates a replay buffer that drops the oldest memory when full.
  2. 2Stores one transition with its episode-end flag d and samples a random batch.

6.2 Target networks

The second fix is the target network. If the network being trained also computes its own target, every gradient step (one small weight change that lowers the loss) moves the guess and the target together, and the Q-values can keep growing instead of settling.

A second copy of the network computes the targets and moves toward the live network by a small share after each update, the soft update the repo uses. The 2015 DQN paper instead copied the live network into it every 10,000 updates (its hyperparameter table), frozen in between.

6.3 One training step with both fixes

One training step, run once for each batch from the replay buffer:

In one DQN training step the target network sets a target, the live network is trained toward it, and the target network then moves slowly toward the live network.
y = r + γ·maxa′ Q(s′,a′;θ⁻)
The target y is the reward r just earned plus γ times the best value the target network sees from the next state s′, maximized over the moves a′ available there. It is the tabular target with the table replaced by a network. The semicolon separates inputs from weights, and θ⁻ marks the target network's weights: because they do not change during this step, the target holds still while the live network moves toward it. On the last step of an episode there is no next state, so the code in Section 10 drops the γ term.
loss = E[(y − Q(s,a;θ))²]
The loss is E, the average over the batch of 64 memories, of the squared gap between y and the live network's guess Q(s,a;θ) for the move actually taken. A network has no table entry to change directly, so the gap becomes a loss and a gradient step lowers it. Squaring keeps high and low misses from cancelling and makes the worst guesses pull hardest.
θ⁻ ← τθ + (1−τ)θ⁻
The arrow means "is replaced by": the target network's weights θ⁻ become a blend of a small share τ of the live weights θ and the rest, 1−τ, of their own. A small τ keeps the target slow and steady; τ = 1 would copy the live network every step and bring back the moving target.

The same three lines in PyTorch, with opt an Adam optimizer over q_live; s, a, r and s_next are a batch of 64 steps, a and r as (64, 1) columns.

import torch
import torch.nn.functional as F

GAMMA, TAU = 0.99, 1e-3

def soft_update(tgt, src):
    old = list(tgt.parameters())
    new = list(src.parameters())
    with torch.no_grad():
        for t, p in zip(old, new):
            t.lerp_(p, TAU)

with torch.no_grad():
    q_next = q_target(s_next)
    best = q_next.max(1, True)
    y = r + GAMMA * best.values
q_sa = q_live(s).gather(1, a)
loss = F.mse_loss(q_sa, y)
opt.zero_grad()
loss.backward()
opt.step()
soft_update(q_target, q_live)
  1. 1Defines soft_update: moves each target weight a fraction τ toward the live weight.
  2. 2Computes the target y from the target network, without gradients; max(1, True) keeps it a (64, 1) column (eq card in Section 6.3, line 1).
  3. 3Moves Q(s, a) toward y by mean squared error (line 2).
  4. 4Soft-updates the target network (line 3).

9 Dueling and Double DQN

The network in the repo is a Dueling Double DQN. The dueling part splits the network into two streams, one estimating how good the situation is and one estimating how much better each move is than average, then adds them (Wang et al., 2016).

The dueling network splits each Q-value into one value for the situation plus each move's edge over the average move.
Q(s,a) = V(s) + A(s,a) − meana′ A(s,a′)
V(s) is the value of being in situation s, whatever move follows. A(s,a), the advantage, is how much better move a is than average there. Subtracting the mean advantage over all moves a′ makes the advantages average to zero, so V(s) alone carries the situation's value and the split is unique. When a situation is bad for every move, only V has to learn that, once, instead of every move's Q-value separately.

The double part reduces overestimation, Q-values that come out too high. Double DQN (van Hasselt et al., 2016) picks the next move with the live network and scores it with the target network.

In the double target the live network picks the next move and the target network evaluates it.
y = r + γ·Q(s′, argmaxa′ Q(s′,a′;θ); θ⁻)
The inner argmax uses the live weights θ to choose the next move; the outer Q uses the target network's weights θ⁻ to evaluate it. In the plain target one network both picks and evaluates, so any move it happens to overrate gets picked and its inflated value enters the target. With two networks, a move overrated by one is less likely to be overrated by the other; the Double DQN paper shows this reduces overestimation on Atari games.

10 DQN in practice

The repo learns every 4 environment steps once the buffer holds more than 64 steps (Figure 10); Stable-Baselines3 has a widely used PyTorch DQN.

Acting costs one forward pass. A learning step costs forward passes of both networks on 64 next states, a forward and backward pass on 64 states, and one blend of the target weights. The 100,000-step buffer is about 30 MB as 32-bit floats.

learn_step is the repo's learning step with the Double DQN target, using q_live, q_target, opt and soft_update from above.

import torch
import torch.nn.functional as F

GAMMA, TAU = 0.99, 1e-3

@torch.no_grad()
def td_target(r, s_next, done):
    live_q = q_live(s_next)
    a2 = live_q.argmax(1, True)
    tgt_q = q_target(s_next)
    q_t = tgt_q.gather(1, a2)
    keep = 1 - done
    return r + GAMMA * q_t * keep

def learn_step(batch):
    s, a, r, s_next, done = batch
    y = td_target(r, s_next, done)
    q_sa = q_live(s).gather(1, a)
    loss = F.mse_loss(q_sa, y)
    opt.zero_grad()
    loss.backward()
    opt.step()
    soft_update(q_target, q_live)
  1. 1Double DQN target (the double target card, line 1): the live network picks the next move and the target network scores it; keep is 0 at the end of an episode.
  2. 2Regresses Q(s, a) toward y.
  3. 3Soft-updates the target network.

Three mistakes break this loop.

  • Store the episode-end flag and multiply the future by 1 − done; without it the last step of an episode takes value from the next episode. Store done as a float; PyTorch cannot subtract a bool tensor from 1.
  • Keep a, r and done as (64, 1) columns; a (64,) reward broadcast against (64, 1) values silently becomes (64, 64).
  • Wait until the buffer holds more than one batch before learning, as the repo does.

12 DQN needs discrete actions

DQN takes the max over a short list: four moves, four Q-values. With a continuous action, such as a push anywhere from 0.0 to 1.0, there are infinitely many actions and no list to take the max over.

So how do you pick the best action when there are infinitely many? The Deep Deterministic Policy Gradient (DDPG) page answers it: DDPG keeps the Q-value and adds a second network, the actor, that outputs the action directly.
