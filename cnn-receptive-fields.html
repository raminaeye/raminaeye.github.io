Receptive Fields, Dilation and Causal Convolutions

  1. CNN Basics
  2. Receptive Fields
  3. CNN Architectures Overview
  4. AlexNet
  5. VGG
  6. Inception
  7. ResNet
  8. Efficient CNNs

Every output of a CNN sees only a limited window of its input, its receptive field. Stacking layers and striding widen that window, spreading a kernel’s taps apart (dilation) widens it with no extra weights, and for a live signal the window must reach only into the past.

This page builds on CNN Basics: Convolution, Stride and Pooling, which slides a kernel over the input with a stride and keeps one value per patch with pooling.

1 Receptive field

A neuron's receptive field (\(\text{RF}\)) is the patch of input pixels that can change its value; this page also calls it the window. Early layers see edges; deep layers can see whole objects, but only if the window is large enough. Section 1.3 and Section 1.5 use two well-known image networks. VGG-16 is a deep stack of 3×3 convolutions, 13 of them in blocks of 2, 2, 3, 3 and 3 with pooling between blocks (VGG: Deep Stacks of 3×3 Convolutions). ResNet-50 is 16 bottleneck blocks with shortcuts, and each block’s two 1×1 layers mix channels without widening the window (ResNet and Residual Connections).

One rule, applied layer by layer from the input up, gives the window of any network. It tracks two numbers: \(\text{RF}\), and the jump \(J\), how far apart two neighboring outputs sit, in input pixels. Both start at 1. For a layer with kernel \(k\) and stride \(s\) (the dilation \(d\), the spacing between a kernel's taps, is 1 until Section 2):

How much each layer widens the window one output sees, applied once per layer from the input up.
\(\displaystyle \htmlClass{eqt}{\htmlData{k=rf}{\htmlStyle{color:#4a7880}{\text{RF}_{\text{new}}}}} = \htmlClass{eqt}{\htmlData{k=rf}{\htmlStyle{color:#4a7880}{\text{RF}_{\text{old}}}}} + \htmlClass{eqt}{\htmlData{k=g}{\htmlStyle{color:#1b7a43}{\text{growth}}}}\)
Each layer adds its growth to the window \(\text{RF}\) and never shrinks it, so the window can only widen with depth. Layers with a larger growth widen it faster.
\(\displaystyle \htmlClass{eqt}{\htmlData{k=g}{\htmlStyle{color:#1b7a43}{\text{growth}}}} = (\htmlStyle{color:var(--sym-kernel)}{k} - 1) \cdot \htmlStyle{color:#a04000}{d} \cdot \htmlClass{eqt}{\htmlData{k=j}{\htmlStyle{color:#7d3c98}{J_{\text{old}}}}}\)
A kernel's first and last taps sit \(k - 1\) gaps apart. Each gap skips \(d\) outputs of the layer below, and neighboring outputs below sit \(J_{\text{old}}\) input pixels apart, so the product is how many extra input pixels the kernel reaches. A 1×1 kernel has no gap and adds nothing; the same kernel adds more after a stride, because \(J_{\text{old}}\) is larger there.
\(\displaystyle \htmlClass{eqt}{\htmlData{k=j}{\htmlStyle{color:#7d3c98}{J_{\text{new}}}}} = \htmlClass{eqt}{\htmlData{k=j}{\htmlStyle{color:#7d3c98}{J_{\text{old}}}}} \cdot \htmlStyle{color:#a04000}{s}\)
The jump \(J\) changes only at a stride \(s\): keeping one output in \(s\) puts neighbors \(s\) times farther apart in the input. Because \(J\) multiplies every later growth, an early stride makes every later layer widen the window faster. Padding changes neither number; same padding only keeps the map from shrinking, so more layers can stack.

1.1 Stacking small kernels

Two stacked 3×3 layers reach as far as one 5×5 layer, with fewer weights per channel pair and an extra ReLU between them.

1.2 Stride and the jump

A pool with stride 2 barely widens the window itself, but it doubles \(J\), so every later layer grows twice as fast. In the first block of a typical CIFAR model (CIFAR is a set of 32×32 color photos), the 3×3 after the pool adds twice what the same 3×3 added before it (Figure 4).

1.3 Receptive fields of real networks

Pools and strides keep multiplying \(J\), so real networks reach hundreds of pixels.

1.4 Effective receptive field

Pixels near the window's center reach the neuron through many paths and edge pixels through few, so influence falls off like a bell (Luo et al. 2016). A rough model treats influence as a bell over the distance from the center.

An illustrative bell of influence inside the receptive field.
\(\displaystyle \text{influence} = \exp\!\left(\frac{-\htmlClass{eqt}{\htmlData{k=d}{\htmlStyle{color:#1272d2}{r}}}^{2}}{2\htmlClass{eqt}{\htmlData{k=sig}{\htmlStyle{color:#2c3e50}{\sigma}}}^{2}}\right)\)
Influence is 1 at the window's center and falls toward 0 with the distance \(r\) from the center. Squaring \(r\) keeps the drop slow near the center and makes it steep further out, and the width \(\sigma\) (sigma) sets the scale: doubling \(\sigma\) lets pixels twice as far out keep the same influence.
\(\displaystyle \htmlClass{eqt}{\htmlData{k=sig}{\htmlStyle{color:#2c3e50}{\sigma }}} = \frac{\htmlClass{eqt}{\htmlData{k=rf}{\htmlStyle{color:#4a7880}{\text{RF}}}}}{5}\)
The width \(\sigma\) is tied to the window \(\text{RF}\), so a larger window has a wider bell. One fifth is this page's choice, not a measured value: the effective receptive field paper shows the bell shape, and the real width depends on the network and its training. With this width the bell stays above half its peak over the middle of the window; that central part is the effective receptive field, the pixels that actually move the output.

1.5 Receptive field and object size

Whether a network sees an object whole comes down to one comparison: the object's width against the effective receptive field, not only against the whole receptive field. The function below makes that check for an object obj pixels wide, against the windows of LeNet (16), VGG-16 (212) and ResNet-50 (427): 

# share of RF above half the peak
ERF = 0.471

def verdict(rf, obj):
    # rf, obj: widths in pixels
    if obj <= ERF * rf:
        return "fully seen"
    if obj <= rf:
        return "partly seen"
    return "not covered"
  1. 1The share of the receptive field inside the effective receptive field, the shaded band in Figure 6.
  2. 2An object inside that band is fully seen.
  3. 3An object wider than the band but inside the receptive field is partly seen; a wider one is not covered.

Figure 6. The verdict flips as grey outgrows the band, then the window.

Overlapping windows matter in self-supervised learning too (SSL failure modes).

2 Dilated convolution

Spread the kernel's taps apart, raising the dilation \(d\), and one kernel covers more input with the same weights (Yu and Koltun 2016):

How wide a dilated kernel reaches.
\(\displaystyle \htmlClass{eqt}{\htmlData{k=span}{\htmlStyle{color:#4a7880}{\text{span}}}} = \htmlStyle{color:#a04000}{d} \cdot (\htmlStyle{color:var(--sym-kernel)}{k} - 1) + 1\)
A dilated kernel still has \(k\) taps and \(k - 1\) gaps, but each gap now steps \(d\) inputs instead of 1, so the reach is \(d\) times the gaps, and the + 1 counts the first tap. Raising \(d\) widens the span with the same \(k\) weights. \(d = 1\) is an ordinary kernel and PyTorch’s default; a very large \(d\) leaves wide holes between taps and, near the border, reads mostly padding. In the receptive field recurrence its growth is (span − 1) · \(J\).

Stacking the same dilation repeats the same holes, so the top output never sees some inputs (the gridding problem, Wang et al. 2018). Mixing rates such as 1, 2, 4 fills them for a 3-tap kernel. A stride before dilated layers spreads the taps further and makes the holes worse, so a plain convolution every few layers restores full coverage.

A dilated first layer skips raw samples before anything has summarized them, so dilation usually starts after a few plain layers. Running several dilated convolutions side by side at different rates and joining their outputs sees fine and coarse context at once; DeepLab calls this Atrous Spatial Pyramid Pooling, or ASPP (Chen et al. 2018, rates 6, 12, 18 and 24; atrous means dilated). The ASPP-style block below runs \(B\) branches on a map \(x\) with \(C\) channels. The positional arguments of Conv2d are in, out, kernel, stride, padding and dilation. Each branch costs as much as a plain 3×3, so the block runs about \(B\) times the compute of one layer. 

import torch
from torch.nn import Conv2d
from torch.nn import ModuleList

C, rates = 64, (1, 2, 4)
branches = ModuleList()
for d in rates:
    # padding d keeps the size
    b = Conv2d(C, C, 3, 1, d, d)
    branches.append(b)
B = len(rates)
fuse = Conv2d(B * C, C, 1)

x = torch.randn(1, C, 32, 32)
outs = [b(x) for b in branches]
y = fuse(torch.cat(outs, dim=1))
# y: [1, C, 32, 32]
  1. 1One 3×3 branch per rate \(d\), padded by \(d\) so the map keeps its size.
  2. 2A 1×1 that fuses the \(B \cdot C\) joined channels back to \(C\); a 1×1 kernel mixes channels only (1×1 convolution, in Inception (GoogLeNet) and 1×1 Convolutions).
  3. 3Runs every branch on \(x\), joins their channels and fuses them.

2.1 A receptive field for 300 ms of sensor data

At 1,000 samples per second a 300 ms event spans 300 samples, so the last layer’s window must reach at least 300. The function below runs the recurrence of Section 1 over (\(k\), \(s\), \(d\)) tuples, with rf and jump as \(\text{RF}\) and \(J\), and builds the seven-layer design of Figure 9 and a copy whose last dilation doubles once more: 

def receptive_field(layers):
    rf, jump = 1, 1  # RF and J
    for k, s, d in layers:
        rf += (k - 1) * d * jump
        jump *= s
    return rf

plain = [(7, 1, 1), (5, 2, 1)]
dils = (2, 4, 8, 16, 16)
stack = [(5, 1, d) for d in dils]
design = plain + stack
wider = design[:-1] + [(5, 1, 32)]
  1. 1The receptive field recurrence: each layer adds \((k - 1) \cdot d \cdot J\), and \(J\) multiplies by \(s\).
  2. 2The design: a kernel-7 layer, a stride-2 layer, then five dilated layers.
  3. 3The design's window reaches past the 300 target, the last point of Figure 9.
  4. 4A copy whose last rate is 32 widens the window further.

3 Causal convolutions and TCNs

When the 300 ms detector of Section 2.1 runs live, at each new sample it must decide using only past samples, but a kernel with centered padding reads half its reach from the future. A Conv1D slides a kernel along one axis, time. In a causal task the output at time \(t\) cannot use later inputs, so the padding goes on the left only:

Causal padding puts zeros on the left only, enough for the kernel's reach into the past.
\(\displaystyle \htmlClass{eqt}{\htmlData{k=v}{\htmlStyle{color:#4a7880}{\text{left pad}}}} = (\htmlClass{eqt}{\htmlData{k=k}{\htmlStyle{color:var(--sym-kernel)}{k}}} - 1) \cdot \htmlClass{eqt}{\htmlData{k=d}{\htmlStyle{color:#a04000}{d}}}\)
A kernel with \(k\) taps and dilation \(d\) reaches \((k - 1) \cdot d\) steps into the past: \(k - 1\) gaps of \(d\) steps each. Padding exactly that many zeros on the left, and none on the right, lines the newest tap up with the current time step, so each prediction depends only on data up to its own time. Centered padding would put half the reach into the future.

A causal convolution in PyTorch is a plain nn.Conv1d that pads \((k - 1) \cdot d\) zeros on the left, so the output keeps the input's length and never sees a later step. 

import torch
import torch.nn as nn
import torch.nn.functional as F

class CausalConv1d(nn.Conv1d):
    """Looks back only"""
    def forward(self, x):
        # x: [B, C, T]
        k = self.kernel_size[0]
        d = self.dilation[0]
        pad = (k - 1) * d
        # pad the past side only
        x = F.pad(x, (pad, 0))
        return super().forward(x)
  1. 1Computes the left padding \((k - 1) \cdot d\) of the card.
  2. 2Pads zeros on the past side of the time axis only.
  3. 3Runs the ordinary convolution on the padded input.

A model trained with ordinary centered padding peeks at the future and scores well offline, then fails live. Doubling the dilation layer by layer grows the window exponentially, as in Section 2. A temporal convolutional network (TCN) stacks such layers:

Receptive field of a causal stack whose dilation doubles at each of \(L\) levels.
\(\displaystyle \htmlClass{eqt}{\htmlData{k=rf}{\htmlStyle{color:#4a7880}{\text{RF}}}} = 1 + (\htmlClass{eqt}{\htmlData{k=k}{\htmlStyle{color:var(--sym-kernel)}{k}}} - 1)(2^{\htmlClass{eqt}{\htmlData{k=l}{\htmlStyle{color:#a04000}{L}}}} - 1)\)
With one causal convolution per level, level \(l\) has dilation \(2^l\) and adds \((k - 1) \cdot 2^l\) steps. The dilations 1, 2, 4 and so on add up to \(2^L - 1\), so each extra level about doubles the window while adding only \(k\) weights per channel pair. A TCN block from the TCN paper (Bai et al. 2018) has two convolutions per level, which doubles the growth again.

If the dilation grows too fast, some time steps fall into holes the output never sees, the gridding problem (Figure 8); repeating a cycle such as 1, 2, 4, 1, 2, 4 avoids it. Deep stacks also need a shortcut so gradients reach the early layers: each level adds its input back to its output, the residual shortcut ResNet introduced (ResNet and Residual Connections). One TCN level in PyTorch takes a ready-built CausalConv1d with dilation \(d\). Dropout zeroes each value with probability \(p\) while training and keeps every value at test time (Regularization). Raising \(p\) regularizes harder, \(p = 0\) turns it off and near 1 almost nothing survives; the TCN code uses 0.2. The authors’ code is at github.com/locuslab/TCN; stacking levels with \(d = 1, 2, 4\) and so on gives the card's window: 

class TCNLevel(nn.Module):
    """y = relu(x + branch)"""
    def __init__(self, conv):
        super().__init__()
        self.conv = conv
        drop = nn.Dropout(0.2)
        self.drop = drop

    def forward(self, x):
        # x and y: [B, c, T]
        h = self.conv(x)
        h = torch.relu(h)
        h = self.drop(h)  # branch
        return torch.relu(x + h)

c, k, d = 16, 3, 4
kw = dict(dilation=d)
conv = CausalConv1d(c, c, k, **kw)
level = TCNLevel(conv)
  1. 1The branch, made of the causal convolution, ReLU and dropout.
  2. 2Adds the input back, then ReLU.
  3. 3Builds one level with dilation 4.

For multi-sensor data such as EEG (recordings of brain waves), treat the sensors as the height of a sensors-by-time grid and apply a Conv2D whose kernel spans all sensors and a time window; for live use the causal padding then goes on the left of the time axis only. The Conformer mixes convolutions with attention for speech (The Conformer Block).

A convolution sees a fixed window. Recurrent networks (RNN Basics) carry a running state through time, and attention (Attention) lets every position see every other one in a single layer.

4 Receptive field problems and fixes

Most of these failures come from a receptive field that is smaller than the object, an effective receptive field smaller than the object, dilation gaps that skip inputs, or padding that lets a live model see the future.

SymptomLikely causeFix
Large objects are missedReceptive field smaller than the objectPool or stride earlier, or add dilation
Large objects are detected weakly or inconsistentlyObject extends past the effective receptive fieldKeep objects under half the receptive field
Fine detail vanishes after dilated layersDilated taps skip inputs (gridding)Mix rates such as 1, 2, 4
Offline scores beat live onesCentered padding saw the futureCausal, left-only padding
