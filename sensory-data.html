Preprocessing Sensory Data

Let's talk a little bit about preprocessing sensory data, like from wearables. Sensory data can be noisy; there can be powerline interference, the hum a sensor picks up from the electrical wiring around it, baseline drifts, the slow wandering of the signal's zero level, and issues with the impedance of the sensors. What you can do is use some signal processing to improve the signal and get the features that have the most information without the noise to feed to your model.

  • Band-pass filtering: Lets only one band of frequencies through: removes low-frequency drift and high-frequency noise and keeps the most important frequencies in between.
  • Notch filtering: A filter that cuts one narrow frequency band, the powerline hum, while leaving the frequencies around it alone. Suppresses powerline interference.
  • Rectification and enveloping: Rectification flips the negative parts positive by taking the absolute value of the signal, and enveloping then traces the outline of how strong the signal is, its magnitude envelope, by low-passing the rectified signal.
  • Z-scoring: Per channel, subtract the signal's own average, then divide by its spread, scaling signals to reduce inter-subject and inter-session amplitude variability.

There are also a variety of time, frequency, and time-frequency domain features you can extract from the signal: time domain features measure the signal as it unfolds over time, frequency domain features measure how much of each frequency it contains, and time-frequency domain features measure how that frequency makeup changes over time. Or you can design CNN and LSTM (long short-term memory, a recurrent layer that carries a memory across a sequence and gates what enters and leaves it) layers in your model that perform feature extraction.

Handling Missing Data and Fusing Modalities

Additionally, there can be missing signals due to Bluetooth packet loss or sweat increasing impedance, which can lead to dropped channels or unreliable signals. If it's noisy or missing data, you can try detecting those channels that have flatlined, gone dead flat, or saturated, pegged at the top of their range, and interpolate them from neighbors. Based on the sensors, the neighbors can be spatial or temporal. You can also try a wide range of augmentations.

You can make the model aware of such noises by providing a binary mask of which sensors are valid, and the model learns to ignore the missing ones. You can use an attention mechanism, a learned scoring that decides how much each input counts, to weight sensors that are more reliable. The model learns end-to-end (as one whole system, from the raw inputs straight through to the prediction, rather than in separate stages built apart) which channels correlate better with the task and which ones don't.

You can combine modalities; if one modality is missing, maybe another can still provide information. Depending on the signals, you could concatenate after processing and use the same encoder, the part of the model that reads one signal in and compresses it into features, but that would assume the modalities align well in time and scale. More commonly, you would use separate encoders and concatenate their latent features (the compressed representation each encoder produces) and feed that to a joint decoder (the network that turns those fused features into the final prediction).

Instead of concatenating, you can have cross-modal attention. Modalities that can complement each other don't necessarily align. For example, one modality might detect some activity sooner than another. Attention can learn to synchronize these modalities. The model can learn how much to trust each modality depending on the context. Features from one of the sensors can form the query, and features from the other sensors can form the keys and values (a query asks what to look for, keys advertise what each sensor offers, values are the features passed along). Attention will decide how strongly to fuse information. And if one modality is missing or noisy, attention can down-weight it.

This is more flexible as it lets each encoder specialize in encoding its signal. You can also have very late fusion, where you train entirely separate models for each modality and fuse their outputs, but that would not really solve the missing signal problem.

You can try foundation-style models, models in the foundation style, trained broadly once on a lot of data and then adapted to each new job, where you train on a large cohort of users and fine-tune it on new users, train the already trained model a little more on that person's data, using calibration sets (a small labeled sample collected from the new user, used to adjust the model to that person). You can try having a shared encoder that is subject-specific, lightweight heads (small task specific output layers, one per task or user) that can be fine-tuned for new users.
