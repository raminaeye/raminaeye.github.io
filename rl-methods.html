Value, policy, or both

Every RL method runs the reinforcement learning loop (see a state, act, get a reward and the next state); what differs is what the agent keeps to pick its move. A value is a guess of how much future reward to expect; a policy is the rule that picks the move. A few methods also learn, or are handed, a model of the world that predicts what each move will do, and plan with it; methods without one are model-free.

Value-based methods

A value-based agent keeps a score, a Q-value, for every move in every state: the future reward it expects from playing that move and playing well after. It mostly plays the move with the highest score, trying a random move with a small chance epsilon to explore (epsilon-greedy), and after each step it nudges the played move's score toward a better guess, the same update as the toy banana step on the RL page:

Q-learning moves the played score a little toward what the step revealed.
target = r + γ · max Q(s′, a′)
r is the reward the move earned and s′ the state it led to. max Q(s′, a′) is the best score on offer there, the max taken over every move a′ available in s′. The discount γ, a number just below 1, shrinks it a little for the delay.
Q(s, a) ← Q(s, a) + α · (target − Q(s, a))
The arrow means "replace with". The score of move a in state s moves a fraction α, the learning rate, of the way toward the target.
Q = np.zeros((n_states, n_moves))         # the table: one score per move
a = Q[s].argmax() if random.random() > eps else random.randrange(n_moves)
s2, r = env.step(a)
target = r + gamma * Q[s2].max()
Q[s, a] += alpha * (target - Q[s, a])

Q-learning (Watkins and Dayan 1992) keeps the scores in a table; DQN (Mnih et al. 2015) swaps the table for a neural network. My banana agent is one, 37 numbers in and four move scores out. Its 37 numbers never repeat, so a table would never see a state twice; the DQN page shows how move scores survive that, and the RL page's three-algorithm comparison shows why scoring every move needs a short list of moves.

Policy-based methods

A policy-based agent skips the scores. Its network turns the state into a probability for each move, and the agent rolls its move from them. It learns once per episode, one run from the start until the world resets. Then every move becomes more likely in proportion to the return that followed it, the reward collected from that move on. That is REINFORCE (Williams 1992), written as the loss the code makes smaller:

REINFORCE makes each move more likely in proportion to the reward that came after it.
loss = −Σt log π(at | st) · Gt
π(at | st) is the probability the policy gave the move it made at step t (the bar reads "given"). Gt is the return from step t on, each later reward shrunk once per step of delay by the discount γ. log, the logarithm, grows whenever that probability grows. Σt adds over the episode. The minus sign makes it a loss: moves before a large return get pushed up, moves before a negative one get pushed down.

The weakness is noise: one lucky episode pushes up every move in it, good and bad alike. The loss line in the code is the equation.

dist = torch.distributions.Categorical(logits=policy(states))  # one row per step
log_probs = dist.log_prob(actions)        # log pi(a_t | s_t) for the moves played
returns, G = [], 0.0
for r in reversed(rewards):               # walk back from the last step
    G = r + gamma * G                     # the return from this step on
    returns.insert(0, G)
loss = -(log_probs * torch.tensor(returns)).sum()
loss.backward()

Actor-critic methods

The fix is a second network. The actor is the REINFORCE policy. The critic learns to guess the return from each state, so the actor asks whether a return beat that guess, not whether it was big. That gap is the advantage, and a lucky episode from an easy state no longer pushes everything up.

In one actor-critic update the critic's guess sets the bar, and the actor's move is judged against it.
A = G − V(s)
V(s) is the critic's guess of the return from state s, and G the return that came after the move. The advantage A is positive if the move beat the guess, negative if it fell short.
actor loss = −log π(a | s) · A
The REINFORCE line with the advantage in place of the return: the move gets more likely only if it beat the guess.
critic loss = (G − V(s))2
The miss, squared so either direction counts. Making it smaller pulls the guess toward the real return.

In the code, the detach call keeps the actor's line from training the critic.

returns = torch.tensor(returns)           # G for every step, from the REINFORCE loop
values = critic(states).squeeze(-1)       # V(s) for every step
advantage = returns - values              # A = G - V(s)
dist = torch.distributions.Categorical(logits=actor(states))
actor_loss = -(dist.log_prob(actions) * advantage.detach()).mean()
critic_loss = ((returns - values) ** 2).mean()
(actor_loss + critic_loss).backward()

In practice G is often a few real rewards plus the critic's guess for the rest, so learning can start before the episode ends. A2C, advantage actor-critic, trains on exactly these actor-critic equations while several copies of the world run at once. PPO, proximal policy optimization (Schulman et al. 2017), is an actor-critic that stops pushing a move's probability once it leaves a small band around its old value; Aligning Language Models with RL uses it for RLHF, reinforcement learning from human feedback.

DDPG (Lillicrap et al. 2016) is an actor and a critic too, but its critic scores a state together with a continuous action, any real number in a range rather than a pick from a list, and the actor nudges its action in the direction that raises that score, with no advantage and no probabilities. My Reacher arm learned its four joint torques this way (see the DDPG page).

What the agent stores

The same world and the same route, stored as a score for every move, the move itself, or both.

Model, data and actions

Besides what it stores, three questions place a method. A model-based method plans ahead with a model: AlphaZero (Silver et al. 2018) uses the game's known rules, MuZero (Schrittwieser et al. 2020) learns its own model and plans inside it. An off-policy method can learn from an older policy's moves, such as steps kept in a replay buffer, a memory of past steps sampled at random; an on-policy one learns only from the current policy's moves, then throws them away. A model-free method learns from experience without predicting what comes next. A discrete method picks from a short list of moves; a continuous one outputs real numbers.
