SARSA: Learning the Value of the Moves You Play

Judge each step by what you will really do next, and learn a safer path.

A robot learning a floor finds the shortest path along a dangerous edge, but while it still tries random steps it keeps falling off. Can it learn a path that stays safe while it is still trying things?

The agent is the learner that picks the moves, as taught in RL Basics. A state is the agent's situation right now; a move, or action, is one choice the agent can make in a state; a reward is the number the world hands back after each move, good or bad, as taught in RL Basics. Here the agent is a warehouse robot that must reach its charging dock. It starts in one bottom corner and the dock sits in the other. The floor is a grid of cells, one per place the robot can stand. It knows only which cell it stands in, not where each move leads or what it costs.

An episode is one run from the start until it ends, as taught in RL Basics. The ledge is the strip of floor between the start and the dock. Sutton and Barto's textbook calls the ledge a cliff and the dock the goal. Reaching the dock can take many moves.

Each move's reward is minus the battery it uses, so the best total is the one closest to zero. Every move costs a little battery; stepping onto the ledge costs a lot and puts the robot back at the start; only reaching the dock ends the episode. The cheapest way to the dock is the shortest path that never steps onto the ledge.

Why the edge route keeps falling

The return is all the reward still to come, with later rewards counted a little less, as taught in RL Basics. A policy is the agent's rule for choosing a move in each state; it may always pick the same move or pick by chance, as taught in RL Basics. A move's value \(Q(s,a)\), also called its score, is the return the agent expects if it makes move \(a\) in state \(s\) and plays on from there, as taught in RL Basics. If the robot never slipped, the edge route would be the cheapest way to the dock, because it is the shortest.

A Q-table keeps one score for every state and move, as taught in Q-Learning. Epsilon-greedy usually plays the top-scored move and, with chance \(\epsilon\), a random one instead, as taught in RL Basics. The discount \(\gamma\) sets how much a reward one step later still counts, as taught in RL Basics. Its table says the step along the edge is best, but a robot that still explores sometimes steps the wrong way, and next to the ledge the wrong way is a fall.

A target is the value the current score is pulled toward. Q-learning's target is the step's reward plus the discounted best score in the next state, as taught in Q-Learning. That target assumes the top-scored move next, but the robot will not always play it. Beside the ledge, one wrong step costs far more than any ordinary step.

The table says the edge route is best, yet the episodes the robot really lives keep losing battery to falls.

Counting the slip into the score

SARSA's target uses the move the robot really picks next, exploring moves included. The chance of a random slip is inside the score, so the scores next to the ledge carry the risk of a fall.

Scoring the move you will play

The TD (temporal difference) error \(\delta\) is how much one step surprised the agent, the target minus the current guess, as taught in RL Basics. The learning rate \(\eta\) sets how big a step each update takes, as taught in RL Basics. A fall sends the robot back to the start, so it must walk the whole floor again.

The sign \(\sim\) means drawn at random from, as taught in RL Basics. The robot stands a cell from the ledge and has already drawn its next move, which could be a slip toward the edge.

On-policy and off-policy learning

On-policy means learning the values of the same policy that is playing, as taught in SARSA. Off-policy means learning the values of one policy while playing another, as taught in SARSA. SARSA is on-policy and Q-learning is off-policy.

The greedy policy plays the top-scored move in each state, as taught in Q-Learning. The behaviour policy is the policy that picks the moves the robot plays. Q-learning's robot plays epsilon-greedy, yet its target reads the top score, the move only the greedy policy would play. Near the ledge, those random moves are the ones that end in a fall.

The target policy is the policy whose scores the target \(y_t\) aims at, and it is a separate idea from the target \(y_t\) itself. SARSA's target reads the score of the move the robot really drew, the same epsilon-greedy choice it plays.

So only SARSA's scores count the slips the robot really makes while it explores. For the robot beside the ledge, the two targets differ in a single symbol.

Each line below shows only the part of the target after the reward, so the one difference stands alone.

\(\displaystyle \htmlClass{eqt}{\htmlStyle{color:#2c3e50}{\gamma}} \max_{\htmlClass{eqt}{\htmlStyle{color:#a04000}{a}}} \htmlClass{eqt}{\htmlStyle{color:#8e44ad}{Q}}(\htmlClass{eqt}{\htmlStyle{color:#2471a3}{s_{t+1}}}, \htmlClass{eqt}{\htmlStyle{color:#a04000}{a}})\)
Q-learning adds the top next score, so it aims at the top-scored move whatever is played, which makes it off-policy. Its target policy is greedy while its behaviour policy is epsilon-greedy, and the step's reward \(r_{t+1}\) in front is the same for both.
\(\displaystyle \htmlClass{eqt}{\htmlStyle{color:#2c3e50}{\gamma}}\, \htmlClass{eqt}{\htmlStyle{color:#8e44ad}{Q}}(\htmlClass{eqt}{\htmlStyle{color:#2471a3}{s_{t+1}}}, \htmlClass{eqt}{\htmlStyle{color:#a04000}{a_{t+1}}})\)
SARSA adds the score of the move it drew, so it aims at the policy actually played, which makes it on-policy. The drawn move comes from epsilon-greedy, so its target and behaviour policies are the same.

The next move, drawn before the update

The setup matches the Q-Learning code, written out in full here. First the table and the move choice.

import gymnasium as gym
import numpy as np

# CliffWalking-v1 needs a recent Gymnasium, older versions name it CliffWalking-v0
env = gym.make("CliffWalking-v1")      # the floor, start, ledge, dock
n_states = env.observation_space.n     # one row per square
n_moves = env.action_space.n           # up, right, down, left
Q = np.zeros((n_states, n_moves))      # the Q-table, every entry at zero

GAMMA = 1.0    # every episode ends at the dock, so no discount
LR = 0.5       # the learning rate, the size of each nudge
EPS = 0.1      # the chance of a random, exploring move
rng = np.random.default_rng(0)

def act(s, eps):
    if rng.random() < eps:
        return int(rng.integers(n_moves))   # explore, any move
    return int(np.argmax(Q[s]))             # exploit, the best move by the table
  1. 1Make the floor and an all-zero table with one row per square and one column per move.
  2. 2Set the discount \(\gamma\), the learning rate \(\eta\) and the exploring chance \(\varepsilon\).
  3. 3Epsilon-greedy picks a random move with chance \(\varepsilon\), otherwise the \(\arg\max\) of the square's row, which is line 1 of the SARSA card.

Then the loop, with the next move drawn before the update.

for episode in range(N_EPISODES):
    s, info = env.reset()                    # back to the start square
    terminated = False
    a = act(s, EPS)                          # the first move is drawn here
    while not terminated:                    # this floor is never cut off
        s_next, r, terminated, truncated, info = env.step(a)
        a_next = act(s_next, EPS)            # draw the next move before the update
        if terminated:
            y = r                            # at the dock, the step's reward alone
        else:
            y = r + GAMMA * Q[s_next, a_next]  # the step's reward plus the drawn move's score
        Q[s, a] += LR * (y - Q[s, a])        # nudge the played entry toward the target
  1. 1Each episode starts at the start square and runs until the dock. terminated is true only at the dock. A fall is an ordinary step, so the episode goes on, and Cliff Walking has no step limit, so truncated never ends it.
  2. 2The names r, s_next and a_next stand for \(r_{t+1}\), \(s_{t+1}\) and \(a_{t+1}\), the reward, the next state and the next move. The next move is drawn before the update, which is lines 2 to 4 of the SARSA card.
  3. 3The target \(y_t\), with the dock case first, then the update.

The loop closes by handing the drawn move over as the move to play.

        s, a = s_next, a_next    # the drawn move is the one played, never redrawn
  1. 1The drawn move becomes the move played next, so it is never drawn twice. This is the walkthrough's last step.

Where each learner's route runs

Each robot's route is the path its best moves trace from the start, drawn as arrows in the tool below; it counts only if it reaches the dock without a loop.

Turn exploring up and SARSA's route moves back from the ledge to the top row, while Q-learning's route stays along the edge and it falls far more often. Turn it down to none and both routes end on the edge, after only the early falls.

Updating a step late

When it updates

SARSA updates after every step, but a step late. It waits until the next move is chosen before it updates the step just played.

The next move comes first

Choose the next move before updating, and play that same move. On this floor every value is below zero, because every step costs battery. Starting every score at zero is hopeful when every real score is below zero, because moves not yet tried then look best, as taught in Q-Learning.

Only the step that reaches the dock uses the step's reward alone. A fall is an ordinary step.

When mistakes while learning cost something

SARSA fits where mistakes made while learning cost something real, a robot near a ledge or a live system that can break while it tries random moves. Exploring continues after training, so the route SARSA learns stays the safe one. When only the final route matters and practice falls are free, prefer Q-Learning.

Learning from remembered steps

A table needs a row for every state. Deep Q-Networks swap the table for a network and learn from remembered steps, a memory called replay, because learning from steps that another policy took is what lets them learn from those steps. Actor-critic methods also learn from the moves they play, as the Policy Gradient Methods page shows.
