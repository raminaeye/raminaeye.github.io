1 A mask decides who may look at whom

A mask is a matrix added to the scores before the softmax: zero where a pair may attend, negative infinity where it must not. Padding and the future are the two reasons to block a pair, and both add a mask matrix \(M\) to the scores before the softmax. The causal mask is built once per sequence length and the padding mask once per batch, both added in every attention layer on every forward pass; loss masking runs every training step, inside the loss only. The mask adds one number to each score, \(T\) squared additions per head per layer, inside the attention call taught in section 3 (Transformer paper section 3.2.3).

The mask is added to the scores before the softmax.
\(\displaystyle \htmlStyle{color:#117a65}{A} = \operatorname{softmax}(\htmlStyle{color:#1f618d}{S} + \htmlStyle{color:#c0392b}{M})\)
A blocked pair gets exactly zero weight, and the open pairs share all of it. The mask \(M\) is added to the score matrix \(S\): 0 where a pair may attend, so its score is untouched, and negative infinity where it may not. Softmax raises \(e\) to each entry, and \(e\) to negative infinity is 0, so the blocked keys vanish from \(A\) and each row's remaining weights still sum to 1.

2 The padding mask hides the padding tokens

Short sequences in a batch are filled out to the same length with padding tokens. Real tokens must not attend to them, so the padding keys are masked; a padding query is harmless, since its output is left out of the loss (Section 4).

The padding mask in PyTorch for two sequences, 5 and 3 tokens long; scores go in and weights with 0 on every padded key come out.

import torch

B, h, T = 2, 8, 5  # batch, heads, padded length
lengths = torch.tensor([5, 3])
keep = torch.arange(T) < lengths[:, None]  # (B, T)

S = torch.randn(B, h, T, T)
blocked = ~keep[:, None, None, :]          # (B, 1, 1, T)
S = S.masked_fill(blocked, float("-inf"))
A = S.softmax(dim=-1)  # padded keys get weight 0
  1. 1Marks which keys are real from each sequence's length, the light columns of Figure 1.
  2. 2Sets the padded keys' scores to negative infinity, the \(M\) of the eq card in Section 1, line 1.
  3. 3Softmax gives those keys weight 0, the dark columns \(k_{4}\) and \(k_{5}\) in Figure 1.

Masking keys only still leaves a real key in every row. Masking padded queries too gives rows that are all negative infinity; there the softmax divides 0 by 0 and writes NaN ("not a number"), which spreads through training.

3 The causal mask hides the future

A decoder, which writes left to right, must not see later tokens. The causal mask blocks every key after the query: zeros on and below the diagonal, negative infinity above it.

The snippet builds that matrix for 5 tokens; look at triu, which keeps negative infinity only above the diagonal. 

import torch

T = 5
NEG_INF = float("-inf")
M = torch.full((T, T), NEG_INF).triu(diagonal=1)
print(M)  # 0 on and below the diagonal, -inf above

Because no row can see its future, training grades all \(T\) next-token predictions in one pass (illustrated on Transformer Architectures).

Figure 2. Each row reads its own word and the words before it. Weights are illustrative.

The causal call runs on the rotated queries and keys from RoPE, using torch.nn.functional, imported here as F: 

out = F.scaled_dot_product_attention(q, k, v, is_causal=True)
  1. 1Causal attention on the rotated queries and keys, eq card in Section 1, line 1, with the causal \(M\) of Section 3.

The call is F.scaled_dot_product_attention in the PyTorch docs.

is_causal=True plus an attn_mask raises an error, so merge them into one mask. The docs say an error is thrown if both are set.

With one query and many cached keys, the stored keys and values of earlier tokens (the KV cache of Transformer Cost and Efficiency), is_causal aligns the triangle top left and shows only the first key, so pass is_causal=False. The docs state the mask takes the upper-left causal bias on a non-square mask.

4 Loss masking removes padding from the loss

Loss masking keeps padded positions out of the loss; you set their targets to -100, the ignore_index that F.cross_entropy skips by default.

import torch
import torch.nn.functional as F

B, T, VOCAB = 2, 5, 100
IGNORE = -100
logits = torch.randn(B, T, VOCAB)
targets = torch.tensor([[4, 8, 15, 16, 23], [42, 7, 9, IGNORE, IGNORE]])
pred = logits.flatten(0, 1)  # (B*T, VOCAB)
target = targets.flatten()   # (B*T,)

loss = F.cross_entropy(pred, target, ignore_index=IGNORE)
print(loss)  # mean over the 8 real targets
  1. 1Logits and targets, flattened to one row per position; -100 marks the two padded targets at positions 4 and 5, the dark columns of Figure 1.
  2. 2The mean cross-entropy counts only the real targets, so the dark padding positions of Figure 1 add nothing to the loss.

Attention masks choose which tokens each token reads; loss masks choose which predictions count.

In BLIP-2 and the Q-Former, three different masks let one set of weights train on three objectives at once.

6 When masking breaks, and when to use which

A fully masked row turns the softmax into NaN: masking padded queries too gives rows that are all negative infinity, and there the softmax divides 0 by 0. The fix is to mask padding keys only, never the queries, and check that every row keeps at least one real key.

A padding mask built for the wrong lengths lets real tokens attend to filler, which silently corrupts training. Build the mask from the same lengths tensor the batch was padded to.

is_causal=True with an attn_mask raises an error. Merge them into one mask.

A full sequence scored or trained without the causal mask leaks future context, so a model graded on a full sequence sees tokens it should not have. Use the causal mask wherever a full sequence is processed in one pass, in training and in scoring a fixed sequence, as in ALiBi paper section 2.1. Cached step-by-step generation correctly uses no causal mask: each step's input holds only tokens already written, so there is no future token to peek at, and with one query and many cached keys is_causal must be False.

Check every row keeps at least one real key; check the mask shape matches the scores shape (\(B\), \(h\), \(T\), \(T\)).
