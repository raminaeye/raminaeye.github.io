Class Imbalance: Resampling, Class Weights and Focal Loss

Why a model trained on mostly easy, common examples ignores the rare class, and the places to fix it: the data, the batches, the loss and the decision threshold.

1 The accuracy trap

A wristband gesture detector sees mostly rest: people spend far more time not gesturing than gesturing. When almost every window is rest, a model that always answers rest scores high accuracy and catches nothing. Training drifts toward that answer, because the easy, frequent class supplies nearly all of the loss. The same trap is extreme in dense object detection, where nearly every candidate box in an image is background: about a thousand background boxes for every object (Lin et al. 2017).

Accuracy hides this, so imbalanced problems are judged with two other measures. Recall is the share of real rare cases the model catches. Precision is the share of the model’s rare-class alarms that are real. The always-rest model has no recall at all. The fixes below act at four places in the loop: the data, the batches, the loss and the final threshold.

2 Fixing the data: resampling and SMOTE

You can oversample the rare class, repeating its examples, undersample the common class, dropping some of its examples, or augment the rare class more (Data Augmentation). SMOTE (Synthetic Minority Over-sampling Technique, Chawla et al. 2002) oversamples without copying: it finds a nearby rare example with nearest neighbours and places a new one between them.

SMOTE places a new minority sample at a random point on the line to a neighbor.
\(\displaystyle {\begin{aligned}\htmlClass{eqt sym-xint}{\htmlStyle{color:var(--sym-xint)}{\mathbf{x}_{\text{new}}}} &= \htmlClass{eqt sym-x}{\htmlStyle{color:var(--sym-x)}{\mathbf{x}_i}} \\ &\quad + \htmlClass{eqt sym-grad}{\htmlStyle{color:var(--sym-grad)}{u}}\,\big(\htmlClass{eqt sym-x}{\htmlStyle{color:var(--sym-x)}{\mathbf{x}_{\text{nn}}}} - \htmlClass{eqt sym-x}{\htmlStyle{color:var(--sym-x)}{\mathbf{x}_i}}\big) \\ \htmlClass{eqt sym-grad}{\htmlStyle{color:var(--sym-grad)}{u}} &\sim \mathcal{U}[0, 1]\end{aligned}}\)
The new sample \(\htmlClass{eqt sym-xint}{\htmlStyle{color:var(--sym-xint)}{\mathbf{x}_{\text{new}}}}\) starts at a minority sample \(\htmlClass{eqt sym-x}{\htmlStyle{color:var(--sym-x)}{\mathbf{x}_i}}\) and moves a share \(\htmlClass{eqt sym-grad}{\htmlStyle{color:var(--sym-grad)}{u}}\) of the way toward \(\htmlClass{eqt sym-x}{\htmlStyle{color:var(--sym-x)}{\mathbf{x}_{\text{nn}}}}\), one of its nearest minority neighbors. \(\htmlClass{eqt sym-grad}{\htmlStyle{color:var(--sym-grad)}{u}}\) is drawn uniformly between zero and one, so the new point always lies between two real minority examples: it fills in the region the class already occupies instead of copying a point. A far neighbor would put samples in unlikely places, which is why SMOTE uses the nearest ones.
So the rare class gets new, plausible examples instead of repeated ones.

Resampling runs once, before training, on the training split only.

3 Fixing the loss: class weights

Instead of changing the data, make mistakes on the rare class cost more. Logistic regression already uses this idea. The card builds on cross-entropy.

Give each class a weight that grows the rarer it is, and scale each example’s loss by it.
\(\displaystyle {\htmlClass{eqt sym-w}{\htmlStyle{color:var(--sym-w)}{w_c}} = \frac{N}{K\, N_c}}\)
The weight of class \(c\) is the inverse of how often it appears, scikit-learn’s “balanced” form. \(N\) is the number of training examples, \(K\) the number of classes, and \(N_c\) the number in class \(c\). A rare class has a small \(N_c\) and so a large weight; with perfectly balanced classes every weight is one.
\(\displaystyle {\htmlClass{eqt sym-loss}{\htmlStyle{color:var(--sym-loss)}{\mathcal{L}}} = -\, \htmlClass{eqt sym-w}{\htmlStyle{color:var(--sym-w)}{w_{y}}}\, \log \htmlClass{eqt sym-prob}{\htmlStyle{color:var(--sym-prob)}{p_{y}}}}\)
Built on line 1: cross-entropy for one example, scaled by the weight of its true class \(y\). \(\htmlClass{eqt sym-prob}{\htmlStyle{color:var(--sym-prob)}{p_{y}}}\) is the probability the model gives that class. A missed rare window now costs as much as many missed common ones.
So the rare class carries a fair share of the loss even though it supplies few examples.

In the code, most labels are common and a few rare, and \(\htmlClass{eqt sym-w}{\htmlStyle{color:var(--sym-w)}{w}}\) is the inverse class frequency. The code uses \(N\) over \(N_c\) without the \(K\); a constant factor only changes the size of the loss, not the balance between classes.

from torch import nn, tensor
import torch.utils.data as tud
labels = [0] * 95 + [1] * 5
y_train = tensor(labels)
counts = y_train.bincount()
w = counts.sum() / counts
# option 1: weighted loss
loss_fn = nn.CrossEntropyLoss(w)

Figure 3. Illustrative windows. A larger \(\htmlClass{eqt sym-w}{\htmlStyle{color:var(--sym-w)}{w}}\) catches more rare windows and flags more common ones.

The boundary is refitted by a small logistic model each time the weight changes. With no extra weight it sits far out, past most rare windows; raising the weight drags it toward the common crowd, catching more rare windows at the price of more false alarms. There is no free setting: the weight picks a point on that trade.

4 Fixing the batches: balanced sampling

Balanced batch sampling gives each batch, the group of examples processed together, roughly equal classes. PyTorch’s WeightedRandomSampler draws each example with a chance proportional to its class weight. The weights are computed once; the sampler draws new batches every epoch. Use the loss weights or the sampler, not both, or the rare class is counted up twice.

# option 2: balanced batches
WRS = tud.WeightedRandomSampler
n = len(y_train)
sampler = WRS(w[y_train], n)

5 Focal loss: down-weight the easy examples

Class weights treat every example of a class alike. Focal loss (Lin et al. 2017) goes further and weights each example by how hard it is. Its setting is RetinaNet, a one-stage object detector that scores about a hundred thousand candidate boxes, called anchors, per image. Almost all are easy background. Each easy box has a small loss, but there are so many that together they swamp the loss of the few boxes that matter.

Focal loss is cross-entropy scaled down for examples the model already gets right.
\(\displaystyle {\htmlClass{eqt sym-prob}{\htmlStyle{color:var(--sym-prob)}{p_t}} = \begin{cases} \htmlClass{eqt sym-prob}{\htmlStyle{color:var(--sym-prob)}{p}} & y = 1 \\ 1 - \htmlClass{eqt sym-prob}{\htmlStyle{color:var(--sym-prob)}{p}} & y = 0 \end{cases}}\)
\(\htmlClass{eqt sym-prob}{\htmlStyle{color:var(--sym-prob)}{p}}\) is the model’s probability for the rare class; \(\htmlClass{eqt sym-prob}{\htmlStyle{color:var(--sym-prob)}{p_t}}\) is the probability it gives the true answer, whichever class that is. Near one means the example is easy and already right. (The paper writes the labels as plus and minus one; this page uses one and zero to match cross-entropy.)
\(\displaystyle {\begin{aligned}\mathrm{FL}(\htmlClass{eqt sym-prob}{\htmlStyle{color:var(--sym-prob)}{p_t}}) &= -\big(1 - \htmlClass{eqt sym-prob}{\htmlStyle{color:var(--sym-prob)}{p_t}}\big)^{\htmlClass{eqt sym-temp}{\htmlStyle{color:var(--sym-temp)}{\gamma}}} \\ &\quad \times \log \htmlClass{eqt sym-prob}{\htmlStyle{color:var(--sym-prob)}{p_t}}\end{aligned}}\)
Built on line 1. Minus log \(\htmlClass{eqt sym-prob}{\htmlStyle{color:var(--sym-prob)}{p_t}}\) is the usual cross-entropy, large when \(\htmlClass{eqt sym-prob}{\htmlStyle{color:var(--sym-prob)}{p_t}}\) is small. The factor in front is near zero for an easy example, so it barely counts, and near one for a misclassified example, which keeps nearly its full loss. Raise \(\htmlClass{eqt sym-temp}{\htmlStyle{color:var(--sym-temp)}{\gamma}}\) (gamma) and easy examples are down-weighted harder; \(\htmlClass{eqt sym-temp}{\htmlStyle{color:var(--sym-temp)}{\gamma}}\) of zero gives back plain cross-entropy. The paper found 2 best and robust over a wide range.
\(\displaystyle {\begin{aligned}\mathrm{FL}(\htmlClass{eqt sym-prob}{\htmlStyle{color:var(--sym-prob)}{p_t}}) &= -\,\htmlClass{eqt sym-w}{\htmlStyle{color:var(--sym-w)}{\alpha_t}} \\ &\quad \times \big(1 - \htmlClass{eqt sym-prob}{\htmlStyle{color:var(--sym-prob)}{p_t}}\big)^{\htmlClass{eqt sym-temp}{\htmlStyle{color:var(--sym-temp)}{\gamma}}} \\ &\quad \times \log \htmlClass{eqt sym-prob}{\htmlStyle{color:var(--sym-prob)}{p_t}}\end{aligned}}\)
Built on line 2: the form the paper uses, with a class weight on top. \(\htmlClass{eqt sym-w}{\htmlStyle{color:var(--sym-w)}{\alpha_t}}\) is \(\htmlClass{eqt sym-w}{\htmlStyle{color:var(--sym-w)}{\alpha}}\) for the rare positive class and one minus \(\htmlClass{eqt sym-w}{\htmlStyle{color:var(--sym-w)}{\alpha}}\) for the negatives. The paper introduces \(\htmlClass{eqt sym-w}{\htmlStyle{color:var(--sym-w)}{\alpha}}\) as the rare class’s weight, yet its best setting with gamma 2 is 0.25, which gives the rare positives less weight than the negatives. The reason is that the gamma factor has already removed most of the easy negatives’ loss, so the remaining balance tips the other way, and the paper lowers \(\htmlClass{eqt sym-w}{\htmlStyle{color:var(--sym-w)}{\alpha}}\) as gamma rises. That is the opposite of Section 3’s rarer-gets-bigger weights.
So focal loss lets the hard examples, often the rare ones, carry the training signal, whatever the crowd of easy ones adds up to.

The loss is summed over all anchors and divided by the number assigned to objects, not by the number of anchors. The final layer’s bias starts so the rare class begins with a low prior probability, which keeps the flood of background from destabilizing the first steps (the formula is in the code of Section 9). Robust losses such as Huber do the opposite of focal loss: they down-weight hard outliers, where focal loss down-weights easy inliers (Lin et al. 2017).

6 Moving the decision threshold

After training, the model outputs a probability, and a cutoff turns it into a decision (the decision boundary). Choose that cutoff on validation data for the recall or precision the application needs: a lower cutoff catches more rare windows and raises more false alarms. It costs nothing, needs no retraining, and works on top of every fix above.

8 The tool: who carries the loss

A detector’s anchors as an illustrative crowd: many easy background boxes the model already scores as background, and a few hard boxes it gets wrong. Each dot sits at its \(\htmlClass{eqt sym-prob}{\htmlStyle{color:var(--sym-prob)}{p_t}}\), and its size is its focal loss. The bar shows how the total loss splits between the two groups.

Figure 5. Illustrative anchors. Raising gamma shrinks the easy crowd’s loss until the few hard ones dominate.

At gamma zero, plain cross-entropy, each easy dot is tiny but the crowd is so large that it owns most of the bar. As gamma rises the easy dots shrink far faster than the hard ones, and the bar swings to the hard side. Moving the balance trades the two groups’ weight directly, which is why the paper tunes it together with gamma.

9 In practice

torchvision’s focal loss takes float targets of the logits’ shape; its defaults match the paper’s settings. The second block is the bias start of Section 5, with pi the rare class’s prior.

import math, torchvision
from torch import nn
loss = torchvision.ops.sigmoid_focal_loss(
    logits, targets.float(), alpha=0.25, gamma=2,
    reduction="sum",
) / num_pos
pi = 0.01
nn.init.constant_(head.bias, -math.log((1 - pi) / pi))
  1. 1Focal loss, line 3, summed and divided by the positives.
  2. 2Start the rare class at a low prior.

When each runs: class weights once, from the training labels; a weighted loss every step; a sampler every epoch; SMOTE once, before training; focal loss every step, per example; the threshold once, after training. Which to try first:

  • Threshold first: free, and often enough when the model already ranks rare cases high.
  • Class weights or a sampler next, one of the two.
  • Focal loss when easy examples vastly outnumber hard ones, as in dense detection.
  • SMOTE for small tabular or feature-vector data, where new points between neighbours make sense.
