Support Vector Machines (SVM)

Support vector machines find the boundary with the most room on both sides. The running example is the logistic page’s: forum posts from 20 Newsgroups, sorted into rec.sport.hockey or comp.windows.x by two counts, how often a post says window or widget and how often it says game or team. Text is the classic case for SVMs (Joachims, 1998).

1 The maximum-margin classifier

An SVM picks, among the boundaries that separate the classes, the one farthest from the closest points. Two boundaries can both get every training point right; which do you trust on new data? The one with room to spare.

That boundary has the maximum margin, the most room on both sides before it touches a point, so a new point near the edge still lands on the right side. Take six training posts: hockey posts with counts (0, 2), (0, 3) and (0, 4), and windows posts with (2, 0), (3, 0) and (4, 0).

Those two posts are the support vectors: moving any other post leaves the boundary in place.

The decision line is where the score w·x + b is zero, and the margin lines are where it hits +1 and −1. For the six posts the widest line has weights −0.5 for the window count and 0.5 for the game count, and offset 0, so its weight vector has length 0.707 and its margin is 2.83 counts wide:

The gap between the two margin lines depends only on the length of the weights: shorter weights, wider gap.
margin width = 2‖w‖
‖w‖ is the length of the weight vector w. Bigger weights make the score change faster, so the ±1 lines come sooner and the margin narrows; halve the weights and the margin doubles. Widening the margin is exactly shrinking the weights.
So the margin width is 2 over the weights’ length, 2.83 for the six posts, and widening it means shrinking w. The next eq card does exactly that.

With no violations allowed, the widest margin is this problem. For the six posts, the line above puts both support vectors at exactly 1:

The widest separator makes the weights as small as it can while every point stays on its own side, outside the margin.
min ½‖w‖2
It maximises the width of the eq card above. min makes what follows as small as it can go: half the squared length of the weights. A smaller w means a wider margin, since the width is 2‖w‖.
s.t. yi(w·xi + b) ≥ 1
The constraint after s.t., read "such that", requires every point's label yi (+1 or −1) times its score to reach at least 1, so each point sits on its own side, at least one unit past the line. xi is point i's features, the · is the dot product (multiply matching features, add them up), and b is the offset. The points that land exactly on 1 are the support vectors.
So the hard margin works only when the groups can be split. Real posts overlap: a hockey post and a windows post that use none of the four words both have counts (0, 0), so no line can put each on its own side. The eq card in Section 2 lets points pay to break the rule.

2 The hinge loss and C

Real data overlaps, so training allows violations and adds a cost for each. The SVM is a linear model trained with the hinge loss, which asks whether the model is right with room to spare. The label times the score is positive on the correct side, and past 1 the loss is zero.

The soft margin (Cortes and Vapnik, 1995) swaps the hard rule for that cost on each violation. Three posts show the three zones:

Label times score, and the hinge each post pays (illustrative posts).

The hinge loss charges a point only when it sits inside the margin or on the wrong side, and the objective trades that charge against margin width.
fi = w·xi + b
It softens line 2 of the second eq card in Section 1. Point i's raw score fi is the dot product of w and xi plus the offset b.
hingei = max(0, 1 − yi·fi)
The shortfall 1 − yi·fi, floored at zero by max: zero once a point is safely past its margin line, and growing the deeper it sits inside the margin or past the line.
J = ½‖w‖2 + C·mean(hinge)
J adds the margin cost to C times the average hinge, the cost for every point that is wrong or too close. The two parts pull against each other: the first wants small weights and a wide margin, the second wants no point inside it. Raise C and violations cost more than width, so the margin narrows; lower it and the model widens the margin and tolerates violations. Near C = 0 only width counts and every point sits inside the margin; a huge C approaches the hard margin above. scikit-learn's SVC puts its C on the summed hinge, so its default 1.0 equals C = n here, with n the number of points (Section 6).
So the soft-margin SVM trades width against these charges: the borderline post pays 0.6, the wrong-side post 1.5. The eq card in Section 3 walks the objective step by step.

C is not a learning rate: a large C puts little weight on keeping w small (weak regularization), a small C much weight. Swap the hinge for the log loss and this is logistic regression.

The svm-pytorch notebook in Machine-Learning-Concepts trains with PyTorch's SGD: one step per batch of 32 points, 1,000 passes over 4,500 training points (about 141,000 steps), learning rate 0.001. It writes the cost as the mean hinge plus 1e-4 times the squared weights, which is J divided by C with C = 5,000. The hinge has a kink, so the step uses the subgradient: a point short of the margin nudges the weights toward its label, and every other point is left alone.

The notebook's training loop in PyTorch; on the posts, X would hold the two counts and y +1 for hockey, −1 for comp.windows.x.

import torch
lr, lam = 0.001, 1e-4
epochs, batch = 1000, 32
w = torch.zeros(2)
b = torch.zeros(1)
w.requires_grad_()
b.requires_grad_()
SGD = torch.optim.SGD
opt = SGD([w, b], lr=lr)
for epoch in range(epochs):
    order = torch.randperm(len(X))
    for idx in order.split(batch):
        f = X[idx] @ w + b
        gap = 1 - y[idx] * f
        hinge = gap.clamp(min=0)
        fit = hinge.mean()
        l2 = w.dot(w) + b.dot(b)
        loss = fit + lam * l2
        opt.zero_grad()
        loss.backward()
        opt.step()
  1. 1Starts w and b at 0 and sets up SGD at the notebook's learning rate.
  2. 2Shuffles each pass and walks it in batches of 32, about 141 steps per pass.
  3. 3Scores f and hinge losses, lines 1 and 2 of the card in Section 2.
  4. 4Mean hinge plus λ times the squared weights, which is line 3 divided by C, with λ one over twice C; the notebook also penalizes b.
  5. 5One subgradient step per batch.

5 Kernels and SVM variants

A kernel lets the same margin bend around curved data, and two variants reuse it for regression and anomalies.

5.1 The kernel trick

Some data no straight line can split, like a toy set of two rings, one inside the other. A lift adds a feature computed from the old ones, here the squared distance from the center.

In practice no one computes the lift: a kernel scores each pair of points as if they had been lifted.

Builds on the dot product (Vectors and Matrices, section 3)

A kernel scores how alike two points are, as if they had first been mapped into a richer space where a flat cut works.
K(x, z) = φ(x)·φ(z)
It replaces the dot product in the score of the eq card in Section 2. φ (phi) is the lift, and K(x, z) is the dot product of two points x and z after it. The kernel computes that number straight from the original points, so the flat cut in the lifted space never needs the lifted coordinates.
So any similarity of this form lets the SVM draw curves; the next eq card is the usual one. Hsu, Chang and Lin’s practical guide (section 3.1) calls the RBF kernel a reasonable first choice.

The RBF kernel calls two points alike when they are close, fading fast with distance; the polynomial kernel grows with their dot product instead.
K(x, z) = exp(−γ ‖x − z‖2)
Both lines are cases of the kernel in the eq card above. K is a similarity score for a pair of points, x and z: e raised to minus γ times the squared distance between the pair, so nearby pairs score near 1 and far pairs fade toward 0. γ (gamma) sets how far each point's influence reaches: raise it and influence shrinks until the boundary bends around each single point; lower it and the boundary smooths toward a straight cut. scikit-learn’s default, gamma = "scale", is 1number of features × variance of the data.
K(x, z) = (γ x · z + c)d
The polynomial kernel scales the dot product by γ, adds a constant c and raises the sum to the power d. With c above 0 it counts every product of up to d features, so d = 2 can draw ellipses and parabolas; at c = 0 only products of exactly d features remain. A higher d bends more and overfits sooner; scikit-learn defaults to d = 3 (degree), c = 0 (coef0) and γ = "scale".
So γ sets how local the RBF boundary is, and d how much the polynomial one bends. The next eq card shows where the kernel enters the trained score.

RBF (radial basis function) scores similarity to nearby points, like distance in k-nearest neighbors. The trained w is a weighted sum of the support vectors, so the score w·x is a sum of dot products, and the kernel replaces each one.

Take two illustrative support vectors, (0, 0) of class +1 and (2, 0) of class −1, each with α = 1, offset 0 and the RBF kernel at γ = 0.5. A new point at (0.5, 0) gets a kernel value of 0.882 from the first and 0.325 from the second, so its score is 0.558 and it is called class +1.

The trained weights are a sum over the support vectors, so the score can be written with the kernel in place of every dot product.
w = Σi αi yi xi
The weights come from training the objective of the eq card in Section 2, and K is the kernel of the eq card above. The solver finds one weight αi (alpha) per training point, at most C. It is zero for every point safely past its margin, so only the support vectors add to w.
f(x) = Σi αi yi K(xi, x) + b
Each dot product xi·x becomes the kernel. Each support vector xi pushes toward its own class yi (+1 or −1) with weight αi, and the kernel K fades that push with distance at the rate gamma sets. The new point x takes the side whose pushes add up stronger; the boundary is where f(x) = 0 and the pushes exactly cancel.
So the kernel trick is this one substitution in the score: the near support vector outweighs the far one. End of the chain.

5.2 Choosing a kernel

RBF is the default for low-dimensional curved data like the toy rings. The polynomial kernel bends the boundary into smooth curves, not RBF's tight local curves. When features outnumber points, as in text, linear usually wins: a straight cut in a huge space is already flexible (Joachims, 1998; Hsu, Chang and Lin, section 3.1).

5.3 SVR and one-class SVM

Support vector regression draws a tube around the predictions and only adds a cost for points outside it. The one-class SVM draws the boundary around normal examples only, and anything outside is an anomaly.

In scikit-learn, SVR's tube half-width epsilon (default 0.1) sets how big a miss is free: wider ignores more, 0 counts every miss. OneClassSVM's nu (default 0.5) caps the share of training points it may call anomalies; it marks new points +1 or −1.

from sklearn.svm import SVC, SVR, OneClassSVM
clf = SVC(kernel="linear", C=1.0)
clf.fit(X, y)
reg = SVR(epsilon=0.1)  # rbf
reg.fit(X, y_reg)
det = OneClassSVM(nu=0.05)  # rbf
det.fit(X_normal)
flags = det.predict(X_new)  # ±1
  1. 1Classifier with a straight boundary.
  2. 2Regression that ignores errors under ε.
  3. 3Novelty detector trained on normal points only.

6 SVMs in practice

The standard recipe for text in scikit-learn: word weights and a linear SVM on the two groups.

from sklearn.datasets import fetch_20newsgroups
from sklearn.feature_extraction.text import TfidfVectorizer
from sklearn.pipeline import make_pipeline
from sklearn.svm import LinearSVC

groups = ["comp.windows.x", "rec.sport.hockey"]
fetch = fetch_20newsgroups
train = fetch(subset="train", categories=groups)
test = fetch(subset="test", categories=groups)
vec = TfidfVectorizer()
svc = LinearSVC(C=1.0)
model = make_pipeline(vec, svc)
model.fit(train.data, train.target)
acc = model.score(test.data, test.target)
  1. 1The two groups with their own train and test split.
  2. 2Word weights (TF-IDF, counts scaled down for common words), then a linear SVM.
  3. 3Fits and scores on the test posts.

SVC, built on libsvm, caches kernel values in 200 MB. Its kernel matrix holds K for every pair of points, so its documentation says fit time grows at least with the square of the samples and suggests LinearSVC or SGDClassifier past tens of thousands, possibly after Nystroem. Scale inside the pipeline, since unscaled features break the RBF distance. SVC handles many classes one pair at a time, 190 pairs for all 20 groups, and scikit-learn 1.9 deprecates probability=True in favor of CalibratedClassifierCV.

scikit-learn's C multiplies the summed hinge, while the J card's C multiplies the mean, so scikit-learn's C equals the page's C divided by n, and its default 1.0 is the page's C = n.

Tuning C and γ together by 5-fold cross-validation (train on four folds, test on the fifth), here on the toy rings.

import numpy as np
from sklearn.datasets import make_circles
from sklearn.model_selection import GridSearchCV
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.svm import SVC
X, y = make_circles(400, noise=0.1, factor=0.4)
sc = StandardScaler()
svc = SVC(kernel="rbf")
model = make_pipeline(sc, svc)
Cs = np.logspace(-2, 3, 6)
gammas = np.logspace(-2, 2, 5)
grid = {}
grid["svc__C"] = Cs
grid["svc__gamma"] = gammas
gs = GridSearchCV(model, grid)
gs.fit(X, y)  # 5 folds by default
best = gs.best_params_
  1. 1The toy rings, scaled, then an RBF SVM.
  2. 2Candidate C and γ values, log spaced.
  3. 3Cross-validates every pair and keeps the best.

Nystroem builds features whose dot products approximate the RBF kernel; RBFSampler is the random alternative.

from sklearn.kernel_approximation import Nystroem
from sklearn.pipeline import make_pipeline
from sklearn.svm import LinearSVC
ny = Nystroem(n_components=300)
lin = LinearSVC(C=1.0)
clf = make_pipeline(ny, lin)
clf.fit(X, y)
  1. 1Approximates the RBF lift with 300 features, then a linear SVM; on the toy rings, as above.
  2. 2Fits in time linear in the number of points.
