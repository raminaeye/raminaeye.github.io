MuZero plans with a model it learned itself, a model of only what planning needs: the reward a move brings, the value of the position it leads to, and which move to pick next. It never rebuilds the screen, so it works where nobody hands it the rules, only screens and points. AlphaZero chose each move by trying moves with the game’s exact rules; MuZero learns its model from play and runs the same search on hidden states, summaries it invents, instead of real positions. Breakout is an Atari game: a paddle at the bottom bounces a ball into a wall of bricks, each broken brick earning points. Training runs the learned model forward a few moves along stored games and asks it to match the real rewards, the values, and the search’s move choices.

Figure 1 shows screens becoming summaries that step forward, with move values read off. Real screens go into a summary, the summary steps one move ahead and predicts its reward, and the next summary is read off for move chances and how good it looks. Take one Breakout moment: the screens become a summary, the summary steps ahead past the paddle move, and the read-off says which move looks best. The three dots under the summary are three moves the search can try from that one summary, and the middle one steps one move ahead.

1 A video game gives no rules to plan with

Atari is a set of classic video games, seen only as screen images. Each game draws a fresh screen many times a second.

The running example is Breakout. MuZero learned to play Breakout and the other Atari games from screens and points alone.

Figure 2 shows the only thing the model ever sees, a Breakout screen that alone says where everything is. The wall of bricks sits at the top, the ball hangs mid-screen, and the orange paddle sits at the bottom. Take the ball falling toward the paddle: the model must learn what to do from screens like this one.

Take the ball falling toward the paddle. The agent, the program that works the paddle, must pick a move, or action: doing nothing, firing the ball to start play, sliding left, or sliding right. Its situation is the state, and what it senses at one moment, the game screen, is the observation. Each move brings a reward, the number the world hands back, good or bad; in Breakout most moves earn nothing, and rewards come only when the ball breaks a brick.

One move in the real game is a real step, bringing its reward and the next state. The agent sees only these screens and the points total, never the game’s code. Learning which moves to make from rewards rather than from labelled answers is RL, short for reinforcement learning.

A model is the agent’s learned guess of where a move leads and what it pays. A model can be given, like the exact rules of a board game, or learned from its own steps. Nobody hands MuZero the rules of Breakout, so its model has to be learned from play. Planning means using a model to try moves in imagination instead of in the real world: one move tried inside the model is an imagined step, and a run of them is an imagined rollout. MuZero plans with imagined steps too, but its model never draws a screen.

Using a model to practise in its head is model-based RL, so the agent needs fewer real steps. Model-free agents learn only from real play, with no model. Earlier model-based agents that tried to predict the whole next screen fell well short of the best model-free agents on the Atari games, judged by points scored, because predicting the screen spends effort on details that do not change the points.

Looking ahead, or search, means trying several moves in the model, then the screens that follow, before choosing one for real.

2 The model predicts rewards, values and moves

Representation function

What. Picture the recent Breakout screens going into one box and coming out as a hidden state, a short summary for planning that need not look like the screens. That box is the representation function.

How. It runs once per real move, on the last \(32\) frames plus the last \(32\) actions that led to them, and the hidden state it returns is where the search starts.

Why. When it works, the summary keeps where the ball and paddle are headed and drops the rest.

Dynamics function

What. Picture a hidden state and one imagined paddle move going in, and a new hidden state coming out with the points that move would earn. That step is the dynamics function.

How. It takes the last imagined hidden state and a move, and gives back the predicted reward and the next hidden state.

Why. When it works, each imagined step lands close to what the real game would do, so the search can trust it.

Prediction function

What. Picture any hidden state being asked two questions: which move looks best, and how many points lie ahead. The prediction function answers both.

How. It reads one hidden state and gives back the move chances and the value, and the search calls it at every new position it reaches.

Why. When it works, the chances point at the strong moves and the value says how good the position is.

MuZero picks each Breakout move by searching inside its learned model, then trains on what that search found.

A policy is the agent’s rule for choosing a move in each state, and a state’s value is the return it expects from there, all the reward still to come, later rewards counted a little less. MuZero’s model is trained only to predict the reward, the value and the search’s choice of move, so it may drop any screen detail that does not help choose.

Figure 3 shows planning moving forward without ever rebuilding the screen. Take one imagined move: the dynamics steps the hidden state forward and predicts the points, and prediction reads off which paddle move looks best. The grey screen at the top right is the real screen the hidden state came from, and the dashed arrow runs from it to the hidden state: the screen feeds the summary.

2.1 Running the model forward along a real game

Unrolling and the trained length K

What. Picture the model imagining further and further ahead from one real moment. Unrolling is feeding the model its own predicted state again and again, and the trained length K is how many moves one unroll runs in training.

How. Training checks the model only along unrolls of K moves from stored real play, so every imagined step has a real step to check against. A search can still imagine further than K moves ahead.

Why. When it works, a longer K keeps the model right further ahead.

3 The three functions and how they are trained

The loss and the value target

What. Picture training unrolling the model along a stretch of real play and checking every prediction against what really happened. The loss scores how wrong those predictions were.

How. The loss adds three checks at each unrolled step: the predicted reward against the real reward, the value against the value target, and the move chances against what the search chose. Running many simulations from a position produces a value for that position, the search value.

Why. When it works, every prediction is pulled toward what really happened.

In a board game a legal move is a move the rules allow, and the player to move is the one whose turn it is. In Breakout every paddle move is allowed, and the agent is always the one to move.

One network gives two quick judgements of a position: the policy head gives a chance for each move the action space lists, legal or not, and the search masks illegal moves only at the root; the value head estimates the game result the player to move can expect from here: a win, a draw or a loss, seen from the player whose turn it is, with \(+1\) for a win, \(0\) for a draw and \(-1\) for a loss.

In Atari the value head instead estimates the discounted rewards still to come.

A hat over a letter marks it as made by the model, not seen in the real game: a state or reward marked with a hat is one the model invented.

3.2 The value target

Equation 2. The value target.
1\(\displaystyle \begin{aligned} \htmlStyle{color:var(--sym-statevalue)}{y_t} &= \htmlStyle{color:var(--sym-reward)}{r_{t+1}} + \htmlStyle{color:var(--sym-discount)}{\gamma}\, \htmlStyle{color:var(--sym-reward)}{r_{t+2}} + \cdots \\ &\quad + \htmlStyle{color:var(--sym-discount)}{\gamma^{n-1}} \htmlStyle{color:var(--sym-reward)}{r_{t+n}} \\ &\quad + \htmlStyle{color:var(--sym-discount)}{\gamma^{n}}\, \htmlStyle{color:var(--sym-statevalue)}{\nu_{t+n}} \end{aligned}\)

A larger discount lets later rewards count for more, so the target rises as \(\gamma\) grows. Counting more real rewards, a larger n, pulls the target toward the real points and away from the search value at the tail.

Intuition. The target adds the points from the next few real moves, each shrunk once more per step, then the search value from after them.
The mathematics. \(\htmlClass{eqt}{\htmlStyle{color:#1f618d}{y_t}}\) equals \(\htmlClass{eqt}{\htmlStyle{color:#7d6608}{r_{t+1}}}\) plus \(\htmlClass{eqt}{\htmlStyle{color:#5d6d7e}{\gamma}}\) times \(\htmlClass{eqt}{\htmlStyle{color:#7d6608}{r_{t+2}}}\), then the dots, plus \(\htmlClass{eqt}{\htmlStyle{color:#5d6d7e}{\gamma^{n-1}}}\) times \(\htmlClass{eqt}{\htmlStyle{color:#7d6608}{r_{t+n}}}\) plus \(\htmlClass{eqt}{\htmlStyle{color:#5d6d7e}{\gamma^{n}}}\) times \(\htmlClass{eqt}{\htmlStyle{color:#1f618d}{\nu_{t+n}}}\). \(\htmlClass{eqt}{\htmlStyle{color:#1f618d}{y_t}}\) is the value target at real step t, what the value head learns to aim at. \(\htmlClass{eqt}{\htmlStyle{color:#7d6608}{r_{t+1}}}\) is the first real reward, in full. \(\htmlClass{eqt}{\htmlStyle{color:#5d6d7e}{\gamma}}\) times \(\htmlClass{eqt}{\htmlStyle{color:#7d6608}{r_{t+2}}}\) is the second reward, shrunk once, and the dots mean every reward in between, each shrunk once more per step, down to \(\htmlClass{eqt}{\htmlStyle{color:#5d6d7e}{\gamma^{n-1}}}\) times \(\htmlClass{eqt}{\htmlStyle{color:#7d6608}{r_{t+n}}}\). 3.3 The loss checks every prediction

Equation 3. The loss. Training unrolls the model along stored real games.
1\(\displaystyle \begin{aligned} \ell &= \sum_{k=1}^{K} \ell^{r}\big(\htmlStyle{color:var(--sym-reward)}{r_{t+k}},\, \htmlStyle{color:var(--sym-reward)}{\hat r^{k}}\big) \\ &\quad + \sum_{k=0}^{K} \ell^{v}\big(\htmlStyle{color:var(--sym-statevalue)}{y_{t+k}},\, \htmlStyle{color:var(--sym-statevalue)}{v^{k}}\big) \\ &\quad + \sum_{k=0}^{K} \ell^{p}\big(\htmlStyle{color:var(--sym-policy)}{\boldsymbol{\pi}_{\text{search},\,t+k}},\, \htmlStyle{color:var(--sym-policy)}{\mathbf{p}^{k}}\big) \\ &\quad + \htmlStyle{color:var(--sym-discount)}{c_{\text{L2}}}\,\lVert\htmlStyle{color:var(--sym-model)}{\theta}\rVert^2 \end{aligned}\)

A longer unroll adds more checked steps, so the summed loss grows with K. A larger penalty weight lifts the whole loss by the same amount at every unroll length.

Intuition. Training checks every prediction at each step along stored real games.
The mathematics. \(\ell\) equals the three sums plus the L2 penalty, \(\htmlClass{eqt}{\htmlStyle{color:#5d6d7e}{c_{\text{L2}}}}\) times the squared size of \(\htmlClass{eqt}{\htmlStyle{color:#117a65}{\theta}}\); raising \(\htmlClass{eqt}{\htmlStyle{color:#5d6d7e}{c_{\text{L2}}}}\) pulls weights harder toward zero. Reward loss \(\htmlClass{eqt}{\htmlStyle{color:#7d6608}{\ell^{r}}}\) scores \(\htmlClass{eqt}{\htmlStyle{color:#7d6608}{r_{t+k}}}\) against \(\htmlClass{eqt}{\htmlStyle{color:#7d6608}{\hat r^{k}}}\), real against predicted; value loss \(\htmlClass{eqt}{\htmlStyle{color:#1f618d}{\ell^{v}}}\) scores \(\htmlClass{eqt}{\htmlStyle{color:#1f618d}{y_{t+k}}}\) against \(\htmlClass{eqt}{\htmlStyle{color:#1f618d}{v^{k}}}\), target against value; policy loss \(\htmlClass{eqt}{\htmlStyle{color:#7d3c98}{\ell^{p}}}\) scores \(\htmlClass{eqt}{\htmlStyle{color:#7d3c98}{\boldsymbol{\pi}_{\text{search},\,t+k}}}\) against \(\htmlClass{eqt}{\htmlStyle{color:#7d3c98}{\mathbf{p}^{k}}}\), search policy against move chances. The line shows plain sums; the weighting lives in code: the first step counts fully, later steps by \(1/K\), except the reward loss, \(1/K\) at every step. The reward sum starts at \(k\) equals \(1\), dropping the paper’s degenerate \(k\) equals \(0\) term, while value and policy start at \(0\). Reward and value are cross-entropy over buckets.
Example. Cross-entropy scores a predicted chance against the real outcome, so when the model puts little chance on the bucket holding the real reward, that step’s cross-entropy is large. The loss loop in the code carries this line.

A tree search tries moves from the current position, then the moves that follow them. The current position is the root; the newest position at the end of a path is a leaf. Monte Carlo tree search runs many simulations, each one pass from the root to a new leaf and back up. A simulator is a program that applies the rules exactly, so a search can step through positions without playing them.

Each simulation picks a move by PUCT, which favours moves that have looked good and moves the search has rarely tried. PUCT stands for predictor plus upper confidence bounds applied to trees: the bound is a bonus, large for moves tried rarely, shrinking as a move is tried more. At a new leaf the search expands it, adding that new position to the tree and reading off the move chances and the value there; the backup writes that value back up the path. The visit count is how many simulations went through a move; the search policy is each move’s share of the root’s visits.

MuZero keeps AlphaZero’s search and the two outputs of AlphaZero’s network, but not AlphaZero’s loss. MuZero’s loss adds a reward term and aims the value at the next few real rewards. In Atari MuZero scores value and reward with cross-entropy, after shrinking each into buckets, ranges of nearby values.

4 Stepping through planning and training

The search on hidden states

What. Picture the search growing a tree of hidden states, trying a move, then its replies, before choosing one for real.

How. Each simulation walks down the tree from the root, picking a move by PUCT. At the new leaf, it expands it, reading off the move chances and the value, and the backup writes that value back up the path, adding it to each move’s total and counting one more visit, so each move’s score is the average of the values below it.

Why. When it works, the visits pile up on the strongest moves.

The prior is the network’s first guess of how likely each move is, the policy head’s chance for that move, before any search. A move’s value, also called its score, is the return the agent expects if it makes a move in a state and plays on from there. In the tree, that score is the average value found below the move so far. The search keeps the prior and that score on every move.

PUCT runs on hidden states. MuZero’s version lets the exploration bonus grow slowly with the visits of the position above. Two constants tune the bonus: raising \(c_1\) weighs it more, so the search tries untried moves, and raising \(c_2\) slows how fast it grows with visits, so the search settles. It also rescales the move values found so far to the range in the tree, because Atari values have no fixed range.

In two-player games the value flips sign because it is read from the player to move, so a good position for one is bad for the other. In Breakout there is one player, so no sign flips; each step up adds that move’s predicted reward, discounted, to the value carried up.

The target sums rewards and value, and the loss compares predictions with targets.

5 MuZero in PyTorch

The three MuZero functions and one unrolled training loss; the search is AlphaZero’s. The paper’s networks carry \(256\) planes, each a flat sheet of numbers tracking one feature.

import torch
import torch.nn.functional as F
from torch import nn
L, R = nn.Linear, nn.ReLU
HIDDEN = 256  # hidden width, 256 planes
N_MOVES = 4  # Breakout moves
class Repr(nn.Module):
    def __init__(self, obs_dim, h=256):
        super().__init__()
        self.trunk = nn.Sequential(
            L(obs_dim, h), R())
    def forward(self, obs):
        return self.trunk(obs)
class Dyn(nn.Module):
    def __init__(self, h=HIDDEN):
        super().__init__()
        self.trunk = nn.Sequential(
            L(h + N_MOVES, h), R())
        self.reward = L(h, 1)
        self.next = L(h, h)
    def forward(self, s, a):
        o = F.one_hot(a, N_MOVES).float()
        x = torch.cat([s, o], dim=-1)
        h = self.trunk(x)
        r = self.reward(h)
        return r, self.next(h)
class Pred(nn.Module):
    def __init__(self, h=HIDDEN):
        super().__init__()
        self.trunk = nn.Sequential(
            L(h, h), R())
        self.policy = L(h, N_MOVES)
        self.value = L(h, 1)
    def forward(self, s):
        h = self.trunk(s)
        p = self.policy(h)
        return p, self.value(h)
repr_ = Repr(obs_dim)
dyn = Dyn()
pred = Pred()

6 How far training checks the learned model

Each imagined step starts from the last imagined state, so a small model error grows the further ahead the agent imagines.

A search can imagine more moves ahead than the K steps training checks, so what happens past K matters.

7 MuZero in practice

In every game, each move runs one search on hidden states, with fewer simulations per move in Atari. Each move starts a fresh search from a new hidden state, built from the recent screens and actions; what carries over between moves is that history and the network weights, not the search tree. Training runs continually on games kept in a replay buffer, a store of past games training draws from again, each sample unrolled K moves. Deep Q-Networks introduced the replay buffer, and MuZero keeps the same store and draws its training samples from it. In Atari the picking of samples for training favours the samples where the search value was furthest from what really happened; board games draw every sample alike. A second copy of the network plays the games, refreshed from the training network at a fixed interval. In self-play one network plays both sides, so each side improves exactly as fast as the other. In Atari this is not self-play, since there is one player.

MuZero General is a commented PyTorch code version of the whole algorithm, built from the paper and its pseudocode.

Later steps’ losses are scaled down, and so is the gradient entering the dynamics. Value and reward are predicted on the shrunk bucket scale, grouping nearby values into ranges.

8 Planning without a simulator

  • MuZero fits when no simulator or rules are available, and there is computing for a search at every step.
  • Against AlphaZero: in chess, shogi, a Japanese board game like chess, and Go, both learned by self-play, each network playing both sides of the same games, and judged by who wins more games, the two play at about the same strength. MuZero also plays where no rules exist.
  • Picture a game with no rules to look up: at every move the search runs on what the model imagined, and the move it picks is only as good as that imagining.

9 Model drift, mixed scales and stale targets

Three things go wrong, each with a fix.

  • Model drift. The dynamics only ever trained on short unrolls, so the further the search goes, the more its imagined states drift from real play. In Atari, searching further ahead stops adding points once the gains flatten. Take the paddle sliding to meet the ball: the model imagines the ball bouncing one way while the real ball goes the other, and the longer the search looks ahead, the further its imagined ball drifts from the real one.
  • Mixed scales. Atari points range from tiny to huge, so value and reward learning turn unstable and the search’s scores have no fixed range. Predicting value and reward on the shrunk bucket scale steadies learning, and rescaling the scores by the smallest and largest values seen so far puts the search on one scale.
  • Stale targets. Stored search policies and values come from older weights, so each stored game teaches less. Re-running the search on stored positions with the newest network gives them fresher targets, so it reaches further on the same number of games than the same method without reanalysis.

10 Learning behaviour inside the model

MuZero still searches at every move. Can an agent learn its behaviour entirely inside the model, with continuous actions, actions that are amounts with any value, like the turning forces at a walking robot’s joints?

Imagine an agent that has learned its behaviour inside the model, with no search when it plays: the paddle slides under the falling ball because the behaviour says where the paddle belongs.

World Models learns a model of the game first, then trains a small controller inside it, a tiny network that turns a hidden state into a move, with no search when it plays. Dreamer learns its behaviour the same way, imagining whole runs ahead inside its own model and keeping the moves that score best there.
