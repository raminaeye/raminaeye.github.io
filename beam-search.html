1 Searching for the likeliest reply

A translation system reads the French Il fait froid. and must write the English sentence. Several sentences are right; the model gives each a chance, one token at a time. A search decoder looks for the whole reply with the highest chance and has no randomness, so it writes the same reply every time. Finding the exact best reply would mean scoring every possible sequence, and there are far too many. Greedy decoding and beam search are two cheap ways to look.

It runs at every generated token, inside the loop of Decoding. The beam carries a few partial replies, each with its score and its own KV cache. Google’s neural translation system used beam search with a length penalty (Wu et al. 2016), and speech recognition runs the same search over alignments in CTC Loss.

2 Greedy decoding: a beam of one

Greedy decoding writes the likeliest next token and moves on. It is fast and needs nothing extra. Its weakness is that it never looks back: a likely first token can lead into a sentence whose later tokens are all unsure, while a slightly less likely first token led somewhere better.

3 Beam search

Beam search keeps the best few partial replies at every step. That number is the beam width. Each step extends every kept reply by every candidate token, scores the longer replies, and keeps only the best few. A reply that picks the end token is set aside as finished. When no partial replies are left, the best finished reply wins.

Greedy keeps the top token at each step; beam search ranks whole partial replies by their summed log chance.

(1)\(\displaystyle {\htmlClass{eqt sym-x}{\htmlStyle{color:#a85a14}{x_t}} = \operatorname*{arg\,max}_{i} p(i \mid \htmlClass{eqt sym-xp}{\htmlStyle{color:#a85a14}{x_{<t}}})}\)
Greedy, equation (1): \(x_t\) is the token written at step \(t\) and \(x_{\lt t}\) the reply so far. The argmax returns the token whose chance is largest, not the chance itself.
(2)\(\displaystyle {\begin{aligned}&\htmlClass{eqt sym-s}{\htmlStyle{color:#117864}{s(x_{1:t})}} \\ &\; = \sum_{u=1}^{t} \log p(\htmlClass{eqt sym-x}{\htmlStyle{color:#a85a14}{x_u}} \mid \htmlClass{eqt sym-xp}{\htmlStyle{color:#a85a14}{x_{<u}}})\end{aligned}}\)
Beam score, equation (2): a partial reply’s score adds the log chance of each of its tokens. A whole reply’s chance is the product of its token chances, and the log of a product is the sum of the logs, so ranking by \(s\) ranks whole replies by their chance. Logs also keep long products from rounding down to zero. Each log is negative, so every extra token lowers the score.

5 Length normalization

Every token adds a negative log, so the plain sum favours short replies: a translation that stops early can beat a complete one. Wu et al. (2016) divide the score by a power of the length. Their first form is equation (3); they report that values of the power between 0.6 and 0.7 usually worked best for it. Their final system uses the softer penalty of equation (4), together with a coverage penalty that rewards covering the whole source sentence.

The length-normalized score divides the summed log chance by a power of the length.

(3)\(\displaystyle {\htmlClass{eqt sym-s}{\htmlStyle{color:#117864}{s_{\text{norm}}}} = \frac{\htmlClass{eqt sym-s}{\htmlStyle{color:#117864}{s(x_{1:L})}}}{L^{\htmlClass{eqt sym-a}{\htmlStyle{color:#7d3c98}{\alpha}}}}}\)
\(L\) is the reply length in tokens and \(\alpha\) sets how hard to correct. Dividing a negative score by a larger number pulls it toward zero, so long replies lose less for having more terms. With \(\alpha\) at zero the bottom is one and this is the plain sum of equation (2); with \(\alpha\) at one it is the average log chance per token.
(4)\(\displaystyle {\begin{aligned}&\mathrm{lp}(Y) = \frac{(5 + |Y|)^{\htmlClass{eqt sym-a}{\htmlStyle{color:#7d3c98}{\alpha}}}}{(5 + 1)^{\htmlClass{eqt sym-a}{\htmlStyle{color:#7d3c98}{\alpha}}}} \\ &\htmlClass{eqt sym-s}{\htmlStyle{color:#117864}{s_{\text{norm}}}} = \frac{\htmlClass{eqt sym-s}{\htmlStyle{color:#117864}{s(Y)}}}{\mathrm{lp}(Y)}\end{aligned}}\)
GNMT’s final penalty, with \(Y\) the reply and \(|Y|\) its length. The constant in the bracket softens the start, so the first few tokens are not over-rewarded. Remove the constant and this is equation (3) again.
scorelength power

Hugging Face’s length_penalty divides a finished beam’s summed score by its length raised to that value, with no constant in the bracket; its default is one, the per-token average.

6 The tool: width and length penalty

At width one the search is greedy. A wider beam reaches replies greedy never sees, and with the plain sum a short reply can win; raising the power lets the complete, longer reply win.

7 The likeliest text loops

For open-ended writing the likeliest text turns out to be bad. Holtzman et al. (2020) gave GPT-2 Large, a 774-million-parameter language model, the opening of a story and let beam search continue it.

Repetition feeds itself: each repeat makes the next one likelier. Holtzman et al. also show that the tokens beam search picks keep a high chance at every step, while human text varies much more from token to token. Their abstract puts it plainly: decoding that maximizes the chance gives text that is bland, incoherent, or stuck in repetitive loops.

8 The repetition penalty

A repetition penalty from CTRL (Keskar et al. 2019) makes a repeat less likely by lowering the score of every token already written.

A token already in the reply has its score divided by the penalty before the softmax.

(5)\(\displaystyle {\begin{aligned}\htmlClass{eqt sym-z}{\htmlStyle{color:#1f6aa5}{z_i}} &\leftarrow \frac{\htmlClass{eqt sym-z}{\htmlStyle{color:#1f6aa5}{z_i}}}{\htmlClass{eqt sym-th}{\htmlStyle{color:#7d6608}{\theta}}}, \quad \htmlClass{eqt sym-th}{\htmlStyle{color:#7d6608}{\theta}} > 1 \\ &\text{each } i \text{ already written}\end{aligned}}\)
\(z_i\) is the token’s logit and \(\theta\) the penalty. Dividing a positive score by a number above one shrinks it, so after the softmax the token is less likely to be picked again; tokens not yet used gain the share it loses. CTRL applies this inside its temperature softmax (CTRL writes that temperature as T; this site writes τ). The argmax of equation (1) now sees the lowered scores.
logitpenalty

CTRL introduced it for sampling and near-greedy decoding and reports that a penalty of about 1.2 gives a good balance with greedy decoding; libraries also apply it with beam search. Dividing a negative score would raise it, so Hugging Face’s repetition_penalty multiplies a negative score by the penalty instead; either way the token is pushed down. It also hurts tokens that should repeat, such as a name or a variable in code. The other common fix is an n-gram block, no_repeat_ngram_size in Hugging Face, which lets every run of that many tokens appear only once. Sampling, on Sampling the Next Token, avoids the loop a different way.

9 Beam search in practice

Code 1, a toy beam search over a stub that returns the log chance of each next token.

import heapq

def beam_search(next_logprobs, width, max_len, end, alpha):
    beams = [((), 0.0)]                      # (tokens, summed log chance)
    finished = []
    for _ in range(max_len):
        grown = [(toks + (t,), score + lp)
                 for toks, score in beams
                 for t, lp in next_logprobs(toks).items()]
        beams = []
        for toks, score in heapq.nlargest(width, grown, key=lambda b: b[1]):
            (finished if toks[-1] == end else beams).append((toks, score))
        if not beams:
            break
    finished += beams                        # unfinished replies at the limit
    return max(finished, key=lambda b: b[1] / len(b[0]) ** alpha)
  1. 1Start with one empty reply; finished replies are set aside.
  2. 2Extend every kept reply by every next token and add its log chance (equation (2)).
  3. 3Keep the best few by score; a reply that ends is set aside as finished.
  4. 4Pick the winner by the length-normalized score (equation (3)). With width=1 this is greedy.

Code 2, the same search in Hugging Face generate.

beams = model.generate(
    input_ids,
    num_beams=WIDTH,
    length_penalty=ALPHA,
    early_stopping=True,
    no_repeat_ngram_size=N,
    max_new_tokens=LIMIT,
)
  1. 1The beam width; one is greedy.
  2. 2The length power of equation (3).
  3. 3Stop as soon as enough finished replies exist.
  4. 4The n-gram block against loops. Capital names are placeholders.

Cost: each step runs the model on width rows instead of one and keeps width KV caches, so beam search costs about width times the work of greedy per step.

Holtzman et al. cite the same large-beam failure in translation (Koehn and Knowles 2017) and with exact search (Stahlberg and Byrne 2019). Use beam search for tasks with one right answer, such as translation and speech recognition, and keep the width small.
