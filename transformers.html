Attention

How each token decides what to listen to

On this page

You've heard the name a thousand times by now. Attention is the idea at the heart of the transformer, and this page builds it from one score up to several heads.

Long dependencies break sequential models

Older sequence models like RNNs (recurrent neural networks) read one token at a time, a token being a word or part of a word, so they cannot run in parallel. If the word that decides the meaning showed up 50 words ago, an RNN carries it through 50 sequential steps. Every step is a chance to forget.

CNNs (convolutional neural networks, which slide a small learned filter across the input) see only a local neighborhood, so many layers must stack before one end of a sentence can reach the other.

Transformers replace both with one idea: every token interacts with every other token in a single step. The token "it" in "the cat sat on the mat because it was tired" can look straight at "cat". That idea is self-attention.

Each token learns which other tokens to listen to

In "the cat sat on the mat", when the model processes "sat", which tokens should it listen to? Probably "cat" more than "the". Attention is the model learning those listening weights by itself. Each token is projected into three vectors:

  • Query (Q): what a token is looking for.
  • Key (K): what a token offers, matched against every query.
  • Value (V): the content a token hands over to the tokens that listen to it.

All three come from the input embedding matrix X: one row per token, each row a learned vector of 512 numbers. One learned weight matrix per role turns X into queries, keys and values. Queries and keys need the same length, because they get dotted together. With 6 tokens and a query length of 64:

Scores become weights, weights blend the values

The score of a query against a key is their dot product: multiply the two vectors entry by entry and add up, a measure of how aligned they are. A softmax turns each query's row of scores into weights that are positive and sum to 1 (raise e to each score, divide by the row's total). The token's output is the values blended by those weights.

The scores are first divided by √dₖ, where dₖ is the length of each query and key. A dot product adds one term per dimension, so scores grow with dₖ. Big scores make the softmax nearly one-hot (one weight near 1, the rest near 0), and the gradients, the signals training uses to adjust the weights, become tiny. Vaswani and colleagues give this reasoning as a suspicion, not a proof.

Why the square root: if each entry of a query and a key is random with mean 0 and variance 1 (variance is the average squared distance from the mean), their dot product has variance dₖ, and dividing by √dₖ brings it back to 1. A check with 10,000 random pairs at dₖ = 64: 

import torch

q, k = torch.randn(10000, 64), torch.randn(10000, 64)  # 10,000 query-key pairs, d_k = 64
dots = (q * k).sum(dim=-1)                              # (10000,) one dot product per pair
dots.var()                                              # about 64: variance grows with d_k
(dots / 8).var()                                        # about 1 after dividing by sqrt(64) = 8

In equations, attention is four steps, then one line that folds them together:

Project the tokens, then score every query against every key.
Q = XWQ, K = XWK, V = XWV
The queries, keys and values are the token matrix X times three learned matrices, one per role, so what a token seeks, offers and carries can differ.
S = QKT√dk
S holds every query dotted with every key; T is the transpose, and dividing by √dk keeps the scores' variance near 1.
Then scores become listening shares, and the shares blend the values.
A = softmax(S)
Softmax, taken row by row, turns each query's scores into positive shares that sum to 1: a fixed listening budget per token.
out = A·V
Each output row blends all the value rows, weighted by that query's shares; the dot is a matrix product.
Attention(Q, K, V) = softmax(QKT√dk)V
The same steps folded into one line, as the 2017 transformer paper writes it; the attention function implements exactly this line.

The same lines in PyTorch, with q, k and v already projected, one row per token: 

import math
import torch

def attention(q, k, v):
    # q: (n, d_k), k: (n, d_k), v: (n, d_v), one row per token
    scores = q @ k.transpose(-2, -1) / math.sqrt(q.size(-1))  # (n, n)
    w = scores.softmax(dim=-1)                                # (n, n), each row sums to 1
    return w @ v                                              # (n, d_v)

q, k, v = torch.randn(6, 64), torch.randn(6, 64), torch.randn(6, 32)
attention(q, k, v).shape                                      # torch.Size([6, 32])

One attention layer, walked through

One attention layer, one step at a time, on three tokens: "the cat sat". It is a toy: real models split words into subword pieces, parts of a word, and use vectors of 512 numbers. One head learns one relationship, so run several in parallel

One set of listening weights captures one type of relationship. But "cat" relates to "the" by grammar and to "sat" by meaning. One head can't do both well.

Multi-head attention runs several copies of attention side by side, called heads, each with its own projections into a smaller subspace, a slice of the model's dimensions. The 2017 transformer uses a model width dmodel of 512 and h = 8 heads, so each head works in 64 dimensions.

Each head runs the attention line from Scores become weights, weights blend the values on its own projections:

Each head attends on its own projections, then the heads are joined and mixed.
headi = Attention(QWiQ, KWiK, VWiV)
Head i runs attention on its own projections, each dmodel × dk; in self-attention the inputs Q, K and V are all X.
MultiHead(Q, K, V) = Concat(head1, …, headh) WO
Concat places the h head outputs side by side, back to dmodel columns, and WO mixes them into one vector per token.

In code, the split is a reshape and the merge is its reverse. The attention function works on any leading dimensions, so one call runs every head: 

import torch, torch.nn as nn

B, T, d_model, h = 2, 6, 512, 8
d_k = d_model // h                                        # 64 per head
qkv = nn.Linear(d_model, 3 * d_model)                     # W_Q, W_K, W_V in one layer
W_o = nn.Linear(d_model, d_model)                         # output projection W^O
x = torch.randn(B, T, d_model)                            # (batch, tokens, d_model)
q, k, v = qkv(x).split(d_model, dim=-1)                   # each (B, T, 512)
split = lambda t: t.view(B, T, h, d_k).transpose(1, 2)    # (B, h, T, 64)
heads = attention(split(q), split(k), split(v))           # (B, h, T, 64), one output per head
out = W_o(heads.transpose(1, 2).reshape(B, T, d_model))   # merge back: (B, T, 512)
out.shape                                                 # torch.Size([2, 6, 512])

Because each head scores in its own subspace, two heads can listen to different tokens. In "The animal didn't cross the street because it was too tired", "it" needs coreference, finding which noun a pronoun refers to, and the local clause around it. With these illustrative weights, each head takes one job:

Head A: coreference Head B: local syntax

Head A puts its weight on "animal"; Head B stays on the clause around "it".

More heads sound like more parameters. They are not. Fix the model width d (short for dmodel) and change only the head count h: each head's slice dₖ is d divided by h, so the total stays put.

The attention parameter count has no h in it.
total = 3d2 + d2 = 4d2
3d² for the query, key and value projections plus d² for WO, ignoring biases; h only changes how d is sliced.

Sixteen 32-dim heads or one 512-dim head: the slices change, the bill does not.

Every head on this page takes its queries, keys and values from the same sequence, which makes it self-attention. When the queries come from one stream and the keys and values from another, say text asking about an image, it becomes cross-attention, covered in Cross-Attention.
