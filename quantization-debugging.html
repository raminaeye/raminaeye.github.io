Debugging a Quantized Model

On this page

1 Common quantization bugs 2 Finding the layer that loses accuracy 3 References

A quantized model that loses accuracy almost always has one of a few causes, and each one leaves a visible symptom. Every tensor in the model runs the round trip taught on the Quantization page, so every check on this page asks one question: which tensor got a bad grid?

The round trip snaps a float onto the integer grid and then reads it back.
xq = round(xs) + z
The scale s is the width of one grid step, so x/s counts steps from 0 and rounding picks the nearest integer level; the zero point z is the integer that stands for 0.0.
x̂ = s·(xq − z)
Reading back undoes the shift and the division. Observers pick s and z from the values they see, and FakeQuantize runs this round trip inside training during quantization-aware training (QAT).

These checks run once, after the model is quantized and its accuracy has dropped, not during training (Figure 1).

The listings use one toy model, TinyCNN from the Quantization page (Figure 2). Imports follow that page, with tq for torch.ao.quantization. Since PyTorch 2.8, torch.ao.quantization (eager and FX modes) is marked deprecated in favor of torchao; the checks carry over.

2 Finding the layer that loses accuracy

The six checks of Figure 1, cheapest first.

2.1 Print each layer's scale and zero point

Weight fake quants keep one scale per output channel by default, so a single number would hide the bad channel; two signs give a bad channel away: a scale of 0 or NaN (not a number), and a scale far above the rest (Figure 3).

The loop prints every fake-quantize module's scale shape and its first four scales.

mods = qat_model.named_modules()
for name, mod in mods:
    if isinstance(mod, tq.FakeQuantize):
        # one scale per out channel
        s = mod.scale
        print(name, s.shape, s[:4])
  1. 1Walks every module and keeps only the fake-quantize ones.
  2. 2Prints each weight scale: one value per output channel, so a huge entry flags a bad channel.

2.2 Plot activation ranges per layer

An observer's range should hug the data. When the range is much wider than the data, most grid levels sit where no value falls (Figure 4).

A forward hook is a function PyTorch runs each time a layer executes, so it can record the layer's output; the histogram goes beside the observer's range (printed in Inspect the observers).

outputs = {}

def record(module, inputs, out):
    outputs["relu1"] = out.detach()

relu1 = model_fp32.relu1
hook = relu1.register_forward_hook(record)
with torch.no_grad():
    model_fp32(calib_batch)
hook.remove()
acts = outputs["relu1"].flatten()
plt.hist(acts.numpy(), bins=100)
  1. 1A forward hook stores the relu1 output each time it runs.
  2. 2Runs one calibration batch with gradients off, then removes the hook.
  3. 3Flattens the stored activations and plots their histogram.

2.3 Keep one layer in float and re-measure

Turn one layer back to float and see whether accuracy comes back. If it does, that layer's grid is the problem.

fq = qat_model.conv1.weight_fake_quant
fq.disable_fake_quant()

# lasting fix: conv1 stays float
qmap = tq.get_default_qat_qconfig_mapping("x86")
qmap.set_module_name("conv1", None)
model = copy.deepcopy(model_fp32)
model.train()
ex = (calib_batch,)
qat_model = prepare_qat_fx(model, qmap, ex)
  1. 1For a quick test, switch off rounding on conv1's weights and re-measure accuracy.
  2. 2For a lasting fix, map conv1 to no qconfig and prepare the model again, so it stays float.

2.4 Read the FX graph table

FX (PyTorch's graph-tracing toolkit) turns the model into a list of operations. A layer with no observer row was never quantized; a quantize and dequantize pair between two layers that should run together usually means a missed fusion.

One call prints that list as a table, one row per operation and per inserted observer.

# needs tabulate
qat_model.graph.print_tabular()

2.5 Inspect the observers' recorded ranges

FX adds each activation observer as a module on the top-level model, named activation_post_process_0, activation_post_process_1 and so on. During QAT each one is a FakeQuantize that holds the observer inside it.

Anything outside an observer's recorded range gets clamped to the grid edge.

prefix = "activation_post_process_"
for name, fq in qat_model.named_modules():
    if not name.startswith(prefix):
        continue
    # the observer
    obs = fq.activation_post_process
    lo = obs.min_val.item()
    hi = obs.max_val.item()
    s = fq.scale.item()
    z = fq.zero_point.item()
    print(name, s, z, lo, hi)
  1. 1Keeps only the activation fake-quantize modules FX inserted.
  2. 2Reads the range the observer recorded during calibration.
  3. 3Prints the scale and zero point computed from that range.

2.6 Compare float and quantized layers with the Numeric Suite

When the cheap checks do not point at a layer, compare every layer at once. PyTorch's Numeric Suite (torch.ao.ns._numeric_suite_fx, imported as ns) logs each layer's output in a float copy and an int8 copy on the same input and scores each pair by its SQNR (signal to quantization noise ratio). The leading underscore means the API can move between PyTorch versions.

SQNR compares one layer's float output with its int8 output on the same input, in decibels.
SQNR = 20 log10 ‖x‖‖x − x̂‖
x is the float layer's output and x̂ the int8 layer's output; the fraction is signal size over noise size (‖·‖ is a vector's length). Higher is closer, and each 6 dB is roughly one more bit of agreement.

The first listing builds the two copies and fills their loggers with one real batch.

import torch.ao.ns._numeric_suite_fx as ns
from torch.ao.quantization import quantize_fx

ref = copy.deepcopy(qat_model).eval()
# float copy
ref.apply(tq.disable_fake_quant)
q = copy.deepcopy(qat_model).eval()
int8 = quantize_fx.convert_fx(q)
Logger = ns.OutputLogger
ref, int8 = ns.add_loggers("fp32", ref, "int8", int8, Logger)
with torch.no_grad():
    ref(calib_batch)
    int8(calib_batch)
  1. 1Makes the float reference, a copy of the model with rounding switched off.
  2. 2Converts a second copy to real int8 kernels.
  3. 3Adds an output logger to every matching layer of both models.
  4. 4Runs one real batch through each so the loggers fill.

The second listing prints each layer's SQNR.

from torch.ao.ns.fx import utils

Logger = ns.OutputLogger
logs = ns.extract_logger_info(ref, int8, Logger, "int8")
for layer, r in logs.items():
    out = r["node_output"]
    fp = out["fp32"][0]["values"][0]
    q8 = out["int8"][0]["values"][0]
    sqnr = utils.compute_sqnr(fp, q8)
    print(layer, sqnr.item())
  1. 1Pairs the logged outputs of the two models layer by layer.
  2. 2Pulls the float and int8 output tensors for one layer.
  3. 3Prints that layer's SQNR; the first sharp drop marks the broken layer.

2.7 Outliers and dead activations

An outlier is one channel whose values are far larger than the rest; with one scale for the whole tensor, it widens the grid step for every channel. A dead activation is an output stuck at zero whatever comes in, so it carries no signal.

Both show up in two numbers, the widest channel range over the median one and the share of exact zeros (outputs comes from the hook listing in Plot activation ranges).

# (8, 1, 3, 3)
w = model_fp32.conv1.weight.detach()
# (8,): range per channel
rng = w.abs().amax(dim=(1, 2, 3))
print(rng.max() / rng.median())
dead = outputs["relu1"] == 0
# share of dead outputs
print(dead.float().mean())
  1. 1This line divides the widest channel range by the median one; a large ratio means outlier channels.
  2. 2This line measures the share of relu1 outputs that are exactly 0; a high share means dead activations.

For an outlier channel, use per-channel weights (the default in get_default_qconfig_mapping("x86")) or a histogram observer that clips the tail. For dead activations, check the layer's input range: if everything going into a ReLU (which passes positive values and zeros the rest) is negative, the fix is upstream, not in the grid.

Once the model quantizes cleanly, the next lever is the architecture itself: Neural Architecture Search looks for a network that is small from the start, and Knowledge Distillation trains it from a larger teacher.
