Normalization and Quantization

What happens to each norm layer before 8-bit inference.

Before a model runs in 8-bit integers, each norm layer either disappears into the layer before it, keeps running with its gain and shift moved, or forces a fix for the huge activations around it.

Each change on this page is done once, offline, before export; the only part that still runs on every token is LayerNorm's centering and division, and RMSNorm's division [2, 5, 6].

ChangeWhen it runsWhat it uses and stores
BN foldonce, offline, after training and before exportthe trained \(\gamma\), \(\beta\), \(\overline{\mu}\), \(\overline{\sigma}^{2}\); stores nothing new and removes a layer [2]
LN gain foldonce, offline\(\gamma\) moves into the next linear weights and \(\beta\) into its bias; centering and division still run every forward pass [6]
SmoothQuantonce, offline, from calibration samplesper-channel factors fold into the previous LayerNorm and the next linear weights; no extra runtime operation [5]

1 BatchNorm folds into the conv before quantizing

Builds on the 1x1 convolution (Inception (GoogLeNet) and 1×1 Convolutions, section 2)

At inference, BatchNorm with fixed statistics only multiplies by a number and adds a number per channel [1]. A conv is already a multiply and add, so the two collapse into one conv with new weights, and nothing is left to quantize between them. Take one output channel of a 1 × 1 conv followed by BatchNorm2d, the Conv, BN pair that static quantization (Quantization, section 6) fuses first.

With a tiny \(\varepsilon\) the two paths still agree. Put the conv output into BN's inference line and regroup.

Folding BatchNorm into the conv before it
\(\displaystyle y = \htmlStyle{color:#7d3c98}{\gamma} \frac{\htmlStyle{color:#2471a3}{W x + b} - \htmlStyle{color:#0e6b59}{\overline{\mu}}}{\sqrt{\htmlStyle{color:#c0392b}{\overline{\sigma}}^{2} + \varepsilon}} + \htmlStyle{color:#7d3c98}{\beta}\)
\(W\) holds the conv's weights, \(b\) its bias and \(x\) its input; \(\overline{\mu}\) and \(\overline{\sigma}^{2}\) are BN's running mean and variance, \(\gamma\) and \(\beta\) its learned gain and shift, \(\varepsilon\) the small constant that keeps the division safe. The conv output goes straight into line 3 of the running-statistics card in Batch Normalization, per output channel. In Figure 1, \(y\) is the same either way.
\(\displaystyle \htmlStyle{color:#2471a3}{\tilde{W}} = \frac{\htmlStyle{color:#7d3c98}{\gamma}}{\sqrt{\htmlStyle{color:#c0392b}{\overline{\sigma}}^{2} + \varepsilon}} \htmlStyle{color:#2471a3}{W}\)
New weights: each output channel's filter times its own \(\gamma / \overline{\sigma}\). In Figure 1, \(\tilde{W}\) is the folded weight.
\(\displaystyle \htmlStyle{color:#2471a3}{\tilde{b}} = \htmlStyle{color:#7d3c98}{\gamma} \frac{b - \htmlStyle{color:#0e6b59}{\overline{\mu}}}{\sqrt{\htmlStyle{color:#c0392b}{\overline{\sigma}}^{2} + \varepsilon}} + \htmlStyle{color:#7d3c98}{\beta},\)
\(\displaystyle \quad \text{so} y = \htmlStyle{color:#2471a3}{\tilde{W}} x + \htmlStyle{color:#2471a3}{\tilde{b}}\)
The folded bias carries the mean shift and the learned shift in one number, so the folded layer matches the original output. A conv with no bias uses \(b\) = 0. In Figure 1, \(\tilde{b}\) is the folded bias.
So the folded layer is a single plain conv: the folded weights times the input, plus the folded bias, giving the same answer \(y\) as the conv plus batch norm did. Figure 1 shows both paths.

Term by term, \(\gamma / \overline{\sigma}\) is the per-channel scale, and it grows when \(\overline{\sigma}\) is small, which can widen the range of weights to quantize: in MobileNet v1 the folded weights show larger outliers than the unfolded ones [3]. \(\overline{\mu}\) and \(\beta\) only move the bias. Folding removes the BN compute, its data movement and the quantization of its output [2]. In PyTorch, by hand and with the library call:

import torch
from torch import nn
from torch.nn.utils import fusion

conv = nn.Conv2d(3, 8, 3, bias=False).eval()
bn = nn.BatchNorm2d(8).eval()
with torch.no_grad():
    sd = torch.sqrt(bn.running_var + bn.eps)
    s = bn.weight / sd
    w = conv.weight * s.view(-1, 1, 1, 1)
    b = bn.bias - bn.running_mean * s
fused = fusion.fuse_conv_bn_eval(conv, bn)
  1. 1The pair, both in eval mode.
  2. 2Lines 2 and 3 by hand: s is \(\gamma / \overline{\sigma}\), and b uses \(b\) = 0 because bias=False.
  3. 3The library call asserts eval mode ("Fusion only for eval!"): failure row 1 [8].

During quantization-aware training the batch statistics would make these folded weights change every step, so BN switches to its running statistics after a delay; the schedule and the PyTorch recipe live in Freezing observers and BatchNorm statistics in QAT (Quantization, section 13).

2 LayerNorm and RMSNorm keep their division at runtime

Builds on Pre-LN and Post-LN (The Transformer Block, section 3) and neural network layers (Multilayer Perceptrons (MLP), section 3)

LayerNorm and RMSNorm take their statistics from the token in front of them, so the mean and spread are new for every token and cannot be baked into weights. What can move is the gain: \(\gamma\) multiplies each feature right before the next linear layer, so it folds into that layer's weights as diag(\(\gamma\)) \(W_{\text{in}}\), where diag(\(\gamma\)) is the matrix with \(\gamma\) on its diagonal and \(W_{\text{in}}\) the next layer's weights [6]. \(\beta\) folds into that layer's bias as \(\beta\) \(W_{\text{in}}\). That works only when the norm's output feeds linear layers alone, the Pre-LN case.

3 A few huge features make LLM activations hard to quantize

Builds on the clipping range (Quantization, section 4)

LLM.int8() measured a few huge activation features, the outliers, in language models [4]; earlier work it cites traces them to LayerNorm.

LLM.int8() measurement [4]Result
ModelsGPT-2, Fairseq and GPT-J, 125M to 13B parameters; 8-bit inference on OPT (Meta's open GPT-style LLMs) up to 175B
Outlier sizeup to 20 times the other dimensions
Whereabout 25% of layers at first; all layers from about 6.7B parameters
At 6.7B150,000 outliers per sequence, in only 6 feature dimensions
Zeroing themperplexity (how surprised the model is by real text, lower is better) rises 600 to 1000%

One outlier channel stretches the range for the whole activation tensor, so every other channel gets only a few of the 256 levels. Why not give each activation channel its own scale, like the per-channel weight scales in Quantization? Per-channel activation scales do not map well to hardware-accelerated matrix-multiply (GEMM) kernels [5].

3.1 SmoothQuant moves the outlier size into the weights

Weights are easy to quantize and activations are not, so shift part of the size to the weights and fold the division into the LayerNorm gain from Section 2. Take a few tokens shaped like an OPT layer's input, entering a linear layer, with one input channel standing for an outlier channel (real outliers are about 100 times larger than most activations [5]). With one int8 range for the whole activation tensor, the other channels use only a few of the 256 levels.

Divide each activation channel by a factor and multiply its weight row by the same factor.

SmoothQuant: divide the activations, multiply the weights
\(\displaystyle Y = (\htmlStyle{color:#2471a3}{X} \operatorname{diag}(\htmlStyle{color:#7d3c98}{s})^{-1}) (\operatorname{diag}(\htmlStyle{color:#7d3c98}{s}) W)\)
\(X\) holds the tokens' activations, \(W\) the layer's weights and \(Y\) its output. \(\operatorname{diag}(s)\) is the matrix with \(s\) on its diagonal: divide input channel \(j\) by \(s_{j}\), multiply weight row \(j\) by the same \(s_{j}\), and the product does not change, as Figure 3 shows: the output does not change.
\(\displaystyle \htmlStyle{color:#7d3c98}{s_{j}} = \frac{\max \lvert \htmlStyle{color:#2471a3}{X_{j}} \rvert^{\alpha}}{\max \lvert W_{j} \rvert^{1 - \alpha}}\)
\(\alpha\) (alpha), the migration strength, sets how much of the size moves to the weights. With \(\alpha\) = 0.5, channel 1's activation max and its weight row max become equal: the two share the difficulty.

Term by term, \(\operatorname{diag}(s)^{-1}\) shrinks the outlier channel, so the other channels rise from a few levels to many; \(\operatorname{diag}(s)\) grows the matching weights, so the smaller weight rows now use fewer levels. The difficulty is split, not removed. Because \(X\) comes out of a LayerNorm, the division by \(s\) folds offline into that LayerNorm's \(\gamma\) and \(\beta\), so no extra operation runs [5], the same gain-folding move as Section 2. Slide \(\alpha\) to move the difficulty:

The dashed ticks ② mark the levels before smoothing. At \(\alpha\) = 0 the factor comes from the weights alone, so both activation channels shrink together and their levels stay at ②. In PyTorch, smoothing one LayerNorm and linear pair from recorded activations:

import torch
from torch import nn

ln, lin = nn.LayerNorm(2), nn.Linear(2, 2, bias=False)
acts = torch.tensor([[64., 1.], [-60., 2.]])
x_max = acts.abs().amax(0)
w_max = lin.weight.abs().amax(0)
alpha = 0.5
s = x_max**alpha / w_max**(1 - alpha)
with torch.no_grad():
    ln.weight.div_(s)
    ln.bias.div_(s)
    lin.weight.mul_(s)
  1. 1The pair and acts, the LayerNorm outputs recorded on calibration tokens (Figure 3's \(X\)).
  2. 2Line 2. nn.Linear stores its weight as out × in, so amax(0) gives one max per input channel [7]. The weights here are random, so s differs from Figure 3's.
  3. 3Line 1, folded into LayerNorm's \(\gamma\) and \(\beta\); mul_(s) broadcasts \(s\) along the input dimension.

5 Folding and smoothing in practice

BN folding has no knob. SmoothQuant has one:

KnobDefaultWhat it does
\(\alpha\), migration strength0.5larger \(\alpha\) moves more of the outlier's size into the weights (Figure 4); SmoothQuant uses 0.5 for all OPT and BLOOM (BigScience's open multilingual LLM) models and a larger \(\alpha\) such as 0.75 when activation outliers are more significant [5]

When accuracy still drops after folding and smoothing, Debugging a Quantized Model shows how to measure where the error comes from.
