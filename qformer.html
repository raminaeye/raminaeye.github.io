From BLIP to the Q-Former

This page follows Cross-Attention.

From that page, each token (a word piece or an image patch, as a vector) makes a query, a key and a value. In cross-attention the queries come from one stream and the keys and values from another, so the output has one row per query, and with learned queries (a fixed table of vectors trained like weights) the output size is fixed whatever the input. A block is attention then a feed-forward network (FFN) applied to each token alone, and a mask blocks chosen query and key pairs.

Attention with the inputs split: stream A asks, stream B answers.
CrossAttn(XA, XB) = softmax((XAWQ)(XBWK)T√dk)(XBWV)
Queries come from stream XA (n rows), keys and values from stream XB (m rows), each through its learned matrix W, so the output keeps A's n rows, built from B's content.

Here, how BLIP (Bootstrapping Language-Image Pre-training) taught one model to match, compare and caption images, and how BLIP-2's Q-Former reuses that recipe so a frozen language model can read a frozen image model.

One text model, three jobs, almost all weights shared

BLIP (Li et al. 2022) learns from images paired with captions using one multimodal mixture of encoder-decoder (MED): a ViT (vision transformer, an image cut into square patches, each patch a token) reads the image, and one BERT-style text Transformer runs in three modes, each trained with its own loss.

  • Unimodal encoder, trained with the image-text contrastive loss (ITC): image and text are encoded separately, and a matched pair is pulled together while the batch's mismatched pairs are pushed apart. The text starts with a [CLS] token that summarizes the sentence.
  • Image-grounded text encoder, trained with the image-text matching loss (ITM): one cross-attention layer is inserted in every block, between self-attention and the FFN, so text reads the image; a linear head says matched or not, trained on hard negatives (mismatched pairs that score similar).
  • Image-grounded text decoder, trained with the language modeling loss (LM): the same stack with bi-directional self-attention (every token sees every token) replaced by causal self-attention (each token sees only earlier ones), so it writes the caption word by word.

The sharing is deliberate: the paper argues encoding and decoding differ most in self-attention, while the embeddings, cross-attention and FFNs do similar work in both, and in its comparison sharing everything except self-attention beat sharing all layers or none. Each image-caption pair costs one pass through the heavy image encoder and three through the text Transformer. 

# a toy sketch of BLIP's three passes, not the paper's code
img = vit(image)                                    # (B, 1 + patches, d): one pass, reused three times
t_cls = text_model(text, mode="text")               # ITC: [CLS] + text, bi self-attention, cross-attention skipped
t_enc = text_model(text, img, mode="multimodal")    # ITM: [Encode] + text, bi self-attention + cross-attention to img
logits = text_decoder(text, img)                    # LM: [Decode] + text, its own causal self-attention,
                                                    #     the encoder's cross-attention and FFN weights

The model cleans its own captions

Web captions (alt-text scraped with the image) often do not describe the picture. BLIP's CapFilt (captioning and filtering) uses two copies of the pre-trained MED, each fine-tuned on the human-written COCO captions, to clean them.

  • The captioner is the decoder mode, fine-tuned with LM. It writes one synthetic caption per web image, sampled with nucleus sampling (picking each word from the most likely words that cover 90% of the probability), which gives more varied captions than always taking the top word.
  • The filter is the image-grounded encoder mode, fine-tuned with ITC and ITM. It drops any web or synthetic caption that its ITM head calls unmatched.

BLIP-2 (Li et al. 2023) keeps the three objectives: ITC, ITM, and ITG (image-grounded text generation, its name for the captioning loss). It also keeps BLIP's 129M training images and cleans their captions the CapFilt way. What changes is that the image encoder and the language model are both frozen, and 32 learned queries sit between them.

Two frozen models need a small trainable bridge

Strong image encoders and large language models (LLMs, trained on huge amounts of text to predict the next token) already exist. BLIP-2 (Li et al. 2023) keeps both frozen, never updating their weights, to save compute and avoid catastrophic forgetting, where new training wipes out what a model knew. Its image encoder is a ViT, and a small trained module must turn its features into input the LLM can use.

Inside the Q-Former, 32 learned queries read the image

The green box is the Q-Former (Querying Transformer), the learned-query idea applied. It holds 32 learned queries of size 768 and two Transformer halves that share only their self-attention layers.

  • An image side, where the queries live. Only the queries read the frozen image features, through cross-attention inserted every other block.
  • A text side that can act as an encoder (reads a caption) or as a decoder (writes one).
  • It starts from the pretrained weights of BERT-base, a 12-layer text Transformer 768 wide; the cross-attention layers start random. Counting the queries as parameters, it has 188M.

One block as a toy sketch, not BLIP-2's code, without LayerNorms and dropout; its mask allowed comes from One set of weights learns three jobs from three masks. 

import torch, torch.nn as nn
class QFormerBlockSketch(nn.Module):                  # a sketch, not the paper's code
    def __init__(self, idx, d=768, h=12):
        super().__init__()
        self.self_attn = nn.MultiheadAttention(d, h, batch_first=True)   # shared by queries and text
        self.cross = nn.MultiheadAttention(d, h, kdim=1024, vdim=1024, batch_first=True) if idx % 2 == 0 else None
        self.ffn_q, self.ffn_t = [nn.Sequential(nn.Linear(d, 3072), nn.ReLU(), nn.Linear(3072, d)) for _ in range(2)]
    def forward(self, x, img, allowed):               # x: (B, 32 + T, 768), img: (B, 257, 1024), allowed: (32 + T, 32 + T)
        x = x + self.self_attn(x, x, x, attn_mask=~allowed)[0]   # nn.MultiheadAttention reads True as BLOCKED, so pass ~allowed
        q, t = x[:, :32], x[:, 32:]                   # query rows, text rows
        if self.cross is not None: q = q + self.cross(q, img, img)[0]   # only the queries read the image: (B, 32, 768)
        return torch.cat([q + self.ffn_q(q), t + self.ffn_t(t)], dim=1)   # separate FFNs, (B, 32 + T, 768)

The paper states the point directly: the Q-Former "extracts a fixed number of output features from the image encoder, independent of input image resolution." With 14-pixel patches, the number of image features follows the image size.

How many feature vectors a ViT with 14-pixel patches gives for a square image P pixels wide.
N = (P14)2 + 1
P14 patches per side, squared, plus one summary vector: N = 257 at the 224 px of pre-training, 677 at 364 px and 1,226 at 490 px, the sizes the paper fine-tunes at. The Q-Former output stays 32 by 768 for all three.

One set of weights learns three jobs from three masks

Stage one trains the Q-Former with the frozen image encoder only, on BLIP's three objectives at once, each with its own mask between queries and text:

  • Contrastive (ITC): pull an image and its own caption together and push the batch's other captions away (a contrastive loss with in-batch negatives, where BLIP kept a queue of past examples). Queries and text cannot see each other, so neither side can copy.
  • Generation (ITG): write the caption from the queries. Queries see only queries; each text token sees all queries and the earlier text, so the queries must carry everything the caption needs.
  • Matching (ITM): say whether an image and a caption belong together, trained with mismatched pairs that look similar. Everything sees everything.

For the contrastive score, the text's first token is a summary token whose output t stands for the caption, and t is compared with each of the 32 query outputs.

The contrastive similarity between an image and a caption.
s(I, T) = maxi sim(zi, t)
sim compares query output zi with the summary t (both projected to length 1, then dotted); maxi keeps the best of the 32, so queries can specialize in different image parts.

The three masks over 32 queries and T text tokens, as boolean grids:

import torch
Nq, T = 32, 6                                         # 32 queries, T text tokens
N = Nq + T                                            # rows look, columns are seen
is_q = torch.arange(N) < Nq                           # (N,), True at query positions
allowed_match = torch.ones(N, N, dtype=torch.bool)    # Matching: everyone sees everyone
allowed_contrast = is_q[:, None] == is_q[None, :]     # Contrastive: each side sees only itself
earlier = torch.tril(torch.ones(N, N)).bool()         # column index <= row index
allowed_gen = (allowed_contrast | ~is_q[:, None]) & (is_q[None, :] | earlier)   # Generation
# convention here: True = allowed; nn.MultiheadAttention wants True = blocked, so the block passes ~allowed

The mask decides the job.

The second stage feeds the language model soft prompts

Stage two connects the Q-Former output Z (32 by 768) to a frozen LLM. One fully connected layer projects each vector to the LLM's embedding size, and the 32 results go in front of the text's token embeddings as soft visual prompts, vectors that act like extra words. Only the Q-Former and the projection train.

OPT, a decoder-only LLM, trains with the plain next-token loss L. FlanT5, an encoder-decoder, trains with a prefix loss: the caption's first part goes into the encoder with the prompts, and the decoder writes the rest.

The decoder-only (OPT) loss: predict each caption token, with the 32 prompts in front.
L = −1T∑t=1T log P(wt | p1, …, p32, w<t)
−log of the probability the LLM gives each true caption token wt, given the prompts p1 to p32 and earlier tokens, averaged over T; the LLM is frozen, so only better prompts lower L.
# llm: a frozen decoder-only LLM with a Hugging Face style interface; Z: the Q-Former output
proj = nn.Linear(768, llm.config.hidden_size)            # trains: 768 to the LLM's width
llm.requires_grad_(False)                                # frozen: no weight updates (gradients still flow through)
prompts = proj(Z)                                        # Z: (B, 32, 768) to (B, 32, d_llm)
emb = llm.get_input_embeddings()(text_ids)               # (B, T, d_llm)
labels = text_ids.masked_fill(text_ids == pad_id, -100)  # -100 = no loss here
labels = torch.cat([torch.full((B, 32), -100), labels], dim=1)            # no loss on the 32 prompt slots
loss = llm(inputs_embeds=torch.cat([prompts, emb], dim=1), labels=labels).loss   # (B, 32 + T) positions

Frozen means requires_grad_(False), not torch.no_grad(): the LLM's weights stay fixed, but gradients must still flow back through it to the projection and the Q-Former.

A small bridge beats an 80B model on image questions

The setup comes first.

  • Data: BLIP's 129M images with captions from public datasets, plus CapFilt-style synthetic captions: the BLIP-large captioner writes captions, a CLIP ViT-L/14 model ranks them with the web caption by image-text similarity, and the top two per image are kept.
  • Frozen image encoders: two pretrained ViTs, ViT-L/14 from CLIP and ViT-g/14 from EVA-CLIP, using the features of their second-to-last layer.
  • Frozen LLMs: OPT and FlanT5 models of several sizes.
  • Training: 250k steps in stage 1 and 80k in stage 2; the largest model (ViT-g with FlanT5-XXL) took under 6 days for stage 1 and under 3 days for stage 2 on one machine with 16 A100 (40GB) GPUs.

The test is zero-shot visual question answering (VQA): answer a question about an image, with no training on that benchmark's examples. VQAv2 is a standard set of such questions, scored by accuracy.

  • The comparison model, Flamingo80B, is an earlier image-and-language model with 80B parameters in total, of which 10.2B train.
  • The 188M is the whole Q-Former, as in the abstract's 54 times; the paper's VQA table lists 108M trainable (12.1B in total) for the exact model that scores 65.0, ViT-g with FlanT5-XXL.
  • Without stage 1, zero-shot VQA is much lower for both kinds of LLM, and the OPT model gets worse as training goes on: catastrophic forgetting. The bridge alone is not enough.
  • On OK-VQA, questions that need outside knowledge, Flamingo80B leads, 50.6 against 45.9. The authors guess this comes from its 70B language model against FlanT5-XXL's 11B.

Where the bridge falls short

The paper names three limits.

  • A few solved examples in the prompt do not improve VQA answers; the authors blame training data with one image-text pair per sample.
  • Answers can be wrong because of the LLM's inaccurate knowledge, a wrong line of reasoning, or out-of-date information.
  • A frozen LLM brings its own risks, such as offensive output, social bias, or leaking private information.
