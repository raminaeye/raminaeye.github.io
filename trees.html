Decision Trees

A decision tree classifies a point by asking yes-or-no questions about its features, one threshold at a time.

1 How a decision tree classifies a point

The running example is the UCI smartphone activity dataset (Anguita et al., 2013): a phone on the waist records short windows of motion, and each window is labelled with what the person was doing. A tree asks one question per node, such as "does the phone shake only a little?", sends the window left or right by the answer, and the leaf it lands in calls the class most common among its training windows.

Logistic regression draws one straight boundary through feature space (The decision boundary). A tree instead carves the space into boxes, one threshold at a time, so it handles sharp thresholds and mixed feature types and needs no feature scaling.

A tree is grown once on the training set, top down. Prediction walks one path from the root to a leaf. Growing a balanced tree costs about \(O(N\,d\,\log N)\) for \(N\) windows and \(d\) features with scikit-learn’s presorting cache (scikit-learn User Guide, Complexity). After training the tree is a fixed set of questions; it carries no other state.

2 Impurity and information gain

A good question leaves each side as pure as possible. In Figure 2 both cuts split eight windows in half, but only one of them separates the classes.

Impurity scores how mixed a group is. Take the root of Figure 1: below the threshold the windows are mostly still, above it mostly moving, so the cut lowers the impurity a lot. The card below turns that into a score.

Builds on surprise and entropy (KL Divergence)

A split is worth making when the groups it leaves are much purer than the group it started from; the gain counts how much purer.
\(\displaystyle \begin{aligned} \htmlStyle{color:#1f618d}{\Delta I} &= I(\text{parent}) \\ &\quad - \htmlStyle{color:#117a65}{I_{\text{children}}} \end{aligned}\)
The gain \(\Delta I\) is the impurity before the cut minus the impurity after it; with entropy as the impurity it is called the information gain. The tree keeps the cut with the largest gain, and a cut that separates nothing gains nothing.
\(\displaystyle \htmlStyle{color:#117a65}{I_{\text{children}}} = \sum_{c} \frac{N_c}{N}\, \htmlStyle{color:#1f618d}{I(c)}\)
Each child \(c\) holds \(N_c\) of the \(N\) windows, and its impurity \(I(c)\) counts in proportion to that share. A tiny pure child cannot hide a large mixed one. This is the "after" term of line 1.
\(\displaystyle \htmlStyle{color:#1f618d}{I_{\text{entropy}}} = -\sum_{k} \htmlClass{eqt sym-prob}{\htmlStyle{color:var(--sym-prob)}{p_k}} \log_2 \htmlClass{eqt sym-prob}{\htmlStyle{color:var(--sym-prob)}{p_k}}\)
\(p_k\) is the share of class \(k\) in the node. \(-\log_2 p_k\) is the surprise of meeting class \(k\), large for a rare class, and entropy is the average surprise: zero for a pure node and largest when the classes are evenly mixed.
\(\displaystyle \htmlStyle{color:#1f618d}{I_{\text{Gini}}} = 1 - \sum_{k} \htmlClass{eqt sym-prob}{\htmlStyle{color:var(--sym-prob)}{p_k}}^{2}\)
Gini is the chance that two windows drawn from the node disagree. It is also zero when pure and needs no logarithm. The two measures usually pick the same cut or nearly the same one, as Tool 1 shows on these windows.
So the tree scores every candidate cut by the drop from the parent’s impurity to the children’s weighted impurity, and keeps the largest drop. Section 3 repeats that choice at every node.

The split search in NumPy; f and 1 - f are the two children’s shares. The Decision_tree notebook in the Machine-Learning-Concepts repo searches splits the same way.

import numpy as np

def gini(y):
    p = np.bincount(y) / len(y)
    return 1 - (p ** 2).sum()

def splits(X):
    for j in range(X.shape[1]):
        vals = np.unique(X[:, j])
        for thr in vals[:-1]:
            yield j, thr

def best_split(X, y):
    best = (0.0, None, None)
    for j, thr in splits(X):
        left = X[:, j] <= thr
        f = left.mean()
        gl = gini(y[left])
        gr = gini(y[~left])
        kids = f*gl + (1-f)*gr
        gain = gini(y) - kids
        if gain > best[0]:
            best = (gain, j, thr)
    return best

  2. 2Tries every feature and every threshold between observed values.
  3. 3Weighted impurity of the two children, line 2.
  4. 4Keeps the cut with the largest drop, line 1.

3 Growing a tree greedily

The tree finds the best cut at the root, splits the windows, and repeats the same search inside each side. It stops when a node reaches a maximum depth, holds too few windows, or is already pure. The growth is greedy: each node keeps its own best cut, and earlier cuts are never revisited, even if a different first question would have led to a better tree.

The leaf rule: each leaf calls its most common class, the class \(k\) with the largest share \(p_k\).

4 Regression trees: leaves that predict a number

The trees inside gradient boosting predict a number for each window: how far its current prediction is from the truth (Residuals). A tree whose leaves predict numbers is a regression tree. It is grown the same way; only the leaf rule and the impurity change.

A leaf either names a class or states a number, and the impurity for numbers is the spread around that number.
\(\displaystyle \hat{y}_{\text{leaf}} = \arg\max_k \; \htmlClass{eqt sym-prob}{\htmlStyle{color:var(--sym-prob)}{p_k}}\)
A classification leaf calls its most common class, the \(k\) with the largest share \(p_k\).
\(\displaystyle \hat{y}_{\text{leaf}} = \htmlClass{eqt sym-target}{\htmlStyle{color:var(--sym-target)}{\bar{y}_{\text{leaf}}}}\)
A regression leaf states the mean target \(\bar{y}_{\text{leaf}}\) of its windows. In boosting the target is the leftover error, so the leaf states its windows’ average leftover error.
\(\displaystyle \htmlStyle{color:#1f618d}{I_{\text{MSE}}(c)} = \frac{1}{N_c} \sum_{i \in c} \left(\htmlClass{eqt sym-target}{\htmlStyle{color:var(--sym-target)}{y_i}} - \htmlClass{eqt sym-target}{\htmlStyle{color:var(--sym-target)}{\bar{y}_c}}\right)^2\)
For numbers, impurity is the spread of the targets \(y_i\) around the node’s mean \(\bar{y}_c\): the mean squared error of predicting that mean (The mean squared error cost). It is zero when every window in the node has the same target.
So a regression tree swaps the impurity of Section 2, line 3 or 4, for this spread and plugs it into Section 2, lines 1 and 2; the best cut is the one that makes each side’s targets most alike, and each leaf says its mean.

In scikit-learn that tree is one line, the call the boosting page uses on its residuals r: DecisionTreeRegressor(max_depth=MAX_DEPTH).fit(X, r).

5 When a tree memorizes, and pruning

Grown until every leaf is pure, a tree gives stray windows boxes of their own. It fits the training windows perfectly and new windows worse, the high-variance end of the capacity curve (Bias, variance and learning curves). Capping the depth or the leaf size stops growth early, the simplest fix. Cost-complexity pruning instead grows the full tree and then removes the branches that do not earn their leaves.

Pruning charges a price for every leaf, so a branch survives only if it fits the training windows well enough to pay for its leaves.
\(\displaystyle R_{\htmlStyle{color:#b9770e}{\alpha}}(T) = R(T) + \htmlStyle{color:#b9770e}{\alpha}\,\htmlStyle{color:#117a65}{\lvert \tilde{T} \rvert}\)
\(T\) is the tree being pruned. \(R(T)\) measures how badly its leaves fit the training windows (scikit-learn uses their total impurity; CART used the training misclassifications), and \(\lvert\tilde{T}\rvert\) is its number of leaves. \(\alpha\) is the price per leaf: at zero the full tree is kept, raising it removes branches whose fit does not pay for their leaves, and a very large price leaves only the root. scikit-learn calls it ccp_alpha, default 0.
So pruning trades fit for size with one knob; each value of the price picks one subtree of the full tree, and the held-out windows decide which price is best.

The same search in scikit-learn: compute the sequence of prices, fit one tree per price, and keep the one that scores best on validation windows.

from sklearn.tree import DecisionTreeClassifier as Tree
from sklearn.tree import export_text
path = Tree(random_state=SEED).cost_complexity_pruning_path(X_tr, y_tr)
alphas = path.ccp_alphas
trees = [Tree(random_state=SEED, ccp_alpha=a).fit(X_tr, y_tr) for a in alphas]
scores = [t.score(X_val, y_val) for t in trees]
best = trees[scores.index(max(scores))]
names = ["shake", "tilt"]
rules = export_text(best, feature_names=names)

6 Where trees break

Trees suit tabular data with mixed feature types, need no scaling, and can be read as rules. Their cuts are always parallel to one feature axis, which Figure 7 shows on a diagonal boundary.

CauseSymptomFix
a deep tree memorized the noiseTrain accuracy near perfect, held-out lowerprune with \(\alpha\) or cap the depth (Section 5); depth limits are regularization for trees
every split tests one featureStaircase boundary on a diagonaladd a combined feature, such as the sum of the two, or use a linear model
greedy splits score one feature at a time, and in an XOR pattern neither helps aloneNo useful first split; the pattern is missedgrow deeper, or use an ensemble so later splits can pick it up
a leaf can only repeat values it sawFlat predictions past the training rangea model with a trend when you must extrapolate
a small change in the training windowsA very different tree (instability)average many trees (Random Forests)
  • Cap the depth or prune before trusting one tree.
  • Set min_samples_leaf so no leaf rests on one stray window.
  • Read the fitted tree with export_text; a readable model is the main reason to choose a single tree.
  • Impurity-based feature_importances_ favour features with many distinct values; prefer permutation importance on held-out data.

7 Trees as building blocks

One tree is unstable and its boundary is coarse. Combining many trees fixes both, in two different ways (Figure 8).

Random ForestsMany deep trees grown side by side on resampled windows vote; their quirks average away. Gradient BoostingSmall trees added one at a time, each fitting what is still wrong.

XGBoost and LightGBM, the boosting libraries most people run, are on XGBoost and LightGBM.

If one tree changes so much when a few windows change, what happens if we grow many trees on slightly different windows and let them vote? That is Random Forests. A different kind of boundary, one wide-margin cut instead of many axis-parallel ones, is Support Vector Machines (SVM).
