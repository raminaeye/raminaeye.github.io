This page builds on RL Basics. Here is what it taught, in the words this page keeps using.

  • An agent acts in a world. In each state \(s\) it makes a move, or action, \(a\), and the world hands back a reward \(r\), good or bad, and the next state (Agent, world, state, move, reward).
  • An episode is one run from the start until it ends. The return \(G_t\) adds up every reward still to come (Episodes and the return), with later rewards shrunk by the discount \(\gamma\) (Discounting).
  • A policy \(\pi\) is the agent’s rule for choosing a move in each state (The policy).
  • A move’s value \(Q(s,a)\) is the return the agent expects if it makes move \(a\) in state \(s\) and plays on from there. \(\arg\max\) picks the move whose value is largest (The value of a move).
  • Epsilon-greedy usually makes the move with the highest value and, with a small chance \(\varepsilon\), a random one instead, so the agent keeps exploring (Explore or exploit).

RL Basics left one question open. In its game level the move values were worked out for you, from a level whose layout was known. A real agent is not told the layout. This page builds Q-learning, the classic way an agent learns its move values from its own tries, one idea at a time.

1 The warehouse floor

One example carries the whole page. A warehouse robot has to drive from its start to its charging dock. The floor is a grid of squares, four deep and twelve wide. The robot starts in the bottom left corner and the dock sits in the bottom right. Between them, along the bottom row, runs a ledge: a loading edge the robot can drive off.

Each square is a state, and in every square the robot has four moves: up, right, down and left. Driving into the outer wall leaves it where it was. Every move uses a little battery. Stepping onto the ledge uses a lot of battery and puts the robot back at the start, and the episode goes on. Only reaching the dock ends the episode.

Each move’s reward is minus the battery it uses, so the best return is the one closest to zero. The cheapest way to the dock is the shortest path that never steps onto the ledge. Reaching the dock can take many moves.

This floor is Cliff Walking, a standard test world from Sutton and Barto’s textbook; they call the ledge the cliff and the dock the goal, and the Gymnasium library ships it ready to use. A real warehouse robot has far more squares, but the same problem: nobody hands it the best route, so it has to learn one from its own driving.

2 A table of move values

In RL Basics a state’s value \(V(s)\) said how good it is to stand on a square. To choose a move with it, the robot would have to look one move ahead: which square does each move lead to, and how good is that square? That needs a map of where every move leads, and the robot has none.

A move’s value skips the look-ahead. It rates each move in each square directly, so choosing is just picking the move with the largest value, the \(\arg\max\) from RL Basics. So the robot keeps a Q-table. A Q-table keeps one move value for every state and move: one row per square, one entry per move.

On this floor every reward is minus some battery, so every move value is minus the battery the robot still expects to spend. The figures on this page draw that battery as a purple bar. The longer the bar, the lower the value, and the best move is the one with the shortest bar.

2.1 Why the robot cannot work them out

If the robot knew the right values, it would simply play the shortest bar everywhere. But at the start its table is only guesses. Could it compute the right values instead? RL Basics defined a move’s value as an average of returns.

\(\displaystyle \begin{aligned} \htmlClass{eqt}{\htmlStyle{color:#8e44ad}{Q_{\pi}}}(\htmlClass{eqt}{\htmlStyle{color:#2471a3}{s}}, \htmlClass{eqt}{\htmlStyle{color:#a04000}{a}}) &= \mathbb{E}_{\htmlClass{eqt}{\htmlStyle{color:#0e6b59}{\pi}}}\big[\, \htmlClass{eqt}{\htmlStyle{color:#8e44ad}{G_t}} \mid \\ &\quad \htmlClass{eqt}{\htmlStyle{color:#2471a3}{s_t}} = \htmlClass{eqt}{\htmlStyle{color:#2471a3}{s}},\ \htmlClass{eqt}{\htmlStyle{color:#a04000}{a_t}} = \htmlClass{eqt}{\htmlStyle{color:#a04000}{a}} \,\big] \end{aligned}\)
RL Basics defined the value of move \(a\) in square \(s\) as the average, \(\mathbb{E}\), of the return \(G_t\) that follows it when the robot then plays by its policy \(\pi\). There are two ways to get that average, and the robot has neither. It could work it out from a map of where every move leads and what it costs, which it is not given. Or it could drive many whole episodes from every square and move and average their returns, but a return is known only once its episode is over, and early on an episode can wander for a very long time before it finds the dock.

So the robot has to fill in its table from its own moves, while it is still driving. The next idea is how one single move can already teach it something.

3 Learning from one step

Waiting for the end of an episode is slow, and after every single move the robot already has two new facts: the step’s reward, and the square it landed on, whose row in the table holds guesses of its own.

3.1 The target

RL Basics split the return into two parts: the next reward, plus the discounted return from one step later (Discounting). After a move, the first part is known; the robot just received it. The second part is not, because the episode has not finished. But the table holds a guess for it. If the robot plays its best from the next square on, the return from there is about the largest move value in that square’s row.

\(\displaystyle \htmlClass{eqt}{\htmlStyle{color:#8e44ad}{G_t}} = \htmlClass{eqt}{\htmlStyle{color:#7d6608}{r_{t+1}}} + \htmlClass{eqt}{\htmlStyle{color:#2c3e50}{\gamma}}\, \htmlClass{eqt}{\htmlStyle{color:#8e44ad}{G_{t+1}}}\)
The return from RL Basics, read one step at a time: the step’s reward \(r_{t+1}\), plus the return from the next step on, \(G_{t+1}\), shrunk once by the discount \(\gamma\). The robot knows \(r_{t+1}\) the moment its move is made. \(G_{t+1}\) is known only when the episode ends.
\(\displaystyle \htmlClass{eqt}{\htmlStyle{color:#196f3d}{y_t}} = \htmlClass{eqt}{\htmlStyle{color:#7d6608}{r_{t+1}}} + \htmlClass{eqt}{\htmlStyle{color:#2c3e50}{\gamma}} \max_{\htmlClass{eqt}{\htmlStyle{color:#a04000}{a}}} \htmlClass{eqt}{\htmlStyle{color:#8e44ad}{Q}}(\htmlClass{eqt}{\htmlStyle{color:#2471a3}{s_{t+1}}}, \htmlClass{eqt}{\htmlStyle{color:#a04000}{a}})\)
The target \(y_t\) swaps the unknown rest of the return for the table’s own guess. \(s_{t+1}\) is the square the move landed on, and \(\max_a\) takes the largest of its move values: the value of the best move from there, the shortest bar in Figure 4. So Q-learning’s target is the step’s reward plus the discounted best move value in the next state. It is grounded in one real reward, the step’s, so on average it moves the entry the right way. On this floor every episode ends at the dock, so \(\gamma\) can be set to one and the target is simply the step’s battery plus the best next bar.
\(\displaystyle \htmlClass{eqt}{\htmlStyle{color:#196f3d}{y_t}} = \htmlClass{eqt}{\htmlStyle{color:#7d6608}{r_{t+1}}} \quad \text{at the dock}\)
When the move reaches the dock the episode is over and nothing comes after it, so the target is the step’s reward alone.

3.2 The TD error

The target and the table’s entry are two guesses at the same move value, one made before the move and one made just after it. Their difference, the TD error, says how surprised the robot should be. TD stands for temporal difference, a difference between two guesses made one time step apart.

\(\displaystyle \htmlClass{eqt}{\htmlStyle{color:#b03a2e}{\delta_t}} = \htmlClass{eqt}{\htmlStyle{color:#196f3d}{y_t}} - \htmlClass{eqt}{\htmlStyle{color:#8e44ad}{Q}}(\htmlClass{eqt}{\htmlStyle{color:#2471a3}{s_t}}, \htmlClass{eqt}{\htmlStyle{color:#a04000}{a_t}})\)
\(\delta_t\) (the Greek letter delta) is the TD error, the target minus the table’s guess for the move \(a_t\) just made in square \(s_t\). When \(\delta_t\) is zero the move went exactly as the table expected. When it is below zero the move turned out worse than expected, a longer bar, as in both rows of Figure 5; above zero, better. On this floor the biggest surprise is a fall, where a step expected to cost a little costs a lot.

4 The learning rate

Should the robot simply replace its entry with the target? A target comes from one single move, and it leans on the next square’s entries, which are still guesses too. In many worlds the same move can also turn out differently from one try to the next: a wheel slips, a box is in the way. Copying each new target over the old entry would let one odd step wipe out everything learned before. So the robot moves its entry only part of the way.

\(\displaystyle \text{new guess} = \text{old guess} + \htmlClass{eqt}{\htmlStyle{color:#2c3e50}{\eta}}\,(\text{target} - \text{old guess})\)
\(\eta\) (the Greek letter eta) is the learning rate, a number between zero and one that sets the size of each nudge. The bracket is the gap between the target and the old guess. With \(\eta\) near zero the guess barely moves; with \(\eta\) equal to one it jumps all the way to the target and forgets the past. In between it moves that share of the gap, so over many visits the entry settles near the average of its targets, and no single odd step can drag it far.

5 The update rule

Now the pieces join into one rule. After every move the robot works out the target, takes the TD error, and nudges the entry for the move it just made by the learning rate times that error.

\(\displaystyle \htmlClass{eqt}{\htmlStyle{color:#8e44ad}{Q}}(\htmlClass{eqt}{\htmlStyle{color:#2471a3}{s_t}}, \htmlClass{eqt}{\htmlStyle{color:#a04000}{a_t}}) \leftarrow \htmlClass{eqt}{\htmlStyle{color:#8e44ad}{Q}}(\htmlClass{eqt}{\htmlStyle{color:#2471a3}{s_t}}, \htmlClass{eqt}{\htmlStyle{color:#a04000}{a_t}}) + \htmlClass{eqt}{\htmlStyle{color:#2c3e50}{\eta}}\, \htmlClass{eqt}{\htmlStyle{color:#b03a2e}{\delta_t}}\)
The arrow \(\leftarrow\) means replace. The table entry for the move just made, in the square it was made in, becomes its old value plus the learning rate \(\eta\) times the TD error \(\delta_t\). It is the nudge card above, with the table entry as the guess.
\(\displaystyle \begin{aligned} &\htmlClass{eqt}{\htmlStyle{color:#8e44ad}{Q}}(\htmlClass{eqt}{\htmlStyle{color:#2471a3}{s_t}}, \htmlClass{eqt}{\htmlStyle{color:#a04000}{a_t}}) \leftarrow \htmlClass{eqt}{\htmlStyle{color:#8e44ad}{Q}}(\htmlClass{eqt}{\htmlStyle{color:#2471a3}{s_t}}, \htmlClass{eqt}{\htmlStyle{color:#a04000}{a_t}}) \\ &\quad + \htmlClass{eqt}{\htmlStyle{color:#2c3e50}{\eta}}\, \big[\, \htmlClass{eqt}{\htmlStyle{color:#7d6608}{r_{t+1}}} \\ &\qquad + \htmlClass{eqt}{\htmlStyle{color:#2c3e50}{\gamma}} \max_{\htmlClass{eqt}{\htmlStyle{color:#a04000}{a}}} \htmlClass{eqt}{\htmlStyle{color:#8e44ad}{Q}}(\htmlClass{eqt}{\htmlStyle{color:#2471a3}{s_{t+1}}}, \htmlClass{eqt}{\htmlStyle{color:#a04000}{a}}) \\ &\qquad - \htmlClass{eqt}{\htmlStyle{color:#8e44ad}{Q}}(\htmlClass{eqt}{\htmlStyle{color:#2471a3}{s_t}}, \htmlClass{eqt}{\htmlStyle{color:#a04000}{a_t}}) \,\big] \end{aligned}\)
The same rule with the TD error written out. Inside the brackets is the target, the step’s reward plus the discounted best move value in the next square, minus the old entry. This is the Q-learning update. At the dock the \(\max\) term is left out, because nothing comes after.

Each move changes only one entry, the one the robot just played. While the move values are still guesses, the best entry can point the wrong way, and the next steps correct it.

6 Learning best play while exploring

The robot explores. With chance \(\varepsilon\) it makes a random move, and near the ledge a random move can mean a fall. Does that mean the table learns the values of a clumsy robot, one that falls now and then?

6.1 The table learns best play

Look at the target again. Whatever move the robot really makes next, the target uses the best move value in the next square, the \(\max\). So every target describes one move followed by best play from there on, never the random moves the robot may make later. Over many updates the table fills in the values of best play: always making the best move.

The greedy policy plays the top-valued move in each state. It never explores, so it is the robot that always makes the best move.

\(\displaystyle \htmlClass{eqt}{\htmlStyle{color:#0e6b59}{\pi_{\text{greedy}}}}(\htmlClass{eqt}{\htmlStyle{color:#2471a3}{s}}) = \arg\max_{\htmlClass{eqt}{\htmlStyle{color:#a04000}{a}}} \htmlClass{eqt}{\htmlStyle{color:#8e44ad}{Q}}(\htmlClass{eqt}{\htmlStyle{color:#2471a3}{s}}, \htmlClass{eqt}{\htmlStyle{color:#a04000}{a}})\)
The greedy policy \(\pi_{\text{greedy}}\) reads its move straight off the table: in square \(s\), the move \(a\) with the largest value, the shortest bar. Following it from the start traces the dashed route in Figure 7.

So the robot drives epsilon-greedy, falls and all, while its table learns the values of the greedy policy. Learning the values of one policy while playing another is called off-policy learning, and Q-learning is off-policy.

6.2 Where the updates settle

Each update nudges one entry toward its target. When does the nudging stop? The nudge is the learning rate times the TD error, so an entry stops moving once its target, on average, equals the entry itself.

When every entry has settled like this, each entry holds the return of making that move and then playing the greedy policy from there on, the best return the robot can get. These settled values are written \(Q^{*}\), read Q-star.

\(\displaystyle \begin{aligned} &\htmlClass{eqt}{\htmlStyle{color:#8e44ad}{Q^{*}}}(\htmlClass{eqt}{\htmlStyle{color:#2471a3}{s_t}}, \htmlClass{eqt}{\htmlStyle{color:#a04000}{a_t}}) = \mathbb{E}\big[\, \htmlClass{eqt}{\htmlStyle{color:#7d6608}{r_{t+1}}} \\ &\quad + \htmlClass{eqt}{\htmlStyle{color:#2c3e50}{\gamma}} \max_{\htmlClass{eqt}{\htmlStyle{color:#a04000}{a}}} \htmlClass{eqt}{\htmlStyle{color:#8e44ad}{Q^{*}}}(\htmlClass{eqt}{\htmlStyle{color:#2471a3}{s_{t+1}}}, \htmlClass{eqt}{\htmlStyle{color:#a04000}{a}}) \\ &\qquad \mid \htmlClass{eqt}{\htmlStyle{color:#2471a3}{s_t}}, \htmlClass{eqt}{\htmlStyle{color:#a04000}{a_t}} \,\big] \end{aligned}\)
Inside the brackets is Q-learning’s target, built from \(Q^{*}\) itself. The line says each Q-star value equals the average, \(\mathbb{E}\), of its own target, so its TD error is zero on average, as in Figure 8. On this floor a move always turns out the same, so the average is just the one target.

Watkins and Dayan proved that the table reaches \(Q^{*}\) if every move keeps being tried in every square and the learning rate shrinks over time in the right way. The shrinking matters only where a move can turn out differently; on this floor a fixed learning rate is enough.

7 One update, step by step

Here is one turn of the loop from RL Basics (The RL loop), from choosing a move to nudging its bar. Pick a kind of step, then go through it one stage at a time.

8 Q-learning in code

The whole method fits in a few lines on Gymnasium’s Cliff Walking, the floor of this page. First the table and the move choice.

import gymnasium as gym
import numpy as np

# CliffWalking-v1 needs a recent Gymnasium; older versions name it CliffWalking-v0
env = gym.make("CliffWalking-v1")      # the floor: start, ledge, dock
n_states = env.observation_space.n     # one row per square
n_moves = env.action_space.n           # up, right, down, left
Q = np.zeros((n_states, n_moves))      # the Q-table, every entry at zero

GAMMA = 1.0    # every episode ends at the dock, so no discount
LR = 0.5       # the learning rate: the size of each nudge
EPS = 0.1      # the chance of a random, exploring move
rng = np.random.default_rng(0)

def act(s, eps):
    if rng.random() < eps:
        return int(rng.integers(n_moves))   # explore: any move
    return int(np.argmax(Q[s]))             # exploit: the best move by the table
  1. 1Make the floor and an all-zero table with one row per square and one column per move.
  2. 2Set the discount \(\gamma\), the learning rate \(\eta\) and the exploring chance \(\varepsilon\).
  3. 3Epsilon-greedy picks a random move with chance \(\varepsilon\), otherwise the \(\arg\max\) of the square’s row.

Then the loop of RL Basics, with the update rule after every move.

for episode in range(500):
    s, info = env.reset()                    # back to the start square
    terminated = False
    while not terminated:                    # this floor is never cut off
        a = act(s, EPS)
        s_next, r, terminated, truncated, info = env.step(a)
        if terminated:
            y = r                            # at the dock: the step's reward alone
        else:
            y = r + GAMMA * Q[s_next].max()  # the step's reward plus the best next value
        Q[s, a] += LR * (y - Q[s, a])        # nudge the played entry toward the target
        s = s_next
  1. 1Each episode starts at the start square and runs until the dock. terminated is true only at the dock. A fall is an ordinary step, so the episode goes on, and Cliff Walking has no step limit, so truncated never ends it.
  2. 2The target \(y_t\), with the dock case first.
  3. 3The Q-learning update, then move on to the next square.

10 Running it in practice

Q-learning updates after every single move, while the episode is still going. It learns online, from a stream of moves, and never has to store whole episodes or wait for them to end.

Starting every move value at zero is hopeful when every real value is below zero, because moves not yet tried then look best. The greedy choice keeps reaching for moves it has not tried, which is extra exploring for free.

Exploring is needed while the table is wrong, but once it is right every random move near the ledge only risks a fall. So in practice \(\varepsilon\) starts high and shrinks after each episode, down to a minimum.

\(\displaystyle \varepsilon \leftarrow \max\big(\htmlClass{eqt}{\htmlStyle{color:#2c3e50}{\kappa}}\, \varepsilon,\ \varepsilon_{\min}\big)\)
After each episode the exploring chance \(\varepsilon\) is multiplied by \(\kappa\) (the Greek letter kappa), the decay factor, a number just below one, so it shrinks a little every time. The \(\max\) keeps it from dropping below \(\varepsilon_{\min}\), the minimum, so the robot never stops trying moves altogether. When \(\varepsilon\) shrinks like this, the robot’s own driving also ends up on the best route.
EPS, EPS_DECAY, EPS_MIN = 1.0, 0.99, 0.05   # start, kappa, the minimum
# ...run one episode with act(s, EPS), as above, then:
EPS = max(EPS_DECAY * EPS, EPS_MIN)
  1. 1Start fully random, shrink a little per episode, never below the minimum.
  2. 2The card above, once per episode.

Watkins and Dayan (1992)The table reaches the values of best play with probability one in the long run, as long as every move keeps being tried in every state and the learning rate shrinks in the right way. They also sketch the case of worlds with no discount that always end, like this floor.

11 When a table is enough

A table works when every entry can be visited often, since each entry learns only from its own visits.

  • The states and moves can be listed and the table fits in memory: grid worlds like this floor, small board games, a robot whose position is one square of a coarse floor plan.
  • Every state and move gets tried many times, which exploring makes sure of.
  • There is no map of the world to plan with, only the chance to try moves and see what happens.

13 Beyond the table

A table needs a row for every state. A video game seen as screen pixels has more possible screens than any table could hold, and the agent would hardly ever see the same screen twice, so what it learned on one screen would never help on a similar one. Deep Q-Networks (DQN) keep this page’s target and update but swap the table for a neural network that takes the state in and gives a value for every move out, so similar states share what they learn. That is how agents learned to play Atari games from the screen (Mnih and colleagues).

Two relatives start from the same update. SARSA changes one thing in the target: it uses the move the robot really makes next instead of the best one. Double DQN carries the Double Q-learning fix for the max over noisy guesses over to networks.
