Double DQN

Why the max of noisy guesses runs high, and the second opinion that fixes it.

A game-playing network's guesses of how well it will do keep climbing far above how well it really does. Why, and how can one line of the method fix it?

The agent is the learner that picks the moves, as taught in RL Basics. A state is the agent's situation right now; a move, or action, is one choice the agent can make in a state; a reward is the number the world hands back after each move, good or bad, as taught in RL Basics. Here the agent is a game-playing program. It sees only the screen and its points, never the game's rules.

In its games the state is the screen, a move is a joystick press, and the reward is the change in its points. A good press lifts its points at once; a bad one can end the game many presses later.

An episode is one run from the start until it ends, as taught in RL Basics. The games are Atari games, classic home video games played with a joystick. On Atari an episode ends at game over. A game can run for a long time, press after press, before it is over.

Figure 1 shows the game screen the program sees and the bars for the presses it can make. The screen is a Breakout game, rows of blocks above a paddle and a ball, and each bar is one press's score, a taller bar a higher score. Take a screen where the ball drops low: the tallest bar is the press the program plays next.

1 Game-playing networks guess too high

The return is all the reward still to come, with later rewards counted a little less, as taught in RL Basics. A policy is the agent's rule for choosing a move in each state; it may always pick the same move or pick by chance, as taught in RL Basics. On Atari the program cannot see its future points; it has to learn which presses lead to them.

A move's value \(Q(s,a)\), also called its score, is the return the agent expects if it makes move \(a\) in state \(s\) and plays on from there, as taught in RL Basics. A Q-table keeps one score for every state and move, as taught in Q-Learning. A Q-network is a neural network that takes the state and outputs one score per move, in place of the table, as taught in Deep Q-Networks. After training, the program plays the joystick press whose score is highest.

The discount \(\gamma\) sets how much a reward one step later still counts, as taught in RL Basics. Q-learning's target is the step's reward plus the discounted best score in the next state, as taught in Q-Learning. On Atari most presses earn no points at all, so the target is mostly the discounted best next score.

Training a Q-network with Q-learning's target is a Deep Q-Network, DQN for short. DQN pulls each bar toward that target, step after step. Every Atari game ends with a final points total, so the points the program really earns can be counted after play.

On Atari those scores end above the return the learned policy really earns, on some games far above. Double DQN, the method on this page, changes one line of DQN's target to fix this. On Atari, Double DQN's estimates end much closer to the return its policy really earns.

Figure 2 shows DQN's estimate climbing above the return its policy really earns, while Double DQN's estimate settles near its own. The red line is DQN's estimate, the teal line Double DQN's, and each dashed line is the return the policy really earns, the upper one Double DQN's and the lower one DQN's. Take a game late in training: DQN's red line sits far above its dashed line, while the teal line sits on its own.

2 Why the max runs high

Bootstrapping means putting your own current guess for the next state inside the target, as taught in RL Basics. On Atari each score's target holds the network's own guess for the next screen, so an error there is copied back.

Overestimation means the values climb above the return the agent really earns, because a max over noisy guesses picks lucky ones. An expected value is the average over everything that can happen by chance, weighted by how likely each outcome is, as taught in Expected value and RL Basics. The sign \(\mathbb{E}\) marks an expected value, as taught in Probability and Bayes Rule. In an Atari state where every move is equally good, the network's guesses are each a little off, and the max picks the one that came out highest.

Equation 1. On one screen every press can look equally good, yet the network's guesses are each a little off, and the max picks the one that came out highest. That suspicion is what this card checks, before the fix in the next sections changes how the target is built. A game-playing program reading its next screen needs this warning before it trusts its own top bar.

The mathematics. This line says \(\htmlStyle{color:#2c3e50}{M}\) equals \(\htmlStyle{color:#0e6b59}{\mathbb{E}}\) of the max over \(\htmlStyle{color:#a04000}{a}\) of \(\htmlStyle{color:#8e44ad}{\hat{Q}}(\htmlStyle{color:#2471a3}{s}, \htmlStyle{color:#a04000}{a})\). \(\htmlStyle{color:#2c3e50}{M}\) is that average. \(\htmlStyle{color:#0e6b59}{\mathbb{E}}\) is the average over the noise, the network's guess errors, built as a sum: take each noise draw, multiply its highest guess by its chance, and add them up. Max over \(\htmlStyle{color:#a04000}{a}\) reads 'the largest guess': \(\htmlStyle{color:#a04000}{a}\) runs over the presses in the screen \(\htmlStyle{color:#2471a3}{s}\), and max picks the highest guess, not the press. \(\htmlStyle{color:#8e44ad}{\hat{Q}}(\htmlStyle{color:#2471a3}{s}, \htmlStyle{color:#a04000}{a})\) is the network's guess of press \(\htmlStyle{color:#a04000}{a}\)'s score; the hat marks a guess, not the true score. Order matters: max first, picking the luckiest guess, then the average over the noise. So \(\htmlStyle{color:#2c3e50}{M}\) is the average highest guess, luck included.
Example. Take one screen where every press is truly worth the same. Each guess comes out a little off, so one press reads highest by luck alone.

Intuition. Averaging each move first lets the lucky errors cancel, so the best of the averages is the true best.
The mathematics. This line says \(\htmlStyle{color:#2c3e50}{M}\) is at least the max over \(\htmlStyle{color:#a04000}{a}\) of \(\htmlStyle{color:#0e6b59}{\mathbb{E}}\) of \(\htmlStyle{color:#8e44ad}{\hat{Q}}(\htmlStyle{color:#2471a3}{s}, \htmlStyle{color:#a04000}{a})\). The sign reads 'at least': the average of the highest guess is never smaller than the max of the averages, and with noise it is bigger. The right side averages first, then takes the max: \(\htmlStyle{color:#0e6b59}{\mathbb{E}}[\htmlStyle{color:#8e44ad}{\hat{Q}}(\htmlStyle{color:#2471a3}{s}, \htmlStyle{color:#a04000}{a})]\) averages each press's guesses over the noise, so the lucky errors cancel, and max over \(\htmlStyle{color:#a04000}{a}\) then picks the best of those averages. The gap between the two sides is the overestimation: the amount the max of noisy guesses runs above the true best score. So the max of noisy guesses averages high, and that gap is what Double DQN has to fix.
Example. Take the same screen, but average each press over the noise first. The lucky errors cancel, and the best average lands on the shared worth.

Figure 3 shows why the max of noisy guesses runs high. Each dot is one press's guess, and the dashed line is the worth every move truly shares, so the dots scatter around it by luck alone. Take the ringed dot, the max: it sits above the line, the luckiest guess, not the true best.

The Double DQN paper proves that even fair guesses overshoot. More moves make it worse, and an earlier study showed the overshoot grows with the noise. Bootstrapping copies the inflated score back to earlier states.

3 A second opinion from the target network

The target network is a slow copy of the Q-network, with weights \(\phi'\), that computes the targets, as taught in Deep Q-Networks. The live network is the Q-network being trained, with weights \(\phi\), as taught in Deep Q-Networks. On Atari, Double DQN needs no new network; it reuses these two.

Figure 4 shows the next screen going to each network, and the score the target network gives feeding the target. The live network picks the move and the target network scores that move, so the pick and the score come from different networks. Take a next screen where the live network picks fire: the target network's score for fire, not its own top score, feeds the target.

Double Q-learning trains two sets of guesses on their own, one to pick the best-looking move and one to score it, so the luck that made a move look best does not also inflate its score. Double DQN uses the target network as the second set. The target network is a copy of the live one that trails behind it, so it is only partly independent, which is enough in practice. This makes Double DQN about the smallest change to DQN that moves it toward Double Q-learning.

Figure 5 shows the two rows of guesses, the live network's above and the target network's below. The live row's highest dot is picked, and a dashed line drops to the dot under it in the target row, which is read, while the target row's own highest dot is left unread. Take a screen where the live row's highest dot sits over a lower dot in the target row: the lower dot is read, and the target row's own highest dot stays unread.

4 The Double DQN target

\(\arg\max\) picks the move whose score is largest, as taught in RL Basics. Replay keeps a memory of past steps, and training draws random batches from it, as taught in Deep Q-Networks. On each remembered Atari step, only the target's next-move choice changes.

A batch is a handful of remembered steps trained on together; the loss averages how far their scores are from their targets, as taught in Deep Q-Networks. From the next screen of a remembered step, the live network thinks fire is best.

Intuition. DQN lets the slow copy both pick the next move and score it, so one network's luck counts twice.
The mathematics. This line says \(\htmlStyle{color:#a04000}{a_{\text{DQN}}}\) equals the argmax over \(\htmlStyle{color:#a04000}{a'}\) of \(\htmlStyle{color:#8e44ad}{Q}(\htmlStyle{color:#2471a3}{s'}, \htmlStyle{color:#a04000}{a'}; \htmlStyle{color:#5d4037}{\phi'})\). \(\htmlStyle{color:#a04000}{a_{\text{DQN}}}\) is the move DQN picks for the next screen \(\htmlStyle{color:#2471a3}{s'}\), the screen the remembered step lands in. Argmax over \(\htmlStyle{color:#a04000}{a'}\) reads 'the move with the largest score': \(\htmlStyle{color:#a04000}{a'}\) runs over the joystick presses in \(\htmlStyle{color:#2471a3}{s'}\), and argmax returns the press itself, not its score. \(\htmlStyle{color:#8e44ad}{Q}(\htmlStyle{color:#2471a3}{s'}, \htmlStyle{color:#a04000}{a'}; \htmlStyle{color:#5d4037}{\phi'})\) is the slow copy's score for each press, and the semicolon reads 'computed with weights \(\htmlStyle{color:#5d4037}{\phi'}\)', the target network's weights. A remembered step is written \(s, a, r, s'\), the prime meaning next. So in DQN the slow copy picks the next move.
Example. Take a remembered step landing on a screen where the slow copy scores fire highest. DQN picks fire and scores it with the same slow copy.

Intuition. The target is the step's reward plus the discounted score of the next move, both from the slow copy.
The mathematics. This line says \(\htmlStyle{color:#196f3d}{y}\) equals \(\htmlStyle{color:#7d6608}{r}\) plus \(\htmlStyle{color:#2c3e50}{\gamma}\) times \(\htmlStyle{color:#8e44ad}{Q}(\htmlStyle{color:#2471a3}{s'}, \htmlStyle{color:#a04000}{a_{\text{DQN}}}; \htmlStyle{color:#5d4037}{\phi'})\). \(\htmlStyle{color:#196f3d}{y}\) is the target for this remembered step, one number. The equals sign splits it into the step's reward \(\htmlStyle{color:#7d6608}{r}\), the points the step paid, plus the discounted score of the next move. \(\htmlStyle{color:#2c3e50}{\gamma}\) is the discount, so only that share of the next screen's score counts. \(\htmlStyle{color:#8e44ad}{Q}(\htmlStyle{color:#2471a3}{s'}, \htmlStyle{color:#a04000}{a_{\text{DQN}}}; \htmlStyle{color:#5d4037}{\phi'})\) is the slow copy's score for the move it picked in the first line, computed with the same weights \(\htmlStyle{color:#5d4037}{\phi'}\). The same slow copy both picks and scores, so the luck that made the move look best counts twice: once in the pick, once in the score.
Example. Take the same remembered step. The target adds the points just earned to the discounted slow-copy score of fire.

Intuition. Double DQN changes only the picker: the live network picks, while the slow copy still scores.
The mathematics. This line says \(\htmlStyle{color:#1f618d}{a_{\text{live}}}\) equals the argmax over \(\htmlStyle{color:#a04000}{a'}\) of \(\htmlStyle{color:#8e44ad}{Q}(\htmlStyle{color:#2471a3}{s'}, \htmlStyle{color:#a04000}{a'}; \htmlStyle{color:#1b4f72}{\phi})\). \(\htmlStyle{color:#1f618d}{a_{\text{live}}}\) is the move the live network picks for the next screen \(\htmlStyle{color:#2471a3}{s'}\). Argmax over \(\htmlStyle{color:#a04000}{a'}\) again reads 'the move with the largest score', but the scores now come from the live network: \(\htmlStyle{color:#8e44ad}{Q}(\htmlStyle{color:#2471a3}{s'}, \htmlStyle{color:#a04000}{a'}; \htmlStyle{color:#1b4f72}{\phi})\) is the live network's score for each press, computed with the live weights \(\htmlStyle{color:#1b4f72}{\phi}\), the weights being trained. The picker changes and nothing else does: the same next screen, the same presses, a different network judging them. So the live network picks the next move.

6 The live network picks, the slow copy scores

The target step below comes from my repo's learn step, with the live network picking and the slow copy scoring. Stable Baselines' DQN implements the same step with its double_q flag turned on.

with torch.no_grad():
    a_live = q_live(s_next).argmax(1, keepdim=True)
  1. 1The live network picks the next move, line 3 of the Double DQN card.
    GAMMA = 0.99   # the discount, DQN's setting, unchanged here
    # still under the same with block above
    q_next = q_target(s_next).gather(1, a_live)
    y = r + GAMMA * q_next * (1 - done)
  1. 1The target network scores the picked move, and the target is built, line 4 of the Double DQN card. done marks the last step of an episode, where the target is the reward alone.

For contrast, the DQN target picks and scores with the slow copy alone.

with torch.no_grad():
    y_dqn = r + GAMMA * q_target(s_next).max(1, keepdim=True)[0] * (1 - done)
  1. 1The DQN target for contrast, lines 1 and 2 of the Double DQN card. The slow copy both picks and scores here, so the same luck counts twice.

8 An extra forward pass per learning step

8.1 When it learns

Double DQN learns exactly when DQN learns, on the same remembered steps. The change costs one extra forward pass of the live network on the next states.

8.2 How it is built

In code the live network takes the argmax over the next states, then the scores are gathered from the target network's outputs, under no_grad.

8.3 The settings

Epsilon-greedy usually makes the move with the highest value and, with a small chance \(\varepsilon\), a random one instead, so the agent keeps exploring, as taught in RL Basics. A soft update moves the target network's weights only a little toward the live network's, with \(\tau\) as the share moved, as taught in Deep Q-Networks. A hard copy overwrites the slow copy with the live weights every so often. The paper's tuned version of Double DQN copied the target less often, explored less and used one shared offset for every move's score.

8.4 The setup

A normalized score of 0 means random play, and 100 percent means a human expert's play, as taught in Deep Q-Networks. The paper rates every game this way, so results from different games can be averaged.

9 Where the second opinion pays off

Double DQN fits nearly always with DQN, because it keeps the same network, costs one extra forward pass, and changes one line of the target. It pays off most when move scores sit far above returns you can measure.

10 Where the second opinion falls short

The learning rate \(\eta\) sets how big a step each update takes, as taught in RL Basics. On Atari, Double DQN adds no setting of its own, so the settings that can break it are the ones it shares with DQN.

11 A state's worth and each move's extra, learned apart

Dueling DQN learns a state's worth and each move's extra apart. For moves that are amounts, the same worry returns, and TD3 takes the lower of two scoring networks.
