The setup

I keep one sandbox where every method has to show its work. Two gradient arrows, g1 and g2, one pull per task on the shared model. You drag them wherever you want, pick a combination rule, and the sandbox draws the update that rule would take: the gold arrow d. Same fight, four philosophies, and the scores say who gets helped.

This is a toy, and it says so everywhere it matters. Two arrows stand in for whole task gradients, and the four rules are the methods' actual math: the plain sum, PCGrad's surgery, MGDA's shortest blend, CAGrad's worst-task tilt. Nothing else lives here.

The score

Every verdict on this page comes from one number, the score $\langle d, g_i \rangle$, my referee. Take the update arrow d and dot it with task i's gradient $g_i$. If the score is positive, the step pushes task i's loss down. If it is negative, the step pushes the loss up, and that task is betrayed.

  1. Take $d = (2, 3)$ and $g_1 = (3, 1)$. Multiply the x parts: $2 \times 3 = 6$.
  2. Multiply the y parts: $3 \times 1 = 3$.
  3. Add: $6 + 3 = 9$. Positive, so task 1's loss goes down.
  4. Now the other fight: $d = (1.5, 1.5)$ against $g_2 = (-1.5, 0.5)$. The x parts: $1.5 \times -1.5 = -2.25$.
  5. The y parts: $1.5 \times 0.5 = 0.75$.
  6. Add: $-2.25 + 0.75 = -1.5$. Negative: the step pushes task 2's loss up.
  7. That second pair is not random. It is the loud-vs-quiet fight, and it gets its own preset in the sandbox below.

The shaded half-planes on the canvas are the betrayal zones: every direction that would hurt a task, drawn as a region. Any update arrow ending inside the purple zone betrays task 1; inside the green zone it betrays task 2. A good method's gold arrow never ends in a shaded zone.

The playground

The four buttons are the four philosophies from the rest of the series, one line each. Plain sum: add the pulls, no questions asked. PCGrad: cut the part of each gradient that fights the other. MGDA: take the shortest legal blend. CAGrad: start from the average, tilt toward the worst-off task. Its leash slider sets how far the update may stray, drawn as the dashed circle. Drag the handles, switch the rules, load the presets; the scores recompute on every move.

How to play
  • The point: Every multitask optimizer is a combination rule: two gradients in, one update out. This sandbox runs the actual math of four of them on arrows you place yourself, and the scores say which tasks each rule actually helps. Drag the arrows; same fight, four philosophies, read the scores.
  • What you'll see: two numbered handles, purple for g1 and green for g2: drag either anywhere inside the canvas. The gold arrow is the update d for the selected method. The shaded half-planes are the betrayal zones: each zone is the set of update directions that would hurt that task, purple for task 1, green for task 2. If the gold arrow lands inside a zone, that task's score goes negative and its verdict flips to HURT. Every method's whole job is keeping the gold arrow out of both zones. Below, each task gets a live score box with a helped or HURT verdict. There is no Play button: dragging is the whole interaction.
  • Try this: load "Paper section 5" and flip between Plain sum and PCGrad; load "Loud vs quiet" and watch task 2's score go negative under the plain sum while PCGrad, MGDA, and CAGrad each fix it differently. Drag the handles yourself and find a configuration where MGDA's arrow nearly vanishes: a Pareto-stationary point.
  • Reset: there is no Reset button because there is no Play button. Dragging is live, and the four preset buttons snap the arrows back to named configurations any time.

Different methods, different questions

Stepping back, the methods are answering different questions. GradNorm asks "how loud should each task be?" Uncertainty weighting asks the same question but answers it from the data's noise. PCGrad asks "is my step hurting you?" CAGrad asks "how do I help the worst-off task without losing sight of the goal?"

The scoreboard

The full comparison, seven methods across five columns. The "what it edits" column is the real split in the field: some methods only ever touch the loss weights, others only ever reshape the update direction.

PCGrad update direction Project out the mutually conflicting components none local improvement under the "tragic triad"; arbitrary Pareto point K backward passes. Conflict-heavy problems, multi-task RL.
GradVac update direction Pull each pair's cosine up to its own running target, not a blanket zero $\beta$, task subset, granularity none (heuristic) K backward passes. Many unequally-related tasks, e.g. multilingual models.

Where they land on the toy

On the toy landscape from the CAGrad page, plotting only where each 20,000-step run ends: GD has three runs stall far above the Pareto set, oscillating, while two reach it. MGDA gets all five into the low-loss region but lands scattered along it: every landing spot is a valid trade-off, yet the initialization does the choosing. PCGrad reaches it on four of five. CAGrad lands two of five exactly on the star, and the rest are still descending when the steps run out (give it the paper's 100,000 steps and all five arrive). As c varies: c = 0 inherits GD's stalled runs, c = 10 inherits MGDA's spread.

Reading the tool below: each point is one run's landing in loss space. The horizontal axis is the final task-1 loss $L_1$, the vertical axis is the final task-2 loss $L_2$. The average loss $L_0$ I keep quoting is their mean: $L_0 = \frac{L_1 + L_2}{2}$. At the star both task losses read -15.0916, so the walk is: $L_0$ = (-15.0916 + -15.0916) / 2 = -30.1832 / 2 = -15.0916. That -15.09 is the floor of this toy: no run can land below the gray curve, because the curve is exactly the set of trade-offs where neither task can improve without hurting the other. The conflict fraction shown on hover is the share of the 20,000 steps where the two task gradients pulled in opposite directions, that is, where their dot product was negative.

All four methods ran the same 20,000 Adam steps (learning rate 2e-3) from the same five starts on the paper's §5.1 toy.   • Click a method chip to spotlight its five starts and read its honest stat line: how many reached the front and where they landed.

  • Reset: click the All methods chip to restore the full twenty-point view.

Teammates, not rivals

Reweighting fixes how loud the tasks are. Surgery fixes the direction they pull. Nothing stops me from doing both: feeding GradNorm's weights into PCGrad's cuts is a common combination, and GradVac gives the pairing a principled form. Zooming out one more level, all of these are multitask optimization methods. They change how the model is trained, not what the model is. Changing the model itself (cross-stitch networks, MTAN) is a separate toolbox.

Comparison done. So which one do I reach for on Monday? That is the field guide's job, and it is next.
