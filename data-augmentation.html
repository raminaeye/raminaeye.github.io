1 What augmentation is and the problem it solves

A gesture recorded with the wristband twisted is still the same gesture, so a twisted copy is a new example with a true label. Data augmentation trains on such label-keeping edits of each recording. Each edit mimics one real source of variation the model will meet: a band worn at another angle, a looser strap, a speaker who pauses.

The problem it solves is too few recordings for the model’s flexibility, the estimation error. A model that sees the same few hundred windows every epoch can memorize them; a model that sees a fresh variation each time cannot, so it has to learn what stays the same across the variations, which is the gesture or the word itself.

Augmentations are drawn fresh each time a training example is loaded, so every epoch sees a new copy. They touch training data only, keep no state, and cost data-loader time, not model time. The same label-keeping edits make the positive pairs of Contrastive Learning. Blending two examples and their labels at once is a different edit, mixup (Zhang et al. 2018), taught on its own page.

2 Augmentation as an average over edits

The plain training objective averages the loss over the recorded examples. Augmentation changes one thing: each example’s loss is averaged over random edits of it.

Average the loss over the examples and, for each one, over random edits of it.
\(\displaystyle {\begin{aligned}&\htmlClass{eqt sym-loss}{\htmlStyle{color:var(--sym-loss)}{\mathcal{L}_{\text{aug}}}}(\theta) = \frac{1}{N} \sum_{n=1}^{N} \mathbb{E}_{t \sim \mathcal{T}} \Big[ \\ &\qquad \htmlClass{eqt sym-loss}{\htmlStyle{color:var(--sym-loss)}{\ell}}\big(f_\theta(t(\htmlClass{eqt sym-x}{\htmlStyle{color:var(--sym-x)}{x_n}})),\ \htmlClass{eqt sym-target}{\htmlStyle{color:var(--sym-target)}{y_n}}\big) \Big]\end{aligned}}\)
Without the \(\mathbb{E}\) and the \(t\), this is the ordinary average loss over the \(N\) recorded examples \(\htmlClass{eqt sym-x}{\htmlStyle{color:var(--sym-x)}{x_n}}\) with labels \(\htmlClass{eqt sym-target}{\htmlStyle{color:var(--sym-target)}{y_n}}\), where \(f_\theta\) is the model with weights \(\theta\) and \(\htmlClass{eqt sym-loss}{\htmlStyle{color:var(--sym-loss)}{\ell}}\) scores one prediction. \(t\) is one edit, drawn from the family \(\mathcal{T}\) of allowed edits (rotations, masks, gains), and \(\mathbb{E}\) averages over those draws; in practice each load draws one, and the average builds up across epochs.
So the model is scored on edited inputs with the original label \(\htmlClass{eqt sym-target}{\htmlStyle{color:var(--sym-target)}{y_n}}\) untouched: an edit that changes the true label teaches the wrong answer.

The idea of averaging over plausible neighbours of each example is vicinal risk minimization (Chapelle et al. 2000); augmentation picks the neighbours by hand from what the real world varies.

3 Wearable sensors

Each augmentation in the table mimics one real source of variation in a wristband’s readings.

augmentationwhat it mimics
channel dropoutlost contact or a misaligned sensor
channel shufflingthe band shifting along the arm
spatial mixingthe displacement blur of a shifted band
rotationthe band worn twisted or at another angle
random scalingstrap tightness or skin-electrode impedance (how much the skin contact holds back the signal)
temporal jitterthe delay that altered placement introduces
cross-modal maskinga missing sensor type

Twisting the band keeps \(x\) and rotates \(y\) and \(z\), so the augmentation rotates the readings.

A general rotation multiplies one rotation per axis together and applies it to each sensor vector.
\(\displaystyle {\begin{aligned}\htmlClass{eqt sym-x}{\htmlStyle{color:var(--sym-x)}{\mathbf{v}'}} &= R_z(\htmlClass{eqt sym-xint}{\htmlStyle{color:var(--sym-xint)}{\psi}})\, R_y(\htmlClass{eqt sym-angle}{\htmlStyle{color:var(--sym-angle)}{\theta}}) \\ &\quad \times R_x(\htmlClass{eqt sym-layerout}{\htmlStyle{color:var(--sym-layerout)}{\phi}})\, \htmlClass{eqt sym-x}{\htmlStyle{color:var(--sym-x)}{\mathbf{v}}}\end{aligned}}\)
The rotated reading \(\htmlClass{eqt sym-x}{\htmlStyle{color:var(--sym-x)}{\mathbf{v}'}}\) (v-prime) is the original reading \(\htmlClass{eqt sym-x}{\htmlStyle{color:var(--sym-x)}{\mathbf{v}}}\), a 3D vector in the band’s \(x\), \(y\), \(z\) axes, multiplied by three rotation matrices. \(R_x(\htmlClass{eqt sym-layerout}{\htmlStyle{color:var(--sym-layerout)}{\phi}})\) turns by the roll angle \(\htmlClass{eqt sym-layerout}{\htmlStyle{color:var(--sym-layerout)}{\phi}}\) (phi) around \(x\), \(R_y(\htmlClass{eqt sym-angle}{\htmlStyle{color:var(--sym-angle)}{\theta}})\) by the pitch angle \(\htmlClass{eqt sym-angle}{\htmlStyle{color:var(--sym-angle)}{\theta}}\) (theta) around \(y\), and \(R_z(\htmlClass{eqt sym-xint}{\htmlStyle{color:var(--sym-xint)}{\psi}})\) by the yaw angle \(\htmlClass{eqt sym-xint}{\htmlStyle{color:var(--sym-xint)}{\psi}}\) (psi) around \(z\). Each matrix only turns the vector, so its length, the strength of the motion, stays the same. The matrices apply right to left, roll first and yaw last, and the order matters because turns about different axes do not commute.
So a rotated copy is the same motion seen from a band worn at another angle.

SciPy rotates a window by a fresh small random roll, pitch and yaw; acc_rotated keeps the shape [time, 3].

import numpy as np
import scipy.spatial.transform
rng = np.random.default_rng()
shape = (200, 3)  # [t, 3]
acc = rng.normal(size=shape)
# roll, pitch, yaw in degrees
deg = rng.uniform(-15, 15, 3)
rad = np.radians(deg)
st = scipy.spatial.transform
euler = st.Rotation.from_euler
rot = euler("xyz", rad)
acc_rotated = rot.apply(acc)
  1. 1One window of readings on three axes.
  2. 2Roll, pitch and yaw, each a small random turn.
  3. 3Rotate every reading.

Channel dropout and shuffling, each into a new array.

import numpy as np
rng = np.random.default_rng()
x = rng.normal(size=(8, 500))
n_ch, p = len(x), 0.1
# channel dropout: zero rows
keep = rng.random(n_ch) > p
x_drop = x * keep[:, None]
# shuffle: swap rows i, i + 1
i = rng.integers(n_ch - 1)
rows = [i, i + 1]
x_shuf = x.copy()
x_shuf[rows] = x[rows[::-1]]
  1. 1One window of several channels.
  2. 2Zero each channel with chance \(\htmlClass{eqt sym-prob}{\htmlStyle{color:var(--sym-prob)}{p}}\).
  3. 3Swap two neighbouring channels.

Random scaling and jitter; wider ranges regularize more, until they make signals no real wearer would record.

# strap tightness per channel
u = rng.random((n_ch, 1))
gain = 0.8 + 0.4 * u
x_scaled = x * gain
# jitter: shift ≤ 20 samples
k = rng.integers(-20, 21)
x_jit = np.roll(x, k, axis=1)
  1. 1A per-channel gain near 1.
  2. 2Shift by a few samples.

A twisted band is augmentation: it could happen to any wearer, so the model should learn to ignore it. Powerline hum and slow drift are different. They are faults to remove, not variations to teach, and Section 9 cleans them before any augmentation runs.

4 Speech: SpecAugment

SpecAugment (Park et al. 2019) augments speech directly on its log-mel spectrogram, the picture of energy per mel channel over time that speech models read. The paper trained Listen, Attend and Spell (LAS) recognizers on LibriSpeech 960h and Switchboard 300h, with the edits applied online during training. It uses three edits: time warp stretches the spectrogram a little along time; a frequency mask blanks a band of mel channels; a time mask blanks a stretch of time steps. A model trained this way must recognize a word with part of its sound missing, as it would be under noise or a dropout in the line.

Pick a random width, then a random start, and blank that band; the same along time, with a cap.
\(\displaystyle {\begin{aligned}f &\sim \mathcal{U}[0, F] \\ f_0 &\sim \mathcal{U}[0,\, \nu - f) \\ \text{masked} &= [f_0,\, f_0 + f)\end{aligned}}\)
A frequency mask. \(\mathcal{U}\) means drawn uniformly at random. The width \(f\) is drawn up to \(F\), the widest band allowed: raise \(F\) and more of the spectrum vanishes per copy. The start \(f_0\) is drawn anywhere it fits among the \(\nu\) (nu) mel channels, and channels from \(f_0\) up to \(f_0 + f\) are blanked.
\(\displaystyle {\begin{aligned}t &\sim \mathcal{U}\big[0, \\ &\qquad \min(T,\, \htmlClass{eqt sym-eta}{\htmlStyle{color:var(--sym-eta)}{\rho}}\,\tau)\big] \\ t_0 &\sim \mathcal{U}[0,\, \tau - t) \\ \text{masked} &= [t_0,\, t_0 + t)\end{aligned}}\)
The same rule along time, built on line 1. A stretch of up to \(T\) steps out of the utterance’s \(\tau\) (tau) steps is blanked, but never more than a share \(\htmlClass{eqt sym-eta}{\htmlStyle{color:var(--sym-eta)}{\rho}}\) (rho) of the utterance, so a short keyword is not wiped out. The paper writes this cap as \(p\); it is not dropout’s \(p\).
So each copy loses a random band and a random stretch, sized so the word is damaged but still there.

Masked values are set to zero, which equals the average energy only because the spectrogram is mean-normalized first (Park et al. 2019), so the code normalizes before masking. The paper’s policies LB and LD set how many masks of each kind to use, one or two, and how wide. With them an end-to-end LAS model beat the earlier hybrid recognizers on LibriSpeech (Park et al. 2019). The Conformer recognizers that came later were trained with SpecAugment as well.

import torchaudio
TA = torchaudio.transforms
# logmel: [channel, mel, time]
spec = (logmel - logmel.mean()) / logmel.std()
# F, T, rho: the policy's settings
spec = TA.FrequencyMasking(freq_mask_param=F)(spec)
spec = TA.TimeMasking(time_mask_param=T, p=rho)(spec)
  1. 1Normalize first, so a zeroed block reads as average energy.
  2. 2A frequency mask up to \(F\) wide, line 1, then a time mask up to \(T\) steps; torchaudio’s p is the cap \(\htmlClass{eqt sym-eta}{\htmlStyle{color:var(--sym-eta)}{\rho}}\) of line 2.

6 The tool: SpecAugment masks

One spoken keyword as an illustrative spectrogram, its word region outlined. Each beat of Play is one epoch: a new copy with new masks, added to the strip of recent copies.

word still visibleerased → intact

Figure 4. Illustrative keyword. Moderate masks hide a different part each time; wide masks erase the word.

At a moderate setting, every copy loses a different piece, and the word is still recognizable in each, so the model learns to use all of its sound rather than one patch. Push the size up and add masks, and some copies lose the word altogether: those train the model on a label the input no longer supports.

7 In practice

  • Where it runs. In the Dataset’s __getitem__, so each load draws new settings; spectrogram masks can move to the GPU if the loader becomes the bottleneck.
  • Training data only. Augment only the training data, or validation and test scores stop measuring real inputs.
  • How wide. Wider ranges regularize more, until they make signals no real wearer or speaker would produce. Start from the variation the deployment actually sees, and tune on validation.
  • Reuse. The same edits make the positive pairs for contrastive pretraining.

9 Clean the signal before augmenting

Builds on Zero-phase filtering Convolution Reading a spectrum Sampling rate and an ADC’s range Cross-Attention

Wearable signals arrive noisy, drifting and sometimes missing. A model fed raw signals learns the sensor faults, then fails on a new strap or in a country with different mains power. Cleaning removes what is never the signal and runs the same way on training, validation, test and live data. Augmentation varies what could be the signal and runs on training data only. In the pipeline, cleaning comes first.

Filters run once per recording, or per window when streaming; z-score statistics are kept per channel for each person or session; the bad-channel check runs on every window, in training and live. Nothing is learned except the per-session mean and spread.

9.1 What each fault looks like

  • Baseline drift: sweat and electrode chemistry move the zero level slowly; a model can read the level as part of the gesture.
  • Powerline hum: the mains wiring couples in at 60 Hz in North America and 50 Hz in Europe (Boyer et al. 2023); a model trained in one region learns the hum and is thrown by the other.
  • Motion artifact: the cable or strap moving on the skin adds slow, large bursts at the low end of the spectrum (De Luca et al. 2010); they look like strong muscle activity.
  • Saturation: the signal hits the top of the converter’s range and is clipped flat, so its shape is lost.
  • Lost contact: an electrode lifts and the channel goes flat; a model that relied on that channel guesses.

9.2 The cleaning pipeline

stepwhat it removes
band-pass filterlow-frequency drift and high-frequency noise, keeping one band
notch filterone narrow band, the powerline hum, leaving the frequencies around it
rectify and envelopethe sign and the fast oscillation: absolute value, then a low-pass, traces how strong the signal is
z-score per channel, per person or sessionamplitude differences across people and sessions: subtract that recording’s average, divide by its spread

The card writes the same four steps; each line uses the line before it.

Filter, then take the envelope, then put every channel on the same scale.
\(\displaystyle {\htmlClass{eqt sym-x}{\htmlStyle{color:var(--sym-x)}{x_{\text{band}}}} = h_{\text{notch}} * h_{\text{bp}} * \htmlClass{eqt sym-x}{\htmlStyle{color:var(--sym-x)}{x}}}\)
The raw signal \(\htmlClass{eqt sym-x}{\htmlStyle{color:var(--sym-x)}{x}}\) passes through two filters. \(h_{\text{bp}}\) keeps one band, removing drift below it and noise above it; \(h_{\text{notch}}\) removes the narrow mains band. \(*\) is convolution, and each filter runs forward and backward so nothing shifts in time (zero-phase filtering).
\(\displaystyle {\begin{aligned}e[n] &= \sum_{k} h_{\text{lp}}[k] \\ &\quad \times \big\lvert \htmlClass{eqt sym-x}{\htmlStyle{color:var(--sym-x)}{x_{\text{band}}}}[n - k] \big\rvert\end{aligned}}\)
Drop the sign with the bars, then smooth with a low-pass filter whose taps are \(h_{\text{lp}}\). What is left, the envelope \(e\), is how strongly the muscle fires at each sample \(n\).
\(\displaystyle {z_c[n] = \frac{e_c[n] - \htmlClass{eqt sym-mean}{\htmlStyle{color:var(--sym-mean)}{\mu_c}}}{\htmlClass{eqt sym-sigma}{\htmlStyle{color:var(--sym-sigma)}{\sigma_c}} + \epsilon}}\)
For each channel \(c\), subtract its mean \(\htmlClass{eqt sym-mean}{\htmlStyle{color:var(--sym-mean)}{\mu_c}}\) and divide by its spread \(\htmlClass{eqt sym-sigma}{\htmlStyle{color:var(--sym-sigma)}{\sigma_c}}\), both measured over one person’s or one session’s recording, so people with different skin contact and strap tightness look alike. \(\epsilon\) (epsilon), a tiny constant, keeps a flat channel from dividing by zero.
So the model receives the muscle’s firing pattern on a common scale, with hum, drift and per-person level removed.

filtfilt runs each filter forward and backward, so nothing shifts in time; the band-pass is 4th order, its edges fractions of the Nyquist rate nyq, half the sampling rate. The 20 Hz high-pass corner is the one De Luca et al. (2010) recommend for surface EMG: low enough to keep muscle activity, high enough to cut most movement artifact and baseline noise.

import numpy as np
from scipy.signal import butter
from scipy.signal import filtfilt
from scipy.signal import iirnotch
fs, hum = 1000, 60  # Hz
x = np.random.randn(8, 2000)
nyq = fs / 2
wn = (20 / nyq, 450 / nyq)
b, a = butter(4, wn, "bandpass")
x_band = filtfilt(b, a, x)
b, a = iirnotch(hum, 30, fs)
clean = filtfilt(b, a, x_band)
  1. 1Sampling rate, hum frequency and channel count.
  2. 2Band-pass to the muscle band, both directions, line 1.
  3. 3Notch out the mains hum, line 1.

The envelope and the per-person z-score; \(z\) keeps the shape [channels, time].

# rectify, low-pass at 5 Hz
b, a = butter(4, 5, fs=fs)
rect = np.abs(clean)
env = filtfilt(b, a, rect)
# z-score per channel
mu = env.mean(axis=1)[:, None]
sd = env.std(axis=1)[:, None]
z = (env - mu) / (sd + 1e-8)
  1. 1Envelope, a slow low-pass, line 2.
  2. 2Z-score per channel, line 3.

Live use changes two things. filtfilt needs the whole window, including samples that have not arrived yet, so a streaming device uses a causal filter that accepts a small delay (IIR filters). The z-score statistics come from a short calibration segment at the start of each session. The order stays filter, then envelope, then z-score. Features are then hand-made in time and frequency, or learned by the model.

9.3 Dead channels

Bluetooth packet loss or sweat can leave missing channels. A channel with no spread, or stuck at the top of its range more than half the time, gets the mean of the good channels, and a mask marking the bad channels goes to the model, so it learns to ignore the missing channels.

Flag a channel that is flat or stuck at the top of the range.
\(\displaystyle {\begin{aligned}\text{flat}_c &= \big[\htmlClass{eqt sym-sigma}{\htmlStyle{color:var(--sym-sigma)}{\sigma_c}} < \epsilon\big] \\ s_c &= \frac{1}{T}\sum_{n=1}^{T} \\ &\quad \Big[\, \big\lvert \htmlClass{eqt sym-x}{\htmlStyle{color:var(--sym-x)}{x_c}}[n] \big\rvert \ge x_{\max} \Big]\end{aligned}}\)
Square brackets count as one when the condition inside holds and zero otherwise. A channel is flat when its spread \(\htmlClass{eqt sym-sigma}{\htmlStyle{color:var(--sym-sigma)}{\sigma_c}}\) is below a tiny \(\epsilon\). \(s_c\) is the share of the window’s \(T\) samples stuck at \(x_{\max}\), the top of the device’s converter range.
\(\displaystyle {\text{bad}_c = \text{flat}_c \lor \big(s_c > \tfrac{1}{2}\big)}\)
Built on line 1: \(\lor\) means or, so a channel is bad when it is flat or stuck more than half the time. Bad channels get the good channels’ mean, and the mask tells the model which ones were filled.
So a dead channel is replaced by something harmless and flagged, instead of feeding the model a flat line or a clipped one.
import numpy as np
x = np.random.randn(8, 500)
x[3] = 0.0  # a flat channel
flat = x.std(axis=1) < 1e-6
pegged = np.abs(x) >= 5.0
share = pegged.mean(axis=1)
bad = flat | (share > 0.5)
fill = x[~bad].mean(axis=0)
x_fill = x.copy()
x_fill[bad] = fill
  1. 1Several channels, one of them flat.
  2. 2Bad if flat, or at its maximum over half the time, lines 1 and 2.
  3. 3Bad channels get the good ones’ mean.

The check runs on every window, in training and live, with no state; the mask travels with the window.

9.4 When a sensor is missing: fusion

Combining modalities lets one sensor cover for another. An encoder compresses a signal into features; a decoder predicts from them.

A shared encoder needs the sensors aligned in time and scale; separate encoders do not. Very late fusion, one model per sensor with only the outputs joined, does not solve missing signals.

With cross-modal attention (Cross-Attention), one sensor’s features query the other’s, so the model learns how much to trust each and down-weights a missing or noisy one. A gives the queries, B the keys and values; fused has A’s shape, \(\htmlClass{eqt sym-attnw}{\htmlStyle{color:var(--sym-attnw)}{w}}\) says how much each A step used each B step, and off marks B steps to ignore, in the default [time, batch, features] layout.

import torch
from torch import nn
# [time, batch, features]
A = torch.randn(50, 2, 32)
B = torch.randn(20, 2, 32)
off = torch.zeros(2, 20).bool()
off[:, 10:] = True  # B drops
MHA = nn.MultiheadAttention
attn = MHA(32, num_heads=4)
# 4th argument: the B mask
fused, w = attn(A, B, B, off)
  1. 1Features for A and B; B’s last steps missing.
  2. 2Attention over several heads.
  3. 3A queries B, masked steps skipped.

Foundation-style models such as SensorLM (Zhang et al. 2025) go further: they pretrain one sensor encoder, paired with text descriptions, on data from a very large cohort of wearers (Self-Supervised Learning), and it then recognizes activities with no labels or only a few labeled examples.
